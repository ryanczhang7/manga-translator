# Audit: the WORLD-007 field report

**Date:** 2026-09-10
**Scope:** the delta field report from `fantasy-world-builder` covering story
WORLD-007 - findings H13-H18, patterns K4-K5, and regression cases 12-18 - read
against the harness at `c9374f3` (after PR #9). Every finding was reproduced or
refuted against this checkout before anything was changed, and every fix was
written test-first: the new selftest case, watched failing, then the code.
**Left out:** nothing in the report was declined. Two things in it turned out to
be already fixed, and one turned out to need a change the report did not ask for;
both are recorded under Evidence.

## Decided

- **`scripts/mutate.sh` is the only sanctioned way to mutate production source,
  and it is allowed in every phase.** H14 was the harness contradicting itself:
  `rules.md` requires a corrected test to be earned by mutating the production
  behaviour it pins, in RED, where production source is frozen, and forbids
  routing around the lock. The script closes the contradiction rather than
  choosing a side - it backs the file up to an explicit path under
  `.claude/state/mutations/`, applies a `sed` expression, runs a command,
  restores, **verifies the restore with `cmp`**, prints the line it put back and
  logs it. A mutation that changes nothing is refused before the command runs.
  Its exit status is the command's, because a non-zero exit is the evidence.
- **The `$`-in-target loophole is closed.** The guard no longer discards a write
  target because it contains a `$`. A variable the command itself assigns is
  resolved and judged; one it cannot resolve is declined and logged, which is
  the contract H1 already established for a parse the guard does not believe.
  Removing the loophole and providing the primitive had to happen together: the
  loophole was load-bearing for a thing the rules demand.
- **`mutate.sh` is deliberately not in `settings.json`'s allow list.** Everything
  after `--` is an arbitrary command, so allowlisting the script would allowlist
  every command through it.
- **BLOCKED is a third gate state, and it exits 3.** Not a pass, not a fail: the
  environment would not let the gate start. `gates.sh` recognises the shapes that
  mean a process never launched, stamps `RESULT=blocked`, and a project extends
  the list with `blocked-when | <gate> | <regex>`. BLOCKED never makes a run
  succeed - a misclassified real failure still stops the story, which is what
  bounds the cost of the classification being wrong.
- **The BLOCKED path through the loop is: PO decision in `## Notes`, REVIEW with
  the gate *pending CI*, DONE only once the PR's CI run for it is quoted.** The
  decision line carries the gate id and the words `pending CI`; the DONE line
  carries the gate id and the run URL. `check-boundaries.sh` enforces both.
- **The Stop hook's clock is the phase change, not file mtimes.** It blocks on
  one thing: closing GREEN or GATES with no gate run since the story entered that
  phase. A recorded failure, a BLOCKED gate, or code touched since the run are
  said without blocking. In GATES the obligation is a **full** run, which is why
  the stamp now carries `FULL=`.
- **Every agent declares `model:`.** All five say `opus`, as a decision rather
  than a default (`rules.md` says why), and `lead-po` records the *resolved*
  model of every dispatch in the story. "Default" is not a model name.
- **A story gets a `## Contract` section, PO-owned before RED and amendable by
  RED in place with a reason.** Signatures, semantics behind every number,
  accessible markup, oracle partition, baseline measurements - and the
  grep-listed callers of every existing export whose signature changes, which is
  the one thing RED provably cannot find for itself.
- **`/advance-story` PLANNED → RED checks the epic's done-when against the
  story's criteria**, and a gap is a numbered PO decision reported to the user
  before GREEN, never absorbed and never skipped silently.

## Evidence

- **H1's four new shapes were already fixed, and are now pinned.** Claim: the
  four commands in regression cases 12-15 (`awk` comparing `getline` against 0,
  a `printf` of prose quoting `>`, a `sed` expression containing `|` or `;` with
  the path in a variable, `grep 'foo\b'`) are blocked by this harness. Measured
  by driving the real hook against a fixture in RED: all four are **allowed**.
  `mask_shell_quotes` (PR #7) closed them; the consuming project was running an
  earlier harness. They are now cases in `phase-guard.test.sh` so they cannot
  regress. What was *not* already fixed is the same command with the path in a
  variable, which the `$` discard let through - that is H14, and it is the one
  case the report marked "allowed today".
- **The `$` resolution is bounded, and the bound is honest.** `shell_assignments`
  reads assignments out of the masked command text only, so `git commit -m
  "note: A=b"` is not an assignment; names are resolved longest-first so `$FILE`
  is not eaten by a rule for `$F`. A variable assigned in an *earlier* command is
  unresolvable - the guard reads one command string, not the shell's environment
  - and declines with the token in `phase-guard-declined.log`. Measured: 92
  cases in `phase-guard.test.sh`, 110 in `lib.test.sh`.
- **`mutate.sh` was verified by using it on this round's own work.** The three
  `lib.test.sh` assertions that passed on their first run - longest-name-first
  ordering, braced expansion, `scripts/mutate.sh` rather than any `mutate.sh` -
  were each earned by one probe through the script: drop `| sort -rn`, delete the
  `${NAME}` substitution, widen the regex. Each produced exactly one failure, the
  right one, and each restore verified byte-for-byte. That is the discipline
  `rules.md` demands of a test written against existing code, applied here.
- **`check-boundaries.sh` had to change, and the report did not ask for it.** It
  refused any REVIEW or DONE story whose recorded gate result did not start with
  `pass`. So the BLOCKED path the report prescribes - REVIEW with a gate pending
  CI - was a path CI would have rejected, and the fix would have shipped
  half-built. Measured by writing the case first: a fixture story at REVIEW with
  a real `gates.sh`-written `blocked` record, refused with "recorded gate result
  is 'blocked...'". Now accepted at REVIEW with the `pending CI` line and refused
  without it; refused at DONE without a CI run URL.
- **The BLOCKED evidence lives in `## Notes`, not `## Gate results`.** The report
  said `## Gate results`. That section is rewritten wholesale by `gates.sh` on
  every run and `check-boundaries.sh` refuses a hand-written one, so a quoted CI
  log there would be destroyed by the next run and is forbidden anyway. `##
  Notes` is where the harness already puts orchestrator decisions and mutation
  evidence. Every document changed this round says `## Notes`.
- **The `pending CI` and CI-URL checks require the gate id on the same line as
  the phrase.** Looking for the words anywhere in the story is satisfied by a
  story that mentions CI about something else; and `## Gate results` needs no
  special-casing, because the `BLOCKED` line `gates.sh` writes there carries
  neither phrase.
- **The Stop hook's new rule does not lose staleness detection.** `code_changed_
  since` still runs and still ignores the gates' own exhaust; it now produces a
  non-blocking note rather than a block. Measured: the 25 cases in
  `gate-reminder.test.sh`, including the coverage report, the build directory,
  the runner cache, generated output nested inside `src/`, and the failure
  screenshot a deliberate mutation produces - all silent - against a real source
  change, a hook, and the gate manifest, all of which warn.
- **A partial run cannot discharge GATES.** `--fast`, `--gate` and `--required`
  write the stamp too, so without `FULL=` the phase-based rule would have let
  `--gate unit` close the phase whose entire job is the full suite. A stamp from
  an older `gates.sh`, with no `FULL` line, is treated as full - fail open on a
  missing line rather than block on it.
- **`mutate.sh` found a defect in itself, which is the strongest thing this
  round produced.** Probing the new "no shipped script depends on `$TMPDIR`"
  assertion by mutating `mutate.sh` corrupted the run: bash reads a script
  incrementally rather than loading it whole, so rewriting the file while it
  executes changes what the interpreter reads next. The run died mid-script and
  the restore - the last thing it does - never happened, leaving the mutation in
  the tree with nothing to say so. The backup was intact and the file was put
  back from it and `cmp`-verified, which is the property the script was built
  for. It now refuses to mutate itself (exit 2), by absolute path too, with a
  case in `mutate.test.sh`. The assertion was then earned against `doctor.sh`
  instead: one failure, the right one, restore verified.
- **Full selftest after every change:** 9 suites, 422 assertions, 0 failures.
  New this round: `mutate` (39), plus additions to `gates` (74), `gate-reminder`
  (25), `phase-guard` (92), `lib` (111) and `boundaries` (16).

## What would have to be true for this to be wrong

- The `blocked-when` default patterns describe launch failures and not ordinary
  ones. A test that prints `command not found` as part of its own assertion would
  be reported BLOCKED rather than FAIL. The consequence is bounded - the run
  still exits non-zero and still needs a decision - but the words would be wrong.
- `systemMessage` is how a Stop hook says something without blocking. If a runner
  does not surface it the object still carries no `decision`, so the stop
  proceeds: the note is lost, never the loop.
- `[ "$GATE_STAMP" -nt "$STATE_FILE" ]` is the phase-change comparison. A gate run
  that completes in the same filesystem timestamp tick as the phase change reads
  as stale and blocks. Blocking is the safe direction, and a gate run that fast is
  not a gate run.
- Resolving `NAME=value` from the command text is sound because masking has
  already turned quoted spans into opaque tokens. If masking regressed, the
  resolver would inherit the error - which is why both have direct unit tests.
- `model: opus` is available to whoever installs this harness. A project that
  wants a cheaper role lowers it deliberately and records the outcome.

## What was not checked

- **Nothing ran on macOS, Linux or bash 3.2.** `mutate.sh` avoids `sed -i`
  entirely for exactly the BSD/GNU divergence `phase.sh` was bitten by, and uses
  only `cp`, `cmp`, `sed`, `awk` and `date`; the `portability` block in
  `lib.test.sh` greps for the constructs concerned. That is reading plus a grep,
  not execution.
- **The `blocked-when` pattern list was not exercised against a real blocked
  toolchain.** The Smart App Control case is reproduced from the report's quoted
  log, in a fixture, with a `printf`. No machine here refuses an unsigned binary.
- **H13 is documentation only, and cannot be tested here.** Hook budgets, GPU
  teardown cost and the 10 %-of-limit rule are guidance in `quality-gates` and
  the `test-developer` prompt. The harness has no test runner of its own to
  enforce them against, and a project's own gates are where they would bite.
- **The `## Contract` section is not machine-checked.** `check-boundaries.sh`
  does not verify that a caller list exists, that it is complete, or that RED
  confirmed it. A `covers`-style structural check is possible later; this round
  put the section in the template and the rule in three prompts.
- **Whether any other file is unsafe to mutate while a command reads it.**
  `mutate.sh` now refuses only itself. A project whose test runner reads a
  config file lazily could hit the same shape; nothing here detects that.
- **`mutate.sh` is not a sandbox.** Its `--` payload is judged by the guard like
  any other command, which means a payload inside `sh -c '...'` is a quoted
  string and is not read - the same documented fail-open the guard has
  everywhere. It adds no hole a bare `sh -c` did not already have.
- **`.claude/state/README.md` could not be updated.** `settings.json` denies
  `Write`/`Edit` on `.claude/state/**`, which covers the two tracked documents in
  that directory as well as the runtime files. Narrowing that deny is a
  permissions change and was left to the user; the `mutations/` directory is
  documented in `rules.md` and `CLAUDE.md` instead.

## Stories filed

None. Findings from a field report are applied here directly and recorded in this
