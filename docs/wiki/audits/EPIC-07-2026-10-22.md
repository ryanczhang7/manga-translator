## Scope

**The question.** If EPIC-07's production code were subtly wrong, would a test
notice? Line coverage is already 100% (the `coverage-core` gate). So every
mutant below runs on covered lines, and a survivor is an assertion gap, not an
uncovered line.

**Tooling.** The `mutation` gate (`uv run mutmut run`) was not run, because
`mutmut` is not installed: `uv run mutmut --version` gives
`Failed to spawn: mutmut ... program not found`. The gate is also waived in
`.claude/harness/project.conf` ("mutmut is not installed and not configured
until the suite is real; stack.md §6"). Mutants were chosen by hand and applied
one at a time with:

    bash scripts/mutate.sh FILE 'SED' -- uv run pytest -q -x -p no:cacheprovider <test files>

The test files named were the narrowest set that should catch each mutant.
`-x` was dropped for "full" runs, where the whole failure set was compared
with a handoff's claim. Every survivor at the bench layer was rerun against the
wide bench set (W, below) before being reported.

## Decided

1. **EPIC-07's tests discriminate very well.** Of 139 mutants, 130 were killed
   and 9 survived. The 9 are 6 distinct findings: RS17 at three values counts
   as one, and SD4 is equivalent. That is the best ratio of the audits in
   `docs/wiki/audits/`, and the bench layer, the hash verification and the API
   key handling have no high-impact survivor. Rests on E-1 and E-2.
2. **The one survivor that changes a verdict the user reads is RS17: S2's
   residual-ink bar is not pinned to its measured value (filed as MT-091).**
   - **The gap.** `RESIDUAL_INK_MAX` (`bench/residual.py:85`, 0.01) can be any
     value in roughly (0, 0.0205] and all 291 bench tests stay green.
   - **Why.** Every assertion on it is relative (`>= 10 * RESIDUAL_INK_MAX`,
     `< RESIDUAL_INK_MAX`, `math.nextafter(RESIDUAL_INK_MAX, ...)`). The one
     absolute test only checks `0 < x < 1`.
   - **The effect.** Doubling the bar lets a clean that leaves twice the ink
     report `S2 PASS`. That is the brief's "no Japanese pixels survive"
     signal, moved silently.
   - **Same story: RS13.** A page with no matched region is read anyway and
     can be listed as `uncleaned ... (measured on the source scan)` when
     nothing on it was measured. The module docstring says this never
     happens, and no test asserts it.
   - Rests on E-2 (RS17, RS17b, RS17c, RS17w, RS13w).
3. **Three low-impact input guards are unpinned (MT-092).**
   - **TR1.** The loader's `type(...) is` strictness. `True` would load as an
     integer coordinate, index or size.
   - **TR4.** `schema_version` below 1 is accepted.
   - **MA9.** `iou`'s own shape check. The only test uses shapes that numpy
     already refuses with its own `ValueError`.

   None of the three can corrupt a measurement on a well-formed document.
   Each is a stated contract with no test.
4. **One low-impact packaging survivor (MT-093).** FM4: a download that
   raises mid-stream leaves its `.part` behind. The spec bundles only manifest
   paths, so the stray file never ships. It is a gap in a stated contract
   ("after removing its `.part`"), not a correctness risk.
5. **Not filed: SD4.** Dropping `sorted(...)` in `seed.py:80` is equivalent.
   `Project.chapter` pages come from `_SELECT_PAGES ... ORDER BY ordinal`
   (`store/project.py:140`), so the input is already sorted.
6. **Every handoff and GATES mutation claim re-run here held** (E-3). One
   prediction was wrong: MT-023's RED table predicted DV-3 (threshold 0.0)
   would turn 4 recall tests red, and the real figure is 16. The mechanism is
   MT-029's validator refusing every fixture. MT-023's GATES had already
   recorded that correction honestly, so nothing is filed.
7. **Tests named as weaker than they look** (E-4). None is pure theatre, but
   three hold less than their names say.
   - `test_masks_of_different_shapes_are_refused_with_a_value_error` passes
     on numpy's own broadcast error, not on the guard it names.
   - `test_the_residual_threshold_is_a_fraction_strictly_between_zero_and_one`
     is the only absolute assertion on a measured constant, and it admits
     every value from 1e-9 to 0.999.
   - `test_ac4_with_no_matched_region_nothing_is_measured_and_the_worst_is_zero`
     omits the one field (`uncleaned_pages`) its scenario exists to pin.

### E-2: survivors, ranked by production impact

**1. RS17 (MEDIUM): `RESIDUAL_INK_MAX` is unpinned by value.**
`src/mangatl/bench/residual.py:85` (`RESIDUAL_INK_MAX: float = 0.01`).

    bash scripts/mutate.sh src/mangatl/bench/residual.py 's/^RESIDUAL_INK_MAX: float = 0\.01/RESIDUAL_INK_MAX: float = 0.02/' -- uv run pytest -q -x -p no:cacheprovider <W>
    291 passed in 147.52s (0:02:27)

The same mutant at 0.001 and at 0.0205, against
`tests/core/test_bench_residual.py tests/core/test_bench_s2.py`: `61 passed`
both times.

- **Claim, so it could be false.** No bench test fails for any value v of the
  constant with 0 < v <= 0.0205625.
- **Inputs.** Three values were measured: 0.001, 0.02 and 0.0205. The range
  between them is inferred, not swept.
- **Reasoning for the range.**
  - The upper bound comes from AC-5's `skipped >= 10 * v`, with skipped at
    0.205625 on `_s2_world`. That figure is from the `residual.py` docstring
    and MT-023's handoff, not re-measured here.
  - The tight-detector assertion (`fraction > v`, at 0.065) is looser than
    that.
  - The lower bound comes from the clean controls, which score exactly 0.0,
    and from `0.0 < v`.
- **Why it survived.** Every comparison against the constant is relative to
  the constant itself, and the only absolute check is
  `test_the_residual_threshold_is_a_fraction_strictly_between_zero_and_one`
  (`tests/core/test_bench_residual.py:105-107`).
- **What kills it.** MT-091 AC-1: a region whose measured fraction is just
  above 0.01 fails `residual_ok`, and one at exactly 0.01 passes. Both are
  measured through `ink_fraction` on a real luma array, not through a
  constructed report.
- **What would make this unrepresentative.** If the bar is meant to be
  re-tuned on the real benchmark chapter (the docstring says "to revisit when
  the benchmark chapter's real pages are measured"), then pinning 0.01 is
  pinning a provisional number. MT-091 says the test must change *with* the
  constant, deliberately. It does not freeze the value forever.

**2. RS13 (LOW-MEDIUM): a page with no matched region is read and can be
listed as uncleaned.** `src/mangatl/bench/residual.py:161` (`if not matched:`).

    bash scripts/mutate.sh src/mangatl/bench/residual.py 's/^        if not matched:$/        if False:/' -- uv run pytest -q -x -p no:cacheprovider <W>
    291 passed in 143.31s (0:02:23)

- **Why it survived.**
  `test_ac4_with_no_matched_region_nothing_is_measured_and_the_worst_is_zero`
  (`test_bench_residual.py:348`) runs exactly this scenario: no detections,
  `cleaned={}`. It asserts `regions == ()` and `worst == 0.0`, but never
  `uncleaned_pages == ()`. Under the mutant every page is read from its source
  scan and listed.
- **Production effect.** On a chapter where detection found nothing on some
  page, `python -m mangatl.bench` prints
  `uncleaned     page N (measured on the source scan)`, a false statement
  about a measurement that did not happen. The S2 verdict is unchanged.
- **What kills it.** MT-091 AC-2.

**3. TR1 (LOW): the loader's exact-type check can be loosened to
`isinstance`.** `src/mangatl/bench/truth.py:157`.

    bash scripts/mutate.sh src/mangatl/bench/truth.py 's/if type(value) is not kind:/if not isinstance(value, kind):/' -- uv run pytest -q -x -p no:cacheprovider <W>
    291 passed in 144.96s (0:02:24)

- **Why it survived.** `_MALFORMED` (`test_bench_truth.py:700-731`) tests a
  `bool` field given an int (`development-use-as-int`). It never tests an
  `int` field given a `bool`, which is the direction `isinstance` admits,
  because `True` is an `int`. `_get`'s docstring names both.
- **Production effect.** A hand-edited `"width": true` or `[true, 10]` vertex
  loads as 1. The validator then reports a size mismatch rather than
  "malformed", so the refusal survives with the wrong message.
- **What kills it.** MT-092 AC-1.

**4. TR4 (LOW): `schema_version` below 1 is accepted.**
`src/mangatl/bench/truth.py:226`.

    bash scripts/mutate.sh src/mangatl/bench/truth.py 's/if version != TRUTH_SCHEMA_VERSION:/if version > TRUTH_SCHEMA_VERSION:/' -- uv run pytest -q -x -p no:cacheprovider <W>
    291 passed in 161.15s (0:02:41)

- **Why it survived.** Only `schema-version-2` is tested.
- **What kills it.** MT-092 AC-2: version 0 refused.

**5. MA9 (LOW): `iou`'s shape guard can be removed.**
`src/mangatl/bench/matching.py:74`.

    bash scripts/mutate.sh src/mangatl/bench/matching.py 's/if a.shape != b.shape:/if False:/' -- uv run pytest -q -x -p no:cacheprovider <W>
    291 passed in 144.28s (0:02:24)

- **Why it survived.**
  `test_masks_of_different_shapes_are_refused_with_a_value_error`
  (`test_bench_matching.py:174-176`) uses shapes (4, 6) and (6, 4). numpy
  refuses to broadcast those with its own `ValueError`, so the test passes
  with the guard deleted. Its needle (`pytest.raises(ValueError)`, no `match=`)
  cannot tell the two apart.
- **Production effect.** A broadcastable pair, for example a (1, W) mask
  against an (H, W) one, would compute a silent wrong IoU.
  `match_regions` always builds both sides at the page's
  `(height, width)`, so no current path produces such a pair.
- **What kills it.** MT-092 AC-3: a broadcastable pair is refused, with the
  guard's message.

**6. FM4 (LOW): a download that raises mid-stream leaves its `.part`.**
`packaging/fetch_models.py:68`.

    bash scripts/mutate.sh packaging/fetch_models.py 's/^            part.unlink(missing_ok=True)$/            pass/' -- uv run pytest -q -x -p no:cacheprovider tests/core/test_fetch_models.py
    17 passed in 51.11s

- **Why it survived.** Every opener the test file uses completes its stream.
  The `.part` clean-up tests (`test_a_mismatch_leaves_neither_the_file_nor_its_part_behind`,
  `...stale_file...`) exercise the hash-mismatch path at line 72, not the
  exception path at line 68.
- **Production effect.** A stray `packaging/models/**/*.part` after an
  interrupted build fetch. It is reopened `"wb"` on the next run, and
  `packaging/mangatl.spec:30-35` bundles only manifest paths, so it is never
  shipped.
- **What kills it.** MT-093 AC-1.

**Equivalent: SD4.** `src/mangatl/bench/seed.py:80`, `sorted(...)` removed:
`291 passed in 148.25s` on W. `Project.chapter` comes from the store, which
selects pages `ORDER BY ordinal` (`src/mangatl/store/project.py:140`), so the
sort cannot change the output. Not filed.

## What would have to be true for this to be wrong

- That `-x` stopping at the first failure never hid a mutant that only
  *appeared* killed through an unrelated error. Every narrow kill printed
  `1 failed`, and the full-run re-checks in E-3 matched by name, but the
  narrow kills' failing assertion was not inspected one by one.
- That the scratch `results.tsv` verdicts map correctly onto exit codes:
  0 = survived, 1 = killed, 3 = expression changed nothing. Every survivor
  was confirmed by a printed `N passed` line with no failures.
- That the test fixtures (`_s2_world`, `_settled_models`) are deterministic,
  as their stories claim (no RNG, no JPEG, exact rasterisation), so a survivor
  is not a flaky pass.
- That numpy 2.5.3's refusal to broadcast (4, 6) against (6, 4) is what makes
  MA9's test pass. Another numpy could differ, which would change MA9's
  verdict, not the gap.
