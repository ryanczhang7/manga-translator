## Scope

**The question.** If EPIC-04's production code were subtly wrong, would a test
notice? Line coverage is already 100% (the `coverage-core` gate), so every
mutant below runs on covered lines. A survivor is an assertion gap, not an
uncovered line.

**Tooling.** The `mutation` gate is waived: `mutmut` is not installed
(`.claude/harness/project.conf` line 697, `stack.md` §6), so none was used.
Mutants were chosen by hand and applied one at a time with
`bash scripts/mutate.sh FILE 'SED' -- uv run pytest -q -x -p no:cacheprovider <test files>`.
The test files named were the narrowest set that should catch each mutant. A
survivor was rerun against a wider set before being reported (see E-2). The
handoff-table checks ran without `-x`, so the full failure set could be
compared with the prediction.

**Environment.** Windows 11 Home 10.0.26200, Python 3.13.15 (`uv run`),
pytest 8.4.2, SQLite 3.53.1, `anthropic` 0.125.0.

## Decided

1. **EPIC-04's tests discriminate well in general, with one serious exception:
   the budget guard's wiring.** Of 110 distinct mutants, 97 were killed and 13
   survived. Of the 13, 11 are real gaps and 2 are not filed (TR1 is
   equivalent; P8 changes behaviour the spec leaves undefined). Rests on E-1
   and E-2.
2. **The two highest-impact survivors both let a run spend past its ceiling,
   and they are the first thing to fix (MT-082).**
   - **TS8.** `TranslateStage.run` can ignore the observed costs and project
     every page at the $0.06 bootstrap estimate, and all 327 tests touching
     the stage, runner, ledger and UI cost readout stay green.
   - **TS2.** The guard can read this run's spend instead of the chapter's,
     and those same 327 tests stay green.
   - **Why the existing test misses TS8.** The refusal fixture in
     `tests/core/test_budget_run.py:169-184` says page 2's refusal exercises
     the observed basis. It does not: the observed mean (50,000) is *below*
     the estimate (60,000), so the estimate refuses page 2 as well. The test
     cannot tell the two bases apart, which is the opposite of what its
     comment claims.
   - **Why it misses TS2.** Every guard test runs as one run, where run spend
     and chapter spend are the same number.

   Rests on E-2 (TS2w, TS8w) and E-4.
3. **The ledger reader `chapter_call_costs` is unpinned against duplicate
   costs (L2a, also in MT-082).** A `DISTINCT` would collapse two equal-cost
   calls into one sample, so the projection would stay on the estimate basis
   and mis-state the mean. It belongs with TS2 and TS8: all three are the
   guard's inputs.
4. **The user-edit glossary rule (`store/glossary.py::_renamed`) has three
   unpinned clauses (MT-083).**
   - **SG3 (step 3, "the user kept the name").** An edit that swaps two names
     would rename one character's glossary entry to the other's name, and
     every later page would then use the wrong name.
   - **SG9 (the end-of-list match in `_occurrences`).** A rename of a name
     that is the last token of the line is silently missed.
   - **SG2 (step 2, "exactly once").** This clause is masked: its only test
     case also keeps the name, so step 3 decides that case first.

   Rests on E-2 and E-5.
5. **Reading a Claude response has three unpinned claims (MT-084).** This
   path is reachable whenever `ANTHROPIC_API_KEY` is set, but it is not v1's
   default (MT-077 PO-1: v1 is Gemini-only), so it ranks below the two
   clusters above.
   - **CL2.** MT-044 C-5 says the ledger records the model that served the
     call. It is unpinned because the test fake's default model equals
     `prompt.MODEL_ID` and no test overrides it. The Gemini equivalent (GM3)
     is pinned.
   - **P7.** No test puts a non-`thinking`, non-`text` block first.
   - **CL5.** An absent cache-write count's "the zero it means" is never
     exercised.
6. **Two low-impact store survivors are filed together as MT-085, the last
   priority.**
   - **PJ2.** `write_proposed` would file reading index -1 under the last
     bubble. No pipeline path reaches it today, because `parse_lines_text`
     rejects negatives first (P1 is killed).
   - **SC3.** The v3->v4 migration could truncate a REAL ceiling instead of
     rounding it. This errs low by one micro-dollar, the safe direction.
7. **Not filed: TR1 and P8** (reasoning in E-3).
8. **A stale claim in production prose, reported rather than filed.**
   `pages_remaining`'s docstring (`pipeline/translate_stage.py:105-109`, from
   MT-044 C-8) says an off-by-one "changes a number MT-018 displays and
   changes no permit or refusal". Since MT-063 that is no longer true: the
   off-by-one makes the last page's `CallPriced` projection take -1 pages,
   `Usd` refuses a negative amount, and the run aborts on its last page
   (E-6). The tests catch it (11 failures), so this is not a test gap. The
   docstring is now wrong, and correcting it belongs to whoever next touches
   the module.

### E-3: survivors not filed, and why

- **TR1, equivalent in production.** `domain/translation.py:55-56` with the
  `cache_read_tokens` and `cache_write_tokens` fields swapped in declaration
  order (`'55{h;d};56{G}'`). Result: `tests/core/test_translation.py`,
  `14 passed in 0.58s`.
  - **Why it is equivalent.** Every production construction of `TokenUsage` is
    either by keyword (`client.py:112`, `gemini.py:178`) or all zeros
    (`client.py:88`, `gemini.py:141`), found with
    `grep -rn "TokenUsage(" src/`. A positional construction with non-zero
    cache counts would make it observable, and none exists.
  - **The docstring is still right to warn.** Its claim that "the order of the
    fields is part of the type" describes a hazard, not current behaviour.
- **P8, behaviour the spec leaves undefined.** `translate/parse.py:131`,
  `lines[reading_index] = english` changed to
  `lines.setdefault(reading_index, english)`. Result:
  `tests/core/test_translate_parse.py tests/core/test_translate_terms.py`,
  `51 passed in 1.46s`.
  - **When the two differ.** Only when two distinct JSON keys parse to the
    same `int`, for example `"1"` and `"01"`: the shipped code keeps the last,
    the mutant the first. `json.loads` already merges *identical* duplicate
    keys before this line runs.
  - **Why it is not filed.** The response schema's
    `"additionalProperties": false` makes `"01"` a schema violation (PP3 is
    killed). No story says which value should win, so a test would be
    inventing a requirement. If a future story decides the answer, the mutant
    above is the probe.

### E-4: the arithmetic behind the two HIGH survivors

Run against the shipped `domain.budget` with
`uv run python -I <scratchpad>/probe_scen.py`, which imports only
`mangatl.domain.budget` and `mangatl.domain.money`. Output, verbatim:

```
TS8 observed: observed 100000 False
TS8 estimate-only (mutant): estimate 60000 True
TS2 chapter spend (correct): False projected 150000
TS2 run spend 0 (mutant): True then actual chapter spend 140000
```

**a. TS8.**
- **The case.** Ceiling 270,000. Two priced calls of 100,000 each, so the
  spend is 200,000, with one page left.
- **Shipped code.** Observed basis, 100,000, so 300,000 > 270,000 and the
  page is refused.
- **Mutant.** Estimate only, 60,000, so 260,000 <= 270,000 and the page is
  permitted. It then spends 100,000, reaching **300,000 against a 270,000
  ceiling**.

**b. TS2.** This uses `test_budget_run.py`'s existing costs (40,000, 60,000,
40,000) and its 120,000 ceiling.
- **The case.** Run 1 translates pages 0 and 1 and stops (cancelled, for
  example). Run 2 resumes at page 2.
- **Shipped code.** Chapter spend is 100,000 and the observed mean is 50,000,
  so the projected 150,000 > 120,000 and the page is refused.
- **Mutant.** Run 2's own spend is 0, so 50,000 <= 120,000 and the page is
  permitted. The chapter ends at **140,000 against a 120,000 ceiling**.

These are the domain-level decisions only. That the stage reaches them is
what MT-082 must show, at the stage, under each mutant.

### E-6: the `pages_remaining` off-by-one now aborts the last page

MT-044's GATES (PO-6) recorded this mutant as killed by exactly one test,
`1 failed, 640 passed`. It now fails 11:

    bash scripts/mutate.sh src/mangatl/pipeline/translate_stage.py 's/return len(ctx.project.pages()) - ctx.page.ordinal$/return len(ctx.project.pages()) - ctx.page.ordinal - 1/' -- uv run pytest -q -p no:cacheprovider -rf tests/core/test_budget_run.py tests/core/test_call_priced.py tests/core/test_translate_stage.py tests/core/test_pipeline.py
    11 failed, 80 passed in 10.22s

The 11 are 2 in `test_budget_run.py` (including
`test_pages_remaining_counts_this_page_and_every_page_after_it`) and 9 in
`test_call_priced.py`.
`test_the_same_chapter_under_the_default_ceiling_finishes_and_bills_every_page`
fails with `assert 'aborted' == 'finished'`.

The mechanism, checked directly:
`Budget().project((Usd.from_micro(40000), Usd.from_micro(60000)), -1)`
