## Decided

1. **The handoff tables of MT-128, MT-129 and MT-160 hold at `64c0a4b`.** Each
   line re-run here reddened exactly the test the handoff named, for the
   reason it named, although every anchor in `workspace.py` has moved by 90-100
   lines since `12108c9`. No story. *(E-1.)*
2. **The code other epics added to the run-again flow is protected**: the
   two-pass preview (`page_stages`), the postlude built, carried and handed to
   the run, the `UnknownContextMode` refusal, and the default `RunSetup`'s
   `build_postlude`. No story. *(E-2, E-4.)*
3. **A run started on page 1 is unprotected on its return** (N09).
   `_return_from_run` restores the row only `if 0 <= self._run_row < count`,
   and the only test of "the page shown before the run is shown again" starts
   on row 1. `app.open_folder` opens every chapter on row 0 and `load_chapter`
   selects nothing, so this is the ordinary path: open a chapter, press Run
   again. Filed as **MT-161**, tests only. *(E-3.)*
4. **`test_focus_returns_to_run_again_when_the_dialog_closes` does not test the
   line it is named after** (N07). Removing `_on_rerun_dialog_finished`'s
   `self._focus_rerun()` leaves it green; removing the `activateWindow()` two
   lines above reddens it (N08). The reading is that Run again already holds
   the window's focus in that test, and re-activating the window restores it.
   Low production impact: a user who clicks or presses Return on Run again
   gives it focus first. Folded into **MT-161** as AC-2, with an escape clause
   for RED if the mutant proves equivalent. *(E-3, E-5.)*
5. **Three survivors are equivalent or defensive and get no story**: N01, N17,
   N18. Reasons in E-5.
6. **MT-125 DV-1, unverified by the first audit, is now reproduced** with a
   sed expression (V09): 8 tests fail, the 7 GATES recorded plus MT-139's
   two-pass test. *(E-1.)*

### E-5 Why three survivors get no story

- **N01** (`workspace.py:1510`, `setup is None` -> `False`): equivalent in
  production. `rerun_button` is built, and `_rerun` connected to it
  (line 1152), only when the window has a `RunSetup`; `_rerun` is private and
  has no other caller. Read from the code, not measured beyond the 34 green.
- **N17** (`workspace.py:1613`, `_return_from_run`'s `activateWindow()` ->
  `pass`): no dialog closes on this path, so in every test the window is
  already active and the call does nothing observable offscreen. On Windows
  `activateWindow` on a background window flashes rather than takes the
  foreground. Equivalent as far as anything can measure here; the real
  platform plugin was not tried.
- **N18** (`workspace.py:1600`, the `panel is None` half of the guard
  dropped): defensive. `panel` is `None` only on a second `_return_from_run`
  after the first; the Review action's button is hidden synchronously by the
  first, and a finished run calls it once. A queued double emission would
  raise in `removeWidget(None)`; nothing in the code emits one. Reasoned, not
  measured.
