## Decided

1. **The EPIC-02 core is well protected.** I executed 34 distinct mutants: 31
   were killed and 3 survived. None of the 3 survivors can lose data, write a
   wrong row or leave a project that will not open. (Evidence E-1.)
2. **Survivor S1: a directory with a page suffix is never tested.** Deleting
   `entry.is_file() and` from `read_chapter`'s filter (`store/intake.py:68`)
   passes every intake, CLI, project and intake-UI test. The code is correct
   today. A test is owed: a subdirectory named `extra.png` must not become a
   page. Filed as **MT-164 AC-1**. (E-2.)
3. **Survivor S2: the handle release on `SchemaTooNew` is never tested.**
   Deleting `connection.close()` before `raise SchemaTooNew`
   (`store/project.py:744`) passes every test that names `SchemaTooNew`.
   MT-157 pinned the same property for a failed upgrade (its AC-4) but not for
   the refusal. The code is correct today. Filed as **MT-164 AC-2**. (E-3.)
4. **Survivor S3: nothing checks that `refresh_from_source` updates
   `Project.chapter`.** Deleting `self._chapter = _read_chapter(...)`
   (`store/project.py:1403`) passes every refresh, stale and replace test. The
   docstring of the `chapter` property promises this behaviour. Today the only
   production readers of `project.chapter` use `source_dir`, which a refresh
   never changes, so the impact is low. Filed as **MT-164 AC-3**. (E-4.)
5. **Not a mutant, and the most serious finding: the epic's last done-when
   clause is not wired into any entry point.** The clause is "replacing one
   input scan invalidates only that page". `Project.refresh_from_source` has no
   caller anywhere under `src/`. `mangatl-run` reopens an existing project and
   runs it without re-reading the folder. So a replaced scan is never noticed
   through the product, and only the library meets the clause. EPIC-11 already
   lists this as open question Q-3, with "not in MT-125" as its recommended
   default. No story owns it. Filed as **MT-163**, which needs the user's
   answer to Q-3 before it leaves PLANNED. (E-5.)
6. **Theatre: `test_a_second_invocation_skips_the_pages_the_first_one_finished`
   (`tests/core/test_cli.py:505`) cannot see a skip.** With both skip
   predicates in the runner forced false, so that every page is re-processed,
   all 78 tests in `test_cli.py` pass. The runner suites do kill that mutant, so
   the runner is protected. What is not protected is the entry point: a change
   that made the CLI rerun pages (for example, resetting statuses on reopen)
   would pass every CLI test. For EPIC-02 that is the expensive failure, since
   rerunning pages means paying for them again. MT-006's N-9 recorded this and
   declined it as "not a defect". This audit disagrees, because the test's name
   claims a behaviour its assertions do not check. Filed as **MT-165**.
   (E-6.)
7. **The handoff mutation tables of MT-005 and MT-006 hold for every row this
   audit sampled.** MT-064's M1 still kills on today's tree. Two pass-on-arrival
   gaps in MT-157 are now closed (E-7):
   - the `foreign_keys` read in its AC-5 test, which its handoff had said was
     not separately earned;
   - the `type(...) is type(...)` half of its AC-4 test, which is redundant
     with `pytest.raises` and cannot fail on its own.

### E-2. S1: a directory named like a page

- **Claim.** No test notices `read_chapter` accepting a directory whose name
  ends in `.png`, `.jpg` or `.jpeg`.
- **Inputs.** `test_only_recognised_suffixes_become_pages_and_nothing_else_does`
  (`tests/core/test_intake.py:59`) builds its subdirectory as `sub`, with no
  suffix (`test_intake.py:67`). So `entry.suffix.lower() in PAGE_SUFFIXES`
  excludes it whether or not `is_file()` runs. A grep of `tests/` for a
  `mkdir` on a `*.png`/`*.jpg` path found none.
- **Commands and results.**

      === mutate: src/mangatl/store/intake.py (1 line(s) changed by 68s/if entry.is_file() and /if /) ===
      === mutate: running uv run pytest -q -p no:cacheprovider tests/core/test_intake.py tests/core/test_page.py ===
      34 passed in 2.44s
      === mutate: command exited 0; restored (verified byte-for-byte ...) ===

      === mutate: running uv run pytest -q -p no:cacheprovider tests/core/test_cli.py tests/core/test_project.py tests/ui -k intake or folder or chapter ===
      333 passed, 2031 deselected in 50.37s
      === mutate: command exited 0; restored (verified byte-for-byte ...) ===

- **Consequence under the mutant (reasoned, not measured).** The directory name
  enters the page list. `(source_dir / filename).read_bytes()` then raises
  outside the `try` (`IsADirectoryError`, or `PermissionError` on Windows), so
  the CLI and the intake window get an unhandled exception instead of a chapter.
  Impact: the chapter will not load. Nothing is written or lost.
- **Could be unrepresentative if** a test outside the widened selection builds
  such a directory. The `tests/` grep makes that unlikely.

### E-3. S2: the handle on a refused newer file

- **Claim.** No test notices `open_project` leaving its connection open when it
  raises `SchemaTooNew`.
- **Inputs.** `test_opening_a_file_whose_schema_version_is_newer_raises_naming_both_numbers`
  (`tests/core/test_project.py:669`) asserts the type and the two numbers in
  the message. It never renames, deletes or reconnects after the raise. The
  `SchemaTooNew` tests in `test_line_store.py` and `test_schema_v8.py` ..
  `test_schema_v14.py` were in the widened run and do not check the handle
  either.
- **Commands and results.**

      === mutate: src/mangatl/store/project.py (1 line(s) changed by 744s/connection.close()/pass/) ===
      === mutate: running uv run pytest -q -p no:cacheprovider tests/core/test_project.py ===
      35 passed in 6.54s
      === mutate: command exited 0; restored (verified byte-for-byte ...) ===

      === mutate: running uv run pytest -q -p no:cacheprovider tests/core/test_line_store.py tests/core/test_schema_v10.py ... tests/core/test_schema_v9.py tests/ui -k new or newer or too_new or SchemaTooNew ===
      30 passed, 2384 deselected in 11.16s
      === mutate: command exited 0; restored (verified byte-for-byte ...) ===

- **Consequence (reasoned).** The code comment at `project.py:742` gives the
  reason for the close: on Windows the open handle locks a file the user may
  want to move out of the way. MT-157 measured that a caller holding the
  exception keeps the connection alive through the traceback, which is the
  same mechanism. `app.py:164` turns the exception into a message string and
  discards it, so in the GUI the lock probably ends when the exception is
  collected. That was not measured. Impact: low to medium, and Windows only.
- **Could be unrepresentative if** the `-k` filter in the widened run missed a

## What was not checked

- **No full-suite run per survivor.** Each survivor was widened (E-2 to E-4),
  but not to the whole of `tests/core` plus `tests/ui`.
- **Mutants considered and not run.**
  - `found > SCHEMA_VERSION` changed to `>=`: certain kill, because every
    current file would be refused.
  - `found < SCHEMA_VERSION` changed to `<=`: probably equivalent, since it
    runs an empty chain inside a transaction. A cost, not a defect.
  - `except BaseException` changed to `except Exception` in
    `_migrate_to_current`: differs only for `KeyboardInterrupt` and
    `SystemExit`. With DV-2 showing that the rollback is redundant with close,
    and SQLite rolling back an uncommitted transaction on the next open, I
    judged it near-equivalent. No test can cheaply raise `KeyboardInterrupt`
    inside `executescript`.
  - Removing `connection.close()` on the upgrade failure path: MT-157's AC-4
    tests were red against code without the close in that story's RED.
  - `create_project` writing the wrong `user_version`, and dropping `_mark_done`:
    certain kills.
  - H02, `UNIQUE (chapter_id, filename)` dropped: intake cannot produce two
    pages with the same filename, so impact is low.
  - MT-005's "refresh deletes all pages' regions" and "matches by ordinal"
    rows, and MT-006's "transaction held across `stage.run`" and "page marked
    done before its stages finish" rows: multi-assertion predictions, lower
    value per run. Not run.
- **AC-6 of MT-004** (the input folder is never written). There is no plausible
  single-line mutant: the code only reads. The property is pinned by hashing
  the tree before and after, and I did not mutate it.
- **Concurrency.** Two processes on one project, or the GUI and the CLI on one
  folder, were not considered.
- **Platform.** Windows only. The handle-release properties (S2, MT-157 AC-4)
  are Windows-shaped. Linux CI would not show a lock even if the close were
  missing.
- **What a re-run after a replaced scan actually writes today** (E-5). Reasoned
  only. Running it would need a CLI invocation with a stubbed pipeline outside
  the test suite, which I did not do.
- **`cli.py` beyond the EPIC-02 path**, `bake.py` beyond `_write_atomically`
  and the folder replace, and every stage implementation. All are out of scope.
