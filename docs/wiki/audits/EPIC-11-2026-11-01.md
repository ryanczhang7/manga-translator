## Decided

1. **MT-124's `rerun_preview` is protected.** Every mutant of `resume.py`
   was killed, including the money: the estimate's samples, the spent total,
   the inclusive ceiling comparison, the ceiling read-out and DV-1's
   `page_status` shortcut. No story is filed against it. *(Rests on E-1.)*
2. **MT-125's dialog and the `run_setup` wiring in `app.py` are protected**
   apart from two lines that are equivalent in production (D08, D13 below):
   no story. *(E-2, E-4.)*
3. **MT-127's border is protected, and its six passed-on-arrival tests are now
   earned**, one mutation each. *(E-5.)*
4. **The guards that keep "Run again" and "Render pages" from overlapping are
   unprotected** - three survivors in `workspace.py`, one of them reachable by
   an ordinary click (W01: "Run again" stays enabled during a render's bake,
   and only the guard stops a run starting on the same project). Filed as
   **MT-128**. Tests only; the production code is correct. *(E-3.)*
5. **The hand-over's smaller promises are unprotected** - a one-page chapter's
   return sentence, focus parked before the body is hidden, and the old dialog
   released on a second press. Filed as **MT-129**, lower priority than
   MT-128. Tests only. *(E-3.)*
6. **Four survivors are equivalent and get no story**: D08, D13, W21, W22. The
   reasons are in E-6. Two of them make assertions in `test_rerun_dialog.py`
   look stronger than they are (`isDefault()` and `isModal()` hold whether or
   not `rerun_dialog.py` asks for them), which is named here so nobody cites
   those two tests as protecting those two lines.
7. **The handoff tables of all three stories check out** where they were
   re-run (E-7). MT-125 DV-1 was not re-run: its record describes the mutation
   in prose and gives no reproducible expression.

### E-6 Why four survivors are called equivalent

- **D13** (`rerun_dialog.py:81`, `setModal(True)` -> `False`): the tests and
  the workspace both show the dialog with `QDialog.open()`, which Qt documents
  as showing it window-modal regardless. `test_the_dialog_is_modal` therefore
  measures `open()`, not line 81. Equivalent in production as long as the
  dialog is only ever opened with `open()`; *not* equivalent for a caller using
  `show()`. Reasoned from Qt's documented `open()` behaviour; not measured with
  `show()`.
- **D08** (`rerun_dialog.py:107`, `setDefault(True)` -> `False`): a
  `QPushButton` in a `QDialog` is `autoDefault`, and the focused auto-default
  button is the default. Focus starts on the primary (D09 is killed), the
  dialog has no other focusable widget than its two buttons, so Return
  activates the same button either way. `test_the_primary_is_the_default...`
  measures focus, not line 107. Reasoned, not measured beyond the 28 green tests.
- **W21** (`workspace.py:1583`, `and self.run.is_running()` dropped):
  `cancel()` and `wait()` on a finished `RunController` return at once.
- **W22** (`workspace.py:1465`, `_run_outcome = None` not reset): the only
  path back to the body after a start is `_run_ended` (which overwrites it) or
  the panel's Review action, which exists only after the run ended. No reachable
  state reads the stale value. Reasoned from the code; not measured.

## What would have to be true for this to be wrong

- That the narrow test file is the only one that could kill a mutant - every
  kill counts regardless, and every real survivor was re-run against all of
  `tests/ui` except W20.
- That a QDialog opened with `open()` is window-modal and that the focused
  auto-default button is the default (D13, D08 equivalence).
- That `_set_render_loading` is the only thing that changes the Render pages
  button's state during a bake, so Run again really is enabled then (W01's
  reachability). Read from the code at `12108c9`, not observed in a running app.
- That the offscreen Qt platform paints QSS borders as the Windows platform
  does (MT-127 earnings).

## What was not checked

- **No mutation tool.** `mutmut` is absent, so the mutant set is a hand-picked
  76, not an exhaustive operator sweep. Arithmetic in `resume.py` was covered
  thoroughly; `workspace.py` was mutated only on MT-125's surface (about 120 of
  its 1,681 lines), not the whole file.
- **`tests/core` was not run against any `workspace.py` or `rerun_dialog.py`
  survivor** - those modules are UI-only and `tests/core` does not import
  them, but that was not verified by a run.
- **W20 was not re-run against `tests/ui`.**
- **MT-125 DV-1 was not reproduced** (E-7).
- **The real app was not launched.** W01's overlap - a bake and a run on one
  project at once - is argued from the code; what it actually does to the
  output (a half-updated render, a `database is locked`, or nothing) was not
  measured.
- **Equivalence was reasoned, not proven**, for D08, D13, W21, W22.
- **High Contrast under a real system palette, Linux CI, and the frozen
  build** were not tried; everything ran on one Windows machine, offscreen.
- The design docs MT-125 touched (`components.md`, `accessibility.md`) are not
  executable and were not audited.
