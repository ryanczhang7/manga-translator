# Audit: the consolidated WORLD-004…009 field report

**Date:** 2026-09-10, extended 2026-09-11 (`scripts/ci-local.sh`)
**Scope:** the consolidated field report from `fantasy-world-builder` covering six
stories, read against the harness at `6703780` (after PR #12). This round acts on
the material that arrived with WORLD-008 and WORLD-009 - findings **H19**, **H20**,
patterns **K3** (sharpened) and **K6**, the generalisations WORLD-008 added to
**H9** and **H13**, the reverse direction of **K2**, and the four new shapes of
**H1** - plus one defect this audit found on its own, in the story template.
Findings H1-H18 and K1-K5 were applied in earlier rounds (PRs #4, #6, #7, #9,
#10) and were re-verified rather than re-implemented.
**Left out:** nothing in the report was declined. Most of what WORLD-008 and
WORLD-009 hit was **already fixed upstream** - the consuming project is running an
older vendored harness - and those cases are now pinned so they cannot regress.
The one thing this round could not do is make `## Deferred verifications` machine-
checkable beyond "named, and discharged or waived"; see What was not checked.

## Decided

- **Every new H1 shape from WORLD-008 and WORLD-009 was already fixed, and is now
  pinned.** Ten cases were added to `phase-guard.test.sh`, including the kind the
  report calls new: commands that **write nothing at all** under any parse, and
  the same commands asserted in **REVIEW** rather than only RED, because the bogus
  token falls through `paths.conf` to the fallback category and every phase but
  SCAFFOLD freezes that. Two cases pin the opposite direction, which is the part
  worth copying: the easy wrong fix here is a scanner that gives up on any command
  it finds hard, and that silently deletes the protection the guard exists for.
- **A generator is part of the specification, not part of the test strategy**
  (H19). Narrowing its domain is a change to what the criterion claims and needs
  the design clause that excludes the value, the limit recorded in the
  architecture document rather than only beside the generator, and a mutation
  proving the property still fails on a lossy implementation. Loosening a
  comparison is a weakening every time. The two are one line each and look
  identical in a diff, so the distinction is stated in the non-negotiables in
  those words rather than left to be inferred.
- **The law has a third branch, and it is the feature-developer's to take.** "Test
  wrong → RED, code wrong → GREEN" has no slot for *the criterion's domain is
  wider than the design's representable domain*, which is the common case the
  moment a story has both a property test and a serialisation format. It is an
  `## Amendments` conversation, and stopping to say so is correct behaviour rather
  than a failure to deliver.
- **A round-trip criterion must say which stored artifacts the read path
  consumes** (H20). An entry written but not read is a legitimate design and must
  be *declared*, with the invariant that stands in for reading it, in the
  architecture document rather than only in a source comment. A round trip proves
  the application self-consistent, not the file sufficient - and for a format
  whose promise is longevity those come apart exactly where the real dependency
  hides.
- **A deferred verification is a section with teeth, not prose** (K6). Stories get
  `## Deferred verifications`: what it verifies as a falsifiable condition, why the
  phase that wants it cannot run it, **the phase that owns it**, and the pasted
  result or an explicit `WAIVED`. `check-boundaries.sh` refuses a PR whose block
  names no phase, and one that reaches REVIEW with neither. The report is explicit
  that the pattern worked only because an orchestrator had written the promise into
  its own report twice, and that nothing would have noticed if it had not.
- **GATES is the preferred owner, not RED.** Source is writable in GATES, so the
  mutation needs no exemption - and a story that bounces back to RED mid-cycle
  earns its corrected assertions from the *same* experiment. That is strictly
  better than mutating in RED, and it narrows what H14's primitive is load-bearing
  for.
- **A mutation is only as informative as the independence of what observes it**
  (K3, sharpened). A codec that is uniformly wrong round-trips through itself
  perfectly, so a suite verifying a format through its own reader passes against a
  wholly broken encoder. Three mutations rather than one, and one of them a wrong
  **value** rather than a missing field: an omission and a corruption fail
  differently, and a suite that catches the first can be blind to the second.
- **The return to RED is triggered by a class, not by "a test is wrong"** (H9,
  generalised by WORLD-008). The general trigger is **any gate failure whose only
  legal fix is a write the current phase forbids**, and a `format` gate WARNing on
  a test file the story itself added is the everyday instance - GREEN freezes test
  files and so does GATES, so the phase whose stated job is fixing lint failures
  cannot fix that one. Stated in `rules.md`, `quality-gates` triage and
  `/advance-story`.
- **REVIEW → RED is a named sub-case with one extra hazard.** The branch is
  published and CI has run against a commit that is now superseded, so the ordering
  rule from GATES → REVIEW applies **again on the way out**: phase to REVIEW before
  the second commit, or that commit carries `phase: RED` and fails a PR that was
  green ten minutes earlier.
- **A time budget is a function of the workload, not a constant** (H13,
  generalised). `base * Math.max(1, siteCount / 100_000)` preserves each measured
  base, scales with what drives the cost, and is numerically identical at the size
  it was measured against - which is what makes it safe to adopt before any new
  measurement exists. The floor is not decoration: a smaller default must not
  shrink a budget that came from observed CI behaviour.
- **K2 runs in both directions.** An instruction from the orchestrator that names a
  *mechanism* is a claim like any other. A subagent that can cheaply verify one
  should, and should report when it does not hold - the case in the report is a
  PO decision naming a GL call that does not wait on the browser in question,
  which followed literally would have published ~8,000 fps at every input size.
- **The story template's body must never be expanded by the shell.** Found here,
  not in the report: the template was written into an unquoted heredoc, so every
  backtick span in it was command substitution. It is now two heredocs - the
  frontmatter interpolates, the body does not - and a new `new-story` suite pins
  both halves.
- **The Stop hook must not point evidence at a section `gates.sh` rewrites.** Also
  found here: on `RESULT=blocked` the hook told the agent to quote the CI run into
  `## Gate results`, which `gates.sh` overwrites on every run and which the
  non-negotiables reserve to it. It now says `## Notes`, which is what
  `/advance-story` says, and the suite asserts both the presence of `## Notes` and
  the absence of `## Gate results`.

- **`scripts/ci-local.sh` runs the CI sequence locally, and the selftest is what
  keeps it honest.** Added after this round's PR checks could not run at all -
  GitHub refused to start both jobs for an account billing reason, on a private
  repository where Actions minutes are metered. The script is the five commands
  the two workflows run, in order, failing fast as a runner does. The thing that
  makes it trustworthy is not the script: it is
  `.claude/tests/ci-local.test.sh`, which derives the expected step list **from
  the workflow files** and asserts agreement **in both directions** - a step in a
  workflow and not in the script fails, and so does a step in the script that no
  workflow runs. A local script that quietly runs *more* than CI is the subtler
  defect, because a green run then makes a stronger claim than the check it
  stands in for.
- **It is explicitly not a replacement, and the script says so in its own
  header.** It is one machine, so every CI-only failure this harness is built
  around - H4's coverage timeout on runner hardware, H13's GPU teardown, H16's
  BLOCKED gate - reports green here. It runs only when invoked, so it cannot
  cover `boundaries.yml`'s actual purpose: the diff the phase-guard hook never
  saw, from a human commit, another tool or a force-push. And branch protection
  can only require a run GitHub performed. Both `CLAUDE.md` and the script's
  header state all three, because the failure mode of a convenience like this is
  someone reading a green local run as a merged-ready story.

## Evidence

- **All ten new H1 shapes are allowed by this harness today.** Claim: the commands
  in the report's regression cases 19-23, plus WORLD-008's `awk 'FNR>=791'` and
  WORLD-009's `codePointAt(0) > 127` and `=>`-in-a-heredoc shapes, are not blocked
  here. Measured by driving the real hook against a fixture in RED **and in
  REVIEW**: all allowed, before any change was made this round. `mask_shell_quotes`
  (PR #7) and the decline-on-implausible-parse rule (PR #4) had already closed
  them; the consuming project was vendoring an earlier harness. This is the second
  consecutive round where that is the finding, which is itself worth acting on
  downstream.
- **Each of those ten assertions was earned, not assumed.** They passed on arrival,
  which by the first non-negotiable makes them no evidence at all, so three
  mutations were run through `scripts/mutate.sh` against the mechanisms they pin:

  | Mutation | Effect | Result |
  |---|---|---|
  | `maskchar` stops masking inside quoted spans (`lib.sh:127`, `:155`) | quoted `>` is a redirect again | **all 8 ALLOW cases red**, 25 failures total |
  | `path_is_implausible` inverted to decline any token containing an alphanumeric | the permissive scanner - the report's named wrong fix | **both DENY cases red**, 38 failures total |
  | `has_content` always true (`check-boundaries.sh:54`) | the new 3h check fires on an absent section | the "silent when absent" control red |

  Every run restored byte-for-byte, verified by `mutate.sh`'s own `cmp`. The
  second mutation is the one worth keeping: it reproduces the failure mode a naive
  H1 fix would have shipped.
- **The `## Deferred verifications` check was written test-first and watched
  failing.** Four of the five new `boundaries` cases were red before the check
  existed (`boundaries: 17 passed, 4 failed`); the fifth is a negative control
  that could not fail until it did, and was earned by the `has_content` mutation
  above.
- **The story template was silently deleting text, measured.** Claim: `bash
  scripts/new-story.sh T-97 x` prints `scripts/new-story.sh: line 14: model::
  command not found` to stderr, exits 0, and writes a story in which *"An agent
  definition's `model:` field"* has become *"An agent definition's  field"*.
  Reproduced on `main` at `6703780` before the branch was cut, so it is not this
  round's doing. `` `model:` `` was the only backtick span in the body, and it was
  the one naming the mechanism H18 exists for. The new suite asserts stderr is
  empty, that every backtick span in the template survives into the story, and
  that the body's heredoc delimiter is quoted; un-quoting that delimiter through
  `mutate.sh` reproduces all three failures.
- **`ci-local.sh`'s drift detection was verified by breaking it in both
  directions**, through `mutate.sh`: changing the `gates` step to `gates.sh
  --fast` reddened *"the script runs no step CI does not"*, and deleting the
  manifest-audit step reddened *"every workflow step appears in the script"*. One
  failure each, the right one each time, restored byte-for-byte. The fail-fast
  assertion is observable rather than read out of prose: with `selftest.sh`
  stubbed red in a fixture, the test asserts no gate stamp was written, because
  `gates.sh` writes one and a script that carried on would have left it.
- **Every CI step passes on this machine, measured at `023659c`.** `selftest.sh`,
  `gates.sh --list`, `gates.sh --audit`, `gates.sh` and
  `check-boundaries.sh origin/main` with `PR_HEAD_SHA` set as the workflow sets
  it - exit 0, five for five. So PR #13's red checks are the billing refusal and
  nothing else. This is the weakest kind of evidence the harness accepts about

- **The whole suite is green, and larger.** `bash scripts/selftest.sh`: 12 suites,

## What would have to be true for this to be wrong

- That `## Deferred verifications` is worth a machine check at all. The check is
  two greps: a phase name from the phase vocabulary, and either a pasted block or
  the word `WAIVED`. It cannot tell a real mutation log from a fenced paragraph
  saying one happened - the same limit `has_pasted_output` has for `## Regressions`
  and `## Gate probes`, and accepted for the same reason: it separates *here is
  what happened* from *trust me, it happened*.
- That naming GATES as the preferred owner of a deferred control does not
  encourage deferring things RED could have run. The wording says "where you have
  the choice", and the test-developer prompt still asks RED to run what it can and
  to decline in writing what it cannot.
- That `WAIVED` as a keyword is not gamed. A story can satisfy the check by writing
  the word; what it cannot do is leave the block silent, which is the failure mode
  the report describes.
- That the H19 rule reads as permission rather than as a licence. It is written
  around the one case that makes it legitimate - the design cannot represent the
  value - and requires a document, not a comment.
- That splitting the story template into two heredocs is not brittle. It is: a
  future section added *above* the `EOF` that closes the frontmatter would be
  interpolated again. The `new-story` suite is what catches that, by asserting on
  spans rather than on the mechanism alone.

## What was not checked

- **H19, H20, K3's independence point and H13's formula are documentation.** The
  harness has no test runner, no generator and no codec of its own to enforce them
  against; they bite in a project's own gates. What is machine-checked this round
  is `## Deferred verifications`, and only its shape.
- **Nothing verifies that a deferred control was *the* control the story named.**
  `check-boundaries.sh` reads the block, not the mutation. An entry naming three
  mutations and pasting one satisfies it.
- **The `## Deferred verifications` check does not fire before REVIEW.**
  `check-boundaries.sh` runs on a PR, and 3b already requires REVIEW or DONE, so a
  story that abandons an entry at GATES and never opens a PR is unexamined. That is
  the same reach every other check in section 3 has.
- **No story exercised the new section end to end.** The five `boundaries` cases
  are fixtures. The first real consumer will be the first story in a project
  written against this template.
- **The H1 fixes were verified by driving the hook, not by driving a real agent
  session.** The hook's contract is stdin JSON in, decision out, which is what the
  suite exercises; a runner that shapes that JSON differently is out of reach here.
- **`ci-local.sh` was never run with a failing gate against a real toolchain.**
  Fail-fast is exercised with a stubbed `selftest.sh` in a fixture. A gate that
  hangs rather than exits is not handled at all: there is no timeout, because a
  runner's own step timeout is what stands in for one and this script has no
  equivalent.
- **The step list agrees with the workflows; the *environment* does not.** The
  test compares commands, not `runs-on`, not the setup steps a bootstrapped
  project will add to `gates.yml` (`setup-node`, `setup-uv`, a browser install).
  A project whose CI installs a toolchain the developer machine lacks will see
  the two diverge in a way this check cannot see, and that divergence is the
  whole reason the script is documented as not a replacement.
- **No check stops a PR from being merged on a local run alone.** That is a
  branch-protection setting, outside this repository, and the script cannot and
  should not compensate for it.
- **Whether the consuming project's vendored copy will actually pick these up.**
  Two rounds running, findings arrived that were already fixed upstream. That is a
  vendoring-currency problem in the consumer, and nothing in this repository can
  detect it.

## Stories filed

None. Findings from a field report are applied here directly and recorded in this
audit; the harness ships its `docs/backlog/` to consumers, so a story about the
harness would be inherited by every project that installs it.
