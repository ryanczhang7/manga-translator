## Context

**Filed 2026-09-30 by the Lead PO**, the second of three stories that let the
window start a run ([[MT-057]] `## Context` has the split). `components.md` §2
`CostEstimate`: spend should be "observable before it happens as well as
during" - brief feature 8, and the product's defining $2/chapter constraint.
[[MT-018]]'s `CostReadout` is the *during*; this is the *before*.

The arithmetic already exists and is the oracle for any number shown:
`mangatl.domain.budget` - `DEFAULT_CEILING` ($2.00),
`BOOTSTRAP_PAGE_ESTIMATE` ($0.06 a page, from `docs/wiki/cost-model.awk`
design A), and `Budget.project`, whose `basis` is `"estimate"` before any call
is priced. **Read those constants; do not re-derive or tune them.**

**Q1 and Q2 were answered by the user on 2026-09-30** (PO-1, PO-2): the
estimate is the single figure the budget guard itself uses before any call is
priced - `BOOTSTRAP_PAGE_ESTIMATE` × pages, labelled as an estimate - and the
budget is $2.00, read-only. The design's range ("$1.10 – $1.90") and its
`unknown` state are not built here; the Lead Designer is asked to amend §2
(PO-1).

Required gates: `unit`, `coverage`, and `coverage-core` if any arithmetic lands
in `domain`. `required_gates: []`.

## Acceptance criteria

- **AC-1** — Given a chapter summary, when it is shown, then it carries a
  `CostEstimate` that states the budget the run will be held to, "Budget
  $2.00": `DEFAULT_CEILING`, read-only, shown to the cent as the design shows
  it (not `str(Usd)`, which prints four places).
- **AC-2** — Given a summary of N pages, when it is shown, then the estimate
  reads "Estimated for N pages: *$x*." where *$x* is `BOOTSTRAP_PAGE_ESTIMATE`
  × N shown to the cent (`Budget.project` with no priced calls, its
  `remaining_chapter`), and it is labelled as an estimate - never presented as
  a measured cost. (20 pages → $1.20.)
- **AC-3** — Given a summary whose estimate exceeds the budget, when it is
  shown, then the whole estimate block takes its **over-budget** state
  (`color.status.warning`, plus a glyph or wording change - `accessibility.md`
  A-10). ([[MT-059]] owns the Start button and its "Start run anyway" label.)
  *(Control: 33 pages - $1.98, within the inclusive ceiling - shows the normal
  state; 34 pages - $2.04 - shows over-budget. RED reads the boundary from the
  two constants rather than hard-coding it, and asserts both sides.)*
- **AC-4** — Given a folder of more than 200 page images, when its summary is
  shown, then it carries the warning "That is more pages than a chapter.
  Estimated cost is *$x*." with AC-2's figure, and nothing is blocked; given
  exactly 200, no warning.
- **AC-5** — Given any estimate shown, when it renders, then it never reads
  `$0.00` for a chapter of one or more pages (`components.md` §8's rule for
  `CostReadout`, applied here: an unmeasured cost displayed as zero is a lie).

## Notes

### Open questions

None open. Both were answered by the user on 2026-09-30 ("accept all
recommendations"), recorded as PO-1 and PO-2; the questions are kept as put.

- **Q1 — RESOLVED (a), PO-1. What does a first-run estimate say?**
  The design's example is a range ("Estimated for 20 pages: **$1.10 – $1.90**")
  and its `unknown` state is "No estimate yet — the first run of a chapter
  measures it". For a folder with no project those contradict: every chapter
  this screen shows is on its first run. The domain has one number,
  `BOOTSTRAP_PAGE_ESTIMATE` × pages ($1.20 for 20 pages), labelled `estimate`.
  Options: (a) that point estimate, labelled as an estimate, and no `unknown`
  state on this screen; (b) a range, from a rule someone states (e.g. the
  thinking-token sensitivity rows of `docs/wiki/cost-model.awk`) - a new domain function with its own oracle;
  (c) always `unknown` before the first run, which makes AC-2 unreachable.
  **Lead PO recommends (a)**; it is the number the budget guard itself uses
  before any call is priced, so the screen and the guard cannot disagree.
- **Q2 — RESOLVED (a), PO-2. Can the budget be entered here?** The design makes the budget
  a setting and the banner's "Change budget…" an action (`components.md` §8),
  but no setting exists, and the chapter's stored ceiling is `NULL` →
  `DEFAULT_CEILING` for every project created today (`translate_stage` C-10).
  Options: (a) show $2.00, read-only, until a settings story exists; (b) a
  budget field on the summary, stored as the new project's
  `budget_ceiling_micro_usd` by [[MT-059]]; (c) a settings story first.
  **Lead PO recommends (a)** for this story and a separate settings story, since
  MT-018's "Change budget…" needs the same setting.

### PO decisions at PLANNED (2026-09-30)

- **PO-1 — a single-figure estimate: decided by the user, 2026-09-30.**
  `BOOTSTRAP_PAGE_ESTIMATE` × pages via `Budget.project` with no priced calls,
  labelled as an estimate (AC-2); the 33/34-page boundary is AC-3's control.
  The screen and the guard use one number, so they cannot disagree about
  whether a chapter fits. **Design-doc amendment requested of the Lead
  Designer:** `components.md` §2 `CostEstimate` shows a range and an `unknown`
  state for a first run; amend it to the single labelled figure, with the
  designer's wording for AC-2's sentence (AC-2 takes that wording if it lands
  while this story is PLANNED).
- **PO-2 — $2.00, read-only: decided by the user, 2026-09-30.** No budget
  field and no settings store here. A **budget setting** story (which MT-018's
  "Change budget…" also needs) is a reported gap, **not filed**.
