Plus one `bash` for the hook itself, plus the test side's `awk` and a `$( )`

**`.claude/tests/phase-guard.test.sh` drives that 307 times**

### The payoff is collected twice

This hook runs on **every Bash tool call an agent makes**, not only in CI. The
307-fold multiplier in the suite is the visible half; the invisible half is a
tax on every command any agent in this repository runs, all day.

**And it is not a new kind of fix here.** `.claude/hooks/lib.sh:763` already
records the same lesson from the other direction:

> One awk process for any number of paths, because spawning one per rule cost
> whole seconds on Windows.

### The hook fails OPEN, which sets the risk of this story

`classify` is called from `phase-guard.sh:42` under a 15 s `PreToolUse` budget
([[MT-031]] PO-15), and **a hook that times out fails open — the lock silently
off**. So the direction of travel here is safe: fewer processes is more margin.
What is *not* safe is a rewrite that changes a verdict, which is why the 307
existing cases are a frozen corpus (AC-2) and why [[MT-034]]'s blast-radius
instrument is reused (AC-6).

### C-2 The substitutions, and which one is a trap

Sixteen of the 21 `tr` spawns have an exact parameter-expansion equivalent that
works on **bash 3.2**:

| today | replacement | n | bash 3.2? |
|---|---|---:|---|
| `tr -d '[:space:]'` | `${s//[[:space:]]/}` | 7 | yes (pattern substitution, bash 2+) |
| `tr '\134' '/'` | `${s//\\//}` | 5 | yes |
| `tr -d '"'` | `${s//\"/}` | 4 | yes |
| `tr 'A-Z' 'a-z'` (`lower()`) | ~~`${s,,}`~~ | 3 | **NO — bash 4. See AC-3.** |
| 2 others | to be identified from the trace | 2 | RED to determine |

Call sites for the first three, from `grep -n "tr " .claude/hooks/lib.sh`:
`1050, 1053, 1077` (`tr -d '[:space:]'`); `549, 550, 616, 627, 668, 679`
(`tr '\134' '/'`); `234, 267, 691` (`tr -d '"'`). Line `205` is a `tr` with a
**two-argument character map** used for placeholder restoration and line `1097`
is `tr -d '\r'` piped into `awk` — neither is one of the four forms above;
judge each on its own and say so in the handoff.

**`${s//\\//}` needs care and a test.** Backslash is both the thing being
matched and bash's escape character inside a substitution pattern, and getting
it wrong silently produces the input unchanged — which on Windows means
`to_rel` stops normalising `C:\Users\…` and every absolute-path verdict moves.
AC-4's and AC-5's inputs must include a backslash-spelled absolute path.

### C-3 `is_ignored`, batched — and the two spellings are not optional

Today:

```bash
is_ignored() {
  [ -n "${1:-}" ] || return 1
  git -C "$HARNESS_ROOT" check-ignore -q -- "$1"  2>/dev/null && return 0
  git -C "$HARNESS_ROOT" check-ignore -q -- "$1/" 2>/dev/null && return 0
  return 1
}
```

Two git processes per classified path. The batched idiom already in this file
at `lib.sh:880` is `git check-ignore --stdin --verbose --non-matching`, which
takes one path per line and reports a verdict per line, so **both spellings of
every candidate go through one process**.

Constraints:

- **`--non-matching` is what makes the output line up with the input.** Without
  it, non-ignored paths produce no line and the caller cannot tell which answer
  belongs to which path. This is the standard way to get this wrong.
- **A path containing a newline** cannot go through `--stdin` safely. Today's
  per-path form has no such limit. Decide explicitly: either use `-z`
  (NUL-delimited, which `check-ignore` supports) or state in the handoff that
  newline-bearing paths fall back to the per-path call, and add a case for it.
  Do not leave it undecided — a guard that mis-answers on a crafted path is a
  lock bypass.
- **`classify` calls `is_ignored` for ONE path.** The batching win is therefore
  not automatic: it is one process instead of two for a single path (AC-4's
  "at most one"), and one instead of 2N wherever a caller has many. Say in the
  handoff which callers have many, so the claim matches the code.
- **Ordering is frozen** ([[MT-034]] C-3): rules on the bare form → rules on the
  slashed form → `git check-ignore` → `source`. Batching invites hoisting the
  git call to the front. Do not.

### C-4 If `lower()` is eliminated — the optional stretch, with its caveat

`to_rel` lowercases both the path and the root only to do a case-insensitive
prefix comparison. `shopt -s nocasematch` (bash 3.0) makes `[[ "$p" ==
"$root"/* ]]` case-insensitive directly, removing both `lower()` calls and both
`tr` spawns without any bash 4 feature.

**The caveat, and it is why this is optional rather than pinned:**
`nocasematch` is **global shell state** and it also affects `case` statements.
`lib.sh` is *sourced* by twelve files, several of which use `case` for path and
command matching where case-sensitivity is load-bearing. So it must be saved and
restored around the one comparison (`shopt -p nocasematch` captures the restore
command), and `set -e`/early returns must not skip the restore.

If that looks fragile, **leave `lower()` alone.** AC-1's budget of 27 does not
assume this, and three `tr` spawns are not worth a global-state bug in the lock.

## Notes

### PO-1 — The dossier proposes a substitution that would turn the lock off on macOS

Dossier §2b says: *"Every `tr` above is replaceable by bash parameter expansion
with no change in meaning: `tr -d '[:space:]'` is `${s//[[:space:]]/}`,
`tr A-Z a-z` is `${s,,}`, `tr '\134' /` is `${s//\//}`."*

**Two of the three are right. The middle one is wrong, and the repository
already knows it.** `${s,,}` is a bash 4.0 feature. `lib.sh:539` carries a
five-line comment explaining that macOS ships bash 3.2, where it is a "bad
substitution" that kills `to_rel`, after which `check_path` sees an empty path
and **allows the write** — *"the lock silently off on every stock Mac"* — and
`lib.test.sh:351-353` asserts that no shipped script contains it. Verified at
PLANNED: **zero** `${var,,}`/`${var^^}`, zero `declare -A`, zero `mapfile` in
any shipped script. The bash-3.2 target is real and observed, not aspirational.

(The third is also slightly mistyped in the dossier — `${s//\//}` **deletes**
slashes; replacing backslash with slash is `${s//\\//}`. C-2 carries the
corrected form, and C-5 probe 2 is there because getting it wrong fails
silently.)

So AC-3 is a criterion, not a note. The cost is three `tr` spawns that stay:
AC-1's budget is 27 rather than 22 because of it, and that is the right trade.

### PO-2 — Why R-2 and R-3 are one story and not two

The dossier ranks them separately. Merged here because they are one behaviour
measured one way: **the number of external processes one guard invocation
costs**. Same file, same call graph (`classify` → `is_ignored`), same
regression corpus (the 307 cases), same trace harness, same blast-radius
criterion. Split, they would be two stories with the same acceptance-criteria
shape against the same suite, and the second would have to re-baseline against
the first. Full sizing reasoning in [[MT-039]] `## Notes` PO-2.

### PO-3 — This story may run in parallel with MT-040

Neither touches a file the other does, and `depends_on` for both is `[MT-039]`
alone. Both will speed up `gates.test.sh` — `gates.sh` sources `lib.sh` — so
whichever lands second should expect its `before` timing to be better than this
