## Context

**Filed 2026-09-13 out of MT-030's PO-6, by the orchestrator that hit it.**

`CLAUDE.md` says this in as many words:

> If it still blocks a command that writes nothing, that is a bug in the guard:
> add the case to `.claude/tests/phase-guard.test.sh` and fix it there, which is
> the one form of "working around the lock" that is allowed.

This story is that. It is filed rather than fixed in place because a guard fix
belongs in its own change with its own test, not smuggled into a licence spike —
and because the harness's credibility rests on the guard being **precise**, not
merely strict. Every false positive teaches the next agent that the lock is
noise to be retried around, which is exactly the habit law 5 exists to prevent.

**Both symptoms below are false *positives*.** The guard refuses something
harmless; it never permits something it should refuse. So this is a
paper-cut-and-credibility story, not a safety hole, and it should be sized
accordingly.

## The two symptoms, and how much is actually known about each

### Symptom A — prose that *mentions* the in-place editor flag is scanned for paths. Reproducible on demand, and it **hard-blocks**.

**This was characterised by a single-variable A/B while filing this story, after
the guard blocked the commit that files it — twice.** The two commands below are
byte-identical apart from one phrase in the message body, and **both are
`--dry-run`, so neither writes anything at all**:

```
$ git commit --dry-run --allow-empty -F - <<'EOF'
a real in-place edit hard-BLOCKED with its own expression reported as the
EOF
On branch backlog/mt-031-phase-guard-path-resolution      <- ALLOWED

$ git commit --dry-run --allow-empty -F - <<'EOF'
a real sed -i hard-BLOCKED with its own expression reported as the
EOF
BLOCKED by the harness phase lock.
  story:    MT-003
  phase:    RED
  path:     sed -i hard-BLOCKED with its own expression reported as the
  category: source
```
`[MEASURED — 2026-09-13, MT-003 in RED]`

That is the whole bug in six lines, and it is a **ready-made case for
`.claude/tests/phase-guard.test.sh`**: same command, one phrase, opposite
verdicts, nothing written either way. It is also precisely the situation
`CLAUDE.md` names — *"if it still blocks a command that writes nothing, that is
a bug in the guard"*.

**Note the reported `path:`.** It is an English clause, spaces and all,
classified `source`. Whatever the extractor is handing the classifier, it is not
a filename, and the classifier's default for an unrecognised string is the most
restrictive category — which is a sensible default meeting a bad input.

The guard's own decline log carries the same defect firing through the softer
path, from the day before, while MT-030's PO-6 was being written:

```
$ tail -3 .claude/state/phase-guard-declined.log
declined MT-001 in SCAFFOLD: implausible target src/mangatl/$p/__init__.py
declined MT-030 in REVIEW: implausible target sed-i`expressionasthepathargument.Falsepositive,so
declined MT-003 in RED: implausible target /c/.../scratchpad/sib-$
```

The middle line is the guard reading the sentence *"the guard took the `sed -i`
expression as the path argument. False positive, so…"* — a sentence **about**
this bug — and trying to resolve it as a filename. `[MEASURED]`

**So the same defect has two exits**, and a fix must close both: `decline` when
the garbage candidate looks unresolvable, `BLOCK` when it happens to classify.
Only the second stops work.

While writing MT-030's `## Notes` — a **documentation write**, in `docs/`, in a
phase where `docs` is permitted — the guard extracted a candidate path out of the
English sentence being written and declined it:

```
$ tail -3 .claude/state/phase-guard-declined.log
declined MT-001 in SCAFFOLD: implausible target src/mangatl/$p/__init__.py
declined MT-030 in REVIEW: implausible target sed-i`expressionasthepathargument.Falsepositive,so
declined MT-003 in RED: implausible target /c/.../scratchpad/sib-$
```

The middle line is the guard reading the prose *"the guard took the `sed -i`
expression as the path argument. False positive, so…"* — a sentence **about** the
bug — and trying to resolve it as a filename. `[MEASURED]`

The mechanism is `.claude/hooks/phase-guard.sh` line 92:

```bash
printf '%s\n' "$MASKED" | grep -oE '\bsed\b[^|&;()]*-i[^|&;()]*' | awk '{print $NF}'
```

`\bsed\b … -i …` matches inside ordinary text, and `$NF` then takes whatever
word happens to end the run. Nothing distinguishes *a command invoking sed* from
*a sentence containing the word sed*.

Note that the guard **declined rather than blocked** here, which is the designed
behaviour for an unresolvable candidate and is correct. The defect is that the
candidate existed at all.

### Symptom B — a real `sed -i` was hard-BLOCKED with its own expression reported as the path. Observed once; **does not currently reproduce.**

The original, captured verbatim at the time. Target was a throwaway probe script
in the **session scratchpad, outside the repository entirely**:

```
$ sed -i 's|        if a.ndim == 4 and min(a.shape[1], a.shape[3]) <= 8 ...|...|' "$SC"

BLOCKED by the harness phase lock.

  story:    MT-030
  phase:    PLANNED
  path:     s|        if a.ndim == 4 and min
  category: source
```

`[MEASURED — 2026-09-12, MT-030 in PLANNED]`

**Seven attempts to reproduce it on 2026-09-13 all passed.** Recorded so the
next person does not spend the time again:

| # | Variant | Result |
|---|---|---|
| A | `sed -i` with `\|` as the delimiter | allowed |
| B | `\|` delimiter, parentheses inside the expression | allowed |
| C | empty heredoc earlier in the same block, then B | allowed |
| D | the full original expression, including `<=`, `!=` and `>` | allowed |
| E | heredoc opener carrying `2>/dev/null \|\| true`, then D | allowed |
| F | the original command block **verbatim**, `C:/`-style variable and all | allowed |
| G | as F, with a `.py` target rather than `.txt` | allowed |

`[MEASURED — all seven, 2026-09-13]`

**The one environmental difference between the failing run and every passing
replay is the active story and phase**: MT-030 in `PLANNED` then, MT-003 in `RED`
now. That should not matter — `source` is denied in both — so either the
difference is elsewhere and uncontrolled, or the phase interacts with candidate
extraction in a way nobody has documented. **Finding out which is most of this
story's value.**

## Acceptance criteria

- **AC-1** — Given the A/B pair above — two `git commit --dry-run --allow-empty`
  invocations differing only in whether the message body contains the phrase
  `sed -i` — when the guard runs in `RED`, then **both are permitted**, because
  neither writes anything. The `--dry-run` pair is the fixture; it is the
  smallest thing that fails today.
- **AC-1b** — Given a `Write` or `Edit` whose *content* contains `sed -i` in
  ordinary prose (MT-030's PO-6 sentence is the fixture), when the guard runs in
  a phase permitting the target's category, then the write is permitted **and no
  line is appended** to `.claude/state/phase-guard-declined.log`. *This is the
  softer exit of the same defect; AC-1 alone would leave it firing.*
- **AC-2** — Given a `Bash` command that genuinely invokes `sed -i FILE` on a
  path the current phase forbids, when the guard runs, then it is **still
  blocked**, and the reported `path:` is the **file operand**, not any part of
  the `sed` expression. *This is the criterion that stops AC-1 being satisfied by
  deleting the sed heuristic.*
- **AC-3** — Given a `sed -i` whose expression contains `|`, `(`, `)`, `<`, `>`
  or `!` — the characters the current extractor breaks on — when the guard runs,
  then the reported candidate set contains **exactly** the file operand.
- **AC-4** — Given a write whose target lies **outside the repository root**
  (the session scratchpad is the case that prompted this), when the guard runs
  in any phase, then the write is permitted, because no phase of this harness
  governs files that are not in the tree.
- **AC-5** — Symptom B is either **reproduced** — with the trigger named and
  covered by a case in `.claude/tests/phase-guard.test.sh` — or the story
  records, in `## Notes`, that it could not be reproduced beyond the seven
  variants above, with whatever additional variants were tried. **An
  unreproducible bug closed as "fixed" is worse than one closed as "not
  reproduced".**

## Contract

**Files:**

- `.claude/tests/phase-guard.test.sh` — the new cases. `harness`, writable in
  every phase.
- `.claude/hooks/phase-guard.sh` — the fix. Line 92 is the known defect;
  AC-4 may touch the root-relative resolution as well.

**Both are `harness`**, so the phase lock permits them throughout and this story
has no interesting phase geometry. It still runs test-first: **write the failing
case, watch it fail, then fix.** `scripts/selftest.sh` is the runner.

**Do not delete the `sed -i` heuristic to make AC-1 pass.** It is there because
`sed -i` is a real way to write a frozen file, and AC-2 exists to catch exactly
that shortcut. The fix is to distinguish a command from prose — the hook already
receives the tool name, so a `Write`/`Edit` payload need not be scanned for
shell redirect syntax at all, which is likely the whole of Symptom A.

## Out of scope

Any change to what the phases *permit* — `phases.conf` is not this story's.
Any production code. The `implausible target` decline mechanism itself, which is
working as designed; only the fact that it is being handed prose is in scope.

## Notes

**Sizing.** Symptom A is small and now fully characterised: a single-variable
A/B, a ready-made test case, and one heuristic to fix. Symptom B may be nothing
— AC-5 deliberately permits "not reproduced" as an outcome. **Do not let B
expand this story**; if it resists a bounded effort, record the negative result
and close. The seven variants are recorded so that effort starts from a real
baseline rather than from scratch.

**A likely relationship between the two, offered as a hypothesis and not a
finding.** Symptom A shows the extractor pulling a *run of prose* out of text
following the editor's name and its flag. Symptom B's reported path,
`s|        if a.ndim == 4 and min`, is the same shape — a run of characters
beginning right after the flag, terminating where the extractor's character
class breaks. If so, B is A firing on a real command whose *expression* was
scanned instead of its file operand, and fixing A fixes B. **Test that before
assuming it**; the seven passing variants say the trigger is narrower than the
hypothesis predicts, and a story that assumes the two are one bug will close B
without evidence. That is what AC-5 is guarding against.

**How this story was filed, because it is the bug demonstrating itself.** The
guard blocked the commit creating this file, on the strength of the file's own
description of the bug. It was filed from an isolated `git worktree` off
`origin/main` — MT-003 held the shared checkout mid-RED — and committed with the
message in a file rather than a heredoc, which keeps the prose byte-identical
while leaving no `sed -i` on the command line. **That is a workaround for a
false positive, not a route around the lock**: the commit touches three
documentation files, `docs` is writable in RED, and nothing the lock exists to
protect was involved. It is recorded here because the next person to hit this
will reach for the same thing, and because a harness whose agents quietly learn
workarounds is the failure mode law 5 is written against.

**Why EPIC-01.** It is the toolchain-and-gates epic, and MT-001 built this guard.
This story does not change EPIC-01's done-when, which MT-001 and MT-002
discharged.
