## Context

Split out of MT-028 on 2026-10-07 (its PO-1, user-approved). Under a contrast
theme every status hue collapses to `WindowText`, so **the silhouette and the
text are the only carriers of state** (A-15.7). This story asserts that the two
places where colour was doing real work still tell their states apart in one
colour — and fixes the one that does not.

It does **not** depend on MT-028: the assertions are over widget text, glyph
identifiers and meter values, none of which read the contrast mode. That is the
point of A-10 — the carriers exist in every mode — and it is what lets this run
alongside the theme-path story.

Floor: `accessibility.md` **A-15.7**, **A-10**; deltas in `components.md`
§10.4 and §10.6.

**What exists today.** `workspace.STATUS_GLYPHS` already gives `reverted` a
return arrow alone (MT-017 PO-2), so the five gutter glyphs are pairwise
distinct — AC-2 is an assertion over data that already holds. `CostReadout`
shows `GLYPH` (`⚠`) for **both** `approaching` and `exceeded` and **no glyph**
when `aborted` (`cost_readout.py:139,152`), where §10.6 wants an **outline**
triangle for `approaching` and a **filled** one for `exceeded` and `aborted`.
That is the code change this story carries.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage` (`tests/ui/`). `required_gates` stays empty.

## Acceptance criteria

- **AC-1** — Given each of the five `CostReadout` states (`unknown`, `normal`,
  `approaching`, `exceeded`, `aborted`), when it is rendered, then all five are
  told apart by a unique **(figure text, glyph, meter fill)** triple with the
  glyphs of `components.md` §10.6 — none / none / outline triangle / filled
  triangle / filled triangle — and **never by hue**: the triple is unique with
  every colour property removed. *(§10.6, A-15.7. `unknown` still shows `$—`,
  never `$0.00`.)*
- **AC-2** — Given the five translation-row statuses (`proposed`, `accepted`,
  `edited`, `reverted`, `failed`), when each gutter glyph is rendered, then all
  five are pairwise distinct glyph identifiers, `reverted` is the single return
  arrow of `components.md` §10.4, and each row's accessible name names the
  status in words. *(A-15.7, §10.4.)*
- **AC-3** — Given the `final` cost state (after a run, `show_final`), when it
  is rendered, then its triple differs from all five live states too — it is
  the sixth state the widget can show, and a reader must not mistake it for
  `normal`.

`GLYPH` (`⚠`) is retired; `set_state`, `mark_aborted` and `show_final` set the
glyph from `GLYPHS[state]`. `mark_aborted` also sets `projection_label` to
`ABORTED_CAPTION` (replacing any projection), because without it `exceeded`
with no projection and `aborted` show the same figure, the same `of $X` and a
full meter — the same triple (PO-2, user-approved). `figure` and
`budget_label` stay frozen on abort, as today.

`triple()` is defined exactly: `(text, glyph, meter)` where `text` is
`" ".join(t for t in (figure.text(), budget_label.text(), projection_label.text()) if t)`,
`glyph` is `glyph.text()` and `meter` is `meter.value()`. It reads the three
labels and the meter and nothing else — no palette, no stylesheet, no
property — which is what makes "never by hue" a property of the function.
