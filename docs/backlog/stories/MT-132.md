## Context

EPIC-05 owns the theme. `components.md` §10.7 (lines 1363-1364): under High
Contrast `ErrorBanner` is ground `Window`, **2px `WindowText` border all
round** plus the **3px `WindowText` leading bar**, glyph and text
`WindowText`. The base rule (`theme.qss.in` 572-577, `QFrame#error-banner`)
is `border: hairline` + `border-left: emphasis`, both `color.status.danger`,
and its comment (570-571) already records that §9 says 3px and no token holds
3, so the base bar is 2px. `theme_hc.qss.in` has no banner rule, so under HC
the colours collapse to `WindowText` through the token map and the widths
stay **1px all round, 2px on the left** - half the design's frame, and a
leading bar only one pixel wider than the frame it sits in. The Lead
Designer's check (2026-11-02, read-only against origin/main 728c07b) found
it as a sibling of MT-131's dialog gap; the user decided it is its own story.
Like MT-131, this is a rule change (the base has these borders at other
widths, so the override restates widths), which `tokens.md` §12.1 puts in the
append-only `theme_hc.qss.in`. The failing paint test that reproduces the
1px/2px frame is the permanent regression test.

The banner is `ErrorBanner(QFrame)` in `src/mangatl/ui/progress.py:174`,
`setObjectName("error-banner")` at line 189; the selector is
`QFrame#error-banner`, verbatim in the base, so
`tokens.check_override_template` accepts it.

**The 3px question (decided, Notes PO-1).** `tokens.toml` `[border-width]` has
`hairline = 1` and `emphasis = 2` (lines 205-206) and nothing holds 3. The
override template takes widths as token placeholders, so this story adds a
3px token, `border-width.bar = 3` (option (a), user decision 2026-11-02). It
does not hard-code `3px`.

Required gate that fails if the artefact breaks: `unit` (and `coverage`),
which run `tests/ui`; `tests/ui/test_tokens.py` refuses a `theme_hc.qss.tmpl`
or `tokens_gen.py` that does not match its source.

## Acceptance criteria

Paint is measured through the real theme path - the sheet composed for High
Contrast or the packaged `theme.qss`, set as the **application** sheet - never
`styleSheet()` on the widget, which stays `""`. "The HC sheet" is
`theme.compose_stylesheet(base_template(), hc_template(), high_contrast=True,
palette=P)` for a five-role palette `P` whose `WindowText` and `Window` are
each a colour no token's value uses. "Line *n*" of an edge is the line *n*
pixels in from that edge, sampled with `radius.sm + bar` pixels skipped at
each end (the banner keeps its `radius.sm` corners; `bar` is the leading-bar
width, C-1), and "is X" means the colour set along it is exactly `{X}`. The
banner is `ErrorBanner("headline", "body")`, shown alone at 480x160.

- **AC-1** - Given the HC sheet applied and the banner shown alone, when its
  own pixels are grabbed, then on each of the **top, bottom and right** edges
  line 0 and line 1 are `P["WindowText"]` and line 2 is `P["Window"]` (the
  ground; `color.surface.raised` maps to `Window` under HC). Today line 1 is
  `Window`: the 1px frame. A 1px border fails on line 1; a 3px frame fails on
  line 2.
- **AC-2** - Given the same, then on the **left** edge lines 0, 1 and 2 are
  `P["WindowText"]` and line 3 is `P["Window"]`: the 3px leading bar. Today
  line 2 is `Window`: the 2px bar. A bar at `emphasis` fails on line 2.
- **AC-3** - *Control, the non-HC sheet is unchanged:* given the packaged
  `theme.qss` applied and the banner shown alone, then on top, bottom and
  right line 0 is `color.status.danger` and line 1 is `color.surface.raised`;
  on the left lines 0 and 1 are `color.status.danger` and line 2 is
  `color.surface.raised` - exactly the base rule as it is today. The override
  must not leak into the base.
- **AC-4** - Given `docs/wiki/design/theme_hc.qss.in` parsed with the
  generator's own regexes (`tokens._RULE`, `tokens._COMMENT`), then it
  carries exactly one rule whose selector is `QFrame#error-banner`, its
  declarations are `border: @{border-width.emphasis}px solid
  @{hc.WindowText}` and `border-left: @{<bar token>}px solid
  @{hc.WindowText}` where `<bar token>` is the width token C-1 names, and
  no declaration carries a literal pixel number.

### C-1 The rule (`docs/wiki/design/theme_hc.qss.in`)

Appended at the end of the file (after MT-131's dialog rules if they are in
by then; the order between unrelated selectors does not matter), under the
file's header constraints:

```
/* components.md 10.7: the error banner is Window inside a 2px WindowText
   frame with a 3px WindowText leading bar. The base authors these widths as
   hairline and emphasis in the danger colour; the colour already collapses
   to WindowText through the token map, so this restates the widths (MT-132). */
QFrame#error-banner {
    border: @{border-width.emphasis}px solid @{hc.WindowText};
    border-left: @{border-width.bar}px solid @{hc.WindowText};
}
```

- `@{border-width.bar}` is the new token, **option (a), decided** (Notes
  PO-1): GREEN adds `bar = 3` under `[border-width]` in `tokens.toml` and
  regenerates. The options as they were weighed:
  - **(a)** add `bar = 3` under `[border-width]` in `tokens.toml` (the name
    is the designer's; `bar` is a suggestion) - the same 3px the page strip's
    selected bar (§4, components.md 604/750/881) and §9's own `ErrorBanner`
    row ask for, which the base currently rounds down to `emphasis` because
    the token did not exist. `tokens_gen.py` regenerates with the new entry;
    `theme.qss` does not change (the base does not reference it yet - moving
    the base bar to 3px is out of scope). `tests/ui/test_tokens.py` counts:
    `ORPHAN_COUNT` is tokens referenced by neither template, so a token the
    HC template references adds none; RED confirms by running the file.
  - **(b)** rule that the HC bar is `emphasis` and amend §10.7 to say so:
    then the bar is indistinguishable from the frame, which is the design
    question the designer has to answer, not this story. AC-2 would be
    amended through `## Amendments` before RED (the story is still PLANNED,
    so an edit here is a PLANNED edit, not an amendment - but the user
    approves it either way).
  - A literal `3px` in the override is **not** an option: the templates take
    every width from a token (`theme_hc.qss.in` header line 18), and AC-4
    pins "no literal pixel number".
- Both declarations keep `solid` and the colour because `border-left` as a
  shorthand resets style and colour for that side; a width-only
  `border-left-width` would also work and RED may amend to it with the
  reason, keeping AC-4's declaration list in step.
- The selector `QFrame#error-banner` is verbatim at `theme.qss.in:572`.
  `radius.sm` is untouched; the corners stay rounded, which is why the edge
  sampling skips `radius.sm + bar` at each end (AC preamble).
- No `QLabel` child rule: glyph, headline and body colours already resolve
  to `WindowText` through the map (§10.7 "glyph and text `WindowText`" is
  MT-061's territory and holds today). The glyph *shape* difference §10.7
  asks for between error and warning variants is not built because the
  warning variant is not built (`theme.qss.in:569`: "the danger variant, the
  only one built so far") - out of scope.
