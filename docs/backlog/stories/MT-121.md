## Context

The user's first ask: the watermark is left out of translation and cleaning
without anyone clicking. EPIC-10 PO-4: the rule is the one
`docs/wiki/audits/MT-117-class-zero-regions.md` **D-1** decides, implemented
here as a pure function and applied once, in `DetectStage.run`, between
`sort_regions` and `write_regions`, so the regions are stored already
excluded and every consumer (MT-118, MT-119, MT-120) sees them so.

**Written against the predicate `kind == "box"`**, which is what MT-117's
R-1 adopts if its measurement comes out clean. If MT-117 decides a narrower
predicate (R-2), **AC-1's predicate is amended here** under `## Amendments`
with `MT-117 D-1` as the approval before this story leaves PLANNED - the
criteria are not yet frozen. If MT-117 decides **no automatic rule**, this
story is closed as a no-op with the audit cited, and the user removes
watermarks by hand (MT-120).

**Why it depends on MT-120.** An automatic exclusion that the user cannot
see or undo is a silent loss of whatever class 0 turns out to also catch;
the workspace's excluded state and Restore action are the safety net the
rule needs (PO-4). Not a collision, a true ordering.

**The spike's decision is settled; its evidence is not** (`story-authoring`,
"When the story depends on an audit"). This story implements D-1 as stated
and does not re-litigate it. The one number it leans on - that on the real
pages the watermark regions and only they match - is **verified here**, on
the real pages, by the integration test (AC-3), not assumed from the audit's
count. That test needs the GPU and the gitignored pages, which is why
`integration` is binding for this story: without it, `gates.sh` would go green
with the story's central claim unrun (`story-authoring`, "When the evidence
lives in an optional gate").

Required gates: `unit`, `coverage`, `coverage-core` (`domain/**` at 100%),
and `integration` by the frontmatter above.

## Acceptance criteria

- **AC-1** - Given a sequence of `RawRegion`s, when `mark_watermarks` is
  applied, then every region with `kind == "box"` comes back with
  `excluded == "watermark"`, every other region comes back **identical**
  (same object or equal in every field), order and length unchanged; a
  region already `excluded == "user"` with `kind == "box"` keeps `"user"`.
  *(Predicate per MT-117 D-1; amended here if D-1 differs.)*
- **AC-2** - Given a detector that returns one `box` and two `bubble`
  regions, when `DetectStage.run` runs, then the store holds three regions in
  reading order with exactly the `box` one `excluded == "watermark"`, and
  `DetectStage.is_done` is `True`. *Control:* the same stage with a detector
  returning three `bubble` regions stores none excluded.
- **AC-3** - *(integration, `gpu`)* Given the five spike pages, when the real
  detect chain runs through `DetectStage`, then every stored region whose
  crop MT-007 A-4 identified as the watermark (one on `012`, one on `013`,
  two on `015`) is `excluded == "watermark"`, and no region on `011` or
  `014` is excluded. *Control:* the nine OCR-confirmed bubbles of `014.jpg`
  (MT-007 A-4's table) are all `excluded is None`.
- **AC-4** - Given the pipeline run headless on a fixture chapter where the
  detector double returns a `box` region, when the run finishes, then that
  region has a line (OCR ran), `proposed_en` is `NULL`, and the translator
  double was never handed its text (MT-118's behaviour, observed end to end
  through the detect stage's write).

### C-1 The rule

```python
# src/mangatl/domain/exclusion.py
WATERMARK_KINDS: frozenset[str] = frozenset({"box"})   # MT-117 D-1

def mark_watermarks(regions: Sequence[RawRegion]) -> tuple[RawRegion, ...]:
    """Each region whose kind is in WATERMARK_KINDS and whose `excluded` is
    None comes back `excluded="watermark"` (dataclasses.replace); every
    other region is returned as is. Pure; order and length preserved."""
```

`domain` imports nothing of ours outside `domain` (`architecture.md` §3 rule
2) - `RawRegion` is `domain.region`, so this is fine. If D-1 is a narrower
predicate, it replaces `WATERMARK_KINDS` with a function
`is_watermark(region) -> bool` over the fields D-1 names, and this block is
amended with the reason.

### C-2 The stage

`DetectStage.run`: `ordered = mark_watermarks(sort_regions(regions))` before
`write_regions`. Nothing else in the stage changes; `is_done` is unchanged
(regions exist). The `RegionsDetected` event (MT-062) carries the ordered
list as before - excluded regions included, with their flag.

### C-3 Oracle partition

AC-1, AC-2, AC-4 **mechanical**. AC-3 is **settled**: the four watermark
regions and the nine bubbles are MT-007 A-4's measured table, read out, not
re-derived; the test identifies them by the bounding boxes A-4 recorded (or
by IoU ≥ 0.7 with those boxes), never by re-reading the crop.

### C-4 Callers

`sort_regions` and `write_regions` keep their signatures. `mark_watermarks`
is new. No existing export changes.
