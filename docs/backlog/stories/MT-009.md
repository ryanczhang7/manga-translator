## Context

Brief feature 2's second half. `architecture.md` D10 records the scope decision
and what lost: v1 orders by geometry and does **not** segment panels, accepting
that some unusual layouts will be ordered wrongly, because the LLM sees the page
image and can attribute speakers from the art, and the human sees the order on
the review screen.

Reading order matters more than it looks. It is the sequence the translator
receives, so it decides pronoun and speaker attribution; it is the order lines
appear in the review column, so it decides whether the human can read down the
list at all; and it is stable identity for a region across a resume.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core`. Pure function on geometry, 100% coverage bar.

## Acceptance criteria

- **AC-1** — Given regions in a single horizontal band, when ordered, then they
  come out right to left.
- **AC-2** — Given regions in two clearly separated horizontal bands, when
  ordered, then every region in the upper band precedes every region in the
  lower band, regardless of horizontal position.
- **AC-3** — Given two regions whose vertical extents overlap by more than
  `BAND_OVERLAP_FRACTION`, when ordered, then they are treated as the same band
  and ordered right to left relative to each other.
- **AC-4** — Given two regions whose vertical extents overlap by less than
  `BAND_OVERLAP_FRACTION`, when ordered, then the higher one precedes the lower
  one even if it is further left.
- **AC-5** — Given any set of regions, when ordered, then `order_regions` returns
  a list of input indices that is exactly a permutation of `range(len(regions))`
  — every index present once, none repeated, none invented — `sort_regions`
  returns those same regions in that order, and running either twice on the same
  input gives the same result.
  *Assert this on the index list, not on list positions.* "Every `reading_index`
  is assigned once, contiguous from 0" was the planned wording; against a
  function returning a reordered list it is a tautology — any list of length `n`
  occupies positions `0..n-1` whatever the function did. Against the returned
  **index list** it is a real assertion that can fail (PO-1).
- **AC-6** — Given the committed annotated fixture pages, when ordered, then the
  produced order matches the hand-annotated ground-truth order on every page
  annotated `"conventional layout"`, exactly.
  *Control:* a left-to-right ordering must score **0 exact-match pages** on the
  same fixture set — if it does not, the fixtures do not discriminate and the
  criterion is measuring nothing.
  *Second control, and the one that matters more (PO-3):* the first control does
  **not** catch a ground truth that was produced by applying the rule under test,
  which would make AC-6 vacuous while left-to-right still scored 0. See PO-3 in
  `## Notes` for how the annotation earns its independence, and state in the
  handoff how each page's order was arrived at.
- **AC-7** — Given a single region, or zero regions, when ordered, then the
  result is that region alone, or an empty list, with no error.

## Amendments

**Both amendments were made at PLANNED → RED, before the story left PLANNED** —
the one phase in which criteria may change without this section. They are
recorded anyway, because `## Acceptance criteria` now differs from `origin/main`
and a reviewer reading the diff is owed what changed and who approved it.
`check-boundaries.sh` asks for exactly this and was right to.

**A-1 — AC-5, reworded to assert on the returned index list.**
*Was:* "…the result is a permutation of the input, every `reading_index` is
assigned once, contiguous from 0, and running the function twice on the same
input gives the same result."
*Now:* the permutation, contiguity and determinism clauses attach to
`order_regions`'s returned **`list[int]`**, with `sort_regions` required to agree
with it.
*Approved by:* the Lead PO at PLANNED → RED, 2026-09-16 (PO-1).
*Why:* PO-1 removed the `OrderedRegion` type, because `reading_index` is already
owned positionally by `store.project.write_regions`. Against a function that
returns a reordered list, "every index assigned once, contiguous from 0" is a
tautology — a list of length `n` occupies positions `0..n-1` however it was
built — so the criterion as written could not fail. Against the returned index
list it can, and DV-3 later made it fail against a pairwise implementation.

**A-2 — AC-6, pinned to a committed fixture and given a second control.**
*Was:* "Given the annotated fixture pages … matches the hand-annotated
ground-truth order on at least the pages annotated as 'conventional layout'",
with one control (left-to-right scores 0).
*Now:* "the **committed** annotated fixture pages … on **every** page annotated
`conventional`", plus a second control requiring the `unusual` pages to be
ordered *differently* from their annotation.
*Approved by:* the Lead PO at PLANNED → RED (PO-2, PO-3); the `unusual`
definition settled by the **user** at the end of RED (PO-5).
*Why:* three reasons, each in `## Notes`. No annotated fixtures existed (PO-2),
and the only real scans are gitignored and reachable solely through the
`optional` GPU `integration` gate — so the criterion would have been judged by a
gate nothing can block on. "At least the pages" left the scored set unbounded
below, which a set of size zero satisfies; it is now "every". And the original
single control cannot catch a ground truth generated by the rule under test,
which would make AC-6 vacuous while left-to-right still scored 0 (PO-3) — hence
the second control, which DV-3's sibling mutation exercises.

Nothing in AC-1, AC-2, AC-3, AC-4 or AC-7 changed.

## Contract

**RED may amend any block in this section in place, with a reason written into
the block. GREEN builds what the amended block says.**

```
src/mangatl/domain/reading_order.py
    BAND_OVERLAP_FRACTION: float      # settled in GREEN from fixture measurement
    def order_regions(regions: Sequence[RawRegion]) -> list[int]
        # input indices, in reading order; a permutation of range(len(regions))
    def sort_regions(regions: Sequence[RawRegion]) -> list[RawRegion]
        # the same regions, reordered; == [regions[i] for i in order_regions(regions)]
```

**There is no `OrderedRegion` type, and that is PO-1 rather than an omission.**
The story as planned named `assign_reading_indices(...) -> list[OrderedRegion]`.
`OrderedRegion` does not exist in the tree, and `reading_index` already has an
owner: `store.project.write_regions` derives it from each region's **position**
in the sequence handed to it, and its docstring says why — *"Nothing here sorts:
reading order is MT-009's and for Japanese it runs right to left, so a store that
invented one would be inventing the wrong one."* A region carrying its own
`reading_index` field would be a second source of truth for that number, and
`write_regions` would ignore it. So the ordering module hands back a reordered
`list[RawRegion]` — exactly what `write_regions` already consumes — and position
stays the single carrier of reading order, the same positional idiom
`merged_from` already uses.

**Semantics behind each number and each direction — read this before writing a
comparator:**

- **Right to left means descending in x.** Japanese reads right to left, so the
  region whose polygon has the **greatest** x-centre comes **first**. Getting
  this backwards produces a chapter that reads perfectly and is entirely wrong,
  which no type checker will notice.
- **Top to bottom means ascending in y**, with y increasing downward as image
  coordinates conventionally do. The top-left of the page is `(0, 0)`.
- **`BAND_OVERLAP_FRACTION`** is the fraction of the *shorter* region's vertical
  extent that must overlap the other's for the two to count as the same band.
  Using the shorter one is deliberate: a tall region beside a short one should
  band with it when the short one sits inside its span, and a fraction of the
  taller extent would refuse that.
- **Banding is transitive within a sweep, not pairwise.** Three regions where
  A bands with B and B bands with C but A does not band with C belong in one
  band. Implementing the pairwise version produces an order that depends on
  input sequence, which AC-5's determinism clause catches.
- **Ties break on x first, then on the region's index in the input**, so the
  order is total. A non-total comparator is the same latent bug as MT-004's.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1..AC-5, AC-7 | **Mechanical** | Synthetic rectangles you place by hand. Enumerate the boundary at exactly `BAND_OVERLAP_FRACTION`, one pixel either side. AC-5 is a `hypothesis` property (permutation, contiguity, determinism). |
| AC-6 | **Oracle-free** | A **committed, geometry-only fixture** under `fixtures/reading-order/` (PO-2) — *not* the real `.jpg`s, *not* the detector, *not* the GPU. Invent the scoring (exact sequence match per page is the obvious one); both controls in the criterion are mandatory. |

**The AC-6 fixture, pinned (PO-2).** `fixtures/reading-order/*.json`, committed,
one file per page, each carrying: the page's `source` (which scan it was traced
from), a `layout` field that is `"conventional"` or `"unusual"`, a list of region
**bounding boxes** `[x0, y0, x1, y1]` in page pixel coordinates, and a
`reading_order` list of indices into that list. Only `"conventional"` pages are
scored by AC-6; `"unusual"` ones may be present and are excluded by the criterion,
which is what D10's "will be wrong on some unusual panel layouts" means in a test.
Bounding boxes rather than full polygons because the ordering function reads only
vertical extent and x-centre, and a fixture carrying more than the function reads
invites a later story to quietly start reading it.

**Narrowing a `hypothesis` generator is allowed only against a design clause**
(`rules.md`). "Polygons have at least three points and lie within the page" is a
legitimate narrowing tied to MT-007's AC-4. "The test was failing on degenerate
zero-area rectangles" is not — a zero-area region is a real MT-007 output if
`MIN_REGION_AREA_PX` is ever wrong, and the ordering must not crash on it.

### RED's amendments to this Contract, 2026-09-16

Eight gaps, all found by trying to write a test that pins the boundary "one pixel
either side" without knowing the constant. **None changes an exported signature**,
so `## Callers of every changed signature` below is unaffected. GREEN builds what
this says.

- **C-A1 — the boundary is inclusive: the comparison is `>=`.** As planned the
  block said only "must overlap by `BAND_OVERLAP_FRACTION`" and left the side
  open. "Must overlap by f" reads as f being sufficient, and a half-open rule
  with no stated side is what two implementations disagree about in silence. At
  *exactly* the fraction, the two regions band.
- **C-A2 — vertical extent is `[min y, max y]` over the polygon's vertices**, and
  its length is `max y - min y`. The overlap length of two extents is
  `min(maxA, maxB) - max(minA, minB)`. Without this, "one pixel either side of the
  boundary" has no referent and the AC-3/AC-4 tests cannot be written.
- **C-A3 — extents that do not overlap never band**, whatever the fraction is:
  an overlap length of zero or less is not a band, and is *not* clamped to zero
  and then divided. This matters more than it looks — see DV-2 in
  `## Handoff`, where the planned mutation turns on precisely this.
- **C-A4 — a zero-extent region bands with another region when their closed
  vertical extents touch.** A zero-area region is a real MT-007 output if
  `MIN_REGION_AREA_PX` is ever wrong, so this case has to be defined rather than
  divided by. Defining it this way also *buys* something: it makes two distinct
  bands provably unable to share a minimum y-top, which is what makes AC-5's
  input-order independence true rather than merely usually true.
- **C-A5 — bands are emitted in ascending order of the minimum y-top of their
  members.** The planned block pinned the order *within* a band and left the order
  *between* bands unstated.
- **C-A6 — `0 < BAND_OVERLAP_FRACTION < 1`, and it is exactly representable as a
  rational with denominator <= 10 000.** The first half is semantic: 0 bands
  everything and 1 demands total containment, and neither makes "the same band"
  mean anything. The second half is what lets RED pin the boundary to the pixel
  while the value is still unbound — the test recovers the constant as an exact
  `Fraction` and scales the geometry by its denominator. Any decimal a human
  would choose satisfies it; `test_the_band_fraction_is_a_proper_fraction_with_an_exact_rational_form`
  fails loudly if GREEN picks one that does not, rather than silently straddling
  the wrong number.
- **C-A7 — the AC-6 fixture carries two more fields than PO-2 listed**, plus one
  on `unusual` pages only:
  - `page_size`, because AC-6's left-to-right control is implemented by
    *reflecting every box about the page's vertical centre line* and re-running
    the real `order_regions`. Banding reads vertical extent only, which a
    horizontal reflection leaves untouched, so the reflection changes the
    direction of the x comparison and nothing else. That is a control with no
    second implementation to drift from the first — see `tdd-cycle`, "a
    mutation is only as informative as the independence of what observes it".
  - `labels`, the region's text, **for human review only**. PO-3's independence
    claim rests on a reviewer being able to open a scan beside the fixture and
    disagree, and an annotation nobody can check is not evidence.
    `## Out of scope` forbids *using* what a region says, so
    `test_the_fixture_labels_are_review_material_and_never_reach_the_ordering`
    pins that the loader builds regions from `boxes` alone.
  - `layout_reason` on `unusual` pages, naming which pair of regions forces the
    exclusion, so the exclusion is auditable rather than a bare label.
- **C-A8 — `layout` is decided from the panel grid, not from any ordering.** PO-2
  pinned the field and PO-3 described it as "a page whose order is genuinely
  ambiguous from the art". Neither is usable as written, and the gap is
  dangerous: define `unusual` as "the pages where the rule disagrees with the
  annotation" and AC-6 becomes "on the pages where the rule is right, the rule is
  right" — the exact vacuity PO-3 exists to prevent, arriving by the back door.
  The definition used, which is a property of the **art** and mentions no
  x-centre, no band and no overlap:

  > A page is `unusual` when reading it requires knowing where the panel borders
  > are: when two or more panels sit side by side, both contain text, and their
  > text is at different vertical offsets, so that the order a human reads is not
  > the order the regions' own positions imply.

  That is exactly `architecture.md` D10's scope boundary — no panel segmentation
  in v1 — restated as a test for a page. By it, 011 and 013 are `unusual` and
  012, 014 and 015 are `conventional`; note that 014 has a tier of **three**
  side-by-side panels and is still conventional, because all three panels' text
  sits in one horizontal band and no border is needed to read it.

  This definition is still *adjacent* to the algorithm, and that is stated rather
  than hidden. What carries the weight instead is the `unusual` pages themselves:
  they are committed with their true, art-derived order, and
  `test_the_unusual_pages_are_ordered_differently_from_their_annotation` asserts
  the produced order **differs** from it. A ground truth generated by running the
  rule would agree on every page and turn that test red. That is PO-3's second
  control made mechanical, and it is the one the left-to-right control cannot be.

  it; the test compares structurally either way.

   settles which clause wins where, so nothing was decided silently here.

   C-A3's own emphasis survives intact, because it is about *clamping* and not
   about the zero-extent case: with positive extents `overlap / shorter` is never
   clamped, so `F = 0.0` does not band non-overlapping regions - the property
   DV-2's rewrite turns on, and the spot-check above is exactly it.

   **Not escalated.** No amendment is needed: both clauses can be implemented as
   written, and the resolution is the one the frozen test already assumes.
   Recorded here rather than left as a code comment because the next reader of
