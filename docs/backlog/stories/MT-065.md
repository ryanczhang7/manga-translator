## Context

Split out of MT-019 by the user on 2026-10-02 (MT-019 `## Notes` PO-2). MT-019
ships `clean.mask.erase_mask`, `clean.inpaint.clean_page` and
`clean.session.load_inpainter` - correct, tested, and called by nothing. This
story puts cleaning into a run: a `clean` stage that, for each page, erases the
stored regions and keeps the cleaned page in the project so that MT-021's bake
can composite English onto it.

Shape it after the stages that exist: `pipeline.detect_stage.DetectStage`
(MT-035) holds an injected callable rather than a session, because
`mangatl.pipeline` may not import `onnxruntime` (architecture.md §3 rule 5; the
contract is transitive), and `mangatl.compose` is the one place that builds a
session (MT-036). `pipeline.stages.build_stages` is the one stage list.

architecture.md §6: one transaction per page per stage, so a crash costs at most
one page of one stage. §4: `region.mask_blob` is stored precisely so a resume
can clean without re-detecting.

**Which required gate fails if this story's artifact breaks:** `unit` and
`coverage`. The stage, the store and the stage list are all assertable in
`tests/core` with a fake cleaner and no GPU, which is why `required_gates` is
empty. The real-model path is MT-019's AC-6/AC-7.

## Acceptance criteria

- **AC-1** — Given a page with stored regions, when the clean stage runs, then
  the project stores a cleaned image for that page, the size of the source
  page, equal to what the injected cleaner returns for that page's source
  pixels and the erase mask of its stored regions.
- **AC-2** — Given a page with no stored regions, when the clean stage runs,
  then the cleaner is never called and the stored cleaned image is
  pixel-identical to the source page.
- **AC-3** — Given a page whose cleaned image is stored, when `is_done` is
  asked, then it is true; before the stage has run on that page it is false;
  and a resumed run does not call the cleaner for a page that is already done.
- **AC-4** — Given a page with a stored cleaned image, when that page's regions
  are written again (re-detection) or its source scan changes and the project
  is refreshed, then its cleaned image is gone and `is_done` is false. No other
  page's cleaned image is touched.
- **AC-5** — Given a stored cleaned image, when the project is closed and
  reopened, then the same pixels are read back.
- **AC-6** — Given the full stage list, then `clean` comes after `detect`, and
  the composition root builds the clean stage from `load_inpainter` on
  `lama_fp32.onnx` in the models directory - asserted without a GPU, as MT-036
  asserts the other stages.
- **AC-7** — Given `mangatl-run --no-translate` (`build_pipeline(models_dir,
  translate=False)`), when the stage list is built, then it is detect, clean,
  OCR - the clean stage built as AC-6 says - and no `Anthropic` client is
  constructed; without the flag it is detect, clean, OCR, translate. Asserted
  without a GPU. *(Added 2026-10-02 at PLANNED: the `--no-translate` clause is
  the user's decision PO-1, the order is the Lead PO's PO-3; `## Amendments`
  A-1.)*

### C-3 The store API, and invalidation

Three methods on `Project`, beside `write_regions`/`read_regions`:

```python
def write_cleaned(self, page_ordinal: int, image: bytes) -> None
def read_cleaned(self, page_ordinal: int) -> bytes | None
def has_cleaned(self, page_ordinal: int) -> bool
```

- **`write_cleaned`** stores `image` for the page, replacing any previous one,
  in its own `transaction()` (so, like `write_regions`, it refuses a caller
  already holding one). The upsert is
  `INSERT INTO cleaned_page (page_id, image_blob) VALUES (?, ?) ON CONFLICT
  (page_id) DO UPDATE SET image_blob = excluded.image_blob`. It raises
  **`ValueError` naming the ordinal, with nothing written,** if `image` does
  not decode as an image (PIL `Image.open(BytesIO(image))`; header only) or if
  its `(width, height)` is not the page's stored `(width, height)`. That check
  is what gives AC-1's "the size of the source page" a mechanism on the stage
  path: a mis-bound cleaner is refused by name rather than stored.
  `store` may import PIL (`store.intake` already does); no contract changes.
- **`read_cleaned`** returns the stored bytes exactly, or `None` when the page
  has none. Opens no transaction (`read_proposed`'s rule).
- **`has_cleaned`** is `SELECT 1 ... LIMIT 1` - it does **not** read the blob.
  `CleanStage.is_done` calls it, and the runner calls `is_done` twice per page.
- No branch for an ordinal that does not exist (`page_status`'s precedent).

**Invalidation (AC-4), each inside the method's existing `with
self.transaction()` block, never a transaction of its own**, using a module
constant `_DELETE_CLEANED = "DELETE FROM cleaned_page WHERE page_id = ?"`. The
two lines are pinned verbatim, because DV-1 and DV-2 anchor on them:

- in `write_regions`, after the `page_id` lookup:
  `cursor.execute(_DELETE_CLEANED, (page_id,))  # invalidate: re-detection`
- in `refresh_from_source`, beside `DELETE FROM region` for each stale page:
  `cursor.execute(_DELETE_CLEANED, (page_id,))  # invalidate: refresh`

Unconditional in `write_regions`: a re-detection that happens to find the same
regions still invalidates (it cannot know the cleaner would agree), and
`write_regions(n, ())` invalidates too. In `refresh_from_source` it runs for
every stale page, including one whose file is gone and one with no regions.

### C-4 `src/mangatl/clean/page.py` - the cleaner the composition root binds

```python
__all__ = ["clean_page_image"]

def clean_page_image(
    session: InpaintSession, image_bytes: bytes, regions: Sequence[RawRegion]
) -> bytes:
    """One page's encoded image and its regions in, the cleaned page out as PNG bytes."""
```

The pattern is `detect.page.detect_page_regions` and
`ocr.page.transcribe_page_regions`: the session first, so
`partial(clean_page_image, session)` is a `PageCleaner` (C-5), and the decode
belongs to the adapter. Steps, and nothing else:

1. `page = _decoded_page(image_bytes)` - PIL, **`.convert("RGB")`** (MT-035
   R-2: a greyscale scan decodes to mode `L`, and `clean_page` refuses a 2-D
   array), `np.asarray(..., dtype=np.uint8)`.
2. `mask = erase_mask(regions, (width, height))` - MT-019's, unchanged.
3. `cleaned = clean_page(page, mask, session)` - MT-019's, unchanged.
4. Encode `cleaned` as PNG; the save line is pinned as
   `Image.fromarray(cleaned, mode="RGB").save(buffer, format="PNG")` (DV-8
   anchors on `format="PNG"`). PNG, never JPEG: MT-019 AC-4's byte identity
   outside the mask has to survive the encode.

It may be called with no regions (it then returns the page re-encoded without
calling the session, since `clean_page` skips an all-`False` mask), but
`CleanStage` never does so (AC-2). It imports `mangatl.clean.inpaint`,
`mangatl.clean.mask`, `mangatl.clean.session` (for `InpaintSession`),
`mangatl.domain.region`, numpy and PIL; `clean` may import its own siblings.

### C-5 `src/mangatl/pipeline/clean_stage.py` - the stage

```python
__all__ = ["CleanStage", "PageCleaner"]

#: One page's encoded source image and its stored regions in reading order in,
#: the cleaned page as encoded image bytes (PNG) out, the page's own size.
PageCleaner = Callable[[bytes, Sequence[RawRegion]], bytes]

@dataclass
class CleanStage:
    clean: PageCleaner
    name: str = "clean"

    def run(self, ctx: PageContext) -> None:
        regions = ctx.project.read_regions(ctx.page.ordinal)
        image_bytes = (ctx.project.chapter.source_dir / ctx.page.filename).read_bytes()
        cleaned = self.clean(image_bytes, regions) if regions else image_bytes
        ctx.project.write_cleaned(ctx.page.ordinal, cleaned)

    def is_done(self, ctx: PageContext) -> bool:
        return ctx.project.has_cleaned(ctx.page.ordinal)
```

- **Bytes in and bytes out, not arrays**, so `pipeline` stays free of numpy,
  PIL and cv2 like `detect_stage.py` and `ocr_stage.py`, and imports nothing
  under `mangatl.clean` (rule 5 is transitive: `clean.inpaint` reaches
  `onnxruntime` through `clean.session`). Imports: `collections.abc`,
  `dataclasses`, `mangatl.domain.region`, `mangatl.pipeline.stage` - nothing
  else. RED adds an AST tripwire for it in the idiom of
  `test_detect_stage.py`, forbidding `mangatl.clean`, `mangatl.detect`,
  `mangatl.ocr`, `mangatl.compose`, `onnxruntime`, `numpy`, `PIL`, `cv2`.
- The `cleaned = ...` line is pinned verbatim (DV-3 anchors on it).
- **The regions come from the store**, in stored reading order, never from a
  fresh detection - which is what `region.mask_blob` is stored for (§4).
- **The source scan is read, never written** (§5). OCR keeps reading the source
  scan, never the cleaned image - which has had its text erased.
- Not `frozen=True`, for MT-035 R-1's reason (`Stage.name` is an instance
  attribute); no event emitted (the runner's `StageFinished(stage="clean")` is
  the whole of its progress, `## Out of scope`). No transaction opened here:
  `write_cleaned` opens its own and `transaction()` is not reentrant.
- `is_done` is "a cleaned image is stored" and nothing else - it does not
  consult regions, lines or `page.status`.

### C-6 `build_stages` - the order, and `--no-translate`

```python
def build_stages(
    detect: PageDetector,
    clean: PageCleaner,
    transcribe: PageTranscriber,
    translate: PageTranslator | None,
) -> tuple[Stage, ...]:
    stages: tuple[Stage, ...] = (
        DetectStage(detect=detect),
        CleanStage(clean=clean),
        OcrStage(transcribe=transcribe),
    )
    if translate is None:
        return stages
    return (*stages, TranslateStage(translate=translate))
```

- **Order: detect, clean, OCR, translate** (PO-3). Clean needs detect's
  regions; OCR reads the source scan, so clean's position does not change what
  OCR reads; and clean before OCR keeps every local, free stage ahead of the
  paid one and keeps the progress stepper on "Reading" rather than
  "Translating" while a page is cleaned (C-1 (g)).
- **`clean` is required, with no default**, for `translate`'s reason (MT-044
  C-6): a default would give the project a stage list that silently does not
  clean. Positional in stage order; every caller is listed in C-1 (a).
- **`translate=None` still cleans** (PO-1, the user's decision): the
  `--no-translate` list is the first three, which is why it is a prefix of the
  full one and the early return is unchanged. The lines above are pinned
  verbatim (DV-4 and DV-7 anchor on them).
- `__all__` stays `["build_stages"]`.

### C-8 Oracle partition (put this in the RED dispatch verbatim)

No criterion here is oracle-free; nothing needs an invented metric.

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1 | **Mechanical** at the stage; **settled** for the composed cleaner | Stage: the stored bytes **equal** what a fake cleaner returned, and the fake was handed the page's source bytes and `read_regions(ordinal)` exactly. Composed cleaner (`clean_page_image`, C-4): read the oracle out of MT-019 - its PNG, decoded, equals `clean_page(decoded, erase_mask(regions, size), same_fake)` called directly; do not re-derive inpainting. Also, through the PNG round trip, every pixel outside `erase_mask` is byte-identical to the decoded source (MT-019 AC-4 must survive the encode), and a greyscale source works (`.convert("RGB")`). Size: `write_cleaned` refuses a wrong-sized image by `ValueError` naming the ordinal with nothing stored (the negative control for "the size of the source page"). |
| AC-2 | Mechanical | Cleaner call count is **0**, and the stored image decodes to exactly the source's pixels. Use a **JPEG** source page as well as a PNG one (`jpeg_7x3_bytes` in `tests/core/conftest.py`), so "pixel-identical" is not satisfied by accident of format. |
| AC-3 | Mechanical | `is_done` false before, true after, through the stage and through `has_cleaned`. Two `run_chapter` calls over one project with a counting cleaner: the second makes **zero** cleaner calls. ### PO decisions, 2026-10-02 (PLANNED → RED preparation)

**PO-1 — `--no-translate` still cleans. Decided by the user.** Asked what the
flag is for: it is MT-044's opt-out from the paid translation API. Cleaning is
local and free, and the flag is about the API, not the GPU, so
`build_pipeline(models_dir, translate=False)` returns detect, clean and OCR,
still with no API client constructed. Folded in as AC-7 (`## Amendments` A-1).
Consequence accepted with it: a `--no-translate` run now needs
`lama_fp32.onnx` in the models directory and the GPU time to run it, and
`tests/integration/test_pipeline_chapter.py` - the one `--no-translate` run in
the suite - exercises the clean stage end to end (C-10). *Lost:* a
detect-and-OCR-only run, which nothing in the product asked for once
translation had its own opt-out.

**PO-2 — Storage is a schema-v7 table holding the encoded image as a blob.
Lead PO.** Evidence from how the project stores and invalidates today: regions,
lines, translations and the ledger all live in `project.db`; every
invalidation is a `DELETE` inside the writer's own transaction
(`write_regions`, `refresh_from_source`), so "the region changed and the
derived state is gone" is atomic with the change itself; and §6's resume
granularity is one transaction per page per stage. A blob row joins that
discipline for free: `write_cleaned` is one statement in one transaction, the
invalidating `DELETE` sits in the same transaction as the write that makes the
image stale (C-3), and the page row's `ON DELETE CASCADE` covers the rest.
Measured on the five fixture scans (1125×1600): RGB PNG is 1.11-1.91 MB per
page against 0.31-0.53 MB for the JPEG source, so a 20-page chapter adds about
30 MB to `project.db` - well inside SQLite's 1 GB default blob limit. *Lost:*
files under `<input>.mtproj/` - which a user could open in an image viewer and
which keep the database small - because the file and the row then have to be
kept in step across a crash (write-then-rename, plus a row that can say "done"
while the file is missing, or a file nobody's row knows about), and
invalidation stops being a single `DELETE` in the transaction that causes it.
Also lost: the space a deleted blob frees stays in the file until a `VACUUM`,
which nothing runs (out of scope).

**PO-3 — Stage order is detect, clean, OCR, translate. Lead PO; reported
first so the user can overrule.** Detect must precede clean (clean reads its
regions). OCR reads the **source scan**, not the cleaned page, so clean's
position relative to OCR does not change what OCR reads - the choice is made on
three other facts: (a) with clean before OCR, every local and free stage runs
before the paid one, so a local failure on a page (an out-of-memory in the
inpainter) aborts before any money is spent on that page; (b) the
`--no-translate` list stays a prefix of the full list (C-6), so the builder's
early return is unchanged; (c) the progress stepper (C-1 (g), PO-6) shows
"Reading" while the page is cleaned and read, rather than "Translating" while
nothing is being spent. *Lost:* detect, OCR, clean, translate (identical
except that the stepper would say "Translating" during cleaning); and clean
last (the `--no-translate` list would no longer be a prefix, the stepper would
read "Done" while the page was still being cleaned, and a budget refusal would
leave the refused page uncleaned).

**PO-4 — A page with no regions stores its source bytes, verbatim. Lead PO.**
AC-2 forbids calling the cleaner and requires the stored image to be
pixel-identical to the source. The stage cannot re-encode without importing PIL
into `pipeline`, which `detect_stage.py` and `ocr_stage.py` keep out on
purpose, so it stores the scan's own bytes: identical by construction, and
lossless because nothing is re-encoded. Consequence, written into C-2: the
stored image is an encoded image, PNG when cleaned and the source's own format
otherwise. *Lost:* a column that is always PNG - bought either with PIL in
`pipeline` or with a second injected callable that only re-encodes.

**PO-5 — Invalidation is an explicit `DELETE`, not a cascade from `region`.
Lead PO.** The cleaned image belongs to the page and exists for pages with no
regions; a cascade from `region` could not remove it when a page's last region
goes, and `write_regions` upserts rather than deleting, so most re-detections
delete no region row at all. Hence C-3's two pinned lines, inside each method's
existing transaction.

**PO-6 — The progress stepper is not changed. Lead PO; reported to the user.**
`ui/progress.py` is the only code that enumerates stage names, and it ignores a
name it does not know - pinned since MT-018 by a test that uses `"clean"` as its
example. With PO-3's order the stepper reads "Reading" through cleaning. A
"Cleaning" step is a change to `components.md` §8, which is the Lead
Designer's, and is out of scope here.

**PO-7 — One RED→GREEN cycle. Lead PO.** Four source modules change
(`store/schema.py`, `store/project.py`, `pipeline/stages.py`, `compose.py`) and
two are new (`clean/page.py`, `pipeline/clean_stage.py`), each small; `cli.py`
changes only words. The C-1 callers are numerous but mechanical - a fake
cleaner added to five call sites, a version literal changed in seven files,
one name excluded in three comparisons. A split would be by layer (the store
alone has no caller; the stage alone has nowhere to write), which is the split
`story-authoring` warns against. **If RED finds the caller list materially
longer than C-1, it stops and reports rather than absorbing it.**

**PO-8 — `required_gates` stays empty; the integration suite is still run.
Lead PO.** Every criterion is asserted in `tests/core` with fakes (C-8), so
`unit` and `coverage` - both `required`, both covering `src/mangatl/**` - fail
if the artifact breaks; every changed source path is read by them, so
`gates.sh`'s optional-only check cannot trip. But this story changes what the
`integration` suite's one end-to-end run does, so C-10 updates it and DV-8
makes GATES run it and paste the result. Making it required would make every
CI run of this story BLOCKED (no GPU there) for no criterion that needs it.

**PO-9 — Epic done-when check (EPIC-06).** *"A reviewed chapter bakes to a
sibling folder of pages with no surviving Japanese pixels inside any cleaned
region, English centred ..., and nothing outside a detected region touched
anywhere on the page."* After MT-019 and this story: every page of a run has a
stored cleaned image (AC-1, AC-2), it survives resume and reopen (AC-3, AC-5)
and goes when its regions or scan change (AC-4). "Nothing outside a detected
