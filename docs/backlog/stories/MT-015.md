## Context

Brief section 8: "the page is the interface… the art is the largest thing on
screen at all times. Controls are secondary." This story builds the shell that
statement describes; MT-016 builds the interaction inside it.

The layout, sizes and token names are settled in `docs/wiki/design/layout.md`
and `docs/wiki/design/components.md` §3. They are **design decisions, not
suggestions** — read them out.

**Which required gate would fail if this story's artifact broke:** `unit`,
which runs `tests/ui/` under `QT_QPA_PLATFORM=offscreen`. If a criterion here
cannot be asserted headlessly, it is phrased wrongly, not un-testable.

## Acceptance criteria

- **AC-1** — Given a window of 1100 px width, when the workspace is laid out,
  then `PageStrip` is 96 px, `TranslationColumn` is 340 px, and `PageCanvas`
  takes the remaining width, with a 48 px header and a 44 px footer.
- **AC-2** — Given the window is resized from 1100 px to 1900 px wide, when the
  layout settles, then `PageCanvas.width()` has increased by the full 800 px
  delta and `PageStrip.width()` and `TranslationColumn.width()` are unchanged.
- **AC-3** — Given the user drags the translation column divider, when it
  settles, then its width is clamped to the range 280–560 px.
- **AC-4** — Given a window smaller than 1100 × 720 is requested, when it is
  shown, then it is 1100 × 720 — the minimum is enforced, not advisory.
- **AC-5** — Given a chapter with no pages loaded, when the workspace opens,
  then the empty state is shown, not a blank canvas.
- **AC-6** — Given a page whose bytes do not decode, when it is selected, then
  the page-failed state is shown naming the file, and the workspace remains
  usable for other pages.
- **AC-7** — Given the workspace widget sources, when they are scanned, then
  **no colour literal appears in them** — every colour resolves through
  `tokens_gen` or `theme.qss`.
- **AC-8** — Given a loaded page, when the canvas is zoomed and panned, then the
  page pixmap is drawn with a 1 px `color.canvas.page-edge` outline on a
  `color.canvas.surround` mat, and zoom is clamped to the range the design
  specifies.

**Geometry semantics (AC-1, AC-2).** The splitter has two handles between its
three widgets. "The remaining width" is measured, not assumed:
`page_canvas.width() == splitter.width() - page_strip.width() -
translation_column.width() - 2 * splitter.handleWidth()`. AC-2 is asserted as a
**delta**: `canvas_after - canvas_before == 800`, and strip and column widths
equal before and after. Widths are read after `window.show()` and
`qtbot.waitExposed`/`processEvents`, with the window sized by `resize()`.

**AC-3 (clamp).** Drag = `splitter.moveSplitter(pos, 2)`. The clamp is asserted at
**both** ends, each exactly on the boundary: dragged far right → 280, dragged far
left → 560. **The 560 end must be tested at a wide window (1900 px):** at 1100
the canvas's `minimumWidth` 520 plus the strip leaves room for at most ~484, so
a test at 1100 would measure the canvas floor, not the column clamp.

**AC-4.** `resize(800, 600)` (or any size below 1100 × 720), `show()`, then
`size() == QSize(1100, 720)` and `minimumSize() == QSize(1100, 720)`.

**AC-5.** `Workspace()` with no `load_chapter` → `page_canvas.state() == EMPTY`,
`message` visible, `page_item is None`. Also: a chapter whose project holds zero
pages, if `create_project` accepts one, gives EMPTY too.

**AC-6.** A real project built with `create_project` over a `tmp_path` holding
one genuine PNG (written with `QImage.save`) and one file of junk bytes named
`*.png`. Select the junk page **through `page_strip.setCurrentRow`** → FAILED,
message names the file. Then select the good page → LOADED with a non-null
pixmap. "Usable" means exactly that recovery.

**AC-7 — the scanner.** Scan every `*.py` under `src/mangatl/ui/` **except**
`tokens_gen.py` and `tokens.py` (the generated artefact and its generator). The
scan must find `workspace.py` and `canvas.py` among its inputs, or it fails —
an empty scan is vacuous. Forbidden, with an allowlist of **zero** entries:
a hex colour `#` followed by 3, 4, 6 or 8 hex digits; `QColor(` whose first
argument is a literal (a quote or a digit) — `QColor(tokens_gen.X)` is allowed;
`QColor.fromRgb`/`fromRgbF`/`fromHsv`/`fromHsl`; `rgb(`/`rgba(`; and
`Qt.GlobalColor` / `Qt.<named colour>` (`black`, `white`, `red`, `green`,
`blue`, `gray`, `transparent`, …). The scanner is a function in the test file
with its own negative control: fed a string containing each forbidden form, it
reports each one.

*[RED amendment, 2026-09-29: the forbidden set is **widened**, never narrowed -

## Design notes

*Lifted from `docs/wiki/design/README.md`:*

> The workspace is three regions in visual order — `PageStrip` (96px fixed),
> `PageCanvas` (all remaining width), `TranslationColumn` (340px, resizable
> 280–560) — plus a 48px header and a 44px footer. The canvas carries the entire
> splitter stretch factor so that enlarging the window enlarges only the art.
> Ground is `color.surface.base`; the canvas mat is `color.canvas.surround` with
> a 1px `color.canvas.frame` line where it meets chrome and a 1px
> `color.canvas.page-edge` outline round the page pixmap. Minimum window size
> 1100 × 720, enforced. States to cover: empty (no chapter), loading page,
> loaded, page-failed-to-decode. Theme values come from the generated artefacts,
> never from literals in the widget code. See layout.md and components.md §3.
>
> **Assertable:** resizing the window from 1100 to 1900 px increases
> `PageCanvas.width()` by the full delta while `PageStrip.width()` and
> `TranslationColumn.width()` are unchanged. Also: no colour literal appears in
> the workspace widget source — every colour resolves through `tokens_gen`.

Accessibility floor: `docs/wiki/design/accessibility.md`, clauses A-01 through
A-05 (contrast, focus visibility, minimum target size) apply to every control
this story adds.

### Export shape the tests pin (fact, not suggestion)

`mangatl.ui.workspace` exports: `STRIP_WIDTH`, `COLUMN_DEFAULT_WIDTH`,
`COLUMN_MIN_WIDTH`, `COLUMN_MAX_WIDTH`, `CANVAS_MIN_WIDTH`, `HEADER_HEIGHT`,
`FOOTER_HEIGHT` (ints), and the classes `PageStrip` (a `QListWidget`),
`TranslationColumn` and `Workspace` (a `QMainWindow`). `Workspace()` takes no
args and has the class attribute `MIN_SIZE == (1100, 720)`. Its instance
attributes are `header`, `footer`, `splitter` (a horizontal `QSplitter`),
`page_strip`, `page_canvas` and `translation_column`, and its methods are
`load_chapter(project: Project)` and `show_page(ordinal: int)`.
`splitter.widget(0/1/2)` is `page_strip`, then `page_canvas`, then
`translation_column`. The stretch is read as `widget.sizePolicy().horizontalStretch()`:
strip 0, canvas > 0, column 0. That is what `setStretchFactor` writes. The
tests drag with `splitter.moveSplitter(pos, 2)`. The PageStrip item texts are
the filenames in ordinal order, and `page_strip.setCurrentRow(n)` must end in
`show_page(n)`.

`mangatl.ui.canvas` exports `EMPTY`, `LOADED`, `FAILED` (compared only against
themselves, never by string value; they must be three distinct values), `EMPTY_TITLE == "No chapter loaded"`,
`EMPTY_ACTION == "Open a folder"`, `FAILED_MESSAGE` (the exact components.md
string), and `PageCanvas` (a `QGraphicsView`, constructible with no args). The
class attributes are `ZOOM_MIN == 0.10` and `ZOOM_MAX == 8.0`. The methods are
`state()`, `set_page(pixmap, error=None)`, `zoom()` and `set_zoom(f)`, and the
attributes are `message` (a `QLabel`-like object with `text()`,
`accessibleName()` and `isVisible()`), `page_item` (has `pixmap()` and
`sceneBoundingRect()`) and `page_edge_item` (has `pen()`, `rect()` and
`mapRectToScene`). Zoom is compared with `abs=1e-9`. That tolerance is a
float-readback slack on a ratio, not a loosened layout number.

**Not constrained, GREEN's choice:** how `message` is placed (overlay, layout
or scene item), provided it is visible in EMPTY/FAILED and hidden in LOADED;
the exact message text beyond containing the pinned strings; whether
`load_chapter` auto-selects a row; the `handleWidth`; header/footer content;
the decode mechanism (`QPixmap(path)` / `QImage`), provided it is synchronous.
