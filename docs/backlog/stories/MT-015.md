## Context

Brief section 8: "the page is the interface… the art is the largest thing on
screen at all times. Controls are secondary." This story builds the shell that
statement describes; MT-016 builds the interaction inside it.

The layout, sizes and token names are settled in `docs/wiki/design/layout.md`
and `docs/wiki/design/components.md` §3. They are **design decisions, not
suggestions** — read them out.

**Which required gate would fail if this story's artifact broke:** `unit`,
which runs `tests/ui/` under `QT_QPA_PLATFORM=offscreen`. If a criterion here
cannot be asserted headlessly, it is phrased wrongly, not un-testable.

## Acceptance criteria

- **AC-1** — Given a window of 1100 px width, when the workspace is laid out,
  then `PageStrip` is 96 px, `TranslationColumn` is 340 px, and `PageCanvas`
  takes the remaining width, with a 48 px header and a 44 px footer.
- **AC-2** — Given the window is resized from 1100 px to 1900 px wide, when the
  layout settles, then `PageCanvas.width()` has increased by the full 800 px
  delta and `PageStrip.width()` and `TranslationColumn.width()` are unchanged.
- **AC-3** — Given the user drags the translation column divider, when it
  settles, then its width is clamped to the range 280–560 px.
- **AC-4** — Given a window smaller than 1100 × 720 is requested, when it is
  shown, then it is 1100 × 720 — the minimum is enforced, not advisory.
- **AC-5** — Given a chapter with no pages loaded, when the workspace opens,
  then the empty state is shown, not a blank canvas.
- **AC-6** — Given a page whose bytes do not decode, when it is selected, then
  the page-failed state is shown naming the file, and the workspace remains
  usable for other pages.
- **AC-7** — Given the workspace widget sources, when they are scanned, then
  **no colour literal appears in them** — every colour resolves through
  `tokens_gen` or `theme.qss`.
- **AC-8** — Given a loaded page, when the canvas is zoomed and panned, then the
  page pixmap is drawn with a 1 px `color.canvas.page-edge` outline on a
  `color.canvas.surround` mat, and zoom is clamped to the range the design
  specifies.

## Contract

```
src/mangatl/ui/workspace.py
    class Workspace(QMainWindow):
        MIN_SIZE: tuple[int, int] = (1100, 720)
        page_strip: PageStrip                 # fixed 96
        page_canvas: PageCanvas               # stretch 1, all remaining width
        translation_column: TranslationColumn # 340 default, clamp 280..560
        def load_chapter(self, project: Project) -> None
        def show_page(self, ordinal: int) -> None

src/mangatl/ui/canvas.py
    class PageCanvas(QGraphicsView):
        ZOOM_MIN: float
        ZOOM_MAX: float
        def set_page(self, pixmap: QPixmap | None, error: str | None = None) -> None
```

**Rules that are settled and must be read out, not re-derived:**

- **The canvas carries the entire splitter stretch factor.** AC-2 is the
  assertion of the brief's "the art is the largest thing on screen at all
  times": enlarging the window must enlarge only the art.
- **Ground is `color.surface.base`; the canvas mat is `color.canvas.surround`**,
  which is *lighter* than the chrome. That inverts the Photoshop convention
  deliberately — the designer's reasoning is simultaneous contrast, and the
  losing option is recorded in `docs/wiki/design/tokens.md` §4. It is not a bug
  to be tidied up.
- **AC-7 is enforceable and should be enforced by a test**, not by review: scan
  the `ui` source for hex-colour and `QColor(` literals. It is the only thing
  that keeps MT-025's generator load-bearing once the first deadline arrives.
- **States to cover:** empty (no chapter), loading page, loaded, page-failed.
  All four are in `docs/wiki/design/components.md` §3 with their tokens.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1..AC-4, AC-8 | **Settled** | The numbers are in `docs/wiki/design/layout.md`. **Read them out. Do not derive, tune or "calibrate" them.** |
| AC-5, AC-6 | **Mechanical** | State transitions; assert the widget shown and its accessible name. |
| AC-7 | **Mechanical** | A source scan with an explicit allowlist of zero entries. |

Nothing here is oracle-free. A RED phase that invents a layout has discarded the
design.

## Design notes

*Lifted from `docs/wiki/design/README.md`:*

> The workspace is three regions in visual order — `PageStrip` (96px fixed),
> `PageCanvas` (all remaining width), `TranslationColumn` (340px, resizable
> 280–560) — plus a 48px header and a 44px footer. The canvas carries the entire
> splitter stretch factor so that enlarging the window enlarges only the art.
> Ground is `color.surface.base`; the canvas mat is `color.canvas.surround` with
> a 1px `color.canvas.frame` line where it meets chrome and a 1px
> `color.canvas.page-edge` outline round the page pixmap. Minimum window size
> 1100 × 720, enforced. States to cover: empty (no chapter), loading page,
> loaded, page-failed-to-decode. Theme values come from the generated artefacts,
> never from literals in the widget code. See layout.md and components.md §3.
>
> **Assertable:** resizing the window from 1100 to 1900 px increases
> `PageCanvas.width()` by the full delta while `PageStrip.width()` and
> `TranslationColumn.width()` are unchanged. Also: no colour literal appears in
> the workspace widget source — every colour resolves through `tokens_gen`.

Accessibility floor: `docs/wiki/design/accessibility.md`, clauses A-01 through
A-05 (contrast, focus visibility, minimum target size) apply to every control
this story adds.

## Deferred verifications

- *Falsifiable condition 1:* with the stretch factor moved from `PageCanvas` to
  `TranslationColumn`, AC-2 **must** fail.
- *Falsifiable condition 2:* with one hex literal reintroduced into the
  workspace source, AC-7 **must** fail. (This one is cheap and is the one most
  likely to have been written as a comment.)
- *Falsifiable condition 3:* with `MIN_SIZE` set to `(0, 0)` — a wrong value,
  not a removed behaviour — AC-4 **must** fail.
- **Owner: GATES.** Three mutations via `bash scripts/mutate.sh`.

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition: mostly settled.** This is the important half of the brief
  — the dispatch prompt must say that `docs/wiki/design/layout.md` holds the
  numbers and they are to be *read out*. The measured finding in
  `story-authoring` is that a Test Developer told "you have no oracle, design
  the metric" across all criteria will re-derive values a design decision
  already fixed. That is the exact risk here.
- **Success condition, falsifiable:** every number asserted in RED matches
  `layout.md` exactly, and AC-2 is asserted as a delta rather than as absolute
  widths. If any layout number in the test file differs from the design
  document, the phase failed regardless of whether the tests pass.
- **Verdict:** *to be recorded.*
