## Context

Filed 2026-10-14 when MT-048 was narrowed (MT-048 PO-1, the user's decision).
`components.md` §`PageStrip` says each strip item "carries its index and a
status glyph" from a seven-row table (pending, running, translated-none-reviewed,
partly reviewed, fully reviewed, has a failed line, skipped) with an accessible
name `"Page 7 of 20, filename, 12 of 18 lines reviewed"`. `layout.md`'s 1440 px
breakpoint says the 28 px rail "still carries every status glyph, which is what
A-10 requires of it". None of this exists: after MT-048 the strip shows the index
(rail) or the filename (full) and `AccessibleTextRole` is `Page N of M, filename`.

The store knows `page.status` (`PAGE_PENDING`, `PAGE_STALE`, `PAGE_DONE`,
`store/project.py:665`) and each line's `status` (`domain/line.py`
`LineStatus`). The seven page statuses are a **derivation** over those, and that
derivation is this story's domain rule.

**Pinned at PLANNED → RED on 2026-10-21** against `components.md` §`PageStrip`
as amended by PO-1 (the user approved all four decisions PO-1..PO-4 below).

## Acceptance criteria

- **AC-1** — Given a strip whose pages are in each of the seven states the
  table names, when the window is **1900 px** wide and when it is **1100 px**
  wide, then each item shows that row's glyph (the exact code point in
  `PAGE_STATUS_GLYPHS`), its glyph carries that row's colour token
  (`PAGE_STATUS_COLOR_TOKENS`), and the seven glyphs are **pairwise distinct
  code points** (A-15.7, PO-1). At 1100 px the rail row still shows the glyph
  and the index, and the row's `sizeHint().width()` is at most
  `STRIP_RAIL_WIDTH` (28).
- **AC-2** — Given a `done` page with 18 regions whose lines are 12 committed
  (a mix of `accepted`, `edited` and `reverted`) and 6 `proposed`, when its
  item is read, then its accessible name is exactly
  `Page N of M, <filename>, 12 of 18 lines reviewed`. Every other status
  carries its PO-4 phrase (block 3), exactly.
- **AC-3** — Given the glyph colours, when the widget sources are scanned, then
  every colour resolves through a token — `PAGE_STATUS_COLOR_TOKENS` is exactly
  the six-token table of block 2, every value is a key of `tokens_gen.TOKENS`,
  the generated `theme.qss` carries one `QLabel#pageGlyph[status="…"]` rule per
  status whose colour is that token's value — and no literal appears (MT-015
  AC-7's scanner covers `workspace.py`).
- **AC-4** — Given the current page's line status changes in the column
  (accept, edit, revert), when the change commits, then the current page's
  glyph and accessible name update to the new derivation without reloading the
  chapter (`Workspace.load_chapter` is not called again).

**Block 1 — the domain rule** (`src/mangatl/domain/page_status.py`, new; the
domain imports nothing of ours but `domain.line`, and nothing of Qt or the
store — import-linter's "domain is independent"):

```python
PageStatus = Literal[
    "pending", "running", "translated", "partly_reviewed",
    "fully_reviewed", "failed", "skipped",
]
PAGE_STATUSES: tuple[PageStatus, ...]   # the seven, in the design table's order

@dataclass(frozen=True)
class PageProgress:
    status: PageStatus
    reviewed: int   # lines whose status is in COMMITTED_STATUSES
    total: int      # len(lines)
    failed: int     # lines whose status == "failed"

def page_progress(
    lines: Sequence[LineStatus | None],
    *,
    page_done: bool,
    stale: bool = False,
    running: bool = False,
) -> PageProgress
```

Rules, **in this order, first match wins** (the counts are computed for every
call, whatever the status): `running` → `running`; `stale` → `skipped`;
`not page_done` → `pending`; `failed > 0` → `failed`; `reviewed == 0` →
`translated` (this includes `total == 0`, PO-3); `reviewed < total` →
`partly_reviewed`; else `fully_reviewed`. A `None` entry is a region with no
line row: it counts in `total` and is neither reviewed nor failed. `reviewed`
reads `COMMITTED_STATUSES` from `domain.line` (`accepted`, `edited`,
`reverted`; PO-2). Pure, total over its inputs, raises nothing.

**Block 2 — the strip's tables** (`src/mangatl/ui/workspace.py`, all in
`__all__`):

```python
PAGE_STATUS_GLYPHS: dict[PageStatus, str] = {
    "pending":         "\N{WHITE CIRCLE}",                                  # ○ U+25CB
    "running":         "\N{CIRCLE WITH LEFT HALF BLACK}",                   # ◐ U+25D0
    "translated":      "\N{WHITE DIAMOND}",                                 # ◇ U+25C7
    "partly_reviewed": "\N{WHITE DIAMOND CONTAINING BLACK SMALL DIAMOND}",  # ◈ U+25C8
    "fully_reviewed":  "\N{BLACK DIAMOND}",                                 # ◆ U+25C6
    "failed":          "\N{WARNING SIGN}",                                  # ⚠ U+26A0, the gutter's
    "skipped":         "\N{BLACK RECTANGLE}",                               # ▬ U+25AC
}
PAGE_STATUS_COLOR_TOKENS: dict[PageStatus, str] = {
    "pending": "color.text.muted",
    "running": "color.accent.base",
    "translated": "color.text.secondary",
    "partly_reviewed": "color.status.success",
    "fully_reviewed": "color.status.success",
    "failed": "color.status.danger",
    "skipped": "color.text.disabled",
}
```

Both keyed in `PAGE_STATUSES` order. The seven glyphs are pairwise distinct
code points (AC-1's distinctness is **mechanical**: code points, not rendered
pixels — the suite runs on `QT_QPA_PLATFORM=offscreen` and on Linux CI, where
the app font is absent, so a rendered-mask comparison would be measuring the
fallback font; MT-074 pinned the gutter the same way). Each was confirmed
present in `Segoe UI Variable Text` on this host (`QRawFont.supportsCharacter`,
2026-10-21). The `running` row's accent **border** is not built: nothing sets
`running` today (Out of scope).

**Block 3 — the accessible name** (`workspace.py`):

```python
def page_accessible_text(index: int, total_pages: int, filename: str, progress: PageProgress) -> str
```

returns `f"Page {index + 1} of {total_pages}, {filename}, {phrase}"` where
`phrase` is, by `progress.status` (PO-4, exact strings):

| status | phrase |
|---|---|
| `pending` | `not translated yet` |
| `running` | `translating` |
| `translated`, `partly_reviewed`, `fully_reviewed` | `{reviewed} of {total} lines reviewed` |
| `failed` | `{reviewed} of {total} lines reviewed, {failed} failed` |
| `skipped` | `skipped, source changed` |

So AC-2's page reads `Page N of M, <filename>, 12 of 18 lines reviewed`, and a
fresh project's page reads `Page 1 of 3, 001.png, not translated yet`.

**Block 4 — `PageStrip`** (`workspace.py`). `set_pages` **changes signature**
(callers below):

```python
def set_pages(self, filenames: Sequence[str], progress: Sequence[PageProgress]) -> None
def set_progress(self, index: int, progress: PageProgress) -> None   # one row, in place
def progress(self, index: int) -> PageProgress                       # what the row shows
```

Each item gets an item widget (`setItemWidget`, as `TranslationColumn` does)
holding two labels: `QLabel` objectName `pageGlyph` with dynamic property
`status` = the `PageStatus` string and text = `PAGE_STATUS_GLYPHS[status]`,
and `QLabel` objectName `pageLabel` with the item's text. The **item's own
`text()` stays** the 1-based index (rail) or the filename (full), as MT-048
pinned, and `item.data(AccessibleTextRole)` is block 3's string, both modes.
`set_rail` relabels in place as today; the glyph label survives it. In rail
mode the row widget's `sizeHint().width() <= STRIP_RAIL_WIDTH`; GREEN chooses
the arrangement (glyph above the index, or beside it at a smaller size).
`set_progress` updates the glyph text, the `status` property (with the
unpolish/polish re-apply the gutter uses, `workspace.py:334`), and the
accessible text, without rebuilding the item (current row and selection
survive). Changing the `status` property on the label is what recolours it:
the colour itself lives only in `theme.qss` (AC-3).

**Block 5 — the sheet** (`docs/wiki/design/theme.qss.in`, beside the §5 gutter

**Block 6 — the workspace wiring** (`workspace.py`):

- `load_chapter` computes every page's `PageProgress` before `set_pages`:
  for each ordinal `o`, `status = project.page_status(o)`, lines =

  `page_progress(lines, page_done=status == PAGE_DONE, stale=status == PAGE_STALE)`.
  `running` is never passed (always `False`).
- `TranslationColumn` gains `linesChanged = Signal()`, emitted after any row's
