## Context

MT-115 PO-2's follow-up, the CLI half. MT-115 built the consistency pass as a
`ChapterStep` (`pipeline.consistency.consistency_step`), gave `run_chapter`
and `collect_volume` a keyword-only `postlude` to run it from, and put
`compose.build_consistency(selection)` in the composition root - and wired
**none** of it, because `cli.py` and `app.py` were under MT-113's and MT-130's
edits that week. So today `mangatl-run` finishes a chapter, and collects a
batch, without the pass EPIC-09's done-when ends on ("...and then runs the
consistency pass"). This story passes the step to both CLI paths and says
what the pass did in the CLI's one-line-per-thing voice. The window half is
**MT-141**, cut beside this story (PO-4 below).

How the glossary pre-pass reached the CLI is the precedent (MT-105, MT-130):
`build_pipeline` hands `cli.main` a `Pipeline` and `main` reads its
`prelude` out. The pass does **not** join `Pipeline`: its fields are pinned
exactly by two tests (`test_compose.py:1720`, `test_glossary_prelude.py:394`)
and `compose.BatchBinding`'s docstring records that pinning as the reason a
batch value stays out of it; and the collect path builds no pipeline at all.
So the CLI asks the composition root for the step by name,
`build_consistency(selection)`, exactly as it asks for
`build_batch_collector(selection)` - a module attribute the tests replace
(PO-1).

What the user sees (PO-2): one stdout line for a pass that ran, in the shape
of the `batch:` line; and a refused or failed pass ends the invocation as
`_fail` ends every other refusal - one stderr line, exit 1, no traceback -
saying the pages are translated and kept and what to do (PO-3, from MT-115
PO-3).

Required gates: `unit`, `coverage` (`tests/core/test_cli.py` is under both;
`covers | unit | src/mangatl/**`). No optional gate is the only one
exercising anything here, so `required_gates` stays `[]`.

## Acceptance criteria

- **AC-1** - Given a Gemini selection and a chapter of three pages, when
  `main` runs the per-page path, then `build_consistency` is called exactly
  once, with the selection `main` made, after `build_pipeline` and before the
  project is created; and the step it returned is called exactly once, with
  the run's id, after every page of the final pass has run and before the
  run's `RunFinished` - the step's own emit stream is the run's, so a
  `CallPriced(ordinal=None)` it emits reaches the reporter.
- **AC-2** - Given a step that emits `CorrectionsApplied(applied=2,
  skipped_user_lines=1, unchanged_returned=0, chunks_run=1, chunks_refused=0)`,
  when the run finishes, then stdout carries exactly one line
  `Consistency pass: 2 lines corrected, 1 reviewed line left alone`, after
  the last page line and before the `N pages written to ...` line; the
  output folder is written and the exit code is 0. With
  `CorrectionsApplied(1, 0, 0, 1, 1)` the line is instead
  `Consistency pass stopped part way: 1 line corrected, 1 of 2 requests made
  before the budget was reached. Raise the budget and run again to finish
  it.`, and the output folder is still written with exit 0. A count of 1 is
  singular (`1 line`), every other count plural (`0 lines`, `2 lines`).
- **AC-3** - Given a step that raises `BudgetRefused`, when the run reaches
  it, then every page is `done`, no output folder exists, the exit code is
  1, stdout has no pass line and no `pages written` line, and stderr is
  exactly one line, `mangatl-run: consistency pass not run: the budget would
  be exceeded. Every page is translated and kept; raise the budget and run
  again to finish.`, with no traceback. Given a step that raises
  `RuntimeError("boom")` instead, the stderr line is `mangatl-run:
  consistency pass failed: RuntimeError: boom. Every page is translated and
  kept; run again to retry it.` A run aborted by a **page** of the final
  pass (a stage raising on page 2) still reads `mangatl-run: run aborted:
  ...` as today, and the step is not called.
- **AC-4** - Given `--no-translate`, or a selection whose `build_consistency`
  answers `None` (the seam returning `None`, as the real one does for
  `anthropic`), when the run finishes, then no pass line is printed, the
  output folder is written and the exit code is 0; under `--no-translate`
  `build_consistency` is not called at all.
- **AC-5** - Given a project with two pending batch jobs and a Gemini
  selection, when `main` collects them, then `build_consistency` is called
  exactly once with that selection, after `build_batch_collector` and before
  any job is collected; every `collect_volume` call receives that step as
  `postlude=`; the step runs exactly once, after the last job's
  `BatchCollected`; and stdout is exactly two lines - the `batch:` line, then
  the pass line of AC-2 - with exit 0. With one job still pending after the
  poll, the step is not called and stdout is the one `batch:` line as today.
- **AC-6** - Given the collect path with a step that raises `BudgetRefused`,
  when the last job is collected, then the jobs are `collected` and the pages
  `done`, stdout is the `batch:` line alone, stderr is the one
  `consistency pass not run: ...` line of AC-3, and the exit code is 1. With
  a step raising `RuntimeError("boom")`, the stderr line is the
  `consistency pass failed: ...` line of AC-3.

**Semantics.**

- *Order on the per-page path (AC-1).* `build_consistency` after
  `build_pipeline` so a provider with no translator refuses once, on
  `build_pipeline`, as today; before `create_project` so a refusal leaves
  nothing behind. The step runs where `run_chapter` runs its postlude: after
  the final pass, only when the run has not already aborted
  (`progress.reason is None`), with the run's `run_id` and the run's `emit`.
- *Exit codes.* The per-page path keeps its promise: `0` means every page is
  complete **and** the output folder was written. A refused or failed pass
  writes no output folder (the bake is skipped exactly as it is for any
  aborted run), exits 1, and the next plain invocation resumes - every page
  skipped as `already done`, the pass run as the postlude, then the bake
  (MT-115 PO-3's recovery). A pass stopped **part way** (`chunks_refused > 0`)
  is not an abort: `run_chapter` finishes, the bake runs, exit 0, and the
  line says what is left to do; the marker stays unset (MT-115), so the next
  run repeats the pass whole. The collect path exits 1 on a refused or
  failed pass for the same reason: the chapter is not finished, and the next
  plain run finishes it.
- *Where the lines go.* Every pass line is stdout, after the pages' lines
  (per-page path) or after the `batch:` line (collect path); the refusal is
  stderr through `_fail`, so a script reading stdout sees the batch line it
  saw yesterday and a script checking the exit code sees the chapter is not
  done.
- *The window is not here.* `app.py`, `ui/**` and their tests are MT-141's.

**Oracle partition.** All six criteria are **mechanical**: a call order, a
keyword argument, exact lines on exact streams, an exit code. Pin them
exactly; invent no metric.

**Test seams and fixtures (for RED).** `tests/core/test_cli.py` already
replaces `mangatl.cli.build_pipeline` (`_CompositionRoot`, line 111) and
`mangatl.cli.build_batch_collector` (`_CollectorRoot`, line 1529). A
