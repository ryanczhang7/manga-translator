## Context

EPIC-10 PO-5 and **Q-1** (answered 2026-10-28: *left as drawn*). After MT-118
an excluded region gets no translation, but `CleanStage.run` still hands every
stored region to the cleaner (`clean_stage.py:58-60`), so the watermark is
inpainted; and `bake.py`'s `_bake_area` unites the erase mask with every
region's polygon, so the area is painted from the cleaned page even though
`_set_blocks` typesets nothing there. This story makes "removed" mean **left as
drawn**: an excluded region is outside the erase mask and outside the bake
area, and the output shows the **source** pixels there - whether the region was
removed before the page was cleaned or after.

**History, kept.** The plan as written on 2026-10-28 (C-2 then) had
`set_excluded` **invalidate the page's `cleaned_page` row on every toggle**, so
the *next run* re-cleaned the page with the new set. On 2026-10-30 the
orchestrator found the defect in that plan while closing MT-120: **the app has
no way to re-run or resume a chapter** - `app.open_folder` opens a folder with a
project straight into the `Workspace`, and `MainWindow._start` is reachable
only from a folder with *no* project (`create_project` refuses an existing
one). Only `mangatl-run` resumes (`cli.py:156-160`). So with MT-120 shipped
(Remove / Restore in the review screen), removing the watermark and then
pressing Render would have deleted the cleaned image and baked the page as the
**untranslated source bytes verbatim**, counted `pages_uncleaned` (`bake.py`
table, "regions, no cleaned image") - every bubble on the page Japanese again,
with no way back short of the command line.

**The user's decision (2026-10-30, verbatim choice: "Paste back at render").**
Keep the cleaned image. At bake, copy the **source** pixels back over each
excluded region's erased area - its own erase mask, dilation included - on top
of the cleaned image, so the region comes out exactly as drawn with no
re-clean. `CleanStage` still hands only included regions to the cleaner, so a
page cleaned *after* the exclusion never erases it in the first place. **Only
one toggle invalidates:** restoring a region whose pixels were **never erased**
in the stored cleaned image (it was excluded when the page was cleaned). That
page needs re-cleaning - there is nothing to paste back and the Japanese would
sit under the English - so `set_excluded(..., None)` deletes the cleaned row in
exactly that case, and the page bakes as source, counted `pages_uncleaned`,
until a re-run exists (EPIC-11, MT-124 / MT-125, planned the same day).
Excluding never invalidates; restoring an erased region never invalidates.

**What the store has to know for that**: which regions the stored cleaned image
erased. Today `cleaned_page` is `(page_id, image_blob)`. This story adds
`cleaned_page.erased`, a JSON array of the reading indices the cleaner was
handed when that image was written, written by `write_cleaned` and deleted with
the row - the fact lives beside the artefact it describes, and every existing
invalidation (`write_regions`, `refresh_from_source`) takes it along for free.
A per-region flag was the alternative and lost: it would survive the row it
describes, and `_UPSERT_REGION` would have to reset it.

**Schema v9 and the renumbering.** MT-118 landed **v8**. MT-103 (EPIC-09) was
written as "schema v8" and MT-118 recorded that whichever lands second takes
the next number; MT-103 is therefore already due to become v9 when it starts.
This story takes **v9** now, so **MT-103 renumbers to v10** when it starts -
one line in its PLANNED text, criteria not yet frozen; a note is left in its
`## Notes`. `plan.sh conflicts` reports MT-103 / MT-119 as CONFLICT on
`schema.py` / `project.py`; they run one after the other.

Required gates that fail if this breaks: `unit`, `coverage` (`tests/core`).

## Acceptance criteria

- **AC-1** - Given a page with two regions, the second excluded, when
  `CleanStage.run` runs, then the cleaner is called with **one** region (the
  first) and `read_erased(ordinal) == frozenset({0})`; given both excluded,
  the cleaner is not called, the stored cleaned image is the source bytes
  verbatim (the existing no-regions rule) and `read_erased(ordinal)` is the
  empty set. *Control:* with nothing excluded the cleaner receives both and
  `read_erased` is `{0, 1}`.
- **AC-2** - Given a PNG page with two regions A (included, with a proposal)
  and B, and a stored cleaned image whose `erased` is `{A, B}` (B was removed
  **after** the page was cleaned, so its pixels are erased in the stored
  image), when the page is baked, then every pixel inside B's polygon **and**
  inside B's dilated erase mask (`MASK_DILATION_PX` band included), minus A's
  own dilated erase mask, equals the **source** page's pixel there; and the
  bake area handed to `bake_page` is `False` over B's polygon minus A's bake
  contribution. *Control:* the same page with B included (no proposal) has
  those pixels equal to the **cleaned** page's pixel - which the fixture makes
  differ from the source - and the bake area `True` there.
- **AC-3** - Given the same page but a stored cleaned image whose `erased` is
  `{A}` (B was excluded **before** the clean, so the cleaner never touched it),
  when the page is baked, then the same pixels of B equal the source, and
  nothing is pasted: the baked page equals the control bake of a cleaned image
  that already carried the source there. (Nothing to erase, nothing to put
  back; one assertion that the two paths meet.)
- **AC-4** - Given a bake of a page where one region is excluded, then
  `BakeReport.regions_empty` does not count it: an excluded region is not a
  region "left without text". *Control:* the same region included and without
  a proposal is counted.
- **AC-5** - `set_excluded` and the cleaned image, four cases on a page with a
  stored cleaned image: (a) excluding an included region keeps the image,
  whatever `erased` holds; (b) restoring a region whose index **is** in
  `erased` keeps the image; (c) restoring a region whose index is **not** in
  `erased` deletes it - `has_cleaned(ordinal)` is `False` afterwards and no
  other page's image is touched; (d) setting the value the region already has
  keeps the image. The `region.excluded` write and the delete are one
  transaction: a delete that fails leaves the exclusion unchanged.
- **AC-6** - Schema v9: a version 8 file opens at 9 (`PRAGMA user_version`
  and `chapter.schema_version` both 9) and `SchemaTooNew` is raised by a reader
  whose `SCHEMA_VERSION` is 8; every `cleaned_page` row the v8 file held reads
  `erased` == **every** reading index of its page (the truth about a row a v8
  cleaner wrote: it was handed every region); a fresh file and a migrated one
  store the same `cleaned_page` declaration in `sqlite_master.sql` (whitespace
  collapsed, the `test_schema_v8.py` comparison); and `write_cleaned` with an
  `erased` index not on the page raises `ValueError` naming it with nothing
  written, as `write_proposed` does.

### C-2 `CleanStage.run`

```python
regions = ctx.project.read_regions(ctx.page.ordinal)
kept = included(regions)
image_bytes = (ctx.project.chapter.source_dir / ctx.page.filename).read_bytes()
cleaned = self.clean(image_bytes, kept) if kept else image_bytes
ctx.project.write_cleaned(
```

### C-3 `bake.py`

- `_set_blocks(page_regions, lines, faces, cleaned)` - signature unchanged;
  **skips a region whose `excluded is not None`** and keeps `enumerate` over
  the full list so reading indices stay aligned with `lines`. `preview_bake`
  follows for free (MT-066 C-1).
- `_bake_area(page_regions, size, interiors)` - signature unchanged; builds
  the mask and the polygon fill from `included(page_regions)` only. So the
  area is `False` over an excluded polygon except where an included region's
  mask, polygon or interior reaches into it (AC-2's "minus A's contribution").
- `bake_chapter`: `regions_empty += len(included(page_regions)) -
  len(set_blocks)` (AC-4). It already holds the source bytes as `payload`;
  they go to `_bake`.
- `_bake(cleaned, source, page_regions, erased, blocks, interiors, filename)
  -> bytes` - gains `source: bytes` and `erased: frozenset[int]`. Decodes
  both with `.convert("RGB")` (a greyscale source has to match the cleaned
  page's shape), calls `_restore_excluded`, then `bake_page` as today.
- New, private:

  ```python
  def _restore_excluded(
      cleaned: NDArray[np.uint8],      # (H, W, 3) the stored cleaned page
      source: NDArray[np.uint8],       # (H, W, 3) the scan
      page_regions: Sequence[RawRegion],
      erased: frozenset[int],          # reading indices the cleaner erased
      size: tuple[int, int],           # (width, height)
  ) -> NDArray[np.uint8]:
      """A copy of `cleaned` with the source put back wherever an excluded
      region was erased: for each region with `excluded is not None` and
      index in `erased`, its own `erase_mask([region], size)` - dilation
      included - minus `erase_mask(included(page_regions), size)`. An
      included region's erased pixels are never restored (two bubbles 2 px
      apart share a band). Nothing to do returns `cleaned` unchanged."""
  ```

  Dilation distributes over union, so one region's `erase_mask` is exactly
  its contribution to the page's mask (MT-019 C-3). Pixels of B outside its
  dilated mask were never touched by the cleaner (MT-019 AC-4, PNG encode),
  so after the paste the whole of B's polygon (minus A's contribution) is
  source - which is what AC-2 asserts.
- `_bake` is private; its only caller is `bake_chapter`. `_set_blocks` and
  `_bake_area` are private and unchanged in signature; callers `bake_chapter`,
  `preview_bake`, `_bake` in `bake.py` only. No test imports any of the three
  (`rg "_set_blocks|_bake_area|\b_bake\(" tests` - the `_bake` hits in
  `test_bake_font.py` are that file's own helper).
- The module docstring's table gains the row: *"regions, a cleaned image and an
  excluded region: the cleaned page with the source put back over the excluded
  region's erased area, then `bake_page`"*.

### C-4 The store: `cleaned_page.erased`, v9

```python
# src/mangatl/store/project.py
SCHEMA_VERSION: int = 9

def write_cleaned(self, page_ordinal: int, image: bytes, *, erased: Iterable[int]) -> None:
    """... `erased`: the reading indices of the regions the cleaner was
    handed for this image. Keyword-only and REQUIRED - a default would say
    "every region" for a page with excluded regions, and a restore of one
    would then not re-clean (AC-5c). Each index must be a reading index of
    the page, else ValueError naming it, nothing written. Stored as a sorted
    JSON array of distinct ints."""

def read_erased(self, page_ordinal: int) -> frozenset[int] | None:
    """The reading indices the stored cleaned image erased, or None when the
    page has no cleaned image. Opens no transaction."""
```

`_UPSERT_CLEANED` names `erased` in the `INSERT` and the `DO UPDATE SET`.
`read_cleaned`, `has_cleaned`, `_DELETE_CLEANED` unchanged.

`set_excluded(page_ordinal, reading_index, reason)` - signature unchanged.
Inside its transaction, after the existing checks: read the row's current
`excluded`; if `reason is None` and the current value is not `None` (a
restore) and the page has a `cleaned_page` row whose `erased` does not contain
`reading_index`, `cursor.execute(_DELETE_CLEANED, (page_id,))` after the
`UPDATE`; otherwise no delete. Docstring states the rule and cites MT-065 C-3
(the delete) and this story. MT-118 C-3's "no `cleaned_page` row is
invalidated here" sentence goes, replaced by the rule.

**Schema** (`schema.py`, `project.py`). `CLEANED_PAGE_DDL` is also
`_MIGRATE_TO_V7`, so the column **cannot** be added to that string: a v6 file
would create the table with it and then hit `duplicate column name` at v9.
Instead one new shared string, appended on both paths:

```python
# schema.py
CLEANED_ERASED_DDL: str = (
    "ALTER TABLE cleaned_page ADD COLUMN erased TEXT NOT NULL DEFAULT '[]';\n"
)
DDL = ... + CLEANED_PAGE_DDL + CLEANED_ERASED_DDL   # fresh file: create, then alter

# project.py
_MIGRATE_TO_V9 = CLEANED_ERASED_DDL + """
UPDATE cleaned_page SET erased = (
    SELECT json_group_array(reading_index) FROM (
        SELECT reading_index FROM region
        WHERE region.page_id = cleaned_page.page_id ORDER BY reading_index
    )
);
"""
```

The `UPDATE` is AC-6's "every reading index": a v8 cleaner was handed every
region (`clean_stage.py:58-60` before this story), and `write_regions` deletes
the image, so the regions stored now are the regions it was handed. `DEFAULT
'[]'` exists because `ADD COLUMN ... NOT NULL` needs one; the store's upsert
always names the column. `json_group_array` is SQLite's built-in JSON1
(`sqlite3.sqlite_version` here: 3.53.1); a page with a cleaned image and no
regions gets `[]`, correctly. RED pins the fresh-vs-migrated declaration
through `sqlite_master.sql` as `test_schema_v8.py` does, with a v8 fixture
built in the test from a transcribed `_V8_DDL` (that file's rule: a historical
artefact, never updated to track `schema.py`). The `SCHEMA_VERSION` docstring
gains a "Version 9" paragraph.

## Out of scope

- Erasing an excluded region (Q-1 "erased", parked as MT-122).
- The detector's box geometry (the clipped letters): an excluded region's box
  is never used, so it does not matter here.
- **Re-running clean after a restore of a never-erased region** (AC-5c): the
  page bakes as source, counted `pages_uncleaned`, until EPIC-11's re-run
  exists. The workspace does not start one, and this story adds no UI and no
  message about it (EPIC-11 MT-125 shows the page as pending in the strip).
- Any UI (MT-120 shipped it), any automatic rule (MT-121).
- `erase_mask` and `clean_page_image` themselves: they still erase whatever
  regions they are handed; the filter is upstream of them.
- Pasting back over an **included** region's pixels, ever - even inside an
  excluded region's band (C-3).
- JPEG pages: the paste-back runs on them too, but the pixel assertions are on
  PNG pages; a JPEG output is one lossy encode away from its input (MT-021 C-5)
  and nothing here changes that.
- Carrying `erased` across a re-detection (`write_regions` deletes the row and
  the column with it, as today).
