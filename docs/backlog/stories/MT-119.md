## Context

EPIC-10 PO-5 and **Q-1**. After MT-118 an excluded region gets no
translation, but `CleanStage.run` still hands every stored region to the
cleaner (`clean_stage.py:58-60`), so the watermark is inpainted; and
`bake.py`'s `_bake_area` unites the erase mask with every region's polygon,
so the area is painted from the cleaned page even though `_set_blocks`
typesets nothing there. This story makes "removed" mean **left as drawn**: an
excluded region is outside the erase mask and outside the bake area, and the
output shows the source pixels there.

**If the user answers Q-1 "erased"**, this story is closed unneeded with the
answer recorded here: the pipeline as MT-118 leaves it already inpaints the
region and typesets nothing over it. Nothing else in the epic moves.
**Answered 2026-10-28: left as drawn**, so this story stands. Erasing
external watermarks is v2, parked as `docs/backlog/parked/MT-122.md`.

**One store decision belongs here, not in MT-118** (its C-3): what a toggle
does to a page that already has a cleaned image. Since the cleaned image
depends on which regions were erased, `set_excluded` **invalidates the
page's `cleaned_page` row** (the `_DELETE_CLEANED` `write_regions` already
issues, MT-065 C-3), so the next run re-cleans the page with the new set and
`CleanStage.is_done` goes false for it. Without this a region removed after a
run stays erased in the output, and a region restored after a run is never
erased. A `cleaned_page` blob is 1-2 MB and re-cleaning one page is seconds
on the GPU (MT-019); the alternative - a stale cleaned image silently baked -
is the failure `architecture.md` §4's invalidation discipline exists to stop.

Required gates that fail if this breaks: `unit`, `coverage`.

## Acceptance criteria

- **AC-1** - Given a page with two regions, the second excluded, when
  `CleanStage.run` runs, then the cleaner is called with **one** region (the
  first); given both excluded, the cleaner is not called and the stored
  cleaned image is the source bytes verbatim (the existing no-regions rule).
  *Control:* with nothing excluded the cleaner receives both.
- **AC-2** - Given a cleaned page and two regions where the second is excluded
  and has no proposal, when the page is baked, then every pixel inside the
  second region's polygon (and its `MASK_DILATION_PX` band) equals the
  **cleaned** image's pixel there - which, by AC-1, is the source pixel - and
  the bake area handed to `bake_page` is `False` over that region. *Control:*
  the same page with the region included and a proposal has the bake area
  `True` there.
- **AC-3** - Given a page with a stored cleaned image, when
  `set_excluded(ordinal, i, "user")` or `set_excluded(ordinal, i, None)`
  changes the region's exclusion, then `has_cleaned(ordinal)` is `False`
  afterwards; when the call sets the value the region already has, the
  cleaned image is kept.
- **AC-4** - Given a bake of a page where one region is excluded, then
  `BakeReport.regions_empty` does not count it: an excluded region is not a
  region "left without text" (`bake.py:174`).

## Contract

**Writes:** `src/mangatl/pipeline/clean_stage.py`, `src/mangatl/pipeline/bake.py`, `src/mangatl/store/project.py`, `tests/core/test_clean_stage.py`, `tests/core/test_bake.py`, `tests/core/test_region_store.py`

### C-1 One filter, named once

```python
# src/mangatl/pipeline/clean_stage.py (or bake.py; pick one and import it
# in the other - the two must not drift)
def included(regions: Sequence[RawRegion]) -> tuple[RawRegion, ...]:
    """The regions the pipeline treats as text: `excluded is None`."""
```

`CleanStage.run`: `regions = included(ctx.project.read_regions(...))`; the
rest of the method unchanged, so an all-excluded page takes the existing
`if regions else image_bytes` branch (AC-1). `CleanStage.is_done` unchanged.

`bake.py`: `_set_blocks` and `_bake_area` take the full region list (reading
indices must stay aligned with `lines`) and skip regions whose `excluded` is
not `None`; `regions_empty` counts only included regions without a block
(AC-4). `preview_bake` reads `_set_blocks` too (MT-066 C-1) and follows.

### C-2 The store

`Project.set_excluded` (MT-118 C-3) gains: if the stored value differs from
`reason`, `cursor.execute(_DELETE_CLEANED, (page_id,))` in the same
transaction; if equal, no delete. Stated in its docstring with MT-065 C-3
cited.

### C-3 Oracle partition

All **mechanical**: a call's argument list, a boolean array over a polygon,
a row's presence, a count. AC-2's pixel equality is on a synthetic page
(`tests/core/_bake_world.py`'s world) - the oracle is the cleaned array
itself, not a perceptual judgement.

### C-4 Callers

`included` is new. `_set_blocks` and `_bake_area` are private; their callers
are in `bake.py` only (`bake_chapter`, `preview_bake`, `_bake`). No existing
export changes signature.

## Out of scope

- Erasing an excluded region (Q-1 "erased"): if chosen, this story closes.
- The detector's box geometry (the clipped letters): an excluded region's box
  is never used, so it does not matter here.
- Re-running clean automatically on a toggle: the invalidation makes the
  **next run** re-clean; the workspace does not start one.
- Any UI (MT-120), any automatic rule (MT-121).
- `erase_mask` and `clean_page_image` themselves: they still erase whatever
  regions they are handed; the filter is upstream of them.
