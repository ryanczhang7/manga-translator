## Context

EPIC-11, the follow-up MT-125 left open (its `## Notes` PO-5, 2026-10-31).
`components.md` §9 `RerunDialog`, budget row: *"The frame takes `CostEstimate`'s
warning hairline; the sentence carries the state (A-10)."* MT-125 built the
half it could reach: `RerunDialog` (`src/mangatl/ui/rerun_dialog.py`) sets the
dynamic property `overBudget` to `not preview.within_budget` before first
polish, and `tests/ui/test_rerun_dialog.py` pins the property. No stylesheet
rule reads it - the theme files were outside MT-125's `touches:` - so today an
over-budget dialog looks exactly like one within budget. The state is not
lost: the budget line says `The estimate is over budget.` / `The budget is
already spent.` (A-10). This is the cosmetic half, a design-conformance gap,
and the failing paint test that reproduces it is the regression test.

**What the hairline is.** `CostEstimate`'s over-budget rule
(`docs/wiki/design/theme.qss.in` line 345,
`#chapter-summary QFrame#summary-cost-estimate[overBudget="true"]`):
`border: @{border-width.hairline}px solid @{color.status.warning}`. This story
adds the same declaration under a selector for the dialog, in the one source
of truth, `docs/wiki/design/theme.qss.in`, and regenerates the shipped
artefacts (`uv run python -m mangatl.ui.tokens`, project.conf task `tokens`):
`src/mangatl/ui/theme.qss` and `src/mangatl/ui/theme.qss.tmpl` change;
`tokens_gen.py` and `theme_hc.qss.tmpl` do not. `tests/ui/test_tokens.py`
already pins the committed artefacts to the design sources byte for byte, so a
rule added to `theme.qss.in` without regenerating fails `unit` on its own.

**High Contrast.** `components.md` §10.7: *"`RerunDialog`'s over-budget border
collapses to `WindowText` like every other; the sentence already carries it."*
§10.9 is the precedent for how: a value change, not a rule change -
`color.status.warning` resolves to `WindowText` through `[hc.map]` in the base
template, and `theme_hc.qss.in` gets **no** rule (`tokens.md` §12.1: the
override template is for rule changes only).

**No source change.** Qt matches a type selector against
`metaObject()->className()`, and PySide6 gives a Python subclass its own
metaobject named after the class, so `RerunDialog[overBudget="true"]` selects
the dialog with no `setObjectName`. Probed offscreen before this story was cut;
output under `## Notes` PO-1. It is the first Python-class type selector in the
sheet (every other rule uses a Qt type name or an object name), recorded in the
`## Contract` with the alternative.

Required gates that fail if this breaks: `unit`, `coverage` (`tests/ui`,
offscreen, the gate `tests/ui` already runs under). No display, no weights, no
project: the dialog is built from a `RerunPreview` value and shown alone.

## Acceptance criteria

All four are paint or text measured through the real theme path - the
packaged `theme.qss` set as the application sheet, or the composed High
Contrast sheet - never `styleSheet()` on the widget, which stays `""`.

- **AC-1** - Given the packaged `theme.qss` applied as the application sheet
  and a `RerunDialog` built from a `RerunPreview` whose `within_budget` is
  `False`, when the dialog is shown and its own pixels grabbed, then the middle
  line of every edge of the dialog - top, bottom, left, right, a
  `border-width.hairline`-pixel border, corners excluded by one hairline at
  each end - is `color.status.warning` on every side and nothing else.
  *Control:* the same dialog shown with **no** application sheet paints no
  `color.status.warning` pixel on any edge - the colour comes from the sheet,
  not from `rerun_dialog.py`.
- **AC-2** - Given the same sheet and a `RerunPreview` whose `within_budget`
  is `True`, when the dialog is shown, then no edge pixel is
  `color.status.warning`: the edge is the dialog's ground,
  `color.surface.base` (the `QMainWindow, QDialog` rule), on every side. The
  within-budget dialog gains no border.
- **AC-3** - Given the packaged base template rendered with
  `color.status.warning` replaced by a sentinel colour that no token's value
  uses, and that rendered sheet applied, when an over-budget dialog is shown,
  then every edge is the sentinel. The rule reads the token; a hard-coded
  colour in the rule fails this.
- **AC-4** - Given the sheet composed for High Contrast
  (`theme.compose_stylesheet(base_template(), hc_template(),
  high_contrast=True, palette=P)` for a five-role test palette `P` whose
  `WindowText` is a colour no token's value uses) applied as the application
  sheet, when an over-budget dialog is shown, then every edge is
  `P["WindowText"]`; and `docs/wiki/design/theme_hc.qss.in` contains no
  `RerunDialog` selector (§10.9: value change, not rule change).

### C-1 The rule (`docs/wiki/design/theme.qss.in`)

One new rule, in a commented section of its own placed directly after the
`CostEstimate` section (the rule it borrows from), in the sheet's comment
style:

```
/* ---- RerunDialog: the over-budget frame (MT-127) ---------------------- */
/* components.md 9 RerunDialog, budget row: the frame takes CostEstimate's  */
/* warning hairline. The state is the dynamic property overBudget, a bool   */
/* rerun_dialog.py sets once before first polish (MT-125). A type selector  */
/* on the Python class: Qt matches metaObject()->className(), and PySide6   */
/* names a subclass's metaobject after the class. Specificity (0,1,1) over  */
/* the QDialog ground rule's (0,0,1), so order does not matter. Colour is   */
/* emphasis only: the budget sentence carries the state (A-10). Under HC    */
/* the token resolves to WindowText; no override rule (components.md 10.9). */

RerunDialog[overBudget="true"] {
    border: @{border-width.hairline}px solid @{color.status.warning};
}
```

- Two tokens, the same two `CostEstimate` uses. No radius: a dialog is a
  top-level window, `radius.sm` has nothing to round.
- No rule for the within-budget dialog: the base `QMainWindow, QDialog` rule
  sets only `background-color`, and Qt paints no border where none is set
  (AC-2 measures the ground on the edge).
- **The selector.** `RerunDialog[overBudget="true"]`, probed 2026-10-31 (PO-1):
  the edge painted the rule's colour with `className=RerunDialog`.
  `QDialog[overBudget="true"]` also works (same probe) but would style any
  dialog that ever sets the property; `RerunDialog` is the only one, and the
  narrower selector says so. Using an object name instead
  (`QDialog#rerunDialog[overBudget="true"]`) would need a `setObjectName` in
  `src/mangatl/ui/rerun_dialog.py` - a source change this story does not
  expect. RED may amend to it only together with adding that file to
  `**Writes:**` and `touches:` and saying why the type selector did not hold.
- Qt matches a `bool` property against the string `true`, as the
  `CostEstimate` rule relies on.
