## Context

EPIC-09 PO-2's last clause: once the glossary is proposed up front (MT-105,
run before any page is translated since MT-130/MT-139), pages stop proposing
terms. Today a page's answer may carry a `glossary` array
(`page_prompt.response_schema` unions `{GLOSSARY_KEY: GLOSSARY_SCHEMA}` into
every page's schema, and `SYSTEM_PROMPT`'s last bullet asks the model to fill
it), every page adapter parses it into `TranslationResult.proposed_terms`
(`client.translate_page`, `gemini.translate_page`, `gemini_batch._result_of`),
and both write paths `merge` it into the chapter's glossary
(`translate_stage._update_glossary`, `pipeline/batch._update_glossary`). With
a fixed glossary that is wasted output tokens on every page - the
corrections-only principle (PO-6) applied to the page call - and a second
source of renderings competing with the pre-pass's.

After this story a page's schema has the region strings and nothing else; the
`glossary` key is **forbidden** by `additionalProperties: false`, so a model
that still returns one is disobeying the schema, and every adapter returns
`proposed_terms == ()` whatever the body says. A page - synchronous or
collected from a batch - marks the glossary's terms seen (`mark_seen`) and
writes nothing new to it. The pre-pass (`pipeline/prelude.py`) keeps `merge`
and `parse_terms_text`; nothing in `domain` or `parse` changes.

**This changes Claude's request too.** `page_prompt` is shared, so Claude's
schema loses `glossary` as well and Claude pages stop proposing - and, since
`compose._translator` binds **no** pre-pass for `anthropic`, a Claude run has
no model-written glossary at all afterwards (PO-4, accepted by the user
2026-11-06). MT-079 AC-1 pinned
Claude's request byte-for-byte, and the system prompt to the character
(`tests/core/test_page_prompt.py`); RED amends those pins in place with this
story's id.

Required gates: `unit`, `coverage` (both `covers: src/mangatl/**`). The paid
`live` gate runs once at GATES, after the required gates are green (PO-2, the
user's approval, 2026-11-06) - this story changes what is sent to Gemini.

## Acceptance criteria

- **AC-1** - `response_schema(n)` has exactly the `n` region properties
  (`"0".."n-1"`, each `{"type": "string", "description": "The English for the
  region at reading index i."}`) and no `glossary` property; it has no
  `required` key, and `additionalProperties` is `False`. `response_schema(0)`
  has an empty `properties` mapping.
- **AC-2** - Given a response body carrying region strings **and** a
  `glossary` array of well-formed items, when it is read by any page adapter -
  `client.translate_page` (Claude), `gemini.translate_page`, and
  `gemini_batch.collect_batch` for a batch item - then the result's `lines`
  are the region strings keyed by index and `proposed_terms` is `()`: a stray
  glossary neither raises nor reaches the result. `parse_terms_text` itself is
  unchanged (the pre-pass reads terms through it).
- **AC-3** - Given a glossary of two terms, one of which appears in the OCR
  text of the page at ordinal 3 and the other not, when that page is
  translated by `TranslateStage` with a translator whose result **proposes a
  new term and a new rendering of an existing one**, then the first term's
  `last_seen_page` is 3, the other's is unchanged, no entry was added, and no
  `term_en` changed.
- **AC-4** - Claude's `build_request` schema equals Gemini's
  `response_json_schema` for the same region count (one `response_schema`,
  still shared, and `gemini_batch.build_batch_requests` carries the same
  `config`), and `GLOSSARY_SCHEMA` and `GLOSSARY_KEY` remain exported from
  `page_prompt` with their values unchanged, for MT-104's pass.
- **AC-5** - Given a submitted batch job over pages whose glossary holds one
  term, when the job is collected with results that propose terms (a new one,
  and the existing one under another rendering), then the glossary afterwards
  holds exactly that one term with its original `term_en`, its
  `last_seen_page` moved to the last page whose OCR text contains it, and
  nothing else - `collect_volume` folds sightings and never proposals.
- **AC-6** - `SYSTEM_PROMPT` no longer tells the model to add terms under
  the `glossary` key: its text is the pre-story text with the final bullet of
  "Continuity across pages" removed and nothing else changed, so it still
  tells the model to use the glossary's renderings exactly.
