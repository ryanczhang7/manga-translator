## Context

EPIC-09 PO-2's last clause: once the glossary is proposed up front (MT-105),
pages stop proposing terms. Today every page's answer may carry a `glossary`
array (`page_prompt.response_schema`, `GLOSSARY_KEY`) that
`translate_stage._update_glossary` merges (`translate_stage.py:114-130`).
With a fixed glossary that is wasted output tokens on every page - the
corrections-only principle (PO-6) applied to the page call - and a second
source of renderings competing with the first.

After this story a page's schema has the region strings and nothing else; a
page marks the glossary's terms seen (`mark_seen`) and writes nothing new to
it. The `glossary` key is **forbidden** by `additionalProperties: false`, so
a model that still returns one is disobeying the schema and the parse drops
it rather than merging it.

**This changes Claude's request too.** MT-079 AC-1 pinned Claude's request
byte-for-byte; `page_prompt` is shared, so Claude's schema loses `glossary`
as well and Claude pages stop proposing. v1 is Gemini-only (EPIC-08) and the
user asked for the fixed glossary; recorded here as accepted, and the MT-079
assertion is amended in RED with this story as the reason.

Required gates: `unit`, `coverage`.

## Acceptance criteria

- **AC-1** - `response_schema(n)` has exactly the `n` region properties and
  no `glossary` property; `additionalProperties` is `False`.
- **AC-2** - Given a response body carrying region strings and a `glossary`
  array, `parse_terms_text` returns `()` and `parse_lines_text` returns the
  regions unchanged - a stray glossary neither raises nor merges.
- **AC-3** - Given a glossary of two terms, one of which appears in page 3's
  OCR text, when page 3 is translated, then that term's `last_seen_page` is
  3, the other's is unchanged, no term was added, and no `term_en` changed -
  whatever the translator's result proposes.
- **AC-4** - Claude's `build_request` schema equals Gemini's
  `response_json_schema` for the same region count (one `response_schema`,
  still shared), and the `GLOSSARY_SCHEMA` fragment remains exported for
  MT-104's pass.

  union; `GLOSSARY_KEY` and `GLOSSARY_SCHEMA` stay exported.
- `parse_terms_text(text)` returns `()` always, **or** is deleted and its
  callers (`gemini.translate_page`, `client`/`prompt` for Claude) stop
  setting `proposed_terms` - RED chooses; `TranslationResult.proposed_terms`
  stays in the type (MT-104's `GlossaryProposal` has its own field) and is
  `()` for every page.
- `_update_glossary` becomes mark-seen only: `mark_seen(before, ocr texts,
  ordinal)` then upsert of changed entries; `merge` is no longer called from
  the stage.
- Callers of the changed assertion: `tests/core/test_prompt.py` (MT-079
  AC-1's byte-for-byte fixture), `tests/core/test_page_prompt.py`,
  `tests/core/test_gemini.py` if it pins the schema. RED amends them in place
  with this story's id.
