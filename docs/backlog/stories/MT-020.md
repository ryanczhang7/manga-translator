## Context

Brief feature 6 and section 8: "comic body font, centred, sensible line breaks,
sized to the bubble… the baked page should look like a normal English release,
not like a machine's output."

**O5 is resolved**: `docs/wiki/design/typeset-font.md` chooses **Shantell Sans
1.011 under the SIL Open Font License 1.1**, shipping the *static* instances
(Regular, Italic, Bold, Bold Italic) rather than the variable font. That document
is settled and is not to be re-litigated here — but two things in it are
explicitly *not* settled and land on this story:

- **§5 licence obligations are mechanical and must actually be performed**: ship
  `OFL.txt`, credit the font in About, and **do not subset** (Reserved Font
  Name). AC-8 makes the first two checkable; the third is a rule for MT-024.
- **§6 records that glyph coverage is unverified** and converts that into a test
  rather than an assertion. AC-7 is that test. Interrobang is deliberately
  **excluded** from the required codepoints — the convention sets `?!`.

`typeset` is in the 100% `coverage-core` set. This is pure geometry and metrics;
it takes a font file and a polygon and returns positioned glyph runs.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core`.

## Acceptance criteria

- **AC-1** — Given a bubble polygon and a string, when it is typeset, then every
  glyph's bounding box lies inside the polygon's inscribed fitting area, at the
  largest size in the allowed range that achieves this.
- **AC-2** — Given a typeset block, when it is positioned, then each line is
  horizontally centred within the fitting area and the block is vertically
  centred within it.
- **AC-3** — Given a string that cannot fit at the minimum size, when it is
  typeset, then it is set at the minimum size, overflow is reported on the
  result, and **nothing is silently truncated**.
- **AC-4** — Given a string, when lines are broken, then breaks occur at
  whitespace and at existing hyphens only — **no automatic hyphenation** — and
  the break chosen minimises the raggedness measure the contract defines.
- **AC-5** — Given `*italic*` and `**bold**` markers in the text, when it is
  typeset, then those runs use the Italic and Bold **font files**, the markers do
  not appear in the output, and an unclosed marker is rendered literally.
- **AC-6** — Given the same string, polygon and font, when typeset twice, then
  the output is byte-identical — no randomness, no dependence on system font
  configuration.
- **AC-7** — Given the shipped font files, when they are inspected, then every
  codepoint in `REQUIRED_CODEPOINTS` is present in the cmap of **all four**
  faces, and the four faces have **distinct `OS/2` style bits** — Bold is bold
  *in the file*, not synthesised.
- **AC-8** — Given the built application tree, when it is inspected, then
  `OFL.txt` is present beside the font files and the About text names the family,
  the designers and the licence.

### C-3 `src/mangatl/typeset/markup.py`

```python
@dataclass(frozen=True)
class Run:
    text: str
    italic: bool
    bold: bool
    @property
    def face_key(self) -> str   # "regular" | "italic" | "bold" | "bold_italic"

def parse_emphasis(text: str) -> list[Run]
```

The grammar, which `typeset-font.md` §7 settles and this block makes exact:

1. `\*` is a literal `*` and is never a delimiter. A `\` before anything else is
   a literal `\`.
2. A **delimiter** is a maximal run of unescaped `*`. Its length is 1, 2, or ≥ 3.
3. Scan left to right. A delimiter of length 1 (italic) or 2 (bold) **opens** a
   span iff the *next* delimiter in the string has the **same length**; those
   two delimiters are consumed and the text between is one emphasised run. The
   scan resumes after the closing delimiter.
4. Every delimiter not consumed by rule 3 — length ≥ 3, unmatched, or followed by
   a delimiter of a different length — is emitted **literally**, as text of the
   surrounding run.
5. Consequence, pinned as examples RED should assert:
   - `"a *b* c"` → `[("a ",-,-), ("b",I,-), (" c",-,-)]`
   - `"a **b** c"` → bold `"b"`
   - `"a *b c"` → one regular run `"a *b c"` (unclosed → literal, AC-5)
   - `"**a *b* c**"` → `"**a "` regular, `"b"` italic, `" c**"` regular
     (nesting is rendered literally per §7)
   - `"***x***"` → regular `"***x***"` (length 3 is literal)
   - `"\*x\*"` → regular `"*x*"`
6. Adjacent runs with identical style are merged; empty runs are dropped. The
   `bold_italic` face is shipped and validated (AC-7) but **no markup reaches
   it** in this story — §7 renders nesting literally. `Run.face_key` still maps
   `italic and bold` → `"bold_italic"`.

### C-4 `src/mangatl/typeset/measure.py`

```python
@dataclass(frozen=True)
class RunMetrics:
    advance: float                                        # page px
    ink: tuple[float, float, float, float] | None         # x0, y0, x1, y1

def measure_run(text: str, face: Face, size_px: float) -> RunMetrics
```

- Scale `k = size_px / face.units_per_em`. `advance` is the sum of the `hmtx`
  advance widths of the cmap glyphs, times `k`. **No kerning, no GPOS, no
  ligatures** — one character, one glyph. MT-021 draws the glyphs at exactly the
  positions C-6 emits, so what is measured is what is drawn.
- `ink` is the union of the glyphs' ink bounds (fontTools `BoundsPen` over the
  glyph set, which works for `glyf` and `CFF` alike) relative to a pen at
  `x = 0` on a baseline at `y = 0`, **y growing downward**: `y0 = -yMax*k`,
  `y1 = -yMin*k`. `None` when no glyph has ink (spaces, empty string).
- A character absent from the face's cmap raises `MissingGlyph(char, face.key)`.
  It is never replaced with `.notdef` and never skipped.

### C-5 `src/mangatl/typeset/fit.py` — numbers and geometry

```python
MIN_SIZE_PX: float = 14.0        # == TOKENS["typeset.size-min"]
MAX_SIZE_PX: float = 42.0        # == TOKENS["typeset.size-max"]
SIZE_STEP_PX: float = 1.0        # == TOKENS["typeset.size-step"]
LINE_HEIGHT_RATIO: float = 1.08  # == TOKENS["typeset.line-height"]
FIT_INSET_RATIO: float = 0.12    # == TOKENS["typeset.padding-ratio"]

Polygon = Sequence[tuple[float, float]]   # a closed ring, last == first,
                                          # page px, y down; ints accepted
                                          # (Region.polygon is tuple[int,int]s)

def fitting_area(polygon: Polygon) -> shapely.Polygon   # may be empty
def line_widths(area: shapely.Polygon, size_px: float, n: int) -> list[float]
def break_lines(runs: Sequence[Run], widths: Sequence[float],
                faces: Faces, size_px: float) -> list[list[Run]] | None
```

One sentence per number:

- **Sizes are page pixels** and are em sizes (`size_px` is what `k` divides by).
  `typeset` tries `MAX_SIZE_PX, MAX − STEP, …, MIN_SIZE_PX` and takes the first
  size at which `layout_at` (C-6) succeeds — which makes AC-1's "largest" exact
  on that grid.
- **`LINE_HEIGHT_RATIO`**: line advance `a = size_px × 1.08`. Too small and
  ascenders of one line touch descenders of the next; too large and a block that
  would fit does not. The token is settled; it is not re-measured.
- **`FIT_INSET_RATIO`**: let `d = 0.12 × min(bbox_w, bbox_h)` of the *input*
  polygon's axis-aligned bounding box (the "short axis" of §7). The fitting area
  is the input polygon buffered **inward** by `d` with shapely's default round
  join (`polygon.buffer(-d)`) — the set of points at least `d` inside the
  outline. A rectangle `W × H` therefore yields the rectangle inset by `d` on
  every side, which is the hand-computable case RED tests against. If the buffer
  is a `MultiPolygon`, the fitting area is its largest-area part; if empty, it is
  empty and every size fails (AC-3).
- **The centre** `(cx, cy)` is the centre of the fitting area's bounding box.
  Lines are centred on `cx`, the block on `cy` (AC-2).
- **Line boxes.** For `n` lines at size `s`: `a = s × LINE_HEIGHT_RATIO`, block
  top `t = cy − n·a/2`, line `i` (0-based) occupies `y ∈ [t + i·a, t + (i+1)·a]`.
- **`line_widths(area, s, n)`** — the shape-aware part (PO-1). `w_i` is `2h` for
  the largest `h ≥ 0` such that the rectangle `[cx − h, cx + h] × line box i` is
  covered by the fitting area; `0.0` if none. In an ellipse this is narrow at the
  top and bottom and wide in the middle, which is what gives the diamond.
  Precision: `h` may be found by bisection; GREEN states the tolerance, and it
  must be ≤ 0.01 px.
- **Break opportunities** (AC-4): (a) any whitespace — a maximal run of
  characters `c` with `c.isspace() and c != " "` — which is collapsed to one
  U+0020 before breaking and is **consumed** by a break (not placed); and (b)
  immediately **after** a U+002D `-` that has a non-whitespace character on both
  sides, where the hyphen stays at the end of the line. Nothing else — no
  U+00A0, no en/em dash, no break inside a word, **no inserted hyphen**. Leading
  and trailing whitespace is stripped.
- **The objective** (AC-4, PO-1): for a break set giving lines `L_1..L_n` against
  widths `w_1..w_n`, a set is **feasible** iff `advance(L_i) ≤ w_i` for every
  `i`, and its cost is `Σ_{i=1..n} (w_i − advance(L_i))²` — **all lines, the last
  included**. `advance(L_i)` is the line's `measure_run` advances summed over its
  runs at the run's face, excluding a consumed break space. `break_lines(runs,
  widths, …)` returns the feasible split into **exactly `len(widths)` lines** of
  least cost, or `None` if none is feasible. Ties: the split whose tuple of break
  positions (character offsets in the normalised text) is lexicographically
  smallest. Implementation is free (DP is the obvious one); **greedy first-fit is
  not an implementation of this** and the suite must say so (falsifiable
  condition 2).
  - **Amended in RED (2026-10-02) - `break_lines`' input and output, which the
    block above left implicit and the tests have to read:** `runs` arrive
    already normalised (markers resolved, whitespace collapsed to single U+0020,
    stripped); `layout_at` normalises before calling, and behaviour on
    unnormalised runs is unconstrained. Each returned line is a list of `Run`s
    whose texts concatenate to that line's characters, **excluding the consumed
    break space** (a line never begins or ends with a consumed space) and
    **including a hyphen at a hyphen break**; every line is non-empty; each
    character keeps its run's style. How a line's characters are grouped into
    runs is not constrained - the tests compare characters and styles, not run
    boundaries. A break's "position" for the tie-break is the offset at which
    its line ends. *Reason:* AC-4's tests call `break_lines` directly (C-9), and
    could not state an expected value without these.

### C-6 `src/mangatl/typeset/fit.py` — the layout

```python
@dataclass(frozen=True)
class PlacedGlyph:
    char: str
    font_path: Path               # the face FILE this glyph is drawn from (AC-5)
    size_px: float
    x: float                      # pen position, left edge of the advance
    baseline_y: float
    advance: float
    ink: tuple[float, float, float, float] | None   # page px, y down

@dataclass(frozen=True)
class Line:
    glyphs: tuple[PlacedGlyph, ...]
    advance: float                # sum of glyph advances
    left: float                   # x of the first glyph's pen
    top: float                    # top of the line box
    height: float                 # == a

@dataclass(frozen=True)
class TypesetBlock:
    lines: tuple[Line, ...]
    size_px: float
    overflowed: bool
    text: str                     # the normalised, marker-free text (AC-3)

def layout_at(text: str, polygon: Polygon, faces: Faces,
              size_px: float) -> TypesetBlock | None
def typeset(text: str, polygon: Polygon, faces: Faces) -> TypesetBlock
```

- **`layout_at`** at size `s`: parse runs (C-3), normalise whitespace (C-5); for
  `n = 1, 2, …` while `n·a ≤` the fitting area's bbox height, compute
  `line_widths(area, s, n)` and `break_lines(...)`. Order the feasible
  candidates by `(cost, n)`; place each in turn (below) and return the first
  whose **every** non-`None` glyph ink box is covered by the fitting area
  (closed: touching the boundary is inside). `None` if none qualifies.
- **Placement.** Line `i` starts at `left = cx − advance(L_i)/2`; glyphs follow
  by advance. Baseline: `baseline_y = (t + i·a + a/2) + (ascender + descender)/2
  × k` — the face's hhea ascender–descender box is centred in the line box. A
  space inside a line is placed (it has an advance) with `ink=None`; a consumed
  break space is not placed. `ink` is the glyph's own ink box translated to its
  pen and baseline.
- **`typeset`** returns the first non-`None` `layout_at` from `MAX_SIZE_PX` down
  to `MIN_SIZE_PX`, with `overflowed=False`. If none: **`overflowed=True`** at
  `MIN_SIZE_PX`, laid out with one uniform width `W` = the fitting area's bbox
  width (the input polygon's, if the area is empty) — `break_lines` with
  `[W]*n` for the least `n` that is feasible once any single word wider than `W`
  is allowed a line of its own — and placed with the same rules, centred on the
  same centre. The overflow layout may cross the outline; that is what the flag
  reports to MT-016's `overflow` status.
  - **Amended in RED (2026-10-02):** when the fitting area is empty, "the same
    centre" is the centre of the **input polygon's** bounding box, as `W` already
    is its width. *Reason:* an empty geometry has no bounding box, so C-5's
    centre is undefined exactly in the case AC-3 requires a layout for.
- **Nothing is truncated** (AC-3): `block.text` is the input with markers
  resolved and whitespace normalised, and the placed glyph characters of
  `block.lines`, joined with `" "` at a whitespace break and `""` after a
  hyphen break, equal `block.text`. This holds for every result, overflowed or
  not.
- **Empty text** (or whitespace only): zero lines, `size_px == MAX_SIZE_PX`,
  `overflowed=False`, `text == ""`.
- **Determinism** (AC-6): two calls with equal arguments return `==` blocks with
  equal `repr()`; and a `Faces` loaded from a byte-identical copy of the font
  directory elsewhere yields an equal block except for `font_path`'s directory.
  No randomness, no system font lookup, no set iteration order in the output.

### Things that should shape the implementation

- `ruff`'s RUF001 rejects literal U+00A0, dashes and curly quotes in source
  strings. Use `\u` escapes in `font.py` (REQUIRED_CODEPOINTS) as the tests do.
- `test_typeset_measure` uses "AV To" (kerning pairs) and compares with the
  plain `hmtx` sum to `rel=1e-12`. Kerning or GPOS would fail it.
- The Ellipse `line_widths` comparison allows 0.021 px. An `h` found by
  bisection to 0.01 px fits within it, either conservative or generous.
- The overflow tests assert the line **count** equals the fewest lines at width
  W (`fitting area bbox width`, 50.4 for SMALL; input bbox width 100 for THIN),
  where a word wider than W gets a line of its own. They assert centring on
  (30, 20) and (50, 50) respectively. They do not pin which overflow split is
  chosen.
- Empty text must equal `TypesetBlock(lines=(), size_px=42.0, overflowed=False,
  text="")` exactly, tested in RECT only. The contract does not say what empty
  text in an empty fitting area gives, and no test pins it.
