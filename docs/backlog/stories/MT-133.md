## Context

EPIC-05 owns the theme. `components.md` §9 (lines 1160-1163, `ErrorBanner`):
ground `color.surface.raised`, **1px and a 3px leading bar** in
`color.status.danger`. The base rule (`docs/wiki/design/theme.qss.in` 573-578,
`QFrame#error-banner`) draws the bar as `@{border-width.emphasis}px` - 2px -
and its own comment (570-571) says why: "section 9 says 3px and no token holds
3". That was MT-018's recorded compromise (MT-018.md 724-726), never a design
decision. MT-132 added the token it was missing, `border-width.bar = 3`
(`tokens.toml` 207), used it for the High Contrast bar, and deferred the base
explicitly (MT-132.md Notes PO-1, 646-647: "the base banner's own 2px bar (§9
says 3) could follow later; not here"). Nothing supersedes §9, so this story
is that follow-up: one placeholder swap in the base template, regenerated into
the packaged sheet, pinned by a paint test. The Lead Designer's read-only check
(2026-11-03, against origin/main f1b2c15) is the source of the line numbers
above; the Lead PO re-read every cited line in this worktree before cutting it.

The failing test that reproduces the 2px bar is the permanent regression test:
MT-132's AC-3 control
`test_control_under_the_packaged_sheet_the_banner_leading_bar_is_two_pixels_of_danger`
(`tests/ui/test_hc_error_banner_border.py` 374-396) pins the base bar at
exactly 2px and is therefore *wrong* once §9 is honoured. RED replaces it with
the 3px version and records why under `## Regressions` - it fails against the
unchanged sheet for the right reason, so it earns itself the ordinary way.

The required gate that fails if the artifact breaks: `unit` (and `coverage`,
the same suite instrumented) over `tests/ui`, which hold the paint test and
`test_tokens.py`'s template/sheet agreement checks. The `tokens` task
(`uv run python -m mangatl.ui.tokens`) regenerates the artefacts and
`test_tokens.py` fails if the committed ones drift from the source.

## Acceptance criteria

- **AC-1** - *The bar is 3px in the base.* Given the packaged `theme.qss` set
  as the **application** stylesheet (never `styleSheet()` on the widget) and a
  shown `ErrorBanner`, when its left edge is sampled line by line (line *n* =
  *n* pixels in from the edge, `radius.sm + border-width.bar` pixels skipped at
  each end), then lines 0, 1 and 2 are every pixel `color.status.danger` and
  line 3 is every pixel `color.surface.raised`.
- **AC-2** - *Control: the frame on the other three edges stays a hairline.*
  Given the same sheet and banner, when the top, bottom and right edges are
  sampled the same way, then line 0 is every pixel `color.status.danger` and
  line 1 is every pixel `color.surface.raised` - the bar widened, the frame did
  not. (MT-132's AC-3 frame-edge control, unchanged, is the test.)
- **AC-3** - *Control: High Contrast is unchanged.* Given the sheet composed
  for High Contrast with the five-role test palette, when the banner's four
  edges are sampled, then the top, bottom and right edges are lines 0-1
  `WindowText` and line 2 `Window`, and the left edge is lines 0-2
  `WindowText` and line 3 `Window` - exactly what MT-132's AC-1 and AC-2 pin
  today. The HC rule still restates both widths after the base change.
- **AC-4** - *The template says `bar`, not a number.* Given
  `docs/wiki/design/theme.qss.in` (and its byte-identical copy
  `src/mangatl/ui/theme.qss.tmpl`), when the `QFrame#error-banner` rule's
  declarations are parsed, then its `border-left` value reads
  `@{border-width.bar}px solid @{color.status.danger}` and no declaration in
  that rule carries a literal pixel number; and the rendered
  `src/mangatl/ui/theme.qss` carries `border-left: 3px solid #FF7A7A` for that
  rule - the value `tokens_gen.TOKENS["border-width.bar"]` renders to.

No AC names a statistic or threshold; every one is an exact pixel-colour or
parsed-text pin, so the negative control is the defect put back (see
`## Deferred verifications`).

### C-1 The base rule (`docs/wiki/design/theme.qss.in` 568-578)

Today:

```
/* The danger variant, the only one built so far. The leading bar is      */
/* border-width.emphasis: section 9 says 3px and no token holds 3.        */

QFrame#error-banner {
    background-color: @{color.surface.raised};
    border: @{border-width.hairline}px solid @{color.status.danger};
    border-left: @{border-width.emphasis}px solid @{color.status.danger};
    border-radius: @{radius.sm}px;
}
```

After GREEN: line 576 reads
`    border-left: @{border-width.bar}px solid @{color.status.danger};` and the
comment at 570-571 no longer claims no token holds 3 - it says the bar is
`border-width.bar` per §9 (MT-133), inside the file's existing 76-column
`/* ... */` box style. Every other declaration of the rule is unchanged:
`border:` stays `hairline` (AC-2), `border-radius` stays `radius.sm`, the
`border:` shorthand stays **before** `border-left` (a shorthand after it would
reset the bar). No other rule in the file changes - the `emphasis` uses at
236-255 (dashed focus, accent, danger frames on other widgets) are not the
banner's.

**The semantics of 3.** `border-width.bar = 3` is the width §9 and §10.7 give
the leading bar; it is wider than `emphasis` (2) so a bar reads as a bar
inside any frame the sheet draws, and it is the inset the paint test already
uses (`_inset() = radius.sm + bar = 4 + 3`), so widening the bar does not move
the sampling window.
