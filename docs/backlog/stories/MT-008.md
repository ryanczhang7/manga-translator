## Context

Open question **O6**, half of it. `docs/wiki/stack.md` §5/O6 and
`architecture.md` D11.

Japanese bubble text is frequently annotated with furigana — small ruby kana in
a thin column beside the main column. A detector emits that column as its own
region, and a region is an utterance: it gets its own line on the review screen,
its own translation, and its own bubble marker on the art. A phantom bubble is
worse than a missed one, because it costs the human attention on every page and
teaches them to distrust the markers.

So ruby is folded in **before** OCR, at the region level. `manga-ocr` separately
ignores ruby *inside* a crop, which covers the case where the detector merged
them already — but it does nothing about a phantom region, which is why this
story exists.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core`. This is pure geometry on region boxes; no model, no GPU.

## Acceptance criteria

- **AC-1** — Given a main text column and a thin adjacent column within
  `FURIGANA_MAX_GAP_PX` of it, whose short-axis extent is below
  `FURIGANA_MAX_RATIO` of the main column's, when merging runs, then one region
  is produced whose polygon covers both and whose `merged_from` records the
  absorbed region.
- **AC-2** — Given two adjacent columns of *comparable* short-axis extent, when
  merging runs, then **two** regions are produced and neither records a merge.
- **AC-3** — Given a thin column separated from any main column by more than
  `FURIGANA_MAX_GAP_PX`, when merging runs, then it survives as its own region.
- **AC-4** — Given a fixture page carrying furigana on every bubble, when
  detection and merging run, then the region count equals the region count of
  the same page with the ruby digitally removed.
  *Control:* with merging disabled, the counts must differ by at least the
  number of annotated ruby columns — otherwise the assertion passes because the
  detector was never emitting ruby regions and AC-4 is measuring nothing.
- **AC-5** — Given a fixture page with two genuinely separate small bubbles
  close together, when merging runs, then they are **not** merged.
- **AC-6** — Given a merged region, when its mask is inspected, then it is the
  union of the merged regions' masks and nothing else.
- **AC-7** — Given horizontal text with ruby *above* it rather than beside it,
  when merging runs, then the same rules apply on the transposed axis.

## Contract

```
src/mangatl/detect/furigana.py
    FURIGANA_MAX_GAP_PX: int          # settled in GREEN from fixture measurement
    FURIGANA_MAX_RATIO: float         # ditto
    def merge_ruby(regions: Sequence[RawRegion]) -> list[RawRegion]

src/mangatl/domain/region.py          # extended by this story
    RawRegion.merged_from: tuple[int, ...]   # indices into the input sequence
```

**Semantics behind each number — this is where a sign or an axis error lives:**

- **"Thin" is measured on the axis perpendicular to the text's run direction.**
  For vertical text, ruby is a narrow column *beside* the main column, so the
  compared extent is **width**. For horizontal text it is *above*, so the
  compared extent is **height**. AC-7 exists because a rule written for one axis
  and applied to both is the default mistake here.
- **`FURIGANA_MAX_RATIO`** is the maximum ratio of ruby extent to main extent.
  Japanese ruby is conventionally about half the main glyph size, so the
  threshold sits above 0.5 and below 1.0 — GREEN measures it on the fixtures and
  records both failure directions. Too high and AC-5 breaks (real bubbles
  merge); too low and AC-1 breaks (ruby survives as a phantom).
- **`FURIGANA_MAX_GAP_PX`** is the maximum edge-to-edge distance, in page
  pixels, and therefore scales with scan resolution. **State in `## Notes` what
  page width it was measured at**, and express it as a fraction of page width if
  the fixtures show it varying. A pixel constant measured on one scan size and
  applied to another is a latent failure.
- **`merged_from` is indices into the input sequence, not ids**, because regions
  have no database identity until MT-005 stores them.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1, AC-2, AC-3, AC-6, AC-7 | **Mechanical** | Synthetic region boxes constructed by hand. These are arithmetic on rectangles; enumerate the boundary cases at exactly the threshold, one pixel inside, one pixel outside. |
| AC-4, AC-5 | **Oracle-free** | These are about real pages. Invent the comparison, and the control in AC-4 is mandatory: a count-equality assertion is satisfied trivially by a detector that emits nothing. |

**The threshold pair is the whole story, and both thresholds move together.**
Any change to one during GREEN must be re-checked against AC-5, and any change
made to reach green on AC-4 that breaks AC-5 is not a fix.

## Deferred verifications

- *Falsifiable condition 1:* with `merge_ruby` replaced by the identity
  function, AC-1, AC-4 and AC-6 **must** fail.
- *Falsifiable condition 2:* with `FURIGANA_MAX_RATIO` set to `1.5` (merge
  anything adjacent), AC-2 and AC-5 **must** fail.
- *Falsifiable condition 3:* with the axis selection **transposed** — width
  compared where height should be — AC-7 **must** fail, and AC-1 should still
  pass, which is what makes it a sharp test of the axis logic rather than of the
  merge logic.
- *Why RED cannot run these:* no implementation exists.
- **Owner: GATES.** Three mutations via `bash scripts/mutate.sh`; the third is a
  wrong *value* (an axis) rather than a removed behaviour.

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition is mixed** (table above) and must go into the dispatch
  prompt verbatim: the geometry criteria are to be pinned exactly and the two
  page-level criteria are where a metric is invented and a control is demanded.
- **Success condition, falsifiable:** RED produces boundary cases *at* each
  threshold rather than comfortably either side of it, and AC-4's control
  separates the merging and non-merging runs by at least the annotated ruby
  count. A suite whose AC-4 assertion would pass against an empty detector has
  failed RED.
- **Verdict:** *to be recorded.*
