## Context

Filed by the mutation audit `docs/wiki/audits/EPIC-05-2026-10-27.md`,
survivors **WS29** and **WS30** (`## Decided` 2, `## Evidence` E-2 items 1 and
2). **HIGH priority.**

EPIC-05's done-when is "edit a line, revert it, close the app, reopen it and
find their edits". The shipped code honours it for an edit in progress as
well. `TranslationColumn.flush()` (`src/mangatl/ui/workspace.py:826-832`)
clears focus from a focused editor first, which commits a dirty field the way
leaving it would (MT-017 C-7 row 11), and only then flushes. Both
`closeEvent` (`:1284`) and a page change (`_load_regions` `:1123`, `set_rows`
`:779`) call it.

**No EPIC-05 test types without pressing Enter and then closes or changes
page.** `test_closing_the_workspace_writes_a_pending_save` (`:691`),
`test_changing_page_writes_a_pending_save_before_the_rows_are_replaced`
(`:673`) and AC-6's round trip (`:707`) all commit by key first. Measured at
the audit's base (`73b7b10`):

- **WS30.** `set_rows` and `_load_regions` each flush the rows' editors
  directly, bypassing `TranslationColumn.flush()`. This survives **all of
  `tests/ui`** (1744 passed).
- **WS29.** `closeEvent` does the same. It survives
  `tests/ui/test_line_review_workspace.py`, `test_workspace.py`,
  `test_line_editor.py` and `test_app_opens_chapter.py` (176 passed). Across
  `tests/ui` the only signal is a *teardown* `sqlite3.ProgrammingError` in
  `test_theme_apply.py`, caused by a stray late save. That is not an
  assertion about this behaviour.

Under either mutant, a user who types a correction and closes the window, or
moves to another page, before pressing Enter loses it. Nothing reaches the
project file.

**Settled (audit `## Decided` 2, do not re-litigate):** the shipped code is
correct, and this story only adds tests.

**Evidence to verify, not assume:** the two survivals above. RED re-runs each
mutant (DV-1) against the new tests before relying on it.

Required gate that fails if this breaks: `unit` and `coverage`, which collect
`tests/ui/test_line_review_workspace.py`. Confirmed at PLANNED against
`bash scripts/gates.sh --list`: both are `required` and run
`uv run pytest -q tests/core tests/ui`, so `required_gates` stays `[]`.

**Epic done-when check (PLANNED).** EPIC-05's "edit a line, revert it, close
the app, reopen it and find their edits" is what AC-1 pins for the edit in
progress; AC-2 is the same promise across a page change. No gap between the
done-when and these criteria, and nothing to narrow, so no PO decision is
needed here.

## Acceptance criteria

- **AC-1** - Given a workspace showing page 1 of a project, with a line's
  editor focused and text typed into it and **no Enter pressed**, when the
  window is closed, then the project file, read with a separate `sqlite3`
  connection, holds that text as the line's `final_en` with status `edited`.
  Fails under WS29.
- **AC-2** - Given the same situation, when the user changes to page 2 instead,
  then the project file holds page 1's typed text as that line's `final_en`
  with status `edited`, and page 2's lines are unchanged. Fails under WS30.
