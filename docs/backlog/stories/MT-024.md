## Context

Brief section 6, a hard constraint: "Installation must not require the user to
manage Python environments, model weights or GPU setup by hand." And section 2:
"What they should *not* be assumed to know: machine-learning tooling, Python
environments, model weights, GPU configuration."

`architecture.md` §8 is the deployment shape. `docs/wiki/stack.md` §3 names the
tools. Two things in this story are checks rather than builds, and they are the
reason it is a story rather than a script:

- **the frozen tree must contain what it must and exclude what it must not** —
  a hidden import PyInstaller cannot see statically fails at the user's first
  launch and nowhere earlier;
- **`.claude/`, `docs/`, `scripts/` and `.github/` never ship**
  (`rules.md`: agentic scaffolding never ships in a production image). Asserted
  over the built tree, not promised in the spec file.

**What the tree looked like when this story was planned (lead-po, 2026-10-08,
measured, not assumed):**

- `dist/mangatl/` from the last `build` gate run (22:52 today) is **501 MB** and
  holds `onnxruntime/capi/onnxruntime_providers_cuda.dll` but **none of the
  `nvidia-*` DLLs** (`find dist/mangatl -iname '*cublas*' -o -iname '*cudnn*'`
  is empty). The frozen app today would fall through to CPU silently (MT-002
  E2). The DLLs the CUDA provider needs are in the venv:
  `nvidia/cu13/bin/x86_64/*.dll` (10 files) and `nvidia/cudnn/bin/*.dll` (10
  files), 1,580 MiB together; `onnxruntime/` is 218 MiB.
- The weights live under gitignored `spikes/MT-002/models/**` on this machine
  only: not on CI, not in any worktree (`environment.md`, "The `integration`
  gate needs a checkout that has `spikes/`").
- `onnxruntime-directml` cannot be installed beside `onnxruntime-gpu`
  (`architecture.md` D3's correction; `stack.md` §3). The locked runtime is
  `onnxruntime-gpu[cuda,cudnn]==1.30.0`.
- Inno Setup was installed nowhere. It is now (PO-4 below).
- `src/mangatl/app_paths.py` exists with `settings_path()` (MT-027). The three
  theme artefacts `theme.qss`, `theme.qss.tmpl`, `theme_hc.qss.tmpl` sit in
  `src/mangatl/ui/` and are read through `importlib.resources`
  (`mangatl.ui.stylesheet`); the spec has **no** `datas` entry for them, so the
  frozen app fails at launch today (MT-061 PO-1).
- `tests/core/test_typeset_packaging.py` **executes the spec** with stub
  `Analysis`/`PYZ`/`EXE`/`COLLECT` and no weights present. The spec must
  therefore never stat a weight file at analysis time; presence is the fetch
  step's job (C-1).

**Which required gate would fail if this story's artifact broke:** `build`
(required, `slow`) produces the tree; the new **`frozen`** gate (required,
`slow`, runs after `build`) is the one that reads it — `uv run pytest -q
tests/frozen`. It is a separate gate because `unit` runs *before* `build` in
`project.conf`, so a tree test in `tests/core` would judge a stale or absent
`dist/`. `installer` is optional for the repository and required for this
story (frontmatter), with a `blocked-when` for a machine without ISCC.

## Acceptance criteria

- **AC-1** — Given a checkout with no `packaging/models/`, when
  `bash scripts/gates.sh --gate build` runs, then the gate first fetches every
  file named in `packaging/models.json` from Hugging Face by pinned revision,
  verifies each SHA-256, and then PyInstaller produces `dist/mangatl/mangatl.exe`
  in a one-folder tree. A fetch whose bytes do not match the manifest exits
  non-zero naming the file, leaves no partial file behind, and no build runs.
- **AC-2** — Given the built tree, when it is inspected, then every entry in the
  manifest exists at `dist/mangatl/_internal/models/<path>`, each file's SHA-256
  matches the manifest, and `_internal/models/models.json` is byte-identical to
  `packaging/models.json`.
- **AC-3** — Given the built tree, when it is inspected, then it contains the
  four Shantell Sans static faces and `OFL.txt` at
  `_internal/mangatl/typeset/fonts/`, byte-identical to the vendored files.
- **AC-3b** — Given the built tree, when it is inspected, then
  `_internal/mangatl/ui/` holds `theme.qss`, `theme.qss.tmpl` and
  `theme_hc.qss.tmpl`, each byte-identical to the package resource. *(`tokens.md`
  §12.1: the High Contrast sheet is composed at runtime from the template and the
  live palette, so the template is a shipped asset, not a build-time input.)*
- **AC-4** — Given the built tree, when every path under `dist/mangatl/` is
  walked, then **none** has a first component under `_internal/` equal to
  `.claude`, `docs`, `scripts`, `.github`, `tests`, `fixtures`, `spikes` or
  `packaging`, and no path under `_internal/mangatl/` has any component equal to
  one of those names. The forbidden set is an explicit list in the test, and the
  walk is over the real tree, never over the spec.
- **AC-5** — Given a models directory and its manifest, when
  `verify_bundled_models(root)` runs, then it returns `None` when every file is
  present with the manifest's SHA-256, and raises `ModelHashMismatch` — whose
  message names the file and says whether it is missing or which hash it had —
  for the first file that is not. Given the application starting with a bundled
  models directory present, when one file does not verify, then `main` builds a
  notice window carrying that message, never calls `build_window`, and returns
  `1`.
- **AC-6** — Given a list of provider names, when `select_providers(available)`
  runs, then it returns the names of `PROVIDER_PREFERENCE` that are in
  `available`, in preference order, with `CPUExecutionProvider` always last and
  always present; and `build_pipeline` requests
  `select_providers(available_providers())` rather than a constant, then logs
  `inference provider: <name>` at INFO on the `mangatl.compose` logger, where
  `<name>` is `selected_provider(detector)` — the provider actually in use, not
  the one requested.
- **AC-7** — Given the built tree, when `dist\mangatl\mangatl.exe --check
  <report-file>` runs, then it exits `0` and the report file holds exactly the
  six lines of C-6 — the theme, both templates, the fonts, the models (count
  verified) and the provider in use — and when the same binary is run with one
  bundled weight altered, it exits `1` and the `models:` line names the file.
  *(This is the "installed app loads them" check MT-025 PO-8 and MT-061 PO-1
  asked for, and the only place a frozen `importlib.resources` lookup is ever
  exercised.)*
- **AC-8** — Given the built tree, when `bash scripts/gates.sh --gate installer`
  runs, then Inno Setup compiles `packaging/installer.iss` into exactly one file,
  `dist/installer/mangatl-setup.exe`, and the script installs per-user (no
  elevation), 64-bit only, from `dist\mangatl\*` recursively. *(The final clause
  of the original AC-8 — installing on a machine with no Python present yields a
  working application — is verified on a clean Windows 11 machine or VM once, by
  hand, and recorded in `## Notes` with the date and the machine. It cannot be a
  gate and must not be pretended to be one.)*
- **AC-9** — Given `resolve_models_dir(override, env, bundled)`, when `override`
  is `None` and `env` names no directory, then it returns `bundled` if that is an
  existing directory, and raises `ModelsNotFound` as before when it is not — so
  `$MANGATL_MODELS` still wins over the bundled weights, and a checkout with no
  fetched weights behaves exactly as today. `app.resolve_models()` and
  `mangatl-run` both pass the bundled directory.

**Moved out of this story (PO-3):** the first-run API-key dialog and the
`settings.json` write (the original AC-7) are **MT-077**; the five D13 notice
obligations are **MT-076**. Both depend on this story and both are in EPIC-07's
story list, so the epic cannot close without them.

- `path` is the location **under the models directory**, and it is C-6 of
  MT-036 exactly: `compose.DETECTOR_FILENAME`, `compose.INPAINTER_FILENAME`,
  `compose.OCR_SUBDIR / ocr.session.{ENCODER,DECODER,VOCAB}_FILENAME`. A test
  asserts the five `path` values against those constants, so the manifest cannot
  drift from the layout `build_pipeline` reads.
- The five SHA-256 values and byte counts are **settled** — MT-002's
  `## Decided`, `[MEASURED]`. Read them out; never re-derive.
- The four `revision` values are the repositories' `main` commit SHAs read from
  the Hugging Face API on **2026-10-08** by the PO (`curl
  https://huggingface.co/api/models/<repo>` → `"sha"`). **A baseline, not a
  verified pairing**: nobody has yet fetched these files *at these revisions*
  and hashed them. GREEN's first fetch is that verification; if a file at its
  pinned revision does not hash as the manifest says, that is a finding to
  record under `## Notes`, and the fix is a revision that does, not a hash that
  matches whatever came down.
- The fetch URL is `https://huggingface.co/{repo}/resolve/{revision}/{file}`,
  followed through redirects, streamed to `packaging/models/{path}.part`,
  hashed while streaming, and renamed to `{path}` only when the hash matches;
  on mismatch the `.part` is removed and the script exits `1` naming the file,
  the expected hash and the one it got. A file already present with the right
  hash is not downloaded (so a developer downloads 728 MB once, and CI with a
  warm cache not at all). The downloader is `urllib.request` — **no new
  dependency**. It is injectable: `fetch_all(manifest, target, opener=urlopen)`
  so `tests/core/test_fetch_models.py` runs it against a fake opener serving
  bytes of its choosing, and the mismatch branch is a negative control that
  runs on every machine.
- `packaging/models/` is gitignored (added by the PO; classifies `ignored`).

### C-4 — `packaging/mangatl.spec`

Executed by `tests/core/test_typeset_packaging.py` with stubs and no weights, so

  under `<site-packages>/nvidia/cudnn/bin/` to `nvidia/cudnn/bin`, located
  through `importlib.util.find_spec("nvidia")` rather than a hard-coded venv
  path. **Checkable, not sacred:** whether `ort.preload_dlls(cuda=True,

  claim the PO has not measured. GREEN verifies it by running
  `dist\mangatl\mangatl.exe --check` on this machine and reading
  `provider: CUDAExecutionProvider`; if it reads CPU, the DLLs are in the wrong

  `os.add_dll_directory` before the preload in `mangatl.app`) is GREEN's to find
  and record under `## Notes`.
- `excludes` and everything else: unchanged.

### Settled decisions

- **The manifest is the source of truth for weights**, for the fetch and for
  the startup check alike. A silently substituted weight is a correctness
  failure with no symptom until the output is wrong.
- **The exclusion list in AC-4 is asserted by walking the built tree**, not by
  reading the spec file.
- **Do not subset the font** (`typeset-font.md` §5). Ship the four faces whole.
- **Code signing is not in scope**: an unsigned installer produces a SmartScreen
  warning (`stack.md` §8 open question).
- **Startup hashing cost is measured, not guessed.** 728 MB through `hashlib`
  on every launch is the price of AC-5; GATES records the wall time of
  `--check` and of the startup check under `## Notes`. If it is over ~3 s on this
  machine, that is a finding for a follow-up story (an mtime/size cache), not a
  reason to weaken AC-5 here.

**Oracle partition: entirely mechanical**, with one exception. AC-1 to AC-9 are
tree walks, hash comparisons, a parsed `.iss`, a pure provider-selection
function and an exact report format. AC-8's clean-machine clause is a **manual
verification**, once, recorded. Nothing here is oracle-free.
