## Context

Brief section 6, a hard constraint: "Installation must not require the user to
manage Python environments, model weights or GPU setup by hand." And section 2:
"What they should *not* be assumed to know: machine-learning tooling, Python
environments, model weights, GPU configuration."

`architecture.md` §8 is the deployment shape. `docs/wiki/stack.md` §3 names the
tools. Two things in this story are checks rather than builds, and they are the
reason it is a story rather than a script:

- **the frozen tree must contain what it must and exclude what it must not** —
  a hidden import PyInstaller cannot see statically fails at the user's first
  launch and nowhere earlier;
- **`.claude/`, `docs/`, `scripts/` and `.github/` never ship**
  (`rules.md`: agentic scaffolding never ships in a production image). Asserted
  over the built tree, not promised in the spec file.

**Which required gate would fail if this story's artifact broke:** `build`,
which is already required and already `slow`. The tests over the built tree run
in `unit` against a build produced by the `build` gate.

## Acceptance criteria

- **AC-1** — Given a clean checkout, when `bash scripts/gates.sh --gate build`
  runs, then PyInstaller produces a one-folder tree containing the application
  executable.
- **AC-2** — Given the built tree, when it is inspected, then it contains every
  `.onnx` weight named in the model manifest, and each file's SHA-256 matches the
  manifest.
- **AC-3** — Given the built tree, when it is inspected, then it contains the
  four Shantell Sans static faces and `OFL.txt`.
- **AC-3b** — Given the built tree, when it is inspected, then it contains
  **both QSS templates** emitted by MT-025 — the placeholder template and the
  High Contrast override template. *(`tokens.md` §12.1: the High Contrast sheet
  is composed at runtime from the template and the live palette, so the template
  is not a build-time input but a shipped asset. Reaching back at a `docs/` path
  would work on a developer machine and fail in the installer, which is the one
  place no other gate can see — and AC-4 excludes `docs/` from the build.)*
- **AC-4** — Given the built tree, when it is inspected, then **no path under it
  matches** `.claude/`, `docs/`, `scripts/`, `.github/`, `tests/` or `fixtures/`.
- **AC-5** — Given the built application, when it starts, then it verifies every
  weight's hash against the manifest and refuses to start — with a named error —
  if one does not match.
- **AC-6** — Given the built application on a machine with no CUDA toolkit, when
  it starts, then it selects the DirectML or CPU execution provider and reports
  which, rather than failing.
- **AC-7** — Given the built application on first run, when it starts, then it
  asks for an API key and writes it to `%APPDATA%\mangatl\settings.json`, and
  that is the **only** setup step — no environment, no weight placement, no GPU
  configuration.
- **AC-8** — Given the built tree, when the installer script runs, then it
  produces a single installer file, and installing it on a machine with no Python
  present yields a working application.
  *(AC-8's final clause is verified on a clean Windows 11 machine or VM once, by
  hand, and the result recorded in `## Notes`. It cannot be a gate and must not
  be pretended to be one.)*

## Contract

```
packaging/mangatl.spec          # PyInstaller spec; datas = weights + fonts + theme.qss
packaging/models.json           # the model manifest: name, filename, sha256, licence
packaging/installer.iss         # Inno Setup script
src/mangatl/app_paths.py
    def bundled_dir() -> Path        # sys._MEIPASS when frozen, repo root otherwise
    def settings_path() -> Path      # %APPDATA%/mangatl/settings.json
src/mangatl/models/manifest.py
    def verify_bundled_models(root: Path) -> None
    class ModelHashMismatch(Exception)
src/mangatl/models/providers.py
    PROVIDER_PREFERENCE: tuple[str, ...]   # CUDA, DirectML, CPU — in that order
    def select_providers(available: Sequence[str]) -> list[str]
```

**Settled decisions:**

- **`PROVIDER_PREFERENCE` is CUDA → DirectML → CPU** (`architecture.md` D3).
  `select_providers` is a **pure function over a provider list** and is tested in
  `tests/core/` against fake lists — which is what makes AC-6 assertable without
  three machines.
- **The manifest is the source of truth for weights**, and the hash check runs at
  startup (AC-5). A silently substituted weight is a correctness failure with no
  symptom until the output is wrong.
- **The exclusion list in AC-4 is asserted by walking the built tree**, not by
  reading the spec file. `rules.md` names `.dockerignore` honesty as the standing
  form of this rule; there is no container here, so the spec is the analogue and
  the walk is the check.
- **Do not subset the font** (`typeset-font.md` §5, Reserved Font Name). Ship the
  four faces whole.
- **Code signing is not in scope** and is a known consequence: an unsigned
  installer produces a Windows SmartScreen warning on the user's own machine.
  Recorded in `stack.md` §8 as an open question rather than silently accepted.

**Oracle partition: entirely mechanical**, with one exception. AC-1–AC-7 are
tree walks, hash comparisons and a pure provider-selection function. AC-8's
clean-machine clause is a **manual verification**, once, recorded — it is not
oracle-free, it is simply not automatable here, and saying so is better than
writing a test that pretends.

## Deferred verifications

- *Falsifiable condition 1:* with one weight's hash altered in the manifest,
  AC-5 **must** fail (the app refuses to start).
- *Falsifiable condition 2:* with `docs/` added to the spec's `datas`, AC-4
  **must** fail. This is the probe that makes the exclusion real rather than
  aspirational.
- *Falsifiable condition 3:* with `PROVIDER_PREFERENCE` reordered to put CPU
  first — a wrong value rather than a removed behaviour — AC-6's "reports which"
  assertion **must** change, and a test asserting only "it started" would not
  notice. Make sure one does.
- **Owner: GATES.** Three mutations via `bash scripts/mutate.sh`.

### Shipping obligations this story inherits — added by MT-030, 2026-09-12

**Written here by MT-030's orchestrator, not by this story's PO, and
deliberately *not* as an acceptance criterion.** Whoever plans MT-024 decides
how to discharge these and writes the AC; what would be wrong is for them to
find out at RED that a shipped installer carries obligations nobody recorded.
An obligation living only in an audit is what this project keeps discovering
the hard way. Evidence: `docs/wiki/audits/MT-030-detector-licence.md`.

This story currently mentions licensing exactly once — `packaging/models.json`
carrying a `licence` field per model (line ~76). **That is metadata about the
weights, not a notice shipped to the user**, and the two are not the same
artifact.

**Obligation 1 — Manga109-s attribution. Live if the detector is the incumbent,
which as of MT-030 it is.** The detector is trained 1/3 on Manga109-s, whose
published terms permit exactly what this product does (commercial use of
results from machine-learning experiments) subject to one binding condition,
quoted verbatim:

> When publishing results (including pre-trained models) obtained from machine
> learning experiments or image processing experiments, the use of the
> Manga109-s dataset must be indicated clearly within the published work.

Note what this is **not**: MT-030 established that the academic-only reading of
Manga109-s recorded across the tree was **false**, and corrected it. The
surviving obligation is attribution and it is cheap. It falls away only if the
user commissions a detector trained on other data.

**Obligation 2 — GPL-3.0, and it is not yet decidable.** The incumbent detector
is GPL-3.0 upstream, this app is *distributed*, and **MT-030 found no
permissively-licensed replacement clearing its floor.** The choice between
shipping GPL-3.0 knowingly and commissioning a detector **is open and is the
user's** — it is not MT-024's to make. But MT-024 is where it lands: if the
answer is "ship it", the installer carries the licence text and the
written-offer / source obligations that follow, and their absence should fail
this story. MT-030 records this as **DV-2**, owner MT-024, falsifiable
condition stated there.

**Do not write an AC for Obligation 2 until the user has decided.** Its content
depends on the answer, and a criterion frozen against a guess is worse than an
absence. Obligation 1 is decidable now.

## Out of scope

will be none. macOS or Linux builds, a brief non-goal. Downloading weights at
first run, which is exactly what the brief's installation constraint forbids.
Bundling a CUDA toolkit.

### Installer size: the inference runtime is 1.75 GB, and MT-002 left the call to this story

Measured by MT-002 on 2026-09-12; full numbers in
`docs/wiki/audits/MT-002-model-runtime.md` E8. **Re-verify them — they are
`## Evidence`, not `## Decided`.**

| | MiB |
|---|---|
| `nvidia/cu13` (cuBLAS, cuFFT, cuRAND, nvrtc, nvJitLink, runtime) | 1,015 |
| `nvidia/cudnn` | 565 |
| `onnxruntime-gpu` wheel | 218 |
| the five model weights | 728 |
| **total inference footprint** | **≈ 2,526 MiB** |

For comparison, `onnxruntime-directml` cp312 is a **15.4 MB** wheel and CPU-only
`onnxruntime` is **5.6 MB**, neither with any NVIDIA dependency — but the latest
cp312 DirectML build is **1.17.3**, well behind the 1.30.0 the CUDA path uses.

**Three questions MT-002 deliberately did not answer, all of which move the
installer by more than a gigabyte:**

1. Ship DirectML by default and make CUDA an **opt-in download**? This is the
   big one, and it is a product decision about what "one double-click installs
   the app" should mean.
2. Can **cuDNN (565 MiB)** be pruned, given which kernels these three models
   actually use? Untested.
3. The fp16 OCR exports (`encoder_model_fp16.onnx`, `decoder_model_fp16.onnx`)
   would cut the weight bundle **728 → ~508 MiB**. **No accuracy measurement was
   made on them** — do not adopt without re-running the audit's E5 ground-truth
   scoring.

Note this interacts with AC-2's hash manifest: an opt-in CUDA download is a
second set of files to pin and verify, not just a smaller build.
