## Context

EPIC-09 PO-2's second half: the run proposes the glossary **once**, before
page 1, and the result is fixed for every page. MT-104 built the call; this
story runs it from the pipeline, guarded (D6: before the call), ledgered as a
chapter-level row (MT-103), and once per chapter.

`run_chapter` (`pipeline/runner.py:102`) walks pages through per-page
stages; nothing in it runs once for the chapter. The runner gains a
keyword-only `prelude`, a chapter step run after `RunStarted` and before the
first page, defaulted to `None` so every existing caller is unchanged. The
step is bound by `compose` for Gemini and is `None` for Anthropic (no Claude
pass exists; v1 is Gemini-only).

**Guarding a call that is not a page.** `Budget.project` projects pages. The
pre-pass is one call of known input size (`estimate_tokens` of the rendered
text) and bounded output (`GLOSSARY_PASS_MAX_OUTPUT_TOKENS`); its estimate is
that usage priced at the model's rates, and the guard's `check(spent,
Projection(next_call=estimate, ...))` is the existing inclusive comparison.
`domain.budget` gains the one function that prices a hypothetical usage.

**Once per chapter.** `glossary_proposed_at` (MT-103) is set in the same
transaction as the glossary upsert; a resumed run with it set skips the pass
and emits nothing for it. The marker, not the ledger, is the evidence: a
ledger row proves a bill, not that the terms were written.

Required gates: `unit`, `coverage`, `coverage-core` (the domain function).

## Acceptance criteria

- **AC-1** - Given a project with no glossary and `glossary_proposed_at`
  unset, a fake proposer returning two terms, when `run_chapter` runs with
  the prelude bound, then **before** any page stage runs the glossary holds
  those two terms with `first_seen_page == 0` and `source == "model"`,
  `glossary_proposed_at` is set, and page 2's context block renders them.
- **AC-2** - Given the same project after AC-1, when `run_chapter` runs
  again, then the proposer is not called, no second ledger row is written,
  and the glossary is unchanged.
- **AC-3** - Given a project whose stored ceiling is below the pass's
  estimate, when the run starts, then the proposer is **not** called, the
  run aborts with `RunAborted(reason=BUDGET, ordinal=None)`, no ledger row and
  no glossary term is written, and `glossary_proposed_at` stays unset.
- **AC-4** - After AC-1, the ledger has exactly one row with `page_id NULL`,
  `pricing "standard"`, the proposer's usage priced at the interactive row,
  and `CallPriced(ordinal=None, spent=that cost, ceiling, projection)` was
  emitted before `PageStarted(0)`.
- **AC-5** - `call_estimate("gemini-3.1-pro-preview", TokenUsage(100_000, 8_192, 0, 0))`
  is `$0.298304` exactly (100k x $2 + 8,192 x $12, per million), and the
  pass's projection uses `estimate_tokens(glossary_pass_text(pages))` as the
  input count and `GLOSSARY_PASS_MAX_OUTPUT_TOKENS` as the output count.
- **AC-6** - `run_chapter(project, stages, emit, cancelled)` without
  `prelude` behaves exactly as before: every existing runner test passes
  unchanged.
- **AC-7** - Given a chapter where no page has a stored OCR line (the
  listing `glossary_pass_text` renders is `""`), when `run_chapter` runs
  with the prelude bound, then the proposer is not called, no `CallPriced`
  is emitted and no ledger row is written for it, `glossary_proposed_at`
  stays unset, and page 1's stages run as they do without a prelude (PO-1).

```python
# domain/budget.py
def call_estimate(model_id: str, usage: TokenUsage, *, pricing: Pricing = "standard") -> Usd
    """`price(model_id, usage, pricing=pricing).cost` - what one hypothetical call would cost. No rounding beyond price's."""

# domain/events.py
@dataclass(frozen=True)
class CallPriced:
    ordinal: int | None       # WIDENED: None is a chapter-level call. Every consumer handles None.
    ...                       # other fields unchanged

# pipeline/prelude.py  (pipeline may not import translate: the proposer is a Callable)
GlossaryProposer = Callable[[Sequence[Sequence[OcrResult]]], GlossaryProposal]
GlossaryListing = Callable[[Sequence[Sequence[OcrResult]]], str]     # RED-A1
ChapterStep = Callable[[Project, int, Callable[[RunEvent], None]], None]   # (project, run_id, emit)

@dataclass(frozen=True)
class Pipeline:                                                      # RED-A2
    stages: tuple[Stage, ...]
    prelude: ChapterStep | None

def glossary_prelude(
    propose: GlossaryProposer,
    model_id: str,
    *,
    listing: GlossaryListing,          # RED-A1: compose binds translate.glossary_pass.glossary_pass_text
    max_output_tokens: int,            # RED-A1: compose binds GLOSSARY_PASS_MAX_OUTPUT_TOKENS
) -> ChapterStep                       # no argument has a default
    """Reads every page's OCR (one sequence per page, ordinal order, empty pages included),
    skips if glossary_proposed_at is set, skips if listing(pages) == "" (PO-1: no call, no event,
    no ledger row, no marker; checked BEFORE the guard), guards with
    Budget(ceiling).check(chapter_total, Projection(next_call=call_estimate(model_id,
    TokenUsage(estimate_tokens(listing(pages)), max_output_tokens, 0, 0)), ...)),
    raises BudgetRefused on refusal, else calls, record_call(ordinal=None) in its own transaction,
    emits CallPriced(None, spent=chapter_total, ceiling, projection), merges terms at page 0 and
    upserts, marks proposed - the upserts and the mark in one transaction."""

# pipeline/runner.py
def run_chapter(project, stages, emit, cancelled, *, prelude: ChapterStep | None = None) -> RunOutcome
    # prelude runs after RunStarted and before the first PageStarted; BudgetRefused -> RunAborted(BUDGET, ordinal=None);
    # any other exception -> RunAborted with its message, ordinal=None, as a page failure is reported today.

# compose.py: gemini binds prelude=glossary_prelude(partial(gemini.propose_glossary, client), model_id,
#   listing=glossary_pass_text, max_output_tokens=GLOSSARY_PASS_MAX_OUTPUT_TOKENS) around the SAME
#   client the translator is bound to (one GeminiClient); anthropic and translate=False: prelude None.
def build_pipeline(models_dir, *, translate=True, selection=None) -> Pipeline    # RED-A2
```

**RED amendments to this block (2026-11-02, test-developer):**

- **RED-A1 - the listing and the limit are bound arguments**, the second of
  the two options above. `glossary_prelude` takes `listing` and
  `max_output_tokens` keyword-only, with no default, and `compose` binds
  `translate`'s `glossary_pass_text` and `GLOSSARY_PASS_MAX_OUTPUT_TOKENS`.
  Chosen over "the proposer reports its own estimate" because it keeps
  `GlossaryProposer` exactly MT-104's `propose_glossary` shape (a bare
  `partial(gemini.propose_glossary, client)` satisfies it) and keeps every
  number the guard uses visible at the one composition site. A default would
  be `translate`'s value spelled a second time inside `pipeline`.
- **RED-A2 - `build_pipeline` returns a `Pipeline(stages, prelude)` frozen
  dataclass, defined in `mangatl.pipeline.prelude`.** A dataclass rather than
  a 2-tuple so a caller still treating the return as the stage tuple fails
  loudly (`Pipeline` is not iterable) instead of iterating `(stages, prelude)`
  as two "stages". In `pipeline` rather than `compose` so `ui` and `cli` can
  name it without importing the composition root (`ui` may not import
  `compose`). Callers changed: `src/mangatl/cli.py` (passes

### PO decisions (PLANNED, 2026-11-02, the user's)

- **PO-1 - an empty listing skips the pass, and that is the first
  interactive run's normal case.** `run_chapter` takes each page through
  every stage before the next page starts, so on a fresh chapter the prelude
  runs before any page has been OCR'd: every `read_lines` is `()` and the
  listing is `""`. The prelude therefore skips - no call, no event, no ledger
  row, and **no marker**, so a later run with OCR stored still proposes. The
  user chose this over folding an OCR-first runner into this story (it
  touches the runner's loop, `build_stages` and every stage-order test); that
  runner is filed as **MT-130**, which makes the interactive path read every
  page before translating any. AC-7 pins the skip. The batch path (MT-111)
  is unaffected: it runs OCR for every page before the prelude by design.
- **PO-2 - a resumed run proposes over the pages read so far.** A run
  stopped after page 5 resumes with five pages' OCR stored; the listing is
  non-empty, the pass runs over those five and the marker is set. That is a
  partial glossary, accepted as interim because pages still propose terms
  until MT-106 and `merge` keeps existing entries. MT-130 removes the case;
  **MT-106 now depends on MT-130**, so per-page proposing is not removed while
  the interactive path can still propose over a partial or empty listing.
- **PO-3 - the epic's done-when.** EPIC-09's done-when is the batch flow end
  to end (MT-111..MT-113, MT-115). This story delivers PO-2's "proposed once,
  up front" for the per-page path and the `ChapterStep` MT-111 calls; nothing
  promised between MT-104 and here is left undelivered by it.
- **PO-4 - AC-1..AC-4's fixtures seed OCR lines** through the store before
  the run (a fresh chapter has none, PO-1). The fake page stages record the
  order they run in, so "before any page stage" is an assertion on that
  record, not on timing.
- **PO-5 - the window's run is wired in MT-130, not here** (from RED's
  E-1, 2026-11-02). The window builds its run through `app.build_stages`
  -> `RunSetup` -> `RunController`; carrying the prelude down that path
  changes `ui/run.py`, `ui/main_window.py`, `ui/workspace.py`, the
  `RunSetup` type and about 70 stand-ins in 11 `tests/ui` files. Under PO-1
  the window's first run would skip the pass anyway, so the only thing lost
  in the interim is PO-2's resumed run from the window. MT-130 already
  changes when the pass can see the whole chapter, and its outcome is
  meaningless if the window never runs it, so the window wiring joins
  MT-130's scope. Here, `app.build_stages` returns `build_pipeline(...).stages`
  and the CLI passes `prelude=pipeline.prelude`.
- **PO-6 - a cursor-level glossary write is in scope** (RED's D-1).
  `store.glossary.upsert` and `mark_glossary_proposed` each open their own
  transaction and `Project.transaction` does not nest, so the terms and the
  marker in one transaction need a public writer that takes a cursor, or one
  that writes both. GREEN adds it in `src/mangatl/store/glossary.py`, now in
  `touches`.
- **PO-7 - the chapter-level `CallPriced.projection`.** Not pinned by any
  test (RED left it open). GREEN emits `budget.project(chapter_call_costs(project),
  len(project.pages()))`: the pass sits before page 1, so every page of the
  chapter is still ahead of it, priced from the per-page samples
  (`chapter_call_costs` excludes `page_id NULL` rows, MT-103).
