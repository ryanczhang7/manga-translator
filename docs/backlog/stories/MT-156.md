### C-2 - what a number is: `numbers_in`

One function, used for **both** sides. It never raises, for any `str`.

1. **Normalise:** `unicodedata.normalize("NFKC", text).lower()`. This is what
   makes `１００` and `100`, `，` and `,`, `．` and `.` the same characters. It
   also turns `①` into `1` and `½` into `1⁄2`; whatever NFKC yields is
   what is read.
2. **A digit is `[0-9]`,** after step 1. Not `\d` and not `str.isdigit()`,
   which accept the digits of other scripts.
3. **A digit number** is, scanning left to right and taking the first form
   that matches:
   - a **grouped** run: one to three digits, then one or more groups of a
     comma and exactly three digits, not followed by another digit
     (`1,000`, `12,345,678`); or else
   - a **plain** run of one or more digits (`14330`);
   - then, optionally, one decimal part: a full stop and one or more digits
     (`3.5`, `1,000.50`).

   Its value is the decimal number the match spells, with the commas removed.
4. **A multiplier** (AC-1, the user's answer to PO-2) is one of four
   characters: `千` 1,000, `万` 10,000, `億` 100,000,000, `兆`
   1,000,000,000,000. No other character is one: not `百`, not `十`.
   - A digit number **directly** followed by a multiplier, with no character
     between, is a **part**. Its value is the product.
   - Parts that follow each other with no character between are **one**
     number, the sum. One digit number directly after the last part, with no
     multiplier of its own, joins the sum too: that is `１千１００`.
   - A multiplier that does not directly follow a digit number is not read.
     So `万` alone is nothing, and in `３千万` the `万` is not read.
   - The product and the sum are taken **exactly**, on the decimal digits as
     written, and turned into a `float` once at the end. Multiplying floats
     is not the same thing: `2.01 * 1000.0` is `2009.9999999999998`.
5. **An English number word** is one of the 28 words `zero` ... `twenty`,
   `thirty`, `forty`, `fifty`, `sixty`, `seventy`, `eighty`, `ninety`, with
   no ASCII letter directly before or after it. Its value is the number it
   names. Longer words win (`fourteen` is 14, never 4).
6. **A compound** is a tens word (`twenty` ... `ninety`), then exactly one
   hyphen `-` or one whitespace character, then a word `one` ... `nine`. It
   is **one** number, the sum. AC-3 names the words that count and is silent
   on how two of them join; this is the reading under which `２５歳` against
   "twenty-five years old" agrees (PO-5).
7. The result is every value found, as `float`, ascending, duplicates kept.

**Two kinds.** A value read by rules 3 and 4 is a **digit number**. A value
read by rules 5 and 6 is a **word number**. `numbers_in` returns both kinds
together; only C-3 treats them differently.

### C-3 - the comparison: `number_mismatch`

Digits on either side always count. An English **word** only ever cancels a
Japanese number; it never causes a flag by itself (AC-3, the user's answer to
PO-3). In steps:

1. `japanese = numbers_in(source_ja)`: every value, of both kinds.
2. Read the English. Call its digit numbers `D` and its word numbers `W`
   (C-2, "Two kinds").
3. `left` is `japanese` with `D` taken out of it as a multiset: one Japanese
   value for each equal English digit number, and no fewer than zero.
4. Each word number in `W` **counts** if `left` still holds a number of its
   value, and takes that one out of `left`. A word number that finds none is
   **ignored**: it is on neither side.
5. `english` is `D` plus the word numbers that counted, ascending.
6. The result is `None` exactly when `japanese == english`. Otherwise it is
   `NumberMismatch(japanese=japanese, english=english)`.

So a line is flagged in exactly two cases: the English has a digit number
the Japanese does not have, or the Japanese has a number nothing in the
English matches.

- **Digits are matched first** (step 3), whatever the order in the text.
  That is what "left to match" means in AC-3.
- **Each side is the whole side,** not the difference: `３人で１００ミリ`
  against "three of us, 1000 mg" gives `NumberMismatch((3, 100), (3, 1000))`.
  The reviewer is being sent to the page, and reads both lists against it.
  The English list does not show an ignored word.
- **Equality is multiset equality of float values.** Order in the text does
  not count; a repeat does; `1000`, `1000.0` and `1,000` are one value; `1.50`
  and `1.5` are one value.
- **The Japanese side is not filtered.** A number word in the Japanese text
  (a sound effect lettered `ONE`) is a Japanese number like any other.
- Both sides empty is `None` (AC-4's first control). An empty string on
  either side is an empty side.
- The values the criteria name are settled, and unchanged by the two new
  rules: AC-2 `NumberMismatch((100,), (1000,))` and `None`; AC-3 `None`; AC-4
  `None` and `NumberMismatch((1433,), ())`; AC-5 `NumberMismatch((),
  (38000,))`.

### C-4 - which lines are checked: `line_mismatch`

```python
def line_mismatch(line: Line) -> NumberMismatch | None:
    if line.status in ("failed", "excluded"):
        return None
    if line.proposed_en is None and line.final_en is None:
        return None
    return number_mismatch(line.source_ja, effective_text(line))
```

- **`failed` and `excluded` are never checked.** A failed line has no English
  to compare and already carries its own caption; an excluded line is out of
  translation.
- **A line with no English yet is never checked.** While a run is on, a
  `proposed` line has `proposed_en is None`; without this rule every
  Japanese line with a digit would say "English none" until its page
  came back.
- **`proposed`, `accepted`, `edited` and `reverted` are checked,** on
  `effective_text(line)`. AC-6 names the first three. `reverted` is the
  fourth status that shows English, and leaving it out would make the caption
  vanish when the user presses Revert on a line that still differs (PO-6).
- A committed empty line (`final_en == ""`, the user deleted the text) is
  checked, and reads `none` on the English side.
- The Japanese is **`line.source_ja`**, not the separate `japanese` argument
  `_row_accessible_text` receives for display.

### C-5 - the sentence: `mismatch_sentence`

```python
f"Japanese {ja}; English {en} - numbers differ, check the page"
```

- `ja` and `en` are each side's values joined with `", "`, or the word `none`
  for an empty side.
- A value prints as `str(int(v))` when `v.is_integer()`, else `repr(v)`:
  `1000`, `38000` (no separator: AC-6's own `1000`), `50000000000000`, `1.5`,
  `inf`.
- The sides are joined by `; ` (a semicolon and one space), so a list's own
  commas never run into the other side. The hyphen is ASCII `-` with one
  space each side. The sentence has **no full stop**; AC-6's "exactly" is
  this string.
- The numbers come first on purpose (`## Notes`, PO-15): the row's caption
  is one unwrapped line, and both numbers must fit in the review column at
  its default width.

| `NumberMismatch` | Sentence |
|---|---|
| `((100,), (1000,))` | `Japanese 100; English 1000 - numbers differ, check the page` |
| `((), (38000,))` | `Japanese none; English 38000 - numbers differ, check the page` |
| `((1433,), ())` | `Japanese 1433; English none - numbers differ, check the page` |
| `((3, 100), (1.5, 3, 1000))` | `Japanese 3, 100; English 1.5, 3, 1000 - numbers differ, check the page` |

### C-6 - the row: caption and accessible name (`ui/workspace.py`)

No new widget. The sentence goes in the row's existing caption slot,
`TranslationRow.error_caption` (`QLabel`, object name `rowErrorCaption`).

- **The chain** in `TranslationRow._render` (`workspace.py:841-845`) gains a
  fourth and last term:

  ```python
  mismatch = line_mismatch(line)
  caption = (
      self._save_error
      or failure_reason(line)
      or (_ART_CAPTION if _left_as_art(line) else None)
      or (mismatch_sentence(mismatch) if mismatch is not None else None)
  )
  ```

  A save error outranks the sentence. By C-4 a failed or excluded line has no
  mismatch, so only the save error can ever hide one.
- **When it is recomputed:** on every `_render`, so on a commit (Enter,
  Accept, Revert, focus leaving the editor), on a save outcome and on
  `set_line`. Not on each keystroke.
- **Accessible name.** `_row_accessible_text(ordinal, total, japanese, line)`
  keeps its signature. When `line_mismatch(line)` is not `None` the name is
  today's name, one space, the sentence, and a full stop:

  ```
  Bubble 1 of 3. Japanese: ハイドロコーン１００ミリ. English: give 1000 mg. machine proposal. Japanese 100; English 1000 - numbers differ, check the page.
  ```

  The name carries the sentence whenever the line differs, whatever the
  caption slot shows, so a row with a save error still names it. RED asserts
  the whole string and `name.endswith(sentence + ".")`.
- The item's size hint is already recomputed on every render
  (`TranslationColumn._describe`), so the row grows when the caption appears
  and shrinks when an edit makes the numbers agree. Status, gutter glyph,
  buttons and the canvas marker do not change: the caption is a warning, not
  a status (PO-5 of the epic).

### C-9 - known limits, recorded so nobody rediscovers them as bugs

The flag compares what the OCR read against what the model wrote. It says
they differ; it never says which is wrong. These all flag a line that may be
perfectly translated, and each is in the module docstring:

- **Kanji numerals are not numbers** (AC-5): `一人` against "one person"
  flags, with `none` on the Japanese side.
- **Only 千, 万, 億 and 兆 multiply, and only directly after a digit number**
  (AC-1). `百` and `十` do not: `３百` is 3. A multiplier after a multiplier is
  not read: `３千万` is 3000, not 30,000,000, and `２億５千万` is 200,005,000.
  Neither spelling occurs in the development set or in the benchmark chapter
  (C-11), which is why the rule stops where the criterion does.
- **`hundred`, `thousand`, `million`, `dozen`, `half`, `twice`, `first`,
  `a`/`an` are not number words**: "eight thousand" is the word 8. Against
  `８千円` it finds no 8 to match and is ignored, so the line flags with
  `Japanese 8000; English none`. This is the most common
  false flag left in the benchmark's copy B (C-11).
- **A wrong number written as a word against no Japanese number is not
  seen** (AC-3): `やめろ` against "Stop, all three of you" agrees, because an
  English word only ever cancels. A wrong word against a Japanese number
  still flags, as the unmatched Japanese number (`３人` against "Two
  doctors").
- **A number word in the Japanese text counts**, though it is rare there.
- **Idiom:** `１日` against "daily", `２人きり` against "just me and
  Ushida-san", `２倍` against "twice", `７割` against "70%". (Written "just
  the two of us", the second agrees: `two` finds the 2.)
- **Units are not compared** (`## Out of scope`): 100 mg against 100 mL
  agrees.

## Design notes

Lead Designer's pass at PLANNED (2026-11-20, `lead-designer`, Claude Fable
5.2, `claude-fable-5-2`, no override), against `voice.md`, `accessibility.md`
A-10 and A-12, `components.md` §5 and §10.4, `layout.md`, and MT-146's D-1 to
D-3. The caption is **unstyled** (the user's answer to PO-4, Contract C-7);
nothing here reopens that.

- **D-1 - no new component, no new state.** The sentence goes in the row's
  existing caption slot (`rowErrorCaption`), exactly as MT-146's art caption
  does: no stylesheet rule, no dynamic property, no token, no theme file. It
  inherits the row's text colour, so it is the guaranteed pair on every row
  ground, on the selected row and under High Contrast, with nothing to add to
  §10.4. A mismatch is **not a status**: gutter glyph, glyph colour, leading
  bar, ground, border and row actions are whatever the line's status already
  gives. The words are the only carrier, which satisfies A-10 because no
  colour is carrying anything.
- **D-2 - the words: confirmed as copy.** `Japanese 100; English 1000 -
  numbers differ, check the page` (AC-6, C-5; the user's choice of
  2026-11-20, D-6) passes `voice.md`: sentence case, no first person, no
  terminal full stop on a label, and only the user's words (*page*, never
  "OCR", "model" or "source"). The two numbers come first because they are
  what the user compares against the page, and the one part that differs
  from row to row; the instruction follows and is the same on every row. It
  does not say which side is wrong, because the app does not know. Each
  side's list is comma-separated and the sides are separated by `; `, so
  `Japanese 3, 100; English 1.5, 3, 1000` reads one way only. `none` for an
  empty side is confirmed (`Japanese none; English 38000`). Values print
  without a thousands separator (`38000`): `voice.md`'s comma rule is for
  money, and a comma inside a value would read as the list's.
- **D-3 - accessible name: confirmed (C-6).** Today's name, one space, the
  sentence, a full stop, so the status phrase is heard first and the warning
  last. It is carried whenever the line differs, whatever the caption slot
  shows. `components.md` §5 records the suffix.
- **D-4 - precedence: confirmed (C-6).** Save error, then failure reason,
  then the art caption, then the mismatch sentence. The slot holds one
  caption. A failed or excluded line is never checked (C-4), so in practice
  only "Not saved: {reason}" can sit over a mismatch; it is the more urgent
  and the shorter-lived, and the name still carries the mismatch meanwhile.
- **D-5 - nothing beyond the caption: confirmed.** No canvas marker, no
  gutter glyph, no count in the page strip or the column header (`## Out of
  scope`). The check has known false flags (C-9), and a mark on the art or in
  the strip would make a maybe look like a status. **No live announcement**
  either: A-12's list is closed, and the caption appears on a commit the user
  just made or on a page they just opened; the row's accessible name is
  rewritten on the same render (C-6), which is what a screen reader reads on
  arriving at the row.

### The export shape the tests already pin (fact, not suggestion)

`tests/core/test_numbers.py` does `from mangatl.domain import numbers` and
`from mangatl.domain.numbers import NumberMismatch, line_mismatch,
mismatch_sentence, number_mismatch, numbers_in`. The tests pin these facts:

- `sorted(numbers.__all__)` is exactly `["NumberMismatch", "line_mismatch",
  "mismatch_sentence", "number_mismatch", "numbers_in"]`.
- `numbers.__doc__` is not `None`, and `"kanji numerals" in __doc__.lower()`.
- `NumberMismatch` is a frozen dataclass. Assigning to an attribute raises
  `dataclasses.FrozenInstanceError`. It can be built positionally, as
  `NumberMismatch((100,), (1000,))`, and by keyword, as
  `NumberMismatch(japanese=..., english=...)`. It compares by value, with the
  fields `japanese` and `english`, in that order.
- `numbers_in(text: str) -> tuple[float, ...]`. Every element is
  `type(v) is float`, not `int` and not `Decimal`, ascending, with duplicates
  kept. `numbers_in("")` is `()`.
- `number_mismatch(source_ja: str, english: str) -> NumberMismatch | None`.
  Tests compare it with `==` against `NumberMismatch(...)` or check `is None`.
- `line_mismatch(line: Line) -> NumberMismatch | None`, called on
  `mangatl.domain.line.Line` instances (`excluded="user"` for the excluded case).
- `mismatch_sentence(mismatch: NumberMismatch) -> str`.

**Left to the implementer:** how the digit and word kinds are carried
internally (C-1 says no export for it), the tokenizer and regexes, whether
exact arithmetic uses `Decimal` or `Fraction`, and any private helper names.
In `workspace.py`, the tests read only `TranslationRow.error_caption` (its
`text()` and `isVisibleTo(row)`), `gutter.text()`, `gutter.property("status")`,
the three action buttons, `editor.status`, and the column item's
`Qt.ItemDataRole.AccessibleTextRole`. Nothing pins how `_render` or
`_row_accessible_text` reach `line_mismatch`.

### Discovered, for the implementation

- **Full-width text in `tests/core/test_numbers.py` trips RUF001/RUF002.** The
  file carries `# ruff: noqa: RUF001, RUF002, RUF003`, with the reason
  beside it, as `test_domain_echo.py` and `test_ocr_decode.py` do.
  `src/mangatl/domain/numbers.py` will meet the same rules if its docstring or
  tables hold `１`, `，` or `．`. `src/mangatl/ocr/decode.py` uses a file-level
  `# ruff: noqa: RUF002` with a reason. Under `check-boundaries.sh` block 3j, a
  suppression a GREEN commit adds to `src` must be named in `## Suppressions`
  with `approved by <who>`. Writing the characters as `１` escapes avoids
  the need.
- **Exactness.** `２．０１千` must be `2010.0`, and `type(v) is float` is
  asserted. Multiply in `Decimal` (or `Fraction`) and convert once. The
  400-nines rows expect `float("inf")` and must not raise: `float(Decimal(...))`
  gives `inf` for these, and the reference did so. Mind `Decimal`'s default
  28-digit context: it rounds a product but does not overflow, which is fine
  for the table.
- **In the save-error test the typed text is `give 1000 mg.`**, so the name
  reads `English: give 1000 mg..`. That is today's double full stop, which C-6
  does not change.
