## Context

EPIC-13 priority 6. The user decided this on 2026-11-07 (U-2, as
re-decided): a **disagreement flag** on numbers, with name readings left to
the glossary.

**What the p018 case really was.** It is corrected here because the first
framing was wrong. The page prints a small horizontal `1000` inside the
vertical column (縦中横). The OCR stored it as `１００`:
`ラクテック全開ハイドロコーン１００ミリ側管注しろ！！`. The official English reads
"1,000 milligrams" (`D:\bench\all-en\p018.jpg`), and the side session that
ran MT-108 confirmed it. So copy B's "1000 mg" was **right**, and copy A's
"100 mil" followed the bad OCR. The reviewer accepted both, because nothing
said the two sides disagreed.

A check of the English against the **OCR'd** Japanese cannot know which
side is wrong. It can only see that they disagree, and on p018 that is
exactly the signal a reviewer needed. It would have flagged B's correct line
and passed A's wrong one, because A agreed with the bad OCR. So the caption
says the numbers **differ** and asks the reviewer to check the page. It never
says the English is wrong. The user chose this framing on 2026-11-07, after
the correction.

PO-5: the check **flags**. It does not clear the proposal. The row shows a
caption naming the numbers on both sides. The status is unchanged
(`proposed`): the caption is a warning, not a failure.

Required gates: `unit`, `coverage`, `coverage-core` (`domain/**` at 100 %),
`ui`.

## Acceptance criteria

- **AC-1** - `number_mismatch(source_ja, english)` returns `None` when the
  multisets of numbers on the two sides are equal. Otherwise it returns
  `NumberMismatch(japanese=(...), english=(...))`, each side sorted. Numbers
  are runs of ASCII or full-width digits, with `,`/`，` thousands separators
  and one decimal point allowed.
- **AC-2** - *(the case)* `number_mismatch("ハイドロコーン１００ミリ", "give 1000 mg")`
  returns `NumberMismatch((100,), (1000,))`, and
  `number_mismatch("ハイドロコーン１００ミリ", "give him 100 mil")` returns `None`.
- **AC-3** - English number words zero to twenty, and the tens to ninety,
  count as numbers: `勤務医は３人` against "Three full-time doctors" is `None`.
- **AC-4** - *(control: no numbers on either side)* Returns `None`. *(Control:
  a dropped number)* `合計1433点` against "Total points" returns
  `NumberMismatch((1433,), ())`.
- **AC-5** - Kanji numerals are not numbers (PO-5's documented limit):
  `三万八千円` against "38,000 yen" returns `NumberMismatch((), (38000,))`. The
  row shows it, and the limit is in the module docstring.
- **AC-6** - In the workspace, a `proposed` row whose line has a mismatch
  shows the caption exactly `Numbers differ - check the page: 100 read in
  the Japanese, 1000 in the English`, with each side's list comma-separated,
  or `none` when empty.
  It carries the warning token from `components.md`, and the row's accessible
  name ends with that sentence. An `edited` or `accepted` row shows it too,
  computed from the shown text (`effective_text`). A row without a mismatch
  shows no caption.
