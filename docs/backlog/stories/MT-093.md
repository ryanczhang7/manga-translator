## Acceptance criteria

- **AC-1 (FM4).** **Given** an opener whose response yields some bytes and then
  raises (for example `OSError`), **when** `fetch_all` runs:
  - the same exception propagates;
  - neither the final file nor its `.part` exists afterwards.

  Fails under FM4.

  *Oracle partition:* **mechanical** - an exception type, an exception
  identity and two file-existence facts. Pin exactly; nothing to invent and
  nothing to calibrate.

## Test plan

One test, unit level, in the `# -- fetch_all` block of
`tests/core/test_fetch_models.py`, directly after
`test_a_mismatch_over_a_stale_file_does_not_leave_the_wrong_bytes_in_its_place`.
Unit is the cheapest level that can falsify AC-1: the behaviour is entirely
inside `fetch_all`, and the file's fake opener already drives it without a
network.

- **`test_a_download_that_raises_mid_stream_propagates_and_leaves_no_part_behind`**
  covers **AC-1 (FM4)**. It uses `_world(tmp_path)` and wraps its opener so that
  `detector.onnx` (the first entry in manifest order, so no second entry is
  fetched after the raise) serves one non-empty chunk, then raises a sentinel
  `OSError("connection reset mid-stream")` from its next `read`. The four
  assertions, in the contract's order:
  1. `pytest.raises(OSError)` around `fetch_all(...)` and
     `raised.value is sentinel`. This pins "the same exception propagates" to
     the identical instance (PO-3), so a wrapped re-raise or a fresh `OSError`
     fails it.
  2. `True in seen`, where `seen` is the `part.exists()` flag of every
     `opener.during` record for `detector.onnx`. This proves the `.part` existed
     while the file was streaming, so assertion 3 cannot pass vacuously.
  3. `not (target / "detector.onnx.part").exists()`. This is the FM4 pin: line
     68's `part.unlink(missing_ok=True)` is the only thing that removes it.
  4. `not (target / "detector.onnx").exists()`. The file's name is never given
     to bytes that did not finish.

**Why the helpers are shaped this way.** The contract allowed either a
`_Response` subclass or an `_Opener` hook. RED chose a **wrapper plus an
`_Opener` subclass**:
- `_ResetAfterFirstChunk` wraps the real `_Response`. Every `read` delegates to
  `_Response.read` *first*, which calls the opener's `observe()`, and only then
  raises (on any read after the first). So on the second read `observe()`
  records `(path, part.exists(), final.exists())` before the exception fires.
  That record is what assertion 2 reads, and it was confirmed to exist (with
  `part is True`) because the mutant run reached assertion 3, past assertion 2.
  The wrapper also asserts that its first chunk is non-empty, so "mid-stream"
  cannot quietly turn into "before any byte". Its `__exit__` closes the inner
  response.
- `_ResettingOpener(_Opener)` reuses the parent's `served`, `paths` and
  `target`, calls `super().__call__` (so URL recording and the `observe` hook
  are unchanged), and wraps the response only for paths named in `reset`.
- The raise therefore comes from `response.read` inside `fetch_all`'s
  `with opener(...) as response, part.open("wb") as out:`, after the `.part` has
  been opened `"wb"` and written once. That is the condition the contract names.

No edge beyond this one: the AC is mechanical and names one path. The
hash-mismatch clean-up path is already pinned by the existing tests. No
parametrization, so the count stays at 18.
