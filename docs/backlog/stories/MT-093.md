## Context

Filed by the EPIC-07 mutation audit, `docs/wiki/audits/EPIC-07-2026-10-22.md`:
survivor FM4 (`## Decided` item 4, `## Evidence` E-2 item 6). **Low
priority.**

- **The contract.** `fetch_all` (`packaging/fetch_models.py`) promises a
  `.part` is removed "after removing its `.part`".
- **The two clean-up paths.**
  - On a hash mismatch, line 72's `part.unlink()` removes it. That path is
    tested.
  - When the download itself raises (network error, timeout, Ctrl-C), line
    68's `except BaseException: part.unlink(missing_ok=True); raise` removes
    it. No test raises from the opener mid-stream.
- **The survivor.** Replace that unlink with `pass` and all 17 tests in
  `tests/core/test_fetch_models.py` stay green.

Production effect, and why this is low: a stray `packaging/models/**/*.part`
after an interrupted build fetch. It is reopened `"wb"` on the next run, and
`packaging/mangatl.spec:30-35` bundles only manifest paths, so it never ships.

**Settled:** unprotected, and the code is correct (audit `## Decided` 4,
consumed, not re-litigated).

## Acceptance criteria

- **AC-1 (FM4).** **Given** an opener whose response yields some bytes and then
  raises (for example `OSError`), **when** `fetch_all` runs:
  - the same exception propagates;
  - neither the final file nor its `.part` exists afterwards.

  Fails under FM4.

  *Oracle partition:* **mechanical** - an exception type, an exception
  identity and two file-existence facts. Pin exactly; nothing to invent and
  nothing to calibrate.

RED may amend any block below in place, with a reason written beside it; GREEN

- **Tests only.** No change to `packaging/fetch_models.py`; its public
  signatures (`fetch_all(manifest, target, *, opener=urlopen) -> list[Path]`,
  `main(argv=None, *, opener=urlopen) -> int`) are unchanged, so **there are no
  callers of a changed signature to list**. Callers of `fetch_all` today, for
  the record: `packaging/fetch_models.py:main`, every `fetch_all` test in
  `tests/core/test_fetch_models.py`; nothing under `src/`.
- **Where.** One new test in the `# -- fetch_all` block of
  `tests/core/test_fetch_models.py`, after
  `test_a_mismatch_over_a_stale_file_does_not_leave_the_wrong_bytes_in_its_place`.
  Suggested name:
  `test_a_download_that_raises_mid_stream_propagates_and_leaves_no_part_behind`.
- **The failing opener.** Reuse the file's fake-opener pattern (`_world`,
  `_Opener`, `_Response`). The response for one entry returns at least one
  non-empty chunk, then its next `read` raises a *sentinel instance* of
  `OSError` created by the test (for example `OSError("connection reset
  mid-stream")`). It must raise from `read`, inside `fetch_all`'s `with`, so
  that the `.part` has already been opened `"wb"` when the exception fires -
  that is the condition under which line 68's `unlink` is the only thing that
  removes it. Either subclass `_Response` or give `_Opener` a hook; RED
  chooses and says which.
- **Assertions, all four, in this order.**
  1. `pytest.raises(OSError)` around `fetch_all(...)`, and
     `raised.value is sentinel` - "the same exception propagates" means the
     identical instance, not merely the type, so a re-raise wrapped in another
     exception or a fresh `OSError` fails it.
  2. The `.part` was observed to exist while streaming (so assertion 3 is
     not vacuous): the file's existing `opener.during` records
     `(path, part.exists(), final.exists())` at every read after the first;
     assert at least one record for that path with `part is True`. If RED
     drives the raise from the second read, `observe()` runs before the raise
     and the record exists; RED confirms this and amends here if it needs a
     different hook.
  3. `not (target / "<path>.part").exists()` afterwards.
  4. `not (target / "<path>").exists()` afterwards.
- **Which entry.** Use `detector.onnx` (the top-level entry, manifest order
  first), so no second entry is fetched after the raise and the target
  directory's state is only this entry's.
