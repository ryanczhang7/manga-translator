## Context

**Filed 2026-09-30 by the Lead PO**, split from [[MT-055]] (its PO-2), both from
[[MT-054]] PO-5. MT-055 gives the no-argument window the `FolderDropTarget`
(`docs/wiki/design/components.md` §2) with its keyboard/click path and a folder
dialog. This story makes it a drop target in fact: a folder dragged from
Explorer opens the chapter, and the target says *before* the drop whether the
drag is acceptable. The state table and copy in `components.md` §2, and
`accessibility.md` A-10 ("drop-target validity | the headline changes
wording"), are the oracle: **read them out, do not reword them.**

A dropped folder has exactly the outcome of choosing it in MT-055, which is
exactly the outcome of `mangatl <folder>` (MT-054): the `Workspace`, or the
error state with the no-project text. Nothing here decides anything new about a
folder; it only adds a way to hand one over.

Required gates that would fail if this broke: `unit` and `coverage` (required),
over `tests/ui` under `QT_QPA_PLATFORM=offscreen` - drag events are synthesised
in process, no display or real drag. `required_gates: []`.

## Acceptance criteria

- **AC-1** — Given the drop target in its empty or error state, when a drag
  carrying exactly one local directory enters it, then it shows the
  **hover-valid** state (headline "Release to load") and accepts the drag; and
  when that drag leaves without dropping, the previous state returns unchanged.
- **AC-2** — Given the drop target, when a drag carrying files, or more than one
  item, enters it, then it shows the **hover-invalid** state (headline "Drop a
  folder, not files", and a body naming what was dragged) and refuses the drag;
  dropping it changes nothing, opens nothing and writes nothing, and on leave
  the previous state returns.
- **AC-3** — Given one local directory dropped on the target, when the drop
  completes, then the outcome is the one MT-055 gives for choosing that folder:
  the `Workspace` on the chapter when a project exists (MT-055 AC-3), the error
  state with the same text when it does not or is too new (MT-055 AC-4), and
  never a created project.
- **AC-4** — Given any drag, when the target changes state, then the headline
  wording changes with it, so validity is never carried by the border colour
  alone (`accessibility.md` A-10).

## Contract

**Not pinned yet** - written at PLANNED → RED once MT-055's contract exists and
Q1 below is answered. Direction:

- The drop path calls the *same* folder resolution MT-055 introduces; no third
  copy of the MT-054 outcomes.
- Drags are driven by constructing `QMimeData` with `setUrls` and sending
  `QDragEnterEvent` / `QDragLeaveEvent` / `QDropEvent` to the widget; the test
  never needs a real drag or a display.
- **Oracle partition.** *Settled:* "Release to load", "Drop a folder, not
  files" (`components.md` §2), the A-10 rule. *Mechanical:* accept/refuse,
  state restoration on leave, AC-3's delegation. *Open:* the body text of
  hover-invalid (Q1) - not to be invented by RED.
- Visual numbers the design fixes, which RED may pin and must not invent
  otherwise: hover-valid border 2px solid `color.accent.base`, ground
  `overlay.fill.hover`; hover-invalid border 2px solid `color.status.danger`.

## Out of scope

- Everything MT-055 lists as out of scope (creating a project or starting a
  run from the window, the loading / populated / disabled states, the
  image-reading error reasons).
- Dropping onto an open `Workspace` to switch chapters.
- Accepting a dropped *file* by opening its parent folder, or a dropped
  `.mtproj` directory by opening its chapter. A file is hover-invalid, full
  stop, as the design says; either convenience would be a new decision.
- Non-local URLs (a drag from a browser), archives, CBZ/PDF (brief non-goal).

## Notes

### Open questions - must be answered before PLANNED → RED

- **Q1 (Lead Designer) — the hover-invalid copy is not fully written.**
  `components.md` §2 says the body "names what was dragged" but gives no
  wording, and its one headline, "Drop a folder, not files", is untrue for a
  drag of *two folders*, which the same row also calls invalid ("a
  multi-item drag"). RED needs, as settled strings: the body for one file, for
  several files, for several folders, and for a mix; whether several folders get
  a different headline (e.g. "Drop one folder"); and what a drag with a
  non-local URL (a browser link) shows. AC-2 is worded so the answer lands in
  the Contract, not the criteria - unless the designer decides several folders
  need their own headline, in which case AC-2's headline clause is amended here
  *before* RED, while it is still PLANNED. Not guessed.

### PO decisions at PLANNED (2026-09-30, lead-po)

- **PO-1 — why this is separate from MT-055:** see MT-055 PO-2. Different input
  mechanism, different test apparatus (synthesised drag events and MIME data),
  a state table of its own, and not needed for MT-055 to be complete, because
  drag is never the only path (`components.md` §2).
