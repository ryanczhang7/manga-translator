## Context

**Filed 2026-09-30 by the Lead PO**, split from [[MT-055]] (its PO-2), both from
[[MT-054]] PO-5. MT-055 gives the no-argument window the `FolderDropTarget`
(`docs/wiki/design/components.md` §2) with its keyboard/click path and a folder
dialog. This story makes it a drop target in fact: a folder dragged from
Explorer opens the chapter, and the target says *before* the drop whether the
drag is acceptable. The state table and copy in `components.md` §2, and
`accessibility.md` A-10 ("drop-target validity | the headline changes
wording"), are the oracle: **read them out, do not reword them.**

A dropped folder has exactly the outcome of choosing it in MT-055, which is
exactly the outcome of `mangatl <folder>` (MT-054): the `Workspace`, or the
error state with the no-project text. Nothing here decides anything new about a
folder; it only adds a way to hand one over.

Required gates that would fail if this broke: `unit` and `coverage` (required),
over `tests/ui` under `QT_QPA_PLATFORM=offscreen` - drag events are synthesised
in process, no display or real drag. `required_gates: []`.

## Acceptance criteria

- **AC-1** — Given the drop target in its empty or error state, when a drag
  carrying exactly one local directory enters it, then it shows the
  **hover-valid** state (headline "Release to load") and accepts the drag; and
  when that drag leaves without dropping, the previous state returns unchanged.
- **AC-2** — Given the drop target, when a drag carrying files, or more than one
  item, enters it, then it shows the **hover-invalid** state (headline "Drop a
  folder, not files" - or "Drop one folder" when every item is a folder - and a
  body naming what was dragged, worded as `## Design notes` settles) and refuses
  the drag; dropping it changes nothing, opens nothing and writes nothing, and on
  leave the previous state returns.
- **AC-3** — Given one local directory dropped on the target, when the drop
  completes, then the outcome is the one MT-055 gives for choosing that folder:
  the `Workspace` on the chapter when a project exists (MT-055 AC-3), the error
  state with the same text when it does not or is too new (MT-055 AC-4), and
  never a created project.
- **AC-4** — Given any drag, when the target changes state, then the headline
  wording changes with it, so validity is never carried by the border colour
  alone (`accessibility.md` A-10).
- **AC-5** — Given the drop target in its empty or error state, when a drag
  carrying any non-local URL (a browser link), or no URLs at all, enters it,
  then the target does not change - headline, body, affordance and description
  as before - and refuses the drag.

### C-1 — `mangatl.ui.intake.FolderDropTarget` becomes a drop target

```python
class FolderDropTarget(QAbstractButton):       # unchanged base (MT-055)
    activated: Signal                          # () - unchanged
    dropped: Signal                            # (Path) - new: once per valid drop
    state: str                                 # "empty" | "error" | "hover-valid" | "hover-invalid"
    def show_error(self, text: str) -> None: ... # unchanged
```

- `acceptDrops()` is `True` from construction.
- **Classification happens at drag enter**, from `event.mimeData()`:
  - no URLs (`urls()` empty, including plain-text-only data), or **any** URL for
    which `QUrl.isLocalFile()` is false → **ignored** (AC-5): `event.ignore()`,
    nothing about the target changes (`state`, the three texts, the
    description).
  - otherwise each URL is `Path(url.toLocalFile())`; it is a *folder* when
    `is_dir()` is true at enter time, else a *file* (a missing path is a file).
  - exactly one URL and it is a folder → **hover-valid**: `event.acceptProposedAction()`
    (so `isAccepted()` is true afterwards).
  - anything else → **hover-invalid**: `event.ignore()` (so `isAccepted()` is
    false afterwards).
- **Texts per state** are `## Design notes`' table, read out verbatim:
  hover-valid headline `Release to load`, body `{name}`; hover-invalid headline
  `Drop a folder, not files` or `Drop one folder` (every item a folder, n ≥ 2),
  body per the table. `affordance.text() == ""` in both hover states (whether it
  is also hidden is GREEN's choice; not pinned). Accessible **name** stays
  `Choose chapter folder`; accessible **description** is
  `"\n".join(t for t in (headline, body) if t)` - MT-055 C-3's rule, unchanged.
- `{name}` is `path.name`; **when that is empty (a drive root such as `C:\`)
  it is `str(path)`** (PO-3). A name longer than 40 characters is
  `name[:20] + "…" + name[-19:]` (U+2026; 40 characters); exactly 40 is whole.
- **Leave** (`dragLeaveEvent`): `state`, headline, body, affordance, their
  visibility and the description return to exactly what they were before the
  enter - `empty` or `error` with its text. The target remembers the pre-drag
  state; it does not re-derive it.
- **Drop** (`dropEvent`):
  - in **hover-valid**: restore the pre-drag state first (as Leave), then
    `event.acceptProposedAction()`, then emit `dropped` **once** with
    `Path(url.toLocalFile())` - not resolved; resolution is `open_folder`'s job
    (MT-055 C-1).
  - in any other state: restore the pre-drag state if a drag was in progress,
    `event.ignore()`, emit nothing. Qt sends no Leave after a drop, so the
    restore is the drop handler's.
- A drop never calls `activated` and never asks the chooser.

### C-2 — `mangatl.ui.main_window.MainWindow`: one path for a folder

- Constructor signature, attributes and the notice window: **unchanged**
  (MT-055 C-2). A notice window has no drop target and accepts no drops.
- `self._target.dropped` is connected to the **same** method the chooser's

  four branches (DV-1).

### C-3 — how the tests drive a drag (measured 2026-09-30, PySide6 6.9.3, offscreen)

- `QMimeData()` + `setUrls([QUrl.fromLocalFile(str(p)), ...])`; a non-local URL
  is `QUrl("https://example.com/page.png")`; "no URLs" is `setText("x")` only.
- `QDragEnterEvent(QPoint(5, 5), Qt.DropAction.CopyAction, mime,
  Qt.MouseButton.LeftButton, Qt.KeyboardModifier.NoModifier)` sent with
  `QApplication.sendEvent(target, event)`; read `event.isAccepted()` after.
  Measured: an accepting `dragEnterEvent` leaves it `True`.
- `QDragLeaveEvent()` via `QApplication.sendEvent`.
  **Amended by RED, 2026-09-30 (measured, PySide6 6.9.3 offscreen; reason: the
  bullet above crashed the suite):** `sendEvent` routes a `QDragLeaveEvent` -
  like a `QDropEvent` - to the widget whose enter was last *accepted* (Qt's
  drag manager holds a raw pointer to it until a leave or a drop), **not to the
  receiver**; with no such widget it goes to the receiver. A test that ends in
  hover-valid leaves that pointer set, and the next test's leave was delivered
  to the deleted widget: `Windows fatal exception: access violation` in
  `sendEvent`, 3 runs in 5. The tests therefore end every drag before pytest-qt
  deletes the widget (`qtbot.addWidget(..., before_close_func=_release_drag)`,
  which sends one leave to a throwaway widget); after that, 8 runs in 8 were
  clean. Nothing changes for GREEN: `dragLeaveEvent` still receives the leave.
  It does mean **no production code should rely on `sendEvent` reaching a
  particular widget with a drag event**.
- **The drop trap - measured, read before writing AC-2's drop test.**
  `QApplication.sendEvent(target, QDropEvent(...))` **does not reach
  `dropEvent` unless the preceding enter was accepted and no leave followed**:
  after a refused enter it returned `False` and `dropEvent` never ran; after an
  accepted enter and a leave, likewise. So an AC-2 "dropping changes nothing"
  test that goes through `sendEvent` passes against a target that opens *any*
  drop - it is vacuous. AC-2's drop test therefore delivers the drop **straight
  to the widget**, `target.dropEvent(drop)` (or `target.event(drop)`, which the
  probe showed does reach it), after a `sendEvent`ed refused enter; AC-3's valid
  drop goes through `sendEvent` after an accepted enter, as a real drag would.
- `QDropEvent(QPointF(5, 5), Qt.DropAction.CopyAction, mime,
  Qt.MouseButton.LeftButton, Qt.KeyboardModifier.NoModifier)`; call
  `setAccepted(False)` before delivery so `isAccepted()` afterwards is the
  handler's decision, not the constructor's default.

## Design notes

**Resolved: Q1 (user, 2026-09-30)** — the Lead Designer's recommended option,
all five points. Recorded in `docs/wiki/design/components.md` §2 ("Drag copy").

Definitions: a *folder* is a local URL whose path is an existing directory when
the drag enters; every other local URL is a *file*. *Several* = 2 or more.
`{name}` = base name, never the full path. `\n` = one newline.

| Case | Headline | Body | Affordance | Accessible description |
|---|---|---|---|---|
| one folder (hover-valid) | `Release to load` | `{name}` | `""` | `Release to load\n{name}` |
| one file | `Drop a folder, not files` | `You are dragging a file: {name}.` | `""` | headline `\n` body |
| several files (n ≥ 2) | `Drop a folder, not files` | `You are dragging {n} files.` | `""` | headline `\n` body |
| several folders (n ≥ 2) | `Drop one folder` | `You are dragging {n} folders. Drop them one at a time.` | `""` | headline `\n` body |
| files and folders | `Drop a folder, not files` | `You are dragging {f} {file\|files} and {d} {folder\|folders}.` (singular at 1) | `""` | headline `\n` body |
| any non-local URL, or no URLs | *ignored*: drag not accepted, no state change | — | — | unchanged |

Examples: `You are dragging 1 file and 2 folders.`,
`You are dragging 3 files and 1 folder.`

- **Truncation.** A `{name}` longer than 40 characters becomes its first 20
  characters + `…` (U+2026) + its last 19 (40 total). Exactly 40 is not cut.
  Counted in characters, not pixels. Applies to both `{name}` slots.
- **Restore.** On leave, and after an invalid drop, headline, body, affordance
  and accessible description equal their values before the drag entered.
- **Accessible name** stays `Choose chapter folder` in every state (A-08).
- **A-10.** Every hover state differs from the state before it by headline
  wording, not only border colour.
- Visuals (unchanged): hover-valid border 2px solid `color.accent.base`, ground
  `overlay.fill.hover`; hover-invalid border 2px solid `color.status.danger`.
- **Drive root:** a drive root (`D:\`) has an empty base name; it shows the
  path as given (`D:\`). Decided by the Lead PO as PO-3 (the designer's
  proposal); RED pins it (Contract C-1).
