## Context

Brief feature 4 and section 3 step 4. This is also the story that makes the
headline success metric *measurable*: the O2 definition in
`docs/wiki/stack.md` §5 compares `norm(proposed)` against `norm(final)`, and
`final` is whatever this editor last committed.

Two design decisions from `docs/wiki/design/components.md` §5–§7 carry real
weight and are not to be softened:

- **"Looked at" is an explicit act, never inferred.** Inferring review from
  scroll position would make S1 measure scrolling. Status is
  `proposed / accepted / edited / reverted / failed`.
- **`reverted` is a distinct persisted state from `proposed`**, and the two are
  visually distinct. A user who reverted a line has made a judgement; a user who
  never looked at one has not, and S1 must be able to tell them apart.

And one durability requirement the designer flagged and `architecture.md` D7
satisfies: **a commit must be durable within 500 ms**, not held until render.
This user reviews for hours; losing an hour of typing is the worst thing the app
can do to them.

**Which required gate would fail if this story's artifact broke:** `unit`
(`tests/ui/` for the editor, `tests/core/` for the persistence and the status
machine).

## Acceptance criteria

- **AC-1** — Given a proposed line, when the user types into it and presses
  `Enter`, then its status becomes `edited`, and the new text is present in the
  project file within 500 ms of the commit.
- **AC-2** — Given an edited line, when `Ctrl+R` is pressed, then the field
  restores the machine proposal **exactly**, and the status becomes `reverted` —
  not `proposed`.
- **AC-3** — Given a line being edited, when `Esc` is pressed, then the field
  restores the value it had when editing began, and the status is unchanged.
- **AC-4** — Given a proposed line, when `Ctrl+Enter` is pressed, then the
  status becomes `accepted` with the text unchanged.
- **AC-5** — Given the editor, when `Shift+Enter` is pressed or text containing
  newlines is pasted, then no line break enters the value — pasted newlines
  collapse to single spaces.
  *(Manual line-break control is a brief §5 non-goal; the typesetter decides
  breaks.)*
- **AC-6** — Given a chapter with lines in each of the five statuses, when the
  app is closed and reopened, then every line's text and status come back
  exactly as they were.
- **AC-7** — Given a save that fails, when the failure surfaces, then the reason
  is shown **and the text stays in the field** — the user's typing is never
  discarded to report an error.
- **AC-8** — Given a line whose region was flagged `untranslated` (MT-011 AC-5)
  or `ocr_empty` (MT-010 AC-4), when it is shown, then its status is `failed`
  with a `Retry` control, and it is distinguishable from an empty `proposed`
  line.
- **AC-9** — Given any of the five statuses, when the row is rendered, then it
  carries a **distinct gutter glyph as well as a colour**, and `Revert`,
  `Accept` and `Retry` are always-visible controls on the row, never hover
  reveals.

## Contract

```

    LineStatus = Literal["proposed", "accepted", "edited", "reverted", "failed"]

    @dataclass(frozen=True) Line:
        region_id: int
        source_ja: str
        proposed_en: str
        final_en: str | None          # NULL until the user commits something
        status: LineStatus
        edited_at: datetime | None

    def normalise(text: str) -> str   # THE O2 DEFINITION — see below
    def effective_text(line: Line) -> str
    def is_accepted_as_is(line: Line) -> bool

src/mangatl/ui/line_editor.py
    SAVE_DEBOUNCE_MS: int = 500
    class LineEditor(QWidget): ...

src/mangatl/store/lines.py
    def commit_line(project, region_id, text, status) -> None
```

**`normalise` is the O2 definition and belongs to `domain`, not to `bench`.**
`docs/wiki/stack.md` §5/O2, exactly:

1. Unicode NFC normalisation;
2. every run of whitespace (including internal line-break markers) collapsed to
   a single space;
3. leading and trailing whitespace stripped.

It does **nothing else**. A one-word fix is a rejection; a punctuation change is
a rejection; a capitalisation change is a rejection. It lives here because
MT-022 measures with it and this story writes the strings it measures — one
definition, one implementation, no second copy in the benchmark harness.

**Other semantics:**

- **`final_en` is `NULL` until the user commits.** `is_accepted_as_is` compares
  `normalise(proposed_en)` with `normalise(final_en or proposed_en)`, so an
  edit-then-restore counts as accepted. That is deliberate — the metric measures
  the output, not the user's mouse.
- **`SAVE_DEBOUNCE_MS = 500`** is an upper bound on data loss, not a
  performance tuning knob. AC-1 asserts the bound.
- **`*italic*` and `**bold**` are literal text** that MT-020 resolves. The editor
  does not render them and does not strip them.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1..AC-6, AC-8 | **Mechanical** | A status machine and a persistence round trip. Pin exactly. AC-2's "exactly" means character-for-character against `proposed_en`, not against a normalised form. |

normalises identically to NFC input. **If a generator is narrowed, name the
design clause** — "text contains no lone surrogates" is legitimate; "the test
was failing on this codepoint" is not.

## Design notes

*Lifted from `docs/wiki/design/README.md`:*

> The `LineEditor` is a plain single-logical-line field, `type.editor`, ground
> `color.surface.sunken`, 2px `color.accent.base` border while editing. It
> accepts no line breaks: `Shift+Enter` does nothing and pasted newlines collapse
> to spaces, because manual line-break control is a brief §5 non-goal.
> `*italic*` and `**bold**` are literal text the typesetter resolves later.
> `Enter` commits, `Esc` restores the value the field had when editing began,
> `Ctrl+R` reverts to the machine proposal, `Ctrl+Enter` marks the line accepted
> without editing. Status is one of `proposed / accepted / edited / reverted /
> failed`, each with a distinct gutter glyph as well as a colour, and `Revert` /
> `Accept` / `Retry` are always-visible controls on the row, never hover reveals.
> A commit writes to disk (debounced 500 ms); a failed save shows the reason and
> **keeps the text in the field**. See components.md §5–7, accessibility.md
> A-07, A-10.
>
> **Assertable:** typing into a line and pressing `Enter` moves its status to
> `edited` and the value is present on disk; pressing `Ctrl+R` afterwards
> restores the proposal text exactly and the status becomes `reverted`, not
> `proposed` — and the two are visually distinct.

Note also that **review does not gate render** (`components.md` §7): the bake
dialog states the count of unreviewed lines and proceeds.

## Deferred verifications

  plausible "helpful" addition — the property test and MT-022's acceptance
  measurement **must** both change; specifically, a fixture pair differing only

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition mixed**; the table goes in the dispatch prompt verbatim.
  State that `normalise` is **settled** — it is the O2 definition from
  `stack.md` §5 and the story implements it, it does not design it. A RED phase
  that adds case-folding or punctuation-stripping "for robustness" has silently
  changed the product's headline metric.
- **Success condition, falsifiable:** RED's suite contains a case-only
  difference and a punctuation-only difference and asserts **both are
  rejections**; and AC-2 asserts `reverted`, not "not proposed". A suite that
  would pass against a `normalise` doing case folding has failed RED.
- **Verdict:** *to be recorded.*
