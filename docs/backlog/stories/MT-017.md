## Context

Brief feature 4 and section 3 step 4. This is also the story that makes the
headline success metric *measurable*: the O2 definition in
`docs/wiki/stack.md` §5 compares `norm(proposed)` against `norm(final)`, and
`final` is whatever this editor last committed.

Two design decisions from `docs/wiki/design/components.md` §5–§7 carry real
weight and are not to be softened:

- **"Looked at" is an explicit act, never inferred.** Inferring review from
  scroll position would make S1 measure scrolling. Status is
  `proposed / accepted / edited / reverted / failed`.
- **`reverted` is a distinct persisted state from `proposed`**, and the two are
  visually distinct. A user who reverted a line has made a judgement; a user who
  never looked at one has not, and S1 must be able to tell them apart.

And one durability requirement the designer flagged and `architecture.md` D7
satisfies: **a commit must be durable within 500 ms**, not held until render.
This user reviews for hours; losing an hour of typing is the worst thing the app
can do to them.

**Which required gate would fail if this story's artifact broke:** `unit`
(`tests/ui/` for the editor, `tests/core/` for the persistence and the status
machine).

## Acceptance criteria

- **AC-1** — Given a proposed line, when the user types into it and presses
  `Enter`, then its status becomes `edited`, and the new text is present in the
  project file within 500 ms of the commit.
- **AC-2** — Given an edited line, when `Ctrl+R` is pressed, then the field
  restores the machine proposal **exactly**, and the status becomes `reverted` —
  not `proposed`.
- **AC-3** — Given a line being edited, when `Esc` is pressed, then the field
  restores the value it had when editing began, and the status is unchanged.
- **AC-4** — Given a proposed line, when `Ctrl+Enter` is pressed, then the
  status becomes `accepted` with the text unchanged.
- **AC-5** — Given the editor, when `Shift+Enter` is pressed or text containing
  newlines is pasted, then no line break enters the value — pasted newlines
  collapse to single spaces.
  *(Manual line-break control is a brief §5 non-goal; the typesetter decides
  breaks.)*
- **AC-6** — Given a chapter with lines in each of the five statuses, when the
  app is closed and reopened, then every line's text and status come back
  exactly as they were.
- **AC-7** — Given a save that fails, when the failure surfaces, then the reason
  is shown **and the text stays in the field** — the user's typing is never
  discarded to report an error.
- **AC-8** — Given a line whose region was flagged `untranslated` (MT-011 AC-5)
  or `ocr_empty` (MT-010 AC-4), when it is shown, then its status is `failed`
  with a `Retry` control, and it is distinguishable from an empty `proposed`
  line.
- **AC-9** — Given any of the five statuses, when the row is rendered, then it
  carries a **distinct gutter glyph as well as a colour**, and `Revert`,
  `Accept` and `Retry` are always-visible controls on the row, never hover
  reveals.

### C-1 — `src/mangatl/domain/line.py` (added beside the existing `OcrResult`)

```python
LineStatus = Literal["proposed", "accepted", "edited", "reverted", "failed"]
LINE_STATUSES: tuple[LineStatus, ...] = ("proposed", "accepted", "edited", "reverted", "failed")

#: The three statuses a user's act writes. `proposed` and `failed` are never
#: stored; they are derived (C-2).
COMMITTED_STATUSES: frozenset[LineStatus] = frozenset({"accepted", "edited", "reverted"})

@dataclass(frozen=True)
class Line:
    reading_index: int          # NOT region_id - see below
    source_ja: str
    proposed_en: str | None     # None = no proposal (untranslated, or not yet run)
    final_en: str | None        # None until the user commits text
    status: LineStatus
    edited_at: datetime | None  # tz-aware UTC; time of the last commit, any status
    ocr_empty: bool = False

def normalise(text: str) -> str               # THE O2 DEFINITION - C-3
def effective_text(line: Line) -> str          # C-4
def is_accepted_as_is(line: Line) -> bool      # C-4
def derive_status(stored: str | None, *, ocr_empty: bool,
                  proposed_en: str | None, page_done: bool) -> LineStatus   # C-2
def failure_reason(line: Line) -> str | None   # C-2
```

**`reading_index`, not `region_id`.** The contract as first drafted said
`region_id`. Every existing addressing of a line - `Project.write_proposed`,
`read_proposed`, `store.glossary.reconcile_from_edit` - is `(page_ordinal,
reading_index)`, and the UI's `OrderedRegion.region_id` / `TranslationRow.region_id`
is in fact the reading index (`workspace._load_regions` builds it from
`enumerate`). The database's `region.id` never leaves the store.

`domain` imports nothing of ours and no third-party package (`architecture.md` §3
contract 2): `unicodedata`, `dataclasses`, `datetime` and `typing` only.

### C-2 — Status: which are stored, which are derived

| Status | Stored in `line.status`? | Reached by |
|---|---|---|
| `proposed` | never (NULL) | derived: nothing committed, not failed |
| `accepted` | yes | `Ctrl+Enter` / Accept on a `proposed` line (C-7) |
| `edited` | yes | a commit whose text differs from `proposed_en` (C-7) |
| `reverted` | yes | `Ctrl+R` / Revert on an `edited` line, or a commit that retypes the proposal exactly on an `edited`/`reverted` line (C-7) |
| `failed` | never (NULL) | derived: `ocr_empty`, or no proposal on a page the run finished |

`derive_status(stored, *, ocr_empty, proposed_en, page_done)`:

1. `stored` not `None` → `stored` (a user's act outranks the pipeline's flag:
   a failed line the user typed a translation into is `edited`);
2. else `ocr_empty` → `"failed"` (MT-010 AC-4);
3. else `proposed_en is None and page_done` → `"failed"` (MT-011 AC-5's
   untranslated region: the run finished the page and the model gave nothing);
4. else → `"proposed"`.

Rule 3's `page_done` is `Project.page_status(ordinal) == PAGE_DONE`. A page the
run has not reached also has NULL `proposed_en`; it is **not** failed, and the
row reads "not translated" / "machine proposal" exactly as MT-016 left it. (PO-3.)

`failure_reason(line)`: `None` unless `line.status == "failed"`; then
`"no text was read in this bubble"` if `line.ocr_empty`, else
`"no translation was returned"`.

`derive_status` raises `ValueError` for a `stored` value outside
`COMMITTED_STATUSES` - a file carrying `'proposed'` or `'banana'` in that column
is corrupt, and the schema CHECK (C-5) should already have refused it.

### C-3 — `normalise` is the O2 definition, verbatim, and nothing else

`docs/wiki/stack.md` §5/O2, exactly:

1. Unicode NFC normalisation;
2. every run of whitespace (including internal line-break markers) collapsed to
   a single space;
3. leading and trailing whitespace stripped.

Pinned implementation shape: `" ".join(unicodedata.normalize("NFC", text).split())`.
"Whitespace" is therefore exactly `str.isspace()` - which includes `\n`, `\r`,
`\t`, U+00A0, U+2028, U+2029, U+3000 (ideographic space). It does **nothing
else**: no case folding, no punctuation stripping, no quote or dash
normalisation, no NFKC (NFKC would fold full-width `Ａ` to `A` - a change O2
does not make). A one-word fix is a rejection; a punctuation change is a
rejection; a capitalisation change is a rejection; deleting the line is a
rejection. It lives in `domain` because MT-022 measures with it and this story
writes the strings it measures - one definition, no second copy in `bench`.

Properties RED must state with `hypothesis`: idempotent
(`normalise(normalise(s)) == normalise(s)`); NFD and NFC spellings of the same
text normalise identically; the output never starts or ends with whitespace and
never contains two consecutive whitespace characters or any whitespace other
than U+0020. **Default `st.text()` excludes lone surrogates (category Cs); that
is the only narrowing permitted, and its design clause is that a Python `str`
read from SQLite or a Qt widget cannot carry one.** Plus example cases: a
case-only difference and a punctuation-only difference are both rejections
(Model guidance's falsifiable success condition).

### C-4 — `effective_text` and `is_accepted_as_is`

- `effective_text(line)` = `line.final_en` if it is not `None`, else
  `line.proposed_en` if it is not `None`, else `""`.
- `is_accepted_as_is(line)` = `line.proposed_en is not None and
  normalise(line.proposed_en) == normalise(effective_text(line))`.

**Not `final_en or proposed_en`.** The drafted wording was
`normalise(final_en or proposed_en)`, and `or` treats a committed `""` as
absent: a user who deleted the whole line would count as accepting the
proposal. O2 says outright "Deleting the line is a rejection." The test that
pins this is a line with `proposed_en="Hello."`, `final_en=""` →
`is_accepted_as_is` is `False`.

`is_accepted_as_is` does not read `status`: O2 compares strings, not history,
so `edited` → retyped-to-match counts as accepted, and an unreviewed
`proposed` line with `final_en is None` also counts (S1b's denominator is the
benchmark's business, MT-022).

### C-6 — `src/mangatl/store/lines.py` (new)

```python
def read_review_lines(project: Project, page_ordinal: int) -> tuple[Line | None, ...]
def commit_line(project: Project, page_ordinal: int, reading_index: int,
                text: str | None, status: LineStatus) -> None
```

- `read_review_lines`: one entry per **region** of the page, in reading order
  (`LEFT JOIN`, as `_SELECT_PROPOSED` does); `None` for a region with no `line`
  row (OCR has not run). Each `Line` carries `status = derive_status(...)`
  with `page_done` read from `project.page_status(page_ordinal) == PAGE_DONE`,
  and `edited_at` parsed from the stored ISO-8601 string (tz-aware UTC) or
  `None`. `()` for a page with no regions. Opens no transaction.
- `commit_line`: in one `project.transaction()`, sets on that line row
  `final_en = text` (`None` → NULL), `status = status`,
  `edited_at = datetime.now(UTC).isoformat()`. Then - **after** that transaction
  has committed, because `Project.transaction()` is not reentrant - if `text is
  not None`, calls `store.glossary.reconcile_from_edit(project, page_ordinal,
  reading_index, text)` (the MT-014 obligation in `## Notes`).
- `commit_line` raises `ValueError` for a `status` outside
  `COMMITTED_STATUSES`, for a reading index not on the page, and `LookupError`
  when the region has no `line` row - all **before** writing anything. It does
  not normalise or otherwise alter `text`: the store stores what it is given,
  character for character (AC-2's "exactly").

### C-7 — `src/mangatl/ui/line_editor.py` (new): the status machine

```python
SAVE_DEBOUNCE_MS: int = 500

SaveFn = Callable[[str | None, LineStatus], None]   # (final_en, status); raises on failure

class LineEditor(QLineEdit):
    statusChanged = Signal(str)        # the new LineStatus
    saveFailed = Signal(str)           # the reason shown
    saveSucceeded = Signal()
    def __init__(self, line: Line, save: SaveFn | None, parent: QWidget | None = None) -> None
    @property
    def status(self) -> LineStatus
    @property
    def line(self) -> Line              # the in-memory state after the last commit
    def revert(self) -> None            # Ctrl+R and the Revert button
    def accept_line(self) -> None       # Ctrl+Enter and the Accept button
    def flush(self) -> None             # write any pending save now, synchronously
```

**`QLineEdit`, not `QWidget`** (the draft said `QWidget`). MT-016 tests
reach the row's editor as `row.editor` and assert `QApplication.focusWidget()
is editor` after the canvas's edit request; a composite `QWidget` would put
focus on a child and break that for no benefit. The gutter, the actions and
the error caption are the **row's** (C-8), and read the editor's state.

"Editing began" = the editor gains focus; the value at that moment is the
**edit-start value** that `Esc` restores. Transitions (`P` = `line.proposed_en`,
`T` = the field's text after C-9's newline collapse):

| Key / act | Precondition | Field becomes | Status becomes | Save called with |
|---|---|---|---|---|
| `Enter` | `T` == edit-start value | unchanged | unchanged | nothing |
| `Enter` | `T` != `P` (incl. `P is None`) | `T` | `edited` | `(T, "edited")` |
| `Enter` | `T` == `P` exactly, status `edited`/`reverted` | `T` | `reverted` | `(T, "reverted")` |
| `Enter` | `T` == `P` exactly, status `proposed`/`accepted`/`failed` | `T` | unchanged | nothing |
| `Ctrl+R` / Revert | status `edited`, `P` not `None` | `P` **exactly** | `reverted` | `(P, "reverted")` |
| `Ctrl+R` | any other status, or `P is None` | `P` if dirty and `P` not `None`, else unchanged | unchanged | nothing |
| `Ctrl+Enter` / Accept | status `proposed`, field not dirty | unchanged | `accepted` | `(None, "accepted")` |
| `Ctrl+Enter` | field dirty | as `Enter` | as `Enter` | as `Enter` |
| `Ctrl+Enter` | status not `proposed`, not dirty | unchanged | unchanged | nothing |
| `Esc` | - | edit-start value | unchanged | nothing |
| focus out | field dirty | as `Enter` | as `Enter` | as `Enter` |
| `Shift+Enter` | - | unchanged | unchanged | nothing (AC-5) |

"Exactly" is `==` on `str`: no `normalise`, no strip. "Dirty" = field text !=
edit-start value. A commit that is a no-op above writes nothing and does not
touch `edited_at`. `accepted` keeps `final_en` NULL (the text is unchanged).

**Saving - AC-1's bound, and AC-6's durability.** A commit updates the in-memory
`line`/`status` and emits `statusChanged` at once, then starts a single-shot
timer of `SAVE_DEBOUNCE_MS` (`Qt.TimerType.PreciseTimer`) if one is not already
running; **a later commit does not restart it** - it is an upper bound on data
loss, not a debounce that a fast typist can postpone forever. When it fires, the
**latest** committed `(final_en, status)` is passed to `save`. `flush()` does the
same immediately and stops the timer. `TranslationColumn.set_rows` flushes every
existing row's editor before discarding it, and `Workspace.closeEvent` flushes
the column: a page change or a window close never drops a pending save.
`save is None` (a row with no project behind it) makes every save a no-op
success.

**A failed save (AC-7).** `save` raising any `Exception` → the field text is
**kept** (never reset to the edit-start value or the proposal), the editor's
dynamic property `saveError` is `True` (re-polished), `saveFailed` is emitted with
`f"Not saved: {exc}"`, and the pending save stays pending: the next commit or
`flush()` retries it. A later successful save clears `saveError` and emits
`saveSucceeded`. The in-memory status is the committed one - the caption, not
the glyph, says it is not on disk.

`*italic*` and `**bold**` are literal text; the editor neither renders nor strips
them.

### C-9 — One logical line (AC-5)

`Shift+Enter` (and `Shift+Return`) inserts nothing and changes no status. Any
text inserted by paste (`Ctrl+V`, `Shift+Insert`, the context menu, drop) has
each maximal run of line-break characters - `\r`, `\n`, `\v`, `\f`, `\x1c`,
`\x1d`, `\x1e`, `\x85`, U+2028, U+2029 - replaced by **one** U+0020. Other
whitespace, including spaces adjacent to the break, is left as pasted:
`"a \n b"` → `"a   b"`; `"a\r\n\r\nb"` → `"a b"`. (The editor does not
normalise; that is O2's job at measurement.) A `QValidator` whose `fixup`/
`validate` rewrites the text is one sound way to cover every insert path;
GREEN's choice, and RED tests at least `Ctrl+V` and `insert()`.

## Design notes

*Lifted from `docs/wiki/design/README.md`:*

> The `LineEditor` is a plain single-logical-line field, `type.editor`, ground
> `color.surface.sunken`, 2px `color.accent.base` border while editing. It
> accepts no line breaks: `Shift+Enter` does nothing and pasted newlines collapse
> to spaces, because manual line-break control is a brief §5 non-goal.
> `*italic*` and `**bold**` are literal text the typesetter resolves later.
> `Enter` commits, `Esc` restores the value the field had when editing began,
> `Ctrl+R` reverts to the machine proposal, `Ctrl+Enter` marks the line accepted
> without editing. Status is one of `proposed / accepted / edited / reverted /
> failed`, each with a distinct gutter glyph as well as a colour, and `Revert` /
> `Accept` / `Retry` are always-visible controls on the row, never hover reveals.
> A commit writes to disk (debounced 500 ms); a failed save shows the reason and
> **keeps the text in the field**. See components.md §5–7, accessibility.md
> A-07, A-10.
>
> **Assertable:** typing into a line and pressing `Enter` moves its status to
> `edited` and the value is present on disk; pressing `Ctrl+R` afterwards
> restores the proposal text exactly and the status becomes `reverted`, not
> `proposed` — and the two are visually distinct.

Note also that **review does not gate render** (`components.md` §7): the bake
dialog states the count of unreviewed lines and proceeds.

**Contract mechanisms checked, not assumed.**
- *C-9's `QValidator`* holds. A validator that returns the rewritten string
  covers Ctrl+V, Shift+Insert, `insert()` and `setText()`, which is what RED's
  probe found. One consequence: a proposal that itself contains a line break is
  collapsed when it is shown, so Ctrl+R could not put it back "exactly". The
  translate stage's output has never been seen to carry one, and no test covers
  it. This is noted, not fixed.

  granularity (see above), but the bound holds.
- *Flush on `set_rows` / `closeEvent`* holds. `TranslationColumn.flush()` first

  would (C-7 row 11), and then flushes. Without that step, text typed but not
  committed when the window closes would be committed by the focus-out that

  stylesheet is applied: nothing in `mangatl.app` or the tests loads

### PO decisions at PLANNED → RED (2026-09-30, lead-po)

- **PO-1 — the epic's done-when has a gap no story closes; filed, not absorbed.**
  EPIC-05's done-when is "open a chapter that has been translated … edit a line,
  revert it, close the app, reopen it and find their edits". `mangatl.app.main`
  still opens the empty `MainWindow` (MT-015 PO-4 deferred wiring `Workspace`
  into the app "until a story gives the window a chapter to open"), and no story
  in the backlog does so. Absorbing it here would add an app-level entry point and
  a chapter picker to a story that is already one full status machine. Decision:
  **filed as MT-054** ("The app opens a chapter in the review workspace",
  EPIC-05, `depends_on: [MT-017]`). MT-017's AC-6 is verified at the level that
  exists: `Workspace` + `Project` closed, `open_project` on the same directory,
  a fresh `Workspace`. Reported to the user before RED so they can overrule.
- **PO-2 — `reverted` is a return arrow alone (↩), in every theme.** Resolves
  the open decision in `docs/wiki/design/README.md` item 6 / `components.md`
  §10.4 / accessibility.md A-15.7, which is explicitly the PO's and "would amend
  §7 and MT-017". One glyph set is cheaper to build and to test than two, and
  the `edited`/`reverted` distinction is what S1 leans on: a filled versus an
  outlined 16 px pencil is the one pair that fails in one colour, and there is
  no reason to keep the weaker pair in the default theme. The Lead Designer
  should update the `reverted` row of components.md §5's table to match; until
  then this decision and C-8's `STATUS_GLYPHS` are the source.
- **PO-3 — "untranslated" needs the page to be done.** `proposed_en IS NULL`
  means both "the model returned nothing" (MT-011 AC-5) and "the run has not
  translated this page yet". C-2 rule 3 separates them with `page.status ==
  'done'`, which already exists, rather than adding a column. `ocr_empty` is
  `failed` unconditionally (MT-010 AC-4 is a completed read).
- **PO-4 — `Retry line` is a control with no production handler yet.** AC-8
  requires the control; re-translating one line is a paid pipeline call with its

  **Reported to the user as an unowned gap** — it needs a story (likely in
  EPIC-03/EPIC-04 alongside the translate stage), and the user may prefer the
  button hidden until it does something.
- **PO-5 — a `failed` line is editable.** The user typing their own English
  into a bubble the model could not read is the fix the review screen exists for.
  The committed status is `edited` (C-2 rule 1: the user's act outranks the
  pipeline flag). There is no revert on such a line: there is no proposal to
  revert to.
