## Context

MT-115 PO-2's follow-up, the window half; the CLI half is **MT-140** (cut
beside this story, MT-140 PO-4). MT-115 built the pass as a `ChapterStep`
and gave `run_chapter` and `collect_volume` a keyword-only `postlude`;
`compose.build_consistency(selection)` builds it. The window reaches neither
hook today: `app.build_batch`'s collect closure calls `collect_volume`
without a postlude, and the per-page run goes `app.build_stages -> RunSetup
-> RunController -> run_chapter` with no chapter step at all. **MT-139**
rewrites that per-page path to carry a `Pipeline` down to `RunController`;
this story waits for it (a true dependency: the step rides whatever MT-139
carries, and MT-139 writes the same five files) and then adds the postlude
to both paths, and says in the window what the pass did and when it did
not run.

Two things are settled now and two are open for this story's own PLANNED:

- Settled: the step is built by `build_consistency(selection)` in `app.py`,
  in the same selection the batch and the stages are built from (MT-140
  PO-1's seam, the window's composition root being `app.py`); a refused or
  failed pass aborts the run it belongs to (MT-115 PO-3) and the window shows
  it as a banner, never a modal (`progress.py`'s rule); the pass is always
  on (MT-140 PO-5).
- Open, **Q-2**: where the counts go. The pass runs inside the poll worker,
  so the **waiting panel** is on screen while it runs (a sentence there,
  `Checking the chapter for consistency...`, costs nothing), but
  `MainWindow._batch_ended("collected")` opens the review the moment the
  poll ends, so a count on the waiting panel is gone before it is read. The
  candidates are a line in the review's header, or nothing beyond MT-116's
  per-line marking of corrected lines. The Lead Designer decides at
  PLANNED, with the user if it is a product call.
- Open, **Q-3**: a refused pass on the batch path. `collect_volume` reports
  it as `RunAborted(BUDGET, None)` on the poll's stream and the controller
  still ends `collected`, so today the review would open with no word that
  the pass did not run. Either the controller ends with a new `BatchEnd`
  (`"pass_refused"`, the window keeping the waiting panel with the banner
  and an action to open the review), or the review opens with a banner. The
  per-page path has no such problem: `RunAborted(BUDGET, None)` after every
  page is done reaches `RunProgressPanel`, which today would say `Run
  stopped at page N+1 of N` - wrong - and the draft AC-4 below fixes it.

Required gates: `unit`, `coverage` (`tests/ui`); `frozen` covers
`src/mangatl/app.py`.

## Acceptance criteria

*Draft; finalised at this story's PLANNED once MT-139 is DONE and Q-2/Q-3
are answered. Wording below is the PO's placeholder, to be settled with the
Lead Designer under `docs/wiki/design/voice.md`.*

- **AC-1** - `app.build_batch`'s collect closure calls `collect_volume(...,
  postlude=build_consistency(selection))`, the step built once per
  `build_batch` call from the same selection; an app-level test drives one
  collection through the closure and sees the step run after the last job's
  `BatchCollected` (the pattern of
  `test_build_batch_collects_one_job_through_collect_volume_at_the_batch_estimate`).
- **AC-2** - The window's per-page run passes the step as `run_chapter`'s
  `postlude` (through whatever MT-139 made `RunSetup.build_stages` return:
  a `postlude` on the `Pipeline`, or a builder beside it - this story's
  PLANNED decides), so a Gemini run started from the window ends with the
  pass between the last page and `RunFinished`; an app-level test pins that
  the default setup carries it, as MT-139 AC-1 pins the prelude.
- **AC-3** - While the pass runs on the batch path the waiting panel says
  `Checking the chapter for consistency...` (set on the last job's
  `BatchCollected`); the review then opens as today when the pass ran, and
  the counts are shown where Q-2 decides.
- **AC-4** - A `RunAborted(BUDGET, None)` arriving at `RunProgressPanel` after
  every page is complete (the pass refused on the per-page path) shows the
  budget banner with the headline `Consistency pass not run - the $X budget
  was reached.`, the body `All N pages are translated and can be reviewed.`
  and the action `Review pages 1-N`; a non-budget `RunAborted(reason, None)`
  in the same position shows the failed banner with the reason and the same
  body and action. Neither says `Run stopped at page N+1`.
- **AC-5** - A refused pass on the batch path is shown as Q-3 decides, and
  the review is never opened silently over a refused pass.
- **AC-6** - A setup whose `build_consistency` answers `None` (Anthropic) runs
  and collects exactly as today: no step, no sentence, no banner.
