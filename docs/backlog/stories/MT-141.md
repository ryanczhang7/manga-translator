## Context

MT-115 PO-2's follow-up, the window half; the CLI half is **MT-140** (cut
beside this story, MT-140 PO-4). MT-115 built the pass as a `ChapterStep`
and gave `run_chapter` and `collect_volume` a keyword-only `postlude`;
`compose.build_consistency(selection)` builds it. The window reaches neither
hook today: `app.build_batch`'s collect closure calls `collect_volume`
without a postlude, and the per-page run goes `app.build_stages -> RunSetup
-> RunController -> run_chapter` with no chapter step at all. **MT-139**
rewrites that per-page path to carry a `Pipeline` down to `RunController`;
this story waits for it (a true dependency: the step rides whatever MT-139
carries, and MT-139 writes the same five files) and then adds the postlude
to both paths, and says in the window what the pass did and when it did
not run.

Two things are settled now and two are open for this story's own PLANNED:

- Settled: the step is built by `build_consistency(selection)` in `app.py`,
  in the same selection the batch and the stages are built from (MT-140
  PO-1's seam, the window's composition root being `app.py`); a refused or
  failed pass aborts the run it belongs to (MT-115 PO-3) and the window shows
  it as a banner, never a modal (`progress.py`'s rule); the pass is always
  on (MT-140 PO-5).
- Open, **Q-2**: where the counts go. The pass runs inside the poll worker,
  so the **waiting panel** is on screen while it runs (a sentence there,
  `Checking the chapter for consistency...`, costs nothing), but
  `MainWindow._batch_ended("collected")` opens the review the moment the
  poll ends, so a count on the waiting panel is gone before it is read. The
  candidates are a line in the review's header, or nothing beyond MT-116's
  per-line marking of corrected lines. The Lead Designer decides at
  PLANNED, with the user if it is a product call.
- Open, **Q-3**: a refused pass on the batch path. `collect_volume` reports
  it as `RunAborted(BUDGET, None)` on the poll's stream and the controller
  still ends `collected`, so today the review would open with no word that
  the pass did not run. Either the controller ends with a new `BatchEnd`
  (`"pass_refused"`, the window keeping the waiting panel with the banner
  and an action to open the review), or the review opens with a banner. The
  per-page path has no such problem: `RunAborted(BUDGET, None)` after every
  page is done reaches `RunProgressPanel`, which today would say `Run
  stopped at page N+1 of N` - wrong - and the draft AC-4 below fixes it.

Required gates: `unit`, `coverage` (`tests/ui`; both `required`, both
`covers: src/mangatl/**`, checked against `gates.sh --list` at PLANNED).

**Settled at PLANNED (2026-11-08, lead-po on Claude Fable 5.1; MT-139 and
MT-140 both DONE):** Q-2 and Q-3 are answered under `## Design notes` D-1
and D-2 and `## Notes` PO-3/PO-4; the step reaches `RunController` through a
defaulted `RunSetup.build_postlude` builder, not a `Pipeline` field (PO-1);
and the window's **Run again** carries the step too, because it is the
window's way to finish a chapter whose pass was refused (PO-2) - which adds
`ui/workspace.py` and its test to `touches:`.

- **AC-1** - `app.build_batch`'s collect closure calls
  `collect_volume(project, job, collector, estimate, emit, postlude=step)`,
  where `step` is `build_consistency(selection)` built **once per
  `build_batch` call**, from the same `selection` the collector was built
  from. An app-level test (the pattern of
  `test_build_batch_collects_one_job_through_collect_volume_at_the_batch_estimate`,
  with a `build_consistency` seam beside the `batch_seams` fixture's
  `build_batch_collector`) drives the volume's only job through the closure
  and sees the step called exactly once, after that job's `BatchCollected`,
  with the job's `run_id`; a second collection through a second `build_batch`
  call builds a second step. A seam answering `None` gives a collection whose
  events are exactly today's.
- **AC-2** - `RunSetup` gains `build_postlude: PostludeBuilder | None = None`
  (`PostludeBuilder = Callable[[], ChapterStep | None]`); `app.build_postlude()`
  returns `build_consistency(selection)` for the selection `build_stages`
  makes (the environment plus the stored key, `MANGATL_PROVIDER` choosing

  `app.build_postlude` **itself** (the pattern of

  per-page run and `Workspace._rerun`'s Run again each call the setup's
  `build_postlude()` once, beside `build_stages`, and hand the result to
  `RunController`, which passes it as `run_chapter`'s `postlude`; so a run
  started from the window runs the pass once, after the last page of the
  final pass and before `RunFinished`, with the run's id. Tests: a Start
  through a setup whose `build_postlude` answers a recording step sees it
  called exactly once, after the last page's events and before
  `RunFinished`, with `RunStarted.run_id`; the same for Run again from the
  workspace.
- **AC-3** - The waiting panel, once it has seen a `BatchCollected` for every
  job of its `WaitingState` (`job_count` of them, counted from `show_state`),
  shows `Checking the chapter for consistency…` (U+2026) on a line with
  object name `batch-pass`, appended to its accessible name after the lines
  it has today; before that the line is empty and hidden and the accessible
  name is unchanged. The review then opens as today when the pass ran
  (`"collected"`).
- **AC-4** - A `RunAborted(reason, ordinal=None)` arriving at a non-batch
  `RunProgressPanel` **after every page of the run's pass has started or been
  skipped** (the pass refused or failed after the last page) shows, for
  `reason == BUDGET`, the banner headline `Consistency pass not run — the
  budget would be exceeded.` (U+2014), body `Every page is translated and can
  be reviewed and rendered.`, the one action `Review the chapter`, and the
  cost readout marked aborted; for any other reason but `CANCELLED`, the
  headline `Consistency pass failed.`, body `{reason}\nEvery page is
  translated and can be reviewed and rendered.`, the same action, the readout
  untouched. The action emits `review_requested(page_count)`. Neither banner
  contains `Run stopped`. The banners for a chapter step refused or failed
  **before** page 1 of the translating pass (MT-139) read exactly as today.
- **AC-5** - On the batch path, a poll that leaves no job pending and during
  which a `RunAborted` was emitted ends the `BatchController` with the new
  `BatchEnd` `"pass_not_run"` (a `BatchFailed` in the same poll still ends
  `"failed"`); the waiting panel, on that `RunAborted`, shows the AC-4 banner
  (same headlines, body and action, chosen by the reason the same way),
  clears and hides the `batch-pass` line, and its action emits
  `review_requested`; `MainWindow` connects that to the review and opens
  **nothing** on `"pass_not_run"`. A window test drives a reopened pending
  job through a collect that emits `BatchCollected` then
  `RunAborted(BUDGET, None)` and asserts the review did not open, the waiting
  panel is still the central widget with the banner, and activating the
  action opens the review.
- **AC-6** - A setup with no `build_postlude`, or whose `build_postlude`
  answers `None`, runs exactly as today: `run_chapter` receives
  `postlude=None`, no panel line or banner changes, and every existing
  `tests/ui` test passes unchanged. `app.build_postlude()` answers `None` for
  an Anthropic selection and raises `ProviderError` for a keyless one before
  building anything.

### C-4 - `ui/progress.py`: the pass banners on the per-page panel

In `on_event`'s `RunAborted` arm, before the `BUDGET` / `CANCELLED`
branches, **only for a non-batch panel**:

```python
elif isinstance(event, RunAborted):
    if self._batch:
        self._batch_abort(event)
    elif event.ordinal is None and self._after_every_page():
        self._pass_abort(event)                           # AC-4
    elif event.reason == BUDGET:
        self._budget_abort(event)
    elif event.reason != CANCELLED:
        self._failed(event)

def _after_every_page(self) -> bool:
    """The run reached its postlude: every page of the pass in progress has
    started or been skipped. `_current` counts, because nothing but the next
    `PageStarted` or `RunFinished` completes the last page, and the postlude
    runs only when every page completed (runner.py:189)."""
    started = self._completed + self._skipped + (1 if self._current is not None else 0)
    return self._page_count > 0 and started == self._page_count

def _pass_abort(self, event: RunAborted) -> None:
    self._complete_current()                              # the last page did complete
    if event.reason == CANCELLED:
        return
    if event.reason == BUDGET:
        headline = "Consistency pass not run \N{EM DASH} the budget would be exceeded."
        lead = ""
    else:
        headline = "Consistency pass failed."
        lead = event.reason + "\n"
    banner = ErrorBanner(headline, lead + PASS_SURVIVED, (REVIEW_CHAPTER,), self)
    for button in banner.actions:
        button.clicked.connect(lambda: self.review_requested.emit(self._page_count))
    self._column.insertWidget(0, banner)
    banner.show()
    self.banner = banner
    banner.announce()
    banner.actions[0].setFocus(Qt.FocusReason.OtherFocusReason)
    if event.reason == BUDGET:
        self.cost_readout.mark_aborted()

PASS_SURVIVED = "Every page is translated and can be reviewed and rendered."
REVIEW_CHAPTER = "Review the chapter"
```

GREEN may fold `_pass_abort`'s banner lines into `_show_banner` by giving it
the body and actions explicitly; the pinned surface is the banner's
`headline`, `body` text, `actions` labels, the `review_requested` argument,
the readout state and focus, not the private helpers. The two constants live
in `progress.py` so `batch_panel.py` imports them from there (it already
imports `ErrorBanner`), never re-spelling them; `__all__` gains both.

**Why "every page has started or been skipped" tells the postlude from the
prelude.** In a two-pass run `PassStarted(TRANSLATING)` zeroes the counters
(`_reset_pass`) before the prelude runs, so a prelude's `RunAborted(None)`
arrives with `started == 0`; a postlude's arrives with every page started.
In a one-pass run (no `PassStarted`; `tests/ui/test_start_run.py`'s fakes)
the same count holds. A resumed run whose pages are all `PageSkipped` and
whose pass is then refused is `_skipped == _page_count`: covered. A page
failure carries an ordinal and never enters this arm.

### Oracle partition

All six criteria are **mechanical**: a keyword argument reaching a call, a
call count and order, exact strings on named widgets, a `Literal` value, an
accessible name. Pin each exactly - the strings from this section, never
read back from the module - and invent no metric. The negative controls are
AC-6 (no step) and the MT-139 banners that must still read as today

## Design notes

Lead Designer at PLANNED (2026-11-08, Claude Fable 5.1), against
`voice.md` ("Errors": what happened, what survived, what to do) and
`components.md` §8.

- **D-1 - Q-2: no count surface in this story.** The pass's result is
  visible where it lands: on the lines it changed, which MT-116 marks with
  the previous text and the reason. A count on the waiting panel is gone
  before it is read (Context), a line in the review header is a new surface
  for a number the user cannot act on from there, and `voice.md` says no
  cheerfulness at completion - a pass that changed nothing has nothing to
  announce. The one new copy is the waiting panel's `Checking the chapter
  for consistency…` while the pass runs, because the wait is otherwise
  unexplained. The review opening is the sign that the pass ran.
- **D-2 - Q-3: the waiting panel keeps the screen.** A refused or failed
  pass is an `ErrorBanner` at the top of the waiting panel, the review
  opening only from its action - the same shape as the per-page panel's
  banners, and MT-113's rule that a batch failure is shown on the panel that
  was waiting. Opening the review with a banner would put the failure on a
  screen the user came to for something else.
- **D-3 - the banner's words**, one banner on both panels:
  - headline, refused: `Consistency pass not run — the budget would be
    exceeded.` - what happened. "Would be exceeded" because the guard refuses
    the call before it is made (it is the CLI's wording, MT-140 `_pass_failure`),
    and no figure, because the panel after a reopen has no ceiling to name.
  - headline, failed: `Consistency pass failed.`, then the reason on its own
    line as the failed banner does today.
  - body: `Every page is translated and can be reviewed and rendered.` - what
    survived; "every" rather than "all N", because a reopened waiting panel
    knows only the pending jobs' pages, and the per-page panel says the same
    so that the two read as one banner.
  - action: `Review the chapter` - what to do; *chapter* is the voice term.
  - No `Run stopped at page N+1 of N`: nothing stopped at a page.
- **D-4 - the pass line**: `Checking the chapter for consistency…`,
  U+2026 as `Remaining estimating…`, a plain label `batch-pass` under the
  last-checked line, in the accessible name last; cleared when the banner
  takes over, because the banner says what happened to the check.
