## Context

**Filed 2026-10-04 by the Lead PO**, from a symptom the orchestrator
diagnosed the same day. Filed into [[EPIC-01]] because that is the toolchain
epic and MT-001 wrote the lines this story corrects. Like MT-031..MT-043 and
MT-053, it is **not a clause of EPIC-01's `## Done when`** and does not reopen
it.

### Symptom

`bash scripts/doctor.sh` reports

    MISSING  ui-tests     nothing discovered by: uv run pytest --collect-only -q tests/ui | grep -q "tests/ui/"

although `uv run pytest --collect-only -q tests/ui` lists **1277 tests**.
Observed 2026-10-04 on three trees: the old checkout, the Dev Drive copy, and
this worktree (`D:\manga-translator\.claude\worktrees\mystifying-bell-52c490`).

### Root cause (reproduced 2026-10-04 in this worktree, by the orchestrator)

    set -o pipefail; uv run pytest --collect-only -q tests/ui | grep -q "tests/ui/"
    -> rc=120, PIPESTATUS=(120 0)

pytest's traceback ends in `OSError: [Errno 22] Invalid argument` at
`sys.stdout.flush()` - Windows' form of EPIPE (on Linux the producer would die
of SIGPIPE, 141). Without `pipefail` the same pipeline returns 0.

The mechanism: `grep -q` exits at its **first** match and closes the pipe. The
producer is still writing, dies on the closed pipe, and exits non-zero.
`scripts/doctor.sh` runs under `set -uo pipefail` (doctor.sh line 14) and
`eval`s each discovery command in a subshell (~line 163) that inherits it, so
the pipeline's status is the producer's failure, not grep's success.

It is **size-dependent**. `core-tests` survives only because its matching line
(`N tests collected`) is the **last** line of pytest's output, so pytest has
finished writing before grep exits. `ui-tests` matches on the first test id,
with ~1277 lines still to come. A short listing would have hidden this; it
appeared when the UI suite grew. The wrong lesson from a spurious MISSING is
to delete the line.

### Every affected line in `.claude/harness/project.conf`

All use `grep -q` / `grep -qE` as the matcher of a pipeline:

| Line (2026-10-04) | Kind | Id | Current status |
|---|---|---|---|
| 297 | `gate`, **required** | `lint` | passes today; latent |
| 613 | `discovery` | `core-tests` | ok (match is the last line) |
| 614 | `discovery` | `ui-tests` | **spurious MISSING** |
| 615 | `discovery` | `cov-domain` | ok today; latent |
| 623 | `discovery` | `ruff-sees-src` | ok today; latent |
| 632 | `discovery` | `providers` | MISSING, **expected** until MT-007 (no onnxruntime) |

The `lint` line is the dangerous one:

    uv run ruff check --no-cache . && uv run ruff check --no-cache --show-files . | grep -qE "src.mangatl.*[.]py" && uv run lint-imports

`scripts/gates.sh` keeps `pipefail` (gates.sh line 59; upstream keeps it
deliberately). `ruff --show-files` lists every file; the first `src/mangatl`
match closes the pipe while ruff may still be writing. Today the listing is
small enough to be flushed before grep exits. When it is not, a **required gate
fails spuriously** on a clean tree - and the failure looks like "ruff sees no
source", which invites exactly the wrong fix.

### The fix

Rewrite each matcher as `grep PATTERN > /dev/null` - same pattern, same `-E`
where present. `grep` without `-q` reads its whole input, so the producer is
never cut off, and the exit status is still grep's match/no-match. This is the
shape upstream `agentic-dev-harness`'s project.conf template now prescribes,
verbatim: "Write the matcher as `grep PATTERN > /dev/null`, NOT `grep -q
PATTERN`."

### Which required gate would fail if this story's artifact broke?

- For the `lint` line: **`lint` itself**, which is required. If the rewrite
  broke its reach assertion - say the redirect landed on the wrong command, or
  the matcher stopped being able to fail - AC-3's probes catch it at this
  story, and the gate's own verdict on every later run.
- For the five `discovery` lines: **none**. `doctor.sh` is not a gate and CI
  does not run it. This is a property of the harness, not of this story, and
  is why the evidence for AC-1 and AC-2 is pasted doctor output rather than a
  gate verdict. `required_gates` stays empty: there is no optional gate to
  promote.

### C-1. The six lines, before and after

Exactly these rewrites, nothing else on each line changes:

| Id | Before (matcher stage) | After (matcher stage) |
|---|---|---|
| `lint` (gate) | `\| grep -qE "src.mangatl.*[.]py" &&` | `\| grep -E "src.mangatl.*[.]py" > /dev/null &&` |
| `core-tests` | `\| grep -qE "[1-9][0-9]* tests? collected"` | `\| grep -E "[1-9][0-9]* tests? collected" > /dev/null` |
| `ui-tests` | `\| grep -q "tests/ui/"` | `\| grep "tests/ui/" > /dev/null` |
| `cov-domain` | `\| grep -qE "^src.mangatl.domain"` | `\| grep -E "^src.mangatl.domain" > /dev/null` |
| `ruff-sees-src` | `\| grep -qE "src.mangatl.*[.]py"` | `\| grep -E "src.mangatl.*[.]py" > /dev/null` |
| `providers` | `\| grep -qE "CUDA\|Dml\|CPU"` | `\| grep -E "CUDA\|Dml\|CPU" > /dev/null` |

Semantics of the `lint` line, so nobody re-derives it: in bash, `|` binds
tighter than `&&`, and a redirect binds to the simple command it follows. So
`A && B | grep -E P > /dev/null && C` is `A && (B | (grep -E P > /dev/null))
&& C`: only grep's stdout is discarded; ruff's diagnostics from `A` and
lint-imports' output from `C` still reach the gate log, which the `evidence |
lint | Contracts: [1-9][0-9]* kept` line (project.conf ~line 319) reads. That
evidence line must still match after the change - AC-3(a)'s run shows it.
