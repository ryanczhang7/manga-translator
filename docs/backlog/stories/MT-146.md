## Context

EPIC-13 priority 2, the groundwork for U-4 and PO-2. MT-147 lets the page
answer mark a region as drawn art text. The region is then excluded:
no proposal, no typesetting, and the art put back at bake (MT-119). Today
`region.excluded` may be only `watermark` (the detector's rule, MT-121, never
switched on) or `user` (the workspace's Remove). The model's judgement is
neither. Folding it into `user` would make the bench (MT-148) and the user
unable to tell the pipeline's call from their own. Folding it into
`watermark` would be false.

SQLite cannot change a column's CHECK in place. Version 13 therefore rebuilds
`region`, with the recipe `_MIGRATE_TO_V10` uses for `llm_call` (renamed
aside, recreated, copied, dropped). The fresh schema and the migrated one
must declare byte-identical tables, which `test_schema_v8.py`'s pattern
holds.

Required gates: `unit`, `coverage` (both run `tests/core` and `tests/ui`, so
the row's tests are judged there; there is no separate `ui` gate) and
`coverage-core` (`domain/**` at 100 %). All three are `required` and cover
`src/mangatl/**` (`gates.sh --list`, 2026-11-10); `required_gates` stays `[]`.

### C-1 - The rebuild recipe is `_MIGRATE_TO_V4`'s, not `_MIGRATE_TO_V10`'s

The Context's "the recipe `_MIGRATE_TO_V10` uses for `llm_call`" is **wrong for
`region`, and the difference destroys data silently.** `llm_call` has no
children; `region` is a **parent**: `line.region_id INTEGER NOT NULL UNIQUE
REFERENCES region(id) ON DELETE CASCADE` (`schema.py:360`). `_MIGRATE_TO_V4`'s
docstring (`project.py:368-404`) measured what the plain recipe does to a
parent: without `PRAGMA foreign_keys = OFF` the rename repoints `line` at the
aside table and the `DROP` **cascades and deletes every line**, with
`foreign_key_check` clean afterwards; with `foreign_keys = OFF` alone the rows
survive but `line` names a table that no longer exists, and only
`foreign_key_check` sees it. So:

```python
#: store/schema.py - the region table as its own string, used by `DDL` and by
#: `_MIGRATE_TO_V13` (the `CHAPTER_DDL` / `_MIGRATE_TO_V4` precedent). Added to
#: `schema.__all__` LAST, keeping it sorted:
#: ["CHAPTER_DDL", "CLEANED_ERASED_DDL", "CLEANED_PAGE_DDL", "DDL",
#:  "LLM_CALL_DDL", "REGION_DDL"]  (RED-A1). Its comment block (the ON CONFLICT
#: note above the table) moves with it, unchanged.
REGION_DDL: str = """
CREATE TABLE region (
    ...
    excluded      TEXT CHECK (excluded IS NULL OR excluded IN ('watermark', 'user', 'art')),
    UNIQUE (page_id, reading_index)
);
"""

# store/project.py
SCHEMA_VERSION: int = 13

_MIGRATE_TO_V13 = (
    """
PRAGMA foreign_keys = OFF;
PRAGMA legacy_alter_table = ON;

ALTER TABLE region RENAME TO region_v12;
"""
    + REGION_DDL
    + """
INSERT INTO region (id, page_id, reading_index, polygon, mask_blob, kind,
                    confidence, merged_from, excluded)
SELECT id, page_id, reading_index, polygon, mask_blob, kind,
       confidence, merged_from, excluded
FROM region_v12;

DROP TABLE region_v12;
"""
)
# _MIGRATIONS gains (13, _MIGRATE_TO_V13). `_migrate_to_current` already
# restores both pragmas after its commit, unconditionally (project.py:750-754).
```

Any index on `region` (there is none today besides the `UNIQUE`'s automatic
one - RED checks `sqlite_master` for `type='index' AND tbl_name='region'`) is
recreated by the shared string, never by the migration alone. **Ids are copied,
so `line.region_id` still points at the same rows.**

**RED-A1 (2026-11-10, test-developer, Claude Opus 5.5) - amended in place
above.** C-1 said `REGION_DDL` goes into `schema.__all__` "beside
`CHAPTER_DDL`". Two existing tests pin `__all__` as an exact list in sorted
order (`test_schema_v4.py:497`, `test_schema_v7.py:292`), so it is appended
last, after `"LLM_CALL_DDL"`, and both pins gain it. Checked in RED: `region`
has no index besides `sqlite_autoindex_region_1` in `schema.DDL` today, and a
migrated file holds only that one (measured on a scratch candidate, see the
handoff); `test_schema_v13.py` pins it.

## Design notes

Lead Designer's call, made by the orchestrator at PLANNED (2026-11-10,
Claude Opus 5.5), against `voice.md` and `components.md` §5:

- **D-1 - same glyph, same colour, a caption.** An `art` row is an excluded
  row in every visual respect (⊘ U+2298, `color.text.secondary`, dashed
  marker, Restore its only action). What differs is a caption in the row's
  existing caption slot - `Left as drawn: read as art text` - because the user
  did not remove it, and a row the user never touched must say who did. The
  slot is unstyled today (no `theme.qss.in` rule for `rowErrorCaption`), so
  no new colour is introduced and no stylesheet changes.
- **D-2 - the words.** "Left as drawn" is MT-120's settled phrase for what
  exclusion does to the art (EPIC-10 Q-1); "read as art text" says the app's
  reading without claiming certainty. The accessible phrase keeps "removed
  from translation" first so a screen-reader user hears the same status as
  for any excluded row, then the reason: `removed from translation, read as
  art text`.
- **D-3 - Restore then Remove makes it the user's.** After a Restore the
  region is an ordinary included region; removing it again is the user's own
  act and is recorded as `user` (AC-6).
