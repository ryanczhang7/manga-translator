## Context

**Decided by the user on 2026-09-12: Windows High Contrast is supported**, not
detected and declined. The Lead Designer revised the floor accordingly —
`docs/wiki/design/accessibility.md` **A-15** (eleven numbered sub-clauses a story
can cite line by line) and `docs/wiki/design/high-contrast.md` (the mapping, the
alternatives, and what is researched rather than observed).

This is the **first of two** stories. The seam is the `resolve` function:

- **MT-026 (this story) — resolution.** Pure functions over a token name, a
  boolean and a plain dict. No Qt, no display, no contrast theme. A-15.1–A-15.3.
- **MT-028 — application.** Detection, stylesheet re-composition, the canvas,
  live changes. A-15.4–A-15.10.

Splitting there is a Lead PO call, recorded as such: the designer's document does
not prescribe a story count, and the two halves have different test surfaces
(`tests/core/` versus `tests/ui/`), different failure modes, and no shared state
beyond the function signature below.

**Why resolution is a story at all, rather than three lines inside MT-028.** The
whole High Contrast commitment rests on one rule — **resolution never silently
falls back**. A missing role or an unmapped token must raise at composition time,
where a test can see it, rather than produce a half-High-Contrast screen at
runtime where nobody can. That rule is invisible in a widget test and obvious in
a unit test, which is exactly why it gets its own cycle.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage`. `resolve` is a pure function; a test of it that needs a display is
phrased wrongly.

## Acceptance criteria

- **AC-1** — Given `high_contrast=False`, when any token is resolved, then the
  authored value from `tokens_gen.TOKENS` is returned — for every token, with no
  exceptions and no partial High Contrast. *(A-15.3.)*
- **AC-2** — Given `high_contrast=True` and an **exempt** token — one whose
  `HC_PALETTE_ROLE` entry is `@static`, **or** one that appears in neither
  `HC_PALETTE_ROLE` nor `HC_OVERRIDE` (the non-colour tokens, which the
  generator does not map) — when it is resolved, then the authored value is
  returned unchanged. *(A-15.2, `high-contrast.md` §4.2: every `overlay.*`
  colour, `color.canvas.surround`, `color.canvas.page-edge`, and every
  non-colour token except `overlay.dim.opacity`. PO-2 in `## Notes`.)*
- **AC-3** — Given `high_contrast=True` and a token mapped to a role, when it is
  resolved, then `palette[role]` is returned.
- **AC-4** — Given `high_contrast=True` and a token whose mapped role is
  **absent from the palette**, when it is resolved, then it **raises**, naming
  the token and the role. *(A-15.3. A silent fall-back to the authored dark
  value is "High Contrast not supported", arrived at quietly.)*
- **AC-5** — Given an **unknown token name**, when it is resolved in either
  mode, then it **raises**, naming the token.
- **AC-6** — Given the shipped `HC_PALETTE_ROLE`, when the set of distinct roles
  in it is taken, then it is a subset of exactly
  `{Window, WindowText, Highlight, HighlightedText, DisabledText, @static}` —
  `Button`, `ButtonText` and `Link` are **not** used. *(A-15.2: Windows
  guarantees the two pairs, not the cross products.)*
- **AC-7** — Given the shipped `TOKENS`, when every key is resolved with
  `high_contrast=True` against a synthetic five-key palette, then **every one
  succeeds** — resolution is total over the token set, with no key left
  unhandled. *(A-15.3.)*
- **AC-8** — Given `high_contrast=True`, when `overlay.dim.opacity` is resolved,
  then it is the string `"1.0"` — `str(HC_OVERRIDE["overlay.dim.opacity"])`,
  because `TOKENS` carries every value as a string (`"0.55"` authored) and
  `resolve` has one return type — so dimming stops under a contrast theme; and
  given `high_contrast=False` it is `"0.55"`, byte-for-byte `TOKENS[name]`.
  *(PO-1 in `## Notes`.)*
  *(A-15.6 and `high-contrast.md` §7.1: dimming is the one place the app
  deliberately reduces contrast, and a contrast theme is a request not to. The
  link survives on stroke width, fill and the ordinal badge.)*
- **AC-9** — Given the resolved token set under `high_contrast=True`, when any
  returned value is checked, then it is present either in the injected
  palette's values or in `TOKENS`' values — except for a token in
  `HC_OVERRIDE`, whose value is exactly `str(HC_OVERRIDE[name])` — so `resolve`
  never synthesises a colour. *(A-15.2. PO-3 in `## Notes`.)*
- **AC-10** — Given the designer's synthetic palette — `Window` `#000000`,
  `WindowText` `#FFFFFF`, `Highlight` `#1AEBFF`, `HighlightedText` `#000000`,
  `DisabledText` `#3FF23F` — and `high_contrast=True`, when every token is
  resolved, then **every non-exempt `color.*` token resolves to one of those
  five values**, and every `overlay.*` token plus `color.canvas.surround` and
  `color.canvas.page-edge` resolves **byte-for-byte** to `TOKENS[name]`.
  *(This is the designer's own assertable, `README.md` → "High Contrast — token
  resolution". Use that palette; do not invent one.)*

## Contract

RED may amend any block below **in place**, with a one-line reason beside the
change; GREEN builds what the amended block says. The blocks are numbered so an
amendment can name one.

**Block 1 — the module and its exports.**

```
src/mangatl/ui/theme.py              # HAND-WRITTEN. Not generated. No Qt import.
    from mangatl.ui.tokens import HC_ROLES, STATIC      # re-exported, not re-declared
    from mangatl.ui.tokens_gen import HC_OVERRIDE, HC_PALETTE_ROLE, TOKENS

    HC_ROLES: frozenset[str]   # == frozenset({"Window", "WindowText", "Highlight",
                               #               "HighlightedText", "DisabledText"})
    STATIC: str                # == "@static"

    class UnknownToken(KeyError):
        token: str
    class MissingPaletteRole(KeyError):
        token: str
        role: str

    def resolve(name: str, *, high_contrast: bool,
                palette: Mapping[str, str]) -> str
```

`HC_ROLES` and `STATIC` already exist in `mangatl.ui.tokens` (the generator,
`tokens.py:61-62`, pure Python, `tomllib` only — no Qt), where MT-025 put them
and `tests/ui/test_tokens.py:342` pins them. `theme.py` **imports and re-exports
them** so there is one declaration; a test asserts `theme.HC_ROLES ==
tokens.HC_ROLES` and `theme.STATIC == tokens.STATIC`, and separately that
`theme.HC_ROLES` is exactly the five names above (so the re-export cannot drift
by following a changed source silently — PO-4).

**Block 2 — resolution order.** Exactly this, in this order; each step is one
assertion in RED:

1. `name not in TOKENS` → raise `UnknownToken`, **in both modes**, before
   anything else is consulted. `TOKENS` membership is the only test of
   "known"; a name present in `HC_PALETTE_ROLE` but absent from `TOKENS`
   cannot exist (MT-025 AC-10) and is not special-cased.
2. `high_contrast is False` → return `TOKENS[name]`. Nothing else is read.
3. `name in HC_OVERRIDE` → return `str(HC_OVERRIDE[name])`. The override wins
   over the map. For the shipped data the two dicts are disjoint, so the
   precedence is pinned rather than observed; a test asserts the disjointness
   of the shipped data so a future overlap is a loud failure, not a quiet
   precedence question.
4. `name in HC_PALETTE_ROLE`:
   - role `== STATIC` → return `TOKENS[name]`;
   - `role not in palette` → raise `MissingPaletteRole`;
   - otherwise → return `palette[role]`, byte-for-byte, with no normalisation
     of case or format. `resolve` does **not** check `role in HC_ROLES`; the
     vocabulary is a property of the shipped data (AC-6), asserted on the dict,
     not re-checked per call.
5. otherwise (in `TOKENS`, in neither dict — the 85 non-colour tokens) → return
   `TOKENS[name]`. This is §4.2's third exempt group; the generator never maps
   non-colour tokens, and MT-025 guarantees every colour token **is** mapped,
   so this branch is only ever reached by a non-colour token (PO-2).

**Block 3 — the exceptions.** Both subclass `KeyError` directly and **neither
subclasses the other**, so `except UnknownToken` never swallows a missing role.
`exc.args[0]` is a plain `str` that contains the token name (both classes) and
the role name (`MissingPaletteRole`); the attributes `token` / `role` carry the
same strings. Message wording beyond that is free.

**Block 4 — the palette.** A `Mapping[str, str]` of `#RRGGBB` strings keyed by
role name. `resolve` reads it with `in` and `[]` only — never `.get`, never
iteration — so a `dict`, a `MappingProxyType` or a test's `Mapping` subclass all
work. Its values are returned as given: `resolve` never validates that a value
is a colour.

**Block 5 — the test surface.**

```
tests/core/test_theme.py             # pytest, no Qt, no display, no fixture dirs
```

`tests/core/` already imports `mangatl.ui.tokens_gen` (`test_typeset_font.py:31`)
so a `mangatl.ui` import from there is established practice; the `lint` gate's
`lint-imports` contracts constrain `src`, not tests. The synthetic palette is
the designer's five values in AC-10, as a module constant. AC-1, AC-7, AC-9 and
AC-10 iterate `TOKENS` **itself** (`for name in TOKENS`), never a hand-written
sample — a sample cannot fail when a colour is added. The set of exempt names
for AC-10 is derived mechanically (`name.startswith("overlay.")` plus the two
canvas names, minus `overlay.dim.opacity`) and cross-checked against the dict:
the test also asserts that exactly that set is `@static` in `HC_PALETTE_ROLE`
(§4.2's first two groups, as data), so the data and the derived set pin each
other.

**Callers of changed signatures:** none. The module is new;
`rg 'ui\.theme\b|from mangatl.ui import theme' src tests` returns nothing on
`main` at `5e5edca`. MT-028 extends this module and already names
`resolve(name, *, high_contrast, palette) -> str` in its contract at the same
shape, so RED's handoff only needs to confirm the module still does not exist
when it starts.

**Gates that judge this artifact:** `unit` and `coverage`, both `required`,
both `covers src/mangatl/**`. `coverage-core` does not cover `src/mangatl/ui`
and is not asked to. `required_gates` stays empty.

**Settled by the design document, and to be read out — not re-derived:**

- **The signature is exactly `resolve(name, *, high_contrast, palette)`**, and
  `palette` is a plain `dict[str, str]` of `#RRGGBB` strings keyed by the five
  role names — **not** a `QPalette`. `high-contrast.md` §4.3. That is what makes
  this layer pure and testable with no display; snapshotting a real `QPalette`
  into that dict is a thin adapter with nothing to decide, and it belongs to
  MT-028.
- **`resolve` is hand-written and does not live in the generated module.**
  `high-contrast.md` §4.3: logic in a generated file is logic nobody reviews.
  MT-025 AC-10 asserts the generated module holds data only; this story holds
  the behaviour.
- **Five roles, and no others** (AC-6). Restricting to two guaranteed pairs plus
  one disabled foreground means every combination the app can produce is one
  Windows has promised.
- **`overlay.dim.opacity` is the single non-colour token that is *not* exempt**
  (AC-8). Everything else non-colour is `@static`. That asymmetry is deliberate
  and is the one value in this story that a reader will assume is a mistake.

**Oracle partition: entirely mechanical, and say so loudly in the dispatch.**
Every value, every role name, every exemption and the sentinel are fixed in
`accessibility.md` A-15 and `high-contrast.md` §4. There is nothing to calibrate,
no metric to invent, and a RED phase that designs a resolution model has
discarded a document that already exists. The nine criteria above are
`assert`s against that document.

## Design notes

Cite `docs/wiki/design/accessibility.md` **A-15.1**, **A-15.2**, **A-15.3** and
**A-15.6**; the reasoning and the full mapping are in
`docs/wiki/design/high-contrast.md` §4 and §7.1.

The clause worth reading before writing a single test is **A-15.1**: a Windows
contrast theme offers **six** user-set colours and guarantees only that each
foreground is legible *on its own paired background*. `tokens.toml` declares 40
colour tokens. Under a contrast theme they collapse onto five roles, so **colour
carries no distinction beyond "selected" and "disabled"**. Every place that
collapse would destroy a distinction, **A-10** has already put a glyph, a number,
a shape or a word there — so A-15 is not a licence to re-open A-10, and a state
distinguished only by hue fails A-10 first.

### PO decisions at PLANNED → RED (2026-10-06, lead-po on Claude Fable 5.1)

The criteria below were **refined before the story left PLANNED**, so they are
committed at PLANNED and need no `## Amendments` entry. Each was found by
reading the generated module against the design document, not by RED.

- **PO-1 — `resolve` returns `str` for every token; `overlay.dim.opacity`
  under HC is the string `"1.0"`.** The design (§4.3, A-15.3) gives the
  signature `-> str`, and `tokens_gen.TOKENS` is `dict[str, str]` — the
  authored opacity is `"0.55"`, a string. The one override, `HC_OVERRIDE`,
  carries a `float` `1.0` (MT-025 pinned its type), and AC-8 as drafted said
  "then it is `1.0`" without saying which type. A function whose other 125
  results are strings and whose 126th is a float is a trap for MT-028's QSS
  composition (`@{...}` substitution wants a string) and for any caller
  comparing results. So the string, and AC-8 is reworded to say so; the
  mechanism is `str(HC_OVERRIDE[name])`, and the expected literal is pinned
  because `str(1.0)` is `"1.0"` today and the test must notice if the
  generator ever writes `1` or `"1"`. `markers.py:189` reads
  `OVERLAY_DIM_OPACITY` as a float today; routing it through `resolve` and
  `float()`-ing the result is MT-028's business, not this story's.
- **PO-2 — tokens absent from both `HC_PALETTE_ROLE` and `HC_OVERRIDE` resolve
  to their authored value under HC.** `HC_PALETTE_ROLE` has 40 entries (the
  40 colour tokens plus nothing else; `tokens.toml` `[hc.map]`), `TOKENS` has
  126 keys. The 85 others are the non-colour tokens §4.2 calls exempt
  ("every non-colour token except `overlay.dim.opacity`"), but the generator
  does not write them into the map as `@static` — it writes nothing. AC-2 as
  drafted covered only the explicit `@static` entries, which would have left
  AC-7's totality claim without a rule to resolve those 85 by. AC-2 is
  reworded to name both exempt forms, and Contract block 2 step 5 pins the
  branch. Safe only because MT-025 AC-10 makes an **unmapped colour token** a
  generation failure, so the branch is unreachable by a colour token.
- **PO-3 — AC-9's "present in the palette or in `TOKENS`" cannot hold for the
  override value `"1.0"`,** which is in neither. AC-9 is reworded to exempt
  exactly the `HC_OVERRIDE` keys, whose value must be exactly
  `str(HC_OVERRIDE[name])`. The claim it protects — `resolve` never synthesises
  a colour — is unchanged: the override is data from the generated module, not
  a value `resolve` made up.
- **PO-4 — `HC_ROLES` and `STATIC` are re-exported from `mangatl.ui.tokens`,
  not re-declared.** The contract as drafted declared them in `theme.py`; MT-025
  already declared them in the generator (`tokens.py:61-62`) and pins them in
  `tests/ui/test_tokens.py:342`. Two declarations of the same five names drift.
  `tokens.py` is pure (`tomllib`, `argparse`, `json`, `re`; no Qt), so the
  import keeps the "no Qt" promise. The test asserts both equality with the
  source and the literal five, so a change at the source is loud here too.
- **PO-5 — resolution order and the override's precedence are pinned, not
  observed.** For the shipped data `HC_OVERRIDE` and `HC_PALETTE_ROLE` are
  disjoint, so no order is visible today. Contract block 2 fixes "override
  wins" and asks RED for a disjointness assertion over the shipped data, so
  that the day they overlap is a failing test rather than a precedence
  question answered by whichever `if` came first.
- **Epic done-when, checked:** EPIC-05's done-when (open a translated chapter,
  select a line and its bubble both ways, edit, revert, reopen, see progress
  and spend during a run) names nothing that High Contrast delivers or that
  lies between the last closed story and this one. No gap; nothing absorbed.
- **Criteria are testable as written:** AC-1..AC-10 are each a pure-function
  assertion over `TOKENS`, `HC_PALETTE_ROLE`, `HC_OVERRIDE` and a five-key
  dict. No display, no fixture, no oracle to invent.
