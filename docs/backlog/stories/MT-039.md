### Why this story exists, and why it comes first

**The cheapest way to make a self-test faster is to run less of it.** MT-040,
MT-041 and MT-042 each make the self-test cheaper, and each of them could be
"achieved" by deleting assertions, adding a `skip`, or quietly dropping a suite —
and **nothing in this repository would notice**. `selftest.sh` runs each suite
and reads its **exit status only**. A suite that executed zero assertions exits
0. A suite emptied to a single `printf` exits 0.

That is the same defect `project.conf`'s header names for gates — *"exit 0 is not
proof of work — it is the absence of a complaint, and a tool with nothing to do
does not complain"* — and it is the defect [[MT-037]] fixed for one gate. It has
never been fixed for the self-test, and three stories that reward a smaller
self-test are about to be dispatched.

So this story ships the floor first, and the three reductions are built behind
it. **This story makes nothing faster.** Its whole product is a mechanism that
makes the next three honest.

### Two facts about this story's own shape, and both are traps

**1. The phase lock will enforce nothing here.** Every path this story touches
classifies as `harness`, which every phase permits:

```
$ bash -c '. .claude/hooks/lib.sh; for p in scripts/selftest.sh \
    .claude/tests/_lib.sh .claude/tests/floors.conf .claude/harness/project.conf; do
    printf "%-34s %s\n" "$p" "$(classify "$p")"; done'
scripts/selftest.sh                harness
.claude/tests/_lib.sh              harness
.claude/tests/floors.conf          harness
.claude/harness/project.conf       harness
```
`[MEASURED — 2026-09-20, Lead PO, this worktree at b7250eb]`

This is the same "no phase geometry" note [[MT-031]], [[MT-033]] and [[MT-034]]
each wrote for themselves. **RED→GREEN here is honoured by the story, not
enforced by the hook.** Two consequences carry over unchanged: the mutation
probes below **can** run in RED, and they still go through
`bash scripts/mutate.sh` so the restore is verified and recorded. `sed -i` is
working around the lock even though the lock would allow it.

**2. No gate judges the harness, and that is the honest answer rather than a
gap to paper over.** The `story-authoring` skill says to name, before RED, the
required gate that would fail if this story's artifact broke. There is none.
Every one of the eight gates in `project.conf` is `uv run` against
`src/mangatl`; no `covers` line names anything under `.claude/` or `scripts/`,
so `gates.sh`'s changed-source check never sees a file this story writes.
`required_gates: []` is a decision, not an oversight. **The judge is the
`Harness self-test` CI step** in `.github/workflows/gates.yml`, plus
`scripts/ci-local.sh`, and it must stay green.

**Do not "fix" this by adding a `selftest` gate to `project.conf`.** CI already
runs `bash scripts/selftest.sh` as its own step; a gate would make CI run the
whole self-test **twice**, in a lineage of stories whose entire purpose is to
stop paying for it once. [[MT-037]] named making such a gate as a possible
follow-up; this story is where that follow-up is explicitly declined, and the
reason is arithmetic.

## Acceptance criteria

<!-- AC-1 is the central claim. AC-2, AC-3 and AC-4 are its negative controls
     and none is optional: without AC-2 the mechanism could satisfy AC-1 by
     failing always; without AC-3 it could satisfy AC-1 by demanding equality,
     which breaks every future story that adds a test; without AC-4 the floor
     could become the ONLY check and a suite with failing assertions could
     pass on count alone. -->

- **AC-1** — Given a floors file recording `floor | new-story | 22` and a
  `new-story` suite that executes **21** passing assertions, when
  `bash scripts/selftest.sh new-story` runs, then it reports a **failure** for
  that suite naming both numbers (the floor and the observed count) and the run
  **exits non-zero**.
  *Today this is false, and the falsity is the defect:* `selftest.sh` reads a
  suite's exit status and nothing else, so a suite that executes 21 of its 22
  assertions — or one of them, or none — exits 0 and the run prints
  `12 harness suite(s) passed.`
  *Control:* AC-2, AC-3 and AC-4 below.

- **AC-2** — *(negative control for AC-1)* Given the floors recorded in C-3
  below and **every suite unchanged**, when `bash scripts/selftest.sh` runs,
  then every suite passes and the run **exits 0**. A mechanism that satisfies
  AC-1 by failing always, or by failing any suite whose count it cannot parse,
  fails here.

- **AC-3** — *(negative control for AC-1: a floor is a floor, not an equality)*
  Given `floor | new-story | 22` and a `new-story` suite that executes **23**
  passing assertions, when the self-test runs, then the suite **passes**.
  *This criterion is what stops the mechanism becoming a tax on every future
  story.* A story that adds one assertion to any suite must not have to edit the
  floors file to stay green; a story that **removes** one must.

- **AC-4** — *(negative control for AC-1: the floor must not displace the
  existing check)* Given a suite that executes **22** passing assertions **and
  one failing assertion** (`new-story: 22 passed, 1 failed`), when the self-test
  runs, then the run **fails**, even though the floor of 22 is met. Today this
  already fails, via the suite's own non-zero exit; it must still fail after the
  floor lands.

- **AC-5** — Given a floors file containing a line that (a) names a suite for
  which no `.claude/tests/<name>.test.sh` exists, or (b) carries a non-numeric
  value, when the self-test runs, then the run **fails** and says which line and
  which of the two faults it has.
  *Measured reason this criterion exists, rather than inferred:* `gates.sh`
  silently ignores a manifest line whose `kind` it does not recognise —
  `scripts/gates.sh:103`, `case "$kind" in evidence|waiver|floor|slow|…) ;; *)
  continue ;; esac`. A floors mechanism that inherits that silence is a floor
  that a one-character typo switches off with no output. *Control:* a floors
  file with **no** faults must not trip this check (AC-2 covers it).

- **AC-6** — Given a suite file `.claude/tests/<name>.test.sh` that exists and
  has **no** `floor` line in the floors file, when the self-test runs, then the
  run **fails** naming that suite.
  *Measured today:* twelve suites exist and zero have floors, so this criterion
  is what makes C-3's table exhaustive rather than a sample. The friction is
  deliberate and is the point: adding a thirteenth suite must require declaring
  what it is worth, because a suite with no floor is a suite that can be emptied.

- **AC-7** — Given the floors file, when a suite's count is read, then the value
  read is the **executed** assertion count printed by `summary()` in
  `.claude/tests/_lib.sh` — the `N` of `<name>: N passed, M failed` — and **not**
  the number of `assert_` call sites in the suite source.
  *These are different numbers, measured, not assumed:*

  | suite | `grep -cE '^[[:space:]]*assert_'` | `N passed` |
  |---|---:|---:|
  | `profiles` | 1 | **44** |
  | `lib` | 57 | **148** |
  | `new-story` | 10 | **22** |
  | `ci-local` | 7 | **8** |
  | `phase` | 24 | 24 |
  | `doctor` | 7 | 7 |

  `[MEASURED — 2026-09-20, Lead PO, this worktree at b7250eb]`

  A single `assert_` call site inside a loop executes many times (`profiles`:
  1 → 44), which is why a source-grep floor would be nearly worthless. Executed
  is always ≥ call sites, but the ratio is not fixed — 44×, 2.6×, 1.14×, 1× —
  so neither number can be derived from the other. The `grep` is not a cheap
  approximation of the floor; it is a different quantity.
  *Control:* a mechanism that counted call sites would record `profiles | 1`,
  and deleting 43 of that suite's 44 executed assertions would still satisfy it.
  The floor for `profiles` is 44 and an implementation that reports 1 fails.

### C-2 Where the floors live — a decision, and dossier §7 is overruled on it

The dossier proposed recording floors **in `project.conf`**, in the vocabulary
that file already uses for gates (`floor | unit | 529`). **The mechanism is
adopted; the location is not.** Floors live in a new file,
`.claude/tests/floors.conf`, read by `selftest.sh`.

Three reasons, the first decisive:

1. **`selftest.sh`'s own header disclaims the coupling, in terms.** It says the
   harness tests *"need bash, git and coreutils and nothing else, so they run
   before a stack has been chosen — which is the point, since the harness has to
   be trustworthy from the first story onwards"*, and then: *"The project's own
   gates are a separate thing entirely: scripts/gates.sh."* `project.conf` is
   written by the **bootstrap story**. Making the self-test read it means the
   self-test cannot run before bootstrap — which is exactly when it is most
   needed, and exactly what that paragraph exists to guarantee.
2. **`gates.sh` would silently ignore the lines.** `scripts/gates.sh:103` drops
   any `kind` outside its known set, so a `selftest-floor` line in
   `project.conf` is invisible to `gates.sh --audit` — the audit whose job is
   catching exactly this. Two readers, one of which ignores the lines, is worse
   than one reader that owns them. AC-5 gives the new file its own audit.
3. **The floors travel with the suites they count.** A story that adds a suite
   adds its floor in the same directory, not in the project manifest.

**The grammar is the same**, deliberately, so the vocabulary is one thing an
agent learns once:

```
# .claude/tests/floors.conf
# <kind> | <suite> | <value>
floor | phase-guard | <n>
floor | gates       | <n>
```

Comments (`#`) and blank lines ignored, `|`-separated, leading/trailing space
trimmed — as `project.conf` does.

### C-4 The mechanism

`selftest.sh` today runs `bash "$suite"` and reads `$?`. It must now also read
the suite's **stdout**, find the `summary()` line, and compare.

Constraints, each of which is a way this has been got wrong:

- **Output must still stream or must still be shown in full.** Capturing with
  `out=$(bash "$suite")` and printing afterwards is acceptable; silently
  swallowing a failing suite's output is not. `VERBOSE=1` must still name every
  assertion (AC in MT-042; pinned here so this story does not break it first).
- **Match the summary line exactly**, anchored to the suite name:
  `^<name>: ([0-9]+) passed, ([0-9]+) failed$`. A suite whose output happens to
  contain that shape in an assertion message must not fool it — anchor, and take
  the **last** match.
- **A suite that prints no summary line at all is a failure**, not a pass. That
  is the strongest form of the defect this story exists to close: a suite
  replaced by `exit 0` prints nothing and must not be read as meeting its floor.
  This is not listed as a separate AC because AC-1's mechanism gives it for
  free — but it is pinned here so GREEN does not implement "no line → skip the
  check".
- **Bash 3.2 compatible**, no associative arrays, as `gates.sh` is (see its
  comment at line 96). Bash, awk and coreutils only. No python
  (`rules.md`, Portability).
- The failure message names the suite, the floor and the observed count, in the
  shape `gates.sh` already uses for a floor shortfall:
  `did <observed> units of work, below the floor of <floor>`.

### C-5 The earning rule — this is the part that is easy to skip

**Every floor in C-3 is written against a suite that already exists, so it
passes on its first execution and would pass forever even if it asserted
nothing.** `rules.md` is explicit that such an assertion is not a test until it
has been earned:

> a test **written or corrected while the implementation already exists** … It
> passes on its first execution and passes forever; it could assert nothing at
> all and nothing would notice. Earn it by mutating the specific production
> behaviour it claims to pin, watching that one assertion go red, reverting, and
> pasting the output.

**Earn it like this, and not with `sed -i`:**

```bash
bash scripts/mutate.sh .claude/tests/new-story.test.sh \
  '66s|^assert_contains|#assert_contains|' \
  -- bash scripts/selftest.sh new-story
```

`new-story.test.sh:66` is `assert_contains "epic" "epic: EPIC-03" …`, a
top-level call site executing exactly once. Commenting it out takes the suite
from 22 executed assertions to 21, against a floor of 22.

- **Expected, and it is the whole point:** the suite still **exits 0** — it has
  no failing assertions — and the self-test must **fail anyway**, naming
  `floor 22, observed 21`. If the run passes, the floor is asserting nothing.
- `new-story` is chosen because it is the cheapest suite (2.5 s), so this probe
  costs seconds rather than minutes.
- `mutate.sh` restores the file and **verifies** the restore; paste its
  `restored (verified)` line along with the failure output.
- Paste the output into `## Test plan` (RED) or `## Regressions` (if the story
  returns to RED). `check-boundaries.sh` refuses a PR that describes a failure
  without showing one.

**One more probe, and it catches a different blindness.** The mutation above
removes an assertion. Also run the mutation that removes the **summary line**,
which is the failure mode C-4 warns about:

```bash
bash scripts/mutate.sh .claude/tests/doctor.test.sh \
  's|^summary |: summary |' \
  -- bash scripts/selftest.sh doctor
```

Expected: the self-test **fails** for `doctor`, because no count could be read.
A mechanism that treats a missing summary as "no floor to check" passes here and
is defeated by a one-line edit. (`doctor` is used rather than `new-story` so the

### The one behaviour RED left open, decided and implemented: C-4(b)

RED's handoff ends its "What is NOT constrained" list with *"what a single-suite
run does about OTHER suites' missing or malformed floors … Pick one and say
which in `## Gate probes`"*. The orchestrator settled it as **C-4(b)** at the
end of RED (`## Notes` PO-4) and **that is what is implemented**, not a choice
of mine:

- `bash scripts/selftest.sh <name>` enforces **that suite's floor only**. A
  malformed or missing line belonging to another suite does not fail it.
- If the **named** suite has no floor, the run prints a two-line
  `WARNING:` to stderr naming it and **exits 0**.
- If the named suite's **own** line is malformed, the run fails — that is its
  own fault, not somebody else's. C-4(b) does not say so in terms; this is the
  reading that makes "enforce that suite's floor" mean anything.
- `bash scripts/selftest.sh` with no argument audits the whole file — unknown
  suite, non-numeric value, unknown kind, or any suite with no floor line — and
  reports **every** fault before running anything, then exits 1. Failing in one
  second rather than after the whole suite has run is the point of doing it up
  front.

## Notes

### PO-1 — Running the self-test **conditionally** was considered and declined

The obvious alternative to making the self-test cheap is running it less often:
a `paths:` filter or an `if:` condition so that the `Harness self-test` step
runs only when `.claude/**` or `scripts/**` changed. **Decision: no.** The user
asked for this to be weighed as a real tradeoff rather than waved through, so
the reasoning and the residual risk are recorded on both sides.

**Four reasons, the first two specific to this repository rather than general
caution:**

1. **"Code-only PR" is not a clean category here.** The harness reads files far
   outside `.claude/**` and `scripts/**`. `rules.md` states that `git
   check-ignore` is what makes the phase lock classify a path as `ignored` — so
   a line added to `.gitignore` changes the guard's verdicts. `phase.sh` and
   `check-boundaries.sh` read story frontmatter under `docs/backlog/stories/**`.
   `gates.sh` is driven entirely by `.claude/harness/project.conf`. A filter
   would have to enumerate all of those, and **the failure mode of an incomplete
   enumeration is silent** — the check does not run, and nothing says so.
2. **The saving is smallest exactly where it is safe.** A harness PR still pays
   the full 14 minutes, and those are the PRs where the self-test is both
   slowest and most load-bearing. Five of EPIC-01's eight closed stories are
   harness corrections, and all four of MT-039..MT-042 are too. The filter saves
   nothing on the work that costs the most.
3. **A `paths`-skipped required check goes permanently pending** under branch
   protection, unless paired with an "always pass on skip" job — which is itself
   a mechanism that reports success without doing work, i.e. the exact defect
   [[MT-037]] removed from the gates and this story removes from the self-test.
   Adding it back one layer up would be incoherent.
4. **`ci-local.test.sh` cannot see the divergence.** It greps `run:` lines only
   (`.claude/tests/ci-local.test.sh:40,55`). A step made conditional with `if:`
   **keeps its `run:` line**, so `ci-local.sh` keeps running it unconditionally
   and the test keeps passing — while local and CI have stopped meaning the same
   thing. The one mechanism that makes "the same sequence" a fact rather than a
   claim would go on asserting it after it stopped being true.

**The residual risk of declining it**, stated rather than left implicit: every
PR keeps paying for the self-test, so if MT-040, MT-041 and MT-042 under-deliver,
the trend measured in `## Context` continues and this decision has to be revisited
against worse numbers. That is accepted, because making the self-test cheap
dominates on coverage — it costs nothing in what is checked, and it helps
harness PRs too, which the filter does not.

**If it is ever adopted anyway**, adopt it only alongside (a) an unconditional
full self-test on `push: main`, and (b) a nightly `schedule:` run — so a harness
regression landing in a code-only PR is caught within **one merge** rather than
never. Record the window as "one merge", not "zero". And fix reason 4 first:
`ci-local.test.sh` must learn to read `if:` and `paths:`, or the local runner
must learn to skip what CI would skip, before any step becomes conditional.

### PO-2 — Why four stories and not one, or two

### PO-4 — A single-suite run does not enforce the whole floors file

**Decided by the orchestrator at the end of RED, 2026-09-21.** RED left one
behaviour deliberately unconstrained and escalated it rather than guessing:
what `bash scripts/selftest.sh doctor` should do about *other* suites' missing
or malformed floors. Every AC-5/AC-6 fixture drives a full run, so no criterion
answers it. Settled as **C-4(b)**: a single-suite run enforces only its own
floor; the file-wide audit is the full run's job.

**The decisive reason is a chicken-and-egg that RED hit for real.** AC-6 makes
an undeclared suite fail the run, and RED's own new suite
`.claude/tests/selftest.test.sh` is the thirteenth — whose floor cannot be known
until it passes, which it cannot do until GREEN exists. If a single-suite run
enforced exhaustiveness, the only way to learn a new suite's count would be a
full run, which is **38 minutes**. Every future story that adds a suite would
pay that to read one number, and the predictable response is to guess the floor
or to skip running the new suite at all — both of which defeat this story.

The guard is not weakened by this, because **the place the audit matters is the
place it still runs**: CI invokes `bash scripts/selftest.sh` with no argument
(`.github/workflows/gates.yml`, step *"Harness self-test"*), and so does
`scripts/ci-local.sh:72`. A floor cannot be switched off by a typo and reach
`main` — the full run is a required check either way. What a single-suite run
buys is the 2.5-second iteration loop the harness depends on, and it stays
honest by printing a loud warning rather than silence when the named suite has
no floor.

**Residual risk, stated rather than hidden:** a developer running only single
suites can leave the floors file malformed for the length of their local loop
and not hear about it until the full run. That is one CI run, not never, and it
is the same window every other `ci-local.sh`-shaped check already has.
