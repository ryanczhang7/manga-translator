## Context

EPIC-05 owns the theme (MT-025 tokens, MT-058 and MT-061 the High Contrast
path). `components.md` §10.2 (lines 1254-1256): under High Contrast elevation
`e2` is `Window` + **2px `WindowText`** and no shadow; `tokens.md` §9 (line
274) says `e2` is "popover / menu / dialog"; `components.md` §10.7 (lines
1374-1376) names `BakeConfirmDialog`, `RerunDialog`, `ShortcutSheet` as
`Window` + 2px `WindowText`, and says `RerunDialog`'s over-budget border
"collapses to `WindowText` like every other". `theme_hc.qss.in` already does
this for `QToolTip` and `QMenu` (line 33 on) and for **no dialog**: the base
`QMainWindow, QDialog` rule (`theme.qss.in` lines 45-47) sets only the ground,
so under HC every dialog is a borderless `Window` rectangle. MT-127 built the
over-budget `RerunDialog` hairline and listed this gap as out of scope "for
the Lead Designer to raise"; the Lead Designer's check (2026-11-02, read-only
against origin/main 728c07b) confirmed it and the user decided the shape, so
this is the fix. Every dialog the sheet styles is in scope: `RerunDialog`
(`src/mangatl/ui/rerun_dialog.py:74`), `BakeConfirmDialog`
(`src/mangatl/ui/bake_dialog.py:61`), `ApiKeyDialog`
(`src/mangatl/ui/api_key_dialog.py:32`) and the settings warning
`QMessageBox` (`src/mangatl/app.py:250`, `show_warning`).

It is a **rule** change, not a value change - the base sets no dialog border
- so per `tokens.md` §12.1 (lines 352-358) it belongs in the append-only
`theme_hc.qss.in`, unlike MT-127's colour, which §10.9 resolves through the
token map. The failing paint test that reproduces the missing border is the
permanent regression test.

**The user's decision (option 2, 2026-11-02).** The base rule
`RerunDialog[overBudget="true"] { border: hairline ... }` (`theme.qss.in`
377-379) has specificity (0,1,1) over `QDialog`'s (0,0,1), so a `QDialog`
rule alone would leave the over-budget Run again dialog at **1px** while every
other dialog takes 2px. The user chose a second HC rule that widens that
selector to `border-width.emphasis`. That contradicts the text half of MT-127
AC-4 (`theme_hc.qss.in` contains no `RerunDialog` selector) and its test
`test_the_high_contrast_override_template_has_no_run_again_dialog_rule`
(`tests/ui/test_rerun_dialog_border.py:309-317`). MT-127 is DONE and its
criteria stay as its record; **this story's RED replaces that test** (C-4),
records why under `## Regressions`, and the replacement is earned by DV-2.
MT-127 AC-4's paint half (every edge of the over-budget dialog is
`WindowText` under HC) still holds and its test is untouched.

Required gate that fails if the artefact breaks: `unit` (and `coverage`),
which run `tests/ui`; `tests/ui/test_tokens.py` additionally refuses a
`theme_hc.qss.tmpl` that is not byte-identical to `theme_hc.qss.in`.

## Acceptance criteria

All paint is measured through the real theme path - the sheet composed for
High Contrast or the packaged `theme.qss`, set as the **application** sheet -
never `styleSheet()` on the widget, which stays `""`. "The HC sheet" below is
`theme.compose_stylesheet(base_template(), hc_template(), high_contrast=True,
palette=P)` for a five-role palette `P` whose `WindowText` and `Window` are
each a colour no token's value uses (as `tests/ui/test_rerun_dialog_border.py`
does). "The 2px edge test" on a grabbed dialog image means, for each of the
four edges and with `emphasis = border-width.emphasis` (= 2) pixels skipped at
each end of every line: **line 0 and line 1** in from that edge are
`P["WindowText"]` and nothing else, and **line 2** in from that edge is
`P["Window"]` and nothing else. A 1px border fails on line 1; a 3px border
fails on line 2; no border fails on line 0.

- **AC-1** - Given the HC sheet applied and an `ApiKeyDialog()` shown alone,
  when its own pixels are grabbed, then it passes the 2px edge test.
- **AC-2** - Given the HC sheet applied and a `BakeConfirmDialog(preview)`
  shown alone, when grabbed, then it passes the 2px edge test.
- **AC-3** - Given the HC sheet applied and a `RerunDialog(preview)` with
  `within_budget=True` shown alone, when grabbed, then it passes the 2px edge
  test.
- **AC-4** - Given the HC sheet applied and a `RerunDialog(preview)` with
  `within_budget=False` shown alone, when grabbed, then it passes the 2px edge
  test. *Control (the 1px/2px discrimination this AC exists for):* the HC
  sheet composed with the `RerunDialog[overBudget="true"]` rule removed from
  the override template - the `QDialog` rule alone - **must** fail this AC on
  line 1 (line 0 `WindowText`, line 1 `Window`: the base hairline wins on
  specificity). Owned by DV-2.
- **AC-5** - Given the HC sheet applied and a `QMessageBox` built in the test
  (`QMessageBox.Icon.Warning`, title `Settings`, one line of text, as
  `app.show_warning` builds it) shown alone, when grabbed, then it passes the
  2px edge test.
- **AC-6** - *Control, the non-HC sheet gains no border:* given the packaged
  `theme.qss` applied as the application sheet, when each of `ApiKeyDialog`,
  `BakeConfirmDialog`, within-budget `RerunDialog` and the AC-5 `QMessageBox`
  is shown alone and grabbed, then on every edge lines 0 and 1 are
  `color.surface.base` and nothing else - the ground, as MT-127 AC-2 measures
  for `RerunDialog` today. (The over-budget `RerunDialog` under `theme.qss` is
  MT-127 AC-1, unchanged: 1px `color.status.warning`.)
- **AC-7** - Given `docs/wiki/design/theme_hc.qss.in`, when its rules are
  parsed with the generator's own regexes (`tokens._RULE`, `tokens._COMMENT`),
  then it carries a rule whose selector is exactly `QDialog` with a `border`
  declaration reading `@{border-width.emphasis}` and `@{hc.WindowText}`, and
  a rule whose selector is exactly `RerunDialog[overBudget="true"]` whose only
  declaration is `border-width: @{border-width.emphasis}px` - no colour: the
  colour still arrives through the base token map (§10.9). Neither rule
  carries a literal pixel number.

### C-1 The two rules (`docs/wiki/design/theme_hc.qss.in`)

Appended after the existing `QMenu` rule (the other `e2` rule), in the file's
slash-star comment style and under its constraints (header lines 14-20: every
selector verbatim in `theme.qss.in`; colours only from the five `@{hc.Role}`
placeholders; widths as ordinary token placeholders; no nested braces):

```
/* e2 under HC for every dialog the sheet styles: Window plus a 2px WindowText
   boundary, no shadow (components.md 10.2, 10.7). A type selector, so every
   QDialog subclass - RerunDialog, BakeConfirmDialog, ApiKeyDialog, QMessageBox -
   takes it. The base sets no dialog border, so this is a rule change (tokens.md
   12.1), not a value change (MT-131). */
QDialog {
    border: @{border-width.emphasis}px solid @{hc.WindowText};
}

/* The over-budget Run again dialog's base hairline (theme.qss.in, MT-127) has
   specificity (0,1,1) over QDialog's (0,0,1) and would stay 1px here. Widen it
   to the same boundary; its colour already resolves to WindowText through the
   token map (components.md 10.9), so only the width is restated (MT-131). */
RerunDialog[overBudget="true"] {
    border-width: @{border-width.emphasis}px;
}
```

- Both selectors are verbatim in `theme.qss.in` (`QMainWindow, QDialog` at
  line 45 - `_selectors` splits the list, so `QDialog` alone is in the base
  set; `RerunDialog[overBudget="true"]` at line 377), so
  `tokens.check_override_template` (`src/mangatl/ui/tokens.py:201-211`)
  accepts them. `@{hc.WindowText}` is one of `HC_ROLES`.
- `border-width.emphasis` is `2` (`tokens.toml:206`); `hairline` is `1`
  (`:205`). Semantics: the boundary is two device pixels on every side, the
  same width the `QToolTip`/`QMenu` `e2` rules already use.
- **Why `border-width` only on the second rule.** The colour is already
  `WindowText` under HC through `HC_PALETTE_ROLE` (`color.status.warning` ->
  `WindowText`), which MT-127 AC-4's paint test pins. Restating only the width
  keeps §10.9's "value change" true of the colour and makes AC-7's "no colour"
  assertion the record of it. A `border:` shorthand here would also pass the
  paint tests; RED may not widen the rule to it.
- The `QDialog` rule matches `QMessageBox` (a `QDialog` subclass) through
  Qt's type-selector inheritance; `QFileDialog` is native (OS-drawn) and out
  of scope. No `hover`/`pressed` rule is touched (header lines 22-24).
- Orphan counts in `tests/ui/test_tokens.py` (`ORPHAN_COUNT = 84`,
  `BASE_REFERENCED_COUNT = 42`) do not move: `border-width.emphasis` is
  already referenced by the HC template and the base changes only in a
  comment.

- **The edge helper is new**, because the sibling's `_edge_colours` samples
  only the middle line (`width // 2`) and cannot tell 1px from 2px. Shape:
  `_edge_line(image, depth: int) -> dict[str, set[str]]` returning, per
  edge, the colour set along the line `depth` pixels in from that edge, with
  `emphasis` pixels skipped at each end (`range(emphasis, w - emphasis)` for
  top/bottom, likewise for left/right). The 2px edge test is then
  `_edge_line(img, 0) == all(WindowText)`, `_edge_line(img, 1) ==
  all(WindowText)`, `_edge_line(img, 2) == all(Window)`, asserted separately
  so a failure names the line. `emphasis` is read from
  `tokens_gen.TOKENS["border-width.emphasis"]`, never typed.
- **Each dialog is shown alone**: construct, `qtbot.addWidget`, `resize(480,
  240)`, `show()`, `qtbot.waitExposed`, two `QApplication.processEvents()`,
  `grab().toImage()`; hold the dialog in a local for the life of the
  assertion. Builders: `ApiKeyDialog()` (no arguments); `BakeConfirmDialog(
  BakePreview(output_dir=tmp_path, page_count=4, total_lines=6, unreviewed=(),
  failed=(), overflowing=()))` (`mangatl.pipeline.bake.BakePreview`, as
  `tests/ui/test_bake_dialog.py:60-67` builds one); `RerunDialog(_preview(
  within_budget=...))`; `QMessageBox()` with `setIcon(Warning)`,
  `setWindowTitle("Settings")`, `setText("...")` - built directly, never
  through the static `QMessageBox.warning`, which blocks in `exec`. A
  `QMessageBox` may refuse `resize` below its layout minimum; the instrument
  precondition asserts only that every edge run is non-empty and the image is
  at least `3 * emphasis + 1` on each axis, not a fixed size.
- **Line 2 is the ground only if no child reaches it.** Every dialog here
  lays out with default or token margins (>= `space.s1`), so the first child
  pixel is well inside line 2; AC-6's control measures the same lines under
  the packaged sheet and finds the ground, which is the check that the
  instrument is reading the dialog and not a child. If RED finds a dialog
  whose child does reach line 2, amend this block (sample line 2 only where
  AC-6 found the ground on it) and say which dialog.
- Dynamic property precondition for AC-3/AC-4 as the sibling does
  (`dialog.property("overBudget") is True/False`).
