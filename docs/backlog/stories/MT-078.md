## Context

**The user's request, 2026-10-09, raised during MT-038 PLANNED:** *"Build it so
I can use a Google Gemini API or OpenAI GPT API key as well."* Translation must
work with an Anthropic (Claude), Google Gemini or OpenAI GPT key. This is the
first of four stories in `EPIC-08`, and the one every other depends on: it
decides **which** provider a run uses, and gives `compose` one place to bind
that provider's translator. It adds no provider. Claude keeps working exactly
as MT-011/MT-044 built it; Gemini and OpenAI arrive in MT-080 and MT-081.

**Product decisions, made by the user on 2026-10-09, recorded here as PO-1 to
PO-3 and binding on all four stories:**

- **PO-1 — provider selection is by which key is set.** `ANTHROPIC_API_KEY`,
  `GEMINI_API_KEY`, `OPENAI_API_KEY`. If more than one is set,
  `MANGATL_PROVIDER` (and a `--provider` flag on `mangatl-run`) picks; with
  several keys and no choice, **the run refuses to guess** - a clear error, not
  a silent pick. No settings screen yet: env vars only (MT-024 deferred
  `settings.json`; MT-077 will have to grow from one key to three - see
  `## Out of scope`).
- **PO-2 — default model per provider.** Claude stays `claude-opus-5` exactly
  as MT-011 built it (unchanged call shape). Gemini: `gemini-3.1-pro`. OpenAI:
  `gpt-6.1-sol` (the flagship GPT-6 Astra at $10/$50 per MTok estimates
  ~$2.24/chapter, over the $2 ceiling, so it was rejected).
- **PO-3 — MT-038 stays Claude-only.** Each new provider story carries its own
  live-measurement criterion, verified on the dev machine when the user has
  that key, modelled on MT-038's answers.

**What exists today** (read on 2026-10-09; re-check before relying):
`compose.build_pipeline` binds `partial(translate_page, Anthropic())` - a bare
`Anthropic()` whose key is the SDK's own environment lookup (MT-044 A-1).
`pipeline.translate_stage.PageTranslator` is
`Callable[[bytes, Sequence[OcrResult], PromptContext], TranslationResult]`,
every half stdlib or `domain`, so the pipeline already names its translator
behind a provider-neutral callable; **the seam exists in `pipeline` and is
missing only in `compose`**. `domain.rates` is keyed by model id, and the
three default model ids are globally unique, so the rate table needs no
re-keying by provider - each adapter story adds its own row.

**The budget guard needs no per-provider image-token rule.** Verified by
reading `domain/budget.py`: `Budget.project` projects from
`BOOTSTRAP_PAGE_ESTIMATE` ($0.06) until `MIN_SAMPLES_FOR_PROJECTION` priced
calls exist and from the observed mean thereafter, and nothing in `src/`
consumes the `est_tokens` that `build_request` returns (`rg est_tokens src`
finds only `translate/prompt.py`). A cheaper provider is projected
conservatively for its first pages and accurately after; no story in this epic
changes the guard.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage` - `src/mangatl/translate/**`, `src/mangatl/compose.py` and
`src/mangatl/cli.py` are read by both via `covers | unit | src/mangatl/**`.
The one `ui` file it touches is read by `unit` through `tests/ui`. No optional
gate is load-bearing; `required_gates` stays empty.

## Acceptance criteria

*Oracle partition: every criterion here is **mechanical** - env mappings in,
a value or a named exception out, one exact message. Pin exactly; nothing is
measured and nothing is settled by a document other than PO-1.*

- **AC-1** — Given exactly one of `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`,
  `OPENAI_API_KEY` is set and non-empty, when the provider is selected with no
  explicit choice, then the selection is that key's provider and carries that
  key's value. (Three cases, one per key. An empty-string value counts as
  unset.)
- **AC-2** — Given two or more keys set and no explicit choice, when the
  provider is selected, then `AmbiguousProvider` is raised, and its message
  names **every** provider whose key is set, `--provider` and
  `MANGATL_PROVIDER` - and no provider is chosen.
- **AC-3** — Given no key set, when the provider is selected, then `NoApiKey`
  is raised, and its message names all three key variables and
  `--no-translate`.
- **AC-4** — Given an explicit choice (the `--provider` flag, else
  `MANGATL_PROVIDER`, the flag winning when both are given), when the provider
  is selected, then it is the chosen one even if other keys are also set; and
  given the chosen provider's key is **not** set, then `KeyMissingForProvider`
  is raised naming the provider and its key variable.
- **AC-5** — Given an explicit choice that is not one of `anthropic`,
  `gemini`, `openai` (case-sensitive, lowercase), when the provider is
  selected, then `UnknownProvider` is raised naming the bad value and the
  three valid ones.
- **AC-6** — Given a selection of `anthropic`, when `build_pipeline` is called
  with `translate=True`, then the translator it binds is `translate_page`
  bound to an `Anthropic` client constructed **as today** (`Anthropic()` with
  no arguments: MT-044 C-13 is unchanged), and the stage list is the one
  MT-044 AC-4 pins. Given a selection of `gemini` or `openai`, then
  `build_pipeline` raises `ProviderUnavailable` naming the provider - the
  state of the tree until MT-080/MT-081 register an adapter - and constructs
  no client of any kind.
- **AC-7** — Given `mangatl-run` with no key, several keys and no choice, a
  missing key for the chosen provider, an unknown `--provider`, **or a
  selected provider that has no translator yet** (`ProviderUnavailable`;
  amended A-2), when it runs, then it exits non-zero with **one line carrying
  the exception's message**, no traceback, **before the weights are loaded and
  before any project directory is created**; and given `--no-translate`, no
  selection is attempted at all and none of those errors can occur.
- **AC-8** — Given the window's Start with a chapter chosen and
  `build_stages` raising any `ProviderError`, when Start is pressed, then the
  window shows the exception's message through its existing `show_error`
  rather than letting the exception escape the slot, **and no project
  directory is created** for the chapter (amended A-1: the window matches
  `mangatl-run`, AC-7).

**AC-6 is the one that can pass vacuously.** A `build_pipeline` that ignores
the selection and always constructs `Anthropic()` satisfies the first half.
The second half (gemini/openai → `ProviderUnavailable` and **no** `Anthropic`
constructed) is its control, asserted with the same spy `test_compose.py`
already uses for `mangatl.compose.Anthropic`.

### C-1 — `mangatl.translate.provider`: selection is pure and takes the environment

New module. **It imports no SDK** - not `anthropic`, not anything MT-080/081
add - so it is testable in `tests/core` with a plain dict, exactly as
`compose.resolve_models_dir` takes `env` as an argument (MT-036). It may
import `domain` only.

```python
Provider = Literal["anthropic", "gemini", "openai"]
PROVIDERS: tuple[Provider, ...] = ("anthropic", "gemini", "openai")   # this order in every message
KEY_VARS: Mapping[Provider, str] = {
    "anthropic": "ANTHROPIC_API_KEY", "gemini": "GEMINI_API_KEY", "openai": "OPENAI_API_KEY"}
PROVIDER_VAR: str = "MANGATL_PROVIDER"

@dataclass(frozen=True)
class Selection:
    provider: Provider
    api_key: str          # the key's value, never logged in full (see C-6)

class ProviderError(Exception): ...          # base; the message is the whole of the user's information
class NoApiKey(ProviderError): ...
class AmbiguousProvider(ProviderError): ...
class KeyMissingForProvider(ProviderError): ...
class UnknownProvider(ProviderError): ...
class ProviderUnavailable(ProviderError): ... # raised by compose, defined here so cli/ui catch one base

def select_provider(explicit: str | None, env: Mapping[str, str]) -> Selection: ...
```

Semantics, one line each:
- `explicit` is the flag's value, else the caller passes
  `env.get(PROVIDER_VAR)`; **`select_provider` itself does not read
  `PROVIDER_VAR`** - the caller resolves "flag beats variable" so the function
  has one input for the choice. *(RED may amend this to have the function read
  the variable if a test reads cleaner that way; say so.)*
- "set" means present **and non-empty after no stripping** - `""` is unset
  (AC-1); a key with surrounding whitespace is passed through as-is, since
  the SDK will reject it and that is the right place.
- Messages, exact text pinned by RED (the words these must carry): `NoApiKey`
  carries the three variable names and `--no-translate`; `AmbiguousProvider`
  carries each set provider's name, `--provider` and `MANGATL_PROVIDER`;
  `KeyMissingForProvider` carries the provider and its variable;
  `UnknownProvider` carries the bad value and `anthropic, gemini, openai`.
- No message ever carries a key's value, in whole or in part (C-6).

**Exact messages, pinned by RED (2026-10-09) - GREEN reproduces these
character for character** (`test_translate_provider.py`, and repeated as
literals in `test_cli.py`, `test_compose.py` and `test_start_run.py`). Names in
`PROVIDERS` order; `{value!r}` is Python's `repr`:

| Exception | `str(error)` |
|---|---|
| `NoApiKey` | `no API key is set: set ANTHROPIC_API_KEY, GEMINI_API_KEY or OPENAI_API_KEY, or run with --no-translate` |
| `AmbiguousProvider` | `API keys are set for more than one provider ({", ".join(set providers)}); choose one with --provider or MANGATL_PROVIDER` |
| `KeyMissingForProvider` | `provider {provider} was chosen but {KEY_VARS[provider]} is not set` |
| `UnknownProvider` | `unknown provider {value!r}: choose one of anthropic, gemini, openai` |
| `ProviderUnavailable` (raised by `compose`, C-2) | `translation with {provider} is not available yet` |

e.g. `API keys are set for more than one provider (anthropic, openai); choose
one with --provider or MANGATL_PROVIDER`, and `unknown provider 'Anthropic':
choose one of anthropic, gemini, openai`. Every exception takes the message as
its single positional argument (`str(NoApiKey("x")) == "x"` is pinned). The
CLI prints `mangatl-run: <message>` through the existing `_fail`. *Reason for
the amendment: C-1 asked RED to pin the text; this is where GREEN reads it.*
`select_provider` does **not** read `PROVIDER_VAR` - RED kept C-1 as written
and pins it (a `MANGATL_PROVIDER` inside `env` with `explicit=None` changes
nothing).
