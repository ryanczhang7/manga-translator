## Context

EPIC-09 PO-5, and D6 applied to a batch: **the guard judges the whole batch
before it is submitted**, and a refused batch submits nothing and spends
nothing. This story is the pipeline's submit half: after detect, clean and
OCR have run for every page (the existing per-page stages, with no translate
stage) and the glossary pre-pass has run (MT-105's `ChapterStep`), build
every page's request in `neighbours` context (MT-107), project the batch,
check it, submit it through the bound submitter (MT-110), persist the job
(MT-103), and say so.

**The projection.** A batch of `n` pages is one decision about `n x
page_estimate(model, pricing="batch")` - MT-100's per-page figure at the
batch tier (MT-102). `Budget.check(spent, projection)` compares
`spent + next_call` to the ceiling inclusively; for a batch `next_call` is
the whole batch. The $2.00 default ceiling against a 200-page volume at
~$0.015 a page is $3.00: **a volume is refused under the default ceiling**,
and that is correct - the ceiling is per chapter, the volume is ten chapters,
and raising or scoping the ceiling is out of this epic (EPIC-09 "Deliberately
not"). The user sets the stored ceiling (MT-044) for a volume; the refusal
names the three numbers so they know what to set.

`pipeline` may not import `translate`: the submitter is a `Callable` bound by
`compose`, and the page input type lives in `domain`.

Required gates: `unit`, `coverage`, `coverage-core` (`domain/budget.py`).

## Acceptance criteria

- **AC-1** - `page_estimate("gemini-3.1-pro-preview", pricing="batch")` is
  the design-A token profile at the batch row, rounded up to the cent
  (`$0.02` at the assumed 50% row: 12,846 micro -> 20,000); `pricing`
  defaults to `"standard"` so MT-100's values are unchanged.
- **AC-2** - `Budget.project_batch(pages, page_estimate)` returns
  `Projection(next_call = pages x page_estimate, remaining_chapter = the same,
  basis "estimate", sample_count 0)`; for 0 pages both are `$0.00`.
- **AC-3** - Given a project with OCR done on three pages, a glossary
  proposed, a fake submitter and a stored ceiling of `$0.06`, when
  `submit_volume` runs, then the submitter receives three `BatchPageInput`s
  in ordinal order whose contexts are the `neighbours` contexts and whose OCR
  is the stored lines; `pending_job(project)` is the submitter's job name
  with `model_id` the selection's; and `BatchSubmitted(run_id, job_id,
  page_count=3, projection)` is emitted.
- **AC-4** - The same with a stored ceiling of `$0.05`: the submitter is
  **not** called, no `batch_job` row exists, `RunAborted(reason=BUDGET,
  ordinal=None)` is emitted with the decision's three numbers in its text,
  and the ledger is unchanged.
- **AC-5** - With a job already pending, `submit_volume` raises nothing to
  the submitter, submits nothing, and reports `BatchPending` through
  `RunAborted` naming the pending job.
- **AC-6** - A page whose OCR has not run (no stored lines) makes
  `submit_volume` refuse before any call, naming the ordinal: a batch is
  built from finished OCR or not at all.

## Contract

**Writes:** `src/mangatl/domain/budget.py`, `src/mangatl/domain/batch.py`, `src/mangatl/domain/events.py`, `src/mangatl/pipeline/batch.py`, `src/mangatl/compose.py`, `tests/core/test_budget.py`, `tests/core/test_batch_submit.py`, `tests/core/test_compose.py`

```python
# domain/budget.py
def page_estimate(model_id: str, *, pricing: Pricing = "standard") -> Usd        # MT-100's, with the tier
class Budget:
    def project_batch(self, pages: int, page_estimate: Usd) -> Projection

# domain/batch.py (MT-103's module)
@dataclass(frozen=True)
class BatchPageInput:
    ordinal: int
    page_image: bytes
    ocr_results: tuple[OcrResult, ...]
    context: PromptContext

# domain/events.py
@dataclass(frozen=True)
class BatchSubmitted:
    run_id: int
    job_id: int           # the batch_job row
    page_count: int
    projection: Projection

# pipeline/batch.py
BatchSubmitter = Callable[[Sequence[BatchPageInput]], str]     # returns the provider's job name
def submit_volume(project: Project, run_id: int, submit: BatchSubmitter, model_id: str, page_estimate: Usd, emit: Callable[[RunEvent], None]) -> int
    """Order: every page has lines (else refuse, AC-6) -> no pending job (AC-5) -> build inputs in
    neighbours context -> Budget.check(chapter_total, project_batch(n, page_estimate)) -> BudgetRefused if not
    permitted -> submit -> record_submission -> emit BatchSubmitted. Returns the job row id."""

# compose.py: for gemini, binds submit = lambda inputs: submit_batch(client, build_batch_requests([BatchPage(...) for i in inputs]), display_name)
#   and page_estimate = page_estimate(model_id, pricing="batch"). How the window/CLI reach submit_volume is MT-113's.
```

The `BatchPage`/`BatchPageInput` duplication is deliberate: `translate` may
not be imported by `pipeline`, so the domain carries the input shape and
`compose` converts. RED may collapse the two by moving `BatchPage` to
`domain` and having `gemini_batch` import it - amend MT-110's block too if so.

Oracle partition: AC-1, AC-2 **settled**; AC-3 to AC-6 **mechanical**.
