## Context

EPIC-11 PO-1, PO-3. The user's run stopped (out of API credits), the window
opened the chapter in the review `Workspace`, and nothing there could run the
rest: `MainWindow._start` is reached only from a folder with no project
(`create_project` refuses an existing one), and `app.open_folder` builds the
`Workspace` with no `RunSetup` at all. The command line resumes
(`cli.py:156-160`); the window does not. MT-119 AC-5c adds a second case that
waits on this: a page whose cleaned image was invalidated by a restore.

**What exists and is reused whole.** `RunController` (`ui/run.py`) runs
`run_chapter` on a worker over its own `Project` and signals every event to
the GUI thread; `RunProgressPanel` (`ui/progress.py`) renders the run, the
cost readout and the budget / failed banners with "Review pages 1-N";
`MainWindow._start` / `_run_ended` / `_review` / `closeEvent` are the sequence
(build stages, run, hand over, cancel-and-wait on close). `BakeConfirmDialog`
is the shape of a "state it, then confirm" dialog (MT-066). MT-124's
`rerun_preview` is the statement. This story wires them into the `Workspace`:
one action, one dialog, the panel in the workspace body for the duration, the
body back and reloaded when the run ends.

**Why inside the workspace** (PO-3). Handing over to the intake window would
mean closing the project, two windows and a second code path for "finished ->
review". Swapping the body keeps one window and one open project, and makes
"no row can be edited while the worker writes" structural: the column is not
on screen. The GUI's `Project` connection reads nothing during the run and
re-reads everything after (`load_chapter`), which SQLite serves fresh - no
cache anywhere in `store`.

**Design.** Drafted below under `## Design notes` by the PO against
`components.md` §3 (`WorkspaceShell` header), §8 (`RunProgressPanel`), §9
(dialogs) and `voice.md` (*run*, never *process*; the abort sentence's shape);
the Lead Designer pass (EPIC-11 Q-1) ran 2026-10-30 and confirmed the label,
placement, dialog copy and return announcements, landed in `components.md` §3
/ §9 / §10.7 and `accessibility.md`. The names and states here are the
contract RED tests; the words in `## Design notes` are read out by RED, not
invented.

Required gates that fail if this breaks: `unit`, `coverage` (`tests/ui`,
offscreen - the gate `tests/ui` already runs under). No display, no weights:
every stage list is a fake implementing `Stage`, as `test_start_run.py` -
except AC-9, which uses the real `build_stages` over fake engines, as MT-124
AC-6 (`tests/core/test_resume.py`) does.

## Acceptance criteria

- **AC-1** - Given a `Workspace` built with a `RunSetup` and a chapter loaded,
  then the header carries a button whose text and accessible name are **"Run
  again"** (the Lead Designer's word; the string RED reads out of `## Design
  notes`), a focus stop reachable by Tab in visual order, placed before the
  cost readout; given a `Workspace` built without a `RunSetup`, the button is
  absent (not merely disabled: a window nobody gave a run setup cannot run,
  `MainWindow` C-3's rule).
- **AC-2** - Given a project of four pages where pages 1-2 have every stage
  done and a fake stage list, when "Run again" is activated, then any pending
  line save is written first, `resolve_models`, `build_stages` and
  `select_model` are called in that order and each once, and a modal dialog
  opens stating `rerun_preview`'s figures in the Design-notes copy: the pages
  still to run ("2 of 4 pages"), the pages to translate, the estimate, the
  spent total and the ceiling, with the over-budget sentence when
  `within_budget` is false; its primary action reads "Run 2 pages". Cancel
  and `Esc` reject it and no `run` row is written. *Control:* with every page
  done the dialog says nothing is left to run, has no primary action, and
  "Close" is its only button.
- **AC-3** - When the dialog is confirmed, the workspace body (strip, canvas,
  column) is replaced by a `RunProgressPanel` built with the chapter and the
  project's ceiling; the fake stages run off the GUI thread; the panel
  receives every `RunEvent` in emission order on the GUI thread; the two done
  pages produce `PageSkipped` and the other two `PageStarted`; the project's
  `run` row ends `finished`. "Render pages" and the header button are not
  activatable while the run is on.
- **AC-4** - When the run ends `finished`, the body returns with the chapter
  reloaded from the same open project (no `open_project` call on the GUI
  thread, `closed` not emitted): the strip's statuses are re-derived, the cost
  readout shows the new total, the page shown before the run is shown again,
  and the live region announces the Design-notes sentence for a finished run.
- **AC-5** - When the run aborts - a fake stage raising on page 3, or a
  `BudgetRefused` - the panel shows its existing banner (copy unchanged from
  MT-059 / MT-018) and its "Review pages" action returns the body as AC-4
  does; pages 1-2 read `done`, page 3 does not; a second "Run again" then
  starts at page 3 (the fake records the pages it ran: `[2, 3]` the first
  time, `[2]`... *exact:* the second run's `PageStarted` ordinals begin at
  the page that failed).
- **AC-6** - Closing the window during a run cancels at the next stage
  boundary and waits for the worker; `closed` is emitted after the worker has
  returned and the run row reads `aborted` / `cancelled`; the pending saves
  rule (MT-054 C-4) is unchanged.
- **AC-7** - With `resolve_models` returning `None`, activating "Run again"
  shows `NO_MODELS` (character for character, `ui/run.py`) in the footer's
  render-status label and announces it, opens no dialog and starts no run; a
  `ProviderError` from `build_stages` is shown the same way with its message.
- **AC-8** - `mangatl.app.open_folder(folder, run_setup=...)` hands the
  `RunSetup` to the `Workspace` it builds, and `build_window` passes the one
  it was given (or built) down every path that reaches `open_folder` - the
  command-line path and the `MainWindow`'s `FolderOpener` - so a chapter
  opened from the intake window and one opened from the command line both
  have the action.
- **AC-9** - (PO-1 below; the epic's done-when.) Given a project of four
  pages, every one `done`, then page 2's cleaned image invalidated the way
  MT-119's restore of a never-erased region invalidates it, and a `Workspace`
  whose `RunSetup.build_stages` returns the **real** `build_stages` over fake
  engines that record each call (MT-124 AC-6's construction), when "Run
  again" is activated, the dialog reads `1 of 4 pages still to run.` and
  `1 to clean.` and has no estimate line; when it is confirmed, the clean
  engine is called for page 2 only, the detect, read and translate engines
  are never called, no `cost` row is added, and after the return page 2 reads
  `done`. *Control:* without the invalidation the dialog shows `Every page is
  done. Nothing to run.` and no engine is called.

### C-1 `Workspace`

```python
class Workspace(QMainWindow):
    def __init__(self, run_setup: RunSetup | None = None) -> None: ...
    rerun_button: ActivatedByEnter | None   # None without a run_setup; text/accessibleName "Run again"
    run: RunController | None               # the run in flight, else None
    run_panel: RunProgressPanel | None      # the panel in the body while a run is on
    rerun_dialog: RerunDialog | None        # the last dialog opened, kept after it closes
```

- `_rerun()` (the button's slot): return if no chapter, a run is on, or a
  render step is loading. `translation_column.flush()`. `setup.resolve_models()`
  -> `None`: `_say(NO_MODELS)` (footer `render_status` text + `live_region`)
  and return. `setup.build_stages(models)` -> `ProviderError`: `_say(str(e))`,
  return. `estimate = page_estimate(setup.select_model())`
  (`domain.budget.page_estimate`; a `ProviderError` here is shown as above).
  `preview = rerun_preview(self._project, stages, estimate)` on the GUI thread
  - reads only, one pass. Open `RerunDialog(preview, self)` with `open()`,
  keep the stages for the confirm.
- On accept: `panel = RunProgressPanel(ceiling, chapter=self._chapter)`;
  `self.run = RunController(project_dir_for(source_dir), stages, self)`;
  `run.event -> panel.on_event`, `run.ended -> self._run_ended`,
  `panel.review_requested -> self._return_from_run`; swap: the body's
  `splitter` is **hidden and the panel inserted in its place** in the body
  layout (header and footer stay; `render_button` and `rerun_button` set
  disabled for the duration - "not activatable", AC-3); `run.start()`.
- `_run_ended(outcome)`: if `outcome.outcome == RUN_FINISHED`,
  `_return_from_run()`; else the panel's banner stays and its action returns.
- `_return_from_run()`: remove the panel, show the splitter, re-enable the
  buttons, `self.load_chapter(self._project)` (same connection),
  `page_strip.setCurrentRow(previous)`, announce. `self.run = None`.
- `closeEvent`: before the render wait, `if self.run is not None and
  self.run.is_running(): self.run.cancel(); self.run.wait()` - `MainWindow`'s
  order, then the existing flush / state write / `closed`.
- Imports `mangatl.ui.run` (`RunController`, `RunSetup`, `NO_MODELS`),
  `mangatl.ui.progress`, `mangatl.pipeline.resume`, `mangatl.pipeline.runner`
  (`RUN_FINISHED`), `mangatl.domain.budget.page_estimate`. Never
  `mangatl.compose` (the stage builder is injected, `ui/run.py`'s rule).

**The action.** `Run again` - text and accessible name both, a `secondary`
button (§1, `ActivatedByEnter` as `render_button` is) in the `WorkspaceShell`
header, **immediately before the `CostReadout`**: after the stretch that
follows the chapter name, so it sits in the header's right-hand cluster beside
the figure it concerns and is unaffected by the narrow breakpoint hiding the
chapter name. `voice.md`'s term is *run*; "Resume" was considered and set
aside - the first run may have finished, and the dialog says what will actually
happen. Tooltip at rest: `Run what is not done yet. Pages already done are
kept.` Tooltip while disabled (§1: a disabled control says why): `A run is on.`
Keyboard: a focus stop in header order, Tab reaches it before anything in the
body; no shortcut (nothing in §4.7 is free that reads as "run", and a one-key
start of a paid run is not wanted). Absent - not disabled - when the window has
no `RunSetup`. Disabled while a run is on; while a render step is loading the
slot returns without opening anything (the button stays enabled, as
`render_button` itself does).

**The dialog** (`RerunDialog`, modal, `elevation.e2`, §9's rules, title and
accessible name `Run again` - the same word as the button, as "Render pages"
names both its button and its dialog). Plain-text labels (`plain_label`,
word-wrapped), top to bottom; the dialog's `accessibleDescription` is the
visible lines joined by `\n`, as `BakeConfirmDialog` does. Figures: `{n}` =

  2 of 4 after the abort. Counting stored-done pages is the reading that
  matches the store; worth a word to the Lead Designer if a later story needs
  it exact.
- **AC-5's prose says `[2, 3]` for the first run**; with a stage raising on
  page 3 the first run starts page 3 only. The test pins the measured `[2]`,

- **The banner prices with the panel's own ceiling** (`progress.py`,

  `project.budget_ceiling() or DEFAULT_CEILING`; the budget case pins that
  with a $5.00 ceiling.
- **Disabled tooltips**: Design notes gives both buttons `A run is on.` while

  tooltip only mid-run.
- **Connect the panel by bound method, not by lambda**: the order test patches
