## Context

EPIC-13 priority 3 (U-1), PO-4 (open to the user on cost). In copy A
(`neighbours`, the mode MT-109 makes the default), p017's regions 4-7 hold
`っ` / `いてーよー！！` / `いてーよー！！` / `急ぐぞ！！こっから先は戦場だ！！`, and they
received "WEE" / "WEE" / "It hurts!!" / "It hurts!!". The battlefield line
landed on region 8, in a small balloon at a tiny size.

**What was checked, so it is not re-litigated.** The response schema keys the
answer by index (`page_prompt.response_schema`). The parser assigns by key,
never by position (`parse.parse_lines_text`, MT-011 C-4, pinned by
`well-formed.json`'s `2, 0, 3, 1` order). The stage maps keys back through
`included` (`translate_stage._to_reading_indices`, MT-118). The model itself
wrote the English under the wrong keys: the page carried three siren
regions whose OCR is hallucinated `んーーー…`/`あああ…`, and a lone `っ`, and it
attached the drawn "WEE-WOO" to the next index. Copy B, given the same
listing, keyed it correctly. Nothing in the answer lets the app see the slip.
MT-147 removes this page's trigger (art text). This story makes any slip
**detectable**.

Each answer entry becomes `{"ja": <the region's Japanese, repeated>, "en":
<English>}`. An entry whose `ja` is not close to the OCR text listed under
that index is a misaligned entry. Its English is dropped and the region is
recorded untranslated. The system prompt already calls that state
recoverable, where an invented line is not. Writing the Japanese next to its
English also conditions the model to keep them together. That is a hoped-for
effect, measured in DV-2, not claimed.

Required gates: `unit`, `coverage`, `coverage-core`.

## Acceptance criteria

- **AC-1** - `response_schema(n)`: each index property is an object with
  required string fields `ja` and `en` and `additionalProperties: false`.
  The index properties themselves are still not required (MT-011 AC-5).
  `SYSTEM_PROMPT` tells the model to copy each region's Japanese into `ja`
  exactly as listed, even where it believes the listing was misread, and to
  write what it reads in the image only when the listing for that region is
  empty (PO-1 in `## Notes`).
- **AC-2** - `echo_matches(listed, echoed)` is True for:
  - an exact copy;
  - a copy differing by whitespace, by full-width against half-width forms
    (NFKC), or by `ECHO_MAX_EDIT_RATIO` or less of the longer string's
    characters (OCR noise the model corrected);
  - an empty `listed` (`ocr_empty`: the model reads the bubble itself).
- **AC-3** - *(control: p017's slip, rebuilt as a fixture)* Given a
  nine-region listing with p017's Japanese, and an answer whose entries 4-7
  carry the `ja` of regions 3-6 with English shifted to match, when parsed and
  checked, then regions 4, 5 and 7 have **no** proposal. Region 6, whose
  echo is its own listing's text (`いてーよー！！`, AC-4's case), keeps
  the English it carries, "It hurts!!", which is correct for it. Regions 0-3
  and 8, whose echoes match, keep theirs. *(Amended, A-1.)*
- **AC-4** - *(control: a repeated line is not a slip)* Two regions with
  identical Japanese (`いてーよー！！` twice), whose entries swap, both keep
  their English. The echo cannot and need not tell them apart.
- **AC-5** - Given a stage run where the checked answer drops k entries, then
  `write_proposed` receives only the accepted ones. Each dropped region reads
  `failed` with the reason `the translation did not line up with this bubble`,
  distinct from `no translation was returned`. The same holds for a page
  collected from a batch job (`pipeline/batch.py`).
- **AC-6** - Every adapter (Claude, Gemini, Gemini batch) returns lines
  through the same `parse_lines_text` and `checked_lines` pair. No adapter
  compares on its own.

### C-1a How the flag travels (pinned 2026-11-11, at PLANNED)

```python
# domain/echo.py
def echo_matches(listed, echoed):
    # both sides: unicodedata NFKC, then every str.isspace() character removed.
    # listed == "" after that            -> True
    # else Levenshtein(listed, echoed) / max(len(listed), len(echoed))
    #                                     <= ECHO_MAX_EDIT_RATIO
def checked_lines(entries, listed):
    # listed[k] is the Japanese sent under answer key k. For each (k, entry):
    #   echo_matches(listed[k], entry.ja) -> lines[k] = entry.en
    #   otherwise                         -> k in misaligned, and NOT in lines
    # A key the answer omitted is in neither (it stays "no translation was returned").

# domain/translation.py
class TranslationResult:
    lines: Mapping[int, str]              # accepted entries only
    usage; call; proposed_terms           # unchanged, still no defaults
    misaligned: frozenset[int] = frozenset()   # same key space as `lines`

# domain/line.py
class Line: ...; misaligned: bool = False      # new, last field
_REASON_MISALIGNED = "the translation did not line up with this bubble"
# failure_reason, for a `failed` line: ocr_empty -> the OCR reason;
# else misaligned -> _REASON_MISALIGNED; else "no translation was returned".

# store/project.py
def write_proposed(self, page_ordinal, proposed: Mapping[int, str],
```

### C-3 The constant

`ECHO_MAX_EDIT_RATIO` is **oracle-free**. RED sets it from two controls
written first:
- AC-2's one-substitution-in-ten case must pass;
- AC-3's shifted echoes must fail. In the fixture the nearest shifted pair is
  `いてーよー！！` against `っ`, at an edit ratio of about 1.0.

Pick the value in the gap and record the measured gap in the comment.

*RED amendment (2026-11-11), measured:* the nearest shifted pair that must
fail is entry 7's, `急ぐぞ！！こっから先は戦場だ！！` echoed as `いてーよー！！`,
at **0.875**; entries 4 and 5 are at 1.0. Entry 6 echoes `いてーよー！！`
against its own identical listing, ratio **0.0** - it cannot fail, and that is
escalated (AC-3, see `## Handoff`). Gap: `[0.25, 0.875)`; RED recommends 0.4.
The tests pin the band, not a literal.

A third control, for short text, where one character is a large share: a
four-character listing echoed with one character changed (ratio 0.25) must
pass. So the value is at least 0.25. How many correctly keyed entries the
check drops on real pages is DV-2's `misaligned` figure, not something a
fixture can settle.

### The export shape the tests pin (fact, not suggestion)

`mangatl.domain.echo` (imported lazily everywhere; a top-level import would
take the session dark):
- `__all__ == ["ECHO_MAX_EDIT_RATIO", "AnswerEntry", "CheckedLines", "checked_lines", "echo_matches"]` (that order: RUF022's isort-style sort).
- `ECHO_MAX_EDIT_RATIO: float`, `0.25 <= R < 0.875`.
- `AnswerEntry`: frozen dataclass, fields exactly `ja`, `en` (in that order),
  constructible positionally `AnswerEntry(ja, en)`.
- `CheckedLines`: frozen dataclass, fields exactly `lines`, `misaligned`;
  constructed by tests as `CheckedLines(lines={...}, misaligned=frozenset({...}))`;
  `type(lines) is dict`, `type(misaligned) is frozenset`.
- `echo_matches(listed, echoed) -> bool`; tests call it positionally and check
  `is True` / `is False` (return a real bool).
- `checked_lines(entries, listed) -> CheckedLines`, called positionally with a
  `dict[int, AnswerEntry]` and a `list[str]`; `listed[k]` indexed by key.
- the module imports only the standard library (an AST check over the file).

`mangatl.translate.parse.parse_lines_text(text, region_indices)` and
`parse_lines(message, region_indices)` return `dict[int, AnswerEntry]`, values
`type(...) is AnswerEntry`, the `ja` carried byte for byte (no normalisation in
the parser). `__all__` of `parse` unchanged.

The adapters: each module binds the name **`checked_lines`** at module level
(`from mangatl.domain.echo import checked_lines`) and calls it as
`checked_lines(entries, listed)` with `listed` the texts of the `ocr_results`
it sent, in order - the spy tests replace `mangatl.translate.client.checked_lines`,
`mangatl.translate.gemini.checked_lines` and `mangatl.translate.gemini_batch.checked_lines`
with `monkeypatch.setattr` (which raises if the attribute is absent), and
require the result's `lines` / `misaligned` to be exactly the recorder's. In the
batch adapter it is called once per page with that page's listing.

`mangatl.domain.translation.TranslationResult` fields, in order: `lines`,
`usage`, `call`, `proposed_terms`, `misaligned` - `misaligned` defaults to
`frozenset()` (and `type(...) is frozenset`).

`mangatl.domain.line.Line` fields end `..., ocr_empty, excluded, misaligned`;
`misaligned: bool = False`. `failure_reason` returns, for `failed`:
`"no text was read in this bubble"` if `ocr_empty`, else
`"the translation did not line up with this bubble"` if `misaligned`, else
`"no translation was returned"`; `None` for every other status, `excluded`
included.

`Project.write_proposed(page_ordinal, proposed, misaligned=())` - the third
argument positional; out-of-range indices in it raise `ValueError` whose
message starts `reading index {index} is not on page` (the existing wording);
an index in both raises `ValueError` naming it, nothing written.
`store.lines.read_review_lines` fills `Line.misaligned` from `line.misaligned`.

Schema: `SCHEMA_VERSION == 14`; `line.misaligned` is `("misaligned",
"INTEGER", 1, "0")` in `table_info` and the **last** column; a migrated
file's `line` `sqlite_master.sql` equals a fresh file's after collapsing
whitespace (see "Implementation notes").

`page_prompt`: `SYSTEM_PROMPT` and `response_schema(n)` exactly as C-1b (the
amended Contract) writes them.

**Not constrained:** how `echo_matches` computes Levenshtein; what
`parse_lines_text` does with an entry that is not a `{ja, en}` object (a bare
