## Context

Cut from MT-130 at its PLANNED under **MT-130 PO-1** (the user, 2026-11-05):
MT-130 gives `run_chapter` the two-pass order - every page read, then the
chapter prelude, then every page translated - and the pipeline shape that
carries it (`Pipeline(stages, prelude, after_prelude)`, `PassStarted`), on
the CLI. The window still builds its run through `app.build_stages ->
RunSetup -> RunController`, which drop the prelude (MT-105 PO-5) and run a
single pass over `Pipeline.page_stages` (MT-130 AC-15). This story carries
the `Pipeline` down that path, so Start and Run again in the window read
every page, propose the glossary once over all of them, and then translate,
and the progress panel says which pass it is in.

**MT-106 depends on this story as well as on MT-130** (MT-105 PO-2): today
the window's Gemini run has no prelude at all, so removing per-page
proposing before the window proposes up front would leave a window run with
no glossary.

The criteria below are the draft carried over from MT-130's `## Proposed
split` (W-1..W-7 there); they are finalised at this story's own PLANNED,
together with the `## Contract`, the callers list and the deferred
verifications. Wording of the pass labels and the reading-pass failure
banner is **MT-130 PO-4** (the user, 2026-11-05): `Reading page n of m`,
`Translating page n of m`, `No pages were translated.`

Required gates: `unit`, `coverage` (`tests/ui`); the `frozen` gate covers
`src/mangatl/app.py`.

## Acceptance criteria

*Draft, carried over from MT-130 W-1..W-7; finalised at this story's PLANNED.*

- **AC-1** - `RunSetup.build_stages` is `Callable[[Path], Pipeline]`
  (`StageBuilder` retyped, name kept); `RunController(project_dir, pipeline,
  parent)` runs `run_chapter(project, pipeline.stages, emit, cancelled,
  prelude=pipeline.prelude, after_prelude=pipeline.after_prelude)`. An
  app-level test pins that `build_window`'s default setup's builder is
  `app.build_stages` and that `app.build_stages` returns the `Pipeline`
  `build_pipeline` returned, prelude included - the defect this story
  exists to remove is the window dropping it.
- **AC-2** - Given a Gemini setup over a fresh chapter in the window, Start
  runs the reading pass over every page, then the prelude (one
  `CallPriced(ordinal=None)` reaches the panel), then the translating pass
  (asserted on a recording pipeline through `RunController`, as
  `tests/ui/test_start_run.py` drives runs today).
- **AC-3** - `Workspace._rerun` previews over `pipeline.page_stages` (so
  `pages_to_translate` and the estimate are unchanged) and runs the
  `Pipeline` it previewed.
- **AC-4** - `RunProgressPanel`: on `PassStarted("reading")` the overall
  label reads `Reading pages`; each `PageStarted(n)` in that pass reads
  `Reading page n+1 of m`; on `PassStarted("translating")` the bar returns
  to 0, the per-pass completed/skipped counters and the ETA reset, the
  stepper is all-pending, the label reads `Translating pages`, then
  `Translating page n+1 of m` per page. Without any `PassStarted` the panel
  reads `Page n+1 of m` as today (`tests/ui/test_run_progress.py` unchanged).
- **AC-5** - In the translating pass `PageStarted` starts the stepper with
  Detecting and Reading **done** and Translating active
  (`PageStageStepper.start(active=2)`), so `StageFinished("translate")`
  leaves Translating and Done done and nothing pending.
- **AC-6** - A `RunAborted` with `ordinal=None` after
  `PassStarted("translating")` and before any `PageStarted` (a refused or
  failed prelude) shows the budget or failed banner with kept = 0: `No
  pages were translated.`, no action. A failure during the reading pass
  (`RunAborted(reason, n)` before `PassStarted("translating")`) shows the
  failed banner naming page n+1 with `No pages were translated.` and no
  action. A budget abort in the translating pass at ordinal k keeps today's
  banner: pages 1-k translated, `Review pages 1-k`.
- **AC-7** - The batch panel (`batch=True`) and `BatchController` are
  unchanged: `submit_chapter` runs a single pass and emits no `PassStarted`.
