## Context

Cut from MT-130 at its PLANNED under **MT-130 PO-1** (the user, 2026-11-05):
MT-130 gives `run_chapter` the two-pass order - every page read, then the
chapter prelude, then every page translated - and the pipeline shape that
carries it (`Pipeline(stages, prelude, after_prelude)`, `PassStarted`), on
the CLI. The window still builds its run through `app.build_stages ->
RunSetup -> RunController`, which drop the prelude (MT-105 PO-5) and run a
single pass over `Pipeline.page_stages` (MT-130 AC-15). This story carries
the `Pipeline` down that path, so Start and Run again in the window read
every page, propose the glossary once over all of them, and then translate,
and the progress panel says which pass it is in.

**MT-106 depends on this story as well as on MT-130** (MT-105 PO-2): today
the window's Gemini run has no prelude at all, so removing per-page
proposing before the window proposes up front would leave a window run with
no glossary.

The criteria below are finalised from the draft MT-130 carried over (W-1..W-7
there). Wording of the pass labels and the reading-pass failure body is
**MT-130 PO-4** (the user, 2026-11-05): `Reading page n of m`, `Translating
page n of m`, `No pages were translated.` Three criteria carry wording or
behaviour PO-4 did not settle; the user decided each on 2026-11-05 (`## Notes`,
"PO decisions" PO-6, PO-7, PO-8), and the decisions are written into the
criteria below.

The defect this story exists to remove: `RunController._work` calls
`run_chapter(project, stages, emit, cancelled)` with no `prelude` and no
`after_prelude`, so a Gemini run started from the window never proposes the
glossary. The gate that fails if the fix breaks is `unit` (required;
`tests/ui`), with `coverage` behind it; nothing here is read only by an
optional gate (`integration` covers `detect/ocr/clean`, none written here),
so `required_gates` stays empty. The `frozen` gate imports `mangatl.app` and
would catch a broken import of `Pipeline` there, but judges nothing else of
this story.

### C-1 - `ui/run.py`: the builder returns a `Pipeline`, the controller runs it

```python
from mangatl.pipeline.prelude import Pipeline

#: The pipeline for a models folder: the reading pass, the chapter step, the
#: translating pass (MT-139). The name is kept; only what it returns changed.
StageBuilder = Callable[[Path], Pipeline]

@dataclass(frozen=True)
class RunSetup:
    resolve_models: ModelsResolver
    build_stages: StageBuilder          # name, position and type-alias name kept
    select_model: ModelSelector
    build_batch: BatchBuilder | None = None

class RunController(QObject):
    def __init__(self, project_dir: Path, pipeline: Pipeline, parent: QObject | None = None) -> None:
        ...
        self._pipeline = pipeline

    def _work(self) -> None:
        with open_project(self._project_dir) as project:
            outcome = run_chapter(
                project,
                self._pipeline.stages,
                self._emit,
                self._cancel.is_set,
                prelude=self._pipeline.prelude,
                after_prelude=self._pipeline.after_prelude,
            )
        self.ended.emit(outcome)
```

`__all__` is unchanged (`StageBuilder` stays exported). **Why one field and
not a defaulted second one** (PO-2 below): every one of the 37 `RunSetup(`
constructions in `tests/ui` passes the builder by position or as
`build_stages=`, so keeping the name and position keeps all 37 valid as
written; what changes is what the 10 stand-in builders *return* (one line
each, listed under `## Callers`). A second, defaulted `build_pipeline` field
would keep a path that drops the prelude alive as a feature - the defect this
story removes - and put the two-shape choice in both windows.

`ui` -> `pipeline.prelude` is a downward import (`architecture.md` §6; the
layers contract allows it; `ui.run` already imports `pipeline.runner`,
`pipeline.batch`, `pipeline.stage`). `prelude.py` imports no `translate`
module, so the three provider contracts hold. **`ui` never imports
`compose`** - the `Pipeline` arrives built, as the stage tuple did.

| Event | Effect |
|---|---|

| `StageFinished` | as today: `_elapsed_ms += ms` (never reset), `_current_ms += ms`, `stepper.finish(stage)` |
| `PageSkipped` | as today |
| `RunFinished` | as today: `_complete_current()`, bar full |

| `RunAborted` | as today's branches, with `_kept` and the `ordinal=None` headlines as below |

translated nothing this run, whatever the ordinal); otherwise as today -
`event.ordinal` when given, else `_completed + _skipped` (which, after
`_reset_pass()`, counts the translating pass only).

the glossary step failed."` and, in `_budget_abort`, `f"Run stopped before
page 1 of {m} \N{EM DASH} the {format_usd(self._ceiling)} budget was
reached."`. "Glossary step" is the PO's term, pending the Lead Designer
(`voice.md`'s terms table has no entry for it).

headline (`kept + 1`), so `test_run_failed_state.py` and the MT-018 budget
