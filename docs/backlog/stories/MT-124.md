## Context

EPIC-11 PO-1 and PO-2. The runner already resumes: `_run_page`
(`pipeline/runner.py:143-204`) skips a page every stage of which is done and,
inside a page it starts, skips each stage whose `is_done` is true. What no code
can say today is **what a run would do before it runs** - how many pages it
would start, which stages it would redo on them, how many it would translate,
and what that is expected to cost. The workspace's "Run again" (MT-125) needs
exactly that for its confirm dialog, the way "Render pages" needs
`preview_bake` (MT-066 C-1): a statement computed by the same rule the action
uses, so the two cannot disagree.

The rule is each stage's own `is_done`, consulted through a `PageContext` as
the runner consults it. The stages arrive already built (the window builds the
real list through `RunSetup.build_stages`; tests use fakes and
`build_stages(...)` over fake callables), so this module imports nothing under
`mangatl.detect`, `mangatl.clean`, `mangatl.ocr` or `mangatl.translate` and
the stage list's semantics are never re-derived here - `test_stages.py` already
pins which stage reads which table.

The money is the guard's own (PO-2): `budget_for(project, page_estimate)` and
`Budget.project(chapter_call_costs(project), pages_to_translate)`, the same
call `TranslateStage.run` makes before every page (`translate_stage.py:246`),
with the chapter's priced calls as samples when there are
`MIN_SAMPLES_FOR_PROJECTION` or more and the selected model's `page_estimate`
otherwise. Nothing new is priced; nothing is written.

Required gates that fail if this breaks: `unit`, `coverage` (`tests/core`).
Lands beside MT-119 (EPIC-10): no shared file.

## Acceptance criteria

- **AC-1** - Given a four-page project and a stage list of two fakes `a` and
  `b`, where pages 0 and 1 have both done, page 2 has `a` done only and page 3
  neither, when `rerun_preview(project, stages, page_estimate)` is called,
  then `page_count == 4`, `pages_to_run == 2`, and `pending` is
  `{"a": 1, "b": 2}` with the keys in **stage order**. *Controls:* every
  stage done on every page gives `pages_to_run == 0` and every count 0; nothing
  done gives 4 everywhere; an empty stage list gives `pages_to_run == 0` and an
  empty `pending` (the runner's `stages and all(...)` rule: a zero-stage run
  starts every page, but it redoes nothing, and the preview says 0 - stated,
  not stumbled into).
- **AC-2** - `pages_to_translate` equals `pending["translate"]` when a stage
  named `"translate"` is in the list, and is 0 when none is (a `--no-translate`
  list, `build_stages(..., translate=None, page_estimate=None)`); then
  `estimate` is `Usd.from_micro(0)`.
- **AC-3** - `estimate == budget_for(project, page_estimate).project(
  chapter_call_costs(project), pages_to_translate).remaining_chapter`,
  `spent == chapter_total(project)` and `ceiling == budget_for(project,
  page_estimate).ceiling` - read out, not re-derived. With no stored ceiling,
  `ceiling == DEFAULT_CEILING`; with a stored one, that one. *Controls:* with
  fewer than `MIN_SAMPLES_FOR_PROJECTION` priced calls the estimate moves
  when `page_estimate` changes; with that many or more priced calls it does
  not (the samples win, `Budget.project`'s rule).
- **AC-4** - `within_budget` is `spent + estimate <= ceiling`, inclusive: an
  estimate that lands the total exactly on the ceiling is within. *Control:*
  one micro-dollar over is not.
- **AC-5** - The preview writes nothing and runs nothing: the project file's
  `sqlite3` dump is byte-identical before and after; no stage's `run` is
  called; each stage's `is_done` is called **at most once per page** (a
  200-page chapter previews in one pass).
- **AC-6** - Given the real stage list over fake callables
  (`build_stages(detect, clean, transcribe, translate, page_estimate)`) and a
  project whose one page has stored regions, lines and a proposal but **no
  cleaned image** (the state MT-119 AC-5c leaves), then `pending ==
  {"detect": 0, "clean": 1, "ocr": 0, "translate": 0}`, `pages_to_run == 1`
  and `pages_to_translate == 0`. *Control:* the same page with a cleaned image
  stored and no proposal gives `clean: 0, translate: 1`, `pages_to_translate
  == 1` and a non-zero `estimate`.

### C-1 `src/mangatl/pipeline/resume.py` - new module

```python
__all__ = ["RerunPreview", "rerun_preview"]

@dataclass(frozen=True)
class RerunPreview:
    """What a run of `stages` over the project would do now, stated before
    it runs, from each stage's own `is_done` (EPIC-11 PO-1)."""

    page_count: int                 # len(project.pages())
    pages_to_run: int               # pages with some stage not done - the PageStarted count
    pending: Mapping[str, int]      # stage.name -> pages where that stage is not done; stage order
    pages_to_translate: int         # pending.get("translate", 0)
    spent: Usd                      # store.ledger.chapter_total(project)
    ceiling: Usd                    # budget_for(project, page_estimate).ceiling
    estimate: Usd                   # budget.project(chapter_call_costs(project), pages_to_translate).remaining_chapter
    within_budget: bool             # spent + estimate <= ceiling (inclusive, as Budget.check)

def rerun_preview(project: Project, stages: Sequence[Stage], page_estimate: Usd) -> RerunPreview:
    """Consult every stage's `is_done` once per page, through a `PageContext`
    as the runner would, and price the pages the translate stage would run.
    Opens no transaction, writes nothing, calls no `run`."""
```

`pending` is a `dict` built in stage order (insertion order is the order).
`page_estimate` is the selected model's `domain.budget.page_estimate(model)`,
the caller's to resolve (MT-125 reads it off `RunSetup.select_model`); it is
required for `budget_for`'s reason (MT-100 C-3).

### C-2 The `PageContext` a preview hands a stage

`PageContext(project=project, page=page, run_id=_NO_RUN, emit=_refuse)` with

```python
_NO_RUN = 0        # no run exists yet; `is_done` writes nothing, so no row can carry it
def _refuse(event: RunEvent) -> None:
    raise RuntimeError("a stage emitted an event from is_done; a preview runs nothing")
```

`run_id` is required without a default (MT-044 C-1) so that a *stage* cannot
forget it; a preview is not a stage and has no run. `0` is no run's id (rowids
start at 1) and the `llm_call.run_id` foreign key would refuse it, so a stage
that wrote from `is_done` would fail loudly rather than mis-file a bill. RED
may prefer a module constant on `stage.py`; say why.
