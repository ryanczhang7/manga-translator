## Context

Filed by the EPIC-04 mutation audit,
`docs/wiki/audits/EPIC-04-2026-10-13.md`: survivors TS8, TS2 and L2a
(`## Decided` items 2 and 3, `## Evidence` E-2 and E-4). **This is the
audit's first priority.** Two of these survivors let a run spend past its
ceiling, and the ceiling is the product's one hard rule (`architecture.md` D6,
brief AC-8).

**What is settled** (the audit's `## Decided`, not to be reopened):
- These three behaviours of `TranslateStage.run` and `store.ledger` are
  unprotected today.
- The fix is tests only. The production code is correct.

**What is evidence, to verify rather than trust:**
- the three mutant commands below, and that each still survives at this
  story's base;
- the arithmetic of the example scenarios (E-4), which was measured against
  `domain.budget` alone, not through the stage.

**The gap, in one paragraph each.**

- **TS8.** `TranslateStage.run` (`src/mangatl/pipeline/translate_stage.py:213`)
  projects from `chapter_call_costs(...)`. Replace that with `()`, so that
  every page is projected at the $0.06 bootstrap estimate, and 327 tests stay
  green. The refusal fixture in `tests/core/test_budget_run.py:169-184` says
  page 2's refusal "exercises the observed basis". It cannot: the observed
  mean there (50,000 micro-dollars) is *below* the estimate (60,000), so the
  estimate refuses page 2 too. A guard that never switches basis lets every
  chapter whose pages cost more than $0.06 run past its ceiling.
- **TS2.** The guard compares `chapter_total(...)` against the ceiling
  (`translate_stage.py:214`). Replace it with `run_total(ctx.project, ctx.run_id)`
  and the same 327 tests stay green, because every guard test is a single
  run. On a resume, a chapter that already spent most of its ceiling starts
  again from zero.
- **L2a.** `chapter_call_costs` (`src/mangatl/store/ledger.py:77`) can
  collapse equal-cost calls (`SELECT DISTINCT`) unnoticed: both of its tests
  record calls of distinct cost. Fewer samples keep the projection on the
  estimate basis and mis-state the mean.

No required gate fails if this story's tests are absent. That is the point:
these are assertion gaps under full line coverage.

## Acceptance criteria

- **AC-1**: Given a chapter whose priced calls so far average **more** than
  `BOOTSTRAP_PAGE_ESTIMATE`, and a stored ceiling that
  `spent + BOOTSTRAP_PAGE_ESTIMATE` would fit under but
  `spent + observed mean` would not, when the translate stage reaches the
  next page, then that page is refused before the translator is called:
  - the run ends `aborted` with reason `budget` on that page;
  - no ledger row is written for it;
  - the chapter total is unchanged.

  This test **fails** under mutant TS8 (below). Verified example, from the
  audit's E-4 a: two calls of 100,000 each, ceiling 270,000. The shipped code
  refuses the third page; TS8 permits it and ends at 300,000.
- **AC-2**: Given a chapter whose **earlier run** already recorded priced
  calls (the spend is in the ledger under a different `run_id`), when a second
  run reaches a page whose `chapter spend + projection` crosses the stored
  ceiling, then that page is refused before the translator is called, even
  though the second run itself has spent nothing.

  This test **fails** under mutant TS2. Verified example, from E-4 b: run 1
  translates pages 0 and 1 (40,000 + 60,000) and stops, the ceiling is
  120,000, and run 2 starts at page 2. The shipped code refuses page 2
  (projected 150,000); TS2 permits it and the chapter ends at 140,000.
- **AC-3**: Given two priced calls of **identical** cost in the ledger, when
  `chapter_call_costs` is read, then it returns both of them, and
  `Budget().project(<that>, n)` reports `sample_count == 2` and
  `basis == "observed"`. This test **fails** under mutant L2a.

**Block 1 - the helper.** `_run_chapter(fixture, *, ceiling_micro, calls=_CALLS,
cancelled=_never)` - two keyword parameters with defaults, so every existing
caller is unchanged. `calls` is handed to `_Translator(calls)`; `cancelled` is
handed to `run_chapter` where `_never` is today.

**Block 2 - AC-1's fixture.** A second cost table, `_HIGH_CALLS`: three
`_Call`s, each `claude-opus-5` with `TokenUsage(input_tokens=2000,
output_tokens=3600, cache_read_tokens=0, cache_write_tokens=0)`, request ids
`msg_high0..2`, `micro=100_000` (MEASURED: `price("claude-opus-5", that
usage).cost.micro() == 100000`; 2000 x $5 + 3600 x $25 per Mtok). Ceiling
`_HIGH_CEILING_MICRO = 270_000`, `_HIGH_REFUSED_ORDINAL = 2`. The guard's
walk, measured:

    page 0: 0 samples, spent       0, next 60000 (estimate)  ->  60000 <= 270000  PERMIT
    page 1: 1 sample,  spent  100000, next 60000 (estimate)  -> 160000 <= 270000  PERMIT
    page 2: 2 samples, spent  200000, next 100000 (observed) -> 300000 >  270000  REFUSE
    page 2 under TS8:  spent  200000, next 60000 (estimate)  -> 260000 <= 270000  PERMIT

The test asserts, on the one run: `RunAborted.reason == BUDGET` at ordinal 2;
`translator.calls == 2`; `_rows_for(db, 2) == 0`; `_ledger(db)` is exactly the
two 100,000 rows under this run's id; `chapter_total(...).micro() == 200_000`.
**And the discriminator, in the same test**: `Budget(Usd.from_micro(270_000))
.check(Usd.from_micro(200_000), Budget().project((), 1)).permitted is True` -
the estimate basis *would* have permitted this page, so the refusal can only
have come from the observed basis. That line is what the old fixture's comment
claimed and could not show.

**Block 3 - AC-2's fixture.** Two real runs through `build_stages`, both via
`_run_chapter`, under `_CALLS` and `_CEILING_MICRO` (120,000):

- Run 1: `cancelled=` a callable returning `fixture.project.page_status(1) ==
  PAGE_DONE`. The runner consults `cancelled()` at the top of the page loop
  (`runner.py:121`), so it stops before page 2 with `outcome == "cancelled"`
  (`runner.CANCELLED`), pages 0 and 1 done, two ledger rows (40,000; 60,000).
  Assert those as the precondition.
- Run 2: `_run_chapter(fixture, ceiling_micro=_CEILING_MICRO)` with `_never`.
  Pages 0 and 1 are `is_done` for every stage; page 2 runs detect and OCR, then
  the guard: spent 100,000 + observed mean 50,000 = 150,000 > 120,000 -> REFUSE.
  Under TS2: `run_total(run 2) == 0`, 0 + 50,000 <= 120,000 -> PERMIT, and the
  chapter ends at 140,000.

The test asserts, on run 2: `RunAborted.reason == BUDGET` at ordinal 2;
`translator.calls == 0` (run 2's own translator, never called); `_ledger(db)`
is still exactly the two run-1 rows (both carrying run 1's `run_id`, neither
run 2's); `chapter_total(...).micro() == 100_000`; and **the discriminator**:
`run_total(fixture.project, run2.outcome.run_id).micro() == 0` - the second
run spent nothing, so a guard reading the run's spend would have permitted the
page. `run_total` is imported from `mangatl.store.ledger` for that line.
`_set_ceiling` is called by `_run_chapter` on both runs with the same value;
that is idempotent and fine.

**Block 4 - AC-3.** In the same file, against the ledger with no stage: open a
run, `record_call` twice on ordinals 0 and 1 with the **same** `CostRecord`
(`price("claude-opus-5", _CALLS[0].usage)`, 40,000), distinct request ids.

**Block 5 - the comment.** Lines 179-184 of the file: replace the sentence
from "The crossover is on page 2" to "bite on real spend." with one saying
that under this fixture the estimate (60,000) and the observed mean (50,000)
**both** refuse page 2, so this fixture does not distinguish the bases, and
that `_HIGH_CALLS` is the fixture that does.

**Block 6 - admissibility.** The new tests pass on arrival. `uv run ruff
format --check`, `ruff check` and `mypy` are not run over tests by the gates,
but `ruff check .` is tree-wide, so the file must stay lint-clean; keep the
