### The cause, counted rather than guessed

`bash -x scripts/gates.sh --list` against the real 629-line manifest:

```
trace lines: 13075
sed         1461
cut          204
grep           1     tr  1     dirname  1     head  1
total external processes: 1669
```
`[MEASURED — 2026-09-20, orchestrator, bash -x trace, this worktree at b7250eb]`

**All 1,461 `sed` spawns are one command**, `trim()` at `scripts/gates.sh:89`:

```bash
trim() { printf '%s' "$1" | sed -e 's/^[[:space:]]*//' -e 's/[[:space:]]*$//'; }
```

Twelve call sites (`gates.sh:102,104,105,114,282,285,287,288,289,290,391,395`),
in two loops that each walk **all 629 lines** of
`.claude/harness/project.conf` — every line, because the loop trims first and
decides whether it is a comment second. Most of them wrap a `cut` that is
itself a spawn:

```bash
kind=$(trim "$(printf '%s' "$line" | cut -d'|' -f1)")
```

So listing a manifest costs ~1,669 processes. `--audit` (71 s) walks the same
parse. **`trim()` is duplicated verbatim** in `scripts/doctor.sh:18` and
`scripts/task.sh:8` — byte-identical, verified 2026-09-20.

### Why this is worth a story: the cost is paid many times over

`.claude/tests/gates.test.sh` runs `gates.sh` **11 times**, i.e. **~16,000
`sed` spawns from `trim()` alone**, and that suite is **25.5%** of the harness
self-test (584.7 s locally; dossier §2c). So this story is not a micro-
optimisation in a 72-second CI step — it is that step, the 71-second one beside
it, and a quarter of the 14-minute one.

### The pure-bash equivalence, checked before it was proposed

Against `${s#"${s%%[![:space:]]*}"}` / `${s%"${s##*[![:space:]]}"}`, over all
629 real manifest lines plus 5 edge cases (empty, all-space, inner-space,
tabs, no-space):

```
disagreements over 629 manifest lines + 5 edge cases: 0
trim_sed   x1461: 153017 ms
trim_bash  x1461:    188 ms
```
`[MEASURED — 2026-09-20, orchestrator, 1,461 calls each, the exact number
`--list` makes]`

**814x.** The local run was contended by a concurrent self-test, so 153 s
overstates an uncontended local figure — but CI's `Show configured gates` is
**72 s** for a run that makes exactly these 1,461 calls, which puts the runner
in the same order of magnitude and makes `trim()` the plausible majority of both
70-second steps.

**This is not a new kind of fix in this repository.** `.claude/hooks/lib.sh:763`
already records the same lesson from the other direction:

> One awk process for any number of paths, because spawning one per rule cost
> whole seconds on Windows.

### C-2 The two mechanisms, and the one that is easy to get wrong

**Mechanism 1 — `trim()` in pure bash.** The equivalence is already
demonstrated (AC-4's measurement):

```bash
trim() { local s="$1"; s="${s#"${s%%[![:space:]]*}"}"; printf '%s' "${s%"${s##*[![:space:]]}"}"; }
```

That is a suggestion, not a mandate; any implementation that satisfies AC-4's
equivalence over the full input set and spawns nothing is acceptable. **Keep
the name `trim` and the single-argument interface** so the twelve call sites do
not move.

**Mechanism 2 — field splitting without `cut`, and this is where it breaks.**
The `-fN-` forms mean *"field N and everything after it, pipes included"*, which
`IFS='|' read` does **not** give you for free: `read` assigns the remainder to
the last variable only when there are fewer variables than fields, and it does
**not** restore the delimiters it consumed while filling earlier variables.

Three distinct splits exist across the three scripts, and all three must be
preserved:

| script:line | form | meaning |
|---|---|---|
| `gates.sh:114` | `-f3-` | `<kind> \| <id> \| <value…>` — evidence, waiver, floor, slow, ci-factor, covers, blocked-when, skipped-when |
| `gates.sh:290`, `task.sh:21` | `-f5-` | `<kind> \| <id> \| <req> \| <cwd> \| <command…>` — gate, task |
| `doctor.sh:133` | `-f4-` | `<kind> \| <id> \| <cwd> \| <command…>` — discovery |

**And there is a second-level split that is easy to miss:**
`gates.sh:391,395` re-splits an already-extracted **value** on `|`
(`cif_n` = `-f1`, `cif_src` = `-f2-`). Whatever helper replaces `cut` must work
on a value as well as on a whole line, or that call site has to keep its own
logic. Name which it is in the handoff.

A workable shape, again a suggestion: one helper `field <n> <line>` and one
`rest <n> <line>`, both pure bash, both tested against the three rows of AC-3's
table.

trimming, and `[:space:]` is what makes a tab-indented `#` a comment.

### C-4 Bash 3.2, and no new dependencies

`gates.sh:96` says *"no associative arrays, for bash 3.2"*. Keep it. Bash, awk
and coreutils only; **no python** (`rules.md`, Portability: on Windows a bare
`python` hits the Microsoft Store alias shim and exits 49 without running
anything). Replacing 1,461 `sed` spawns with one `awk` spawn would satisfy AC-1
and is acceptable **only** if it also satisfies AC-2 and AC-3 — but note that
pure parameter expansion needs no process at all, which is strictly better and
is what the A/B measured.

### C-5 The earning rule

Every assertion this story adds about `trim` and about field splitting is
written against code that **already exists and already works** — the shipped

## Out of scope

**Every item below is a non-goal. Touching one is a reason to stop and raise it,
not a free win.**

1. **Any change to `.github/workflows/**` or `scripts/ci-local.sh`.**
   `.claude/tests/ci-local.test.sh` derives `ci-local.sh`'s expected step list
   from the `run:` lines of `gates.yml` and `boundaries.yml`, **in both
   directions**. If this story ever needs a workflow step changed, the matching
   `ci-local.sh` change lands in the same commit and that test must pass in both
   directions. It should not need to: this story changes what `gates.sh` does
   internally, not how it is invoked.
2. **`.claude/harness/project.conf`'s contents.** Not one line moves. Changing
   the manifest to make it cheaper to parse is solving the wrong problem, and
   `profiles.test.sh` reads the shipped file.
3. **`.claude/hooks/lib.sh`.** [[MT-041]]'s subject. `gates.sh` sources it, so
   the two stories will both make `gates.test.sh` faster; they must not both
   edit the same file.
4. **`scripts/selftest.sh`.** [[MT-039]]'s and [[MT-042]]'s.
5. **Any gate, gate command, evidence line, floor, `covers` line or
   `skipped-when` line.** This story changes the parser, never the manifest, and
   never what a gate reports. [[MT-037]] built the mechanisms that read these
   lines and they are heavily asserted.
6. **Deduplicating `trim` into a shared library.** Tempting — three copies of
   one function — but `doctor.sh` must run before a stack exists and before
   anything is installed, and making it source `.claude/hooks/lib.sh` is a
   coupling change with its own argument. AC-5 requires all three to be the fast
   form; it does not require them to be one form in one place. File the
   deduplication separately if anyone wants it.
7. **Deleting, weakening or reordering any existing assertion in
   `gates.test.sh`.** It is 155 call sites and the second-largest suite in the
   repository, and it is this story's regression corpus. [[MT-039]]'s floor for
   it is binding.
8. **Making `--list` or `--audit` print less.** AC-2 forbids it, and it is the
   obvious way to make the number go down without making anything faster.
