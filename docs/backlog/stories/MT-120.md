## Context

The user's second ask: *remove any region from a page in the workspace*. The
mechanism is MT-118's `Project.set_excluded`; this story is the action, the
two states it produces, and the counts that stop treating a removed region
as an unreviewed line.

**What exists.** `TranslationRow` (`ui/workspace.py:613`) is `[status
gutter][ordinal badge][editor][actions]` with `Revert` / `Accept` / `Retry
line` as always-visible `ghost` / `secondary` buttons shown by status
(`components.md` §5 "Row actions"). `BubbleMarker` (`ui/markers.py`) has
`IDLE / HOVER / SELECTED` and dimming. `Workspace._load_regions` builds one
`OrderedRegion` and one row per stored region, in reading order;
`read_review_lines` gives the `Line | None` per region; `_stored_progress`
feeds `page_progress(lines, ...)` for the strip's "k of m lines reviewed".
The region keeps its `reading_index` and ordinal when excluded (EPIC-10 PO-3),
so the link does not move.

**What a restored region is.** After MT-118 it has a line (OCR ran, PO-2) and
no proposal. On a page the run finished, `derive_status` gives it `failed`
("no translation was returned") with the `Retry line` control - honest, and
the user can type the English by hand (MT-098). This story does not run a
translation for it; EPIC-10 "Deliberately not".

**Design.** Written below under `## Design notes` by the PO against
`components.md` §4.3, §4.7, §5 and `accessibility.md` A-07, A-08, A-10, A-12;
**a Lead Designer pass is requested before RED** (EPIC-10 Q-4) to confirm the
label, the key and the excluded-state tokens, and to land the §4.3 / §4.7 / §5
additions in `components.md` and A-07's table row. The states and names here
are the contract RED tests; the hues are the designer's.

Required gates that fail if this breaks: `unit`, `coverage` (`tests/ui`
runs under both), `coverage-core` for the `domain` changes.

## Acceptance criteria

- **AC-1** - Given a page open in the workspace with a proposed line at
  ordinal 2, when the user activates the row's **Remove** control, then
  `read_regions(ordinal)[1].excluded == "user"` in the store, the row takes
  the `excluded` state (its editor read-only, its text `color.text.secondary`,
  gutter glyph the §5 "removed" glyph, status phrase "removed from
  translation"), its only action is **Restore**, the marker takes
  `MarkerState.EXCLUDED`, and the badge still reads **2**. The other rows and
  markers do not move or renumber.
- **AC-2** - Given an excluded row, when the user activates **Restore**, then
  the store's `excluded` is `None`, the row's state is `derive_status` of its
  line (`failed` on a finished page with no proposal; `proposed` where a
  proposal exists), and its actions are the ones that status shows (§5).
- **AC-3** - Given focus on a row (not editing) or on the canvas with a
  selection, when `Ctrl+E` is pressed, then the focused / selected region's
  exclusion toggles exactly as AC-1 / AC-2; while a row is being **edited**,
  `Ctrl+E` does nothing to the exclusion. The `ShortcutSheet`-equivalent list
  of bindings, if one exists in code, gains the row; `components.md` §4.7
  gains it regardless.
- **AC-4** - Given a toggle, then the live region announces "Bubble 2 removed
  from translation." or "Bubble 2 restored." (A-12), and the row's accessible
  name ends in the status phrase of AC-1 or AC-2 (A-08). Both controls carry
  their label as accessible name and are reachable by `Tab` within the row.
- **AC-5** - Given a page of four regions with one excluded, then the column
  header reads "… 3 lines, k reviewed" and the strip's progress phrase counts
  3 lines: `page_progress` leaves an excluded region out of `total`,
  `reviewed` and `failed`; a page whose every region is excluded reads "0
  lines" and is `fully_reviewed` for the strip's purposes. *Control:* with the
  exclusion cleared the counts are 4.
- **AC-6** - Given a region removed, when the workspace is closed and the
  chapter reopened, then the row and marker come back in the excluded state
  (the flag is the store's; nothing is kept in `workspace_state`).
- **AC-7** - Given a removed region, when the user selects it (click on the
  marker or `Up` / `Down` onto its row), then selection works as for any
  region (§4.5): the marker takes the selected core over its excluded style,
  the row is selected, and `Enter` on the canvas lands on the row but does
  **not** begin editing (the editor is read-only in this state).

### C-3 Markers

`MarkerState.EXCLUDED = "excluded"`. Style: core `overlay.bubble.idle` at
`overlay.stroke.core-idle`, **dashed** (`Qt.PenStyle.DashLine`, dash pattern
Qt default), no fill, badge **outline** with the numeral, drawn at
`overlay.dim.opacity` whether or not something else is selected - **except
when it is itself selected, which is full opacity** (Lead Designer, §4.3/§4.5:
selected stays unmistakable). Only the core is dashed; the halo stays solid
and the badge is never dashed. Hover over
an excluded marker: the hover core, still dashed. Selected: the selected core
and filled badge, still dashed - "dashed" is the one carrier of exclusion
that survives every state (A-10). `paint_marker` takes the pen style from the
state table. `OrderedRegion` gains `excluded: bool = False` (`ui/link.py`),
filled from `read_regions` in `_load_regions`.

**RED amendment (2026-10-29, test-developer) - what the tests pin.** A marker's
*state* is still one of `IDLE / HOVER / SELECTED / EXCLUDED`, so "dashed while
hovered or selected" cannot come from the state alone: `paint_marker(painter,
region, state)` dashes the core when `state is MarkerState.EXCLUDED` **or**
`region.excluded` is true. The canvas (`PageCanvas._restyle`) gives an excluded
region `SELECTED` when it is selected (opacity 1.0), `HOVER` when hovered and
not selected (opacity `overlay.dim.opacity`), and otherwise `EXCLUDED` (opacity
`overlay.dim.opacity` whether or not anything is selected). `EXCLUDED`'s style
row is `IDLE`'s colour and width with no fill and an outline badge. Unpinned:
`paint_marker(..., MarkerState.EXCLUDED)` on a region whose `excluded` is
false; the z-values; High Contrast (dim is 1.0 there already).

**Decisions on the PO's three (?) and the label**

1. **Gutter glyph: ⊘ (U+2298 `\N{CIRCLED DIVISION SLASH}`) confirmed; colour
   changed to `color.text.muted`.** One-colour: it is the seventh distinct
   silhouette next to ◯ ✔ ✎ ↩ ⚠ and the shrink glyph - the hollow circle of
   `proposed` with a diagonal through it, "a line, struck out", so
   `tests/ui/test_status_glyphs_one_colour.py`'s pairwise-distinct check holds
   once `STATUS_GLYPHS["excluded"]` is added. Font: measured with
   `QRawFont.supportsCharacter` - Segoe UI (and "Segoe UI Variable Text", which
   resolves to Tahoma on this machine) carries **none** of the status glyphs
   except ◯; ✔ ✎ ↩ ⚠ already render through Qt's fallback to Segoe UI Symbol,
   which has U+2298. So ⊘ falls back exactly as the existing set does; no new
   risk. Colour: `color.text.disabled` on `color.surface.selected` is 2.25:1,
   below the 3:1 non-text floor the moment the row is selected (AC-7), and the
   glyph is a status carrier (A-10). `color.text.muted` is 4.99:1 on raised and
   3.51:1 on selected (`tokens.md` §6). **C-6 names `color.text.disabled`; the
   rule GREEN writes is `QLabel#rowGutter[status="excluded"] { color:
   @{color.text.muted}; }` - PO to update C-6 to match.** No AC names the
   colour, so nothing frozen moves.
2. **Marker: dashed core, always at `overlay.dim.opacity`, confirmed, with one
   refinement: a *selected* excluded marker is at full opacity.** C-3's
   "whether or not something else is selected" is read as "something *else*";
   when the excluded marker is itself selected it is the §4.3 `selected` row
   (selected core, fill, filled badge, opacity 1.0) with a dashed core, so §4.5
   "the selected marker is unmistakable" and the A-06 render check for
   `selected` are untouched. "Always dimmed" is right: dimming already means
   "not the one you are working on", and an excluded region is permanently
   that; under HC dim is 1.0 and the dash alone carries it, which is why a dash
   is used at all. Distinguishability: only the **core** is dashed, the halo
   stays solid - Qt's default `DashLine` is 4 x width on / 2 x width off, so
   8 px / 4 px at the 2 px cosmetic idle core, the same on screen at every zoom;
   over dark art a light dashed line, over light art a dark line carrying light
   dashes. A dashed halo would open gaps in the A-06 path and was rejected. The
   badge is never dashed. Draw order: excluded idle sits in the bottom
   "dimmed idle" tier (§4.8, amended).
3. **`Ctrl+E` confirmed.** No binding in `src/mangatl/ui/` or in §4.7 / A-07
   uses it (grep `Ctrl+`, `QKeySequence`, `QShortcut`, `Key_`: `Ctrl+R`,
   `Ctrl+Enter`, `Ctrl+J`, `Ctrl+0/1/9`, `Ctrl+=/-` only). It is not a
   `QKeySequence.StandardKey` on Windows and `QLineEdit` has no Windows
   binding for it, so AC-3's "inert while editing" is a matter of
   `LineEditor` not claiming it (its `ShortcutOverride` filter at
   `line_editor.py:146` claims only its own chords, so a
   `WidgetWithChildrenShortcut` on the column would still fire while editing
   unless the slot checks the editing state - GREEN must gate the slot, not
   rely on the filter). Mnemonic: E for exclude. There is **no `ShortcutSheet`
   in code** (grep), so AC-3's "if one exists" clause is satisfied by §4.7.
4. **"Remove" / "Restore" confirmed.** The word is the user's own, it is what
   the counts do ("N lines" drops by one), and it pairs with "Restore".
   voice.md gives no reason against it. The erase risk (Q-1: left as drawn) is
   carried off by three things that are not the label: the status phrase says
   what it is removed *from*, the marker stays on the art (dashed), and a
   tooltip - Remove: "Leave this bubble out of translation. Nothing on the page
   is erased."; Restore: "Put this bubble back into translation." "Ignore"
