## Context

Brief feature 1 and section 3 steps 1–2. The input contract for the whole
product: a folder of `.png`/`.jpg` page scans, processed in filename order, with
the output preserving order and filenames.

Two things here are quietly load-bearing. **Filename order is not string order**
in any sense a user expects: `page10.png` sorts before `page2.png` under plain
lexicographic comparison, and a chapter delivered out of order is a chapter
whose translation context is wrong on every page. And **the input folder is the
user's scans** — the tool never writes there (`architecture.md` §5).

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — this is pure `domain` plus one filesystem read, all testable
against a `tmp_path`.

It depends on MT-003 rather than directly on MT-001 because it is the first
story to write a `domain` module, and `domain`'s independence contract should be
enforced before the first import is written rather than after.

## Acceptance criteria

- **AC-1** — Given a folder containing `p1.png`, `p2.png`, `p10.png`, when the
  folder is read as a chapter, then the pages are ordered `p1`, `p2`, `p10`.
- **AC-2** — Given a folder containing `a.png`, `b.JPG`, `c.jpeg`, `notes.txt`,
  `thumbs.db` and a subdirectory, when the folder is read, then exactly `a`, `b`
  and `c` are pages, in that order, and nothing else is.
- **AC-3** — Given a folder containing no image files, when it is read, then a
  named error is raised identifying the folder and saying no pages were found —
  not an empty chapter.
- **AC-4** — Given a chapter read from a folder, when each page is inspected,
  then it carries its ordinal (0-based, contiguous), its filename, its pixel
  width and height, and the SHA-256 of its bytes.
- **AC-5** — Given a folder containing a file named `p3.png` whose bytes are not
  a decodable image, when the folder is read, then that file is reported as an
  unreadable page naming the filename and the decode failure, and the remaining
  pages still load.
- **AC-6** — Given any chapter read operation, when it completes, then no file
  inside the input folder has been created, modified or deleted. *(Verified by
  hashing the whole input tree before and after.)*
- **AC-7** — Given two files that differ only in case (`A.png`, `a.png`) on a
  case-insensitive filesystem, when the folder is read, then the ordering is
  deterministic and the same on every run.

## Contract

**Modules and exports** (`architecture.md` §2; `domain` imports nothing of ours,
so the filesystem read lives in `store` and the ordering rule lives in `domain`):

```
src/mangatl/domain/page.py
    @dataclass(frozen=True) Page:
        ordinal: int          # 0-based, contiguous, assigned at intake
        filename: str         # basename only, never a path
        width: int
        height: int
        sha256: str           # lowercase hex, 64 chars

    @dataclass(frozen=True) Chapter:
        source_dir: Path      # informational; domain never opens it
        pages: tuple[Page, ...]

    PAGE_SUFFIXES: frozenset[str]        # {".png", ".jpg", ".jpeg"}
    def natural_key(name: str) -> tuple[object, ...]
    def order_filenames(names: Iterable[str]) -> list[str]

src/mangatl/store/intake.py
    def read_chapter(source_dir: Path) -> Chapter
    class NoPagesFound(Exception)
    class UnreadablePage(Exception)
```

**The semantics behind each number and rule — one sentence each:**

- **`natural_key` splits a filename into alternating non-digit and digit runs**,
  comparing digit runs as integers. `p2` < `p10` because `2 < 10`, not because
  of any zero-padding the user may or may not have used.
- **Case folding happens in the key, not in the filter.** Ordering compares
  case-folded text so `A.png` and `a.png` have a stable relative order; the
  *suffix* match is also case-insensitive, so `.JPG` is a page.
- **`ordinal` is assigned after ordering and is contiguous from 0.** It is the
  page's identity for the rest of the product and never changes for a given
  chapter read.
- **`sha256` is over the file's raw bytes**, not over decoded pixels. It is what
  makes MT-005's per-page invalidation work: re-encoding an identical image must
  count as a change, because the tool cannot know it is identical without
  decoding, and the cheap conservative answer is the right one.
- **A subdirectory is not descended into.** One folder is one chapter; nesting
  is not a chapter structure this product recognises.

**The tie-break must be total.** If two names fold to the same key, fall back to
the raw byte ordering of the name. AC-7 exists because a non-total comparator
gives a different order depending on the input sequence, which is a bug that
only shows up on someone else's filesystem.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1, AC-2, AC-7 | **Mechanical** | Pin exactly. These are enumerable; table-drive them. |
| AC-3, AC-5 | **Mechanical** | The error types and what their messages must name are fixed above. |
| AC-4, AC-6 | **Mechanical** | AC-6 is a before/after hash of the input tree; it is a property, not a judgement. |

There is nothing oracle-free in this story. Do not invent a metric.

**A property test is appropriate for AC-1/AC-7** (`hypothesis`): for any list of
filenames, `order_filenames` is a total order — deterministic, and a permutation
of its input. **If a generator is narrowed during RED or GREEN, name the design
clause that excludes what was excluded** (`rules.md`): "filenames cannot contain
a path separator" is a legitimate narrowing tied to the basename-only contract
above; "the test was failing on this input" is not.

**PO-1 — The image reader is Pillow, and the integrity call is `load()`, not
`verify()`.** `domain` may not import `PIL` (`pyproject.toml`, contract "domain
is independent"), so the decode lives in `store/intake.py`, which is free to.

The *mechanism* is checkable and was checked, because the obvious choice is
wrong. Measured against Pillow 12.3.0 on a PNG with a valid 8-byte signature, a
valid `IHDR` declaring 13×29, an `IDAT` of junk bytes, and a valid `IEND`:

| call | result |
|---|---|
| `Image.open(p)` | **OK, `size == (13, 29)`** |
| `Image.open(p); im.verify()` | **OK — does not raise** |
| `Image.open(p); im.load()` | `OSError: broken data stream when reading image file` |

So a reader built on `open()` alone, or on `open()` + `verify()`, accepts a
corrupt scan and reports a confident width and height for it. **`read_chapter`
must call `img.load()`** and read `img.size` after it. If RED or GREEN finds a
cheaper call that also rejects that fixture, say so rather than following this
line — it is a measurement, not a decree.

Pillow 12.3.0 ships `py.typed` (verified: `PIL/py.typed` exists). Do **not** add
a `[[tool.mypy.overrides]] ignore_missing_imports` entry for `PIL`; that would
be a weakening of the `typecheck` gate to solve a problem that does not exist.

    raw = b"".join(b"\x00" + bytes(rgb) * width for _ in range(height))
    def chunk(tag: bytes, data: bytes) -> bytes:

**PO-3 — AC-5 takes two fixtures, and one of them is (c).** A single
all-garbage fixture is a vacuous test of this criterion: `Image.open` rejects
garbage on its own, so such a test passes against a header-only reader that
would happily accept a truncated scan. Pin both:

| fixture | what rejects it |
|---|---|
| `p3.png` containing `b"this is not an image at all\n"` | `Image.open` → `UnidentifiedImageError` (a subclass of `OSError`) |
| `p4.png` containing the 81 bytes of (c) | `img.load()` → `OSError: broken data stream when reading image file` — **and nothing earlier** |

AC-5 also says "the remaining pages still load", so both corrupt files sit in a
folder with good pages. How a corrupt page is *reported* alongside good ones is
fixed here: `read_chapter` raises `UnreadablePage` on the first undecodable
file, whose message names that filename and the underlying decode failure. It
does not return a partial chapter — a partial chapter would give every later
page a wrong ordinal. "The remaining pages still load" is therefore asserted by
removing the corrupt file and reading the folder again, and by the raise
naming `p3.png`/`p4.png` specifically rather than the first file in the folder.

**PO-4 — AC-7 is a `domain` test, not a filesystem test.** `A.png` and `a.png`
cannot coexist in one directory on the NTFS volume this project is developed on;
a test that writes both gets one file and passes vacuously. The criterion's real
content is that the comparator is **total and deterministic**, which is a
property of `order_filenames(["A.png", "a.png"])` — a pure function over a list
of names, with no filesystem involved. Assert it there: the same input list in
several different input orders must give one identical output. The
`hypothesis` property named in `## Contract` above is the same assertion
generalised; both belong in `tests/core/`, against `domain`, and neither uses
`tmp_path`.

**PO-5 — `required_gates` stays empty, and that was checked rather than
assumed.** Read out of `bash scripts/gates.sh --list` today:
`src/mangatl/domain/**` is covered by `unit` (required), `coverage` (required)
and `coverage-core` (required); `src/mangatl/store/**` is covered by `unit` and
`coverage`, both required. No path this story writes is read only by an optional
gate, so there is no optional gate to promote. Note the consequence for RED:
`coverage-core` demands **100%** of `src/mangatl/domain` from `tests/core` alone,
so every branch of `natural_key` and `order_filenames` needs a case in
`tests/core/`, and `coverage` demands 90% across `src/mangatl`, which
`store/intake.py` is inside.

**PO-6 — where the tests live.** `tests/core/` for all of them. Nothing in this
story needs a GPU, the network or a display, so nothing belongs in
`tests/integration/` (which is still empty and waived until MT-007) or
`tests/ui/`. A test placed in `tests/integration/` would be read by no required
gate — the exact failure `covers` exists to catch.

**The `natural_key` type trap (row 4) was designed out, not hoped away.** A
capturing `re.split(r"(\d+)")` always returns an odd-length list alternating
text, digits, text, …, so index 0/2/4 is always `str` and index 1/3/5 always

and is tie-broken against `SS`/`ss` by the raw name, which is exactly the total
tie-break AC-7 asks for.

### Design notes GATES may need

- **Case folding is in `natural_key`; the suffix filter lower-cases separately.**
  `natural_key` casefolds text runs, which is what makes `natural_key("A.png") ==
  natural_key("a.png")` and `natural_key("p02.png") == natural_key("p2.png")`
  true. The *order* between such equal-key names comes from
  `order_filenames`' secondary key — `sorted(names, key=lambda n: (natural_key(n), n))`
  — which is the "fall back to the raw byte ordering of the name" clause. The
  suffix match is a separate mechanism entirely: `entry.suffix.lower() in
  PAGE_SUFFIXES` in `intake.py`. This split matters for DV-3; see below.
- **The decode runs against bytes in memory**, not against the open file:
  `read_bytes()` once, `Image.open(BytesIO(raw))`, and the same `raw` feeds
  `hashlib.sha256`. One read per page, no writable handle into the user's
  folder, and the `sha256` is provably over the same bytes that were decoded.
- **`UnreadablePage` aborts on the first undecodable file in reading order**
  (PO-3), with `raise UnreadablePage(f"cannot decode page {filename}: {error}")
  from error` — so `str(exc)` names the file and the decode failure, and
  `__cause__` is the Pillow `OSError`. The message deliberately does not
  interpolate `source_dir`, so it cannot accidentally contain another page's
  name.
