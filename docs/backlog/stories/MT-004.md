## Context

Brief feature 1 and section 3 steps 1–2. The input contract for the whole
product: a folder of `.png`/`.jpg` page scans, processed in filename order, with
the output preserving order and filenames.

Two things here are quietly load-bearing. **Filename order is not string order**
in any sense a user expects: `page10.png` sorts before `page2.png` under plain
lexicographic comparison, and a chapter delivered out of order is a chapter
whose translation context is wrong on every page. And **the input folder is the
user's scans** — the tool never writes there (`architecture.md` §5).

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — this is pure `domain` plus one filesystem read, all testable
against a `tmp_path`.

It depends on MT-003 rather than directly on MT-001 because it is the first
story to write a `domain` module, and `domain`'s independence contract should be
enforced before the first import is written rather than after.

## Acceptance criteria

- **AC-1** — Given a folder containing `p1.png`, `p2.png`, `p10.png`, when the
  folder is read as a chapter, then the pages are ordered `p1`, `p2`, `p10`.
- **AC-2** — Given a folder containing `a.png`, `b.JPG`, `c.jpeg`, `notes.txt`,
  `thumbs.db` and a subdirectory, when the folder is read, then exactly `a`, `b`
  and `c` are pages, in that order, and nothing else is.
- **AC-3** — Given a folder containing no image files, when it is read, then a
  named error is raised identifying the folder and saying no pages were found —
  not an empty chapter.
- **AC-4** — Given a chapter read from a folder, when each page is inspected,
  then it carries its ordinal (0-based, contiguous), its filename, its pixel
  width and height, and the SHA-256 of its bytes.
- **AC-5** — Given a folder containing a file named `p3.png` whose bytes are not
  a decodable image, when the folder is read, then that file is reported as an
  unreadable page naming the filename and the decode failure, and the remaining
  pages still load.
- **AC-6** — Given any chapter read operation, when it completes, then no file
  inside the input folder has been created, modified or deleted. *(Verified by
  hashing the whole input tree before and after.)*
- **AC-7** — Given two files that differ only in case (`A.png`, `a.png`) on a
  case-insensitive filesystem, when the folder is read, then the ordering is
  deterministic and the same on every run.

## Contract

**Modules and exports** (`architecture.md` §2; `domain` imports nothing of ours,
so the filesystem read lives in `store` and the ordering rule lives in `domain`):

```
src/mangatl/domain/page.py
    @dataclass(frozen=True) Page:
        ordinal: int          # 0-based, contiguous, assigned at intake
        filename: str         # basename only, never a path
        width: int
        height: int
        sha256: str           # lowercase hex, 64 chars

    @dataclass(frozen=True) Chapter:
        source_dir: Path      # informational; domain never opens it
        pages: tuple[Page, ...]

    PAGE_SUFFIXES: frozenset[str]        # {".png", ".jpg", ".jpeg"}
    def natural_key(name: str) -> tuple[object, ...]
    def order_filenames(names: Iterable[str]) -> list[str]

src/mangatl/store/intake.py
    def read_chapter(source_dir: Path) -> Chapter
    class NoPagesFound(Exception)
    class UnreadablePage(Exception)
```

**The semantics behind each number and rule — one sentence each:**

- **`natural_key` splits a filename into alternating non-digit and digit runs**,
  comparing digit runs as integers. `p2` < `p10` because `2 < 10`, not because
  of any zero-padding the user may or may not have used.
- **Case folding happens in the key, not in the filter.** Ordering compares
  case-folded text so `A.png` and `a.png` have a stable relative order; the
  *suffix* match is also case-insensitive, so `.JPG` is a page.
- **`ordinal` is assigned after ordering and is contiguous from 0.** It is the
  page's identity for the rest of the product and never changes for a given
  chapter read.
- **`sha256` is over the file's raw bytes**, not over decoded pixels. It is what
  makes MT-005's per-page invalidation work: re-encoding an identical image must
  count as a change, because the tool cannot know it is identical without
  decoding, and the cheap conservative answer is the right one.
- **A subdirectory is not descended into.** One folder is one chapter; nesting
  is not a chapter structure this product recognises.

**The tie-break must be total.** If two names fold to the same key, fall back to
the raw byte ordering of the name. AC-7 exists because a non-total comparator
gives a different order depending on the input sequence, which is a bug that
only shows up on someone else's filesystem.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1, AC-2, AC-7 | **Mechanical** | Pin exactly. These are enumerable; table-drive them. |
| AC-3, AC-5 | **Mechanical** | The error types and what their messages must name are fixed above. |
| AC-4, AC-6 | **Mechanical** | AC-6 is a before/after hash of the input tree; it is a property, not a judgement. |

There is nothing oracle-free in this story. Do not invent a metric.

**A property test is appropriate for AC-1/AC-7** (`hypothesis`): for any list of
filenames, `order_filenames` is a total order — deterministic, and a permutation
of its input. **If a generator is narrowed during RED or GREEN, name the design
clause that excludes what was excluded** (`rules.md`): "filenames cannot contain
a path separator" is a legitimate narrowing tied to the basename-only contract
above; "the test was failing on this input" is not.

## Model guidance

- **RED model:** to be recorded by the orchestrator at dispatch, by name; the
  default from `.claude/agents/test-developer.md` is `claude-opus-5`
  (Claude Opus 5).
- **GREEN model:** likewise, from `.claude/agents/feature-developer.md`.
- **Oracle partition: entirely mechanical** (table above). `story-authoring`'s
  measured finding is that the partition matters more than the model, and a
  fully mechanical story is the cheapest case there is. This is a reasonable
  place to try a weaker model on RED and record what happened — but only with
  the partition in the dispatch prompt, and only with the verdict written down.
- **Success condition, falsifiable:** RED produces a table-driven suite covering
  the `p2`/`p10` case, mixed case suffixes, the empty folder, the corrupt file
  and the input-tree hash, plus a `hypothesis` property for totality — and does
  **not** invent a "sensible ordering" metric, because the ordering is specified
  above and is to be read out, not derived.
- **Verdict:** *to be recorded.*
