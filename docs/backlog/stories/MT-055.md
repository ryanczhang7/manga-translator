## Context

**Filed 2026-09-30 by the Lead PO** from [[MT-054]] PO-5. After MT-054 a chapter
opens only as `mangatl <folder>`: a double-clicked installed app ([[MT-024]])
has no argument, so it shows the empty window (MT-054 AC-4) and there is no way
from there to any chapter. The brief's first five minutes begin "Open the app.
It asks for a folder of page images" (`product-brief.md` §3, step 1). This story
makes the no-argument window ask.

The designed component is `FolderDropTarget` (`docs/wiki/design/components.md`
§2), with its accessible name in `accessibility.md` A-08 and its screen layout
in `layout.md` "Intake and run screens". Those documents are the oracle for
every string and role below: **read them out, do not reword them.** This story
builds the component's *keyboard and click* path - the region as a button and a
native folder dialog. Drag-and-drop is [[MT-056]], split out because the design
says "Drag-and-drop is never the only path to any behaviour", so this path ships
first and is complete on its own (see `## Notes`, PO-2).

**A picked folder behaves exactly as `mangatl <folder>` does** (the user's
direction when filing): it opens the review `Workspace`, or it says no project
exists and names `mangatl-run "<folder>"`. It never creates a project. That is
narrower than the design's intake flow, whose next state is `ChapterSummary`
and "Start run"; see `## Out of scope` and PO-3.

Required gates that would fail if this broke: `unit` and `coverage` (both
required) collect `tests/ui` under `QT_QPA_PLATFORM=offscreen` and cover
`src/mangatl/ui/**` and `src/mangatl/app.py`; `lint` judges the import layers.
No optional gate is the only judge, so `required_gates: []`.

## Acceptance criteria

- **AC-1** — Given the app launched with no argument, when the window is shown,
  then its content is the `FolderDropTarget` in its **empty** state: headline
  "Drop a chapter folder here", body "Or choose a folder. Pages are processed in
  filename order.", and a visible "Choose folder…" affordance. The region is the
  **only** keyboard focus stop in the target and the **only** accessible Button
  in it, with accessible name "Choose chapter folder"; the "Choose folder…"
  affordance is neither focusable nor an accessible Button (PO-5).
- **AC-2** — Given the empty drop target, when the region is activated by
  Enter, by Space, or by a click anywhere on it - on the "Choose folder…"
  affordance included - then the folder chooser is asked for a folder, once per
  activation.
- **AC-3** — Given a chosen folder whose sibling `.mtproj` project exists, when
  the chooser returns it, then the review `Workspace` opens on that chapter with
  its pages listed and the first page shown, the intake window closes, and
  closing the `Workspace` closes the project - the same outcome as
  `mangatl <folder>` (MT-054 AC-1 and C-4).
- **AC-4** — Given a chosen folder with no project, when the chooser returns it,
  then the drop target shows its **error** state carrying the same text
  `mangatl <folder>` shows for that folder (MT-054 AC-3: "No project exists for
  *resolved folder*." and the command `mangatl-run "<resolved folder>"`) and a
  visible "Choose a different folder" affordance; the region is still the only
  focus stop and the only accessible Button, and activating it asks the chooser
  again; and nothing is created on disk. A project written by a newer build is
  the same error state carrying that project's `SchemaTooNew` message (MT-054
  C-2 case 5). *This is the interim no-project outcome: [[MT-057]] replaces it
  (for the picker and for `mangatl <folder>` alike, MT-057 PO-3) with the
  chapter summary or an intake error, and (through [[MT-059]]) "Start run".*
- **AC-5** — Given the chooser is dismissed without a folder, when it returns,
  then nothing changes: the drop target keeps the state it had (empty or error),
  no other window opens, and nothing is written.

### C-1 — `mangatl.app`: one resolution, two callers (PO-7)

```python
def open_folder(folder: Path) -> QMainWindow | str: ...
def build_window(arguments: Sequence[str]) -> QMainWindow: ...   # signature unchanged
```

- `open_folder` is the whole folder → outcome decision `build_window` makes today
  for one argument, moved verbatim: `folder = folder.resolve()`; not a directory
  → `NO_FOLDER_NOTICE.format(folder=...)`; `open_project(project_dir_for(folder))`
  called **through `mangatl.app`'s namespace** (MT-054's `_capture_projects`
  monkeypatches `app_module.open_project` and must keep working untouched);
  `FileNotFoundError` → `NO_PROJECT_NOTICE.format(folder=...)`; `SchemaTooNew`
  → `str(error)`; otherwise a `Workspace`, **not shown**, with `load_chapter`
  done, `page_strip` row 0 current and `closed` connected to closing the project.
  A `str` return is a notice; a window return is the opened chapter.
- `build_window([])` → `MainWindow(open_folder=open_folder)` (the intake window,
  C-2). `build_window([x])` → `open_folder(Path(x))`, wrapping a `str` as
  `MainWindow(notice=...)`. Two or more → `MainWindow(notice=USAGE_NOTICE)` as
  today. So the command line and the picker run the *same function object*:
  RED pins that `build_window([])`'s window holds `app_module.open_folder` (via
  C-2's `open_folder` attribute), not a copy.
- The three notice constants stay in `mangatl.app`, unchanged. No string moves.

### C-2 — `mangatl.ui.main_window.MainWindow`

```python
FolderOpener = Callable[[Path], QMainWindow | str]
FolderChooser = Callable[[QWidget], Path | None]

class MainWindow(QMainWindow):
    def __init__(self, notice: str | None = None, *,
                 open_folder: FolderOpener | None = None,
                 choose_folder: FolderChooser | None = None) -> None: ...
    open_folder: FolderOpener | None        # what it was given
    opened: QMainWindow | None              # the window it handed over to; None until then
```

- `notice` given → exactly MT-054 C-5, unchanged; `open_folder` / `choose_folder`
  are ignored and no drop target exists.
- `notice is None` → the central widget is a `FolderDropTarget` (C-3).
  `open_folder` is then **required**: `MainWindow()` with neither raises
  `TypeError` (a window that can choose a folder and do nothing with it is not a
  state this app has). `choose_folder=None` means the real dialog, C-4.
- Activation (C-3) calls `choose_folder(self)` exactly once. `None` → nothing
  (AC-5). A `Path` → `open_folder(path)` exactly once. A `str` result → the target
  goes to its **error** state with that text (AC-4). A window result → it is
  stored in `self.opened`, **shown, then** this window closes (show first, so
  Qt's quit-on-last-window-closed never sees zero windows). `self.opened` keeps
  the `Workspace` alive for as long as `main` holds the intake window.
  **RED amendment, 2026-09-30:** "this window closes" means `self.close()` - the
  window receives a `QEvent.Close` - not `hide()`. *Reason:* the ordering test
  observes the Close event with an event filter and records whether `opened` is
  visible at that instant; `hide()` sends no Close event and would read as "never
  closed". `close()` is also what Qt's quit-on-last-window-closed counts.
  `choose_folder` given alone (no `open_folder`, no notice) is the same
  `TypeError` as neither.
- `WINDOW_TITLE` and `NOTICE_OBJECT_NAME` unchanged. **`CANVAS_ACCESSIBLE_NAME`
  is removed** from `main_window` and its `__all__`: nothing in the window is a
  canvas any more, and `PageCanvas` names itself (A-08). Its two importers are
  in the callers list below.

### C-3 — `mangatl.ui.intake.FolderDropTarget` (new module)

```python
class FolderDropTarget(QWidget):          # a QAbstractButton subclass is GREEN's choice
    activated: Signal                     # () - once per activation
    state: str                            # "empty" | "error"
    def show_error(self, text: str) -> None: ...
```

- Object names, so tests find the parts without importing constants: the target
  `folder-drop-target`; its children `headline`, `body`, `affordance`. All three
  children have `focusPolicy() == Qt.NoFocus`, and none exposes accessible role
  Button. Note `QAccessible.Role.Button` **is** `PushButton` (both 43, measured
  2026-09-30): a `QPushButton` affordance fails AC-1 by construction.
- The target: `focusPolicy()` accepts Tab (`Qt.StrongFocus` or `Qt.TabFocus`);
  `QAccessible.queryAccessibleInterface(target).role() == Button`;
  `.text(QAccessible.Text.Name) == "Choose chapter folder"`;
  `.text(QAccessible.Text.Description) == "\n".join(t for t in (headline.text(), body.text()) if t)`
  in every state.
- **empty**: `headline` "Drop a chapter folder here"; `body` "Or choose a folder.
  Pages are processed in filename order."; `affordance` "Choose folder…" (U+2026,
  one character). All three visible.
- **error** (`show_error(text)`, PO-8): `headline` is `text` verbatim - the
  reason *is* the headline, because the design gives the error state no headline
  copy of its own and this story does not invent one; `body` is empty and hidden;
  `affordance` "Choose a different folder". Calling `show_error` again replaces
  the text. There is no way back to **empty** in this story.
- **RED amendment, 2026-09-30:** `headline`, `body` and `affordance` are each a
  `QLabel` (tests find them with `findChild(QLabel, name)` and read `text()`,
  `textFormat()`, `textInteractionFlags()`). *Reason:* the bullet below already
  requires what only a label has (a text format, interaction flags), and a
  `QPushButton` affordance fails AC-1 by construction (role 43); naming the
  class removes a guess GREEN would otherwise have to make.
- Children are plain text (`Qt.PlainText`: a folder name holding `&` is not
  markup) and **not** selectable - a selectable label would swallow the click
  AC-2 requires to land on the region. Copying the command is lost in the
  window; the command line's notice keeps it (PO-8).
- Activation = `activated` emitted once for: `Key_Return`, `Key_Enter`,
  `Key_Space` while the target has focus; a left click on the target, on
  `headline`, on `body`, or on `affordance`. A right click, and any other key
  (e.g. `Key_A`, `Key_Escape`), do not activate.
- Styling (not pinned by tests unless RED chooses to; if pinned, read out, do
  not invent): 2px dashed `color.border.interactive`, `radius.md`, ground
  `color.surface.base`, headline `type.display`; error border 2px solid
  `color.status.danger`; single centred column, max width 720 px, `space.8`
  padding (`layout.md`). The design's "danger-coloured icon" is not built here
  (A-10 is satisfied by the headline's words).

  read…", undecodable pages, >200 pages): they belong to the run-starting
  intake. The only error reasons here are AC-4's two.

  window.
- The command-line notice windows (MT-054 C-2 cases 2, 5 and 6 via
  `MainWindow(notice=...)`): unchanged. They do not gain a picker here.
- Recent chapters, a File menu, `Ctrl+O`, reopening the last chapter on launch,
  choosing a folder from inside an open `Workspace`, and the `PageCanvas` empty
  state's "Open a folder" text becoming an action.
- Multi-folder selection (the dialog chooses one directory).
- Window title naming the chapter (MT-054 out of scope, still).
