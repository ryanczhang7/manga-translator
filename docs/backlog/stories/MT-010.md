## Context

Open question **O6**, the other half. `docs/wiki/stack.md` §5/O6 and §5/O3.

Japanese bubble text runs vertically. The decision recorded in the stack
document is that this is handled by **model choice** — `manga-ocr` is trained on
manga crops in their native orientation and reads vertical columns directly —
and that the failure mode is a *helpful* pre-processing step: a deskew or a
rotate-to-horizontal that turns readable input into garbage. So the criteria
below are as much about what the pre-processing must **not** do as about what it
must do.

Read `docs/wiki/audits/MT-002-model-runtime.md`: its `## Decided` section
settles which OCR model and export are used. Its `## Evidence` numbers are to be
re-verified here, not assumed.

`required_gates: [integration]` is set for AC-6 and AC-7, which need the real
model. Everything else runs against a fake session.

## Acceptance criteria

- **AC-1** — Given a region and its page, when a crop is prepared, then the crop
  covers the region's polygon bounding box plus `CROP_PADDING_PX`, clipped to
  the page, with the region's orientation **unchanged** — no rotation, no
  deskew, no transpose.
- **AC-2** — Given a crop, when it is prepared for the model, then it is resized
  to the model's expected input size preserving aspect ratio, padded rather than
  stretched, and normalised with the constants the audit records.
- **AC-3** — Given a fake session returning a known token sequence, when decode
  post-processing runs, then it produces the expected Japanese string with the
  model's special tokens stripped and no trailing whitespace.
- **AC-4** — Given a fake session returning an empty sequence, when decode runs,
  then the region's text is the empty string and the region is flagged as
  `ocr_empty` rather than silently carrying `""` as if it were read.
- **AC-5** — Given a page's ordered regions, when OCR runs over them, then each
  region's text is stored against its own region id and the reading order from
  MT-009 is unchanged.
- **AC-6** — *(integration)* Given the real OCR model and a fixture crop of
  **vertical** Japanese, when it runs, then the transcription matches the
  hand-annotated ground truth by character-level accuracy of at least
  `OCR_MIN_ACCURACY`.
  *Control:* the **same crop rotated 90°** must score materially worse — below
  half that accuracy. If rotating the input does not hurt, the test is not
  measuring transcription of vertical text and AC-1's "do not rotate" rule is
  unverified.
- **AC-7** — *(integration)* Given a fixture crop whose main column carries
  furigana that MT-008 did not strip, when OCR runs, then the ruby characters do
  **not** appear in the transcription.
  *Control:* a crop of the ruby column **alone** must transcribe to the ruby
  characters — otherwise AC-7 passes because the model outputs nothing.

## Contract

```

    def load_ocr(model_path: Path, providers: Sequence[str]) -> OcrSession

    CROP_PADDING_PX: int
    def crop_for_region(page: NDArray[np.uint8], region: RawRegion) -> NDArray[np.uint8]
    def to_model_input(crop: NDArray[np.uint8], size: tuple[int, int]) -> NDArray[np.float32]

src/mangatl/ocr/decode.py
    def decode(tokens: Sequence[int], vocab: Mapping[int, str]) -> str

src/mangatl/ocr/stage.py
    class OcrStage:  # implements pipeline.Stage
        name = "ocr"
```

**Semantics, and the traps:**

- **`crop_for_region` must not rotate. Ever.** `manga-ocr` was trained on
  vertical crops; presenting it a rotated crop is presenting out-of-distribution
  input. AC-6's control is the assertion that makes this rule enforceable rather
  than a comment.
- **Padding, not stretching** (AC-2). A vertical column has an extreme aspect
  ratio, and a naive `resize(w, h)` to a square input destroys the glyphs. Pad
  to the model's aspect and then resize.
- **`CROP_PADDING_PX`** gives the model a little context around the glyphs;
  sized in page pixels, so record the page width it was measured at, as MT-008
  does.
- **`OCR_MIN_ACCURACY`** is character-level accuracy (1 − normalised Levenshtein
  distance) against the annotation. It is **not settled here**: GREEN measures it
  on the fixture set and records the measurement, the fixture count, and the
  rotated-control figure in `## Notes`. A threshold set to whatever the
  implementation scored is not a threshold — set it below the measured value with
  stated headroom, and say how much.
- **`ocr_empty` is a distinct state from empty text** (AC-4) because the
  translator must be able to tell "the model read nothing here" from "this region
  has no text", and the review screen shows them differently.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1..AC-5 | **Mechanical** | Fake session, hand-built arrays. AC-1 in particular is assertable without a model: compare the crop's pixel content against the page's, at the same orientation. |
| AC-6, AC-7 | **Oracle-free** | Real model, real crops. Invent the accuracy metric; **both controls named in the criteria are mandatory and both must fire hard.** |

## Deferred verifications

- *Falsifiable condition 1:* with `crop_for_region` made to rotate the crop 90°,
  AC-6 **must** fail. This is the single most valuable mutation in the story: it
  is the exact defect AC-1 exists to forbid, and AC-1's own test (a pixel
  comparison) and AC-6's (an accuracy score) should *both* catch it.
- *Falsifiable condition 2:* with `to_model_input` made to stretch rather than
  pad, AC-6 **must** fail. AC-2's mechanical test catches the shape; only AC-6
  catches the consequence.
- *Falsifiable condition 3:* with `decode` made to drop the **last** token of
  every sequence — a wrong value rather than a missing behaviour — AC-3 and AC-6
  **must** both fail.
- *Why RED cannot run these:* no implementation, and in RED the integration
  suite does not load at all, so AC-6 and AC-7's controls are **claims until
  GREEN**. RED must record their expected values in the handoff table and GREEN
  must confirm the measured ones.
- **Owner: GATES.** Three mutations via `bash scripts/mutate.sh`.

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition mixed**; the table goes into the dispatch prompt verbatim.
  Emphasise that AC-1's "no rotation" is **settled** — it comes from the model's
  training distribution, recorded in `stack.md` §5/O6 — and is to be asserted,
  not reasoned about afresh.
- **Success condition, falsifiable:** RED's handoff carries a table of every
  negative control with its **expected** value (rotated-crop accuracy below half
  the threshold; ruby-alone crop transcribing to ruby) marked explicitly as
  unverified-in-RED, and GREEN pastes the measured values beside them. A handoff
  that asserts a control fired without having run it is the failure this shape
  exists to prevent.
- **Verdict:** *to be recorded.*

## Out of scope

Translation. Correcting OCR errors — that is the LLM's job in MT-011, by design
(`stack.md` §5/O3), and building a correction pass here duplicates it. Language
detection. Any language but Japanese.
