## Context

EPIC-09 PO-1: one request per page, submitted together as one batch. This
story is the Gemini **adapter** for a batch - the SDK-facing half - with the
request and result shapes MT-101 `## Decided` fixed (D-? for `client.batches.*`,
the job states, per-request errors). Everything is testable with a fake
client; no money is spent in `tests/core`.

A batch request is the per-page request `translate/gemini.py:build_request`
builds today - same image cap, same system prompt, same schema (without
`glossary`, MT-106), same thinking config - with the context from
`neighbours` mode (MT-107), because that is the only context that exists
before any answer. The adapter does not know about modes: it receives
`PromptContext`s already built.

A finished batch answers one item per request, in order. Each item is either
an answer (parsed exactly as `translate_page` parses one) or an error; the
adapter returns both kinds and lets the pipeline decide (MT-112 marks the
page's lines `failed`).

Required gates: `unit`, `coverage`.

## Acceptance criteria

- **AC-1** - `build_batch_requests(pages)` for three `BatchPage`s returns
  three inline requests in ordinal order, each carrying `contents` and
  `config` equal to `build_request(page_image, ocr_results, context)`'s for
  that page, and a per-request key equal to `str(ordinal)` where the API
  supports one (MT-101 D-?); two calls are byte-identical.
- **AC-2** - `submit_batch(client, requests, display_name)` makes exactly one
  `client.batches.create` call with `model == MODEL_ID`, the requests as
  `src`, and the display name, and returns the job name the response
  carries; a client that raises propagates the exception and nothing is
  retried.
- **AC-3** - `batch_state(client, job_name)` maps the API's job states to
  `"pending"` (queued or running), `"succeeded"`, `"failed"`, `"cancelled"`,
  `"expired"`, each by name from MT-101 D-?, and an unknown state raises
  `UnknownBatchState` naming it rather than mapping to pending.
- **AC-4** - `collect_batch(client, job_name, pages)` on a succeeded job
  returns, per ordinal, a `TranslationResult` whose lines, usage (thinking
  added to output) and `call.model_id` (the item's `model_version`, else
  `MODEL_ID`) are read from that item, with `call.request_id ==
  f"{job_name}#{ordinal}"`; an item with an error returns a `BatchItemError`
  carrying the error text; a response with fewer items than requests raises
  `BatchShapeError` naming both counts.
- **AC-5** - `collect_batch` on a job whose state is not `succeeded` raises
  `BatchNotFinished` naming the state; no item is parsed.

## Contract

**Writes:** `src/mangatl/translate/gemini_batch.py`, `tests/core/test_gemini_batch.py`

```python
# translate/gemini_batch.py - imports google.genai; translate is the one package that may
BatchStateName = Literal["pending", "succeeded", "failed", "cancelled", "expired"]

@dataclass(frozen=True)
class BatchPage:
    ordinal: int
    page_image: bytes
    ocr_results: tuple[OcrResult, ...]
    context: PromptContext

@dataclass(frozen=True)
class BatchItemError:
    ordinal: int
    message: str

class UnknownBatchState(Exception): ...
class BatchNotFinished(Exception): ...
class BatchShapeError(Exception): ...

def build_batch_requests(pages: Sequence[BatchPage]) -> list[dict[str, Any]]
def submit_batch(client: Client, requests: Sequence[dict[str, Any]], display_name: str) -> str
def batch_state(client: Client, job_name: str) -> BatchStateName
def collect_batch(client: Client, job_name: str, pages: Sequence[BatchPage]) -> dict[int, TranslationResult | BatchItemError]
```

The exact SDK argument names (`src`, `config.display_name`, the state enum,
the result item shape) are **read out of MT-101 D-?** and written into this
block before RED; the names above are placeholders for the audit's. No new
dependency: `google-genai` is already pinned. Oracle partition: all
**mechanical**.

## Out of scope

- Reading pages from a project, guarding, persisting the job, ledgering:
  MT-111 and MT-112.
- Retrying a failed job or re-submitting failed items.
- File-based (GCS) batch input; inline requests only, up to the limit MT-101
  D-? records - a volume over it is refused in MT-111.
- Cancelling a job.

## Notes

- The per-item `request_id` of `{job}#{ordinal}` is the ledger's
  `request_id` for a batch page (MT-112); it is here so the adapter and the
  store agree on one spelling.
