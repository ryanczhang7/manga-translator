## Acceptance criteria

*Re-scoped 2026-10-12 to the Gemini key (the user's decision: v1 is
Gemini-only - see `## Notes` PO-1). Still a PLANNED draft: confirmed and
made testable at this story's own PLANNED → RED, so no `## Amendments` entry
is owed for this rewrite.*

- **AC-1** — Given `settings.json` absent or without a `gemini_api_key`, and
  no `GEMINI_API_KEY` in the environment, when the application starts, then
  before the intake window is usable it shows a dialog asking for the Gemini
  API key, with a link to where one is obtained (Google AI Studio) and a
  Cancel that leaves the app runnable in review-only mode (no run can start;
  the Start button's error names the missing key).
- **AC-2** — Given a key entered, when the dialog is accepted, then
  `settings.json` holds `gemini_api_key` and **every other key the file
  already had is preserved byte-for-value** — a `lettering_font_dir` the user
  set (MT-027) survives — and the file is written atomically (temp file and
  rename) so a crash mid-write cannot leave a half file.
- **AC-3** — Given a key in `settings.json` and none in the environment, when
  the window's Start builds the pipeline, then the selection is
  `Selection("gemini", <that key>)` and the client is
  `google.genai.Client(api_key=<that key>)` (MT-080's explicit-key
  construction, unchanged); with no key in either place and `translate=True`,
  the MT-078 `NoApiKey` refusal is what the Start button shows, before any
  weights load and before any project is created (MT-078 A-1).
- **AC-4** — Given a key in `settings.json`, or `GEMINI_API_KEY` in the
  environment, when the application starts, then no dialog is shown.
- **AC-5** — Given the key is read, when it is logged, displayed or reported
  anywhere, then it is never written in full: the dialog masks it, and no log
  line or error message carries more than its last four characters.
- **AC-6** — Given `GEMINI_API_KEY` in the environment and a *different*
  `gemini_api_key` in `settings.json`, when the window's Start builds the
  pipeline, then the selection carries the **environment's** key (PO-2: the
  variable a user set on purpose beats the stored default, the same order as
  `MANGATL_MODELS` over the bundled weights).

**C-1 `mangatl.store.settings` (extended, never duplicated).** Pure: no Qt,
no SDK. Additions to `__all__`:

- `API_KEY_SETTING: str = "gemini_api_key"`.
- `gemini_api_key(settings_file: Path) -> str | None` — the stored key, or
  `None`. `None` for: file absent; key absent, `null` or `""`; the file
  unreadable, not JSON, not an object; the value not a string. Never raises.
  A leading UTF-8 BOM is skipped (same read as `lettering_font_dir`). No
  stripping: the value is returned as stored.
  *Why `None` and not a `str` detail for "unreadable" like
  `lettering_font_dir`:* the key itself is a `str`, so a detail would be
  indistinguishable from a key. An unreadable file surfaces at the write
  instead (C-2), which is where the user is acting.
- `class SettingsUnreadable(Exception)` — the existing file cannot be parsed
  as a JSON object. Message is exactly `_unreadable(file, why)`'s
  (`"{file} could not be read: {why}"`) and **never** contains the value
  being written.
- `write_setting(settings_file: Path, key: str, value: str) -> None` —
  reads the existing object (absent file = `{}`; BOM tolerated), sets
  `key`, writes. Every other key keeps its value (`==` after `json.loads`,
  not bytes). Creates the parent directory if missing (first run: `%APPDATA%\mangatl\`
  may not exist). Serialised as `json.dumps(obj, indent=2, ensure_ascii=False) + "\n"`,
  UTF-8, no BOM. **Atomic:** written to a temp file in the *same directory*
  (`tempfile.NamedTemporaryFile(dir=settings_file.parent, delete=False)` or
  `mkstemp`), then `os.replace(temp, settings_file)` - called as
  `os.replace` through this module's `os` so a test can make it raise. If
  anything after the temp file exists raises, the temp is removed and the
  exception propagates; the original file is byte-identical to before.
  An existing file that is unreadable / not JSON / not an object raises
  `SettingsUnreadable` **and is not overwritten** - a hand-edited file the
  app cannot parse is the user's, not the app's to replace.
- `mask_key(key: str) -> str` — `"****" + key[-4:]` when `len(key) > 4`,
  else `"****"`. The only form in which a key may appear in a log line or
  message (AC-5).

**C-2 `mangatl.ui.api_key_dialog` (new).** Imports PySide6 only (no
`mangatl.app`, no SDK, no store). `__all__ = ["AI_STUDIO_URL", "ApiKeyDialog", "ask_api_key"]`.

- `AI_STUDIO_URL: str = "https://aistudio.google.com/apikey"`.
- `class ApiKeyDialog(QDialog)`, `__init__(self, parent: QWidget | None = None)`:
  - `windowTitle() == "Gemini API key"`; modal.
  - `key_field: QLineEdit`, `echoMode() == QLineEdit.EchoMode.Password`
    (AC-5 masks it), `accessibleName() == "Gemini API key"`, focus on open.
  - `link_label: QLabel` whose text contains `href="{AI_STUDIO_URL}"`,
    `openExternalLinks() is True`, `textFormat() == Qt.TextFormat.RichText`.
  - `buttons: QDialogButtonBox` with exactly `Ok` and `Cancel`; `Ok` is
    disabled while `key_field.text().strip() == ""`, enabled otherwise,
    updated on every `textChanged`.
  - an explanatory `QLabel` saying that without a key chapters can still be
    opened and reviewed but not translated (wording is GREEN's, voice.md;
    tests assert only that the dialog's visible text contains "review").
  - `key(self) -> str` — `key_field.text().strip()` (surrounding whitespace
    is a paste artefact; inner characters are not touched).
- `ask_api_key(parent: QWidget | None = None) -> str | None` — builds the
  dialog, `exec()`s it (modal at startup, before any main window exists);
  `Accepted` → `key()`, otherwise `None`.

**C-3 `mangatl.app` (extended).** New names in `__all__`: `first_run`,
`translation_env`, `ask_api_key` (re-exported import, the seam), `show_warning`.
`build_stages(models_dir: Path)` keeps its signature; its body changes.

- `translation_env(env: Mapping[str, str], settings_file: Path) -> dict[str, str]`
  — a copy of `env`; when `env.get("GEMINI_API_KEY")` is falsy and
  `gemini_api_key(settings_file)` is a non-empty `str`, the copy carries it
  as `"GEMINI_API_KEY"`. **The environment wins** when both are set (PO-2,
  AC-6). `env` is never mutated. The variable name is read from
  `mangatl.translate.provider.KEY_VARS["gemini"]`, never re-spelled.
- `build_stages(models_dir)` — `env = translation_env(os.environ, settings_path())`;
  `selection = select_provider(os.environ.get(PROVIDER_VAR) or None, env)`;
  `return build_pipeline(models_dir, translate=True, selection=selection)`.
  `select_provider` raises **before** `build_pipeline` is called, so a
  keyless Start is `NoApiKey` with no weight loaded and no project created -
  `MainWindow._start` already shows a `ProviderError` and creates nothing
  (MT-078 C-4). `settings_path` is called by `mangatl.app`'s own imported
  name, so tests rely on the `APPDATA` isolation in `tests/conftest.py`.
  **`compose` and `select_provider` are unchanged** (PO-3).
- `first_run(settings_file: Path, env: Mapping[str, str], ask: Callable[[], str | None]) -> str | None`
  — returns `None` without calling `ask` when `env.get("GEMINI_API_KEY")`
  is truthy or `gemini_api_key(settings_file)` is (AC-4). Otherwise calls
  `ask()` once: `None` (Cancel) → returns `None`, writes nothing (AC-1:
  review-only); a key → `write_setting(settings_file, API_KEY_SETTING, key)`,
  logs once at INFO on logger `"mangatl.app"`:
  `"Gemini API key saved ({mask_key(key)})"`, returns `None`. On
  `SettingsUnreadable` (or `OSError`) from the write: logs it at WARNING and
  returns `str(error)` - a message that never carries the key (AC-5).
- `show_warning(message: str) -> None` — `QMessageBox.warning(None, "Settings", message)`.
  A module-level seam tests replace.
- `main(argv)` — after `check_bundled_models()` returns `None` and **before**
  `build_window`: `problem = first_run(settings_path(), os.environ, ask_api_key)`;
  if `problem` is a `str`, `show_warning(problem)`; then `build_window` as
  before. `ask_api_key` and `show_warning` are looked up on the module at
  call time (tests `monkeypatch.setattr(app_module, "ask_api_key", ...)`).
  `--check` and the failed-weights notice path never reach `first_run`.

## Notes

**PO-1 (lead-po, 2026-10-12) — re-scoped to the Gemini key.** The user:
*"do not assume we will add an anthropic or open ai key for v1 or this
project. assume that we are proceeding just with the gemini key."* So this
story asks for **one** key, the Gemini key, and writes `gemini_api_key` -
not the Anthropic key it was written for, and not the three keys MT-078's
`## Out of scope` expected it to grow to. `architecture.md` §8 step 4 is
updated to say so. Two things the re-scope leaves for this story's own
PLANNED → RED to pin, not decided here:

1. **Settings file vs environment.** The draft above makes the environment's
   `GEMINI_API_KEY` sufficient on its own (AC-4) - the CLI and every test
   already work that way (MT-078) - and the settings file the installed app's
   source. Which one wins when both are set and differ is open; the PO pins
   it with the user before RED.
2. **Where the settings key enters selection.** `compose.build_pipeline`
   already takes `selection=` (MT-078 C-2); the window path passes `None`
   today and selects from the environment. The contract must say whether
   `app.build_stages` builds the `Selection` from the settings file or
   `select_provider` learns to read it - with MT-078's callers listed.

**PO-2 (lead-po, 2026-10-12) — the environment wins.** Put to the user at
PLANNED → RED: *"When a Gemini key is saved in the settings file AND a
different GEMINI_API_KEY is set in the environment, which should a run use?"*
Answer: **Environment wins.** Recorded as AC-6 (added while still PLANNED,
so no `## Amendments` entry). Same order as `MANGATL_MODELS` over the bundled
weights; the CLI and every existing test keep working unchanged.

**PO-3 (lead-po, 2026-10-12) — the settings key enters through `app`, not
`select_provider`.** `app.translation_env` overlays the stored key onto a copy
of the environment and `app.build_stages` passes the result to the unchanged
`select_provider`, then hands `selection=` to the unchanged `build_pipeline`
(C-3). `select_provider` stays pure over one mapping and every MT-078 caller
(`cli`, `compose._translator`, its tests) is untouched; `compose.py` and
`tests/core/test_compose.py` came out of `touches:`. The CLI does **not**
read the settings file: it is a developer's tool and the environment is its
contract (MT-078). Known edge left as-is: an environment holding
`ANTHROPIC_API_KEY` plus a stored Gemini key is `AmbiguousProvider`, the same
refusal an environment with both variables gets today.

**PO-4 (lead-po, 2026-10-12) — epic done-when check.** EPIC-07's done-when
ends "a build of the app installs and runs on a clean Windows 11 machine with
nothing preinstalled". MT-024 built the installer; the remaining gap was the
API key living only in the environment, which this story closes. No other
gap between MT-024 and this story was found against that sentence.
