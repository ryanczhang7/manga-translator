## Context

Split out of MT-024 by its PO-3 (2026-10-08). `architecture.md` §8 step 4:
"First run asks for the Anthropic API key and writes it to
`%APPDATA%\mangatl\settings.json`. That is the only setup step, and it is the
one the brief permits." Brief section 6 forbids every other kind of setup —
no environment variable, no weight placement, no GPU configuration — and
today the key is `Anthropic()`'s own environment lookup (`mangatl.compose`'s
docstring, MT-044 A-1): the installed app would need `ANTHROPIC_API_KEY` in
the user's environment, which is exactly the setup the brief forbids. This is
the gap between MT-024's installer and EPIC-07's done-when, named in MT-024
PO-3 so it is closed by a story rather than absorbed or skipped.

What already exists and must be extended, never duplicated:
`mangatl.app_paths.settings_path()` (MT-027); `mangatl.store.settings`
reads one key, `lettering_font_dir`, tolerating a UTF-8 BOM, never raising;
`mangatl.ui.intake`/`main_window` own the first window the user sees.

## Acceptance criteria

- **AC-1** — Given `settings.json` absent or without an `anthropic_api_key`,
  when the application starts, then before the intake window is usable it
  shows a dialog asking for the API key, with a link to where one is obtained
  and a Cancel that leaves the app runnable in review-only mode (no run can
  start; the Start button's error names the missing key).
- **AC-2** — Given a key entered, when the dialog is accepted, then
  `settings.json` holds `anthropic_api_key` and **every other key the file
  already had is preserved byte-for-value** — a `lettering_font_dir` the user
  set (MT-027) survives — and the file is written atomically (temp file and
  rename) so a crash mid-write cannot leave a half file.
- **AC-3** — Given a key in `settings.json`, when `build_pipeline` constructs
  the client, then it is `Anthropic(api_key=<that key>)`, never the environment
  lookup; and with no key in the file and `translate=True`, `build_pipeline`
  raises a named exception the Start sequence turns into the AC-1 error rather
  than a request-time failure on the first page.
- **AC-4** — Given a key in `settings.json`, when the application starts, then
  no dialog is shown.
- **AC-5** — Given the key is read, when it is logged, displayed or reported
  anywhere, then it is never written in full: the dialog masks it, and no log
  line or error message carries more than its last four characters.
