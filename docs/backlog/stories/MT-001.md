## Context

The first story of the project. It turns an empty repository into the stack
`docs/wiki/stack.md` describes, and — more importantly — it is where that
document's *researched, unexecuted* commands are executed for the first time.

Read `docs/wiki/stack.md` §3 (versions), §4 (layout), §6 (gates, evidence,
discovery, covers, slow, blocked-when) and **§7 (the Windows Python trap)**
before touching anything. §7 is not advisory: a bare `python` or `pytest` in a
gate command on this machine hits the Microsoft Store App Execution Alias and
exits 49 without running. Every command goes through `uv run`.

Also read `.claude/skills/stack-profiles/reference/python-uv.md` and
`.claude/skills/stack-profiles/reference/python-uv-pyside6.md`.

**Which required gate would fail if this story's artifact broke:** all of them —
this story *is* the gates. Which is exactly why AC-9 exists: a gate that has
never been observed to fail is not a gate, and a gate command that does no work
exits 0 as cheerfully as one that does.

This story runs under SCAFFOLD. That is the only phase where nothing forces a
test to exist first, which is why `## Scaffold inventory` is mandatory and why
the sizing rule below is strict.

**Sizing.** The toolchain and the gates, green on a walking skeleton, and
nothing else. No detection, no store schema, no API client, no workspace. The
`ui` package contains one window that opens and closes. Everything
project-specific is a later story with a failing test in front of it.

## Acceptance criteria

- **AC-1** — Given the scaffolded repository, when `bash scripts/gates.sh --gate lint`
  runs, then `ruff check` and `lint-imports` both execute and the gate passes.
- **AC-2** — Given the scaffolded repository, when `bash scripts/gates.sh --gate unit`
  runs, then the test runner discovers and passes at least one real example test
  in `tests/core/` and at least one `pytest-qt` test in `tests/ui/` under
  `QT_QPA_PLATFORM=offscreen`.
- **AC-3** — Given the scaffolded repository, when `bash scripts/gates.sh --gate coverage`
  and `--gate coverage-core` run, then each reports coverage and each fails when
  its configured threshold (90% and 100% respectively) is not met.
- **AC-4** — Given the scaffolded repository, when `bash scripts/gates.sh --gate build`
  runs, then PyInstaller produces a runnable one-folder artefact.
- **AC-5** — Given the scaffolded repository, when `bash scripts/task.sh dev` runs,
  then a Qt window opens.
- **AC-6** — Given `.claude/harness/project.conf`, when it is read, then every
  required gate has a command, `BOOTSTRAPPED=yes`, and every `discovery`,
  `covers`, `evidence`, `floor`, `slow` and `blocked-when` line from
  `docs/wiki/stack.md` §6 is present and corrected against what actually ran.
- **AC-7** — Given `.claude/harness/paths.conf`, when a path from this stack is
  classified, then `tests/**` and `**/conftest.py` classify as `test`,
  `pyproject.toml`, `uv.lock` and `packaging/*.spec` classify as `config`, and
  `src/mangatl/**` classifies as `source`.
- **AC-8** — Given the manifest, when `bash scripts/gates.sh --audit` runs, then
  it passes: every required gate has a command, an existing `cwd`, and an
  `evidence` line.
- **AC-9** — Each required gate has been observed to fail. Moving `tests/` aside
  makes `unit` fail; putting it back makes it pass. The same for every other
  required gate, per `## Gate probes`.
- **AC-10** — Given `docs/wiki/stack.md`, when this story ends, then its version
  table states what `uv.lock` actually locked, and the "Unverified" header has
  been replaced by a statement of what was verified and when.

## Contract

**Package layout** — exactly as `docs/wiki/stack.md` §4. Create every package
directory with an `__init__.py`, even the empty ones: MT-003's import contracts
point at them, and a contract aimed at a package that does not exist is
satisfied vacuously.

```
src/mangatl/{domain,store,detect,ocr,translate,clean,typeset,pipeline,bench,ui}/__init__.py
src/mangatl/app.py          # entry point: opens one QMainWindow, exits cleanly
tests/core/                 # at least one real test
tests/ui/                   # at least one pytest-qt test
tests/integration/          # exists, marked `gpu`/`network`, may be empty here
packaging/mangatl.spec
pyproject.toml              # deps, ruff, mypy, pytest, coverage, import-linter
uv.lock                     # committed
```

**The example tests must be real.** `test_imports` is not a test. `tests/core/`
gets one test of an actual pure function — a `domain` value type with one rule
is enough — and `tests/ui/` gets one that constructs the window, asserts its
window title and its central widget's accessible name, and closes it. AC-9's
probe has to have something to break.

**Configuration lives in `pyproject.toml`**, not in scattered dotfiles. One
place the next agent will find. The coverage thresholds live in the *gate
commands* (`--cov-fail-under`), not in config, so the number is visible where it
is enforced.

**`QT_QPA_PLATFORM=offscreen`** is set via `pytest-env` in
`[tool.pytest.ini_options]`, so an agent running `uv run pytest` by hand gets
the same behaviour as the gate. Do not set it only in the gate command.

**`.gitignore`** covers `.venv/`, `__pycache__/`, `.pytest_cache/`,
`.ruff_cache/`, `.mypy_cache/`, `dist/`, `build/`, `*.spec.bak`, and
`.claude/state/`. Adding an ignore for generated output is never a phase
violation (`rules.md`).

**Oracle partition of these criteria:** all **mechanical**. Every one is "this
command runs and produces this evidence". Pin them exactly; invent nothing. The
one place judgement is needed is AC-9's probes, and the rule there is
mechanical too: break it, watch it, paste it, revert it.

**Amendable by SCAFFOLD in place, with a reason.** Versions in
`docs/wiki/stack.md` are candidates; if `uv` resolves something different,
amend the table there and note why here. That is expected, not a failure.

## Deferred verifications

**The `ruff` liveness gap.** `docs/wiki/stack.md` §6 records it: the `lint`
evidence regex asserts that `lint-imports` did work, and asserts nothing about
whether `ruff` saw any files. `ruff check` on an empty tree prints
`All checks passed!` and exits 0 — the canonical vacuous pass.

- *Falsifiable condition:* with `src/` moved aside, the `lint` gate must fail or
  report no evidence of work. If it passes, `ruff`'s reach is unasserted and the
  gate is partly theatre.
- *Why it cannot be settled from this document:* it depends on what the
  installed `ruff` prints, which nobody here has run.
- **Owner: GATES** — this story's own GATES phase, which for a bootstrap story
  is where the gate commands are exercised. (SCAFFOLD may settle it earlier;
  GATES is the phase that owns the answer either way.) Find a `ruff` invocation
  that emits a file count (`-v`, `--statistics`, `--output-format=json`, or a
  canary rule that must fire), wire it as the `ruff-sees-src` `discovery` line,
  and paste the result here. **Deleting the requirement is not an outcome.**

## Model guidance

- **SCAFFOLD phase model: `claude-opus-5` (Claude Opus 5).** Resolved from
  `model: opus` in `.claude/agents/lead-po.md`; no session override was in
  effect for the planning dispatch that wrote this story. The Lead PO drives
  this story directly, per the bootstrap exception in `.claude/harness/rules.md`.
- **Oracle partition: entirely mechanical** (see `## Contract`). This is the
  cheapest kind of phase to run and there is no case for a stronger model. The
  case *against* a weaker one is the failure mode this harness exists to
  prevent: a weaker model reaching green by loosening a gate.
- **Success condition, falsifiable:** the story lands with every required gate
  probed, and no gate command in `project.conf` differing from
  `docs/wiki/stack.md` §6 without a recorded reason. If it lands with a probe
  described but not pasted, or with the `ruff` deferred verification quietly
  dropped, the phase failed regardless of whether the gates are green.
- **Verdict:** *to be recorded when SCAFFOLD ends.*
