## Context

The first story of the project. It turns an empty repository into the stack
`docs/wiki/stack.md` describes, and — more importantly — it is where that
document's *researched, unexecuted* commands are executed for the first time.

Read `docs/wiki/stack.md` §3 (versions), §4 (layout), §6 (gates, evidence,
discovery, covers, slow, blocked-when) and **§7 (the Windows Python trap)**
before touching anything. §7 is not advisory: a bare `python` or `pytest` in a
gate command on this machine hits the Microsoft Store App Execution Alias and
exits 49 without running. Every command goes through `uv run`.

Also read `.claude/skills/stack-profiles/reference/python-uv.md` and
`.claude/skills/stack-profiles/reference/python-uv-pyside6.md`.

**Which required gate would fail if this story's artifact broke:** all of them —
this story *is* the gates. Which is exactly why AC-9 exists: a gate that has
never been observed to fail is not a gate, and a gate command that does no work
exits 0 as cheerfully as one that does.

This story runs under SCAFFOLD. That is the only phase where nothing forces a
test to exist first, which is why `## Scaffold inventory` is mandatory and why
the sizing rule below is strict.

**Sizing.** The toolchain and the gates, green on a walking skeleton, and
nothing else. No detection, no store schema, no API client, no workspace. The
`ui` package contains one window that opens and closes. Everything
project-specific is a later story with a failing test in front of it.

## Amendments

**AC-9, amended by GATES on 2026-09-12. Approved by lead-po (this story's PO);
reported to the user in the phase report for them to overrule.**

- *What it said:* "Each required gate has been observed to fail. Moving `tests/`
  aside makes `unit` fail; putting it back makes it pass. The same for every
  other required gate, per `## Gate probes`."
- *What it says now:* the probe is a mutation applied and reverted through
  `scripts/mutate.sh`, and the `unit` probe shrinks the collected suite below its
  floor rather than moving `tests/` aside.
- *Why:* **the stated method is refused by the phase lock in the phase that owns
  it, and the replacement is strictly stronger.**

*Substance unchanged.* The criterion is "each required gate has been observed to
fail"; only the mechanism moved. Nothing was weakened and no probe was dropped —
all six required gates are probed in `## Gate probes`, and `unit` is probed twice.

**Reproduced independently before the amendment was accepted**, per
`/advance-story` ("a claim that the contract itself is wrong you reproduce
independently"). Not by re-running an agent's probe — by feeding the guard a
synthetic hook payload, so nothing moved on disk:

```
$ printf '{"tool_name":"Bash","tool_input":{"command":"mv tests tests.aside"}}' \
    | bash .claude/hooks/phase-guard.sh
{"hookSpecificOutput":{"permissionDecision":"deny","permissionDecisionReason":
 "BLOCKED by the harness phase lock.
    story:    MT-001
    phase:    GATES
    path:     tests.aside
    category: test
  Story is in GATES. Tests are frozen: ..."}}
```

`bash -c '. .claude/hooks/lib.sh; classify tests.aside'` → `test`, and GATES
permits `vendor,ignored,source,config,docs,harness`. So the move-out is denied.
Worse, the *move-back* is permitted (`classify tests` → not `test`, because the
patterns are `**/tests/**` and need a path under the directory): taking the
literal route would have moved the suite out of a tree that could not legally put
it back. There is a destination that would have slipped through — `.claude/state/`
classifies as `harness` — and choosing one to get past a denial is what law 5
calls working around the lock, so it was not used.

`rules.md` names the sanctioned alternative for exactly this case: "The one
mutation the law *requires* of a frozen file … goes through `scripts/mutate.sh`,
which restores the file and proves it did."

**Why the replacement is stronger, not a concession.** Moving `tests/` aside
makes pytest exit **5** with "no tests ran" — a crude signal any exit-code check
catches. Un-collecting one test leaves pytest at **exit 0** printing
`11 passed`, which matches the `evidence` regex `[1-9][0-9]* passed`; the gate
fails **only** because of the `floor`. That is the failure mode this story's own
`## Context` is about — "a gate command that does no work exits 0 as cheerfully
as one that does" — and the literal probe would not have exercised it.

## Contract

**Package layout** — exactly as `docs/wiki/stack.md` §4. Create every package
directory with an `__init__.py`, even the empty ones: MT-003's import contracts
point at them, and a contract aimed at a package that does not exist is
satisfied vacuously.

```
src/mangatl/{domain,store,detect,ocr,translate,clean,typeset,pipeline,bench,ui}/__init__.py
src/mangatl/app.py          # entry point: opens one QMainWindow, exits cleanly
tests/core/                 # at least one real test
tests/ui/                   # at least one pytest-qt test
tests/integration/          # exists, marked `gpu`/`network`, may be empty here
packaging/mangatl.spec
pyproject.toml              # deps, ruff, mypy, pytest, coverage, import-linter
uv.lock                     # committed
```

**The example tests must be real.** `test_imports` is not a test. `tests/core/`
gets one test of an actual pure function — a `domain` value type with one rule
is enough — and `tests/ui/` gets one that constructs the window, asserts its
window title and its central widget's accessible name, and closes it. AC-9's
probe has to have something to break.

**Configuration lives in `pyproject.toml`**, not in scattered dotfiles. One
place the next agent will find. The coverage thresholds live in the *gate
commands* (`--cov-fail-under`), not in config, so the number is visible where it
is enforced.

**`QT_QPA_PLATFORM=offscreen`** is set via `pytest-env` in
`[tool.pytest.ini_options]`, so an agent running `uv run pytest` by hand gets
the same behaviour as the gate. Do not set it only in the gate command.

**`.gitignore`** covers `.venv/`, `__pycache__/`, `.pytest_cache/`,
`.ruff_cache/`, `.mypy_cache/`, `dist/`, `build/`, `*.spec.bak`, and
`.claude/state/`. Adding an ignore for generated output is never a phase
violation (`rules.md`).

**Oracle partition of these criteria:** all **mechanical**. Every one is "this
command runs and produces this evidence". Pin them exactly; invent nothing. The
one place judgement is needed is AC-9's probes, and the rule there is
mechanical too: break it, watch it, paste it, revert it.

**Amendable by SCAFFOLD in place, with a reason.** Versions in
`docs/wiki/stack.md` are candidates; if `uv` resolves something different,
amend the table there and note why here. That is expected, not a failure.

## Deferred verifications

**The `ruff` liveness gap.** `docs/wiki/stack.md` §6 records it: the `lint`
evidence regex asserts that `lint-imports` did work, and asserts nothing about
whether `ruff` saw any files. `ruff check` on an empty tree prints
`All checks passed!` and exits 0 — the canonical vacuous pass.

- *Falsifiable condition:* with `src/` moved aside, the `lint` gate must fail or
  report no evidence of work. If it passes, `ruff`'s reach is unasserted and the
  gate is partly theatre.
- *Why it cannot be settled from this document:* it depends on what the
  installed `ruff` prints, which nobody here has run.
- **Owner: GATES** — this story's own GATES phase, which for a bootstrap story
  is where the gate commands are exercised. (SCAFFOLD may settle it earlier;
  GATES is the phase that owns the answer either way.) Find a `ruff` invocation
  that emits a file count (`-v`, `--statistics`, `--output-format=json`, or a
  canary rule that must fire), wire it as the `ruff-sees-src` `discovery` line,
  and paste the result here. **Deleting the requirement is not an outcome.**

### RESULT — run by GATES, 2026-09-12. The condition holds; the gap was real.

**Verdict: the `lint` gate does fail with `src/` moved aside, so the falsifiable
condition is satisfied — but NOT because of `ruff`.** Measured, not reasoned. The
gap the block predicted was real, and it is now closed inside the gate.

**1. The `ruff` invocation that emits a count.** `--show-files` prints the
resolved file list (SCAFFOLD's correction, PO-5). With `src/` present:

```
$ uv run ruff check --no-cache --show-files . | wc -l
17
$ uv run ruff check --no-cache --show-files . | grep -c 'src.mangatl.*[.]py'
14
```

**2. `src/` moved aside — and a first attempt that was WRONG.** The obvious
`mv src src.aside` is a confounded measurement: `src.aside` is still inside the
tree, `extend-exclude` does not cover it, so ruff walked the same 14 files under
a new name and still resolved **17**. Only the grep pattern stopped matching. Had
that run been pasted as the result it would have been evidence of nothing. Moved
instead to `.claude/state/mt001-src-aside/` (gitignored, and `.claude` is in
ruff's `extend-exclude`, so ruff cannot reach it):

```
$ uv run ruff check --no-cache --show-files . | wc -l
3
pyproject.toml
tests\core\test_money.py
tests\ui\test_main_window.py
```

**3. What each half of the gate did.** The gate failed — and the mechanism is the
finding:

```
$ uv run ruff check .                      # incidental: I001 on the TEST files
Found 2 errors.                            # exit 1
$ uv run ruff check --ignore I001 .         # the same run, coincidence suppressed
All checks passed!                          # exit 0   <-- THE VACUOUS PASS
$ uv run lint-imports
Could not find package 'mangatl' in your Python path.    # exit 1
$ uv run ruff check --no-cache --show-files . | grep -qE "src.mangatl.*[.]py"
discovery exit: 1                           # the line correctly reports no src/
```

`ruff check .` exits 1 only because with `src/` gone `mangatl` stops resolving as
first-party, so isort re-classifies it *in the test files* and I001 fires. That is
a coincidence of this project's layout. Suppress it and ruff prints
`All checks passed!` over 3 files, **0 of them under `src/`**. So ruff's own exit
code asserts nothing about its reach, exactly as the block predicted. `src/` was
restored and verified (`ls -d src` → present, 13 entries under `src/mangatl`,
`uv run python -c "import mangatl"` → `mangatl ok 0.1.0`, `git status` clean of
any `src.aside`).

**4. The gate would have passed vacuously.** Decisive, because it removes the
isort coincidence while keeping `src/` on disk: exclude `src` from ruff and run the
**old** gate command.

```
$ bash scripts/mutate.sh pyproject.toml 's/"fixtures", "\*\.md"/"fixtures", "*.md", "src"/' \
    -- bash -c 'uv run ruff check . && uv run lint-imports; echo "OLD COMMAND EXIT: $?"'
  62 - extend-exclude = [".claude", "docs", "fixtures", "*.md"]
  62 + extend-exclude = [".claude", "docs", "fixtures", "*.md", "src"]
All checks passed!
Nothing imports ui KEPT
Contracts: 1 kept, 0 broken.
OLD COMMAND EXIT: 0
=== mutate: command exited 0; restored (verified byte-for-byte ...) ===
```

**Exit 0, `Contracts: 1 kept` — matching the `evidence` regex AND the `floor` of
1 — with ruff having checked zero files of this project's source.** That is
"partly theatre", demonstrated rather than argued. Note the mutation is not
hypothetical: PO-4 edited that exact list four hours earlier.

**5. Closed inside the gate (PO-6).** The reach assertion is now part of the
`lint` gate command, not only of `doctor.sh`:

```
gate | lint | required | . | uv run ruff check . && uv run ruff check --no-cache --show-files . | grep -qE "src.mangatl.*[.]py" && uv run lint-imports
```

Probed — the same mutation now fails the gate, where before it passed:

```
$ bash scripts/mutate.sh pyproject.toml 's/"fixtures", "\*\.md"/"fixtures", "*.md", "src"/' \
    -- bash scripts/gates.sh --gate lint
FAIL         lint (0s, exit 1) -> .claude/state/gate-logs/lint.log
--- gate log: "All checks passed!" and nothing else: ruff was happy, the
    reach assertion is what caught it ---
```

**The requirement was not deleted, and the `discovery` line was kept.** `doctor.sh`
still carries `ruff-sees-src`; the gate now carries it too, because `doctor.sh`
does not run in CI and the gates do.

## Test plan

Written under SCAFFOLD, which is the one phase where nothing forces a test to
exist before the code. Twelve tests, all real, none of them `test_imports`.

**`tests/core/test_money.py` — 7 tests, the pure half.** `Usd` is a frozen
dataclass carrying one rule: *spend is never negative*. The tests pin the rule in
both directions (a positive amount is kept **exactly**, zero is accepted, a
negative one raises and the message names the offending amount), the ordering and
equality that make it usable in a ledger, and `__str__` at **four** decimal
places rather than two — a single page's API cost is a fraction of a cent, and a
ledger that rounds each entry to two places sums to the wrong total. This is the
file `coverage-core` holds at 100%.

**`tests/ui/test_main_window.py` — 5 tests, the Qt half, under `pytest-qt`.**
Three construct `MainWindow` through `qtbot` and assert the three things the
contract names: the window title, the central widget's **accessible name**, and
that `close()` both returns true and leaves the window not visible. Two cover
`app.main()` by substituting a `_FakeQApplication` for `QApplication` — a real
`app.exec()` blocks forever and only one `QApplication` may exist per process,
which `qtbot` has already made. They assert that `main` returns the Qt exit code
it was given and that it falls back to `sys.argv` when called with no arguments;
between them they close the `argv is None` branch under branch coverage.

**What makes these admissible to the gates rather than merely green:**
`QT_QPA_PLATFORM=offscreen` is set through `pytest-env` in
`[tool.pytest.ini_options]`, not in the gate command, so `uv run pytest` by hand
behaves exactly like the gate. Measured 2026-09-12: `unit` 0.8 s plain,
`coverage` 1.5 s instrumented — far enough under any timeout that the CI-hardware
multiplier this harness warns about has nothing to bite.

**`tests/integration/` is deliberately empty** and carries a README saying why.
The gate over it exits 5 and is waived until MT-002. The directory exists now
rather than later because the adapter split in `architecture.md` §2 is
load-bearing: a story that finds no `tests/integration/` puts its smoke test in
`tests/core/` against the fake session, and the fake quietly becomes the only
thing anyone tests.

### A vacuity finding these probes turned up, filed rather than fixed

Two of the three window tests assert against the **imported constant**, not a
literal:

```python
from mangatl.ui.main_window import CANVAS_ACCESSIBLE_NAME, WINDOW_TITLE
assert window.windowTitle() == WINDOW_TITLE
assert central.accessibleName() == CANVAS_ACCESSIBLE_NAME
```

So mutating `WINDOW_TITLE = "mangatl"` to any other string **fails nothing** —
which is why the `unit` probes above break the money rule instead. This is not
a defect: the assertions pin the *wiring* (that `setWindowTitle` was called with
that constant, and that a central widget exists at all), and they do catch
`setWindowTitle("")` or a missing `setCentralWidget`. They do not pin the
**values**, and nothing in this story's contract says they must — the title string
is not a stated requirement anywhere, and inlining a literal in a test to pin a
constant one line away from it is its own anti-pattern. Recorded here so the next
agent knows it was noticed and decided, not missed. **MT-025/MT-026 own the design
tokens and the accessibility floor**; if either makes the strings contractual, the
assertion to add is a literal in *that* story.

### PO-4 — ruff 0.16 formats Markdown, and the plan did not know that

**Measured 2026-09-12.** `uv run ruff format --check .` reported **115 files**
against a tree holding 16 Python files. ruff 0.16.7 formats Python code blocks
inside **Markdown**, and 98 of those 115 were `.claude/**/*.md` and
`docs/**/*.md` — the vendored harness and the wiki.

Two consequences, neither of them hypothetical:

1. `uv run ruff format .` — the obvious thing to type after a `format` WARN —
   rewrites harness documentation. `check-boundaries.sh` refuses a harness change
   without a `VERSION` bump, so that lands as a confusing CI failure in a story
   that never meant to touch the harness.
2. The `format` gate's file count, and therefore any floor on it, would move
   whenever anyone edited a Markdown file.

`pyproject.toml` now carries `extend-exclude = [".claude", "docs", "fixtures",
"*.md"]`. The count is a stable **16** and the gate means "this project's Python
is formatted", which is what `stack.md` §6 intended. This is not a narrowing to
make a gate pass: nothing was failing. It is a scoping of a tool that reaches
further in 0.16 than it did in 0.12.

### PO-5 — what the `providers`, `ruff-sees-src` and workflow findings cost

Three of `stack.md` §6's researched commands did not survive contact:

1. **`ruff-sees-src` never matches.** Proposed as
   `uv run ruff check --no-cache -v . 2>&1 | grep -qE "[Cc]hecked [1-9][0-9]* files"`.
   ruff 0.16.7 prints no such line — `-v` emits one `Included path via 'include'`
   DEBUG line per file with no total, and `--statistics` prints nothing at all on
   a clean run. Corrected to `--show-files` + a grep for `src.mangatl`, which
   asserts the same thing without depending on a summary line surviving a ruff
   release. Observed: 14 files. **The requirement was not deleted** — the story's
   `## Deferred verifications` block still owns the experiment that proves the
   *gate* (not just the discovery line) notices a missing `src/`, and GATES runs
   it.
2. **The `integration` gate exits 5, not 0, over an empty directory.** Waived,
   with MT-002 named as the story that removes the waiver.
3. **A `uv sync` step in `gates.yml` breaks the harness self-test.**
   `.claude/tests/ci-local.test.sh` derives `ci-local.sh`'s step list from the
   `run:` lines in the workflows, and `ci-local.sh` runs those steps inside bare
   fixtures that have no `pyproject.toml`. Adding `uv sync --all-extras --frozen`
   as a step turned one green self-test suite red. Resolved by **not** adding the
   step: every gate command begins `uv run`, which installs the locked
   environment on first use, and a job-level `UV_FROZEN: "1"` gives more than the
   step would have — it applies to *every* `uv run` in the job, so a `uv.lock`
   out of step with `pyproject.toml` fails on CI rather than being silently
   re-resolved. Verified locally: `UV_FROZEN=1 uv run python -c "import mangatl"`
   succeeds.
