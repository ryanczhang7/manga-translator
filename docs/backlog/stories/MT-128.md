**The gap, one line each** (line numbers at `12108c9`):

- **W01** - `workspace.py:1422`, `_rerun`'s `or self.render_button.property("loading")`.
  Replaced with `or False`, all 1,926 tests in `tests/ui` pass. During a
  render's bake Run again is enabled, so this guard alone stops a run starting
  on the project the bake is reading.
- **W03** - `workspace.py:1344`, `_render_pages`'s `or self.run is not None`.
  Removed, all of `tests/ui` passes. `Workspace.render()` is the contract's
  public command (MT-066 C-4) and reaches `_render_pages` whatever the button
  says.
- **W02** - `workspace.py:1421`, `_rerun`'s `or self.run is not None`. Removed,
  all of `tests/ui` passes. Run again is disabled during a run, so tests only
  ever reach it through a disabled button; a `clicked` emission reaches it
  regardless.
- **W26** - `workspace.py:1420`, `_rerun`'s `or self._project is None`. Removed,
  all of `tests/ui` passes. No test presses Run again before `load_chapter`.

No required gate fails if this story's tests are absent: these are assertion
gaps under full line coverage. **Not in this story:** disabling Run again
during a render (that is a behaviour change and a design question, not a test
gap); any change to `workspace.py`.

  loaded, and a render step in flight (the "Render pages" button in its

## Test plan

One new file, `tests/ui/test_rerun_guards.py`: UI integration tests (pytest-qt,
offscreen), the cheapest level at which a real click reaches `Workspace._rerun` /
`Workspace.render()` with the real `BakeController` and `RunController` behind
them. Fixtures are copied (not imported) from `test_rerun_workspace.py`
(`chapter`, `Setup`, `Gate`, `FakeStage`, `World`) and `test_bake_render.py`
(`Step`).

**How each state is set up.**

- *Render step in flight (AC-1):* `preview_bake` and `bake_chapter` are replaced
  at their seam in `mangatl.ui.bake` by `Step` fakes; preview answers at once
  with one unreviewed line, `bake_chapter` blocks on an event (at most
  `GATE_S`). The test clicks Render pages, waits for the `BakeConfirmDialog`,
  clicks its confirm and waits until the bake fake is entered - so the loading
  state is exactly the one `_on_bake_dialog_finished` leaves while a bake runs
  (a real bake on a real, gated `BakeController`, the Contract's first option).
  The control clears it the same way: releases the bake and waits for
  `loading is False` (`_end_render`).
- *Run in progress (AC-2, AC-3):* Run again -> its `RerunDialog` -> `run_button`,
  over `FakeStage("detect", gate)` that blocks on page 3 (ordinal 2) until
  released; the test waits for the gate to be entered.
- *No chapter (AC-4):* `Workspace(run_setup=...)` shown, `load_chapter` never
  called.
- `workspace_module.BakeController` is wrapped by a recorder that still builds
  the real controller (AC-2's synchronous needle).
- The `world` fixture releases every gate and bake fake, waits (bounded) for
  each fake to go idle, cancels and waits for every run, closes any dialog left
  open, then closes every window. Windows are deliberately NOT registered with
  `qtbot.addWidget` (pytest-qt closes those before fixture teardown, and
  `closeEvent` would wait out the held bake/run's `GATE_S` - observed: 10 s
  teardowns on three tests before the change, 0.0x s after).
