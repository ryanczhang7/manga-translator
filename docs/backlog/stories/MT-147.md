## Context

EPIC-13 priority 2. The user decided (U-4) that the model marks art text. On
the benchmark, **30 regions on 13 pages** were drawn sound effects or signs.
They were proposed, some translated ("WEE-WOO", "gachi gachi (rattle
rattle)"), and set over the art. p016's drawn sign was typeset as "Emergency
Entrance" over leftover Japanese. `product-brief.md` §5 says art text is left
completely untouched in v1. The detector cannot tell it apart (MT-117 D-1),
and OCR reads hallucinations confidently. The translate call already sends
the page image, and the model can see what is drawn.

So the answer gains one non-index key, `art_text`: the indices the model
judges to be text drawn into the art rather than lettered dialogue,
narration or captions. The stage excludes those regions with reason `art`
(MT-146) and writes no proposal for them. Bake already puts the source back
over an excluded region's erased area (MT-119), so the art comes back as
drawn even though the cleaner, which runs before translation, erased it.

This is a v1 *refusal* to touch art text. It is not EPIC-12's v2 finding
step, which may reuse it (EPIC-12 Q-3).

Required gates: `unit`, `coverage`, `coverage-core`.

## Acceptance criteria

- **AC-1** - `response_schema(n)` has a property `art_text`: an array of
  integers from 0 to `n - 1`, with unique items. It is not required, and
  `additionalProperties` is still `false`. `SYSTEM_PROMPT` tells the model to
  list there any region whose text is drawn into the artwork (sound effects,
  signs, labels on objects) and to give it no translation, and says that
  dialogue, narration and captions are never art text.
- **AC-2** - `parse_art_text_text(text, region_indices)` returns the set of
  listed indices, and `frozenset()` when the key is absent. An index
  outside `region_indices`, or one that is not an integer, raises
  `UnknownRegionIndex` naming it, as a line key does.
- **AC-3** - Given a fake translator whose answer for a four-region page
  lines regions 0, 1 and 3 and lists `art_text: [1, 2]`, when `TranslateStage.run`
  runs, then:
  - regions 1 and 2 are stored `excluded == "art"` with `proposed_en`
    `NULL`. Region 1's line is discarded: art wins.
  - regions 0 and 3 carry their proposals.
- **AC-4** - Given a page where region 0 was excluded by the user before the
  run, and the answer (over the *sent* listing) marks its index 0 as art,
  when the stage runs, then the region that index maps to through `included`
  is the one marked `art`. The user's region stays `user`. *(The
  MT-118 mapping, exercised for the new key.)*
- **AC-5** - Given a collected batch result carrying `art_text`, when
  `pipeline.batch` writes it, then the same regions are excluded `art` as in
  AC-3. Both paths share one helper, and no second copy of the rule exists.
- **AC-6** - *(end to end, headless)* Given the fixture chapter with a
  detector double, a cleaner double that paints regions white, and a
  translator double marking one region art, when the chapter runs and is
  baked, then that region's pixels in the baked page equal the source scan's
  (MT-119's restore). No glyph is typeset there.
- **AC-7** - The Claude, Gemini and Gemini batch adapters each return
  `TranslationResult.art_text` from their response, through
  `parse_art_text_text`.

### C-1 Names

```python
# translate/page_prompt.py
ART_KEY: str = "art_text"        # beside GLOSSARY_KEY; never a reading index
# translate/parse.py
def parse_art_text_text(text: str, region_indices: Sequence[int]) -> frozenset[int]
def parse_art_text(response: Message, region_indices: Sequence[int]) -> frozenset[int]
# parse_lines_text skips ART_KEY exactly as it skips GLOSSARY_KEY
# domain/translation.py
TranslationResult.art_text: frozenset[int] = frozenset()   # LAST, defaulted
```

`TranslationResult` gains a defaulted last field, so every positional
construction site keeps working (the `RawRegion.merged_from` precedent).

### C-2 The write

One helper in `pipeline/translate_stage.py`, imported by `pipeline/batch.py`:
`apply_answer(project, ordinal, result, included)`. It maps `art_text` and
`lines` through `included` (the existing `_to_reading_indices` rule). It sets
`excluded="art"` on each art region, drops any line for an art region, then
calls `write_proposed`. It opens no transaction (the stage's existing rule),
and marks the art before it writes the proposals.

### C-3 Callers

`parse_lines_text` is unchanged in signature. Its behaviour changes only by
skipping `ART_KEY`. Its callers are `translate/gemini.py:186`,
`translate/gemini_batch.py:221` and `translate/parse.py` (`parse_lines`).
`parse_lines` is called by `translate/client.py:92`. RED's handoff confirms
the list with `rg -n "parse_lines" src tests`. `write_proposed`'s callers,
`translate_stage.py:280` and `batch.py:396`, both move to `apply_answer`.

### C-4 Oracle partition

AC-1 to AC-7 are **mechanical**. Whether the model actually marks the right
regions is **oracle-free**, and is measured, not tested (DV-2).
