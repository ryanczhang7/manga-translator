## Context

EPIC-13 priority 2. The user decided (U-4) that the model marks art text. On
the benchmark, **30 regions on 13 pages** were drawn sound effects or signs.
They were proposed, some translated ("WEE-WOO", "gachi gachi (rattle
rattle)"), and set over the art. p016's drawn sign was typeset as "Emergency
Entrance" over leftover Japanese. `product-brief.md` §5 says art text is left
completely untouched in v1. The detector cannot tell it apart (MT-117 D-1),
and OCR reads hallucinations confidently. The translate call already sends
the page image, and the model can see what is drawn.

So the answer gains one non-index key, `art_text`: the indices the model
judges to be text drawn into the art rather than lettered dialogue,
narration or captions. The stage excludes those regions with reason `art`
(MT-146) and writes no proposal for them. Bake already puts the source back
over an excluded region's erased area (MT-119), so the art comes back as
drawn even though the cleaner, which runs before translation, erased it.

This is a v1 *refusal* to touch art text. It is not EPIC-12's v2 finding
step, which may reuse it (EPIC-12 Q-3).

Required gates: `unit`, `coverage`, `coverage-core`. Every test this story
writes is under `tests/core`, which all three run, AC-6's included; nothing
here rests on an `optional` gate, so `required_gates` stays empty.

## Acceptance criteria

- **AC-1** - For `n >= 1`, `response_schema(n)` has a property `art_text`: an
  array whose items are integers restricted to the reading indices `0` to
  `n - 1`. It is not required, and `additionalProperties` is still `false`.
  `response_schema(0)` has no properties. `SYSTEM_PROMPT` tells the model to
  list there any region whose text is drawn into the artwork (sound effects,
  signs, labels on objects) and to give it no translation, and says that
  dialogue, narration and captions are never art text.
- **AC-2** - `parse_art_text_text(text, region_indices)` returns the set of
  listed indices, and `frozenset()` when the key is absent. An index
  outside `region_indices`, or one that is not an integer, raises
  `UnknownRegionIndex` naming it, as a line key does.
- **AC-3** - Given a fake translator whose answer for a four-region page
  lines regions 0, 1 and 3 and lists `art_text: [1, 2]`, when `TranslateStage.run`
  runs, then:
  - regions 1 and 2 are stored `excluded == "art"` with `proposed_en`
    `NULL`. Region 1's line is discarded: art wins.
  - regions 0 and 3 carry their proposals.
- **AC-4** - Given a page where region 0 was excluded by the user before the
  run, and the answer (over the *sent* listing) marks its index 0 as art,
  when the stage runs, then the region that index maps to through `included`
  is the one marked `art`. The user's region stays `user`. *(The
  MT-118 mapping, exercised for the new key.)*
- **AC-5** - Given a collected batch result carrying `art_text`, when
  `pipeline.batch` writes it, then the same regions are excluded `art` as in
  AC-3. Both paths share one helper, and no second copy of the rule exists.
- **AC-6** - *(end to end, headless)* Given a chapter with a detector
  double, a cleaner double that paints each handed region's mask pixels
  white, and a translator double marking one region art, when the chapter
  runs and is baked, then every pixel inside that region's polygon in the
  baked page equals the source scan's (MT-119's restore). No glyph is
  typeset there.
  *Control:* the same run with the translator marking nothing leaves that
  region's mask pixels white in the baked page, so the equality is about the
  exclusion and not about the page.
- **AC-7** - The Claude, Gemini and Gemini batch adapters each return
  `TranslationResult.art_text` from their response, through
  `parse_art_text_text`.

### C-1 Names and signatures

```python
# translate/page_prompt.py   (add "ART_KEY" to __all__)
ART_KEY: str = "art_text"        # beside GLOSSARY_KEY; never a reading index

# translate/parse.py   (add both to __all__; re-export ART_KEY as GLOSSARY_KEY is)
def parse_art_text_text(text: str, region_indices: Sequence[int]) -> frozenset[int]
def parse_art_text(response: Message, region_indices: Sequence[int]) -> frozenset[int]
#   parse_art_text is parse_art_text_text(first_text_block(response), region_indices),
#   as parse_lines is to parse_lines_text.
#   parse_lines_text skips ART_KEY exactly as it skips GLOSSARY_KEY: the exact
#   key, checked before the int() conversion, value never inspected.

# domain/translation.py
TranslationResult.art_text: frozenset[int] = frozenset()
#   the LAST field, after `misaligned`, and defaulted like it.
#   Field order becomes: lines, usage, call, proposed_terms, misaligned, art_text.

# pipeline/translate_stage.py   (add "apply_answer" to __all__)
def apply_answer(
```

### C-2 The schema and the prompt (AC-1)

`response_schema(n)` for `n >= 1` adds one property beside the indices:

```python
ART_KEY: {
    "type": "array",
    "description": "Reading indices of regions whose text is drawn into the artwork.",
    "items": {"type": "integer", "enum": list(range(n))},
}
```

- **The range is an `enum` on the items, not `minimum`/`maximum`, and there
  is no `uniqueItems`** (PO-1). One schema goes to both providers as-is
  (`translate/prompt.py:105`, `translate/gemini.py:150`). Claude's structured
  outputs document `minimum`, `maximum` and complex array constraints as
  unsupported, and `enum` as supported. A repeated index costs nothing: the
  parser returns a set.
- **`response_schema(0)` is unchanged: `properties == {}`.** An `enum` of no
  values is not a valid schema, no call is made for a page with no regions,
  and `tests/core/test_page_prompt.py:480` already pins the empty case.
- Still no top-level `required`, and `additionalProperties` is still `False`.
  The index properties are untouched.

`SYSTEM_PROMPT` gains **one bullet**, inserted directly after the bullet that
begins `- In "en", write the English` and before the blank line above
`Continuity across pages:`. No other character of the prompt changes, so the
golden in `tests/core/test_page_prompt.py` is derived by one insertion, as
MT-149's was by one replacement:

```
- The one exception to translating every region is text drawn into the \
artwork itself: sound effects, signs, labels on objects. List the reading \
index of each such region under the "art_text" key and give that region no \
entry and no translation. Dialogue, narration and captions are never art \
text, however they are lettered.
```

(Shown as it sits in the source: each trailing backslash is the line
continuation the existing bullets use, so the bullet is one line of text.)

The prompt is the stable prefix every page re-reads. The bullet names no
page, so it stays cacheable. `domain/budget.py`'s page estimate is **not**
changed by this story: the list is a handful of integers against MT-149's 500
echoed tokens.

### C-3 The parser (AC-2)

`parse_art_text_text(text, region_indices)`:

| The body's `art_text` | Result |
|---|---|
| key absent | `frozenset()` |
| `[]` | `frozenset()` |
| `[1, 2]`, both in `region_indices` | `frozenset({1, 2})` |
| `[1, 1]` | `frozenset({1})` |
| an item outside `region_indices`, negative included | `UnknownRegionIndex` naming the item |
| an item that is not an `int` (`"1"`, `1.0`, `null`, a list) | `UnknownRegionIndex` naming the item |
| an item that is `true` or `false` | `UnknownRegionIndex` naming it: a `bool` is an `int` to `isinstance`, and `true` must not become region 1 |
| a value that is not a list (`null`, `"1"`, `3`, an object) | `UnknownRegionIndex` naming `art_text` and the value |

- It reads only `ART_KEY`. Line keys are `parse_lines_text`'s, and a bad line
  key in the same body is not this function's to raise.
- It reuses `_body` and `_unknown`, so the message has the shape a line key's
  has: the offending value by `repr`, then the page's sorted indices.
- A body that is not JSON raises out of `json.loads`, as `parse_lines_text`
  does.
- **Strict, where a malformed line entry is lenient** (MT-149 PO-4 parses it
  to `None`). The reason is the direction of the error: a dropped art index
  typesets English over drawn art with nothing flagged, while a failed page is
  seen and re-run. AC-2 fixes the two item cases; the non-list row is this
  block's, and RED may amend it.

### C-5 The write (AC-3, AC-4, AC-5)

`apply_answer(project, ordinal, result, included)` is the only place the rule
lives. In order:

1. **Map.** `result.lines`, `result.misaligned` and `result.art_text` are
   each mapped through `included` by `_to_reading_indices`' rule
   (`included[k]` is the reading index of the `k`-th region sent). A key
   outside the listing, in any of the three, raises `ValueError` naming it,
   **before anything is written**. `_to_reading_indices` keeps its signature
   and its `(proposals, misaligned)` return; how the art set shares its
   bounds check is GREEN's choice.
2. **Art wins.** A reading index in the art set is removed from the proposals
   **and** from the misaligned set. AC-3 says it for a line. The misaligned
   half is the same rule: an art region is no failed translation, and it must
   not read `failed` if the user restores it.
3. **Mark.** For each art index, ascending, whose stored region has
   `excluded is None`: `project.set_excluded(ordinal, index, "art")`. A
   region already excluded keeps its reason (PO-2), and its line stays
   dropped. The stage never sends an excluded region, so this arm is reached
   only from the batch path, which sends every region.
4. **Write.** `project.write_proposed(ordinal, proposals, misaligned)`.

- **Marks before proposals.** Each `set_excluded` and the `write_proposed`
  open their own transaction, and `apply_answer` opens none (`translate_stage`
  module docstring; `Project.transaction()` is not reentrant). A crash between
  them leaves art marked and no proposals, so the page is translated again
  with the art regions already excluded. The other order leaves a page that
  reads done with its art typeset.
- **Callers.** `TranslateStage.run` replaces its last two lines
  (`translate_stage.py:288-289`) with `apply_answer(ctx.project,
  ctx.page.ordinal, result, included)`; the bill, `CallPriced` and the
  glossary stay where they are, before it. `pipeline/batch.py` `_write_page`
  replaces line 397 with `apply_answer(project, n, result,
  range(len(project.read_regions(n))))`: a batch answer is keyed by reading
  index already (its PO-2), so the mapping is the identity. `batch.py` imports
  `apply_answer` beside `budget_for` (line 107).
- **"No second copy" (AC-5), as a test reads it:** `_write_page` reaches the
  store through `apply_answer` (a recorder in its place sees the call), and
  `pipeline/batch.py`'s source contains no call to `set_excluded` and none to
  `write_proposed`.
- **Stated consequences, not criteria.** A page whose every region is art has
  no proposal, so `TranslateStage.is_done` stays false and a later run enters
  the stage again; all its regions are excluded by then, the translator is
  handed `()` and makes no call. `write_proposed` never clears, so a region
  that carried a proposal from an earlier run and is now marked art keeps
  that text in the store; it is excluded, so it is neither shown as a
  proposal nor baked. AC-3's `NULL` is the fresh-page case.

### C-6 The end-to-end test (AC-6)

`tests/core/test_art_text_bake.py`, run by `unit`, `coverage` and
`coverage-core`. It builds the stage list with `pipeline.stages.build_stages`
from doubles (the shape `tests/core/test_stages.py` uses), runs the chapter,
then calls `pipeline.bake.bake_chapter`.

- The source page is textured, so "equals the source" and "is white" are
  different observations (`tests/core/_bake_world.py` does the same).
- The cleaner double paints only each handed region's **mask** pixels. Bake's
  restore pastes the source over the region's erase mask, which contains the
  mask; a double that whitened the whole polygon would leave white the
  restore never claims to cover.
- The art region sits clear of every other region, further apart than the
  erase mask's growth and dilation, so no included region's mask reaches it.
- At least one other region carries a proposal and is typeset, so the page
  is really baked and not copied.
