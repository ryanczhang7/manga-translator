## Acceptance criteria

*Revised in PLANNED on 2026-09-15 by lead-po, before the story left PLANNED and
before the branch existed, on the measurements in `## Notes` PO-1/PO-2/PO-3.
Landed on `main` first so the base branch carries them: `check-boundaries.sh`

- **AC-1** — Given a fake session returning a known probability map and a known
  box list, when detection post-processing runs, then it produces one region per
  connected component above the threshold **that lies inside an accepted box**,
  each with a polygon and a 1-bit mask of the same dimensions as the page.
- **AC-2** — Given a probability map with a component of area below
  `MIN_REGION_AREA_PX`, when post-processing runs, then that component produces
  no region.
- **AC-3** — Given a probability map with two components whose masks overlap,
  when post-processing runs, then two regions are produced and each region's
  mask contains only its own pixels.
- **AC-4** — Given a page, when detection runs, then every returned region's
  polygon lies entirely within the page bounds and every mask pixel outside the
  polygon's bounding box is zero.
- **AC-5** — Given a region, when its mask is stored and read back through
  MT-005's store, then it is bit-identical.
- **AC-6** — Given a fixture whose probability map carries a text blob covered
  by an accepted box and a separate SFX blob covered by **no** box, when
  post-processing runs with the shipped configuration, then **no region overlaps
  any pixel of the annotated SFX area**, at every threshold in the swept range
  and every dilation setting.
  *Control:* the same fixture with the SFX blob's rectangle added to the box
  list must produce a region there — otherwise the assertion is passing because
  the detector finds nothing at all. The control must fire by a wide margin, and
  RED records both numbers.
- **AC-7** — *(integration)* Given the real detector model and a real page
  fixture, when the session loads and runs, then the **provider actually
  selected** is reported from `session.get_providers()`, the graph returns `blk`,
  `seg` and `det` of the expected shapes and dtype, post-processing yields at
  least one region, and the decoded box head covers **0.000** of each of the six
  annotated SFX rectangles on `012.jpg`.
- **AC-8** — *(integration)* Given the real detector model and `014.jpg`, when
  detection runs, then **every one of the nine frozen reference boxes** in
  `spikes/MT-030/out/w2-reference-014.json` is overlapped by at least one
  returned region's mask.

### C-1 — the session is a thin ONNX wrapper and owns no arithmetic

```python
# src/mangatl/detect/session.py
MODEL_INPUT_SIDE: int = 1024
PAD_VALUE: int = 114                 # grey letterbox padding

@dataclass(frozen=True)
class RawDetectorOutput:
    blk: NDArray[np.float32]         # (1, 64512, 7)  cx cy w h obj cls0 cls1, canvas coords
    seg: NDArray[np.float32]         # (1, 1, 1024, 1024) in [0, 1]

class DetectorSession(Protocol):
    def run(self, canvas: NDArray[np.float32]) -> RawDetectorOutput: ...
        # canvas: (1, 3, 1024, 1024) float32, RGB, already divided by 255

def load_detector(model_path: Path, providers: Sequence[str]) -> DetectorSession
def selected_provider(session: DetectorSession) -> str
```

**Everything that is arithmetic lives in `postprocess`, not here**, because this
module is only ever exercised by `integration`, which never runs on CI. A
letterbox or a decode written in this file is a letterbox no required gate reads.

`selected_provider` reads `session.get_providers()[0]`. **Never
`get_available_providers()`** — MT-002 E2/PO-3 measured that it advertises CUDA
identically whether or not the DLLs loaded, and that requesting CUDA does not
raise when it silently falls back to CPU. `get_providers()` is the honest one.

`load_detector` calls `ort.preload_dlls(cuda=True, cudnn=True, msvc=True)` before
constructing the first `InferenceSession`. This is mandatory, not tuning: without
it every model runs on CPU on this machine (578 ms vs 23 ms), failing without
raising. Re-verify it rather than assuming it.

### C-3 — `regions_from_detection` REPLACES `regions_from_probability`, and this is the story's one real design change

The signature this story was planned with —
`regions_from_probability(prob, page_size)` — **cannot satisfy AC-6**, and that
is measured, not argued. See `## Notes` PO-1 for the numbers and the command that
produced them. The short form: the incumbent's `seg` head covers 27–59% of every
annotated SFX area at *every* threshold from 0.10 to 0.999, and the box head
covers exactly 0.000 of all six. The SFX exclusion is a property of the **box
head**, so a function that cannot see the boxes cannot implement it.

`boxes` is therefore a parameter, not an implementation detail.

### C-4 — the order of operations, each step of which has a measured reason

1. **Letterbox** the page into 1024², grey 114, aspect preserved.
2. **Resize the probability map to page size, THEN threshold.** Not the other way
   round. MT-030 E4 measured both orderings: resize-then-threshold gives recall
   0.9658 / IoU 0.5657, threshold-then-resize gives 0.9492 / 0.5847. The first is
   correct for a probability map; nearest-neighbour on a thresholded mask
   discards sub-pixel evidence.
3. **Threshold** at `MASK_THRESHOLD`.
4. **Intersect with the accepted boxes.**
5. **Dilate** by `DILATE_ITERATIONS` of a 7×7 kernel.
6. **Intersect with the accepted boxes AGAIN.** The boxes are a fence, not a
   filter applied once. A dilation after the only intersection walks the mask
   back out over the SFX and silently breaks AC-6.
7. **Connected components**, discarding those below `MIN_REGION_AREA_PX`.
8. **Polygon and mask** per surviving component, in page pixel coordinates.

Step 5 is why the epic's bubble-level region count exists at all: on `012.jpg`
the same page yields 64 components at dilation 0 and **8** at dilation 2, against
6 boxes. MT-030's escalation E-1 records that "a bubble-level region count only
exists after refinement"; step 5 is that refinement.

### C-5 — `MASK_THRESHOLD`: what it means and what settles it

The probability above which a pixel is text. Raising it loses faint text;
lowering it bleeds into screentone. **Not settled here** — GREEN measures it on
the fixture set and records the measurement and both failure directions in
`## Notes`.

Two measurements it may read out rather than re-derive, both reproduced by the
orchestrator on 2026-09-15:

- the incumbent's peak IoU against the author's reference mask is **0.714–0.753
  at threshold ≈0.77–0.81**, not the upstream default of 0.3;
- that reference is the author's *refined* mask, so the right operating point for
  a raw map feeding this story's own refinement is **not** necessarily the peak.

It is a number a later story may read out. It is a number this story must derive.

### C-6 — `MIN_REGION_AREA_PX`: a speckle floor, not a size filter

It exists to discard speckle, **not to discard small bubbles**. A single-kana
bubble is legitimate and must survive. The floor is sized below the smallest
annotated region in the fixture set, and the fixture that pins it is named in
`## Notes`.

Measured on `012.jpg` inside accepted boxes at threshold 0.5: component areas
min 2, p10 44, median 254, max 1372, n=73. Upstream uses 20. That is a starting
point to be re-derived against the single-kana fixture, not a value to adopt.

### C-7 — the region type stays free of numpy

```python
# src/mangatl/domain/region.py
@dataclass(frozen=True)
class RawRegion:
    polygon: tuple[tuple[int, int], ...]   # page pixel coords, closed
    mask: bytes                            # PNG-encoded 1-bit, page-sized
    confidence: float                      # MEAN probability inside the mask
    kind: Literal["bubble", "box"]
```

`domain` may import the standard library and nothing else of ours — **and not
`numpy`, `PIL`, `PySide6`, `onnxruntime` or `anthropic`** (architecture.md §3,
contract 2, enforced by the `lint` gate). `mask` is therefore `bytes`, and the
encoding happens in `detect`.

`confidence` is the **mean** probability inside the mask, not the max. The max is
1.0 for almost every region and carries no information — the `seg` head's
measured range on `012.jpg` is exactly [0.0, 1.0].

`coverage-core` demands **100%** of `src/mangatl/domain/**`. Every branch of this
module, validation included, needs a test.

**Settled by the user on 2026-09-15** (`## Notes` PO-2). The story was planned

is a property of the model, not of this code, and it is asserted by AC-7 against

exercises the real model, and that is the deliberate trade.

**Write down which fixture came from where.** MT-002 and MT-030 both carry a
`## Fixtures, and their provenance` section; the same discipline applies to

- *Falsifiable condition:* with step 6 removed — dilation left as the last
  operation — AC-6 **must** fail. If it still passes, either the dilation is not

  boxed blob, and the fixture is wrong.

- **Owner: GATES.**

- *Falsifiable condition:* with `confidence` computed as the **max** rather than

  maxes are not all 1.0, C-7's stated reason is wrong and should be corrected.
- *Why RED cannot run it:* needs the real probability map through the real
  implementation.
- **Owner: GATES.**

#### PO-1 — the `## Contract` made AC-6 unsatisfiable, and the contract changed, not the criterion

The story was planned with
`regions_from_probability(prob: NDArray, page_size) -> list[RawRegion]`. That
signature cannot see the box head, and the box head is the **only** thing that
discharges AC-6.

Independently reproduced by the orchestrator — own letterbox, own YOLO decode,
own greedy NMS, not MT-030's code — on `spikes/MT-002/pages/012.jpg` against the
real `comic-text-detector.onnx` on `CUDAExecutionProvider`:

```

  0.100         75   13860         6      0.355   2.90%
  0.300         78   12254         6      0.309   2.48%

  0.772         87    9805         6      0.230   1.82%
```
