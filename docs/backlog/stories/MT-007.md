Brief feature 2, and the story the brief's S2 metric attaches to. It also sets
the boundary that enforces the brief's firmest non-goal: **art-integrated sound
effects are never touched**, and that is a property of what this detector is

## Acceptance criteria

*Revised in PLANNED on 2026-09-15 by lead-po, before the story left PLANNED and
before the branch existed, on the measurements in `## Notes` PO-1/PO-2/PO-3.
Landed on `main` first so the base branch carries them: `check-boundaries.sh`
compares criteria to the base whatever phase the edit happened in, and an
`## Amendments` entry here would assert something untrue — that they changed
after the story left PLANNED.*

- **AC-1** — Given a fake session returning a known probability map and a known
  box list, when detection post-processing runs, then it produces one region per
  connected component above the threshold **that lies inside an accepted box**,
  each with a polygon and a 1-bit mask of the same dimensions as the page.
- **AC-2** — Given a probability map with a component of area below
  `MIN_REGION_AREA_PX`, when post-processing runs, then that component produces
  no region.
- **AC-3** — Given a probability map with two components whose masks overlap,
  when post-processing runs, then two regions are produced and each region's
  mask contains only its own pixels.
- **AC-4** — Given a page, when detection runs, then every returned region's
  polygon lies entirely within the page bounds and every mask pixel outside the
  polygon's bounding box is zero.
- **AC-5** — Given a region, when its mask is stored and read back through
  MT-005's store, then it is bit-identical.
- **AC-6** — Given a fixture whose probability map carries a text blob covered
  by an accepted box and a separate SFX blob covered by **no** box, when
  post-processing runs with the shipped configuration, then **no region overlaps
  any pixel of the annotated SFX area**, at every threshold in the swept range
  and every dilation setting.
  *Control:* the same fixture with the SFX blob's rectangle added to the box
  list must produce a region there — otherwise the assertion is passing because
  the detector finds nothing at all. The control must fire by a wide margin, and
  RED records both numbers.
- **AC-7** — *(integration)* Given the real detector model and a real page
  fixture, when the session loads and runs, then the **provider actually
  selected** is reported from `session.get_providers()`, the graph returns `blk`,
  `seg` and `det` of the expected shapes and dtype, post-processing yields at
  least one region, and the decoded box head covers **0.000** of each of the six
  annotated SFX rectangles on `012.jpg`.
- **AC-8** — *(integration)* Given the real detector model and `014.jpg`, when
  detection runs, then **every one of the nine frozen reference boxes** in
  `spikes/MT-030/out/w2-reference-014.json` is overlapped by at least one
  returned region's mask.

### C-1 — the session is a thin ONNX wrapper and owns no arithmetic

```python
# src/mangatl/detect/session.py
MODEL_INPUT_SIDE: int = 1024
PAD_VALUE: int = 114                 # grey letterbox padding

@dataclass(frozen=True)
class RawDetectorOutput:
    blk: NDArray[np.float32]         # (1, 64512, 7)  cx cy w h obj cls0 cls1, canvas coords
    seg: NDArray[np.float32]         # (1, 1, 1024, 1024) in [0, 1]
    det: NDArray[np.float32]         # (1, 2, 1024, 1024)   [A-1]

class DetectorSession(Protocol):
    def run(self, canvas: NDArray[np.float32]) -> RawDetectorOutput: ...
        # canvas: (1, 3, 1024, 1024) float32, already divided by 255
    def get_providers(self) -> Sequence[str]: ...      # [A-2]

def load_detector(model_path: Path, providers: Sequence[str]) -> DetectorSession
def selected_provider(session: DetectorSession) -> str
```

**Amended in RED — A-1: `det` joins `RawDetectorOutput`.** AC-7 asserts that the
graph "returns `blk`, `seg` and `det` of the expected shapes and dtype", and a
type that drops `det` makes that clause unassertable through the contract's own
API. Re-measured in RED on this machine against this `.onnx`: outputs are
`blk [1,64512,7]`, `seg [1,1,1024,1024]`, `det [1,2,1024,1024]`, all
`tensor(float)`; input `images [1,3,1024,1024]`. Nothing in this story reads
`det` — it is carried so AC-7 can see it, and MT-019 may want it.

**Amended in RED — A-2: the Protocol declares `get_providers`.**
`selected_provider(session)` reads `session.get_providers()[0]`, so a Protocol
that does not declare it does not typecheck under `mypy --strict`, and the
AC-7 test passes a proxy object rather than an `InferenceSession`.

**Checked in RED, and the contract's claim is half right.** `get_providers()`
returned `['CUDAExecutionProvider', 'CPUExecutionProvider']` for a session built
after `preload_dlls`. `get_available_providers()` returned
`['Tensorrt…', 'CUDA…', 'CPU…']` **identically before and after**
`ort.preload_dlls(cuda=True, cudnn=True, msvc=True)` — which is the property
MT-002 E2 describes, reproduced. What RED could **not** re-verify is the *578 ms
vs 23 ms* half: `preload_dlls` is process-global and not undoable, so proving
that a session built without it silently runs on CPU needs a second process and
was out of scope here. Treat the preload as mandatory, as C-1 says; the honest
statement is that RED confirmed the dishonest call is dishonest, not that it
confirmed the fallback.

**Everything that is arithmetic lives in `postprocess`, not here**, because this
module is only ever exercised by `integration`, which never runs on CI. A
letterbox or a decode written in this file is a letterbox no required gate reads.

`selected_provider` reads `session.get_providers()[0]`. **Never
`get_available_providers()`** — MT-002 E2/PO-3 measured that it advertises CUDA
identically whether or not the DLLs loaded, and that requesting CUDA does not
raise when it silently falls back to CPU. `get_providers()` is the honest one.

`load_detector` calls `ort.preload_dlls(cuda=True, cudnn=True, msvc=True)` before
constructing the first `InferenceSession`. This is mandatory, not tuning: without
it every model runs on CPU on this machine (578 ms vs 23 ms), failing without
raising. Re-verify it rather than assuming it.

### C-2 — post-processing owns the letterbox, the decode and the regions

```python
# src/mangatl/detect/postprocess.py
MASK_THRESHOLD: float            # derived in GREEN; see C-5
MIN_REGION_AREA_PX: int          # derived in GREEN; see C-6
BOX_CONFIDENCE: float = 0.40
NMS_IOU: float = 0.45
DILATE_ITERATIONS: int = 2
DILATE_KERNEL_SIDE: int = 7      # [A-8]

@dataclass(frozen=True)
class LetterboxTransform:
    ratio: float                 # page -> canvas scale
    pad_x: int
    pad_y: int

def letterbox(page: NDArray[np.uint8],          # (height, width, 3) uint8
              side: int = MODEL_INPUT_SIDE,
              pad: int = PAD_VALUE) -> tuple[NDArray[np.float32], LetterboxTransform]
              # canvas: (1, 3, side, side) float32 in [0, 1]

def decode_boxes(blk: NDArray[np.float32],
                 transform: LetterboxTransform,
                 page_size: tuple[int, int]) -> NDArray[np.float32]
                 # (N, 6) x0 y0 x1 y1 conf cls, PAGE pixel coords,   [A-3]
                 # descending conf                                   [A-3]

def probability_to_page(seg: NDArray[np.float32],
                        transform: LetterboxTransform,
                        page_size: tuple[int, int]) -> NDArray[np.float32]
                        # (height, width) float32, still a PROBABILITY

def regions_from_detection(prob: NDArray[np.float32],        # (height, width) float32
                           boxes: NDArray[np.float32],       # (N, 6) from decode_boxes
                           page_size: tuple[int, int],       # (width, height)   [A-6]
                           *,
                           threshold: float = MASK_THRESHOLD,           # [A-5]
                           dilate_iterations: int = DILATE_ITERATIONS,  # [A-5]
                           ) -> list[RawRegion]
```

**Amended in RED — A-3: `decode_boxes` returns `(N, 6)`, not `(N, 5)`.** The
sixth column is the class index, `argmax(blk[..., 5:])`, kept as a float so the
array stays one dtype. `RawRegion.kind` has no other source in the whole
pipeline: with `(N, 5)` the only honest implementation is to hardcode
`"bubble"`, which makes `kind` dead and the schema's column a fiction. Rows come
back in descending `conf`, which is what greedy NMS produces anyway, so the
order is a fact rather than a choice the tests have to tolerate.

**Amended in RED — A-5: `threshold` and `dilate_iterations` are keyword
parameters.** AC-6 demands "every threshold in the swept range and every
dilation setting". Without parameters, the only way to sweep is to monkeypatch
module globals, which tests the patch. The defaults read the module constants at
definition time, so GATES' D-1 mutation of `MASK_THRESHOLD` still moves the
default — checked against `scripts/mutate.sh`'s substitution model, not assumed.

**Amended in RED — A-6: the two conventions every pixel count depends on.**
`page_size` is `(width, height)` in every signature above, and `prob.shape` is
`(height, width)`; a mismatch raises `ValueError` naming both. Box membership is
**half-open**: pixel `(x, y)` is inside `(x0, y0, x1, y1)` when
`floor(x0) <= x < floor(x1)` and `floor(y0) <= y < floor(y1)`, so a box of
integer coordinates covers exactly `(x1 - x0) * (y1 - y0)` pixels. Neither was
stated, and every exact assertion in `tests/core/test_detect_postprocess.py`
turns on both.

**Amended in RED — A-8: the structuring element is named.** `DILATE_ITERATIONS`
without a kernel size is half a specification. A 7x7 square element grows a
component by 3 pixels in every direction per iteration, so 2 iterations close a
12-pixel gap and no more; the 16-pixel clearance in `overlapping-bubbles.json`
and the 4-pixel gap in `sfx.json` are both sized against that number, and a test
asserts the 3-per-iteration growth directly rather than inferring it.

**Amended in RED — A-12: a component thinner than two pixels is not a region.**
Found by running this suite against a reference implementation of the contract:
`findContours` returns **two** points for a 1-pixel-tall component, so it has no
polygon, and `RawRegion` (C-7, as amended) refuses a ring of fewer than four
vertices — a `ValueError` on a legal input. Discard such slivers with the
speckle, whatever their area: a 1x300 scanline is 300 px and still nothing
MT-016 can typeset into or MT-019 can inpaint. At the shipped dilation no
component is that thin, which is exactly why this would have been found late.

### C-3 — `regions_from_detection` REPLACES `regions_from_probability`, and this is the story's one real design change

The signature this story was planned with —
`regions_from_probability(prob, page_size)` — **cannot satisfy AC-6**, and that
is measured, not argued. See `## Notes` PO-1 for the numbers and the command that
produced them. The short form: the incumbent's `seg` head covers 27–59% of every
annotated SFX area at *every* threshold from 0.10 to 0.999, and the box head
covers exactly 0.000 of all six. The SFX exclusion is a property of the **box
head**, so a function that cannot see the boxes cannot implement it.

`boxes` is therefore a parameter, not an implementation detail.

### C-4 — the order of operations, each step of which has a measured reason

1. **Letterbox** the page into 1024², grey 114, aspect preserved.
2. **Resize the probability map to page size, THEN threshold.** Not the other way
   round. MT-030 E4 measured both orderings: resize-then-threshold gives recall
   0.9658 / IoU 0.5657, threshold-then-resize gives 0.9492 / 0.5847. The first is
   correct for a probability map; nearest-neighbour on a thresholded mask
   discards sub-pixel evidence.
3. **Threshold** at `MASK_THRESHOLD` (`prob >= threshold`).
4. **Intersect with the accepted boxes.**
5. **Connected components** (8-connectivity), **discarding those below
   `MIN_REGION_AREA_PX`.** *(Moved here from step 7 — amendment A-7 below.)*
6. **Dilate** the survivors by `DILATE_ITERATIONS` of a 7×7 kernel.
7. **Intersect with the accepted boxes AGAIN.** The boxes are a fence, not a
   filter applied once. A dilation after the only intersection walks the mask
   back out over the SFX and silently breaks AC-6.
8. **Connected components again** (8-connectivity). These are the regions:
   dilation merges neighbours, and that merging is the whole point of step 6.
   No second area check is needed — every component here contains a survivor of
   step 5. Components thinner than 2 px in either dimension are dropped (A-12).
9. **Polygon and mask** per surviving component, in page pixel coordinates,
   emitted **sorted by (bounding-box y0, bounding-box x0)**. That is an
   *emission* order, chosen because it is deterministic; it is **not** a reading
   order and MT-009 will reassign `reading_index`.

**Amended in RED — A-7: the area floor moves before the dilation.** As written,
steps 5 and 7 contradicted **AC-2**, which is frozen: *"Given a probability map
with a component of area below `MIN_REGION_AREA_PX`, … that component produces
no region."* Applied after dilation, the floor sees the dilated area, and a 4 px
speckle becomes 14×14 = 196 px — so it produces a region for every floor below
196, which is every value C-6 contemplates.

Measured in RED on `spikes/MT-002/pages/012.jpg`, threshold 0.5, dilation 2,
floor 20, box-fenced both ways:

```
floor AFTER dilation :  11 regions, three of them area 182/303/387 with MEAN
                        probability 0.064 / 0.185 / 0.285 and max 0.545 /
                        0.643 / 0.734 - i.e. speckle that never contained one
                        confident pixel
floor BEFORE dilation:   9 regions, those three gone, the other eight identical
```

and on the synthetic `single-kana` fixture, where the answer is arithmetic:

```
MIN_REGION_AREA_PX     5    20    44   196   252   253
floor before dilation  1     1     1     1     1     0   regions   <- AC-2 holds
floor after  dilation  2     2     2     2     1     1   regions   <- AC-2 fails
```

C-6's own words are "a speckle floor, not a size filter". After dilation a
speckle is no longer speckle-sized, so the floor cannot do the job C-6 gives it.
AC-8 is unaffected: 9/9 reference boxes are still overlapped under either order
(measured, minimum overlap 2,684 px).

**Checked in RED, and C-4's step-2 ordering claim stands but its component
counts do not reproduce exactly.** PO-1's sweep reports `comps` 64 at dilation 0
and 8 at dilation 2 for threshold 0.500; RED measured 65 and 9 for the same
threshold under resize-then-threshold with the floor before dilation, and 66/9
under threshold-then-resize. The differences are ±2 and come from convention —
NMS at 0.35 versus 0.45, box clipping, inclusive versus half-open fences. **No
acceptance criterion depends on a component count on a real page**, which is why
this is recorded rather than escalated; no test asserts one.

Step 5 is why the epic's bubble-level region count exists at all: on `012.jpg`
the same page yields 64 components at dilation 0 and **8** at dilation 2, against
6 boxes. MT-030's escalation E-1 records that "a bubble-level region count only
exists after refinement"; step 5 is that refinement.

### C-5 — `MASK_THRESHOLD`: what it means and what settles it

The probability above which a pixel is text. Raising it loses faint text;
lowering it bleeds into screentone. **Not settled here** — GREEN measures it on
the fixture set and records the measurement and both failure directions in
`## Notes`.

Two measurements it may read out rather than re-derive, both reproduced by the
orchestrator on 2026-09-15:

- the incumbent's peak IoU against the author's reference mask is **0.714–0.753
  at threshold ≈0.77–0.81**, not the upstream default of 0.3;
- that reference is the author's *refined* mask, so the right operating point for
  a raw map feeding this story's own refinement is **not** necessarily the peak.

It is a number a later story may read out. It is a number this story must derive.

### C-6 — `MIN_REGION_AREA_PX`: a speckle floor, not a size filter

It exists to discard speckle, **not to discard small bubbles**. A single-kana
bubble is legitimate and must survive. The floor is sized below the smallest
annotated region in the fixture set, and the fixture that pins it is named in
`## Notes`.

Measured on `012.jpg` inside accepted boxes at threshold 0.5: component areas
min 2, p10 44, median 254, max 1372, n=73. Upstream uses 20. That is a starting
point to be re-derived against the single-kana fixture, not a value to adopt.

### C-7 — the region type stays free of numpy

```python
# src/mangatl/domain/region.py
@dataclass(frozen=True)
class RawRegion:
    polygon: tuple[tuple[int, int], ...]   # page pixel coords, closed
    mask: bytes                            # PNG-encoded 1-bit, page-sized
    confidence: float                      # MEAN probability inside the mask
    kind: Literal["bubble", "box"]
```

`domain` may import the standard library and nothing else of ours — **and not
`numpy`, `PIL`, `PySide6`, `onnxruntime` or `anthropic`** (architecture.md §3,
contract 2, enforced by the `lint` gate). `mask` is therefore `bytes`, and the
encoding happens in `detect`.

`confidence` is the **mean** probability inside the mask, not the max. The max is
1.0 for almost every region and carries no information — the `seg` head's
measured range on `012.jpg` is exactly [0.0, 1.0].

`coverage-core` demands **100%** of `src/mangatl/domain/**`. Every branch of this
module, validation included, needs a test.

**Amended in RED — A-4: `kind` is the class of the box that fenced the region,
and the mapping is `1 -> "bubble"`, `0 -> "box"`.** That is the opposite of the
obvious guess, and it is measured rather than guessed. Across `011-015.jpg`, 33
accepted boxes: **29 are class 1 and 4 are class 0**. All nine class-1 boxes on
`014.jpg` are the speech bubbles MT-002 E5 read back through manga-ocr. Every
one of the four class-0 boxes — one on `012`, one on `013`, two on `015` — was
cropped and looked at in RED, and all four are the scanlation watermark
(`DL-Raw.Se`, `RawLazy.Com`): free-floating text on art, not text in a bubble.
Neither MT-002's nor MT-030's spike code distinguishes the classes (both take
`p[:, 5:].max(1)` and throw the index away), so this is new.

Where a region is fenced by more than one box, its kind comes from the box with
the **greatest pixel overlap**; ties go to the lower row index. A consequence
worth stating for MT-011: the watermark is a `box` region and will be OCR'd and
translated unless something later filters it.

**Amended in RED — A-9: the validation, stated so it can be tested.**
`coverage-core` demands 100% of this module and a validation nobody names is a
line GREEN will not write and the gate will then fail on. `__post_init__` raises
`ValueError` naming the field for each of:

| Field | Refused when |
|---|---|
| `polygon` | fewer than 4 vertices, or `polygon[0] != polygon[-1]` — it is a **closed ring**, the last vertex repeating the first |
| `polygon` | any coordinate is not a **non-negative `int`** |
| `mask` | does not begin with the 8-byte PNG signature |
| `confidence` | outside the closed interval `[0.0, 1.0]` |
| `kind` | not `"bubble"` or `"box"` |

The `int` check is not pedantry: contours come out of the array library as
`numpy.int32`, which is **not** a subclass of `int` and which `json.dumps`
refuses — and AC-5's store writes the polygon as JSON. Caught here it names the
field; caught there it is a `TypeError` two layers away from its cause.

**Amended in RED — A-10: "1-bit" means bit depth 1, colour type 0.** The mask is
a PNG whose `IHDR` declares `width = page width`, `height = page height`,
bit depth `1`, colour type `0` (greyscale); a set bit is a covered pixel. PIL
reads exactly that back as mode `"1"`. The tests assert it twice, once through
PIL and once by unpacking `IHDR` with `struct`, because a decoder that widens
the image on the way in would hide an 8-bit mask.

### C-8 — the store gains a region reader and writer, because it has none

MT-005 created the `region` table and **no code reads or writes it**. Verified:
`src/mangatl/store/project.py` exposes `chapter`, `pages`, `page_status`,
`transaction`, `refresh_from_source` and nothing region-shaped. AC-5 is therefore
not a round trip through an existing API — this story writes that API.

```python
# src/mangatl/store/project.py  (methods on Project)
def write_regions(self, page_ordinal: int, regions: Sequence[RawRegion]) -> None
def read_regions(self, page_ordinal: int) -> tuple[RawRegion, ...]
```

The table is `region(id, page_id, reading_index, polygon, mask_blob, kind,
confidence, merged_from)` with `UNIQUE (page_id, reading_index)`. MT-005's schema
notes warn that the upsert form depends on that UNIQUE constraint being declared
exactly as it is; read them before writing the upsert.

`reading_index` is assigned by MT-009, not here. Write the emission order and say
so — this story must not invent a reading order.

**Amended in RED — A-11: `write_regions` is a page-level replace, not an
append.** Four things the block did not say, each of which a test now pins:

1. `reading_index` is the region's **position in the sequence handed over**,
   0 upwards. Nothing sorts.
2. The write **upserts** on `(page_id, reading_index)` — `INSERT … ON CONFLICT
   … DO UPDATE`, never `INSERT OR REPLACE`. MT-005 measured that `OR REPLACE`
   deletes the row and the live `ON DELETE CASCADE` takes its `line` with it: a
   re-run of detection would silently destroy every translation on the page, and
   no row count would show it.
3. Rows whose `reading_index >= len(regions)` are **deleted**, so a re-run that
   finds fewer regions leaves no stragglers for MT-009 to read. `write_regions(n,
   ())` therefore clears the page, which is the honest answer for a page the
   detector now finds nothing on.
4. It **opens its own `transaction()`**, so it is atomic on its own and MT-005's
   non-reentrancy guard refuses a caller that already had one open. Stated here
   so the pipeline story learns it from this line rather than from a half-written
   page.

`merged_from` stays NULL — it is MT-008's. Following `page_status`'s precedent
(MT-005: "deliberately no branch for an ordinal that does not exist"), neither
method invents a branch for an unknown ordinal and no test asks for one.

### C-9 — the fixture set, and where each fixture may come from

**Settled by the user on 2026-09-15** (`## Notes` PO-2). The story was planned
around `fixtures/pages/` holding four real page scans. It does not, because the
only pages carrying real art-integrated SFX are `spikes/MT-002/pages/011–015.jpg`
— non-redistributable scanlation scans of a commercial release, which
`fixtures/**` classifies as `test` and would therefore commit to every clone and
every CI runner. The split instead is:

| Fixture | Lives in | Read by | Redistributable |
|---|---|---|---|
| Synthetic probability maps + box lists for AC-1..AC-6 | `fixtures/detect/` (committed) | `unit`, `coverage` (**required**) | yes — authored here, no provenance question |
| `012.jpg`, `014.jpg` + the real `.onnx` for AC-7, AC-8 | `spikes/**` (**gitignored**, already present) | `integration` (never runs on CI) | not committed, so the question does not arise |

A synthetic fixture is a **hand-built pair**: a page-sized `float32` probability
map and an `(N, 5)` box array, each constructed so the property under test is
arithmetic rather than a judgement. At minimum the set carries a clean-bubbles
fixture, an **SFX fixture** (a boxed text blob and an unboxed SFX blob, with the
SFX rectangle annotated), an overlapping-bubbles fixture, and a **single-kana
fixture** whose area pins `MIN_REGION_AREA_PX` (C-6).

**What this buys and what it costs, stated so GREEN does not rediscover it.**
It buys AC-6 running in a *required* gate, which the original plan could not have
— a real SFX page in `fixtures/` would have been unshippable, and one in
`spikes/` is only ever read by the optional `integration` gate. It costs the
demonstration that the *real detector's* box head is silent on *real* SFX: that
is a property of the model, not of this code, and it is asserted by AC-7 against
`012.jpg` on the machine that has the GPU. Nothing committed to this repository
exercises the real model, and that is the deliberate trade.

**Write down which fixture came from where.** MT-002 and MT-030 both carry a
`## Fixtures, and their provenance` section; the same discipline applies to
anything committed here, synthetic included — "generated by `<script>` on
`<date>`" is a provenance.

### C-10 — the oracle partition, which is the important half of RED's brief

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1..AC-5 | **Mechanical** | Fake session, synthetic probability maps and box lists you construct by hand. Pin exactly; these are arithmetic. |
| AC-6 | **Oracle-free** | The SFX exclusion has no settled metric. Invent one — pixel overlap against the annotated SFX rectangle is the obvious candidate — and **demand the control named in the criterion fires hard**. An assertion that passes against a detector returning zero regions is the failure this AC exists to prevent. The orchestrator's own probe measured the separation as 0 px against 2,319 px on the real page; a synthetic fixture should separate at least as sharply, and if it does not, say so. |
| AC-7, AC-8 | **Mechanical** | Provider, shapes, dtype, non-empty, 0.000 box coverage, nine boxes overlapped. Smoke tests against measured constants, nothing more. |
