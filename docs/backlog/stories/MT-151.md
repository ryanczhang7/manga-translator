## Context

EPIC-13 priority 4 (cleaning). The benchmark's worst residual-ink region is
p011 region 0 at **0.4352**, against `RESIDUAL_INK_MAX = 0.0100`: white
narration over a photo, 70 x 629 px, which came out as a grey smear. Its
neighbour in the ranking, p008 region 1 at 0.0329, is 190 x 514 px. Both are
taller than `512 - 2 x MIN_CONTEXT_PX = 448`, so `clean_page` sends them down
the **downscale path**. That path shrinks the crop to 512 on its long side,
inpaints, and grows it back, so a 629 px column is reconstructed at about
0.8x and interpolated up. The module calls this path "a correctness fallback:
no component on the fixture pages takes it". On the benchmark,
**10 of 264** truth regions have a long side over 448 px.

A component that is long in one direction only can be cleaned at native
resolution in overlapping windows along its long axis. Each window is cut
from the working result, so the part already filled is context for the next
one. The seam failure MT-002 DV-1 names comes from cutting a hole across a
tile boundary that was filled independently. Sequential windows over the
working result fill each hole pixel once, with real context on both sides.
DV-2 checks that claim on real pages.

Required gates: `unit`, `coverage`. The real-model quality check is DV-2.

## Acceptance criteria

All with a recording fake `InpaintSession` that fills holes with a known
value and records every call's image and mask:

- **AC-1** - Given a 60 x 1000 px hole on a 1414 x 2000 page, when
  `clean_page` runs, then:
  - every session call receives a 512 x 512 window whose non-hole pixels are
    a byte-exact native crop of the working page, with no resize;
  - every hole pixel is written exactly once;
  - the calls advance down the long axis.
- **AC-2** - Consecutive windows on one component overlap by at least
  `STRIP_OVERLAP_PX` along the long axis, and each call's mask is only the
  part of the hole not yet filled.
- **AC-3** - *(control: the fallback is still there)* Given a 600 x 600 hole,
  long on **both** axes, then the downscale path runs as today, and the
  session sees a resized crop.
- **AC-4** - A component that fits the native window (at most 448 on both
  axes) is cleaned exactly as today, with one call. AC-4 of MT-019 (nothing
  outside the mask changes) holds for every case above.
- **AC-5** - A horizontal 1000 x 60 hole is cleaned the same way along x.

## Contract

**Writes:** `src/mangatl/clean/inpaint.py`, `tests/core/test_clean_inpaint.py`

- `STRIP_OVERLAP_PX: int` is new. The windows are 512 along the long axis,
  stepped by `512 - 2 x MIN_CONTEXT_PX - STRIP_OVERLAP_PX`. The short axis is
  the `_native_span` of the component, as today.
- The path is chosen per component:
  - **native**: both axes at most 448, as today;
  - **strips**: exactly one axis above 448;
  - **downscale**: both above, as today.
- `clean_page`'s signature is unchanged and has no other caller change
  (`clean/page.py`).
- `STRIP_OVERLAP_PX` is **oracle-free**. Start at `MIN_CONTEXT_PX` and
  change it only on DV-2's evidence, recorded in the comment.
- Oracle partition: AC-1 to AC-5 are **mechanical**, on the fake session.
