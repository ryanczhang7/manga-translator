## Context

**Filed 2026-09-13 out of MT-031's corrective RED, by the orchestrator.** The
test-developer escalated it rather than resolving it quietly, which was the right
call: pinning it either way inside MT-031 would have frozen a behaviour nobody had
decided on, or contradicted a contract clause MT-031 had already pinned.

**This is pre-existing, not a regression from MT-031.** The old extractor took
`awk '{print $NF}'` for `cp|mv` too, so `mv src/main.ts docs/gone.md` yielded
`docs/gone.md` and was allowed. MT-031 replaced that with a real operand parse and
kept the same per-command semantics (its C-3: `cp`/`mv` judge the **last** operand,
the destination). So MT-031 neither introduced this nor fixed it, and nothing
merged needs re-auditing on its account.

### The hole

`mv` does not only write its destination — it **removes its source**. The guard
judges the destination and says nothing about the operand that is about to
disappear. Measured against the `_lib.sh` fixture with the shipped guard, on
MT-031's branch:

```
=== RED: source is frozen ===
mv src/main.ts docs/gone.md          ALLOWED     <- a frozen file leaves its path
mv src/main.ts src/renamed.ts        BLOCKED  src/renamed.ts
cp src/main.ts docs/copy.md          ALLOWED     <- correct: cp is a pure read
rm src/main.ts                       BLOCKED  src/main.ts          (control)
mv docs/notes.md src/main.ts         BLOCKED  src/main.ts          (control)

=== GREEN: tests are frozen ===
mv tests/main.test.ts docs/gone.md   ALLOWED     <- A FROZEN TEST, IN GREEN
mv tests/main.test.ts tests/renamed.test.ts  BLOCKED  tests/renamed.test.ts
rm tests/main.test.ts                BLOCKED  tests/main.test.ts   (control)

=== and a command the guard has never heard of ===
git mv src/main.ts docs/gone.md      ALLOWED
```
`[MEASURED — 2026-09-13, orchestrator's own fixture]`

**Three findings, and the second and third are not in the escalation.**

1. **`mv` out of a frozen path is unjudged.** The escalation's finding.
2. **It applies in GREEN to tests, not only in RED to source.** `mv
   tests/main.test.ts docs/gone.md` makes a frozen test disappear during GREEN.
   That is the same law-2 territory as MT-031's fourth bypass, by a different
   route, and it is the more serious direction because GREEN is the phase where
   an agent has a motive to make a test stop failing.
3. **A rename *within* a frozen category is caught only by accident** — because
   the destination happens to be frozen too, not because the source was judged.
   `mv src/main.ts docs/gone.md` proves the source is never looked at.
4. **`git mv` is not in the extractor's command list at all**, so it is unjudged
   in both directions. Neither is `install`, and `ln -f` can replace a path
   without naming it as a destination the current rules recognise.

### Why it was not folded into MT-031

A numbered PO decision, recorded so the reasoning survives:

- **No MT-031 acceptance criterion covers it.** MT-031's ACs are about operand
  *parsing* — prose read as a path, a redirect hiding an operand, a capture group
  truncating a match. This is about operand *semantics*: which operands of a
  command constitute a write.
- **Fixing it contradicts a clause MT-031 pinned.** MT-031's C-3 says `cp`/`mv`
  judge the last operand, and MT-031's own `## Regressions` R-1 added six
  assertions pinning exactly that. Changing it is a contract amendment, new tests,
  new source work and another GREEN/GATES cycle on a story that had already
  bounced once and carries 185 assertions.
- **`story-authoring`'s sizing rule**: one story is one RED→GREEN cycle. This is
  its own cycle.

## Acceptance criteria

- **AC-1** — Given `mv FROZEN PERMITTED` in a phase that freezes the source
  operand's category, when the guard runs, then it is **blocked**, and the
  reported `path:` is the **source** operand. Measured allowed today, in RED for
  `source` and in GREEN for `test`.
- **AC-2** — Given `cp FROZEN PERMITTED`, when the guard runs in any phase, then
  it is **permitted**. `cp` does not modify its source; this is the criterion that
  stops AC-1 being satisfied by judging every operand of both commands, which is
  the false positive MT-031's PO-11 exists to prevent.
- **AC-3** — Given `mv PERMITTED FROZEN` and `mv FROZEN FROZEN`, when the guard
  runs, then both are still blocked, naming a frozen path. The existing
  destination rule must survive.
- **AC-4** — Given `git mv FROZEN PERMITTED`, when the guard runs, then it is
  **blocked** naming the source operand. Today `git mv` is not a command the
  extractor recognises at all.
- **AC-5** — Given `cp a b c` with three arguments and `b` frozen, when the guard
  runs, then it is **permitted** — MT-031's C-3 and its R-1 assertions, which this
  story must not regress. The whole of MT-031's suite is the rest of this
  criterion.
- **AC-6** — The reported `path:` distinguishes *which* operand was refused, so a
  denial on the source of an `mv` is legible as such rather than looking like a
  denial on the destination.

## Contract

- `.claude/hooks/lib.sh` — `write_candidates`, added by MT-031. The per-command
  table in its header comment is the thing this story changes: `mv` gains a rule
  that its **non-final** operands are writes (they are removed), while `cp`'s stay
  reads.
- `.claude/tests/phase-guard.test.sh` — the new cases.
- Both classify `harness`, writable in every phase. Verified by MT-031 C-1.
- **Verifier:** `bash scripts/selftest.sh`, which CI runs as the required step
  *"Harness self-test"*. No gate in `gates.sh` reads `.claude/**` — see MT-031 C-6
  and PO-19. `required_gates` stays `[]`.

**Read MT-031 before starting.** Its `## Contract`, `## Handoff: GREEN -> GATES`
and `## Deferred verifications` carry the parser's design, its measured `sed`
grammar, the 15 s `PreToolUse` hook budget (MT-031 PO-15) and the mutation
technique for earning an assertion against code that already exists. This story is
a small change to a parser that story built and documented heavily.

## Notes

**Sizing.** Small: one clause in one function, plus cases. But it is a *semantic*
change to the lock, so it wants the same care MT-031 got — in particular AC-2 and
AC-5, which exist to stop the fix becoming a false-positive machine.

**Priority.** Above the feature backlog, below nothing urgent. The hole requires an
agent to `mv` a frozen file, which is rarer than the `> /dev/null` idiom MT-031
closed — but the GREEN-and-test direction is the same severity as anything MT-031
fixed, and `git mv` is exactly what an agent reaches for when renaming a module.

**Do not let AC-4 expand this story.** `git mv` is named because it was measured.
`install`, `ln -f`, `rsync` and `dd` are the same family and are **out of scope**
here; if they matter they get their own story with their own evidence. Only `sed`,
`tee`, `cp`, `mv`, `rm` and `touch` plus `git mv` are in scope.
