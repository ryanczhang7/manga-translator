## Context

Filed 2026-10-14 when MT-048 was narrowed (MT-048 PO-1, the user's decision).
`layout.md` §Window says the window's size, position, maximised state and the
splitter positions are **remembered**, and the region table says the column
width is "remembered". Nothing persists any of it: there is no `QSettings`,
`saveState` or `saveGeometry` anywhere under `src/mangatl/ui`. MT-048 adds
`_column_dragged`, a flag reset only by `load_chapter`; the user-dragged width
it protects is lost on close.

Measured on this host before pinning (offscreen platform, 2026-10-22): a bare
`Workspace()` shown without a resize is **1100 × 720** (the minimum); the
offscreen work area is 800 × 800; `setWindowState(WindowMaximized)` before
`show()` opens the window maximised with `normalGeometry()` keeping the size
and position set before it; `QSplitter.moveSplitter(pos, 2)` trips MT-048's
flag. Every test, in every folder, runs with `APPDATA` pointed at a fresh empty
directory (`tests/conftest.py`), so a state file written in one test is never
read by another.

**Pinned at PLANNED → RED on 2026-10-22** against `layout.md` §Window as
amended by PO-1.

## Acceptance criteria

- **AC-1** — Given a state file recording 1600 × 1000 at (120, 80), not
  maximised, when `open_folder` builds the workspace (or `remember_layout` is
  called on one) and it is shown, then `size() == (1600, 1000)` and
  `pos() == (120, 80)`. Given the same file with `maximized: true`, then
  `isMaximized()` is true and `showNormal()` returns it to 1600 × 1000 at
  (120, 80). Given a workspace that was resized, moved or maximised, when it
  closes, then the file holds exactly that state (`layout_state()`), so a
  second workspace built from it opens the same way.
- **AC-2** — Given the user dragged the column (MT-048's flag set) to a width
  `W` inside 280–560, when the workspace closes and another is built from the
  file and shown, then `splitter.sizes()[2] == W`, `_column_dragged` is true,
  and resizing across 1440 in both directions leaves the column at `W`
  (MT-048's rule holds across sessions). Given the column was **not** dragged,
  then the file records `column_width: null` and the reopened column is the
  breakpoint default for its width.
- **AC-3** — Given no state file, or one that is unreadable, not JSON, or of
  another version, when the workspace is built, then it opens at
  `first_run_size(work_area, MIN_SIZE)`: 1600 × 1000 on a 1920 × 1040 work
  area, 1400 × 900 on a 1400 × 900 one, and 1100 × 720 on an 800 × 800 one
  (the minimum wins); the column is the breakpoint default (380 at 1600 wide,
  300 at 1100) and `_column_dragged` is false.
- **AC-4** — Given a state file whose values violate the limits, when it is
  read, then it is clamped, never applied as is: 900 × 500 → 1100 × 720; a
  width above the work area → the work area's width; column 100 → 280 and
  900 → 560; a top-left that would put any part of the window outside the
  work area → moved so the whole window lies inside it (AM-1). A `Workspace` built **without** `remember_layout` reads and
  writes nothing; a state path whose parent cannot be created never stops the
  window closing (`closed` is still emitted).

imports only the standard library, so its tests need no `QApplication`):

    x: int

    # `minimum` on EITHER axis (aw < min_w or ah < min_h).

    # A-1: `minimum` on BOTH axes when the work area cannot hold `minimum`;

**A-1 (RED, 2026-10-22).** AC-3 pins "1100 × 720 on an 800 × 800 one (the
minimum wins)"; the per-axis formula above gives **1100 × 800** there
(`max(720, min(1000, 800)) = 800`). The criterion is frozen and the formula is
not, so the formula gains the rule AC-3 implies: a work area that cannot hold
the minimum yields the minimum. `clamp_state` follows the same rule, so a file
read against the offscreen 800 × 800 screen opens at 1100 × 720 — what
`## Callers of changed signatures` already assumed for the five `build_window`
files. Pinned by `…first_run_size…[A-1-short-in-height-only]`,
`…[A-1-short-in-width-only]` and the two "smaller than the minimum" clamp tests.

**Block 3 — `Workspace`** (`workspace.py`):

```python
WorkArea = Callable[[], Rect]
def remember_layout(self, path: Path, *, work_area: WorkArea | None = None) -> None
def layout_state(self) -> WorkspaceState       # what closeEvent would write now
```

`remember_layout` arms remembering for this window and applies the file **now**,
before any `show()`: `work_area()` defaults to this window's screen's
`availableGeometry()` (the primary screen before the window has one), as an
`(x, y, w, h)` tuple. With `read_state(path) is None` the window is
`resize`d to `first_run_size(work_area(), MIN_SIZE)` and nothing else changes.
Otherwise `clamp_state(state, work_area(), MIN_SIZE, (COLUMN_MIN_WIDTH,
COLUMN_MAX_WIDTH))` is applied: `resize(width, height)`, `move(x, y)`, then
`setWindowState(WindowMaximized)` if `maximized`; if `column_width` is not
`None`, `_column_dragged = True` and the clamped width is what the splitter
shows once the window is laid out — `splitter.sizes()[2] == column_width`
after `show()` and a settle, and `_apply_breakpoint` leaves it alone on every
crossing (the existing `if not self._column_dragged` guard). GREEN chooses
where the remembered width is applied (the first `resizeEvent` is the
natural place; splitter sizes are unreliable before the window is shown).
`layout_state()` reads `normalGeometry()`'s size and position when
`isMaximized()`, else `size()` and `pos()` — **A-2:** when maximised, the
size and position of the normal geometry **in `pos()` terms** (the frame's
top-left, what `move()` takes), i.e. what `size()`/`pos()` will be after
`showNormal()`. Measured offscreen (2026-10-22): after `show()`,
`move(200, 100)`, `showMaximized()`, `normalGeometry()` is
`QRect(202, 102, 1500, 900)` — the *client* top-left, 2 px inside `pos()` —
while for a window maximised before its first `show()` it is
`QRect(120, 80, …)`, the `move()` value. A literal reading would walk the
window 2 px per session. GREEN chooses how (tracking the last normal
size/position in `moveEvent`/`resizeEvent` while not maximised works);
pinned by `test_a_window_maximised_after_a_move_writes_the_moved_position_and_reopens_there`; `column_width` is
`splitter.sizes()[2]` if `_column_dragged` else `None`. `closeEvent`, when
armed, calls `write_state(path, self.layout_state())` after the flush and
before `closed.emit()`; a `False` return changes nothing. **A `Workspace`
never given `remember_layout` reads and writes no file** — every existing UI
test builds one that way, and their explicit `resize` calls keep working.

## Amendments

- **AM-1 — AC-4, 2026-10-22, approved by the user in chat.** *Was:* "a
  top-left outside the work area → moved to the nearest point inside it".
  *Now:* "a top-left that would put any part of the window outside the work
  area → moved so the whole window lies inside it". *Why:* read literally, a
  stored x = 5000 on a 1920-wide area becomes x = 1919 and the window reopens
  almost entirely off-screen; the Contract (block 1) and RED's tests already
  clamp the whole window (x → 320). Found by RED; put to the user as a choice
  between the two readings; the user chose the whole window.
