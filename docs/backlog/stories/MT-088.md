## Context

Filed 2026-10-14 when MT-048 was narrowed (MT-048 PO-1, the user's decision).
`layout.md` §Window says the window's size, position, maximised state and the
splitter positions are **remembered**, and the region table says the column
width and a collapsed strip are "remembered". Nothing persists any of it: there
is no `QSettings`, `saveState` or `saveGeometry` anywhere under `src/mangatl/ui`
(grep, 2026-10-14). MT-048 adds `_column_dragged`, a flag that is never reset;
the user-dragged width it protects is lost on close.

## Acceptance criteria

*Draft; to be pinned at PLANNED → RED against `layout.md` §Window. Where the
settings file lives is `app_paths.py`'s decision (MT-024), not `QSettings`'
default, so the frozen binary and the dev run agree.*

- **AC-1** — Given the user closes the workspace at 1600 × 1000 at a given
  position, when the app reopens a chapter, then the window opens at that size
  and position (clamped to the current work area), and maximised if it was.
- **AC-2** — Given the user dragged the column to 400 px, when the workspace
  reopens, then the column is 400 px and MT-048's drag flag is set, so crossing
  the breakpoint still does not reset it.
- **AC-3** — Given no remembered state (first run), when the workspace opens,
  then it is 1600 × 1000 or the work-area size if smaller (`layout.md`
  "Default on first run"), and the column is the breakpoint default.
- **AC-4** — Given a remembered state that violates the minimum (1100 × 720) or
  the column clamp (280–560), when it is read back, then it is clamped rather
  than applied.

## Contract

To be pinned. Expected shape: a small `WorkspaceState` dataclass read and
written through a path from `app_paths`, applied in `Workspace.showEvent` and
captured in `closeEvent`; no `QSettings`.

## Out of scope

Remembering the rail/strip collapse by the user (no user collapse exists yet).
