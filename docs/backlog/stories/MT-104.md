## Context

EPIC-09 PO-2: the glossary is proposed once, up front, by one text-only call
over every page's local-OCR Japanese. This story is the **call**: what is
asked, the schema of the answer, the parse, and the Gemini adapter function
that sends it - all testable with a fake client. Wiring it into a run is
MT-105.

Today a page's `response_schema` carries an optional `glossary` array
(`translate/page_prompt.py:185-205`, `GLOSSARY_SCHEMA`), parsed by
`translate/parse.py:parse_terms_text` into `ProposedTerm(term_ja, term_en,
note)`, and merged per page (`domain/glossary.py:merge`). The pre-pass reuses
those two: the same schema fragment for the answer, the same parse, the same
domain type - so MT-105's merge sees nothing new.

Size: 200 pages x ~500 OCR tokens (`cost-model.awk` OCR_JA) is ~100k input
tokens, under the 200k tier the Gemini row is priced for. A volume whose
listing would exceed the tier is refused by name rather than priced at a tier
the table has no row for.

`mangatl.translate` is the one package that may import `google.genai`; the
pure functions go in a new SDK-free module so `tests/core` can test them
without a client, as `page_prompt.py` is split from `gemini.py`.

Required gates: `unit`, `coverage`. `integration` reads `translate/**` but
is optional; the adapter is tested here with a fake `Client`, as
`tests/core/test_gemini*.py` do today.

## Acceptance criteria

- **AC-1** - `glossary_pass_text(pages)` for three pages of Japanese lines
  renders every line once, grouped under a per-page header that carries the
  1-based page number, in page then reading order, with `ocr_empty` lines
  left out; two calls with the same input are byte-identical.
- **AC-2** - `GLOSSARY_PASS_SCHEMA` requires a `glossary` array whose items
  are `GLOSSARY_SCHEMA`'s (`term_ja`, `term_en`, `note`, all required) and
  forbids additional properties at both levels; `parse_glossary_pass` on a
  conforming body returns the terms in order as `ProposedTerm`s and on a body
  with no `glossary` key raises `ValueError` naming the key.
- **AC-3** - Given a fake client, `propose_glossary(client, pages)` sends one
  `generate_content` call whose `model` is `MODEL_ID`, whose `contents` is
  exactly `[glossary_pass_text(pages)]` (no image part), whose config has
  `system_instruction == GLOSSARY_PASS_PROMPT`, `response_mime_type ==
  "application/json"`, `response_json_schema == GLOSSARY_PASS_SCHEMA`,
  `ThinkingLevel.MEDIUM`, `max_output_tokens == GLOSSARY_PASS_MAX_OUTPUT_TOKENS`;
  and returns a `GlossaryProposal` whose `terms` are the parsed terms, whose
  `usage` is the response's four counts mapped as `translate_page` maps them
  (thinking added to output), and whose `call.model_id` is
  `response.model_version`.
- **AC-4** - Given pages whose rendered text `estimate_tokens` to more than
  `GLOSSARY_PASS_MAX_INPUT_TOKENS`, `propose_glossary` raises
  `VolumeTooLarge` naming the estimate and the limit, and the fake client
  records no call.

## Contract

**Writes:** `src/mangatl/translate/glossary_pass.py`, `src/mangatl/translate/gemini.py`, `src/mangatl/domain/translation.py`, `tests/core/test_glossary_pass.py`, `tests/core/test_gemini_glossary_pass.py`

```python
# translate/glossary_pass.py - SDK-free
GLOSSARY_PASS_PROMPT: str          # asks for recurring names, honorifics, places, catchphrases; one rendering each; no translation of lines
GLOSSARY_PASS_SCHEMA: dict[str, Any]
GLOSSARY_PASS_MAX_INPUT_TOKENS: int = 180_000    # MT-101 D-12: the 200k tier is measured on the prompt; 20k headroom for the system prompt
GLOSSARY_PASS_MAX_OUTPUT_TOKENS: int = 8_192     # a volume's glossary is longer than a page's answer
class VolumeTooLarge(Exception): ...
def glossary_pass_text(pages: Sequence[Sequence[OcrResult]]) -> str
def parse_glossary_pass(text: str) -> tuple[ProposedTerm, ...]

# domain/translation.py
@dataclass(frozen=True)
class GlossaryProposal:
    terms: tuple[ProposedTerm, ...]
    usage: TokenUsage
    call: CallInfo

# translate/gemini.py
def propose_glossary(client: Client, pages: Sequence[Sequence[OcrResult]]) -> GlossaryProposal
```

Semantics: the page header is `Page {n}:` with `n = index + 1`; lines are
`text` verbatim, one per line; `estimate_tokens` is `domain.glossary`'s. The
input limit is checked **before** the call. Oracle partition: AC-1 to AC-4
**mechanical**.

*Amended in RED (2026-11-01, test-developer) - the exact bytes, which the
paragraph above left open and AC-1's byte-identical pin needs:*
`glossary_pass_text` is exactly
`"\n\n".join(f"Page {i + 1}:\n" + "\n".join(r.text for r in page if not r.ocr_empty) for i, page in enumerate(pages) if any(not r.ocr_empty for r in page))`
- a page block is its header then its lines joined by `\n`; blocks are
separated by one blank line; no preamble, no trailing newline. **A page with
no non-`ocr_empty` line (all `ocr_empty`, or no regions) is dropped, header
included**, and the pages after it keep their own index-based number (a gap,
not a renumbering); a volume with no readable line renders as `""`. Reason for
dropping rather than keeping: the listing is for finding terms, a header with
no lines carries none, and a run of art pages would otherwise spend input
tokens against the 180,000 limit for nothing; the index-based `n` keeps the
page a model note could cite correct either way. Also pinned from this block:
`VolumeTooLarge` derives from `Exception` directly (not `ValueError`, so a
refusal is not caught as a malformed answer); "SDK-free" means importing
`glossary_pass` does not load `google.genai` (importing `translate.parse`,
and so the Anthropic SDK, is permitted - it is the shared parse); the
`VolumeTooLarge` message carries the estimate and the limit as plain or
comma-grouped integers (`180001` or `180,001`); `call.request_id` is
`response.response_id`, as `translate_page` records it.

No signature changes to existing exports. No new dependency.
