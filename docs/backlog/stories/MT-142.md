## Context

EPIC-13 enabler. Every fix in the epic has to be measured before and after
on pages that are **not** the held-out benchmark (`product-brief.md` O1;
EPIC-13 "Evidence"). The bench refuses any truth document flagged
`development_use: true`, both in `load_ground_truth`'s default mode and inside
`measure` (MT-022 AC-8). That refusal is right for the headline and stays
the default. This story adds a deliberate, visibly labelled way to measure a
development document, so that a development figure can never be mistaken
for a benchmark result.

Required gates: `unit`, `coverage`, and `coverage-core`, which holds `bench/**` at 100 %. No optional gate is involved.

## Acceptance criteria

- **AC-1** - Given a truth document flagged `development_use: true` and its
  project, when `python -m mangatl.bench FOLDER --development` runs, then it
  exits `0`. Its first line is exactly `DEVELOPMENT SET - not a benchmark
  result`. Every line after it is the line the same measurements would print
  for an unflagged copy of the document, except that each line beginning
  `S1b`, `S1a`, `S2` or `S5` ends with the suffix `  [development]` (two
  spaces).
- **AC-2** - Given the same document, when the bench runs **without**
  `--development`, then it still refuses with
  `BenchmarkChapterUsedInDevelopment` and exits `2` (MT-022 AC-8 unchanged).
- **AC-3** - *(control: the flag cannot relabel the benchmark)* Given a
  document flagged `development_use: false`, when the bench runs with
  `--development`, then it exits `2` and prints nothing on stdout. Its
  stderr names the chapter and says it is the held-out benchmark (C-3).
- **AC-4** - Given a flagged document handed directly to `measure`,
  `measure_recall`, `measure_residual` or `measure_s2`, when the call passes
  `development=True`, then it measures. When it does not, it raises
  `BenchmarkChapterUsedInDevelopment` as today. And `development=True` with
  an unflagged document raises `NotADevelopmentSet`, from all four.

### C-1 One rule, in `bench/truth.py`

```python
class NotADevelopmentSet(Exception):
    """`development=True` was asked of a document not flagged development_use."""

def check_mode(truth: GroundTruth, *, development: bool) -> None:
    """Raise BenchmarkChapterUsedInDevelopment when not development and the
    document is flagged; raise NotADevelopmentSet when development and it is
    not flagged; otherwise return None."""
```

`truth.py` is the home because every measurement module already imports its
refusal from there. Without a shared rule, four private copies of the same
`if` would drift. The refusal messages:
- `BenchmarkChapterUsedInDevelopment` (unchanged words): `chapter {name!r} is
  flagged development_use, so it is not held out and cannot be a benchmark`;
- `NotADevelopmentSet`: `chapter {name!r} is not flagged development_use: it
  is the held-out benchmark, so measure it without --development`.

### C-2 Signatures

```python
def measure(project, truth, *, development: bool = False) -> AcceptanceReport        # acceptance.py
def measure_recall(project, truth, *, development: bool = False) -> RecallReport     # recall.py
def measure_residual(project, truth, *, development: bool = False) -> ResidualReport # residual.py
def measure_s2(project, truth, *, development: bool = False) -> S2Report             # s2.py
```

- Each function calls `check_mode(truth, development=development)` first,
  in place of its own `if truth.development_use` block.
- `measure_residual` passes `development=development` to its own
  `measure_recall` call.
- `measure_s2` passes `development=development` to both collaborators,
  which it still calls through its module globals (MT-023 A-2).

`__main__`:
- adds `--development` (`store_true`) and binds
  `development: bool = arguments.development`;
- loads with `load_ground_truth(path, benchmark=not development)`, catching
  `NotADevelopmentSet` beside the other refusals;
- passes `development=development` to `measure` and `measure_s2`;
- when `development` is set, prints the label line first and appends
  `  [development]` to every rendered line that starts with `S1b`, `S1a`,
  `S2` or `S5`.

`render_*` are unchanged. The standalone `bench.acceptance` and `bench.s2`
commands keep refusing: they get no flag in this story.

### C-3 The refusal's stderr

AC-3's stderr is `_fail`'s one line, `python -m mangatl.bench: ` followed by
the `NotADevelopmentSet` message above, which names the chapter and the
words `held-out benchmark`.

## Deferred verifications

### DV-1 The refusal put back

This puts back the defect the story must not introduce: a flag that
silently turns development mode on. With `__main__`'s
`development: bool = arguments.development` mutated to `development: bool =
True`, both of these **must** fail:
- AC-2: the flagged document measures without the flag;
- AC-3: the unflagged document is refused for the wrong reason, or measured.

Mutating `load_ground_truth`'s argument alone would prove nothing, because
the measurements refuse a second time inside (C-2). Command:

    bash scripts/mutate.sh src/mangatl/bench/__main__.py 's/development: bool = arguments.development/development: bool = True/' -- uv run pytest -q tests/core/test_bench_main.py

RED cannot run it: the flag does not exist yet. **Owner: GATES.**
