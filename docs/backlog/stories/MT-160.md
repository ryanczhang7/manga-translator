## Context

`tests/ui/test_rerun_workspace.py::test_the_panel_receives_every_event_in_order_on_the_gui_thread`
(MT-125's suite, [EPIC-11](../epics/EPIC-11.md)) fails intermittently: 1 run in
8 alone, and in one full gate run it failed in `unit` and passed in `coverage`
on the same tree. The failure is always the same line, in the `_confirm` helper:

    AssertionError: window.run is None after the confirm

**The cause, found and reproduced.** `_confirm` clicks the dialog's
`run_button`, calls `_settle()` (two `QApplication.processEvents()`), and only
then reads `window.run`. In `src/mangatl/ui/workspace.py` the click runs
`_on_rerun_dialog_finished` -> `_start_run` synchronously, which sets
`self.run = run` and calls `run.start()`. `run.ended` is connected queued to
`_run_ended`, which on `RUN_FINISHED` calls `_return_from_run`, and that sets
`self.run = None`. This test's fake run (two skipped pages, two pages of
50-event bursts) can finish on the worker before `_settle()` runs; `_settle()`
then delivers the queued `ended`, the body returns, and `window.run` is `None`.
The helper reports "no run" for a run that started and has already returned.

**The production behaviour is correct. The defect is in the test helper**, which
reads the run one event-loop turn too late. The same file already says so at
one call site that does not use the helper (the comment "Not `window.run`: this
run can finish inside `_settle()`" above the `started` capture, near line 1469).

This is a test-only fix: `tests/ui/test_rerun_workspace.py` is the only code
file it writes. The required gate that reads it is `unit`
(`uv run pytest -q tests/core tests/ui`), and `coverage` runs the same suite;
no optional gate is involved, so `required_gates` stays empty.

### The one edit

`_confirm` in `tests/ui/test_rerun_workspace.py` (lines 545-554 today). Its
signature, docstring and callers do not change:

    def _confirm(window: Workspace) -> RunController:

Today the body ends `primary.click()`, `_settle()`, `run = window.run`, the
`isinstance` assertion, `return run`. After the fix it reads the run **before**
it settles:

    primary.click()
    run = window.run
    assert isinstance(run, RunController), f"window.run is {run!r} after the confirm"
    _settle()
    return run

- **Why reading first is right, not merely convenient.** `primary.click()`
  runs `Workspace._on_rerun_dialog_finished` -> `_start_run` synchronously, and
  `_start_run` assigns `self.run` before it returns. Nothing queued is needed
  for `window.run` to be set, so reading it with no event processing in between
  is deterministic, and it is the stricter check: it pins "the confirm starts
  the run during the click", where the old order pinned "a run is still on two
  event-loop turns later".
- **Keep the `_settle()`**, after the read. The nine call sites (lines 925,
  960, 982 - the named test - 1031, 1058, 1114, 1169, 1588 and 1646) were
  written against a helper that has settled before it returns; removing it
  changes what every one of them sees next and is not this story.
- **Keep the line `    run = window.run` spelled exactly so**, at four spaces,
  and the assertion message unchanged. DV-2's expression matches that line.
- **Nothing else in the file changes.** No new test function is required: the
  criteria are about a helper, and they are pinned by the probes below, which
  the named test observes. If RED finds it wants a new test, it says why here.
- No test-only dependency is needed. `time` is already imported by the file
  (line 55), which is what lets the probes be one `sed` expression.
  `pytest-repeat` is **not** installed (absent from `pyproject.toml` and
  `uv.lock`), so AC-3 is a bash loop, not `--count`.

### Probe P (AC-1) - the run ends before the helper settles

    bash scripts/mutate.sh tests/ui/test_rerun_workspace.py '/^def _confirm/,/^def _wait_returned/s/^    _settle()$/    time.sleep(0.5); _settle()/' -- uv run pytest -q -p no:cacheprovider "tests/ui/test_rerun_workspace.py::test_the_panel_receives_every_event_in_order_on_the_gui_thread"

It puts a 0.5 s sleep in front of the helper's `_settle()`, which gives the
worker time to finish, so the queued `ended` is waiting when `_settle()` runs.
0.5 s is not a threshold; it is "far longer than this fake run takes" (the run
is 110 in-memory events). The expression is addressed by range rather than by
line number so that the **same** command applies before and after the fix:

| Helper | Probe P must | Why |
|---|---|---|
| as it stands today | FAIL, `window.run is None after the confirm` | the read comes after the settle that returned the body |
| corrected | PASS | the read already happened; the settle returning the body is now harmless, and `_wait_returned` passes on a body that has already returned |

**Baseline, measured 2026-11-20 on `main` at 0b0e378** by the session that
found the cause, with the same edit spelled by line number
(`551s/^    _settle()$/    time.sleep(0.5); _settle()/`): failed 1 of 1 with
exactly that assertion, and `mutate.sh` restored the file. The range spelling
above selects the same single line (551 is the only `_settle()` between
`def _confirm` and `def _wait_returned`) but has not itself been run; RED's
first step is to run it and see the same failure.
