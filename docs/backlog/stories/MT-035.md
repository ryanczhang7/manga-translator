## Context

**This story closes EPIC-03's assembly gap, and it exists because MT-009 PO-4
named it.** The epic's done-when says *"Given a page scan, the **pipeline**
produces regions with masks ... in right-to-left top-to-bottom reading order."*
MT-007 shipped `regions_from_detection`, MT-008 shipped `merge_columns`, MT-009
shipped `order_regions` — three correct, well-tested pure functions — and a
caller sweep in MT-009 found **zero source callers** of
`store.project.write_regions`. Nothing in `src/mangatl/pipeline/` calls any of
them. The epic has every piece and no assembly; MT-006's `run_chapter` walks
pages through a `PassThroughStage` and nothing else. This story builds the stage
that makes the epic's sentence true.

Two documents bound it. `architecture.md` §2 *The adapter split* says the
**logic** of a detection stage is a pure function over arrays taking an
*injected session object*, tested against a fake session in `tests/core` which a
required gate reads, with the real model getting a smoke test in
`tests/integration` — *"Without this split, every required gate could pass over
stories whose artifact nothing exercised."* `pipeline/stage.py` says a stage is a
`Protocol` rather than a base class, and that **`Project.transaction()` is not
reentrant** (MT-005 PO-5), so the stage owns its transaction, one per page per
stage (§6).

**Which required gates would fail if this story's artifact broke: `unit` and
`coverage`.** Both are `required` in `project.conf` and both carry
`covers | src/mangatl/**`, which reads `src/mangatl/pipeline/**` and
`src/mangatl/detect/**`. AC-1 to AC-9 are all asserted in `tests/core` against
fakes and really execute on CI — measured at 34 s and 24 s on the MT-009 PR.
`coverage-core`'s 100 % bar covers only `domain`, `typeset` and `bench`, so it
does **not** read either module this story adds; that is a fact about the bar,
not a gap, because `unit` and `coverage` do.

`required_gates: [integration]` follows MT-007 PO-4 and MT-008 PO-3 exactly:
this story adds a file under `src/mangatl/detect/**`, which `covers | integration
| src/mangatl/detect/**` reads, and the line escalates that gate to required **on
the machine running the loop**, where it executes 11 real tests on the GPU. On CI
`STORY_REQUIRES` is empty and it stays optional, where it skips in 1.5 s for want
of a CUDA provider and the gitignored weights. **Only AC-10 depends on it**, and
AC-10 is deliberately not a central claim: the epic's ordering sentence is AC-1,
which runs in `unit`. MT-009 PO-2 is the standing warning here and it is honoured
rather than argued with.

## Acceptance criteria

<!-- AC-1 to AC-6 are the stage; AC-7 to AC-9 are the detect adapter; AC-10 is
     the real detector and runs only under `integration`. -->

- **AC-1** — Given a page and a detector that returns regions in an order that is
  **not** reading order, when the detect stage runs that page, then
  `project.read_regions(ordinal)` returns exactly those regions in
  `domain.reading_order.order_regions` order — `reading_index` 0 is the
  top-right region, `reading_index` n-1 the bottom-left.
  *Control:* the fixture's detector order must differ from the reading order, and
  the test asserts that difference on the fixture itself — otherwise a stage that
  wrote the detector's order straight through would satisfy AC-1 by accident. A
  stage that omits the ordering step must fail this criterion; that mutation
  cannot run in RED and is deferred below.
- **AC-2** — Given a page, when the stage runs it, then the injected detector is
  called **exactly once**, with the exact bytes of
  `project.chapter.source_dir / page.filename`, and the contents of `source_dir`
  are unchanged afterwards — same filenames, same bytes. `architecture.md` §5:
  the user's scans are read-only to this app, always.
- **AC-3** — Given a page whose regions are already in the store, when the
  stage's `is_done` is consulted, then it is `True`; given a page with no stored
  regions, then it is `False`. And given a single-stage `run_chapter` over a page
  that already has regions, then `PageSkipped` is emitted for that page and the
  injected detector is **not** called.
- **AC-4** — Given a page whose regions were written by an earlier run, when the
  stage runs again and the detector now returns **fewer** regions, then the store
  holds exactly the new set, in reading order, with no rows surviving from the
  previous run — `read_regions` returns exactly the new regions and nothing else.
- **AC-5** — Given a detector that returns no regions at all, when the stage runs,
  then the page's stored regions are empty, no exception is raised, and `is_done`
  for that page subsequently reports **`False`**.
  *This is a decision, not an oversight,* and it is written as a criterion so it
  is falsifiable: a genuinely textless page is re-detected on every run. See
  `## Contract` C-6 for why that is the honest answer and what the alternative
  would cost.
- **AC-6** — Given a detector that raises, when the stage runs a page that
  already has stored regions, then the exception propagates out of `run` (which
  is what makes `run_chapter` emit `RunAborted` naming the page) and the page's
  stored regions are **unchanged** — the stage writes once, after it has every
  region, and never clears first.
- **AC-7** — Given a fake `DetectorSession` and a page's encoded image bytes, when
  `detect.page.detect_page_regions` runs, then the session's `run` is called
  **exactly once** and its argument is the letterboxed canvas —
  `MODEL_INPUT_SIDE` square, `float32` — and not the decoded page at its own
  dimensions.
  *Control:* a chain that handed the decoded page straight to the session passes
  an array of the page's own shape, which this criterion must reject; the test
  asserts the shape, so the control is the assertion.
- **AC-8** — Given a fake session whose probability map places two columns of one
  utterance inside a single detected box, when `detect_page_regions` runs, then it
  returns **one** region whose `merged_from` records both inputs, while
  `regions_from_detection` on the *same* session output returns **two** — the
  MT-008 merge is in the chain.
  *Control:* the two-region baseline is the control and is asserted in the same
  test, on the same session output. Without it the criterion is satisfied by a
  synthetic page the detector only ever found one region on, which would make it
  measure nothing.
- **AC-9** — Given a fake session and a page of size `(W, H)` with `W != H`, when
  `detect_page_regions` runs, then every returned region's mask decodes to
  exactly `(H, W)` and every polygon vertex lies inside the page rectangle — the
  probability map was carried back through the letterbox transform into page
  coordinates.
  *Control:* a chain that skipped `probability_to_page` yields masks at model
  scale (`MODEL_INPUT_SIDE` square), which this criterion rejects. `W != H` is
  load-bearing: on a square page a transposed or unscaled mask has the right
  shape and the criterion goes blind.
- **AC-10** — *(`integration`, GPU only)* Given the real detector session and
  `spikes/MT-002/pages/011.jpg` intaken as a one-page project, when the detect
  stage runs that page, then the store holds at least one region and
  `read_regions(ordinal)` equals `sort_regions` of the same region set — the real
  chain composes end to end and reaches the store in reading order. Skips cleanly
  on a checkout without the gitignored weights and pages, as
  `tests/integration/test_column_merge_pages.py` already does.
  **No criterion above depends on this one.** It is real-detector evidence, and on
  CI it does not run.

### C-1 — Injection is forced by the `lint` gate. It is not a style preference.

This is the decision the story turns on, and it was settled by running the tool
rather than by reading its configuration.

`pyproject.toml`'s contract *"Only detect, ocr and clean import onnxruntime"* is
a `forbidden` contract listing `mangatl.pipeline` among its `source_modules`, and
it does **not** set `allow_indirect_imports`. Import-linter therefore reports
transitive chains. Every module in `mangatl.detect` reaches `onnxruntime`:
`columns -> postprocess -> session -> onnxruntime`. Probed with a throwaway
config against the real tree, touching no project file:

```
$ uv run lint-imports --config <scratch>/indirect.ini
Analyzed 53 files, 94 dependencies.
does a forbidden contract catch an INDIRECT chain BROKEN
Contracts: 0 kept, 1 broken.

mangatl.detect.columns is not allowed to import onnxruntime:

-   mangatl.detect.columns -> mangatl.detect.postprocess (l.60)
    mangatl.detect.postprocess -> mangatl.detect.session (l.56)
    mangatl.detect.session -> onnxruntime (l.32)
```

So **`mangatl.pipeline` may not import `mangatl.detect` at all** — not
`columns`, not `postprocess`, not even the `DetectorSession` protocol in
`session`. A stage that constructed or merely *named* its detector would break
`lint`, a required gate, on the first run.

Two consequences, both of which the design below obeys:

1. The stage takes its detector **injected, behind a type it can name without
   importing `detect`** — a plain `Callable` over `bytes` and `RawRegion`, both
   stdlib and `domain`.
2. The composition of the MT-007/MT-008 functions ships **inside `mangatl.detect`**,
   because that is the only package allowed to hold it.

This lands where `architecture.md` §2 was already pointing, and it also answers
MT-009 PO-2's warning in the right direction: every criterion except AC-10 is
driven by fakes in `tests/core`, under `unit` and `coverage`, which really run on
CI. Tests are not part of the `mangatl` root package, so `tests/integration` may
import both sides and wire the real thing; that is AC-10.

### C-2 — `src/mangatl/detect/page.py` — new module

```python
__all__ = ["detect_page_regions"]

def detect_page_regions(
    session: DetectorSession,
    image_bytes: bytes,
) -> list[RawRegion]: ...
```

The whole detect chain for one page, composed from what MT-007 and MT-008 already
shipped, in the order `postprocess`'s module docstring fixes (MT-007 C-4) — read
those steps out, do not re-derive them:

1. decode `image_bytes` to an RGB `uint8` array (`PIL`; `detect` may import it);
2. `letterbox(page)` → `(canvas, transform)`;
3. `session.run(canvas)` → `RawDetectorOutput`;
4. `decode_boxes(raw.blk, transform, (width, height))`;
5. `probability_to_page(raw.seg, transform, (width, height))`;
6. `regions_from_detection(prob, boxes, (width, height))`;
7. `merge_columns(regions, integer_boxes(boxes, width, height))`.

`page_size` is `(width, height)` while `prob.shape` is `(height, width)`; the
mismatch raises rather than transposing a page silently (MT-007 A-6). The
reference for this composition is `tests/integration/test_column_merge_pages.py`'s
`detected` fixture, which performs exactly these seven steps inline today —
**this story moves that composition into shipped source**, which is the point.

**It does not order.** `architecture.md` §2 puts reading order outside `detect`
explicitly (*"`detect` ... explicitly does not own: reading order"*), and
`merge_columns`' own docstring says so. The return is MT-008's `(y0, x0)` merge
order. Ordering is the stage's, C-3.

Production wiring, for whoever assembles it later:
`partial(detect_page_regions, load_detector(model_path, providers))`. Nothing in
`src` performs that wiring in this story — see `## Out of scope`, and the
escalation recorded there.

### C-3 — `src/mangatl/pipeline/detect_stage.py` — new module

```python
__all__ = ["DetectStage", "PageDetector"]

#: Page image bytes in, regions out, in any order. The narrowest type the stage
#: can name: `bytes` is stdlib and `RawRegion` is `domain`, so naming it costs
#: `pipeline` no import of `detect` (C-1).
PageDetector = Callable[[bytes], Sequence[RawRegion]]

@dataclass(frozen=True)
class DetectStage:
    detect: PageDetector
    name: str = "detect"

    def run(self, ctx: PageContext) -> None: ...
    def is_done(self, ctx: PageContext) -> bool: ...
```

`run` is four steps and nothing else:

1. `image_bytes = (ctx.project.chapter.source_dir / ctx.page.filename).read_bytes()`;
2. `regions = self.detect(image_bytes)`;
3. `ordered = sort_regions(regions)` — `mangatl.domain.reading_order`;
4. `ctx.project.write_regions(ctx.page.ordinal, ordered)`.

`is_done` is `bool(ctx.project.read_regions(ctx.page.ordinal))`.

Four things about that shape are load-bearing:

- **`sort_regions`, not `order_regions`.** Position is the only carrier of
  reading order (MT-009 PO-1): `write_regions` derives `reading_index` from the
  position in the sequence it is handed, and no region carries an index of its
  own. `sort_regions(regions)` is `[regions[i] for i in order_regions(regions)]`.
- **The stage opens no transaction.** `write_regions` opens its own, and
  `Project.transaction()` is deliberately not reentrant (MT-005 PO-5) — a stage
  that wrapped the write would turn it into a `RuntimeError`. This needs no
  separate criterion: AC-1's test raises if it is ever violated.
- **One write, at the end.** `write_regions` is a page-level replace that also
  deletes rows at or past `len(regions)` (MT-007 A-11), so AC-4's "no stragglers"
  is already the store's behaviour and the stage must not add a clearing write of
  its own. That is what AC-6 pins.
- **`name` is a field with a default, not a `ClassVar`.** The `Stage` protocol
  declares `name: str` as an instance attribute; a `ClassVar` does not satisfy a
  protocol member typed that way and `mypy` will say so.

`pipeline/detect_stage.py` imports: `mangatl.domain.region`,
`mangatl.domain.reading_order`, `mangatl.pipeline.stage`, and stdlib. **No
`numpy`, no `PIL`, no `mangatl.detect`.** If RED or GREEN finds it wants any of
those, the seam is in the wrong place — stop and say so rather than adding the
import.

### C-6 — why `is_done` is "has regions", and what that costs

`stage.py` says done-ness is per stage per page, and the only thing the detect
stage writes is regions, so "has regions" is the only honest thing to read back.
The consequence, pinned by AC-5: a page on which the detector genuinely finds
nothing is re-detected on every run. That is accepted for v1 because re-detecting
is idempotent and costs one GPU inference — no API spend, no data loss — whereas
the alternatives each buy a new problem: a per-stage completion marker is a
schema change this story has no mandate for, and `page.status` is per page and
already owned by the runner (`architecture.md` §5, `runner._mark_done`). If a
later story adds per-stage markers, AC-5 is the criterion it amends.

## Notes

### Sizing: one cycle, and where the seam is if RED disagrees

Ten criteria and two new modules is at the top of this project's demonstrated
cycle size, so the judgement is recorded rather than assumed. It is one cycle
because **neither half is shippable alone**: `detect/page.py` without the stage
is a fourth pure function nobody calls — precisely MT-009 PO-4's complaint, one
level up — and `DetectStage` without the adapter is a stage with no real
implementation to inject, whose only production wiring would live in a test.
Splitting re-creates the gap this story exists to close. For comparison, MT-007
shipped `session.py` and `postprocess.py` in one cycle; the implementation here is
thinner than either, because every rule it depends on is already written and
tested.

**If RED finds it does not fit, the seam is clean and pre-named:** AC-7 to AC-9
(`detect/page.py`) split from AC-1 to AC-6 (`pipeline/detect_stage.py`), with the
adapter first and the stage depending on it, and AC-10 going with the stage. Stop
and say so rather than trimming criteria to fit.

### Ordering against MT-010

MT-009 PO-4 recommended this story sit "after MT-010". It is filed as a **sibling
of MT-010 instead, depending only on MT-009**, because nothing in it needs OCR:
the detect stage writes regions, and MT-010 writes lines. Waiting would block a
closable gap behind an unrelated story, and going first means MT-010's own stage
can follow the `PageDetector` pattern C-3 establishes rather than inventing a
second one. Recorded here because it is a deliberate departure from the
recommendation that created the story.

### Where AC-6 came from, and what was trimmed

An earlier draft carried a criterion asserting `run_chapter` emits `RunAborted`
naming the page when the detector raises. That was cut: MT-006 AC-4 already owns
it and re-asserting it here tests the runner, not this stage. What survives as
AC-6 is the part that *is* this stage's claim — that it writes once, at the end,
and so leaves the previous run's regions intact when the detector fails. A stage
that cleared the page first would pass every other criterion in this file.
