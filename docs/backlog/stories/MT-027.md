## Context

**Decided by the user on 2026-09-12.** The Lead Designer proposed it
(`docs/wiki/design/typeset-font.md` §3) and planning left it as a scope question
rather than answering it: the brief's non-goal forbids "per-bubble font or size
control", and whether that also forbids *one application-wide* setting is a
reading of the user's intent, not a planner's call.

The user's answer: **Shantell Sans stays the default and still ships; a user who
owns another comic-lettering face can point one app-wide setting at it.** The
per-bubble non-goal stands untouched. The scope reading is now written into the
brief's §5 so it is not re-litigated, and `architecture.md` D9 is amended.

**Split out of MT-020 rather than folded into it.** MT-020 already carries eight
criteria covering fitting, breaking, emphasis, determinism, glyph coverage and
licence obligations. The override is a different behaviour — resolving and
validating a font the project did not ship — and it drags in settings, file I/O
and a user-facing failure surface. That is a second RED→GREEN cycle, not a
ninth criterion.

**It depends on MT-021, not MT-020**, even though its subject is typesetting:
AC-7 records the fallback on the `BakeReport`, and that type does not exist
until MT-021. So it runs last in EPIC-06.

**The failure behaviour is the story, not a footnote.** A configured font file
can be missing, unreadable, not a font at all, lacking the glyphs English
lettering needs, or lacking a real bold or italic. Falling back to the default
*silently* and falling back *loudly* are different products: silent fallback
means a user bakes twenty pages in the wrong face and discovers it in Photoshop.
Every one of those cases has a criterion below.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — font resolution is pure logic over a settings value and a
file, and `typeset` carries the 100% bar.

## Acceptance criteria

- **AC-1** — Given no font override in settings, when the lettering faces are
  resolved, then the four shipped Shantell Sans static faces are used, and the
  resolution reports `default`.
- **AC-2** — Given an override naming a directory containing four valid faces
  (regular, italic, bold, bold-italic), when they are resolved, then those faces
  are used, the resolution reports `override` with the family name read from the
  font's own `name` table, and MT-020's typesetting uses them unchanged.
- **AC-3** — Given an override pointing at a path that does not exist, when
  resolution runs, then the shipped default is used **and** a named, surfaced
  warning identifies the configured path and says the default was substituted.
  The bake is not blocked.
- **AC-4** — Given an override pointing at a file that exists but is not a
  parseable font, when resolution runs, then the same: default used, warning
  naming the file and the parse failure, bake not blocked.
- **AC-5** — Given an override whose faces parse but are **missing codepoints in
  `REQUIRED_CODEPOINTS`** (MT-020 AC-7), when resolution runs, then the default
  is used and the warning **names the missing codepoints**, not just "unsuitable
  font".
- **AC-6** — Given an override supplying a regular face but **no distinct bold or
  italic** — the `OS/2` style bits do not differ, MT-020 AC-7's second clause —
  when resolution runs, then the default is used and the warning says which
  style is missing. *(A faux-oblique of a comic face is the exact defect that
  eliminated the runner-up font; accepting one here would discard the reason
  Shantell Sans was chosen.)*
- **AC-7** — Given any fallback from AC-3 through AC-6, when the bake runs, then
  the `BakeReport` records that a fallback occurred and why, so the failure is
  visible after the run and not only at the moment it happened.
- **AC-8** — Given an override is configured and valid, when a chapter is baked,
  then **every** typeset region uses the override — there is no path by which
  some regions use one family and some another.
- **AC-9** — Given a valid override, when it is later removed from settings, then
  the next bake uses the shipped default with no residue of the previous choice.

**How a user's folder is read** (the four files will not carry Shantell's names):

- Candidates are the regular files directly in the folder whose suffix is `.otf`
  or `.ttf`, case-insensitive. Anything else (`OFL.txt`, a README) is ignored.
  Not recursive.
- Each candidate is classified by `OS/2.fsSelection`: ITALIC bit 0 and BOLD bit 5
  → `regular` (neither), `italic`, `bold`, `bold_italic` — the same bits MT-020's
  C-7 table pins for the shipped faces. Candidates are taken in sorted filename
  order; the first file per style wins. A second file of an already-filled style
  is ignored, not an error.
- `family` is `name` ID 16 (typographic family) of the regular face, else ID 1.

**Checks, in this order — the first that fails is the reason reported:**

| # | Condition | `fallback` | `detail` (exact) |
|---|---|---|---|
| 1 | the path does not exist | `missing_path` | `{path} does not exist` |
| 1b | the settings file is unreadable / not a JSON object / value not a string | `missing_path` | `{settings_file} could not be read: {error}` |
| 2 | the path exists and is not a directory, **or** a candidate fails to parse (`TTFont` raises, or `OS/2`/`cmap`/`name` absent) | `unparseable` | `{file} is not a font: {error}` |
| 3 | a style has no file | `missing_style` | `{dir} has no {styles} face` — missing styles in `STYLE_KEYS` order, written with spaces (`bold italic`), joined `, ` |
| 4 | a face's cmap lacks codepoints in `REQUIRED_CODEPOINTS` | `missing_glyphs` | `{file} lacks {cps}` — the **first** failing face in `STYLE_KEYS` order, its missing codepoints as `U+XXXX`, ascending, joined `, ` |

**Amended by RED (2026-10-04)** - each `{error}` the table left open, pinned, because
the detail is asserted exactly and an open `{error}` is a guess GREEN would have to make:

- **Row 2, path not a directory:** `{path} is not a font: not a folder`; the file is
  not opened, even when it is a real font file. *Reason: the setting names a folder
  (settled); `{error}` had no value for this case.* (Escalated - see `## Handoff`, Q-1.)
- **Row 2, table absent:** `{error}` is `no {tag} table`, `{tag}` one of `OS/2`, `cmap`,
  `name` (e.g. `... is not a font: no OS/2 table`). *Reason: no exception exists to
  stringify.*
- **Row 2, `TTFont` raises:** `{error}` is `str(exception)`; tests obtain it by asking
  fontTools to parse the same bytes (`_font_fixtures.parse_error`), never hard-coded.
  **Every** candidate is parsed before row 3 runs, including a second file of an
  already-filled style; with several broken candidates, the first in sorted filename
  order is reported. *Reason: "first that fails" needed an order within row 2.*
- **Row 4:** `U+XXXX` is `f"U+{cp:04X}"` - at least four upper-case hex digits
  (`U+0020`, `U+2026`). *Reason: pins the padding the example implied.*
- **Row 1b, `{error}` exactly:** invalid JSON -> `str(json.JSONDecodeError)`; JSON that
  is not an object (a list, a string, a number, `null`) -> `not a JSON object`; the
  value present and neither a string nor `null` -> `lettering_font_dir is not a string`;
  an `OSError` opening the file -> `str(error)` (only the prefix and a non-empty reason
  are asserted; the OS's wording is not). *Reason: three cases had no `{error}`.*
- **Row 1b at the bake:** when `lettering_font_dir` returns a `str`, `bake_chapter` and
  `preview_bake` letter in the shipped faces and `BakeReport` carries
  `font_fallback="missing_path"`, `font_detail=` that string, `font_family=FONT_FAMILY`.
  *Reason: the pinned block routed a `str` nowhere.*
- **`BakeReport.font_family`:** `FONT_FAMILY` on every fallback and with no override;
  the resolution's `family` (name ID 16, else 1) with a valid override.
  `font_detail == ""` exactly when `font_fallback == "none"`.
- **The CLI line goes to stdout**, after the summary, as the last line printed.

`{path}`, `{file}`, `{dir}`, `{settings_file}` are `str(Path)`. Row 1b exists
because a setting the user wrote and the app silently ignored is exactly what
this story forbids, and it reuses `missing_path` rather than widen the frozen

**Settled, and to be read out:**

- **The setting names a *directory* of four faces, not a single file.** A comic
  lettering family is four files, and MT-020 AC-5 resolves emphasis to real face
  files rather than synthesising. A single-file setting would force exactly the
  faux-oblique this product rejects.
- **Validation is the same check MT-020 AC-7 already performs on the shipped
  font**, reused, not reimplemented — `REQUIRED_CODEPOINTS` in the cmap of all
  four faces, and distinct `OS/2` style bits. If that check is not already
  callable against an arbitrary directory when this story starts, making it so
  is part of this story.
- **Fallback is always to the shipped default, never to a system font.** The
  shipped font is the one whose licence, coverage and metrics are known; a
  Windows system font is none of those.
- **Fallback never blocks the bake.** The user asked for an override as a
  convenience; a convenience that can stop a chapter rendering is worse than no
  convenience. Loud, recorded, and it proceeds.
- **`REQUIRED_CODEPOINTS` excludes the interrobang**, as MT-020 records — the
  convention sets `?!`. Do not widen the required set here to make an override
  fail more often.
- **The override is read once per bake**, not per region (AC-8), which is what
  keeps `architecture.md` D9 true: `typeset` still has no per-bubble parameters.

**Oracle partition: entirely mechanical.** Every criterion is a resolution
outcome over a constructed fixture directory, with a named reason. There is no
metric here and nothing to calibrate. The only judgement calls — directory not
file, fall back to shipped not system, never block — are settled above.

**Fixtures this story needs** (`test` category, so RED authors them): a valid
four-face directory; a directory missing bold; a directory whose faces parse but
lack `…` and `—`; a file that is not a font; and a path that does not exist.
A tiny synthesised font is sufficient and preferable to vendoring a second real
family — `fontTools` can build one.

## Out of scope

Per-bubble font control, size control and manual line breaks — the brief's
non-goal stands and this story does not touch it. Font *size* override: not
asked for, and sizing is derived from the bubble. A font picker UI beyond a path
setting. Bundling any second font. Subsetting — forbidden by the shipped font's
Reserved Font Name clause, and not this story's business for a user's own file
either. Vertical English.

## Test plan

Oracle partition: **entirely mechanical**, as the contract says. Every expectation is a
resolution outcome over a synthesised fixture (`tests/core/_font_fixtures.py`), with an
exact reason and `detail`. The four settled calls are asserted, not reconsidered:
directory not file (`test_an_override_that_names_a_file_not_a_folder_is_not_a_font`);

`FONT_DIR/<shipped name>`, or `bundled_dir/<shipped name>`); never blocks
(`..._never_blocks_the_bake...`, the CLI exit status); once per call (AC-8, PO-3 tests).

alone; the file names (`f1.ttf`..`f4.ttf`) never say the style. One fixture per reason;
AC-5's has all four styles and lacks U+2026 and U+2014; AC-6's has full coverage and
lacks a style. About 3.5 ms per face.
