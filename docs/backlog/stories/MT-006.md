## Context

The spine. `architecture.md` §6 and D8. After this story the app can be pointed
at a folder and produce a sibling folder, reporting progress per page and
resuming a killed run — with **no stage doing anything yet**. Every later stage
plugs into this rather than inventing its own orchestration.

The event stream is the part that matters most and is easiest to get wrong. If
`pipeline` calls into widgets, the whole pipeline becomes untestable without a
display, and MT-018's cost readout becomes untestable without a GPU and an API
key. So: typed events out, commands in, and every test in this story runs
headless.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage`. Nothing here needs a GPU or the network, and if a test of this story
wants either, the boundary is wrong.

## Acceptance criteria

- **AC-1** — Given a project of 4 pages and a stage list, when a run starts,
  then each page is processed once, in ordinal order, and the run ends with
  outcome `finished`.
- **AC-2** — Given a run over 4 pages, when it executes, then the event stream
  contains, in order, `RunStarted`, then for each page `PageStarted(ordinal)`
  followed by one `StageFinished(ordinal, stage)` per stage, then `RunFinished`
  — and no event names a page that is not in the chapter.
- **AC-3** — Given a run, when `cancel()` is called while page 2 is in flight,
  then the run stops after page 2's current stage completes, emits
  `RunAborted(reason="cancelled")`, and pages 1 and 2 keep whatever they
  completed.
- **AC-4** — Given a run that raised on page 3, when the run ends, then it emits
  `RunAborted` naming page 3 and the error, and pages 1 and 2 are still
  persisted and complete.
- **AC-5** — Given a project where pages 1 and 2 already have all stage results,
  when a run starts, then pages 1 and 2 are skipped (no `StageFinished` for
  them) and the run begins work at page 3.
- **AC-6** — Given a completed run, when the output is written, then
  `<source>_en/` contains exactly one file per page, with the same filenames and
  the same order as the input, and each file's bytes are the page's current
  rendered output (for this story: the input bytes, unchanged).
- **AC-7** — Given the output write for page 3 fails partway, when the folder is
  inspected, then no file named `page3.png` exists in a partial state — the
  write goes to a temporary name and is renamed only on success.
- **AC-8** — Given a run, when it executes, then **no file inside the source
  folder** has been created, modified or deleted.
- **AC-9** — Given a run driven entirely headlessly (no Qt application object
  constructed), when it executes, then it completes and emits its full event
  stream. *(This is the boundary criterion: it fails if `pipeline` imports
  anything from `ui`.)*
- **AC-10** — Given a folder of scans and no existing project, when
  `mangatl.cli.main([str(folder)])` is invoked, then it creates the project
  beside the folder, runs every page, writes `<folder>_en/` with one
  identically-named file per page in the same order, emits one line of progress
  output per page, and returns exit code `0`. *(Added at PLANNED by PO-1, on the
  user's decision of 2026-09-15, to close EPIC-02's done-when gap. PLANNED is
  the last phase in which a criterion may change without an `## Amendments`
  entry, which is why it is here and not later.)*

## Contract

```
src/mangatl/domain/events.py
    @dataclass(frozen=True) RunStarted(run_id: int, page_count: int)
    @dataclass(frozen=True) PageStarted(ordinal: int)
    @dataclass(frozen=True) StageFinished(ordinal: int, stage: str, elapsed_ms: int)
    @dataclass(frozen=True) PageSkipped(ordinal: int, reason: str)
    @dataclass(frozen=True) RunAborted(reason: str, ordinal: int | None)
    @dataclass(frozen=True) RunFinished(run_id: int, pages_done: int)
    RunEvent = RunStarted | PageStarted | StageFinished | PageSkipped | RunAborted | RunFinished

src/mangatl/pipeline/stage.py
    class Stage(Protocol):
        name: str
        def run(self, ctx: PageContext) -> None: ...
        def is_done(self, ctx: PageContext) -> bool: ...

src/mangatl/pipeline/runner.py
    def run_chapter(project: Project, stages: Sequence[Stage],
                    emit: Callable[[RunEvent], None],
                    cancelled: Callable[[], bool]) -> RunOutcome

src/mangatl/pipeline/export.py
    def write_output_folder(project: Project, output_dir: Path) -> None
```

**Semantics behind each decision — one sentence each:**

- **`emit` is a plain callable and `cancelled` is a plain predicate.** No Qt, no
  threading primitive, no queue in the signature. The UI adapts a Qt signal to
  `emit` and a `QThread` interruption flag to `cancelled`; that adaptation lives
  in `ui`, which is why AC-9 can be true.
- **`is_done` is what makes resume work**, and it is per stage per page, not per
  page. A page that has regions but no translations resumes at translation.
- **Cancellation is checked between stages, never inside one.** A stage that is
  half-done is a stage that must be re-run, and for the translation stage
  half-done means money already spent — so the boundary is the stage, and the
  granularity of loss is one stage of one page.

  > **AMENDED BY RED, 2026-09-15 — *which* boundaries, exactly.** "Between
  > stages" does not by itself say whether a run cancelled before it starts does
  > one page's work, nor whether a cancel after the last stage of page 2 emits a
  > `PageStarted(2)` with nothing after it. Both are visible in the ordered
  > projection AC-2 demands, so RED could not write the expected list without
  > answering them. Pinned, and built into
  > `tests/core/test_pipeline.py`: **`cancelled()` is consulted at the top of
  > the page loop and at the top of the stage loop, and nowhere else.** A page
  > whose stages have all completed is marked done *before* the next boundary is
  > consulted. That single rule gives all three cases their natural answer — a
  > run cancelled before it starts emits `RunStarted, RunAborted` and touches no
  > page; a cancel during page 2's only stage stops after that stage with no
  > stray `PageStarted`; and a cancel during page 2's *first* of two stages runs
  > neither the second stage nor anything after it.
- **`RunAborted.ordinal` is `None` for a cancel and the failing page's ordinal
  for an error.** The distinction is what MT-018 shows the user.
- **The output write is temp-then-rename per file** (AC-7). `os.replace` on the
  same filesystem is atomic on Windows and POSIX alike; a write straight to the
  final name is not.
- **`<source>_en/` is created if absent and its contents are replaced, not
  merged.** A stale file from a previous run with a filename no longer in the
  chapter must not survive — otherwise the "same order and filenames" promise is
  broken by a file the user cannot account for.

**Stages in this story:** exactly one, a `PassThroughStage` whose `run` is a
no-op and whose `is_done` consults the store. It exists so the runner has
something to sequence and so AC-5's skip logic has something to skip. It is not
a placeholder to be deleted later — it is the identity element, and keeping it
means the runner is exercised with a zero-stage and a one-stage list.

> **AMENDED BY RED, 2026-09-15 — where it lives, and what "consults the store"
> means.** The block above names `PassThroughStage` and gives it neither a
> module, a `name`, nor a definition of done-ness — and PO-7 writes the expected

### PO-2 — `PageContext` and `RunOutcome` are named in the contract and defined nowhere

Both appear in signatures above and neither has a definition, so RED would have
to invent them and GREEN would have to guess the same thing. Pinned:

```python
# src/mangatl/pipeline/stage.py
@dataclass(frozen=True)
class PageContext:
    project: Project          # from mangatl.store.project
    page: Page                # from mangatl.domain.page

# src/mangatl/pipeline/runner.py
RUN_FINISHED = "finished"
RUN_ABORTED  = "aborted"

@dataclass(frozen=True)
class RunOutcome:
    run_id: int
    outcome: str              # RUN_FINISHED | RUN_ABORTED
    pages_done: int
    aborted_reason: str | None
```

`PageContext` carries the `Project` because `is_done` must consult the store
(that is the whole of AC-5) and a stage writes its results through
`ctx.project.transaction()`. It carries the `Page` and not the ordinal because
a stage that needs the filename or the dimensions should not have to re-query
for them.

`RunOutcome.outcome` is the same string written to the `run` row's `outcome`
column, so AC-1's "ends with outcome `finished`" is one value asserted in two
places. `run_chapter` **inserts the `run` row first** — that is where
`RunStarted.run_id` comes from — and updates `ended_at`, `outcome` and
`aborted_reason` on the way out.

> **AMENDED BY RED, 2026-09-15 — `pages_done` had no definition, and three tests
> need one.** It appears on `RunOutcome` and on `RunFinished` and is defined
> nowhere; PO-7 pins it at `4` for a 4-page run, which does not settle the two
> cases that matter. Pinned: **`pages_done` is the number of pages that are
> complete when the run ends — pages this run processed *plus* pages it skipped
> as already done — and it never counts the page an abort happened on.** So:
> a clean 4-page run reports `4`; a resumed run that skipped pages 0 and 1 and
> processed 2 and 3 reports `4`, not `2`; a run that aborted on page 3 reports
> `2`; a run cancelled before it started reports `0`. The alternative reading
> ("pages this run did work on") makes a fully translated chapter report `2` on
> the readout MT-018 builds, which is the wrong number to show a user.
>
> The abort-side reading is the one AC-4 already implies — "pages 1 and 2 are
> still persisted and complete" is two pages, and `RunAborted` carries no count
> of its own, so `RunOutcome.pages_done` is where that two is said.

### PO-6 — "killing the process halfway" is AC-4 composed with AC-5. RED writes the composition

### PO-7 — AC-2 asserts an ordered **projection**, never raw dataclass equality

AC-2 says "assert the whole ordered list, not a subset", and it is right. But
`StageFinished` carries `elapsed_ms`, which is a **measured duration** — so
comparing a list of event dataclasses against expected instances is a flaky
test that will pass on this machine and fail somewhere slower, and the fix
under pressure is to stop asserting the list.

So: project each event to `(type(e).__name__, ordinal-or-None, stage-or-None)`
and assert **that** list exactly. Assert `elapsed_ms` separately, and only as
`isinstance(e.elapsed_ms, int) and e.elapsed_ms >= 0` — never a value, never an
upper bound. A `>= 0` is not a weakened assertion here; it is the only true one,
and pinning a duration is how a suite acquires a timing flake.

The exact expected projection for a 4-page chapter with the one-stage list
`[PassThroughStage()]`, which RED should write out literally:

```
RunStarted(run_id, page_count=4)
PageStarted(0)  StageFinished(0, "passthrough")
PageStarted(1)  StageFinished(1, "passthrough")
PageStarted(2)  StageFinished(2, "passthrough")
PageStarted(3)  StageFinished(3, "passthrough")
RunFinished(run_id, pages_done=4)
```

and for the **zero-stage** list `[]` — which the story's contract says must be

### 4. The export shape the tests already pin

**Nothing below is a suggestion.** Each name and signature is already imported
by a test, so getting it wrong is an import error rather than a debate.

```python
# src/mangatl/domain/events.py
#   Frozen dataclasses. NO methods, NO __post_init__, NO validation, NO
#   properties, NO `if TYPE_CHECKING` and NO `sys.version_info` branch: this
#   module is inside coverage-core's --cov-fail-under=100 set (PO-4), and a
#   branch no test reaches fails a REQUIRED gate.
@dataclass(frozen=True) class RunStarted:    run_id: int;  page_count: int
@dataclass(frozen=True) class PageStarted:   ordinal: int
@dataclass(frozen=True) class StageFinished: ordinal: int; stage: str; elapsed_ms: int
@dataclass(frozen=True) class PageSkipped:   ordinal: int; reason: str
@dataclass(frozen=True) class RunAborted:    reason: str;  ordinal: int | None
@dataclass(frozen=True) class RunFinished:   run_id: int;  pages_done: int
RunEvent = RunStarted | PageStarted | StageFinished | PageSkipped | RunAborted | RunFinished

# src/mangatl/pipeline/stage.py
@dataclass(frozen=True)
class PageContext:
    project: Project          # mangatl.store.project.Project
    page: Page                # mangatl.domain.page.Page

class Stage(Protocol):
    name: str
    def run(self, ctx: PageContext) -> None: ...
    def is_done(self, ctx: PageContext) -> bool: ...

class PassThroughStage:       # constructed with no arguments by the tests
    name = "passthrough"      # the literal PO-7's projection is written with
    def run(self, ctx: PageContext) -> None: ...            # writes nothing
    def is_done(self, ctx: PageContext) -> bool: ...        # page.status == PAGE_DONE

# src/mangatl/pipeline/runner.py
RUN_FINISHED = "finished"
RUN_ABORTED  = "aborted"

@dataclass(frozen=True)
class RunOutcome:
    run_id: int
    outcome: str              # RUN_FINISHED | RUN_ABORTED
    pages_done: int
    aborted_reason: str | None

def run_chapter(project: Project, stages: Sequence[Stage],
                emit: Callable[[RunEvent], None],
                cancelled: Callable[[], bool]) -> RunOutcome: ...

# src/mangatl/pipeline/export.py
def write_output_folder(project: Project, output_dir: Path) -> None: ...

# src/mangatl/cli.py
def main(argv: Sequence[str] | None = None) -> int: ...

# src/mangatl/store/project.py  -- ONE ADDED CONSTANT, nothing else changes
PAGE_DONE: str = "done"
```

Three shape facts that are not in the signatures and are pinned anyway:

1. **`write_output_folder` must call `os.replace(...)` as an attribute on the
   `os` module.** `tests/core/test_export.py` injects AC-7's failure with
   `monkeypatch.setattr(os, "replace", ...)`; a `from os import replace` at the
   top of `export.py` binds the name before the patch and the injection silently
   does nothing — which shows up as `DID NOT RAISE`, not as a pass, but costs a
   confusing hour.
2. **`PassThroughStage()` takes no constructor arguments**, and
   `PageContext(project=..., page=...)` is constructed by keyword.
3. **The stage list is positional**: `run_chapter(project, stages, emit,
   cancelled)`, in that order, all four positional.

**What the tests do NOT constrain, and is yours to choose.** The `PageSkipped`
reason string (asserted only as a non-empty `str`). The `RunAborted.reason`
format for an error, beyond containing the exception's message. How
