## Context

**Filed 2026-09-30 by the Lead PO** at the user's request, closing [[MT-055]]
Q2: a double-clicked app can open a chapter already translated, but cannot
translate one. The brief's first five minutes (`product-brief.md` §3, steps 2-3)
are "Point it at a chapter … It works through the pages", and the designed path
is `FolderDropTarget` → `ChapterSummary` → `CostEstimate` → "Start run"
(`docs/wiki/design/components.md` §2). That is three stories, split by what each
one can demonstrate on its own:

- **MT-057 (this)** - a folder of pages with no project shows *what will be
  run*: its name, page count, first and last page, the order warning, and the
  intake errors. Reads the folder; writes nothing.
- [[MT-058]] - the summary shows the estimated cost against the budget.
- [[MT-059]] - "Start run" creates the project and runs the pipeline from the
  window, feeding [[MT-018]]'s progress panel, and opens the review workspace
  when the run finishes.

This story replaces [[MT-055]] AC-4's interim outcome (the no-project error
naming `mangatl-run`) **and MT-054's command-line no-project notice**: by the
user's decision (PO-3), `mangatl <folder>` and the picker share one resolution,
so a folder with no project shows the summary - or one of the intake errors -
whichever way it was named. [[MT-054]] is DONE and is **not reopened**; its
AC-3 tests are rewritten here, deliberately, and listed in `## Contract`. The
folder is read by
the store's existing `mangatl.store.intake.read_chapter` (MT-004), in
`domain.page.order_filenames` order - the same order a run will use. The copy
is `components.md` §2's: **read it out, do not reword it.**

Required gates that would fail if this broke: `unit` and `coverage`, over
`tests/ui` offscreen, with real image fixtures from the intake tests.
`required_gates: []`.

## Acceptance criteria

"Chosen" below means either path: returned by MT-055's chooser, or given as
`mangatl <folder>` (the argument resolved, as MT-054 C-2 does). Every criterion
holds for both, and the tests drive both.

- **AC-1** — Given a chosen folder with no project, holding page images that
  all decode, when it is chosen, then the window shows the `ChapterSummary`:
  the folder name, the page count, and the first and last filenames in
  processing order (`order_filenames`). Given as `mangatl <folder>`, the window
  is the intake window showing that summary - not MT-054's notice window.
- **AC-2** — Given a chosen folder with no `.png`/`.jpg`/`.jpeg` files, when
  it is chosen, then the drop target shows its error state with "No page
  images in *folder*. This tool reads `.png` and `.jpg` files."
- **AC-3** — Given a chosen folder the app cannot list, when it is chosen, then
  the error state reads "Windows would not let this app read
  *folder*." followed by the operating system's error text.
- **AC-4** — Given a folder whose filenames sort differently lexically and
  naturally (`1, 10, 11, 2` against `1, 2, 10, 11`), when its summary is shown,
  then a warning notice lists both orders explicitly and states that the
  natural order is the one the run will use; there is no control to change it
  (PO-5). Given a folder whose two orders agree, no notice is shown.
  *(Control: a folder of `p1 … p9` only must show no notice; `p1 … p12` must.)*
- **AC-5** — Given any chosen folder, when its summary or its error is shown,
  then nothing has been created, modified or deleted - no `.mtproj`, and the
  input folder byte-for-byte as it was.
- **AC-6** — Given a chosen folder with no project in which one page file will
  not decode, when it is chosen, then no summary is shown: the drop target
  shows its error state naming that file - "*filename* could not be opened as
  a page image. Remove or replace it, then choose the folder again." - and
  nothing is created. With two undecodable files, the one named is the first in
  processing order (`read_chapter`'s rule). *(Control: the same folder with
  that file replaced by a valid image must show the summary.)* The sentence is
  the Lead Designer's (`components.md` §2, amended 2026-09-30), adopted at
  PLANNED under this criterion's own clause (PO-6).

**C-1 — `UnreadablePage` carries its filename** (`src/mangatl/store/intake.py`).

```python
class UnreadablePage(Exception):
    def __init__(self, message: str, *, filename: str) -> None: ...
    filename: str   # the base name of the first undecodable file, in order_filenames order
```

`str(error)` is unchanged (`"cannot decode page {filename}: {error}"`); the one
raiser is `read_chapter` (intake.py:77) and passes `filename=filename`. The UI
names the file from `.filename`, **never by parsing the message**. The existing
catchers - `src/mangatl/cli.py:98` (`str(error)`) and
`tests/core/test_intake.py` (`excinfo.value` message assertions) - are
unaffected; nothing else constructs it (`rg "UnreadablePage\("`, 2026-09-30).
Its test lives in `tests/core/test_intake.py`: `excinfo.value.filename` for the
existing two-bad-files-first-in-order fixture.

**C-2 — the resolution: `mangatl.app.open_folder`.**

```python
def open_folder(folder: Path) -> QMainWindow | Chapter | str: ...

class IntakeError(str):
    """An outcome that is the intake's own error state (AC-2, AC-3, AC-6),
    as opposed to a notice (no such folder, a newer build's project)."""
```

`folder` is resolved first, as today. In order:

1. not a directory → `NO_FOLDER_NOTICE` (plain `str`, unchanged);
2. `open_project(project_dir_for(folder))` succeeds → the `Workspace`
   (unchanged); raises `SchemaTooNew` → its message (plain `str`, unchanged);
3. raises `FileNotFoundError` (no `project.db`, including a bare `.mtproj`
   directory) → `read_chapter(folder)`, and:
   - returns → that `Chapter` (**AC-1**);
   - `NoPagesFound` → `IntakeError("No page images in {folder}. This tool reads .png and .jpg files.")` (**AC-2**);
   - `UnreadablePage` as `e` → `IntakeError("{e.filename} could not be opened as a page image. Remove or replace it, then choose the folder again.")` (**AC-6**);
   - any other `OSError` as `e` → `IntakeError("Windows would not let this app read {folder}.\n{os_error}")`, `os_error = e.strerror if e.strerror is not None else str(e)` (**AC-3**).

`{folder}` is `str(folder.resolve())`, whole. No second directory walk and no
second sort anywhere in `app` or `ui` for the *run* order: it is
`[p.filename for p in chapter.pages]`. `NO_PROJECT_NOTICE` is **deleted**
(`hasattr(app_module, "NO_PROJECT_NOTICE")` is `False`); `create_project` is
still not imported (MT-054's test stays).

**C-3 — the command line: `build_window([folder])`.** For the outcome of
`open_folder`:

- a `QMainWindow` → returned (unchanged);
- a `Chapter` → `MainWindow(open_folder=open_folder)` with `show_summary(chapter)`
  called; **AC-1's CLI path**;
- an `IntakeError` → `MainWindow(open_folder=open_folder)` with
  `show_error(text)` called: the intake window, target in its error state;
  **AC-2/3/6's CLI path**;
- any other `str` → `MainWindow(notice=text)` (unchanged: MT-054's notices).

No-argument and two-argument behaviour is unchanged. Returned NOT shown.

**C-4 — `MainWindow`** (`src/mangatl/ui/main_window.py`).

```python
FolderOpener = Callable[[Path], QMainWindow | Chapter | str]

class MainWindow(QMainWindow):
    def show_summary(self, chapter: Chapter) -> None: ...
    def show_error(self, text: str) -> None: ...
```

- The current view is `window.centralWidget()`: a `FolderDropTarget` or a
  `ChapterSummary`, exactly one. Tests find it there, never by `findChild`
  (a replaced widget may linger until deferred deletion).
- `show_summary`: the central widget becomes a new `ChapterSummary(chapter)`;
  keyboard focus is on its scroll area (`summary-scroll`) once shown.
- `show_error`: the central widget is a `FolderDropTarget` (a new one if the
  summary was showing, wired exactly as the constructor wires it - `activated`
  → chooser, `dropped` → hand-over) in its error state with `text` as headline.
- The one hand-over path (MT-056 C-2), for a chosen, dropped, or
  summary-chosen folder: `QMainWindow` → shown, this window closes (unchanged);
  `Chapter` → `show_summary`; `str` (including `IntakeError`) → `show_error`.
- The summary's `choose_other` signal → the same `_choose` as the target's
  `activated`: the injected chooser, and on `None` nothing changes (the same
  summary stays, focus back on its button).

**C-5 — `ChapterSummary`** (new module `src/mangatl/ui/summary.py`,
`__all__ = ["ChapterSummary"]`).

```python
class ChapterSummary(QWidget):
    choose_other = Signal()
    def __init__(self, chapter: Chapter, parent: QWidget | None = None) -> None: ...
```

Parts, found by **object name** (a part the rule says is absent is **not
created**: `findChild(QWidget, name) is None`, not merely hidden):

| objectName | type | text |
|---|---|---|
| `chapter-summary` | the widget itself | - |
| `summary-scroll` | `QScrollArea`, horizontal scroll off, focusable | accessible name `Chapter summary`; description = the visible lines of the parts below in order, joined by `\n`, heading as the **uncut** base name, notice as its three lines |
| `summary-name` | `QLabel` | `_display_name(source_dir)` - base name, 40-char middle cut (first 20, `…`, last 19; drive root: the path); accessible name the uncut base name |
| `summary-count` | `QLabel` | `1 page` / `{n} pages` |
| `summary-first` | `QLabel`, only when ≥ 2 pages | `First page: {first}` |
| `summary-last` | `QLabel`, only when ≥ 2 pages | `Last page: {last}` |

| `summary-order-notice` | `QFrame`, only when the orders differ | accessible name = its three lines joined by `\n` |
| `order-lead` | `QLabel` in the notice | `These filenames sort differently as numbers and as text. The run uses natural order.` |
| `order-natural` | `QLabel` in the notice | `Natural order (used): ` + `", ".join(natural)` |
| `order-lexical` | `QLabel` in the notice | `Text order (not used): ` + `", ".join(lexical)` |
| `summary-choose` | `QPushButton`, **outside** the scroll area | `Choose a different folder`; clicked, Enter or Space → `choose_other` |

- `natural = [p.filename for p in chapter.pages]` (the chapter's order - which is
  `order_filenames`, by `read_chapter`); `lexical = sorted(natural)` (plain
  code-point order). The notice exists iff `lexical != natural`. Every filename
  listed, never elided.
- Every label: `Qt.TextFormat.PlainText` set before the text, word-wrapped,
  `TextSelectableByMouse` only, `Qt.FocusPolicy.NoFocus`.
- `summary-choose` is the **only** `QAbstractButton` in the widget: no Start
  button (Out of scope). The summary does not accept drops
  (`acceptDrops()` is `False` on it and on the window's central widget).
- Tokens (`## Design notes`) are GREEN's styling; tests do not pin pixels.

**C-6 — AC-5's no-write oracle.** Before and after: every path under
`tmp_path` (the folder's parent) with the SHA-256 of every file, compared for
equality; and `folder.with_name(folder.name + ".mtproj")` does not exist
afterwards (or, for the bare-`.mtproj` case, still holds nothing).

**C-7 — AC-3's fixture.** No real ACL: `pathlib.Path.iterdir` is monkeypatched
to raise `PermissionError(13, <probe text>, str(path))` **only** for the chosen
folder's resolved path, and delegates otherwise; `<probe text>` is a string no
constant could contain (e.g. `"Access is denied (probe 7f3a)"`), so the test
shows the OS text is passed through, not written. This is a mechanism claim: if
RED finds `read_chapter` does not reach `iterdir` for the folder (or another
caller trips the patch), amend this block rather than work around it.

**C-8 — fixtures.** Page images are real PNG bytes (the intake tests' `_png` via
`QImage`, or Pillow), never `b"not read"` except where a file is *meant* not to
decode (AC-6). AC-1 uses a folder whose natural and lexical orders differ *and*
whose first/last differ from directory-listing order, so a summary built from
`iterdir()` order or `sorted()` fails.

## Design notes

*Lead Designer, 2026-09-30.* The source is `docs/wiki/design/components.md` §2
(amended today for PO-4/PO-5); this is its MT-057 slice, repeated so RED need
not hunt. Strings are character-exact; `{…}` are placeholders; `\n` is one

**AC-6 wording (designer's, differs from the PO draft):**
`{filename} could not be opened as a page image. Remove or replace it, then choose the folder again.`
- "an image" → "a page image" (voice.md says *page*; matches AC-2's "page
  images"); "and choose" → ", then choose". `{filename}` is the base name as in
  the folder, whole; with two bad files, the first in `order_filenames` order.

**Error headlines** (drop target error state, the reason verbatim as headline,
affordance "Choose a different folder" as today):
- AC-2: `No page images in {folder}. This tool reads .png and .jpg files.` (no
  backticks - they were formatting in the story, not copy)
- AC-3: `Windows would not let this app read {folder}.` + `\n` + `{os_error}`
- `{folder}` is the resolved full path, as MT-054/MT-055's texts print it.
  `{os_error}` is the `OSError`'s `strerror` if not `None`, else `str(error)`.

**`ChapterSummary`** (populated state; replaces the drop target). Top to bottom,
parts 1-5 inside a `QScrollArea` (vertical as needed, horizontal off), part 6
pinned below it:

| # | Copy | Token |
|---|---|---|
| 1 heading | `{name}` | `type.title`, `color.text.primary` |
| 2 count | `1 page` / `{n} pages` | `type.body`, `color.text.primary` |
| 3 first | `First page: {first}` | `type.body`, `color.text.secondary` |
| 4 last | `Last page: {last}` | `type.body`, `color.text.secondary` |
| 5 notice | three lines below, only when orders differ | see below |
| 6 leave | `secondary` button `Choose a different folder` | components.md §1 |

- `{name}`: folder base name (drive root: the path), **40-char middle cut
  applies** (first 20 + `…` + last 19; exactly 40 whole). Heading's accessible
  name is the uncut base name.
- Exactly one page: parts 3-4 become one line `Only page: {first}`; no "Last
  page" line.
- Spacing `space.2` under heading, `space.1` between 2-4, `space.4` above the
  notice and above the button.

**Order notice** (AC-4). Shown iff `sorted(names) != order_filenames(names)`:
1. `These filenames sort differently as numbers and as text. The run uses natural order.` (`type.body-strong`)
2. `Natural order (used): {natural}` (`type.body`)
3. `Text order (not used): {lexical}` (`type.body`)

Separator `", "`. Every filename listed, never elided (200 pages = 200 names per
line); lines word-wrap, the summary scrolls vertically. Ground
`color.surface.raised`, 1px border `color.status.warning`, `radius.sm`, padding
`space.3`, `space.1` between lines. No glyph, no control, not an `Alert`, not
announced.

**Leaving the summary** (designer's decision). The button opens the same
`choose_folder_dialog`; its result goes down `MainWindow`'s one hand-over path
(new summary / drop-target error / workspace). Dismissed → summary unchanged,
focus back on the button. **Drops onto the summary are not accepted** in this
story (no `acceptDrops`; nothing changes) - out of scope, recorded.

**Accessibility, and what tests should assert:**
- Focus order: scroll area → button. On the summary appearing, focus is on the
  scroll area (focus ring per A-04); it scrolls with arrows/Page/Home/End.
  Button: Enter and Space activate. Labels are never focus stops.
- Scroll area accessible name `Chapter summary`; accessible description = the
  visible lines of parts 1-5 in order joined by `\n`, heading line uncut.
  Notice widget's accessible name = its three lines joined by `\n`.
- A folder named `a<b>c` (or a file) shows literally, not as markup.
- Assert: exact strings above; singular `1 page`; `Only page:` for one page and
  no `Last page:`; notice absent for `p1…p9`, present for `p1…p12` with both
  full lists; the button reaches the chooser by keyboard and a chosen folder
  with no images replaces the summary with AC-2's error; no Start button exists.

## Notes

### Open questions

None open. All three were answered by the user on 2026-09-30 ("accept all
recommendations") and are recorded as PO-3 to PO-5 below; the questions are
kept as they were put.

- **Q1 — RESOLVED (a), PO-3. Does `mangatl <folder>` change too?** MT-055 made the picker
  and the command line share one resolution, and the user asked that a picked
  folder "behave exactly as `mangatl <folder>` does". With this story the picker
  shows a summary for a folder with no project. Either (a) the command line
  does too, and MT-054's "No project exists … run `mangatl-run`" notice retires
  for folders of pages (MT-054 AC-3's tests are rewritten here, deliberately);
  or (b) the command line keeps the notice and the two paths diverge here for
  the first time. **Lead PO recommends (a)**: one resolution, and a user who
  typed `mangatl <folder>` also wants to run it. Changes AC-1's scope and the
  caller list.
- **Q2 — RESOLVED (a), PO-4. A page that will not decode.**
  `components.md` §2 says it "loads anyway; the bad page is listed in
  `ChapterSummary` as skipped with its filename". The store does the opposite
  on purpose: `read_chapter` raises `UnreadablePage` on the first undecodable
  file, because "a partial chapter would give every later page a wrong ordinal,
  and the ordinal is the page's identity for the rest of the product" (MT-004).
  Options: (a) the summary shows the error state naming the file - the store's
  rule, and the CLI's behaviour; (b) change the store to skip and keep ordinals
  stable, which is a data-model change and its own story; (c) the design's
  wording is read as "copied to the output unchanged" (`PageCanvas` error
  state), which needs (b) anyway. **Lead PO recommends (a) for v1**, and asks
  the designer to amend §2. AC-6 is written from the answer.
- **Q3 — RESOLVED (a), PO-5. The "Use natural order" toggle.** The design shows both orders
  and a toggle, default on. The store has one order, natural
  (`order_filenames`); a toggle to lexical order would have to reach
  `create_project`, whose page ordinals are "filename order at intake and never
  change" (`architecture.md` §4). Options: (a) the warning lists both orders
  and states that natural order is used, no toggle; (b) the toggle, with the
  store change it needs (a separate story before MT-059). **Lead PO recommends
  (a)**: the hazard the design names is *silently* wrong order, and the warning
  removes the silence.
