## Context

One migration for the epic. Four later stories each need something the store
cannot hold today, and a migration per story would be four schema versions
in one epic, each a RED->GREEN of its own on the same `schema.py`. The
sizing rule's second axis (`story-authoring`, footprint) says two stories
that must share a file are one story or two waves; four that must share
`schema.py` are one story. Each addition is observable on its own and has
its own criterion.

What the store needs (schema v7 -> v8, `src/mangatl/store/project.py:111`):

1. **A chapter-level ledger row.** `llm_call.page_id` is `NOT NULL
   REFERENCES page(id)` (`store/schema.py:125`). The glossary pre-pass
   (MT-105) and the consistency pass (MT-115) are calls about the chapter,
   not a page. `page_id` becomes nullable.
2. **The pricing tier on a ledger row** (EPIC-09 PO-4), `llm_call.pricing`,
   so the ledger says which rate priced a call. Reads `CostRecord.pricing`
   (MT-102).
3. **A `batch_job` table** (MT-111, MT-112): the provider's job name, the run
   that submitted it, its state, so a closed app can resume collecting.
4. **A `correction` table** (MT-115): what the consistency pass changed, from
   what, and why.
5. **`chapter.glossary_proposed_at`** (MT-105): the pre-pass runs once per
   chapter, and the marker must survive a crash between the pass and page 1.

**One consequence for the guard.** `chapter_call_costs` feeds
`Budget.project` as per-page samples (`translate_stage.py:213`). A
chapter-level row is not a page sample: a $0.50 glossary pass averaged into
200 pages of $0.03 would put the projection $0.0025 a page high, and a
$0.50 pass averaged into two priced pages would triple it. So
`chapter_call_costs` returns **page rows only**, and `chapter_total` (what
was spent) returns **every** row. Both are stated in the contract and pinned.

Required gates that fail if this breaks: `unit`, `coverage` (`tests/core`).
A v7 fixture project is committed for the migration test, as `test_schema_v7.py`
did for v6 -> v7.

## Acceptance criteria

- **AC-1** - Given a project file at schema 7 with two priced calls, when it
  is opened, then its `schema_version` is 8, both calls read back with
  `pricing == "standard"`, their costs unchanged, and `SchemaTooNew` is
  raised by the previous release's reader - the existing v7 test's pattern.
- **AC-2** - `record_call(project, run_id, None, request_id, record)` writes
  a row with `page_id NULL`; `chapter_total` includes it; `chapter_call_costs`
  does **not**; `run_total` includes it. With one page row of $0.03 and one
  chapter row of $0.50, `chapter_call_costs` is `($0.03,)` and `chapter_total`
  is `$0.53`.
- **AC-3** - `record_call` with a `CostRecord(pricing="batch")` stores
  `pricing = 'batch'` and the row reads back so; the append-only triggers
  still refuse `UPDATE` and `DELETE` on `llm_call`.
- **AC-4** - `record_submission(project, run_id, "batches/abc", "gemini-3.1-pro-preview")`
  returns a job id; `pending_job(project)` returns that job with state
  `"submitted"`; after `mark_collected`, `pending_job` is `None` and the job
  reads back `"collected"` with a `collected_at`; after `mark_failed(...,
  "reason")` it reads back `"failed"` with the reason. A second
  `record_submission` while one is pending raises `BatchPending` naming the
  pending job.
- **AC-5** - `record_correction(project, run_id, ordinal, reading_index,
  before_en, after_en, reason)` writes a row; `corrections_for(project,
  ordinal)` returns that page's corrections in `reading_index` order, each
  carrying the four strings and the run id; a page with none returns `()`.
- **AC-6** - `glossary_proposed_at(project)` is `None` on a fresh project;
  `mark_glossary_proposed(project)` sets it to a UTC ISO timestamp and a
  second read returns the same value.

    id              INTEGER PRIMARY KEY,
    run_id          INTEGER NOT NULL REFERENCES run(id),
    provider_job_id TEXT    NOT NULL,

    id            INTEGER PRIMARY KEY,
    run_id        INTEGER NOT NULL REFERENCES run(id),

    reading_index INTEGER NOT NULL,
    before_en     TEXT    NOT NULL,
    after_en      TEXT    NOT NULL,
    reason        TEXT    NOT NULL,
    at            TEXT    NOT NULL
);

Semantics: `pricing` is stored as `record.pricing` verbatim; `chapter_call_costs`
filters `page_id IS NOT NULL`; `pending_job` is the one row with state
`submitted` (at most one, by `BatchPending`); timestamps are
`datetime.now(UTC).isoformat()` as `ledger.py` writes them.

**Changed signature and callers:** `record_call`'s `ordinal` widens to
`int | None` - no caller breaks: `src/mangatl/pipeline/translate_stage.py`,
`tests/core/test_ledger.py`, `tests/core/test_call_priced.py`,
`tests/core/test_budget_run.py`, `tests/core/test_bench_cost.py`,
`tests/ui/test_run_progress_cost.py` (RED confirms the list against the tree).

Oracle partition: all **mechanical**. Fixture: a v7 project file committed
under `tests/core/fixtures/`, produced by the current release before this
story's GREEN - RED writes it in RED (it is a test fixture) with a note of the
commit that produced it.
