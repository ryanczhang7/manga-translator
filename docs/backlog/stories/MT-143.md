## Context

EPIC-13 enabler. The epic's evidence was read off the held-out benchmark
(*Black Jack* vol. 1 pages 3-58). No EPIC-13 story may derive a constant from
it, or measure its before/after on it. This spike builds the set they use
instead, and records the baseline each one is judged against.

**Pages.** One whole episode of the same volume, from `D:\bench\all-jp`
outside 3-58 (209 pages, 1414x2000, official English page-aligned in
`D:\bench\all-en`). The spike finds the episode boundary from the title page
and records it. If that episode is under 30 pages, the next one is added.

**Why a spike.** The output is a truth document, an audit and a baseline. No
production code is written. The document lives beside the scans, outside the
repo (the scans are not ours to commit), and the audit records its sha256 so
that every later measurement can name the exact file it was made against.

## Acceptance criteria

- **AC-1** - `D:\bench\<name>.truth.json` exists, is flagged
  `development_use: true`, validates with `bench.truth.validate` against its
  project, and has been confirmed region by region by the user. The
  confirmation is recorded per region, in the MT-108 truth's
  `note: confirmed by the user <date>` form. It was seeded with `python -m
  mangatl.bench.seed` and corrected by a review pass using the benchmark
  truth's rules: art text out, per `product-brief.md` §5, and fragments
  refit to one region per balloon.
- **AC-2** - `docs/wiki/audits/MT-143-development-set.md` records the page
  range, the commit the detector ran at, the document's sha256, and the
  verbatim output of `python -m mangatl.bench FOLDER --development` (MT-142)
  on the seed run. It records the S2 lines in full, and the S1 lines as
  well if a translation ran.
- **AC-3** - The audit tables the counts each EPIC-13 story's before/after
  reads, each measured, with the method stated:
  - fragmented balloons, and the pieces in them (a seed region whose pixels
    lie at least 50 % inside one truth region, but which matches none at IoU
    0.5);
  - art-text regions (a seed region at least 50 % outside every truth
    region);
  - the along-run and across-run gaps between pieces of one balloon, and
    between regions of *different* balloons that share a fence box (MT-145's
    negative);
  - truth regions with a long side over 448 px (MT-151);
  - regions over `RESIDUAL_INK_MAX`, with their crops looked at and the
    cause named;
  - pairs of regions sharing one `bubble_interior` (MT-155).
- **AC-4** - The audit lists each count's benchmark-chapter figure from
  EPIC-13's "Evidence" beside the development figure, and says whether the
  development set shows the same defect at a comparable rate. If a defect
  does not occur on the development set, it says so, and names which story
  then lacks a development before/after.

## Contract

**Writes:** `docs/wiki/audits/MT-143-development-set.md`

- The truth document and the scratch scripts that count are **not** in the
  repo. The counting method is written into the audit precisely enough to be
  re-run.
- A translation run on the development set is a **paid** run (Gemini, about
  $0.011 a page on MT-108's figure). It happens only if the user asks for it.
  Without one, the audit carries the S2 lines only, which need no
  translation.
- Oracle partition: AC-1 is the user's judgement (**oracle-free**; the
  control is the MT-108 review rule, applied unchanged). AC-2 to AC-4 are
  **mechanical** counts.
