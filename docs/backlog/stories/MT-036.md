## Context

**Filed in MT-010's PLANNED phase, 2026-09-16, by user decision (MT-010 PO-4).**
It is the third instance of the same gap: MT-009 PO-4 filed MT-035 because
MT-007/008/009 shipped correct pure functions nothing invoked, MT-035 PO-1
predicted the gap would recur one stage later, and it did.

After MT-010 the project has `DetectStage` and `OcrStage`, both correct, both
tested, and **neither is in any stage list**. `cli.py` still calls
`run_chapter(project, [PassThroughStage()], ...)`. EPIC-03's done-when —
*"Given a page scan, **the pipeline produces** regions … each carrying
transcribed vertical Japanese"* — is true of no command a user can run until
this story lands.

## The blocker this story exists to remove

A composition root must construct real ONNX sessions. Every candidate module is
forbidden from doing so. Measured in MT-010's PLANNED phase:

```
Only detect, ocr and clean import onnxruntime BROKEN
mangatl.cli is not allowed to import onnxruntime:
-   mangatl.cli -> mangatl.detect.page (l.113)      <- inside a function body
    mangatl.detect.page -> mangatl.detect.session (l.64)
    mangatl.detect.session -> onnxruntime (l.32)
```

import-linter analyses function bodies, so a lazy import is **not** an escape —
that was probed, not assumed. The contract's `source_modules` list names
`mangatl.app`, `mangatl.cli`, `domain`, `store`, `translate`, `typeset`,
`pipeline`, `bench`, `ui`, with no `allow_indirect_imports`.

Removing the entry points from that list has a direct in-repo precedent: the
*"Nothing imports ui"* contract already omits `mangatl.app` with the recorded
reason *"the entry point's whole job is to open the window, and a contract
forbidding that breaks `scripts/task.sh dev`."* The architectural value of the
onnxruntime contract is confining the runtime away from `domain`, `store`,
`pipeline`, `translate`, `typeset`, `bench` and `ui` — and that survives intact.

Note the counter-precedent before deciding: MT-006 PO-5 *added* `mangatl.cli` to
the "Nothing imports ui" contract deliberately, to make headlessness enforceable.
An exemption here must not quietly undo that; they are different contracts and
the story must say so.

**This is an `architecture.md` §3 amendment and it is the first acceptance
criterion, not a side effect.**

## Acceptance criteria

*Draft — to be confirmed against the tree when this story is advanced, which is
the last phase in which they may change without an `## Amendments` entry.*

- **AC-1** — Given the amended `architecture.md` §3 and `pyproject.toml`, when
  `lint-imports` runs, then five contracts are still reported `kept`, the
  confinement contract still forbids `onnxruntime` to `domain`, `store`,
  `pipeline`, `translate`, `typeset`, `bench` and `ui`, and a probe module
  placed in each of those still breaks it.
- **AC-2** — Given a detector callable and a transcriber callable, when the
  stage list is built, then it is `(DetectStage, OcrStage)` in that order, named
  `"detect"` and `"ocr"` — asserted without loading a model.
- **AC-3** — Given a chapter folder, when `mangatl-run` executes, then the
  stages it runs are the built list and not `PassThroughStage`.
- **AC-4** — *(integration)* Given the real weights and the fixture pages, when
  a run completes, then every page has regions in reading order and every region
  has a line, and the chapter's stored text matches MT-002 E5's nine
  transcriptions on `014.jpg`.
- **AC-5** — Given a run interrupted after detection, when it is resumed, then
  detection is skipped and OCR is not — `is_done` is per stage per page.

## Notes

### Why this could not be folded into MT-010

MT-010 already carries ten criteria and seven new modules, above the project's
demonstrated cycle size, and two of its criteria need the real GPU. Adding an
architecture amendment to it was put to the user with that cost stated and
declined in favour of this story.

### What MT-010 hands over

`PageDetector` (MT-035 C-3) and `PageTranscriber` (MT-010 C-1) are both plain
`Callable`s over stdlib and `domain` types, so the stage list can be assembled
without either package being imported by `pipeline`. The composition root is the
only place that may bind them to real sessions.
