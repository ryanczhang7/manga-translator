## Context

**Filed in MT-010's PLANNED phase, 2026-09-16, by user decision (MT-010 PO-4).**
It is the third instance of the same gap: MT-009 PO-4 filed MT-035 because
MT-007/008/009 shipped correct pure functions nothing invoked, MT-035 PO-1
predicted the gap would recur one stage later, and it did.

After MT-010 the project has `DetectStage` and `OcrStage`, both correct, both
tested, and **neither is in any stage list**. `cli.py` still calls
`run_chapter(project, [PassThroughStage()], ...)`. EPIC-03's done-when —
*"Given a page scan, **the pipeline produces** regions … each carrying
transcribed vertical Japanese"* — is true of no command a user can run until
this story lands. **EPIC-03 closes on this story, not on MT-010** (PO-8).

**The required gate that fails if this story's artifact breaks.** `unit` and
`coverage` both carry `covers: src/mangatl/**`, so every source file this story
writes is read by a required gate. But the *artifact* — a real chapter walked by
real sessions — is exercised only by `integration`, which is `optional` for the
repository. `required_gates: [integration]` in the frontmatter above makes it
binding for this story, and that is a PO decision taken here rather than
discovered in GATES. Its `blocked-when` expression means a machine without CUDA
reports `BLOCKED` rather than `FAIL`; on the development machine CUDA is
present and MT-010 ran the same gate in 6 s.

A composition root must construct real ONNX sessions. Every candidate module is
forbidden from doing so.

**Reproduced independently by the orchestrator on 2026-09-17**, against this
tree rather than inherited from MT-010's PLANNED measurement, with one top-level
`from mangatl.detect.page import detect_page_regions` added to `cli.py` through
`scripts/mutate.sh` (restored and verified byte-for-byte afterwards):

```

---------------------------------------------

mangatl.cli is not allowed to import onnxruntime:

-   mangatl.cli -> mangatl.detect.page (l.32)
    mangatl.detect.page -> mangatl.detect.session (l.64)
    mangatl.detect.session -> onnxruntime (l.32)

--- PROBE CONFIG (cli removed from onnx contract) ---

domain is independent KEPT
Nothing imports ui KEPT
```

Two things that were *measured*, not assumed. import-linter analyses function
bodies, so a lazy import is not an escape. And removing `mangatl.cli` from that
one contract's `source_modules` — **one name, nothing else** — is sufficient:
the other four contracts, "Nothing imports ui" included, stay `KEPT` with the
offending import still in place.

**This is an `architecture.md` §3 amendment and it is the first acceptance
criterion, not a side effect.** The amendment is written: `architecture.md` §3
now carries *"The composition-root exception to rule 5"*, with this measurement,
the eight modules the rule still confines, and the two things the amendment
deliberately does not do.

### C-1 — `src/mangatl/pipeline/stages.py` (new). AC-2.

```python
__all__ = ["build_stages"]

def build_stages(detect: PageDetector, transcribe: PageTranscriber) -> tuple[Stage, ...]:
    """The pipeline's stage list: detect, then OCR."""
```

- Returns **exactly** `(DetectStage(detect=detect), OcrStage(transcribe=transcribe))`,
  a `tuple`, in that order. Order is semantic, not stylistic: `OcrStage.run`
  reads `ctx.project.read_regions(...)`, so OCR before detect transcribes the
  *previous* run's regions on a resume and nothing at all on a fresh page.
- It lives in `pipeline` and imports only `pipeline.detect_stage` and
  `pipeline.ocr_stage`, both of which are already onnx-free by construction.
  **That is why AC-2 is assertable without a model**, and it is the reason this
  function is not in `compose.py`: the *list* is a pipeline fact, the *sessions*
  are not.
- `Stage` is the `Protocol` in `pipeline/stage.py`. The return type is
  `tuple[Stage, ...]` and not a two-tuple of concrete classes, so a later story
  adding `translate` is a one-line change here and nowhere else.

### C-2 — `src/mangatl/compose.py` (new, top level). AC-3.

The composition root: the one module allowed to build real sessions. Named in
`architecture.md` §3's amendment.

```python
__all__ = [
    "DETECTOR_FILENAME",
    "MODELS_ENV",
    "OCR_SUBDIR",
    "PROVIDER_PREFERENCE",
    "ModelsNotFound",
    "build_pipeline",
    "resolve_models_dir",
]

MODELS_ENV: str = "MANGATL_MODELS"
DETECTOR_FILENAME: str = "comic-text-detector.onnx"
OCR_SUBDIR: str = "manga-ocr"
PROVIDER_PREFERENCE: tuple[str, ...] = ("CUDAExecutionProvider", "CPUExecutionProvider")

class ModelsNotFound(Exception):
    """No models directory was given, or it does not hold what is expected."""

def resolve_models_dir(override: Path | None, env: Mapping[str, str]) -> Path: ...
def build_pipeline(models_dir: Path) -> tuple[Stage, ...]: ...
```

- **`resolve_models_dir` is pure and takes the environment as an argument.**
  `override` first, then `env[MODELS_ENV]`, then `ModelsNotFound`. Taking the
  mapping rather than reading `os.environ` is what makes every branch testable in
  `tests/core` without `monkeypatch.setenv`, and it is what keeps this function
  inside the `coverage` gate's reach.
- It raises `ModelsNotFound` when neither is given, **and** when the resolved
  path is not a directory. It does **not** check that the four weight files are
  present: that is `build_pipeline`'s business, and a `resolve` that stats files
  cannot be tested without them.
- **AMENDED IN RED, 2026-09-17 — an empty `$MANGATL_MODELS` is "not given", not
  "the current directory".** `Path("")` is `Path(".")` and `Path(".").is_dir()`
  is `True` (checked on this machine; the test carries the check as its own
  premise), so a resolver that asks only "is the variable present?" answers *the
  directory the user happened to be standing in* for `MANGATL_MODELS=`, and
  `build_pipeline` then fails with an onnxruntime error about a missing file
  instead of the sentence PO-4 asked for. An unset variable and an empty one are
  the same statement, and this is the one branch where the difference between
  them is a stack trace. Pinned by
  `test_compose.py::test_an_empty_environment_variable_is_not_a_models_directory`.
  Nothing else in C-2 changes.
- **AMENDED IN RED, 2026-09-17 — the `ModelsNotFound` raised when neither is
  given must name `MODELS_ENV` in its message.** PO-4 says the failure names
  both `--models` and `$MANGATL_MODELS`; `--models` is the argument parser's
  word and belongs to `cli.py`, and the variable is the half this module can be
  held to. Pinned by `test_compose.py` (the exception's `str`) and by
  `test_cli.py` (the same string reaching stderr). The rest of the message, and
  the message of the not-a-directory branch beyond naming the path, are
  deliberately unconstrained.
- `build_pipeline(models_dir)` calls `load_detector`, `load_ocr` and
  `load_vocab`, binds `partial(detect_page_regions, detector)` and
  `partial(transcribe_page_regions, ocr, vocab)`, and returns
  `build_stages(...)`. It is the only function in the project that may do any of
  that. It is **not** coverable by `tests/core` and is not expected to be; see
  PO-7 for the headroom measurement.
- `PROVIDER_PREFERENCE` is CUDA then CPU, **not** CUDA/DirectML/CPU. D3's
  correction in `architecture.md` records that the chain is a packaging choice
  between mutually exclusive wheels, not a runtime fallback, and this project
  installs `onnxruntime-gpu[cuda,cudnn]`. MT-024 owns the real
  `select_providers`; this constant is the interim and says so in its docstring.
- **`compose` must not import `mangatl.ui`.** It is listed in the *"Nothing
  imports ui"* contract by C-5.

### C-3 — `src/mangatl/cli.py` (changed). AC-3.

- New optional argument: `--models PATH`, `type=Path`, `default=None`,
  `help="directory holding the model weights (or set MANGATL_MODELS)"`.
- `main(argv: Sequence[str] | None = None) -> int` — **signature unchanged.**
  No test-only parameter.
- The seam is a module attribute. `cli.py` does
  `from mangatl.compose import ModelsNotFound, build_pipeline, resolve_models_dir`
  and calls `build_pipeline(...)` by that name, so a `tests/core` test
  monkeypatches `mangatl.cli.build_pipeline`. That is the whole mechanism by
  which AC-3 is assertable with no weights on the machine, and the reason the
  composition root is a separate module rather than four more lines of `main`.
- Order inside `main`: resolve the models directory **before** `read_chapter`,
  so a missing `--models` fails in one line without creating a project
  directory. `ModelsNotFound` is caught and turned into `_fail(str(error))` —
  exit 1, one sentence on stderr, no traceback, exactly as `NoPagesFound` is.
- The call becomes `run_chapter(project, stages, _reporter(filenames), _never)`
  where `stages = build_pipeline(models_dir)`. `PassThroughStage` is **no longer
  imported by `cli.py`**. It stays in `pipeline/stage.py` — it is the identity
  element the runner tests use, not a placeholder to delete.
- `mangatl-run` now fails on a machine with no weights where it previously wrote
  an `_en` folder. That is intended (PO-4) and is the visible half of the gap
  this story closes.

### C-4 — `src/mangatl/pipeline/runner.py` (changed). AC-5.

**This is a behaviour change to shipped code and the one place this story can go
wrong quietly.** Measured by the orchestrator at PLANNED on 2026-09-17: the
runner today consults `is_done` **only** in the page-level `all(...)` check and
then runs every stage unconditionally.

```
detect.ran = [0, 1]      # is_done() was True for every page
ocr.ran    = [0, 1]
events     = ['RunStarted', 'PageStarted', 'StageFinished:detect',
              'StageFinished:ocr', 'PageStarted', 'StageFinished:detect',
              'StageFinished:ocr', 'RunFinished']
```

So AC-5 is not satisfied by the current runner, and `Stage`'s own docstring —
*"is_done … is per stage per page … a page that has regions but no translations
resumes at translation"* — is a claim no code makes true. The change:

1. **Inside `_run_page`'s stage loop, a stage whose `is_done(ctx)` is `True` is
   not run.** `stage.run` is not called and no `StageFinished` is emitted for it.
2. **The page-level skip stays exactly as it is.** `if stages and all(stage.is_done(ctx) for stage in stages)`
   still emits `PageSkipped` and returns before `PageStarted`. This is not
   redundant with (1) and removing it breaks two frozen expectations:
   `_RESUMED_PROJECTION` in `tests/core/test_pipeline.py`, and
   `tests/core/test_detect_stage.py:487` which asserts a fully-detected page is
   skipped rather than started. **Both behaviours, not one replacing the other.**
3. `cancelled()` is still consulted at the top of the stage loop, **before** the
   `is_done` check, so the cancel boundary does not move.
4. `_mark_done` still runs at the end of a page that was not page-skipped, even
   if every stage in it was individually skipped.
