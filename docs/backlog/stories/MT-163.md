## Context

Filed by the EPIC-02 mutation audit, `docs/wiki/audits/EPIC-02-2026-11-25.md`
(`## Decided` 5, `## Evidence` E-5). The audit found no surviving mutant here.
No code calls the behaviour, so there is no line a mutant could change.

EPIC-02's done-when ends: "and replacing one input scan invalidates only that
page". MT-005 built that as `Project.refresh_from_source`
(`src/mangatl/store/project.py:1352`), and it is well tested on its own: audit
mutants B04, B05, B06 and B08 were all killed. But nothing in `src/` calls it.
`mangatl-run`'s resume path (`src/mangatl/cli.py:260-263`) reopens the project
and runs it without re-reading the folder. So when a user replaces a scan, the
product never notices.

**Open question, to put to the user before this story leaves PLANNED.**
EPIC-11 Q-3 asks: "Should a re-run first re-read the source folder
(`refresh_from_source`), so a replaced scan is re-detected? `mangatl-run` does
not. Recommended default: not in MT-125". That default put the question off;
it did not answer it. This story is the "yes, for `mangatl-run`" answer.

If the user says no, close this story as not wanted. The Lead PO then amends
EPIC-02's done-when so that the epic stops promising what the product does not
do. Either outcome removes the contradiction. Keeping both the promise and the
current behaviour does not.

**What is settled.** The library behaviour works, and the entry point does not
call it today (audit E-5, a grep anyone can repeat).

**What is evidence, to verify.** The audit worked out what a re-run writes
today after a scan is replaced by reading the code. It did not run it. RED's
first test will measure it.

**Required gate that would fail if this broke:** `unit`.

## Acceptance criteria

- **AC-1** - Given a chapter that one `mangatl-run` invocation has finished,
  and one scan in its folder replaced by different bytes under the same
  filename, when `main` is invoked again, then the composition root's stages
  run for that page and for no other page.
- **AC-2** - Given the same re-run, when it finishes, then the replaced page's
  file in the output folder is derived from the new scan, and every other
  page's output file is byte-identical to the first run's.
- **AC-3** - Given a finished chapter whose folder has not changed, when `main`
  is invoked again, then no stage runs for any page. The refresh must not make
  an unchanged chapter look stale.

## Contract

**Writes:** `src/mangatl/cli.py`, `tests/core/test_cli.py`

- Call `project.refresh_from_source()` on the resume path, after the reopen and
  before `run_chapter`. GREEN chooses the exact place, with two limits: it must
  be inside the `with project:` block, and it must not be on the first-run
  path, where `create_project` has only just read the folder.
- `refresh_from_source` raises `NoPagesFound` or `FileNotFoundError` when the
  folder has been emptied or deleted (see its docstring). `main` already calls
  `read_chapter` first and returns `_fail(...)` for `NoPagesFound`. RED must
  establish whether the refresh can still reach that case, not assume it.
- The test seam is the existing `composition_root` fixture in
  `tests/core/test_cli.py`. `_CountingStage.ran` records which pages a stage
  ran for.
- `refresh_from_source` itself does not change. Its contract is MT-005's:
  match by filename, ignore a new file, mark a page whose file is gone as
  stale.
- **Callers of changed signatures:** none. No signature changes.
