## Context

Split out of MT-024 by its PO-3 (2026-10-08) so that each story is one
RED→GREEN cycle. `architecture.md` **D13** — decided by the user on 2026-09-13 —
ships the GPL-3.0 detector knowingly, conveying weights and not code, and names
five obligations that "MT-024 owns". They are discharged here, by the story
that depends on MT-024's manifest and frozen tree. The evidence behind each is
`docs/wiki/audits/MT-030-detector-licence.md` and MT-002's `## Decided`.

**Do not collapse these into one "credits" criterion.** O-1 to O-3 are copyleft
obligations; O-4 is attribution; O-5 is this project's own rule. A credits
screen discharges O-4 and none of the others (D13).

MT-020 AC-8 already put the font's OFL notice in `mangatl.about.ABOUT_TEXT`
(`src/mangatl/about.py`); "no About screen exists yet (MT-020 PO-5)". Whether
this story adds the screen or only the shipped text files is a PO decision to
record at PLANNED → RED; the brief's constraint is that the notices **ship with
the installer**, which text files in the frozen tree satisfy.

## Acceptance criteria

- **AC-1 (O-1)** — Given the built tree, when it is inspected, then
  `_internal/notices/GPL-3.0.txt` exists and is the full GPL-3.0 text, pinned
  by SHA-256 against the canonical text from `https://www.gnu.org/licenses/gpl-3.0.txt`
  (hash recorded in the story at PLANNED → RED, read out by the test).
- **AC-2 (O-2, O-3)** — Given the built tree, when
  `_internal/notices/THIRD_PARTY_NOTICES.txt` is read, then it names
  `comic-text-detector.onnx` as GPL-3.0, its upstream
  `https://github.com/dmMaze/comic-text-detector`, the Hugging Face export repo
  and revision from `packaging/models.json`, the file's SHA-256, and a
  corresponding-source statement: a URL to the upstream repository at the
  revision used, or a written offer.
- **AC-3 (O-4)** — Given the same file, when it is read, then it states that the
  Manga109-s dataset was used in training the detector, in words that satisfy
  the quoted condition ("the use of the Manga109-s dataset must be indicated
  clearly").
- **AC-4** — Given the same file, when it is read, then it carries one entry per
  manifest entry in `packaging/models.json` — name, repo, revision, SHA-256,
  licence — and the Shantell Sans OFL notice already in `mangatl.about`.
- **AC-5 (O-5, the negative control)** — Given `packaging/notices/notices.json`
  (one entry per `packaging/models.json` entry, keyed by `name`), when a model
  is added to the manifest with no corresponding notice entry, then a test in
  `tests/core` **fails** naming the model; and when a notice entry names a model
  the manifest does not, the same test fails naming it. The test reads both
  real files, so it is red the day the manifest drifts.
- **AC-6** — Given the built tree, when inspected, then
  `THIRD_PARTY_NOTICES.txt` is generated from `notices.json` + `models.json` at
  build time or committed and pinned equal to that generation — RED chooses
  and says which — so the shipped text can never disagree with the manifest.
