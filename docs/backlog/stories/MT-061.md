## Context

**Filed 2026-09-30 by the Lead PO** from a finding recorded in [[MT-057]]'s GREEN
phase: `src/mangatl/ui/theme.qss` is generated from
`docs/wiki/design/theme.qss.in` by `uv run python -m mangatl.ui.tokens`
([[MT-025]]), and `docs/wiki/design/tokens.md` §1 says its consumer is
`QApplication.setStyleSheet` - "all widget chrome". **Nothing in `src/` calls
it.** `mangatl.app.main` runs every window - the folder intake, the
`ChapterSummary`, the review `Workspace`, the notice window - on Qt's default
palette. The finding is verified below (`## Notes`, "Verification of the
finding"), and two consequences of it were found that the finding did not name:

- **`FolderDropTarget` draws no region at all.** Its `paintEvent` hands the
  ground and border to "a stylesheet rule for the target" (`intake.py`), and
  there is no such rule and no sheet. `components.md` §2's dashed 2 px region,
  the hover-valid/hover-invalid borders and the error border are not on screen.
- **Applying the sheet naively breaks two things already shipped.** The base
  sheet's `QWidget { color; font-size; font-weight }` rule beats both
  `setFont` and `setPalette` (QSS wins over both; `high-contrast.md` §2 records
  the same precedence for the palette). So `ChapterSummary`'s heading would drop
  from `type.title` (16 px/600) to `type.body` (13 px/400), and the
  `TranslationRow` status gutter - coloured by `setPalette` in
  `workspace.py` `_render` ([[MT-015]]) - is at risk of losing its five status
  colours. This story turns the sheet on, so it owns not breaking those.

And `ChapterSummary` itself (MT-057) deliberately set only token spacing, type
sizes and a widget-level warning border, and left text colours and the
notice's `color.surface.raised` ground out, because a token text colour
(`#EDEDED`) painted over an unthemed light ground would be unreadable. Once the
sheet is applied that reason is gone, and a widget-level colour becomes a
liability: under High Contrast ([[MT-028]]) the application sheet is
re-composed from the palette, and a colour set on the widget from
`tokens_gen` would bypass that and stay authored.

**What this story is:** apply the generated base sheet at startup, at
application level, before the first window is built; have the Lead Designer
add the `components.md` §2 rules (intake and summary) to `theme.qss.in`; make
the summary and the drop target take every colour, ground, border and type
size from the application sheet and nothing else; and keep the status gutter
and the summary heading as they are.

**What it is not:** High Contrast. [[MT-026]] (resolution) and [[MT-028]]
(detection, re-composition, `apply_theme`) own that, are both PLANNED, and are
not dependencies; see `## Notes`, "Overlap with MT-026 and MT-028".

**Which required gate would fail if this story's artifact broke:** `unit`
(`uv run pytest -q tests/core tests/ui`, required), which runs `tests/ui/`
under `QT_QPA_PLATFORM=offscreen`. The offscreen platform renders a
stylesheet into `QWidget.grab()` exactly as it applies it, so every criterion
below is checkable there. `coverage` reads the same tests. Nothing here needs
an optional gate; `required_gates` stays empty.

## Acceptance criteria

- **AC-1** — Given `mangatl.app.main` is run with no argument, with a folder of
  pages with no project, and with a folder that has a project, when it starts,
  then the application's stylesheet is set **exactly once**, to the **packaged**
  `theme.qss` text (`mangatl.ui` package resource, UTF-8) byte for byte, and it
  is set **before** `build_window` is called - so no window is ever built or
  shown unthemed.
- **AC-2** — Given the application stylesheet is the packaged `theme.qss`, when
  each top-level window `build_window` can return is shown - the intake (empty),
  the intake showing a `ChapterSummary`, the intake in its error state, the
  notice window, and the `Workspace` - then its painted ground is
  `color.surface.base`.
  *Control:* with the application stylesheet empty, the same measurement is
  **not** `color.surface.base` on any of them (the ground is not the token by
  coincidence).
- **AC-3** — Given the application stylesheet is the packaged `theme.qss`, when
  a `ChapterSummary` is shown for a chapter whose filenames sort differently as
  numbers and as text, then every part has the text colour and the type size and
  weight `components.md` §2 gives it - heading `type.title`/`color.text.primary`;
  page count `type.body`/`color.text.primary`; first and last page (and "Only
  page" for a one-page chapter) `type.body`/`color.text.secondary`; notice lead
  `type.body-strong`/`color.text.primary`; natural and lexical lines
  `type.body`/`color.text.primary` - and the order notice's painted ground is
  `color.surface.raised` inside a `border-width.hairline` border of
  `color.status.warning` - and the scroll area's content ground, between the
  parts, is `color.surface.base`.
  *Control:* the heading measured with the application stylesheet empty is not
  `color.text.primary`, and the heading measured with the sheet applied is
  **not** `type.body` size - the regression the base `QWidget` rule causes
  against a widget-level `setFont`. The content ground measured with the
  application stylesheet empty is Qt's light grey `#EFEFEF`, not the token.
- **AC-4** — Given the application stylesheet is the packaged `theme.qss`, when
  the `FolderDropTarget` is shown in each state it has today - **empty**,
  **hover-valid**, **hover-invalid** and **error** - then it paints the border
  `components.md` §2 gives that state (empty: `border-width.emphasis` dashed
  `color.border.interactive`, `radius.md`, ground `color.surface.base`;
  hover-valid: `border-width.emphasis` solid `color.accent.base`, ground
  `color.surface.hover` (DQ-1); hover-invalid and error:
  `border-width.emphasis` solid `color.status.danger`), its body line is
  `color.text.secondary`, and its headline is `type.display`. A drag that leaves,
  and an invalid drop, restore the previous state's **painted** border, not only
  its text.
- **AC-5** — Given the application stylesheet is the packaged `theme.qss`, when
  the `ChapterSummary`'s scroll area and the `FolderDropTarget` each take
  keyboard focus, then each paints a `focus.width` ring in `color.focus.ring`
  (A-04), and loses it when focus moves on.
- **AC-6** — Given an application stylesheet rendered from the **packaged
  template** (`theme.qss.tmpl`) with one colour token replaced by a sentinel
  value no token uses, when the summary and the drop target are shown, then every
  part AC-3 and AC-4 measure in that token shows the **sentinel** - for each of
  `color.text.primary`, `color.text.secondary`, `color.surface.raised`,
  `color.status.warning`, `color.status.danger` and `color.border.interactive` in
  turn. No part of the intake or the summary takes a colour from anywhere but the
  application sheet.
  *Control:* MT-057's `summary.py` as it stands sets the notice's warning border
  on the widget from `tokens_gen`; against it the `color.status.warning` case
  **must fail** (the border stays `#FFC14D`). This is the criterion MT-028
  depends on: it re-composes the application sheet, and only colours that come
  from it follow.
- **AC-7** — Given the application stylesheet is the packaged `theme.qss`, when
  a `TranslationRow` is rendered in each of its five statuses (`proposed`,
  `accepted`, `edited`, `reverted`, `failed`), then the status glyph is
  **painted** in the token `components.md` §5 gives that status - the same
  five tokens `workspace.STATUS_COLOR_TOKENS` names - and a row whose status
  changes repaints in the new status's colour.
  *Control:* the measurement must tell the five apart: on the same rows with a
  sheet whose `QWidget` rule sets `color` to `color.text.primary` and nothing
  for the gutter, at least four of the five fail.
- **AC-8** — Given the application stylesheet is the packaged `theme.qss`, when
  a `Workspace` is shown with pages in its strip and lines in its column, then
  both item views any window `build_window` returns - `Workspace().page_strip`
  (objectName `pageStrip`) and `Workspace().translation_column.list`
  (objectName `translationList`) - paint their viewport ground, below the last
  item, in `color.surface.raised`; and a **non-current** `pageStrip` item (row 1
  or later) shows its text in `color.text.primary`. The current or selected
  item's highlight is not asserted.
  *Control:* with the application stylesheet empty, the same ground pixel is
  `#ffffff`, not the token. This is the regression applying the sheet causes on
  its own: the base `QWidget` rule turns the lists' text `#EDEDED` while their
  viewports stay the default palette's white (about 1.2:1).

### C-1. The loader - `src/mangatl/ui/stylesheet.py` (new, hand-written)

```python
THEME_RESOURCE: str = "theme.qss"

def base_stylesheet() -> str
    """importlib.resources.files("mangatl.ui").joinpath(THEME_RESOURCE),
    read as UTF-8. No caching required. No try/except: a build without the
    file fails at startup, loudly, rather than running unthemed."""

def apply_base_stylesheet(app: QApplication) -> None
    """app.setStyleSheet(base_stylesheet()). Nothing else."""
```

- **Why a package resource and not a path.** `tokens.md` §12.1: "a PyInstaller
  build ships only what the package carries (MT-024)". `theme.qss` must never be
  read from `docs/wiki/design/` or from a path built off `tokens.PACKAGE_DIR`'s
  parents. The wheel already carries it (`## Notes`, check 4).
- **Why a new module and not `theme.py`.** [[MT-026]]'s contract creates
  `src/mangatl/ui/theme.py` as hand-written, **Qt-free** `resolve`, and
  [[MT-028]] extends it with `compose_stylesheet` and `apply_theme`. This story
  must not create `theme.py` ahead of MT-026 or put a Qt import into it. MT-028
  replaces the one call in C-2 with `apply_theme(app, source)`; see `## Notes`.
- **Why not `mangatl.ui.tokens`.** It is a development tool that "never runs at
  application startup" (its docstring) and reads the design sources.

### C-2. The wiring - `src/mangatl/app.py`

`main` becomes, in this order:

```python
app = QApplication(argv)
apply_base_stylesheet(app)        # before build_window: AC-1
window = build_window(argv[1:])
window.show()
return app.exec()
```

`build_window`, `open_folder` and `main`'s signature are **unchanged**.
`build_window` stays unthemed-agnostic: it is the in-process seam, and tests
that call it directly decide for themselves whether a sheet is applied.

### C-3. The theme rules - `docs/wiki/design/theme.qss.in` (Lead Designer, before RED - done)

*Amended at PLANNED, 2026-09-30, to match the Lead Designer's rules and the
user's resolution of conflicts (a)-(e) in `## Design notes`, "Resolution". The
designer's table there is the authoritative selector list.*

The Lead Designer has added, under `components.md section 2` and
`components.md section 5` headings in the template's own comment style, rules
for:

- `#folder-drop-target` keyed on a dynamic property **`state`** whose values are
  exactly `intake.py`'s constants: `"empty"`, `"hover-valid"`,
  `"hover-invalid"`, `"error"` (one rule per state, AC-4);
- the **state-scoped** focus selectors
  `#folder-drop-target[state="empty"]:focus, #folder-drop-target[state="error"]:focus`
  (AC-5) - **not** a bare `#folder-drop-target:focus`, which has the same
  specificity as the state rules, so file order would decide and either order
  is wrong (focus last hides a drag's border; focus first shows no ring).
  Conflict (a). Focus on the drop target is therefore not additive, a named
  A-04 exception recorded in `components.md` §2 (conflict d);
- the drop target's `QLabel#headline` and `QLabel#body` parts, scoped under
  `#folder-drop-target` (both object names are generic). `#affordance` takes
  **no** rule (designer item 3);
- `#chapter-summary`'s parts by their existing object names: `#summary-name`,
  `#summary-count`, `#summary-first`, `#summary-last`, `#summary-only`,
  `#summary-order-notice` **(ground, border, radius)** - no padding, because
  QSS padding adds to the `space.3` contents margins C-4 keeps in Python
  (conflict b) - `#order-lead`, `#order-natural`, `#order-lexical`;
  `QScrollArea#summary-scroll` (ground, and a transparent `focus.width` border at
  rest) and `#summary-scroll:focus`;
- **the scroll content ground**:
  `#chapter-summary QScrollArea#summary-scroll > QWidget#qt_scrollarea_viewport > QWidget`
  → `color.surface.base` (conflict c; AC-3). Without it the reading area is
  Qt's `#EFEFEF` under `#EDEDED` text;
- **the item-view ground**: one base rule
  `QAbstractItemView { background-color: @{color.surface.raised}; }`, before the
  scroll-bar rules (conflict e; AC-8). Specificity (0,0,1): every id rule
  outranks it; no window but `Workspace` contains an item view, and
  `PageCanvas` is a `QGraphicsView`, not an item view, so its surround brush is
  untouched;
- `QLabel#rowGutter[status="proposed"|"accepted"|"edited"|"reverted"|"failed"]`,
  five rules keyed on the **existing** `status` dynamic property, colour =
  `workspace.STATUS_COLOR_TOKENS[status]` (`components.md` §5) - only because
  applying the sheet otherwise takes the gutter's colour away (measured: 0 of 5
  correct without them; AC-7). Not a §5 redesign.

Type sizes and weights go in these rules (`font-size`, `font-weight`), because
the base `QWidget` rule overrides `setFont`. The template's own editing rules
stand: no overlay token, no 8-digit colour (Qt reads it as AARRGGBB) - hence
DQ-1's `color.surface.hover` for hover-valid in place of `overlay.fill.hover`.
The template comment saying workspace components "are added by the stories that
build them" is how this lands; MT-057 should have, and this story does.

Then **GREEN** regenerates with `uv run python -m mangatl.ui.tokens` and
commits `src/mangatl/ui/theme.qss` and `src/mangatl/ui/theme.qss.tmpl`. Until it
does, MT-025's

### C-5. Measurements RED pins

- **Painted** colour, not `palette()`: `widget.grab().toImage().pixelColor(x, y)`
  at a point that is ground only (a margin/padding pixel), border only (the
  middle of an edge, inset by half the border width), or glyph core. Compare as
  `QColor.name()` (`#rrggbb`), exactly. A `palette()` read may be added, never
  instead - the gutter shows why: its palette and its paint can disagree.
- **A window's own ground (AC-2).** The `Workspace`'s children may cover every
  pixel, so a corner sample can measure a child. Render the window's background
  alone: `window.render(pixmap, QPoint(), QRegion(), QWidget.RenderFlag.DrawWindowBackground)`
  (no `DrawChildren`), after `ensurePolished()`, and sample it.
- **The drop target takes focus when its window is shown** (it is the window's
  only focus stop; offscreen activates the window, measured `hasFocus() ==
  True`). AC-4's **empty** and **error** borders are measured with focus
  **cleared** (or moved elsewhere), or they read `color.focus.ring` by design.
  AC-5 sets focus deliberately.
- **The empty border is dashed** (8 px on, 4 px off, measured). Sample a **run**
  of edge pixels: assert the token is among them and nothing else but the ground
  is. A single midpoint can land in a gap.
- **Grounds are sampled at least `border-width.emphasis` + 2 px inside the
  edge.** The notice's ground is any pixel in the 12 px margin band between its
  1 px border and its labels. The summary scroll area's ring is its own border,
  at the scroll area's geometry; its content ground (AC-3) is sampled between
  parts.
- **Item views (AC-8):** `view.viewport().grab()` at a pixel **below the last
  item** (or in an empty view), so no item, current-row or selection highlight
  is sampled. For text, a non-current `pageStrip` item at row 1 or later:
  adding the first item makes row 0 current, and it paints Qt's highlight.
- **Type:** `label.ensurePolished()` then `label.font().pixelSize()` and
  `.weight()`, against `TYPE_*_SIZE` / `TYPE_*_WEIGHT`.
- **Tokens are read from `tokens_gen.TOKENS`**, never retyped. The part-to-token
  table is `components.md` §2 and §5; read it out.
- **Test isolation.** Tests that apply a sheet to the real `QApplication` restore
  `""` in teardown (a fixture), or MT-015/MT-057's suites inherit it in whatever
  order `pytest-randomly` picks. AC-1 uses the recording fakes of C-2, not the
  real application.
- **AC-6's sheet** is `tokens.render_qss(tokens_with_one_sentinel, template)`
  where `template` is the packaged `theme.qss.tmpl` read as a resource. Sentinel:
  a `#rrggbb` that is not a value of any colour token (RED asserts that). One
  token per case, so a failure names the token.

**Why the heading keeps `type.title` and the gutter keeps its colours (AC-3,
AC-7).** Qt's stylesheet cascade ranks by CSS2 specificity (ids, then
attributes and pseudo-states, then type names) and merges per property. The
base rules are `QWidget` = (0,0,1) and `QWidget:disabled` = (0,1,1). Every new
summary rule is (2,0,1) (`#chapter-summary QLabel#summary-name`), every
drop-target part (2,0,1), every gutter rule (1,1,1). So each wins `color`,
`font-size` and `font-weight` over the base rule regardless of file order -
and a stylesheet `font-size` wins over `setFont`, which is why the size is in
the rule and not left to Python. Without the gutter rules the base `QWidget`
`color` overrides `setPalette` for all five statuses (measured below).

**Drop-target focus ordering, by specificity, not by file order.** The state
rules are (1,1,0); the focus rule is (1,2,0) and matches only `empty` and
`error`. So the ring beats the resting-state border, and never matches a drag
state, whose border therefore always shows. See "Contract deviations" (a) for
why this is not the bare `#folder-drop-target:focus` C-3 names.
