## Context

The closing story of EPIC-13 (`docs/backlog/epics/EPIC-13.md`). The user
decided on 2026-11-18 (`docs/backlog/stories/MT-153.md`, `## Notes`, PO-5 and
answer 3 below it) that the epic's residual-ink audit is delivered by a small
story at the end of the epic. That story measures **every** "Done when" line
on the development set and writes the result under `docs/wiki/audits/`.

**Why it is needed.** The epic's third done-when line reads: "The worst
residual ink is at or under `RESIDUAL_INK_MAX`, or each region over it is
named with its cause in an audit." No story in the epic writes that audit, and
no story reports the other lines as before and after the epic. Each story
measured only its own change.

**Why a spike.** The output is a document. No production code and no test is
written. If a measurement shows a defect, the fix is a new story, not part of
this one.

**The set and the baseline.** MT-143's development set: 46 pages (p061-p084,
p087-p108) in `D:\bench\blackjack-v1-ep02-03\`, truth
`D:\bench\blackjack-v1-ep02-03.truth.json`, 253 regions, its sha256 given in
full in `docs/wiki/audits/MT-143-development-set.md`. "Before the epic" is
that audit's seed run at commit `723b8ec`: recall 92.5 % (234 of 253), 19
missed, spurious 106, worst residual ink 0.0991 with six regions over 0.0100.
The before figures are read from that audit. They are not re-run, because the
code they measured is no longer what `main` holds. The benchmark chapter
(pages 3-58) is never run, copied or read by this story.

**Where the residual line stands today** (after MT-152, before MT-153;
`D:\bench\review\mt152-after-bench-dv152.txt`). Five regions are over the
limit, worst 0.5235:

| Report line | File | Value | In MT-143's table of six? |
|---|---|---|---|
| page 0 region 0 | p061 | 0.5235 | **No.** It was `missed` in the seed run, so it had no residual value then. Its cause is not yet named anywhere |
| page 14 region 2 | p075 | 0.0826 | Yes: strokes redrawn inside a fully masked narrow balloon |
| page 14 region 3 | p075 | 0.0418 | Yes: faint stroke ghost |
| page 14 region 0 | p075 | 0.0202 | Yes: faint stroke ghosts |
| page 25 region 0 | p088 | 0.0991 | Yes: the episode title on screentone, repainted |

Two of MT-143's six are no longer over: page 3 region 1 (p064) and page 37
region 5 (p100) both read 0.0000 in that file. These figures are evidence, not
the answer. MT-153 and the stories after it change the code, so this story
measures again and names what is over the limit **then**. MT-143's causes are
a starting point, and each is looked at again on the new crops. MT-153's DV-2
item 3 lists the regions still over after its fill, which is the nearest
input.

**What a no-spend run cannot measure.** Two lines depend on a translation,
which is a paid Gemini run and happens only on the user's request:

- the slip count (MT-150) reads 0 by construction when nothing was
  translated;
- the art-text part of `spurious` falls only when the model marks regions as
  art (MT-147, counted by MT-148), so without a translation no region is
  excluded as `art`. That is the design as the epic states it (U-4). The
  story confirms it on the run rather than assuming it.

The fifth done-when line, the live benchmark run reviewed by the user, is the
user's own and is not made here.

**The reading of two lines (the Lead PO's, open to the user).** MT-143 counts
89 fragment pieces and 17 art-text regions, which together equal the seed
run's 106 spurious regions. It counts 18 fragmented balloons, of which 16
were missed and 2 were already matched by a whole region. So "spurious falls
by at least the pieces and art regions" is read as a fall of 106, and "recall
rises by the fragmented balloons" as the 16 that were missed, since only
those can raise the matched count. The audit states both readings beside its
verdicts, so that a different reading can be applied to the same figures.

**Gates.** This story changes no code, so no gate exercises its artifact. Its
criteria are checked by reading the audit against the command output pasted
in it.

## Acceptance criteria

The audit is `docs/wiki/audits/MT-159-epic-13-done-when.md`, in the shape of
`docs/wiki/audits/TEMPLATE.md`. "The after run" is detect and clean on a fresh
copy of the development set's 46 pages, on `main` with every story in
`depends_on` merged, followed by `uv run python -m mangatl.bench FOLDER
--development`.

- **AC-1** - Given the after run, when the audit is read, then it records the
  commit the run was made at, the folder, the truth document's sha256 and the
  bench output verbatim. The residual list is given in full, or cut only to
  the regions over the limit with the cut stated.
  *Control:* the sha256 equals the one in
  `docs/wiki/audits/MT-143-development-set.md`, the pasted output begins
  `DEVELOPMENT SET - not a benchmark result`, and the folder holds 46 pages,
  none of them p003 to p058. A run that fails any of the three is not the
  after run, and the audit is not written from it.
- **AC-2** - Given the five lines of EPIC-13's "Done when", when the audit is
  read, then a table has one row per line, in the epic's order and quoting
  the line. Each row gives the before figure and where it was read from, the
  after figure, and exactly one verdict: `met`, `not met` or `not measured`.
  A `not measured` row says why, and what would measure it. No verdict is
  given for a figure the pasted output does not show.
- **AC-3** - Given the `spurious` and `recall` lines, when the audit is read,
  then:
  - every region the after run reports as spurious is classed, by MT-143's
    methods as restated in the audit, as a fragment piece, an art-text region
    or neither, and the three counts sum to the bench's `spurious`;
  - each of the 16 balloons MT-143 counts as missed because fragmented is
    named as matched or still missed in the after run, and the number now
    matched is set beside the change in the bench's `matched`;
  - every region still missed is listed by page file and truth region.

  *Control:* the same classing script, run on MT-143's seed project
  (`D:\bench\blackjack-v1-ep02-03`), gives MT-143's own figures: 89 pieces,
  17 art-text regions, 16 missed fragmented balloons. If it does not, the
  difference is reported and the after counts are not presented as
  comparable with the before.
- **AC-4** - Given the residual-ink line, when the audit is read, then every
  region the pasted output shows above `RESIDUAL_INK_MAX` (0.0100) has a row
  giving: its page file and truth region; its value; whether MT-143's audit
  named it, and its value there; its cause; and the evidence for that cause.
  The evidence is the original and cleaned crops looked at, how many of the
  counted ink pixels lie inside the erase mask, how many are unchanged from
  the source, and which path the inpainter took. A cause the evidence does
  not show is written `cause not known`, with what was measured. Each of
  MT-143's six regions that is no longer over the limit is listed with its
  value now. If no region is over the limit, the audit says so and the row's
  verdict in AC-2 is `met` on the first half of the line.
  *Control:* the number of rows equals the number of residual lines above
  0.0100 in the pasted output, and each row's value equals its line. A region
  over the limit with no row fails this criterion.
- **AC-5** - Given the user has not asked for a paid translation of the
  development set, when the audit is read, then the slip-count row and the
  art-text part of the `spurious` row are `not measured`. Each says that the
  figure printed is zero, or unchanged, by construction. The audit states
  that no Gemini call was made. Given the user did ask, in their own words
  and recorded with the date in `## Notes`, then both are measured on the
  development set only, the bench's `left as art` and slip lines are pasted,
  and the run's cost is reported from the bench's S5 line.
- **AC-6** - Given the fifth done-when line, when the audit is read, then its
  row is `not measured` and says the live benchmark run is the user's to ask
  for and to review. The audit holds no figure measured on pages 3 to 58,
  other than figures quoted from the epic or from MT-143's audit and labelled
  as quoted.
- **AC-7** - Given the audit, when its `## Decided` section is read, then it
  says which done-when lines the epic meets on the development set and which
  it does not. For each line not met, it names the regions or counts
  responsible. It proposes no threshold and no fix. A defect it finds is
  listed as a candidate story, by title only, for the user to accept or
  decline.

## Out of scope

- Any fix, constant or threshold. A region over the limit is named, not
  repaired. Follow-up stories are proposed by title, and cut only if the user
  accepts them.
- The benchmark chapter, pages 3 to 58, in any form: no run, no copy, no
  count. The release measurement is made once, on the user's request, and is
  not this story.
- A paid translation run the user has not asked for. Nothing here spends
  Gemini credit by default.
- Re-running the "before". The baseline is MT-143's audit, quoted.
- Changing `RESIDUAL_INK_MAX`, the bench's definitions or the truth document.
- MT-153's ghost measure. It is not a done-when line. The audit may cite
  MT-153's DV-2 result but does not repeat it.
- Marking EPIC-13 done. The audit says which lines are met. The epic's status
  is the user's call, after the live run.
- Committing the scratch scripts. As in MT-143, the method is written into
  the audit precisely enough to be run again.
