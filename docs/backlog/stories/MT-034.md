### The defect

Every `paths.conf` glob for a directory carries a `/` — `docs/**`,
`**/tests/**`, `scripts/**`, `fixtures/**` — so a **bare** directory name matches
none of them and falls to the classifier's restrictive default, `source`. And the
trailing slash an agent actually types does not survive to the classifier:
`normalize_rel` skips the empty last segment.

```
$ bash -c '. .claude/hooks/lib.sh; for p in docs docs/ docs/sub docs/backlog src src/ tests tests/ scripts fixtures; do
    printf "classify %-14s -> %s\n" "$p" "$(classify "$p")"; done'
classify docs           -> source
classify docs/          -> docs
classify docs/sub       -> docs
classify docs/backlog   -> docs
classify src            -> source
classify src/           -> source
classify tests          -> source
classify tests/         -> test
classify scripts        -> source
classify fixtures       -> source

$ bash -c '. .claude/hooks/lib.sh; normalize_rel "docs/"'
docs
```
`[MEASURED — 2026-09-14, orchestrator]`

So `docs`, `tests`, `scripts` and `fixtures` all classify `source`. It is not a
`docs` quirk and it is not a `mv` or a `-t` quirk: it is `classify`, and it
reaches `cp`, `mv`, `rm`, `touch` and redirects identically, because every branch
of the guard funnels through the same call at `phase-guard.sh:42`.

### C-2 The defect, stated exactly

`.claude/hooks/lib.sh`, `classify()`:

```bash
classify() {
  local rel="$1" cat
  [ -z "$rel" ] && { printf 'outside'; return; }
  cat="$(printf '%s\n' "$rel" | classify_stdin | awk -F'\t' 'NR == 1 { print $1 }')"
  [ -z "$cat" ] && cat=source
  [ "$cat" = "source" ] && is_ignored "$rel" && cat=ignored
  printf '%s' "$cat"
}
```

`classify_stdin` converts each `paths.conf` glob to a regex anchored `^…$`.
`docs/**` becomes `^docs/.*$`, which **requires** a slash, so the string `docs`
matches nothing and the function's documented default — *"the right default for a
file about to be authored"* — applies to something that is not a file.

Two facts make this reachable rather than theoretical:

1. `normalize_rel` drops the trailing slash (`''|.) continue`), so a candidate the
   author wrote as `docs/` arrives at `classify` as `docs`.
2. `paths.conf` already contains the fix for one category and only one. Its
   vendor section carries thirteen twin rules under the comment *"The directories
   themselves, so that `rm -rf node_modules` and friends are classified as vendor
   rather than falling through to source."* Somebody met this defect, solved it
   locally for `vendor`, and the same thing was never done for `docs`, `test` or
   `harness`. **That is evidence about which fix to choose, not merely context —
   see C-3.**

### C-3 The fix: a trailing-slash retry inside `classify`, and nowhere else

**Decision, and it is the Lead PO's to make rather than GREEN's.** When a path
matches no `paths.conf` rule and would therefore take the `source` default,
`classify` tries the same path **with a single trailing `/` appended** before
falling back. If the slashed form matches a rule, that rule's category is the
answer. If it does not, behaviour is exactly as today: `is_ignored`, then
`source`.

Ordering, which is part of the pin: **rules on the bare form → rules on the
slashed form → `git check-ignore` → `source`.** Putting `is_ignored` last
preserves today's precedence, where an explicit rule beats `.gitignore`.

**The `src` row is the whole reason this shape was chosen over the alternatives,
and it is safe for a reason worth stating: the retry is rule-driven. There is no
rule whose glob begins `src/`, so no retry can invent a category for `src`.** The
fix cannot resolve a directory to its children because it never looks at
children.

**Rejected: `paths.conf` (add bare-directory twin globs).** Cheapest to write, has
precedent in the file, and would satisfy AC-1 through AC-5. Rejected on two
grounds. First, **AC-6**: `paths.conf` is read by `classify_stdin`, which is what
`gate_tree_hash` and `check-boundaries.sh` consume, so the fix lands in the one
function whose output a CI check compares hashes of — today no tracked path is
spelled like a bare directory so the hash would not move, but the surface is
wider than the defect. Second, and decisively, **the precedent argues against
itself**: a twin-rule list is exactly what shipped for `vendor`, and it did not
generalise — nobody remembered to write the `docs`, `test` and `harness` twins,
and the result is the live false positive above. A fix that depends on a future
maintainer remembering is a fix that has already failed once, in this file.

**Rejected: `normalize_rel` (preserve the trailing slash).** It would work, and it
would fix direction 3 at the source. Rejected because `normalize_rel`'s output is
used for **path identity**, not only for classification: `phase-guard.sh:209`
feeds it straight into the `$EXEMPT` membership test, which compares the candidate
string for **exact equality** against the resolved `scripts/mutate.sh` FILE
argument. A trailing slash surviving there silently un-exempts the one diagnostic
the harness itself requires in RED — MT-033's R-5 hazard in a new coat.
`command_cwd` also joins its output with `/`, so `docs/` + `/` + `x` would need
re-collapsing. Wider blast radius, for a narrower gain.

### C-4 Mechanism, and the one process budget

`classify` is called once per candidate, from `phase-guard.sh:42`, under a 15 s
`PreToolUse` budget, and **a hook that times out fails OPEN — the lock silently
off**. Measured at PLANNED on this machine, 20 iterations each: one `classify`
call costs 50–175 ms, dominated by process spawn, and an unmatched path already
pays two extra `git check-ignore` forks on top.

**Constraint: the retry must not add a process.** `classify_stdin` reads one path
per line and prints one answer per line, so both spellings can be judged in the
**same** `awk` invocation — feed it `rel` and `rel/`, take the first line that is
not the default, fall through otherwise. That is a suggestion, not a mandate; any
mechanism that adds no fork in the common path is acceptable, and a lazy second
call performed only when the first missed is acceptable too, because that branch
already pays for `git check-ignore`.

**`phase-guard.sh` should not need to change.** If GREEN finds it must, that is a
signal the fix has drifted out of `classify` — stop and say so in the handoff
rather than widening quietly.

Guard against the obvious slip: do not append a slash to a path that already ends
in one, and do not retry a path that **did** match a rule.

### C-5 A directory that does not exist is still classifiable — AC-5, decided

`classify` consults `git check-ignore` but **never the filesystem**, and that is
deliberate: MT-031 pinned it in `write_candidates`' header — *"Nothing here
consults the filesystem"* — for a reason this story must not undo. The guard
judges a **token in a command string**, not an inode. A `stat` would make the
verdict depend on the order commands run in (`mkdir docs` then `mv x docs/` would
be judged differently from the same two commands reversed), it would add a
syscall per candidate to a hook that fails open on timeout, and it would make the
lock unable to judge a write to a path that is about to be created — which is most
of them.

**So the fix stays filesystem-blind, and AC-5 pins it.** The price, recorded here
rather than discovered later: a **file** named exactly `docs`, `tests`, `scripts`
or `fixtures`, with no extension, would classify as that directory's category
rather than `source`. No such file exists in this repository, none is plausible,
and the alternative costs the contract above. If GREEN proposes a
filesystem-consulting fix, that is an escalation to the Lead PO, not a choice.
