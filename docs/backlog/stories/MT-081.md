## Context

The user's request of 2026-10-09 (`EPIC-08`, MT-078 `## Context` PO-1 to
PO-3): translation must work with an OpenAI GPT key. Same shape as MT-080
and the same reasons; read MT-080 `## Context` first, it is not repeated.
This story fills MT-078's `openai` arm.

**Default model: `gpt-6.1-sol`** (PO-2, the user, 2026-10-09). The flagship
GPT-6 Astra at $10/$50 per MTok estimates ≈$2.24/chapter, over the $2
ceiling, and was rejected.

**Unverified (web search 2026-10-09, not the official page):** `gpt-6.1-sol`
**$2 in / $10 out per MTok**; the official pricing page lists cached input
for `gpt-6-astra` at **0.1×** - whether `gpt-6.1-sol` carries the same
multiplier is to be confirmed. Every SDK shape in C-2/C-3 is UNVERIFIED and
confirmed by the same mechanism as MT-080 C-5: the live test.

**The module is `translate/openai_adapter.py`, not `translate/openai.py`**:
a module named `openai` inside `mangatl.translate` shadows the SDK for
every `from openai import ...` written under that package, and the error it
produces is an `ImportError` that reads as a missing dependency.

**Which required gate would fail if this story's artifact broke:** as
MT-080 - `unit`, `coverage` (`coverage-core` for `rates.py`). The live test
is under the optional `integration` gate and **not** in `required_gates`
(PO-3).

## Acceptance criteria

*Oracle partition as MT-080: AC-1..6 **mechanical**, AC-7 **settled** by the
confirmed page, AC-8 a **live measurement** to record.*

- **AC-1** — Given a page image, N OCR results and a `PromptContext`, when
  the OpenAI request is built, then it carries exactly one image input (the
  1,568-px-capped JPEG from `page_prompt.prepare_page_image`, as a base64
  data URL), `page_prompt.SYSTEM_PROMPT` in the request's instructions /
  system slot, the context text only when non-empty, and
  `page_prompt.user_text(ocr_results)` as the last text input.
- **AC-2** — Given the request, then it asks for JSON output constrained by
  a schema derived from `page_prompt.response_schema(N)` (C-2 says exactly
  what the derivation may change and why), names `MODEL_ID == "gpt-6.1-sol"`,
  asks for the **"medium"-equivalent reasoning effort**, and caps output at
  `MAX_OUTPUT_TOKENS` (4096).
- **AC-3** — Given a recorded well-formed response fixture keyed out of
  order, when parsed, then each region gets its own line; an omitted region
  is absent; **a region whose value is `null` is treated as omitted** (C-2's
  strict-schema trap); an unknown index raises `UnknownRegionIndex` - all via
  `parse_lines_text`.
- **AC-4** — Given a response whose usage reports I input tokens of which C
  are cached and O output tokens (reasoning included), when converted, then
  `TokenUsage(input=I-C, output=O, cache_read=C, cache_write=0)`; absent
  details count as 0. *Control:* not subtracting C double-bills cached
  tokens; the fixture has C > 0 and `reasoning_tokens > 0` so a conversion
  that adds reasoning tokens a second time is also caught.
- **AC-5** — Given every region `ocr_empty`, when `translate_page` runs, then
  no call is made and the result is the zero result (MT-011 AC-7).
- **AC-6** — Given a selection of `openai`, when `build_pipeline(translate=True)`
  runs, then the bound translator is this module's `translate_page` with an
  `openai.OpenAI(api_key=selection.api_key)` constructed explicitly, and no
  `Anthropic` or Gemini client is constructed.
- **AC-7** — Given `RATES`, then it lists `gpt-6.1-sol` with the four
  confirmed figures, `RATE_TABLE_VERSION` is bumped, and one hand-computed
  micro-dollar figure is reproduced.
- **AC-8** — *(live, `network`; skips with no `OPENAI_API_KEY`)* as MT-080
  AC-8 (a)-(e), for OpenAI: usage, cost and **`response.model` as reported**
  (OpenAI commonly reports a dated snapshot id; if it is not `MODEL_ID` the
  reported id is added to the rate table with the same figures and recorded
  as a finding), pricing without `UnknownModel`, at least one region
  translated, second-call `cache_read_tokens` **recorded not asserted**, and
  cost × 20 beside the ceiling in `## Notes` and `stack.md`.

### C-1 — `mangatl.translate.openai_adapter`

MODEL_ID: str = "gpt-6.1-sol"

### C-2 — the request (UNVERIFIED; confirm each line)

Prefer the **Responses API** (`client.responses.create`) over Chat
Completions if the docs mark it current for structured output with images;
RED decides from the docs and says which:
- `model=MODEL_ID`, `instructions=SYSTEM_PROMPT`;
- `input=[{"role": "user", "content": [{"type": "input_image", "image_url": "data:image/jpeg;base64,..."}, <context input_text if non-empty>, {"type": "input_text", "text": user_text}]}]`;
- `reasoning={"effort": "medium"}` (the same intent as Claude's
  `effort: "medium"`; another level is a cost-model decision for the user);
- `max_output_tokens=MAX_OUTPUT_TOKENS` - confirm whether reasoning tokens
  count against it; note, do not raise;
- structured output: `text={"format": {"type": "json_schema", "name": "page", "schema": ..., "strict": True}}`.
  **The strict-schema trap, named here so GREEN does not meet it late:**
  strict mode is documented to require every property in `required` and
  `additionalProperties: false`, which cannot express "an omitted region is
  legal" (MT-011 AC-5) by omission. The derivation pinned for OpenAI only:
  every region property becomes `{"type": ["string", "null"], ...}` and is
  listed in `required`; the adapter **drops `null` values before
  `parse_lines_text`** so a `null` region is AC-5's absent region. `glossary`
  likewise required and nullable, `null` → no terms. If RED finds strict
  mode accepts optional keys after all, amend to use
  `page_prompt.response_schema(N)` unchanged and remove the null handling;
- no caching control: OpenAI prompt caching is automatic (documented
  minimum prefix ≈1,024 tokens, UNVERIFIED - our stable prefix is ≈200, so
  expect `cache_read == 0`, a finding not a defect); `cache_write = 0`
  always.

### C-3 — usage (UNVERIFIED field names; arithmetic pinned)

Responses API: `usage.input_tokens` (I, **includes** cached - confirm),
`usage.input_tokens_details.cached_tokens` (C), `usage.output_tokens` (O,
**includes** `output_tokens_details.reasoning_tokens` - confirm). Pinned:
`input = I - C`, `output = O`, `cache_read = C`, `cache_write = 0`. If the
docs say I excludes C, amend to `input = I` with the reason.

The text: `response.output_text` if the SDK offers it, else the first
`output_text` content of the first `message` output item - **not**
`output[0]`, which may be a `reasoning` item (the same trap as MT-011 C-4's
thinking block). `CallInfo(request_id=response.id, model_id=response.model)`.
