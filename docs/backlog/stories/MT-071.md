## Context

Filed 2026-10-05 by the Lead PO from **MT-069 PO-5**, by the user's choice of a follow-up story
over amending MT-069's frozen criteria. EPIC-01, beside MT-068/069/070.

MT-069 shipped `cv2.setNumThreads(-1)` beside every `import cv2`, so that parallel
cv2 survives a process whose default thread pool has lost its I/O completion
port (audit `docs/wiki/audits/MT-068-cv2-parallel-failure.md`). Its tests call
`erase_mask` and `letterbox` only, and either module's call protects the whole
process. `mangatl.clean.inpaint` imports **neither** `clean.mask` nor
`detect.postprocess` (measured), so in a process that imports only `inpaint`,
`inpaint.py`'s own line is the only containment, and **no test pins it**:
with it replaced by `pass`, all 1297 `tests/core` tests pass (MT-069 PO-5).

The required gate that fails if this artifact breaks is `unit`, which runs `tests/core`.
## Acceptance criteria

- **AC-1** - Given a fresh Python process that imports `mangatl.clean.inpaint` and
  **not** `mangatl.clean.mask` or `mangatl.detect.postprocess`, and whose default
  thread pool's I/O completion port has been closed before any cv2 call, when
  `clean_page(page, mask, session)` runs with a stub `InpaintSession` on a page
  whose mask is not all-`False`, then it returns the same array as in a fresh
  process where nothing was closed, and does not raise.

## Contract

**RED may amend any block in place with a reason; GREEN builds what the amended block says.**

- **Entry point (unchanged):** `mangatl.clean.inpaint.clean_page(page: NDArray[np.uint8], mask: NDArray[np.bool_], session: InpaintSession) -> NDArray[np.uint8]`. The stub session follows the `InpaintSession` Protocol in `clean/session.py`; reuse the pattern in `tests/core/test_clean_inpaint.py`.
- **Test:** `tests/core/test_cv2_lost_completion_port_inpaint.py`, `skipif(sys.platform != "win32")`, fresh `sys.executable` children (clean and induced), house style of `tests/core/test_cv2_lost_completion_port.py` (MT-069) - re-derive, do not import from it. The child must **assert** that neither `mangatl.clean.mask` nor `mangatl.detect.postprocess` is in `sys.modules`, or the test proves nothing.
- **Inputs built before the close** (MT-068 PO-7). The mask must reach cv2's parallel path: `cv2.connectedComponentsWithStats` at `inpaint.py:86` (was written as `:83`; re-measured against the tree on 2026-10-07, the MT-069 line sits at 42-43 and shifted it). Whether that call actually takes the parallel path is a MECHANISM CLAIM: RED's earning mutation (below) is what checks it, and if the mutation does not go red RED reports that rather than hunting for another cv2 call.
- **Vacuity canary:** MT-069 C-4 as amended - raw `SetThreadpoolWait` on a fresh thread raises `0xC000070A` in the induced child and succeeds in the clean one.
- **This test is written against code that already has the fix**, so it passes on its first run. Per rules.md it is earned by mutation in RED: `bash scripts/mutate.sh src/mangatl/clean/inpaint.py 's/^cv2.setNumThreads(-1)$/pass/' -- <the test>` must turn it red with `Unknown C++ exception`, and the output goes in `## Regressions`-style evidence in the handoff. GREEN is then expected to be a no-op, verified by the orchestrator, not dispatched.
- **Callers of changed signatures:** none.
- **Oracle:** mechanical (exact equality with the clean child; no exception).
