## Context

Filed by the mutation audit `docs/wiki/audits/EPIC-05-2026-10-27.md`,
survivors **WS17** and **CV12** (`## Decided` 4, `## Evidence` E-2 items 3 and
4). **LOW priority.** Both are stated rules with no test at their edge. The
shipped code is correct for both.

- **WS17.** In `src/mangatl/ui/workspace.py:592`, the row's accessible name
  reads "English: not translated" exactly when there is **neither** a proposal
  **nor** committed text (MT-017 C-8, RED amendment).
  - **The mutant.** Dropping the `and line.final_en is None` half survives all
    of `tests/ui` (1744 passed at `73b7b10`).
  - **Why.** No test builds a row with committed text and no proposal.
  - **Reachable?** Yes. A `failed`, untranslated line is always editable
    (MT-017 PO-5), and typing into it commits `edited` with
    `proposed_en=None`.
  - **The effect.** A screen-reader user would hear "not translated" for a
    line they just wrote.
- **CV12.** `components.md` §4.8 says a click is "the same point" within 3 px,
  and a press and release within 3 px is a click, not a drag.
  - **The mutant.** `_within`'s `<=` (`src/mangatl/ui/canvas.py:577`) can
    become `<`, and it survives all of `tests/ui` (1744 passed).
  - **Why.** The tests use 2 px and 10 px
    (`tests/ui/test_link_workspace.py:661`) and never exactly 3.

**Settled (audit `## Decided` 4):** the code is correct, and this story only
adds tests.

**Evidence to verify, not assume:** both survivals. The audit's scratch probes
(outside the tree) passed on the shipped code and failed under each mutant.
RED re-runs DV-1 before relying on that.

Required gate that fails if this breaks: `unit` and `coverage`, which collect
both test files.

## Acceptance criteria

- **AC-1** - Given a translation row whose line has committed text `"Mine."`,
  no proposal (`proposed_en=None`) and status `edited`, when its accessible
  text is read, then it is exactly
  `"Bubble 1 of 1. Japanese: 一. English: Mine.. edited."`. It does not say
  "not translated". Fails under WS17.
- **AC-2** - Given the two overlapping regions of
  `tests/ui/test_link_workspace.py`'s `_overlapping` fixture, after a first
  click at the overlap point (which selects region 1), when a second click
  lands **exactly 3 px** to the right of the first, then the selection cycles
  to region 0. Fails under CV12.
- **AC-3** - Given the same fixture with nothing selected, when the left button
  is pressed at the overlap point and released **exactly 3 px** to the right,
  then region 1 is selected. That is a click, not a drag. Fails under CV12.

## Contract

- **AC-1** goes in `tests/ui/test_status_glyphs_one_colour.py`, beside
  `test_each_rows_accessible_name_names_its_status_in_words` (`:452`).
  - Build a `TranslationColumn`, then call `set_rows([region], ["一"], [None],
    lines=[Line(reading_index=0, source_ja="一", proposed_en=None,
    final_en="Mine.", status="edited", edited_at=None)])` with any one
    `OrderedRegion` of id 0.
  - Read `column.list.item(0).data(Qt.ItemDataRole.AccessibleTextRole)`.

    `一`, and the probe hit that.
