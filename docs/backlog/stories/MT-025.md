## Context

The first story of EPIC-05, and the reason it exists is a property of the stack
rather than of the design: **QSS has no variables.** `docs/wiki/stack.md` D1
records this as the cost of choosing Qt, and
`docs/wiki/design/tokens.toml` is the machine-readable source the Lead Designer
wrote in response — values in one place, generated into the forms Qt can use.

The Lead Designer's closing constraint is the whole shape of this story:

> The token generator must emit **two** artefacts, `theme.qss` *and* a Python
> constants module. QSS does not style `QGraphicsItem`s, so every marker colour
> is painted from Python and would otherwise drift from the chrome.

Marker colours drifting from chrome colours is not cosmetic here: the overlay
contrast mechanism (`docs/wiki/design/tokens.md` §5, two-stroke dark halo plus
light core) is the only thing making bubble markers legible over both black and
white art, and it is expressed entirely in token values.

**Which required gate would fail if this story's artifact broke:** `unit` — the
generator is a pure function from a TOML document to two strings, plus a check
that the committed artefacts match.

## Acceptance criteria

- **AC-1** — Given `docs/wiki/design/tokens.toml`, when the generator runs, then
  it emits `src/mangatl/ui/theme.qss` and `src/mangatl/ui/tokens_gen.py`.
- **AC-2** — Given the generated Python module, when it is imported, then every
  token in the source document is reachable by a name derived mechanically from
  its dotted path (`color.overlay.bubble.selected` →
  `COLOR_OVERLAY_BUBBLE_SELECTED`), and no token is missing.
- **AC-3** — Given the generated QSS, when it is parsed, then it contains no
  token reference that the source document does not define.
- **AC-4** — Given a source document containing a token that is referenced
  nowhere in either template, when the generator runs, then it **reports** the
  orphan rather than silently dropping it.
- **AC-5** — Given the committed artefacts and the committed source document,
  when the generator runs, then the output is byte-identical to what is
  committed — so an edited `.qss` that was not regenerated fails the gate.
- **AC-6** — Given a source document with a malformed colour value, when the
  generator runs, then it fails naming the token and the value, and writes
  nothing.
- **AC-7** — Given the two artefacts, when the `theme.qss` and `tokens_gen.py`
  values for any token that appears in both are compared, then they are equal.
  *(This is the drift the designer's constraint is about.)*
- **AC-8** — Given the source document, when the generator runs, then it emits
  **four** artefacts, not two: `theme.qss` (the default non-HC sheet — exactly
  the base template rendered with the authored values, containing no
  `@{hc.*}` placeholder and no rule taken from the override template),
  `tokens_gen.py`, **the placeholder template copied into the package**,
  and **the High Contrast override template**. *(`tokens.md` §12.1. The third
  exists because a contrast theme's colours are known only at runtime, so the HC
  sheet cannot be a committed file — and because a PyInstaller build ships only
  what the package carries, MT-024.)*
- **AC-9** — Given the source document, when the generator runs, then
  `tokens_gen.py` exposes `TOKENS: dict[str, str]`,
  `HC_PALETTE_ROLE: dict[str, str]` (token dotted name → palette role or the
  `@static` sentinel) and `HC_OVERRIDE: dict[str, str | float]`, and every
  `HC_OVERRIDE` key names an existing token. *(`tokens.md` §12.2.)*
- **AC-10** — Given a source document in which one **colour** token carries no
  `[hc.map]` entry, when the generator runs, then it **fails**, naming the token
  — a missing mapping is a generation failure, never a default.
  *(A-15.3 and `tokens.md` §12.2: totality is the whole anti-drift mechanism;
  adding a colour must force a decision about its High Contrast behaviour.)*
- **AC-11** — Given a source document containing `[meta]`, `[hc]`, `[hc.map]`
  and `[hc.override]`, when the generator runs, then **every key under `[hc]`
  and under `[meta]` is excluded** from the token set, from `TOKENS`, from the
  constant-name mapping and from AC-4's orphan report. *(`tokens.md` §12.3: an `[hc.map]` key is a
  *reference to* a token, not a declaration of one. A generator that flattens
  the document naively emits `HC_MAP_COLOR_SURFACE_BASE` as a token and every
  downstream assertion then counts the wrong things — including AC-2, AC-4 and
  MT-026 AC-7.)*
- **AC-12** — Given the High Contrast override template, when it is checked
  against the base template, then every one of its `@{hc.RoleName}` placeholders
  names one of the five roles in `[hc].roles`, and **it overrides only selectors
  the base template already defines**. *(`tokens.md` §12.1: one file stays
  authoritative for structure, and the restriction is mechanically checkable.)*
- **AC-13** — Given the generated module, when it is inspected, then it contains
  **data only** — no function definitions and no branching. *(`tokens.md` §12.2
  and `high-contrast.md` §4.3: `resolve` is hand-written in MT-026, because
  logic in a generated file is logic nobody reviews.)*

## Amendments

Both made at PLANNED, 2026-09-28, before RED; approved by the user in the
`/advance-story MT-025` session (PO-2, PO-3), recorded by lead-po.

- **AC-8.** Was: "`theme.qss` (unchanged, the default non-HC sheet)". Now:
  "`theme.qss` (the default non-HC sheet — exactly the base template rendered
  with the authored values, containing no `@{hc.*}` placeholder and no rule
  taken from the override template)". Why: no `theme.qss` had ever been
  committed, so "unchanged" had nothing to compare against and could not be
  tested. The new wording is what `tokens.md` §12 meant: the HC work leaks
  nothing into the default sheet.
- **AC-11.** Was: "…containing `[hc]`, `[hc.map]` and `[hc.override]` … every
  key under `[hc]` is excluded…". Now: "…containing `[meta]`, `[hc]`, `[hc.map]`
  and `[hc.override]` … every key under `[hc]` and under `[meta]` is
  excluded…". Why: `[meta]` (schema, theme, version) is document metadata like
  `[hc]`; a naive flatten would emit `META_SCHEMA` and report all three as
  orphans.

**C-1 — the generator module.**

```
src/mangatl/ui/tokens.py
    TOKENS_SOURCE: Path                 # <repo>/docs/wiki/design/tokens.toml
    BASE_TEMPLATE_SOURCE: Path          # <repo>/docs/wiki/design/theme.qss.in
    HC_TEMPLATE_SOURCE: Path            # <repo>/docs/wiki/design/theme_hc.qss.in
    PACKAGE_DIR: Path                   # src/mangatl/ui (the default out_dir)
    STATIC: str = "@static"             # the HC exemption sentinel
    HC_ROLES: frozenset[str]            # the five roles, high-contrast.md §4.1
    EXCLUDED_SECTIONS: frozenset[str] = frozenset({"hc", "meta"})   # AC-11
    def load_tokens(path: Path) -> dict[str, TokenValue]   # flattened, dotted keys,
                                        # source-document order, [hc]/[meta] excluded
        # [RED amendment, 2026-09-28] "source-document order" means a depth-first walk
        # of the dict tomllib returns. Reason: textual order is ambiguous once a table
        # is reopened; measured identical to textual order on today's document (126/126).
    def load_hc(path: Path) -> tuple[dict[str, str], dict[str, str | float], list[str]]
                                        # ([hc.map], [hc.override], [hc].roles)
    def to_constant_name(dotted: str) -> str
    def is_colour_token(dotted: str, value: TokenValue) -> bool          # C-4
    def token_text(value: TokenValue) -> str                             # C-3
    def render_qss(tokens: Mapping[str, TokenValue], template: str) -> str
    def render_python(tokens, hc_map, hc_override) -> str
    def check_override_template(override: str, base: str, roles: Iterable[str]) -> None  # AC-12
    def generate(source: Path, base_template: Path, hc_template: Path,
                 out_dir: Path) -> GenerationReport
    def main(argv: Sequence[str] | None = None) -> int    # `python -m mangatl.ui.tokens`
        # [RED amendment, 2026-09-28] argv options, each defaulting to the constant
        # above: --source PATH, --base-template PATH, --hc-template PATH, --out-dir DIR.
        # Reason: with no options, main() can only be exercised by writing into src/,
        # so C-7's exit codes and stderr lines would be untestable against a fixture.
    TokenValue = str | int | float | bool
    @dataclass(frozen=True) class GenerationReport:
        written: tuple[Path, ...]       # the four paths, in the C-2 order
        orphans: tuple[str, ...]        # AC-4, sorted dotted names
    class TokenError(Exception)                       # base of the four below
    class MalformedToken(TokenError)                  # AC-6, name collisions, bad grammar
    class UnresolvedPlaceholder(TokenError)           # AC-3: a @{x} naming no token
    class MissingHighContrastMapping(TokenError)      # AC-10
    class OverrideTemplateViolation(TokenError)       # AC-12, and an [hc.override] key
                                                      # naming no token (AC-9)
```

*Signature change against the original contract:* `generate` gains the two
template paths, because the templates are inputs the original signature had no
way to receive (PO-1). Every error message names the offending token (and, for
AC-6, the value) verbatim.

**C-2 — the four generated artefacts** — all committed, none hand-edited, all
`source` category:

```
src/mangatl/ui/theme.qss            # render_qss(tokens, base template); no HC content
src/mangatl/ui/tokens_gen.py        # data only (C-5)
src/mangatl/ui/theme.qss.tmpl       # the base template, copied byte-for-byte
src/mangatl/ui/theme_hc.qss.tmpl    # the HC override template, copied byte-for-byte
```

The two `.tmpl` files are **verbatim copies** of their inputs: the generator
validates them (AC-3, AC-12) but does not transform them. MT-028 composes them at
runtime.

**C-3 — value text.** The string form of a token, used by QSS substitution *and*
by `TOKENS`: `str` verbatim; `bool` → `"true"` / `"false"`; `int` → `str(v)`;
`float` → `repr(v)` (`0.55` → `"0.55"`). One function, `token_text`, so AC-7 is
comparing one conversion against itself only through the artefacts. The
per-token **constants** carry the native TOML type (`OVERLAY_DIM_OPACITY = 0.55`,
`SPACE_S2 = 8`, `TYPESET_HYPHENATE = False`); `TOKENS` carries the text form.

**C-4 — what a colour token is.** A token is a colour token iff its dotted name
starts with `color.` or `overlay.` **and** its value is a `str`. (`overlay.stroke.*`
are integers and are not colours.) Against today's document that is exactly 40
tokens, and `[hc.map]` has exactly 40 keys — the same 40. A colour token's value
must match `^#[0-9A-Fa-f]{6}([0-9A-Fa-f]{2})?$`; anything else is AC-6's
`MalformedToken`. `elevation.*.surface = "color.surface.base"` is a string token
that is not a colour token and is not validated as one.

**C-5 — the generated Python module.** In this order: a header comment saying it
is generated from `tokens.toml` by `mangatl.ui.tokens` and must not be edited;
`from __future__ import annotations` if needed; one `NAME = <literal>` line per
token in source-document order; then `TOKENS: dict[str, str] = {...}`,
`HC_PALETTE_ROLE: dict[str, str] = {...}`, `HC_OVERRIDE: dict[str, str | float] = {...}`,
each in source-document order. **As emitted, it must pass `ruff check`,
`ruff format --check` and `mypy`** — the `lint` gate reads `src/**` and a
generated file that fails it would be "fixed" by hand, which is AC-5's failure.
No `def`, no `class`, no `if`/`for`/`while`/`match`/`try`, no comprehension,
no lambda (AC-13 — assert it on the AST).

**C-6 — writing.** Every validation (AC-3, AC-6, AC-10, AC-12, the AC-9 key
check, constant-name injectivity, the token-name grammar) runs **before any file
is opened for writing**; a failure leaves `out_dir` byte-for-byte as it was.
Files are written as UTF-8 with **`\n` line endings on every platform**
(`newline="\n"` or `write_bytes`). `.gitattributes` pins `eol=lf`, so the
committed copies are LF on disk; a generator writing Windows text mode would emit
CRLF and fail AC-5 on this machine only.

**C-7 — orphans (AC-4).** An orphan is a token (after the AC-11 exclusion)
referenced by a `@{name}` placeholder in **neither** input template. Against
today's document that includes every `overlay.*` and `typeset.*` token, by
design — they are painted from Python. An orphan is **reported, never fatal**:
`GenerationReport.orphans`, and `main()` prints one line per orphan to stderr
and still exits 0. `main()` exits non-zero, printing the `TokenError`'s message,
on any validation failure.
*[RED amendment, 2026-09-28]* The orphan line's wording is free, but each orphan's
dotted name appears as a whole word on exactly one stderr line (no other line may
mention it). A constant-name collision's `MalformedToken` names **both** colliding
dotted names. Reason: "one line per orphan" and "names the offending token" were
otherwise not pinnable.

**C-8 — the template grammar (AC-3, AC-12).** Placeholders match
`@\{([^}]+)\}`. In the base template every placeholder names a token. In the
override template a placeholder is either `hc.<Role>` with `<Role>` ∈ `[hc].roles`,
or a token name. For AC-12: strip `/* … */` comments; a rule is
`<selector list> { <declarations> }` with no nested braces; split the selector
list on `,` and collapse whitespace in each selector; every override selector
must be in the set of base selectors. A violation names the selector.
**Placeholders contain braces**, so mask every `@\{[^}]+\}` *before* splitting
rules on `{`/`}` — otherwise `padding: @{space.s2}px;` reads as a nested block.
(Found by the Lead Designer writing the seed; RED should pin it with a case.)

**C-9 — inputs to outputs, and the baseline to read out, not re-derive.**
`docs/wiki/design/theme.qss.in` → `src/mangatl/ui/theme.qss` (rendered) and
`src/mangatl/ui/theme.qss.tmpl` (verbatim); `docs/wiki/design/theme_hc.qss.in`
→ `src/mangatl/ui/theme_hc.qss.tmpl` (verbatim). Measured by lead-po on
2026-09-28 against the committed seed with a parser independent of the
designer's: **126 tokens, 40 colour tokens, 29 distinct base selectors, 9
override selectors (all in the base set), 26 distinct tokens referenced across
the two templates (25 base + `border-width.emphasis`), all five roles used in
the override, 100 orphans.** The large orphan list is correct, not a failure.

**Semantics and rules:**

- **`to_constant_name` is mechanical and total**: dotted path uppercased,
  `.` and `-` to `_`. `color.canvas.surround` → `COLOR_CANVAS_SURROUND`. It must
  be injective over the source document — two tokens colliding on one constant
  name is a `MalformedToken`, not a last-writer-wins.
- **AC-5 is the load-bearing criterion.** Without it the generator is a
  convenience somebody bypasses on a busy afternoon, and the two artefacts
  diverge exactly as the designer warned. Assert regeneration produces the
  committed bytes; do not assert "the generator ran at some point".
- **`HC_PALETTE_ROLE` is data, not behaviour.** The generator copies the mapping
  out of the source document and validates that it is total over colour tokens
  (AC-10). It does not know what a role means and does not resolve anything;
  that is MT-026's `resolve`, hand-written. `high-contrast.md` §4.3.
- **The five roles are `Window`, `WindowText`, `Highlight`, `HighlightedText`,
  `DisabledText`, plus the `@static` sentinel** — `high-contrast.md` §4.1–§4.2.
  The generator may check membership in that set; it may not invent a sixth.
- **`theme.qss` carries no High Contrast content** (AC-8, reworded 2026-09-28,
  PO-2). The earlier wording — "byte-identical", "unchanged" — had nothing to be
  identical *to*: no `theme.qss` has ever been committed. What `tokens.md` §12
  actually means is that the HC work touches no authored value and leaks nothing
  into the default sheet, and that is what AC-8 now asserts: `theme.qss` equals
  `render_qss(tokens, base template)` and contains no `@{hc.` and no rule from
  the override template.
- **The templates are emitted into the package, not read from `docs/`.** The
  running app needs the placeholder template at startup and a PyInstaller build
  ships only what the package carries (MT-024 AC-4 excludes `docs/`). Reaching
  back at a source path would work on a developer machine and fail in the
  installer — the one place this gate cannot see.
- **All four artefacts are `source` category** and are committed. They are generated,
  but they are generated *by this project* and read by the shipped app, so they
  are not `.gitignore` material: a build that requires a generator step before
  the app can start is a build that breaks the installer story (MT-024).
  Say so in `## Notes` rather than reopening it later.
- **The generator is not run at application startup.** It is a development tool;
  the app imports `tokens_gen` and reads `theme.qss` as data.

**Oracle partition: entirely mechanical.** A pure function with a known output.
Nothing to calibrate. AC-4, AC-6 and AC-9 are the only judgement calls and all
three are settled above (report the orphan; fail writing nothing; fail on a
missing High Contrast mapping).

**Criteria changed at PLANNED, 2026-09-12.** AC-8 through AC-13 were added after
the user decided that High Contrast is supported. High Contrast is a
token-*resolution* problem before it is a widget problem, so the generator must
carry a path for it or MT-026 has nothing to resolve against. The story grew
from two artefacts to four (`tokens.md` §12.1) — that is the largest single
change and it is the reason AC-8 exists as its own criterion. No `## Amendments`
entry is required because the story had not left PLANNED; recorded here so the
change is not mistaken for drift.

**Criteria changed at PLANNED, 2026-09-28** (lead-po, decided by the user; see
`## Notes` PO-1 to PO-3). AC-8's "unchanged" became a testable no-leakage clause,
and AC-11's exclusion was widened from `[hc]` to `[hc]` and `[meta]`. Still
PLANNED, but `check-boundaries.sh` compares the criteria against `main` whatever
the phase, so both are recorded under `## Amendments`.

**AC-11 is the one a reader will skip and the implementation will get wrong.**
`[hc]`, `[hc.map]` and `[hc.override]` are *metadata about* tokens, not tokens.
A generator that flattens the document naively emits `HC_MAP_COLOR_SURFACE_BASE`
as a token, and then AC-2's key-set check, AC-4's orphan report and MT-026's
totality assertion are all counting the wrong things — while passing.

## Design notes

From `docs/wiki/design/README.md`, the closing constraint, plus
`docs/wiki/design/tokens.md` §5–§6 for why marker colours cannot live in QSS.
The contrast figures the designer computed (worst case 6.89:1 for the error core
over near-black, 4.98:1 for the halo over 50% screentone) are **evidence**, not
decisions: they are re-verified by MT-016's render test, not by this story,
which only has to carry the values through without changing them.

**Seed templates, 2026-09-28** (lead-designer, Claude Opus 5.5, `claude-opus-5-5`;
PO-1). `theme.qss.in` (23 rules) covers global chrome only — window, dialog,
tooltip, menu, button, line/plain-text edit, scroll bar. `theme_hc.qss.in` (8
rules) carries only rule changes. Decisions the designer made that MT-015 should
see, **not** this story's scope: plain `QPushButton` is the secondary variant (no
variant selector exists in components.md, so no ghost/primary/destructive rules
and the §10.1 ghost-gains-a-boundary delta cannot be written yet); a menu's
current item is Highlight/HighlightedText under HC; plain edits focus with the
white ring (A-04), not the azure LineEditor border of §6. Open design gaps
reported: focus offset and focus-visible are not expressible in QSS; a 1px shift
on focus; no target-size or scroll-bar-width token (12px bar vs A-05's 28px);
whether Qt's QSS parser takes the unquoted `type.family.ui` fallback list.
