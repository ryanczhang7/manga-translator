## Context

EPIC-09's first story and the one every batch story reads numbers out of. The
epic's cost case rests on five facts about Gemini's Batch API that nobody in
this repository has checked against Google's current documentation: the
discount (assumed 50%), whether a batch request accepts the
`GenerateContentConfig` `translate/gemini.py:106-114` sends (a JSON
`response_json_schema`, `ThinkingLevel.MEDIUM`, `max_output_tokens`), whether
implicit or explicit context caching applies to batch requests, what
turnaround is promised, and what a prompt over 200k tokens costs (the
`_PUBLISHED` Gemini row in `domain/rates.py` is the <=200k tier). A story
that assumed any of these would ship a rate row or a request shape the
provider rejects, after the user has paid for the attempt.

A spike's output is a document: `docs/wiki/audits/MT-101-gemini-batch.md`,
with the sections `## Sources`, `## Findings`, `## Live probe`, `## Decided`.
MT-102 reads its rates out of `## Decided`; MT-110 reads the request and
result shapes; MT-114 reads the tier threshold. Nothing here changes code.

**The live probe needs the user** (EPIC-09 Q-1): one batch of one request,
built with exactly the config the per-page path sends, on the user's key. It
costs well under a cent and is the only way to learn whether the structured
output and thinking config are accepted in batch rather than merely
documented. The user runs the probe script the spike provides and pastes the
job's final state and usage into `## Live probe`.

No gate judges a document; `required_gates` stays empty for a spike's reason
(MT-068 `## Notes` PO-4).

## Acceptance criteria

A spike's criteria are about what is *known* at the end.

- **AC-1** - `## Sources` cites every page read, by URL, with the date read
  and the page's own "last updated" line where it has one; every number in
  `## Decided` traces to one of them. A number with no source is not decided.
- **AC-2** - `## Decided` states the Gemini 3.1 Pro batch rate per million
  tokens for input, output (thinking included or not - say which) and cached
  input, as `Decimal` strings MT-102 can transcribe, and states the ratio to
  the interactive rate. If the discount is not 50%, the epic's cost case in
  EPIC-09 `## Why now` is re-stated there with the real ratio.
- **AC-3** - `## Decided` states, for each of `response_mime_type`,
  `response_json_schema`, `thinking_config` and `max_output_tokens`, whether
  a batch request accepts it - from the docs **and** from the live probe - and
  names the exact SDK calls and argument shapes for submitting inline
  requests, polling a job and reading results (`client.batches.*`), including
  the job state names and how a per-request error is reported.
- **AC-4** - `## Decided` states whether context caching (implicit, explicit)
  applies to batch requests and at what rate; if it does not, it says the
  batch estimate carries no cache read.
- **AC-5** - `## Decided` states the turnaround Google promises (target and
  maximum) and what happens to a job that exceeds it, with the source.
- **AC-6** - `## Decided` states the token threshold of the pricing tier and
  the rates above it, interactive and batch, and whether the threshold is on
  the prompt alone; MT-114 chunks under it.
- **AC-7** - `## Live probe` carries the probe's request config, the job
  name, its final state, the per-request usage counts as the API reported
  them, the parsed JSON (or the rejection text verbatim), and the cost priced
  by `domain.rates.price` at the interactive row beside the batch figure
  from AC-2. *Control:* the same request submitted interactively through
  `translate/gemini.py` must parse; if the batch item fails where the
  interactive one succeeds, the document says which config field the batch
  path rejected.

## Contract

**Writes:** `docs/wiki/audits/MT-101-gemini-batch.md`

- The document has the four sections above, in that order. `## Decided` is a
  list of numbered decisions `D-1 ... D-n`, each one sentence plus its
  source, so the implementing stories can cite `MT-101 D-3`.
- The probe script is written **inside the document** as a fenced block, not
  as a file in the tree: a spike commits no code (`story-authoring`, Types),
  and the next story that needs a batch client writes it test-first.
- Oracle partition: every criterion is **mechanical** - a fact with a source,
  or a probe result pasted. No metric, no control beyond AC-7's.
- No test-only dependency; no code.
