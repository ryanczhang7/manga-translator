## Context

Filed 2026-10-28 from the user's report: *"i got an estimate of around $20 for
a volume with near 200 pages"* and *"didnt we switch to gemini... i instructed
to switch to gemini earlier"*. The user has only `GEMINI_API_KEY` set and v1
translates on `gemini-3.1-pro-preview` (`stack.md` §3, MT-080).

**The defect, verified in the code 2026-10-28.** `CostEstimate`
(`src/mangatl/ui/cost_estimate.py:70-71`) shows
`Budget().project((), pages).remaining_chapter`, which is
`pages x BOOTSTRAP_PAGE_ESTIMATE`; `BOOTSTRAP_PAGE_ESTIMATE`
(`src/mangatl/domain/budget.py:71`) is **$0.06**, transcribed from
`docs/wiki/cost-model.awk` design A - *claude-opus-5* at $1.14 per 20 pages,
rounded up. So with only `GEMINI_API_KEY` set, a 200-page folder reads
`Estimated for 200 pages: $12.00.` (`components.md` §2 even tabulates that
row). The same constant is the projection the in-run budget guard uses before
two calls have been priced (`pipeline/translate_stage.py:213`,
`budget.project(chapter_call_costs(...), pages_remaining(...))`), and the
screen and the guard **deliberately share that one number** (MT-058's
docstring: "so the screen and the guard cannot disagree about whether a chapter
fits"). This story keeps that property: both get the figure from one domain
function, keyed on the model the run will actually call.

The user's "$20" is not reproduced by the code as it stands - 200 pages reads
$12.00, and 333 pages would read $19.98. The reproduction this story pins is
the $12.00 figure; the gap is noted in `## Notes` and not chased here.

**Why the Gemini figure is derived, not measured.** `domain/rates.py` already
prices `gemini-3.1-pro-preview` at $2 in / $12 out / $0.20 cache read. The
cost model's per-page token profile (`cost-model.awk`: 2,296 image + 500 OCR +
900 rolling context uncached input, 1,500 cached prefix, 700 visible + 800
thinking output) priced at those rates is **$0.025692 a page, rounded up to
$0.03** - the same derivation that gave Claude its $0.06 (18,480 + 750 +
37,500 micro-dollars = $0.05673, up to $0.06), and `budget.py`'s stated rounding
direction: *an estimate that errs low lets a run start that it cannot finish*.
MT-080 *measured* Gemini at $0.0054-$0.0057 a page (`stack.md` §5/O4: 2 calls,
one page, ~1,600 prompt tokens, ~209 output, **0 thinking tokens reported**
under `ThinkingLevel.MEDIUM`). Two calls on one page with no thinking reported
is too thin to anchor a figure that only has to err high, so this story takes
the token-profile derivation and records the measured value as the known
lower bound. **This is the one product decision the user may want to make
differently** (see `## Notes`, Q-1): anchoring on the measurement instead
would give $0.01 a page and `$2.00` for 200 pages.

**Constraints.** `mangatl.domain` imports nothing of ours outside `domain`
(`architecture.md` §3 rule 2; `pyproject.toml` *"domain is independent"*), so
the domain can know *models* (it already keys `RATES` on model ids) but not
*providers*. Which model a provider calls is `translate`'s fact
(`translate/gemini.py:82 MODEL_ID`, `translate/prompt.py:62 MODEL_ID`), and
`translate/provider.py` is the one SDK-free module of that package - `ui`
already imports it to catch `ProviderError` (MT-078 C-1), and `ui` may not
import `google` or `anthropic`. `domain` sits under `coverage-core`'s
`--cov-fail-under=100` with branch coverage, so every branch added there needs
a test that reaches it.

Required gates that fail if this breaks: `unit` and `coverage`
(`tests/core`, `tests/ui`), `coverage-core` for the domain half, `lint`
(`lint-imports`) if any layer is crossed.

## Acceptance criteria

- **AC-1** (the reproduction) - Given an environment in which `GEMINI_API_KEY`
  is the only provider key set and no explicit provider is chosen, when the
  summary for a 200-page chapter is shown, then its estimate line reads
  `Estimated for 200 pages with gemini-3.1-pro-preview: $6.00.` and **not**
  `$12.00`, its budget line reads `Budget $2.00. The estimate is over budget.`,
  and the Start button reads `Start run anyway`. Before this story the same
  state reads `Estimated for 200 pages: $12.00.`.
- **AC-2** - Given the same Gemini-only environment, when the summary for a
  66-page chapter is shown, then the estimate is `$1.98`, the budget line is
  `Budget $2.00.` with no over-budget sentence, and Start reads `Start run`;
  for 67 pages the estimate is `$2.01` and the summary is over budget. (The
  boundary moves with the model: on Claude it is 33/34 pages, as
  `components.md` §2 tabulates today.)
- **AC-3** - Given an environment in which `ANTHROPIC_API_KEY` is the only key
  set, when the summary for a 200-page chapter is shown, then the estimate line
  reads `Estimated for 200 pages with claude-opus-5: $12.00.` - Claude keeps
  Claude's figure.
- **AC-4** - Given an environment with no provider key set, or with more than
  one set and no explicit choice, when the summary is shown, then the estimate
  line reads `No estimate: <the ProviderError's message>.` (the sentence
  `select_provider` raises, verbatim), the budget line reads `Budget $2.00.`
  with no over-budget sentence, `over_budget` is `False`, Start reads
  `Start run`, and - above 200 pages - the page warning is
  `That is more pages than a chapter.` with no cost sentence. Pressing Start
  still fails as it does today (`MainWindow._start` shows the `ProviderError`).
- **AC-5** - Given a project bound to the Gemini selection with no priced
  calls, when the translate stage consults the guard for its first page, then
  the projection it judges is `next_call == $0.03` with basis `estimate`:
  with a stored ceiling of `$0.02` the first page is refused with that
  projection in the `BudgetRefused` decision, and with a stored ceiling of
  `$0.03` it is permitted. The same project bound to the Anthropic selection
  projects `$0.06` and is refused at a `$0.05` ceiling. (Today both refuse at
  $0.05 and permit at $0.06, whichever the provider.)
- **AC-6** (the shared number) - For every provider that has a translator
  (`anthropic`, `gemini`), the figure the summary shows for `n` pages equals
  `remaining_chapter` of the guard's first projection for `n` pages on that
  provider's model, for `n` in {1, 20, 200}. The two sides are computed through
  the same exported function and cannot drift.
- **AC-7** (the derivation, settled) - `page_estimate(model_id)` is
  `price(model_id, DESIGN_A_PAGE_TOKENS).cost` rounded **up** to a whole cent:
  `claude-opus-5` -> `$0.06`, `claude-sonnet-5` -> `$0.03`,
  `gemini-3.1-pro-preview` -> `$0.03`; every value is strictly positive; an id
  not in `RATES` raises `UnknownModel` naming it. `Budget()` built without a
  `page_estimate` projects at the **dearest** listed model's figure (`$0.06`
  today), so an unnamed model errs high, never low.
- **AC-8** - `MODEL_IDS["gemini"] == translate.gemini.MODEL_ID` and
  `MODEL_IDS["anthropic"] == translate.prompt.MODEL_ID`; every value of
  `MODEL_IDS` is a key of `RATES`; `model_for("openai")` raises
  `ProviderUnavailable` with the sentence `compose._translator` raises for it,
  `translation with openai is not available yet`.

### C-1 `mangatl.domain.budget` - the per-model estimate

```python
#: cost-model.awk design A, per page: 2,296 image + 500 OCR + 900 rolling
#: context as uncached input; the 1,500-token prefix as a cache READ (the awk
#: writes it once a chapter and reads it 19 times - per page that is a read);
#: 700 visible + 800 thinking as output; no cache write.
DESIGN_A_PAGE_TOKENS: TokenUsage = TokenUsage(
    input_tokens=3696, output_tokens=1500, cache_read_tokens=1500, cache_write_tokens=0
)

def page_estimate(model_id: str) -> Usd:
    """`price(model_id, DESIGN_A_PAGE_TOKENS).cost` rounded UP to the cent.
    Raises `domain.rates.UnknownModel` (unchanged, from `price`) for an id the
    table does not list. Strictly positive for every listed model."""

#: What `Budget()` projects when no model is named: the dearest listed model's
#: `page_estimate`, so an unnamed model errs high. $0.06 today (claude-opus-5).
BOOTSTRAP_PAGE_ESTIMATE: Usd = max(page_estimate(model_id) for model_id in RATES)

class Budget:
    def __init__(self, ceiling: Usd = DEFAULT_CEILING, *, page_estimate: Usd = BOOTSTRAP_PAGE_ESTIMATE) -> None
    # `self.page_estimate` is what `project` uses in the estimate branch, in
    # place of the module global. `project` and `check` signatures unchanged.
```

Semantics: rounding up to the cent is `Usd.from_micro(-(-cost.micro() // 10_000) * 10_000)`
or equivalent exact integer arithmetic - no `Decimal` context, no float.
Values that follow: opus 56,730 -> 60,000 micro ($0.06); sonnet 22,692 ->
30,000 ($0.03); gemini 25,692 -> 30,000 ($0.03). `budget.py` imports
`domain.rates` and `domain.translation` - both inside `domain`, so the
*"domain is independent"* contract is untouched; `budget.py`'s docstring
("imports nothing of ours but `domain.money`") is updated to say so. `Usd` is
`order=True`, so `max` works. The `## Notes` of `tests/ui/test_cost_estimate.py`
say several tests `monkeypatch.setattr(budget, "BOOTSTRAP_PAGE_ESTIMATE", ...)`
to move the boundary; after this story the widget takes a model, so those
tests move the boundary by choosing the model (or by monkeypatching
`budget.RATES`/`page_estimate`), and RED rewrites them - see the caller list.

**`Budget.__init__` gains a keyword-only argument with a default: no existing
caller breaks** (`Budget()` and `Budget(ceiling)` keep their meaning).
