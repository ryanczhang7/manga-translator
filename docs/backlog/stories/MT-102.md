## Context

EPIC-09 PO-4: batch calls are priced at Gemini's batch rate, from a rate row
of their own, and the ledger reconciles against the bill. Today
`domain/rates.py` has one table, `RATES`, keyed on model id, and `price(model_id,
usage)` has one tier. A batch call priced at the interactive row would
over-report spend by the whole discount, and the guard (`Budget`, D6) would
refuse batches the user can afford; a batch rate silently applied to an
interactive call would under-report, which `rates.py`'s docstring calls the
worst failure the module has.

The numbers come from MT-101 `## Decided` D-? (the batch rate decision). The
figures below assume the 50% discount the epic was costed on - **$1.00 in /
$6.00 out / $0.10 cache read** - and are confirmed or replaced from the audit
before this story leaves PLANNED; `depends_on: [MT-101]` enforces the order.

`domain` is under `coverage-core`'s 100% branch gate; `rates.py`'s loader
deliberately validates only the four categories (MT-012 F-6), and this story
keeps that shape: a second table built by the same loader.

Required gates that fail if this breaks: `unit`, `coverage-core`.

## Acceptance criteria

- **AC-1** - `price("gemini-3.1-pro-preview", usage, pricing="batch")` prices
  `usage` at the batch row: for `TokenUsage(1_000_000, 0, 0, 0)` the cost is
  exactly the batch input rate in dollars, and for `TokenUsage(0, 1_000_000,
  0, 0)` exactly the batch output rate; the returned `CostRecord.pricing` is
  `"batch"` and its `rate_table_version` is the new version.
- **AC-2** - `price(model_id, usage)` with no `pricing` argument prices at the
  interactive row exactly as before this story, and the record's `pricing`
  is `"standard"`: every pre-existing `test_rates.py` assertion on cost holds
  unchanged except for the version string.
- **AC-3** - `price("claude-opus-5", usage, pricing="batch")` raises
  `UnknownModel`, whose message names the model **and** the tier (`batch`)
  and lists the models the batch table does have.
- **AC-4** - `RATE_TABLE_VERSION` is a later date than `2026-10-12`, and
  every row of both tables carries all four categories (the loader raises
  `IncompleteRateTable` at import otherwise - the existing AC-7 of MT-012,
  extended to the second table by a test that feeds the loader a batch table
  missing one key).
- **AC-5** - For every model in `BATCH_RATES`, each of its four rates is
  strictly less than the same model's interactive rate (a batch row that is
  not a discount is a transcription error).

## Contract

**Writes:** `src/mangatl/domain/rates.py`, `tests/core/test_rates.py`

```python
Pricing = Literal["standard", "batch"]

#: Batch-tier rows, same shape, same loader. Only models with a published batch
#: price appear; a model absent here cannot be batch-priced (AC-3).
_PUBLISHED_BATCH: Mapping[str, Mapping[str, Decimal]] = {
    "gemini-3.1-pro-preview": {   # MT-101 D-?: <url>, read <date>
        "input_per_mtok": Decimal("1.00"),
        "output_per_mtok": Decimal("6.00"),
        "cache_write_per_mtok": Decimal("1.00"),   # no write surcharge, as the interactive row
        "cache_read_per_mtok": Decimal("0.10"),
    },
}
BATCH_RATES: Mapping[str, ModelRates] = load_rates(_PUBLISHED_BATCH)
RATE_TABLE_VERSION: str = "2026-10-28"   # or the audit's date, if later

@dataclass(frozen=True)
class CostRecord:
    ...                       # existing fields unchanged, in order
    pricing: Pricing = "standard"   # NEW, last, defaulted - no positional caller breaks

def price(model_id: str, usage: TokenUsage, *, pricing: Pricing = "standard") -> CostRecord
```

Semantics: `pricing` picks the table (`RATES` or `BATCH_RATES`); PO-4's single
rounding is unchanged; `UnknownModel`'s message gains ` at {pricing} rates`
before the table listing. `__all__` gains `BATCH_RATES`, `Pricing`. Cache-read
figure: if MT-101 D-? says caching does not apply in batch, the row still
carries the four categories (the loader demands them) and the value is the
batch input rate, with the comment saying so.

**Callers of `price(`** (grep 2026-10-28, none break - keyword with default):
`src/mangatl/pipeline/translate_stage.py`, `tests/core/test_rates.py`,
`tests/core/test_ledger.py`, `tests/core/test_call_priced.py`, `tests/core/test_budget_run.py`.
**Callers that build `CostRecord(` positionally** must still pass: the new
field is last and defaulted; RED checks `tests/core/test_ledger.py` and
`tests/core/test_bench_cost.py`.

Oracle partition: AC-1 to AC-4 **settled** (read the audit's numbers out;
do not derive a discount); AC-5 **mechanical**.
