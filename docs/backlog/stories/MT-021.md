## Context

Brief feature 7 and section 3 step 5. MT-006 built the sibling-folder write for
pass-through pages; this story composes the real thing — cleaned page plus
typeset English — and bakes it.

`architecture.md` D8: written whole, to a sibling folder, atomically per page.
The output is **baked pixels**, not an overlay — an overlay format is a brief
non-goal, and this is where somebody would be tempted to add one "just in case".

**Which required gate would fail if this story's artifact broke:** `unit`,
`coverage`, and — because the glyph rendering lives in `mangatl.typeset`
(PO-4) — `coverage-core` at 100 %. `gates.sh --list` `covers` lines:
`unit`/`coverage` read `src/mangatl/**`, `coverage-core` reads
`src/mangatl/typeset/**`. Nothing this story builds is read only by an optional
gate (no GPU, no network, no browser), so `required_gates` stays empty.

### C-2 — Rendering a block (`bake_page`)

- Ink colour is **black, `(0, 0, 0)`**. No stroke, no outline, no shadow —
  nothing in `typeset-font.md` asks for one.
- Each `PlacedGlyph` is drawn alone, in its own `font_path` at its own
  `size_px`, with its **left-baseline** at `(x, baseline_y)` in page pixels —
  exactly the position `fit` emitted (`measure.py`: "what is measured is what is
  drawn"). No re-layout, no kerning, no rounding of `size_px`.
- Coverage is the rasteriser's anti-aliased 8-bit alpha `a ∈ [0, 255]`.
  Composite is alpha-over, per channel:
  `out = round(dst * (255 - a) / 255)` with black ink, integer result,
  computed so it is exact for `a == 0` (`out == dst`) and `a == 255` (`out == 0`).
- Blocks are composited **in the order given** (reading order), each over the
  result of the previous. With black ink the result is order-independent in
  value, but the order is still fixed so that a later ink colour cannot make it
  nondeterministic.
- **The mechanism is a checkable suggestion, not part of the contract:**
  Pillow's `ImageFont.truetype(font_path, size=size_px)` (float size, Pillow
  ≥ 10.1) and `ImageDraw.text((x, baseline_y), char, font=..., anchor="ls")`
  onto an `L` layer, which honours fractional positions in Pillow 12.3 (the
  installed version). If GREEN measures that it rounds the position or that
  hinting moves ink by a pixel, it reports that and chooses another way to hit
  the same positions; what is pinned is the position, not the API.
- *RED amendment (2026-10-03, Test Developer):* **measured, the suggestion as
  written misses the pinned position.** Plain `ImageDraw.text(..., anchor="ls")`
  at the glyph's own `size_px` fails `test_each_glyph_darkens_exactly_the_pixels_its_ink_box_covers`
  on 1 of its 8 glyphs (`g`/regular/19.5: leftmost inked column 125, ink box
  starts in column 124), and in a wider probe (4 faces x 15 glyphs x 5 sizes x 3
  sub-pixel offsets) its inked bounding box differed from the fontTools ink box
  rounded outward on 476 of 900 cases. The same call at **4x, 8x or 16x** the
  size and position, reduced by a box mean over each 4x4/8x8/16x16 block, passed
  every test in `test_typeset_render.py`. That is a measurement for GREEN, not a
  choice made for it; the pinned thing is still the position.

### C-3 — The bake area and the clip

The **bake area** `A` of a page is the union of:

1. MT-019's erase mask, `mangatl.clean.mask.erase_mask(regions, (W, H))` — the
   union of region masks **dilated by `MASK_DILATION_PX`**. The cleaner changes
   pixels in the dilation ring, so the original "union of region masks" was
   false against the code (PO-5).
2. Every region's `polygon` **filled** (`cv2.fillPoly`, closed ring, page
   pixels). The polygon is the mask component's outer contour, so its fill
   covers holes in the mask that typeset English may land on (PO-5).

`bake_chapter` computes `A` and passes it as `clip`. `bake_page` sets `a = 0`
wherever `clip` is `False`. So a block that **overflowed** (`TypesetBlock.
overflowed`, ink possibly past the polygon) is clipped to the bake area rather
than painted onto the art — the epic's "nothing outside a detected region
touched" (PO-5).

AC-2's test computes `A` itself — the dilation **from the pinned radius**, not
by calling `erase_mask` — so that a bake area grown by the implementation is
not agreed with by construction.

### C-4 — What each region gets (`bake_chapter`)

Per page, regions from `project.read_regions(ordinal)` and lines from
`mangatl.store.lines.read_review_lines(project, ordinal)`, zipped by position
(both are in `reading_index` order, one entry per region).

A region is **empty** (no block; counted in `regions_empty`) when its line is
`None`, or its `status == "failed"`, or
`mangatl.domain.line.effective_text(line).strip() == ""`. Otherwise its block is
`typeset(effective_text(line), region.polygon, faces)` with
`faces = load_faces()` loaded **once per `bake_chapter` call**.

A `MissingGlyph` from `typeset` **propagates** (the bake fails, with AC-4's
guarantees). Font fallback is MT-027's, which records it on this `BakeReport`.

`unreviewed_lines` counts lines (not `None`) whose status is `"proposed"`.
`failed` lines are not counted there: they are empty regions, and
`BakeConfirmDialog` lists them separately (`components.md` §9).

*Added by the PO in RED, 2026-10-03, answering the test-developer's open
question (PO-6):* the two counts have different scopes.
`unreviewed_lines` is about **review**, so it counts every `proposed` line in
the chapter, **including on a page with no cleaned image** (C-5 row 2) — the
dialog's "6 of 340 lines" is a chapter number. `regions_empty` is about the
**bake**, so it counts only regions on pages that were actually baked (C-5 row
3); regions on an uncleaned page are not baked at all and are reported through
`pages_uncleaned`. A whitespace-only `proposed` line counts in **both**, as C-4
reads literally: it is an empty region and a line nobody reviewed.

### C-5 — What each page becomes, and its encoding

| Page | Bytes written |
|---|---|
| no regions | the source file's bytes, verbatim |
| regions, but `project.read_cleaned(ordinal) is None` | the source file's bytes, verbatim; counted in `pages_uncleaned` |
| regions and a cleaned image | `bake_page(decoded cleaned RGB, blocks, A)` encoded in the source's format |

- Decoding: `Image.open(...).convert("RGB")` for both the cleaned image and,
  in tests, the source. Output mode is **RGB** for every baked page — a
  greyscale source comes out as RGB with equal channels (AC-2 compares in RGB).
- Format is taken from the **source filename's suffix**, case-insensitively:
  `.png` → `format="PNG"`; `.jpg`/`.jpeg` → `format="JPEG", quality=95,
  subsampling=0` (4:4:4). Nothing else is reachable: intake accepts only
  `PAGE_SUFFIXES`.
- The JPEG loss is PO-1's recorded cost of keeping the filename.

### C-6 — The output folder (MT-006 semantics, kept)

- `output_dir` is created if absent and **emptied before the first page is
  written** (`architecture.md` §5: "Overwritten on each bake"). That emptying is
  AC-5's stale-file removal.
- Pages are written in `project.pages()` order, each to
  `output_dir / (page.filename + ".part")` and then `os.replace`d onto
  `output_dir / page.filename`. The temp is unlinked in a `finally`. `os.replace`
  is called **as `os.replace`**, never `from os import replace`, so a
  `monkeypatch.setattr(os, "replace", ...)` reaches it (MT-006's constraint).
- An `OSError` (or any exception) propagates; no `BakeReport` is returned for a
  failed bake. What was written before it stays whole and correctly named.
- `pages_written` is the number of files written: `len(project.pages())` on
  success.
- The source folder is opened for reading only (AC-7).

### Oracle partition — entirely mechanical

Every criterion has an exact right answer. AC-2 is exact equality on the
complement of `A`, with no tolerance, as in MT-019 AC-4. No criterion needs an
invented metric.

AC-2 is **stronger** than MT-019 AC-4, not a duplicate of it: MT-019 asserts the
cleaner did not touch outside the mask; this asserts the whole bake path —
clean, typeset, composite, encode — did not. An encoder setting that
recompresses the whole page would pass MT-019 and fail this (on PNG).

## Amendments

All four were made on 2026-10-03 **while the story was still PLANNED**, by the
PO, on the user's answers to three questions put before RED. They are recorded
here because `check-boundaries.sh` compares the criteria with `origin/main`,
where the story was committed in its pre-dispatch form.

- **AC-2.** *Was:* "the output is the cleaned page with each region's typeset
  block composited at its fitted position, and every pixel outside the union of
  region masks equals the source page." *Now:* the same, but outside the **bake

  array for every page and on the decoded file for PNG input. *Why:* exact
  equality is unreachable for a JPEG re-encode (user, PO-1), and "union of
  region masks" was false against MT-019's dilated erase mask and MT-020's
  polygon fitting (PO, PO-5). *Approved:* the user (PO-1); PO-5 by the PO and
  reported to the user before RED.
- **AC-3.** *Was:* "written as `.png` only if the design says so — otherwise it
  preserves the input extension and format (settled: preserve)." *Now:* keeps
  filename, extension and format (PNG → PNG, JPEG → JPEG at quality 95, 4:4:4);
  a page with no regions is the source bytes unchanged. *Why:* settles the
  encoder and the lossless no-region path PO-1 chose. *Approved:* the user.
- **AC-8.** *Was:* "the bake dialog states the count of unreviewed lines rather
  than blocking." *Now:* `BakeReport.unreviewed_lines` states it; the dialog is
  MT-066. *Why:* the UI has no bake command; the dialog was a story's worth of

- **AC-9 (added).** `mangatl <folder>` writes baked pages and prints the summary

### Positional oracle (AC-2, deferred condition 3) - why it is exact

Each glyph in `test_typeset_render.py` is a hand-built `PlacedGlyph` placed so
that the **left and top** edges of its ink box - read by `_typeset_oracle.ink_px`
with fontTools, importing nothing from `mangatl` - fall on a half pixel, and the
sizes are chosen so the **right and bottom** edges fall in [0.34, 0.66] of a
pixel (asserted by a precondition test). Every pixel the ink box overlaps by at
least ~0.3 px then has coverage far above 1/255, and every pixel it does not
touch has coverage exactly 0, so the bounding box of the changed pixels per
glyph equals the ink box rounded outward **exactly**, robust to any renderer
error below ~0.3 px (hinting, filter, supersampling factor) and broken by any
1 px shift. "Changed" equals "a > 0" because the cleaned page keeps every
channel >= 140 (C-2's formula changes a value at a = 1 iff it is >= 128). The
composite formula is checked without knowing `a`: the three channels differ, so a
pixel is consistent only if one `a` in 0..255 reproduces all three. Rendering
detail GREEN must confirm: that its rasteriser hits these positions to within
0.3 px - plain Pillow at the glyph's own size does not (C-2 RED amendment).

At chapter level the file is compared (a) against the decoded SOURCE outside
`A` with no module help, and (b) against `bake_page(cleaned, typeset blocks, A)`,
which pins that the chapter bakes the cleaned page, the effective text, the
right polygons and a clip that includes the polygon fill (masks here cover a
small part of each bubble: `A` = 11 844 px, the dilated masks alone 1 972 px).
