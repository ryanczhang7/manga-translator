## Context

Brief feature 7 and section 3 step 5. MT-006 built the sibling-folder write for
pass-through pages; this story composes the real thing — cleaned page plus
typeset English — and bakes it.

`architecture.md` D8: written whole, to a sibling folder, atomically per page.
The output is **baked pixels**, not an overlay — an overlay format is a brief
non-goal, and this is where somebody would be tempted to add one "just in case".

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage`.

## Acceptance criteria

- **AC-1** — Given a chapter where every page has cleaned pixels and typeset
  blocks, when bake runs, then `<source>_en/` contains one file per page with
  the **same filenames** as the input and no others.
- **AC-2** — Given a page, when it is baked, then the output is the cleaned page
  with each region's typeset block composited at its fitted position, and
  **every pixel outside the union of region masks equals the source page**.
- **AC-3** — Given a `.jpg` input, when it is baked, then the output is written
  as `.png` **only if** the design says so — otherwise it preserves the input
  extension and format. *(Settled below: preserve the extension; see Contract.)*
- **AC-4** — Given a bake that fails partway on page 7, when the folder is
  inspected, then no partial `page7` file exists and pages 1–6 are complete.
- **AC-5** — Given a previous bake left a file whose page no longer exists in
  the chapter, when bake runs, then that file is removed — the output folder
  matches the chapter exactly.
- **AC-6** — Given a line whose status is `failed` or whose text is empty, when
  its region is baked, then the region is **cleaned but left empty**, and the
  bake result reports how many regions were left empty.
- **AC-7** — Given a bake, when it completes, then **no file inside the source
  folder** has been created, modified or deleted.
- **AC-8** — Given lines that have not been reviewed, when bake is requested,
  then it proceeds, and the bake dialog **states the count of unreviewed lines**
  rather than blocking. *(`docs/wiki/design/components.md` §7: review does not
  gate render.)*

## Contract

```
src/mangatl/pipeline/bake.py
    def bake_page(cleaned: NDArray[np.uint8],
                  blocks: Sequence[TypesetBlock]) -> NDArray[np.uint8]
    @dataclass(frozen=True) BakeReport:
        pages_written: int
        regions_empty: int
        unreviewed_lines: int
    def bake_chapter(project: Project, output_dir: Path) -> BakeReport
```

**Settled decisions, so they are not re-argued in RED:**

- **Output preserves the input extension and format** (AC-3). The brief says
  "sibling folder, same order and filenames" — changing `page3.jpg` to
  `page3.png` breaks "same filenames", and the user's next step is an image
  editor that does not care. JPEG re-encode quality is a real loss and is
  recorded here as the cost of honouring the brief; if the user would rather
  have PNG everywhere, that is a change to a stated constraint and goes to them.
- **Compositing is alpha-over at the fitted position**, on the cleaned page, in
  reading order. Reading order matters only where two typeset blocks overlap,
  which should not happen and must be deterministic when it does.
- **Atomic per file**: write to a temporary name in the destination directory,
  then `os.replace`. Same filesystem, so the rename is atomic on Windows and
  POSIX alike.
- **The output folder is made to match the chapter** (AC-5), not merged with
  whatever was there. A stale file the user cannot account for breaks the
  "same order and filenames" promise more quietly than a missing one.

**Oracle partition: entirely mechanical.** Compositing, file naming, atomicity
and tree equality all have exact right answers. AC-2's "equals the source
page" is exact equality on the complement of the masks, as in MT-019 AC-4 — no
tolerance.

Note that AC-2 is **stronger** than MT-019's AC-4 and not a duplicate of it:
MT-019 asserts the cleaner did not touch outside the mask, this asserts the
*whole bake path* — clean, typeset, composite, encode — did not. An encoder
setting that recompresses the whole page would pass MT-019 and fail this.

## Deferred verifications

- *Falsifiable condition 1:* with `bake_chapter` made to write to the final
  filename directly rather than temp-then-rename, AC-4 **must** fail.
- *Falsifiable condition 2:* with the stale-file cleanup removed, AC-5 **must**
  fail.
- *Falsifiable condition 3:* with the composite offset shifted by **one pixel**
  — a wrong value rather than a removed behaviour — AC-2 **must** fail. A
  one-pixel error is the kind that a tolerance-based assertion would swallow,
  which is why AC-2 is exact.
- **Owner: GATES.** Three mutations via `bash scripts/mutate.sh`.

## Design notes

Bake dialog: `docs/wiki/design/components.md` §7. It states the unreviewed-line
count and proceeds; it does not block. Error-message shape: `voice.md`.

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition: entirely mechanical.** The two judgement calls (preserve
  extension; match-not-merge the output folder) are settled in this contract.
- **Success condition, falsifiable:** AC-2 is asserted as exact pixel equality
  on the mask complement, not with `allclose` or a PSNR threshold. A tolerance
  there makes the criterion unable to see a whole-page re-encode, which is the
  defect it exists to catch.
- **Verdict:** *to be recorded.*
