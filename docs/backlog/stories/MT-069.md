## Context

Filed by the MT-068 spike under its AC-4(a). Read
`docs/wiki/audits/MT-068-cv2-parallel-failure.md`, `## Decided` 1, 3 and 4 and
evidence E3-E6 and E9, before anything else.

**What breaks.** OpenCV 5.0.0 runs its parallel calls on the statically linked MSVC
Concurrency Runtime. The first parallel cv2 call on a thread attaches that thread
to ConcRT, and the attach calls `SetThreadpoolWait` on the calling thread. If the
process's default Windows thread pool has lost its I/O completion port handle,
`SetThreadpoolWait` raises `0xC000070A` (`STATUS_THREADPOOL_HANDLE_EXCEPTION`).
cv2 reports that as `cv2.error: Unknown C++ exception from OpenCV code`, and it
happens on **every** parallel cv2 call that thread makes, for the life of the
process.

**How this has failed.** It failed the `unit`, `coverage` and `coverage-core`
required gates four times between 2026-09-28 and 2026-10-05. Inducing the state
reproduces the 2026-10-05 logs exactly: 135 failed, 30 errors, the same ids
(audit E6).

**Exposure in the app [INFERRED].** The app runs each pipeline run and each bake
on a new thread, so the app is exposed too.

**What this story does.** It makes the production cv2 call sites survive that
state. It is defence in depth. The trigger, a stray `CloseHandle` from CPython
3.12's `_wmi` worker, is MT-070's.

The required gate that fails if this story's artifact breaks is `unit`, which
runs `tests/core`.

## Acceptance criteria

- **AC-1** - Given a fresh Python process whose default thread pool's I/O
  completion port has been closed before any cv2 call, when `erase_mask` and
  `letterbox` are called on the main thread with the fixture inputs, then both
  return the same arrays and values as the same calls in a fresh process where
  nothing was closed. Neither raises.
- **AC-2** - Given the same process state, when the same two calls run on a
  `threading.Thread` started after the port was closed, then they return the same
  results as in AC-1's clean process.

## Contract

- **Production entry points under test (unchanged signatures):**
  `mangatl.clean.mask.erase_mask(regions: Sequence[RawRegion], page_size: tuple[int, int]) -> NDArray[np.bool_]`
  and
  `mangatl.detect.postprocess.letterbox(page, side=MODEL_INPUT_SIDE, pad=PAD_VALUE) -> tuple[NDArray[np.float32], LetterboxTransform]`.
  Use a page that is **not** already `side` wide. A same-size resize copies, never
  reaches ConcRT, and so cannot fail (audit E9). A 48x64 erase mask does reach
  ConcRT (audit E3).
- **The inducing step**, re-derived from audit recipe A and not copied from
  `spikes/`:
  - in a fresh `sys.executable` subprocess, before any cv2 call, close the
    lowest-valued handle whose object type (`NtQueryObject`,
    `ObjectTypeInformation`) is `IoCompletion`;
  - then make the calls.

  The audit measured that closing that handle, and only that one of the 15
  thread-pool handles tried, breaks parallel cv2 (E5).
- **Oracle partition.** Both criteria are **mechanical**: equality with the clean
  process's output, and no exception.
  - *Negative control:* the clean process must produce the reference output.
  - *RED's expected failure:* in the induced process, both calls raise `cv2.error`
    whose message contains `Unknown C++ exception from OpenCV code`, in every
    attempt. The audit measured 30 of 30 for a bare `cv2.dilate` (E5).
  - A RED failure of any other kind is the wrong failure.
- **Baselines read out, not re-derived:** audit E5 (30/30 induced, 30/30
  control), E6 (exact suite match), E9 (`cv2.setNumThreads(0)` or `(1)` survives
  the closed port; a thread that attached *before* the loss survives, one
  attaching after it does not).
- **Platform.** The mechanism is Windows-only. A `skipif(sys.platform != "win32")`
  marker is a fact about the platform, not a weakening. CI's `gates.yml` runs on
  `windows-latest`.
- **Layer: production start-up.** That means any process that imports the modules
  calling cv2, not `mangatl.app` alone. The gates are where this failed, and the
  test harness must inherit the fix by importing production code, not from a
  conftest of its own. The implementation is not chosen here. Audit E9 states the
  constraint that makes one option known to work, and it is evidence, not a
  recommendation.
