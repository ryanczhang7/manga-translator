## Acceptance criteria

*Draft — to be confirmed and made testable in this story's own PLANNED phase.*

- **AC-1** — *(integration)* Given a two-page fixture where a name appears on
  both pages, when both are translated live with the glossary enabled, then the
  same English name appears in both pages' proposals.
  *Control:* the same two pages translated with the glossary **disabled** (both
  pages given `EMPTY_CONTEXT`) must be allowed to differ. If they never differ,
  the fixture does not exercise the mechanism and AC-1 is measuring nothing.
  Record how many of K runs differed in each arm.

## Oracle

**Oracle-free, stochastic.** Do not write it as one run asserting equality.
Invent the consistency measure (for example: page 2's rendering of the name
equals page 1's, read from `proposed_terms` and the lines). State K, record the
observed counts for both arms, and set the bar with headroom over the control.

**Fixture design is the risk.** A name with one obvious romanisation
(さくら → Sakura) will be consistent with the glossary off, the control will
never differ, and the story will measure nothing. The name must have several
defensible renderings, such as a kanji name with more than one reading (翔:
Shō / Sho / Shou / Kakeru) or a long-vowel name (りゅうのすけ: Ryūnosuke /
Ryuunosuke / Ryunosuke). Page 2 must show it without furigana. Cost is about
K × 4 page calls; at MT-038's measured per-page cost, state K's price before
dispatch.
