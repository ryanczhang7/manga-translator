- **AC-1** — *(integration, live)* Given the two-page fixture (C-1) in which
  the name **翔** appears on both pages with no furigana, when the pair is
  translated live on Gemini **K = 10** times with continuity **on** - page 1
  with `EMPTY_CONTEXT`, page 2 with the glossary and rolling blocks built from
  page 1's result exactly as `pipeline.continuity.build_prompt_context`
  builds them (C-3) - then in **at least 9 of the 10** runs the reading of 翔
  extracted from page 2's name line (C-2) equals the reading extracted from
  page 1's, and neither is `"?"`.
- **AC-2** — *(integration, live; the negative control)* Given the same pair
  translated K = 10 times with continuity **off** - both pages given
  `EMPTY_CONTEXT` - then the two readings differ, or one is `"?"`, in **at
  least 4 of the 10** runs. This arm is what makes AC-1 a measurement: if it
  comes out ≥ 7 of 10 consistent the fixture is not exercising the mechanism
  and the **test fails**, and the fixture - never the bar - is what changes.
  Both arms' per-run readings, the counts, and page 1's proposed `name` terms
  are printed and pasted into `## Notes`.
- **AC-3** — *(core, mechanical)* Given page 1's `TranslationResult` and its
  OCR lines, when the live test's own page-2 `PromptContext` (C-3) is compared
  with `build_prompt_context(project, 1)` on a real project holding the same
  page-1 regions, proposals and glossary, then the two are **equal** - so the
  live test sends what the pipeline sends, and cannot drift from it.

## Oracle

**Oracle-free, stochastic.** Do not write it as one run asserting equality.
Invent the consistency measure (for example: page 2's rendering of the name
equals page 1's, read from `proposed_terms` and the lines). State K, record the
observed counts for both arms, and set the bar with headroom over the control.

**Fixture design is the risk.** A name with one obvious romanisation
(さくら → Sakura) will be consistent with the glossary off, the control will
never differ, and the story will measure nothing. The name must have several
defensible renderings, such as a kanji name with more than one reading (翔:
Shō / Sho / Shou / Kakeru) or a long-vowel name (りゅうのすけ: Ryūnosuke /
Ryuunosuke / Ryunosuke). Page 2 must show it without furigana. Cost is about
K × 4 page calls; at MT-080's measured Gemini per-page cost (≈ $0.0055), state K's price before
dispatch.

**C-1 The fixture: `fixtures/translate/kakeru-{p1,p2}.png`, `kakeru-ocr.json`, `kakeru_render.py`.**
Two synthetic manga-style pages (PO-1), rendered once with
`kakeru_render.py` (Pillow, a Japanese font found on the rendering machine -
`C:/Windows/Fonts/msgothic.ttc` or `YuGothM.ttc` here; the font is **not**
committed and the PNGs are, so nothing at test time needs the font) and
committed. Each page: white, portrait, long edge ≤ 1568 px (so
`prepare_page_image` does not resize), 3-5 speech bubbles of short, natural
dialogue, **different** dialogue and layout on the two pages so they are not
the same image twice. The name **翔** appears in exactly one bubble per page,
as a bare kanji with **no furigana** on either page, in a different sentence
position on each (e.g. p1 `翔、こっちだ！`; p2 `翔はもう行ったのか？`). No
other kanji name; no romaji anywhere. `kakeru-ocr.json` is one JSON object
`{"p1": [...], "p2": [...]}`, each a list of `{"text", "ocr_empty"}` in
reading order - the bubble text as rendered, the same shape as
`page-011-ocr.json` - and the index of the name bubble on each page is a
constant in the test (`NAME_REGION = {"p1": i, "p2": j}`), asserted by a
non-live test that the region's text contains 翔 and no other region's does.
Provenance (who rendered it, with which font, the SHA-256 of each PNG) goes
in `fixtures/translate/README.md`. RED may change the dialogue, the name's
placement and the rendering if the control arm comes out too consistent
(AC-2); it may **not** replace 翔 with a name that has one obvious reading.

**C-2 The measure.** `READINGS = ("Shou", "Shō", "Shoh", "Syo", "Sho", "Kakeru")`
- longest first, so `Sho` cannot pre-empt `Shou`. `reading(text) -> str`
returns the first member of `READINGS` that is a case-sensitive substring of
`text`, else `"?"`. For a run, `r1 = reading(lines_p1[NAME_REGION["p1"]])`
and `r2 = reading(lines_p2[NAME_REGION["p2"]])`, where `lines_pN` is
`TranslationResult.lines`; a region the model omitted reads as `""` → `"?"`.
A run is **consistent** iff `r1 == r2 != "?"`. Also recorded per run, never
asserted: page 1's proposed terms whose `term_ja` contains 翔 (their
`term_en` and `note`), the raw name lines of both pages, and each call's
usage and priced cost (`domain.rates.price`, as `test_gemini_live.py` does).
RED may extend `READINGS` with a reading Gemini actually produced (say so).

**C-3 The arms.** One `run(context_for_p2)` does two `gemini.translate_page`
calls on one real `google.genai.Client(api_key=GEMINI_API_KEY)`:
page 1 with `EMPTY_CONTEXT`, then page 2 with `context_for_p2(result_p1, ocr_p1)`.
- **continuity on:** `PromptContext(render_block(mark_seen(merge([], result_p1.proposed_terms, 0), [l.text for l in ocr_p1], 0), MAX_GLOSSARY_TOKENS), render_rolling([result_p1.lines[i] for i in range(len(ocr_p1)) if i in result_p1.lines], MAX_ROLLING_TOKENS))`
  - the composition `continuity.build_prompt_context` makes for ordinal 1
  after `translate_stage._update_glossary` ran on page 0, without a store.
- **continuity off:** `EMPTY_CONTEXT`.
K = 10 runs per arm, run alternately (on, off, on, off, ...) so a transient
model-side change hits both arms alike. 40 calls per full run.

**C-4 `tests/integration/test_glossary_live.py`.** `pytestmark = pytest.mark.network`,
