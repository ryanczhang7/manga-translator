## Context

Filed by the EPIC-04 mutation audit,
`docs/wiki/audits/EPIC-04-2026-10-13.md`: survivors SG3, SG9 and SG2
(`## Decided` item 4, `## Evidence` E-2 and E-5).

MT-014 C-6 settled the single-span rule by which a user's edit to a line
updates the chapter glossary (`store/glossary.py::reconcile_from_edit`, via
`_renamed`). Three of its clauses can be removed or bent with every test
green:

- **SG3, step 3 ("the user kept the name", `store/glossary.py:123`).** Remove
  the check and the suite stays green, because no fixture has a `replace`
  landing exactly on a name the user kept. A user who *swaps* two names
  (`"Kenji came, Sato left."` -> `"Sato came, Kenji left."`) would then have
  Kenji's glossary entry renamed to "Sato", and every later page would call
  Kenji "Sato". This is the one in this story that silently changes a name.
- **SG9, `_occurrences`' last window (`store/glossary.py:145`).** An
  off-by-one in the range misses a name that is the line's last token. Every
  fixture ends in punctuation, so nothing notices, and a rename such as
  `"Run, Kenji"` -> `"Run, Mr. Tanaka"` is then silently not recorded.
- **SG2, step 2 ("exactly once in the proposal", `store/glossary.py:120`).**
  The one twice-in-proposal case also keeps the name, so step 3 decides it
  and step 2 is never the deciding clause.

**Settled** (the audit's `## Decided`): these clauses are unprotected, and
C-6's rule is unchanged; this story pins it rather than revisiting it.
**Evidence, to verify:** the three `_renamed` results below were measured on
the shipped code and under each mutant (audit E-5), and RED re-measures them.

## Acceptance criteria

- **AC-1 (SG3)**: Given a glossary entry for a name, and a line whose proposal
  contains that name once, when the user's edit **swaps** it with another
  name that stays in the line (proposal `"Kenji came, Sato left."`, final
  `"Sato came, Kenji left."`), then the entry keeps its rendering and its
  `source`: the edit is not read as a rename. Fails under SG3, where the entry
  becomes `"Sato"`.
- **AC-2 (SG9)**: Given a glossary entry for a name that is the **last token**
  of the proposed line, with no trailing punctuation (proposal `"Run, Kenji"`),
  when the user replaces exactly that name (final `"Run, Mr. Tanaka"`), then
  the entry takes the user's wording (`"Mr. Tanaka"`, `source == "user"`).
  Fails under SG9, where the entry is left unchanged.
- **AC-3 (SG2)**: Given a name that occurs **twice** in the proposed line,
  when the user renames **both** occurrences the same way (proposal
  `"Sakura? Sakura!"`, final `"Sakura-chan? Sakura-chan!"`), then the entry
  is left alone, because C-6 step 2 reads only a name that occurs exactly
  once. Fails under SG2, where the entry becomes `"Sakura-chan"`.
