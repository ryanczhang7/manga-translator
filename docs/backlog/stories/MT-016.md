## Context

**The brief calls this the single most important interaction in the product**,
and gives the reason: the review screen is the only place a human can catch an
error, and an unclear link makes the review worthless. Every other story in this
epic is in service of this one.

Design is settled in `docs/wiki/design/components.md` §4 and
`docs/wiki/design/accessibility.md` A-06, A-07, A-10. Two of the designer's
decisions are restrictions somebody will later try to "improve", and both are
written as normative:

- **hover never moves any viewport**;
- **selection pans but never zooms.**

One contrast decision is load-bearing and is not a palette choice: **no single
flat colour clears 3:1 against both pure black and pure white art** (the
designer's arithmetic: ≤0.175 versus ≥0.183 relative luminance, mutually
exclusive). Every marker is therefore stroked twice — dark halo, light core.
Tokens cannot prove the paint code draws both strokes; AC-8 is what does.

**Which required gate would fail if this story's artifact broke:** `unit`
(`tests/ui/`, offscreen).

## Acceptance criteria

- **AC-1** — Given a page with regions, when a translation row is selected, then
  exactly one region is marked selected on the canvas, and it is that row's
  region.
- **AC-2** — Given a page with regions, when a region is clicked on the canvas,
  then that region's row becomes the selected row and is scrolled into view in
  the translation column.
- **AC-3** — Given a selected row whose region lies **outside** the viewport,
  when the selection is made, then the view pans so the region's bounding rect
  is fully contained with at least 24 px margin, **and `transform().m11()` (the
  zoom) is unchanged**.
- **AC-4** — Given a selected row whose region is **already fully visible**, when
  the selection is made, then the viewport does not change at all.
- **AC-5** — Given a region is hovered, when the hover state settles, then both
  the region and its row show their hover treatment, **and neither the canvas
  viewport nor the list scroll position changes**.
- **AC-6** — Given two overlapping regions, when the overlap area is clicked,
  then the smaller-area region is selected; when the same point is clicked
  again, the selection cycles to the other.
- **AC-7** — Given a selection, when the canvas is inspected, then every
  non-selected marker is dimmed to `overlay.dim.opacity`, and each marker carries
  its reading-order ordinal as a badge — so the link survives without colour.
- **AC-8** — Given a marker is painted, when its paint calls are captured, then
  **two strokes are drawn**: the halo at `overlay.halo` and the core at the
  region's state colour, in that order.
  *Control:* with the halo stroke removed, this assertion must fail — the test is
  about the mechanism, not about the final pixel, because a single-stroke marker
  over mid-grey screentone still looks fine and fails over black art.
- **AC-9** — Given focus is in the translation column, when `Up`/`Down` are
  pressed, then selection moves between rows; when focus is on the canvas and
  `Enter` is pressed, then focus moves into the selected row's editor.
- **AC-10** — Given a selection changes, when the accessibility tree is
  inspected, then the selected row's accessible name states its reading-order
  ordinal, and a live region announces the change.
  *(Per-`QGraphicsItem` screen-reader navigation is **not** promised — Qt does
  not expose graphics items to UI Automation, and `accessibility.md` A-13 records
  that limit rather than papering over it.)*

- **PO-3 — no page-edge padding.** The scroll range is the page's scene rect, so
  a region within 24 screen px of the page edge cannot get the full margin. The
  `OffscreenIndicator` (§4.6) is what the design gives for "it did not fit"; it
  is not in this story's criteria and is recorded as a follow-up. AC-3's
  fixture keeps regions away from the page edge.
- **PO-4 — no animation.** §4.5's `motion.duration.base` pan is left for later:
  an animated pan makes AC-3/AC-4 assert on a timer, and the criteria are about
  where the view ends up.
- **PO-5 — canvas `Up`/`Down`/`Home`/`End` and the `OffscreenIndicator` are not
  built.** Normative in §4.6/§4.7 but in no criterion here; building them
  untested would break law 1. Follow-up story recommended at the end.

**Rules that are settled and must be read out:**

- **One selection at a time**, held as a single `selected_region_id`. Hover is
  separate state and never changes selection.
- **The reading-order ordinal is the primary carrier of the link** — a badge on
  the art and the leading element of the row. Colour is secondary. This is what
  makes the link work for a colour-blind user and in a screenshot.
- **`pan_to_contain` returns `None` when no pan is needed**, which is what makes
  AC-4 assertable as "the viewport did not change" rather than as "it changed by
  approximately zero".
- **Pens are cosmetic** (`QPen.setCosmetic(True)`), so marker stroke width is
  constant in screen pixels regardless of zoom. Without this, a marker vanishes
  when zoomed out and becomes a slab when zoomed in.
- **Hit test: smallest area wins; repeated clicks at the same point cycle.**

## Design notes

*Lifted from `docs/wiki/design/README.md`:*

> One selection at a time, held as a single `selected_region_id`; hover is
> separate state and never changes selection. The primary carrier of the link is
> the reading-order ordinal, rendered as a badge on the art and as the leading
> element of the row — so the link survives without colour. Selected bubble:
> `overlay.bubble.selected` core at `overlay.stroke.core-selected` over an
> `overlay.halo` stroke, `overlay.fill.selected`, filled badge, **and every other
> marker dimmed to `overlay.dim.opacity`**. Selected row: `color.surface.selected`
> ground, 3px `color.accent.base` leading bar, filled badge. Hover highlights
> both sides but never scrolls the list and never pans the canvas. Selection pans
> the canvas by the minimum amount that brings the region fully into view with
> `space.6` margin, and **never changes zoom**. If the region still is not fully
> visible, the `OffscreenIndicator` appears at the nearest viewport edge. Pens
> are cosmetic. Overlapping regions: smallest-area-wins hit test, repeated clicks
> cycle. Keyboard: `Up`/`Down` move selection in either pane, `Enter` on the
> canvas moves focus into the selected row's editor. See components.md §4 and
> accessibility.md A-06, A-07, A-10.
>
> **Assertable:** selecting a row whose region lies outside the viewport pans the
> view so the region's bounding rect is fully contained with ≥ 24px margin, while
> `transform().m11()` (the zoom) is unchanged — and selecting a row whose region
> is already fully visible does not change the viewport at all.
