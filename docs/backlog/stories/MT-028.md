## Context

The second of the High Contrast stories (MT-026 is the first). MT-026 built
`resolve`; this story is the **theme path** that calls it — detection behind an
interface, stylesheet re-composition, application at startup, and a live mode
change that must not cost the user a sentence they were typing.

**Cut down on 2026-10-07 (PO-1 in `## Notes`, user-approved).** As drafted this
story carried thirteen criteria across six modules, and four of them rested on
components the dark theme does not have: the canvas has no `color.canvas.frame`
line (MT-015 deferred it), no QSS focus-ring rule, no `ghost`/`secondary`/
`destructive` button exists, no `e2` drop shadow exists, and the cost readout
shows one glyph where `components.md` §10.6 wants two. One story is one
RED→GREEN cycle. So:

- **MT-028 (this story)** — the theme path: detection, snapshot, compose,
  apply, the override rules that exist, live change, announcement.
- **MT-073** — the canvas under High Contrast, including the frame line and
  viewport focus ring MT-015 deferred, and the runtime mat check.
- **MT-074** — status glyphs that survive one colour: the `CostReadout` triple
  and the translation-row gutter.

Floor: `docs/wiki/design/accessibility.md` **A-15.3, A-15.4, A-15.8, A-15.10**,
with the reasoning in `docs/wiki/design/high-contrast.md` §2, §3 and §8 and
the deltas in `components.md` §10.1, §10.8.

Two things from the design document set the shape of the work:

- **The stylesheet overriding the palette is the bug, not the mechanism.**
  `QApplication.setStyleSheet` wins over `QPalette`, so a fully QSS-themed app
  keeps painting its own colours while a contrast theme is active. The app does
  **not** drop or narrow the stylesheet under High Contrast; it **re-composes**
  it from resolved values. `high-contrast.md` §2, §2.1.
- **Detection is one injectable boolean, default off.** The offscreen platform
  never reports a contrast theme, so without injection nothing here is testable
  on CI (A-15.4), and the fail-closed default is the opposite polarity from A-09
  for the reason §3 gives: an unpopulated palette is black on black.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage`, both `required`, both `covers src/mangatl/**`; they run `tests/ui/`
under `QT_QPA_PLATFORM=offscreen`. `required_gates` stays empty.

## Acceptance criteria

- **AC-1** — Given High Contrast reaches the app as **one boolean behind an
  interface**, when a test substitutes that interface, then the whole theme path
  runs under either setting with no display and no contrast theme present; and
  when nothing is injected — the platform call is not wired, fails, or the
  platform is not Windows — the default is **off**. *(A-15.4.)*
- **AC-2** — Given High Contrast is active, when the stylesheet is composed,
  then every `@{token}` placeholder in the base template is replaced by
  `resolve(token, high_contrast=True, palette=...)`, the override template is
  appended with its `@{hc.Role}` placeholders replaced by `palette[Role]`, and
  the result is **applied** with `QApplication.setStyleSheet` — the stylesheet
  is not dropped, not narrowed and not bypassed. *(A-15.3, §2.1.)* The
  assertable form (`README.md`): the composed sheet contains **no authored
  literal of any non-exempt colour** — no `#1C1C1C`, no `#4CC2FF` — while every
  `@static` colour the base template uses keeps its literal.
- **AC-3** — Given a real `QPalette`, when it is snapshotted for `resolve`, then
  the result is a plain `dict[str, str]` of uppercase `#RRGGBB` keyed by exactly
  the five role names, `DisabledText` taken from the **Disabled** group's
  `WindowText` and the other four from the **Active** group, and the adapter
  does nothing else. *(`high-contrast.md` §4.1, §4.3.)*
- **AC-4** — Given High Contrast is **off**, when the stylesheet is composed,
  then it is **byte-for-byte** the packaged `theme.qss` — the default theme is
  unchanged by this story, and startup still applies exactly one sheet before
  any window is built (MT-061 AC-1 keeps holding).
- **AC-5** — Given High Contrast is active, when the composed sheet is read,
  then the override template's rules are present **after** the base rules and
  resolve to the palette: `QPushButton:hover` sets its ground to `Window` (hover
  is **never a ground change**), `QPushButton:pressed` is the
  `Highlight`/`HighlightedText` pair, `QWidget` selection is that same pair,
  `QPushButton:disabled` and the text fields' disabled borders are
  `DisabledText`, and `QToolTip`/`QMenu` carry a 2 px `WindowText` border.
  *(`components.md` §10.1, `theme_hc.qss.in`.)*
- **AC-6** — Given High Contrast is active, when a focus rule in the composed
  sheet is read, then the ring takes **the foreground of the ground it sits
  on**: every `:focus` rule the base template defines resolves its ring to
  `WindowText`, except `QPushButton[variant="primary"]:focus` — the one
  `Highlight`-ground selector the base defines — whose ring is
  `HighlightedText`. *(A-15.8, A-04.)*
- **AC-7** — Given the app is running with an open `LineEditor` holding
  **uncommitted text**, a selected region, a scrolled translation column and a
  panned, zoomed canvas, when the contrast theme is switched on, and then off
  again, then the stylesheet is re-composed and re-applied each time and **none
  of those four is lost** — same `selected_region_id`, same column scroll value,
  same canvas `transform().m11()` and scroll offsets, same editor text with the
  edit still uncommitted. *(A-15.10, §8 — the uncommitted text is the one that
  would actually hurt.)*
- **AC-8** — Given a live mode change, when it completes, then the live region
  announces **exactly once** — "High contrast on." or "High contrast off." —
  and **no notice, banner or toast is shown**; and the initial application at
  startup announces nothing. *(§8, A-12.)*
- **AC-9** — Given a mode change signal whose value equals the current mode,
  when it fires, then nothing is re-applied and nothing is announced — the
  controller reacts to **changes**, not to notifications.

**Block 1 — detection: `src/mangatl/ui/contrast.py` (new).**

```
class ContrastSource(QObject):                 # the interface; QObject so it can carry a Signal
    changed = Signal(bool)                     # the NEW value, emitted only when it differs
    def is_high_contrast(self) -> bool: ...    # abstract: raise NotImplementedError

class FixedContrastSource(ContrastSource):     # the test double
    def __init__(self, value: bool = False, parent: QObject | None = None) -> None
    def is_high_contrast(self) -> bool
    def set_value(self, value: bool) -> None   # emits `changed(value)` iff value != current

class SystemContrastSource(ContrastSource):    # Windows: SPI_GETHIGHCONTRAST + WM_SETTINGCHANGE
    def __init__(self, parent: QObject | None = None) -> None
    def is_high_contrast(self) -> bool         # the last value read

def read_system_high_contrast() -> bool        # one ctypes call; False on ANY failure
```

- `read_system_high_contrast()` calls `ctypes.windll.user32.SystemParametersInfoW`
  with `SPI_GETHIGHCONTRAST = 0x0042` and a `HIGHCONTRASTW` struct
  (`cbSize: c_uint`, `dwFlags: c_uint`, `lpszDefaultScheme: c_wchar_p`), and
  returns `bool(dwFlags & HCF_HIGHCONTRASTON)` with `HCF_HIGHCONTRASTON = 0x1`.
  **Any** exception — `AttributeError` on a platform with no `windll`, a zero
  return from the call, anything — yields `False`. That is A-15.4's fail-closed
  default and it is total: the function never raises.
- `SystemContrastSource` reads once at construction and installs a
  `QAbstractNativeEventFilter` on `QCoreApplication.instance()` **if one
  exists** (never on an object handed to it); on a Windows `WM_SETTINGCHANGE`
  (`0x001A`) it re-reads and emits `changed` only when the value flipped. It
  keeps a reference to its filter (Qt does not). The ctypes mechanism is
  **checkable, not sacred**: GREEN runs `read_system_high_contrast()` on this
  host with the theme off and records `False`; the on-state is DV-4.
- Tests drive `FixedContrastSource` only. Nothing in `tests/ui/` imports
  `ctypes` or asserts anything about `SystemContrastSource` beyond: it is a
  `ContrastSource`, constructing it off-Windows (or with `windll` absent) gives
  `is_high_contrast() is False`, and it does not raise.

**Block 2 — the palette adapter: also `src/mangatl/ui/contrast.py`.**

```
def palette_snapshot(palette: QPalette) -> dict[str, str]
```

Returns exactly `{"Window", "WindowText", "Highlight", "HighlightedText",
"DisabledText"}` as keys, in that order; values are
`QColor.name(QColor.NameFormat.HexRgb).upper()` — `#RRGGBB`, uppercase, alpha
dropped. `DisabledText` is `palette.color(ColorGroup.Disabled, ColorRole.WindowText)`;
the other four are `palette.color(ColorGroup.Active, ColorRole.<same name>)`. No
other role is read; the function is total over any `QPalette`.

**Block 3 — composition: `src/mangatl/ui/theme.py` (extended; MT-026's `resolve`
is untouched).**

```
def compose_stylesheet(base_tmpl: str, hc_tmpl: str, *,
                       high_contrast: bool, palette: Mapping[str, str]) -> str
```

- `high_contrast=False` → the base template with every `@{name}` replaced by
  `resolve(name, high_contrast=False, palette=palette)`; the override template
  is **not** appended. The result equals the packaged `theme.qss` byte-for-byte
  (AC-4): `tokens_gen.TOKENS` carries each value in the text form the generator
  wrote, so the substitution is the generator's.
- `high_contrast=True` → the base template with every `@{name}` replaced by
  `resolve(name, high_contrast=True, palette=palette)`, then `"\n"`, then the
  override template with `@{hc.Role}` replaced by `palette[Role]` and any other
  `@{name}` by `resolve(name, high_contrast=True, palette=palette)`.
- Placeholder grammar is the generator's: `@{...}` (`tokens.py` `_PLACEHOLDER`).
  An `hc.Role` whose `Role` is not in `palette` raises `MissingPaletteRole`
  with `token="hc.<Role>"`, `role="<Role>"`; an unknown token raises
  `UnknownToken` (both from MT-026). Nothing is swallowed.
- The templates come from the package: `stylesheet.py` gains
  `BASE_TEMPLATE_RESOURCE = "theme.qss.tmpl"`, `HC_TEMPLATE_RESOURCE =
  "theme_hc.qss.tmpl"`, `base_template() -> str` and `hc_template() -> str`,
  read as `importlib.resources` bytes decoded UTF-8, exactly as
  `base_stylesheet()` does. `apply_base_stylesheet` and `base_stylesheet` stay
  as they are.

**Block 4 — the controller: also `src/mangatl/ui/theme.py`.**

```
class ThemeController(QObject):
    themeApplied = Signal(bool)                # after each apply, with the mode applied
    def __init__(self, app: QApplication, source: ContrastSource,
                 *, palette_provider: Callable[[], Mapping[str, str]] | None = None,
                 parent: QObject | None = None) -> None
    @property
    def high_contrast(self) -> bool            # the mode most recently applied
    live_region: LiveRegion                    # owned; parentless, off-screen (link.LiveRegion)
    def apply(self) -> None                    # compose for source.is_high_contrast(); app.setStyleSheet

def apply_theme(app: QApplication, source: ContrastSource) -> ThemeController
```

- `apply_theme` constructs the controller, calls `apply()` once, connects
  `source.changed` to the controller's change handler, and returns it. The
  caller keeps the reference (`app.py` stores it on a module-level name, say
  `_theme`, so it outlives `main`'s locals).
- `palette_provider` defaults to `lambda: palette_snapshot(QGuiApplication.palette())`
  — the **class-level** Qt palette, so that with High Contrast **off nothing but
  `setStyleSheet` is ever called on `app`** (the startup test's stand-in has only
  `setStyleSheet` and `exec`; block 6). The provider is called only when the
  mode being applied is `True`.
- The change handler: if `value == self.high_contrast` → return, no apply, no
  announcement (AC-9). Otherwise `apply()`, then `live_region.announce("High
  contrast on.")` or `"High contrast off."` — exactly those strings, once. The
  initial `apply()` from `apply_theme` never announces (AC-8).
- Re-applying is `app.setStyleSheet(new_sheet)` and nothing else: no widget is
  rebuilt, no window is recreated, no state is touched. Qt re-polishes every
  widget on a sheet change; preserving editor text, scroll, zoom and selection
  is a property of **not** doing anything else (AC-7), which is what DV-2 puts
  back.
- No notice, banner or toast: `ThemeController` imports nothing from
  `mangatl.ui.progress` and creates no `QWidget` other than its `LiveRegion`.
