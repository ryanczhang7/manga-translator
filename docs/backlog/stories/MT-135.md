## Context

EPIC-05 owns the review workspace and its theme. `components.md` §5
(`TranslationRow`, lines 876-881 at origin/main f1b2c15) gives the selected
row a **3px `color.accent.base` leading bar on a `color.surface.selected`
ground** and the hovered row a `color.surface.hover` ground, and
`accessibility.md` A-03 (38-41) makes that bar load-bearing: the selected
ground is 1.42:1 against `color.surface.raised`, so the bar is the only
selection carrier that clears 3:1. Neither is a rule today. `TranslationRow`
(`workspace.py` 641) is a plain `QWidget` set with `setItemWidget` (881-883),
transparent, so Qt's `::item` highlight shows through from beneath as the
selected ground; its `hovered` property is set and re-polished (670, 784-790)
and **no sheet rule reads it**; `theme.qss.in` 406-412 scopes MT-061 to the
gutter colours and says "the rest of the row is a later story". This is that
story for the selection and hover states. Under High Contrast the base bar
would be `Highlight` on `Highlight` (`[hc.map]`, `tokens.toml` 342-354), so
the override restates it, and §10.4 (`components.md` 1311 at f1b2c15, amended
2026-11-03) makes the selected HC row's gutter glyph and ordinal badge
`HighlightedText`.

The mechanism is MT-134's, chosen by the Lead Designer and confirmed by the
user on 2026-11-03: a `selected` dynamic property set and re-polished by
`TranslationColumn` from the list's current row, `WA_StyledBackground` on the
row, base rules in precedence order, an HC override with descendant rules.
Two user decisions bind it: the hover ground rule is **included** here, and
the selected bar **persists under the locked column** (components.md 933,
amended). MT-136 adds the status borders between these rules. Every line
number above was re-read in this worktree by the Lead PO at PLANNED.

The required gate that fails if the artifact breaks: `unit` (and `coverage`)
over `tests/ui`; `project.conf` `covers | unit | src/mangatl/**` reads
`workspace.py`.

## Acceptance criteria

All sampling below is under the **packaged `theme.qss` set as the application
stylesheet** (never `styleSheet()` on a widget), in a shown `Workspace` whose
column holds at least three rows (`test_app_theme_paint.py`
`_workspace_with_rows`, which also selects row 0 through `set_regions`), rows
fully inside the viewport. A row's "column *n*" is the vertical line of pixels
*n* pixels in from the row's left edge over the row's height less the list's
item spacing band at top and bottom (RED measures and records the band).
"Selected" means `window.translation_column.select(k)` (or `link.select(k)`),
which makes the list's row *k* current.

- **AC-1** — *The selected row carries the bar.* Given row *k* selected, when
  its columns are sampled, then columns 0, 1 and 2 are every pixel
  `color.accent.base` and column 3 is every pixel `color.surface.selected`.
- **AC-2** — *Control: an unselected row carries nothing.* Given row *k*
  selected, when every other row's columns are sampled, then columns 0 to 3
  are every pixel `color.surface.raised`.
- **AC-3** — *Nothing moves.* Given row *j ≠ k* selected, when row *k* is
  selected, then every row's `geometry()` and `sizeHint()` and every row's
  gutter, badge and editor `mapTo(viewport, (0, 0))` are identical before and
  after.
- **AC-4** — *The bar is the contrast carrier, by the fixture table.* Given
  `theme.contrast_ratio` over `tokens_gen.TOKENS`, then `color.accent.base`
  on `color.surface.selected` ≥ 3:1 (5.31) and on `color.surface.raised`
  ≥ 3:1 (7.54); *negative control:* `color.surface.selected` on
  `color.surface.raised` is **below** 3:1 (1.42, A-03).
- **AC-5** — *A selection change repaints.* Given row *k* selected and
  sampled as AC-1, when row *k+1* is selected and both are re-sampled, then
  row *k+1* satisfies AC-1 and row *k* satisfies AC-2; and selecting `None`
  leaves every row satisfying AC-2.
- **AC-6** — *Hover is a ground, never a bar.* Given row *k* selected and row
  *m ≠ k* hovered (`translation_column.set_hovered(m)`), when both are
  sampled, then row *m*'s columns 0 to 3 are every pixel `color.surface.hover`
  and row *k* still satisfies AC-1; when row *k* itself is hovered, its
  columns are unchanged from AC-1 (selected wins the ground over hover);
  *control:* with hover cleared (`set_hovered(None)`) row *m* satisfies AC-2.
- **AC-7** — *The bar persists under lock.* Given row *k* selected, when the
  column is disabled (`window.translation_column.setEnabled(False)`, the
  widget-level lock a run would apply) and row *k* is re-sampled, then
  columns 0 to 2 are still every pixel `color.accent.base`; re-enabling leaves
  AC-1 true.
- **AC-8** — *Under High Contrast the bar, the glyph and the badge are
  `HighlightedText`.* Given the sheet composed for High Contrast with the
  five-role test palette (`test_hc_error_banner_border.py` `PALETTE`), when
  row *k* is sampled, then columns 0 to 2 are every pixel `HighlightedText`
  and column 3 every pixel `Highlight`; the ink of row *k*'s `rowGutter` and
  `rowBadge` labels is `HighlightedText`; and an unselected row's gutter ink
  is `WindowText` (control). *Negative control:* the base template alone
  rendered against the same palette (no override) gives columns 0 to 3 all
  `Highlight`.
- **AC-9** — *The override is a real override.* Given the composed HC sheet,
  when `test_theme_apply.py`'s `OVERRIDES` table is extended with the new
  selectors (C-3), then each one's effective rule carries the declared
  palette values and the last rule naming it is in the appended block.

AC-4's 3:1 is WCAG 1.4.11 as `accessibility.md` fixes it; no other AC names
a threshold. The central claim's negative control is the defect put back
(`## Deferred verifications`).

### C-1 The base rules (`docs/wiki/design/theme.qss.in`, new block after the `QLineEdit#rowEditor[status="excluded"]` rule, 441-446)

The designer's precedence list has seven slots (components.md 998-1016); this
story authors **1, 2 and 6**, in that order, leaving a comment where 3-5
(MT-136) and 7 (focus, unbuilt) go. Later wins at equal specificity, and every
rule restates only the side it owns:

```
#translationRow {
    background-color: transparent;
    border: none;
}

#translationRow[hovered="true"] {
    background-color: @{color.surface.hover};
}

/* MT-136 authors [status="failed"], [status="edited"], [status="excluded"] here. */

#translationRow[selected="true"] {
    background-color: @{color.surface.selected};
    border-left: @{border-width.bar}px solid @{color.accent.base};
    color: @{color.text.primary};
}

#translationRow[selected="true"] QLabel#rowGutter,
#translationRow[selected="true"] QLabel#rowBadge {
    background-color: transparent;
}
```

- `[hovered]` sets **only** a ground (the sheet's standing rule, `theme.qss.in`
  26-28: hover rules set ground and text so focus stays additive, A-04).
  `[selected]` wins the ground over `[hovered]` by order (AC-6).
- **The semantics of 3.** `border-width.bar = 3` is §5's bar width, and the
  token MT-132/MT-133/MT-134 use. The `edited` bar (MT-136) is `emphasis`, 2,
  deliberately. The bar is painted inside the row's rect over its leftmost
  3 px and does not change the hint (AC-3); if RED measures a reflow, the
  fallback is a constant `border-left: @{border-width.bar}px solid
  transparent` at rest with `border-left-color` in the state rules, as the
  primary button does (124-127). RED amends this block if it needs that.
- `color` on the row is honest and inert in the base (QSS does not inherit
  `color` to children); the two descendant selectors exist so the HC override
  may restyle them (`check_override_template`, `tokens.py` 209-213), and they
  declare the labels' real transparent ground, **never** `color`, which at
  (2,1,1) would beat the six `QLabel#rowGutter[status=...]` rules (1,1,1) and
  erase the status colours on the selected row. The editor (`QLineEdit#rowEditor`)
  keeps its own ground and text rules (145-160, 443-446) and is not touched.

**Designer's answer on C-4's margin (2026-11-03, measured).** The premise is
wrong: the gutter does not sit at x = 0. `line_layout` has zero margins
(workspace.py 703) but it is nested in the row's outer `QVBoxLayout` (712),
which never sets its margins and so takes the style's default — measured under
the packaged sheet with an offscreen `TranslationRow`: outer margins 11/11/11/11,
gutter at x = 11 (width 13), badge at x = 26. The 3px bar paints over
columns 0-2, inside that 11px margin, and the gutter grab in
`test_app_theme_paint.py` (columns 11-23) never includes it. **Drop C-4: no
new margin, and no transparent-border-at-rest either.** The two are answers to
different problems — the margin keeps content off the bar (already true by
11px), the transparent border keeps the row from reflowing when the bar
appears (AC-3 measures that directly; a plain `QWidget` with
`WA_StyledBackground` paints its stylesheet border inside its own rect and
does not feed it to the layout, so no reflow is expected). If RED's
measurement nonetheless shows a reflow, the fallback is the transparent border
with `border-left-color` in the state rules, never a margin. If a later story
zeroes the outer margins, a constant margin of `border-width.bar` is the
acceptable shape then (the rail precedent, MT-134 C-4); a per-state one never
is.
