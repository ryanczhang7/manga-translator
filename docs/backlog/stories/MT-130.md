## Context

Filed from MT-105 PO-1 (2026-11-02, the user's decision). `run_chapter`
takes each page through every stage before the next page starts, so the
glossary pre-pass MT-105 adds runs before any page has been OCR'd on a fresh
chapter: its listing is empty and it skips. On a resumed run it proposes
over the pages read so far (MT-105 PO-2). Neither is the "one call over
every page's Japanese" EPIC-09 PO-2 decides.

This story splits the interactive run in two: the **reading** stages
(detect, clean, OCR) run for every page first, then the chapter prelude,
then the **translate** stage page by page. The batch path (MT-111) already
has this order by design; this gives the per-page path the same one, so the
pre-pass always sees the whole chapter.

Open for PLANNED: how the runner tells reading stages from the translate
stage (a second stage tuple from `build_stages`, or a marker on the stage),
how `PageStarted`/`PageSkipped` and the progress panel's "Page n of m" read
across two passes, and what a cancel between the passes leaves.

## Acceptance criteria

To be written at this story's PLANNED. The outcome they must pin: on a fresh
chapter with the prelude bound, the proposer receives every page's OCR
lines; a resumed run whose reading pass is incomplete finishes it before
the prelude; a run without a prelude produces the same rows as today.
