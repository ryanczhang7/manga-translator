## Context

Filed from MT-105 PO-1 (2026-11-02, the user's decision). `run_chapter`
takes each page through every stage before the next page starts, so the
glossary pre-pass MT-105 adds runs before any page has been OCR'd on a fresh
chapter: its listing is empty and it skips. On a resumed run it proposes
over the pages read so far (MT-105 PO-2). Neither is the "one call over
every page's Japanese" EPIC-09 PO-2 decides.

This story splits the run in two passes: the **reading** stages (detect,
clean, OCR) run for every page first, then the chapter prelude, then the
**translating** stage page by page. The batch path (MT-111, MT-113 C-1)
already has this order by design - `submit_chapter` runs the local stages
through `run_chapter`, then the prelude, then submits; this gives
`run_chapter` itself the same order, so the pre-pass always sees the whole
chapter, on the CLI today and in the window once the window carries the
prelude.

**Scope after PLANNED sizing (PO-1, the user, 2026-11-05).** The window
wiring MT-105 PO-5 put here - `Pipeline.prelude` down `app.build_stages ->
RunSetup -> RunController`, and the progress panel reading two passes - is
**MT-139**, cut after this one and before MT-106. This story is the runner,
the pipeline shape, the composition root and the CLI, with
`app.build_stages` kept behaviour-compatible so the window's run is
unchanged until MT-139 (AC-15).

Required gates: `unit`, `coverage` (both read `tests/core`), `coverage-core`
(`domain/events.py` gains a dataclass and carries the 100% bar).

### C-1 - `pipeline/runner.py`: two passes, the prelude between them

```python
#: `PassStarted.name` for the two passes. Constants beside BUDGET/CANCELLED
#: for their reason: the panel and the CLI import them rather than re-spell.
READING = "reading"
TRANSLATING = "translating"

__all__ = ["BUDGET", "READING", "RUN_ABORTED", "RUN_FINISHED", "TRANSLATING", "RunOutcome", "run_chapter"]

def run_chapter(
    project: Project,
    stages: Sequence[Stage],
    emit: Callable[[RunEvent], None],
    cancelled: Callable[[], bool],
    *,
    prelude: ChapterStep | None = None,
    after_prelude: Sequence[Stage] = (),
) -> RunOutcome:
```

Semantics, in order. `stages` is the pass **before** the prelude's slot,
`after_prelude` the pass **after** it, whether or not a prelude fills it.

1. `pages = project.pages()`; the `run` row; `emit(RunStarted(run_id, len(pages)))`.
2. **Two-pass mode is `bool(after_prelude)`.** With `after_prelude=()` and
   `prelude=None` nothing below changes and no `PassStarted` is emitted: the
   stream is today's, byte for byte (AC-5). With `after_prelude=()` and a
   prelude, the one pass is `stages` and the prelude runs **after** it (rule
   4 with an empty second pass) - the prelude's slot is always after
   `stages`, never before. No caller in the tree passes a prelude without
   `after_prelude` once RED has rewritten the four that pass one, and
   `submit_chapter` never passed a prelude.
   **A-R1 (RED, 2026-11-05, clarification; no criterion touched).** "Rule 4
   with an empty second pass" leaves open whether this case emits
   `PassStarted` and whether its one pass marks pages done (rule 3 marks only
   when there is no second pass; rule 5's empty walk would emit a
   `PageStarted` per page with no stage in it). No criterion, no test and no
   caller reaches it. GREEN chooses; the recommended reading is one pass over
   `stages` marked done as today, then the prelude, and no `PassStarted`. If
   coverage needs the branch tested, that test is a return to RED.
3. If two-pass: `emit(PassStarted(READING))`. Walk every page through
   `stages` exactly as `_run_page` does today - the page-level skip, the
   per-stage `cancelled()` check, the per-stage `is_done` skip, `StageFinished`
   per stage run - **except** that `_mark_done` is called only when there is
   no second pass (PO-7). A cancel or a failure here ends the run as today
   (`RunAborted`, outcome `aborted`), and `pages_done` counts only when this
   is the final pass (PO-6).
4. Between the passes, in this order: `cancelled()` once (PO-8) - `True`
   sets `reason=CANCELLED` and skips to 6; `emit(PassStarted(TRANSLATING))`;
   `_run_prelude(...)` unchanged (`BudgetRefused` -> `BUDGET`, anything else
   -> `f"{type}: {msg}"`, `ordinal=None`); a failed prelude skips to 6.
5. Walk every page through `after_prelude` exactly as `_run_page` does today,
   `_mark_done` included; `pages_done` counts this pass (processed plus
   skipped).
6. End the run as today: the `run` row, `RunFinished(run_id, pages_done)` or
   `RunAborted(reason, ordinal)`, the `RunOutcome`.

Unchanged, and the module docstring's four decisions still hold: the cancel
boundary is the stage (plus the one new boundary in 4, which is the moment
before the first paid call); no transaction is held across a stage; the skip
predicate is `stages and all(...)` per pass; `pages_done` is pages complete
when the run ends, now "complete" meaning through the final pass.
