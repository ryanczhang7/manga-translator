## Context

`docs/wiki/stack.md` §3 names this the largest single risk in the plan, and
`architecture.md` D3 records the decision it rests on. The claim is:

> Usable ONNX exports of a comic text detector, `manga-ocr` and LaMa exist, and
> run on an RTX 5070 (Blackwell, sm_120) under `onnxruntime-gpu`.

That claim is **researched, not verified**. Three later epics depend on it, and
it decides a dependency in `pyproject.toml` and roughly 2 GB of installer size.
A spike is the right shape: the output is a decision document, not code.

The named fallback if it fails is `torch` + `torchvision` on the `cu128` index
(Blackwell needs CUDA 12.8+), at the cost of a much larger installer.

A spike's phase path is PLANNED → REVIEW → DONE. Any code it writes is throwaway
and lives under `spikes/MT-002/`, which `.gitignore` covers — so if it is
committed at all, it goes in `## Scaffold inventory` and is explicitly labelled
unreviewed. **Nothing later may reuse it without re-deriving it.**

## Acceptance criteria

A spike's criteria are about what is *known* at the end, not about behaviour.

- **AC-1** — `docs/wiki/audits/MT-002-model-runtime.md` exists and states, for
  each of the three models, whether a usable ONNX export was obtained, where
  from, its file hash, and its licence.
- **AC-2** — For each model obtained, the document records a measured forward
  pass on a real manga page fixture on this machine: execution provider
  selected, wall time, peak VRAM, and whether the output was plausible (a
  detector producing regions, the OCR producing Japanese, LaMa producing
  non-garbage pixels).
- **AC-3** — The document records what `onnxruntime.get_available_providers()`
  actually returns on this machine, and whether the CUDA execution provider
  loaded or fell through to DirectML or CPU.
- **AC-4** — The document ends with a `## Decided` section naming the runtime
  for EPIC-03 and EPIC-06 — ONNX Runtime or the PyTorch fallback — the
  dependency lines to add to `pyproject.toml`, and the estimated installed size
  of the bundled weights.
- **AC-5** — Anything the document reports as a *measurement* is labelled with
  what it was measured on, and anything it reports as a *claim from the web* is
  labelled as such. A number with no provenance is a guess with a citation.

## Contract

**Output paths:**

- `docs/wiki/audits/MT-002-model-runtime.md` — the decision document.
- `docs/wiki/stack.md` §3 — amended in place with the settled dependency.
- `spikes/MT-002/` — throwaway probe scripts, if any survive.

**The `## Decided` / `## Evidence` split is load-bearing.** Later stories will
be told "read the audit and follow its recommendation; do not re-litigate it" —
and that instruction is correct about `## Decided` and wrong about
`## Evidence`. Put every *number* a later story might depend on (a latency, a
VRAM figure, a threshold, a claim that two exports agree) under `## Evidence`,
where it is to be re-verified rather than assumed. `story-authoring` carries the
case where an audit's recommendation was right and its supporting number failed
for 58% of inputs.

**What a later story may take from this spike, stated now so it does not have to
be argued later:** the *choice of runtime* and the *model file identities*
(URL + hash). Nothing else. Any pre-processing code written here is unreviewed
and must be re-derived test-first in MT-007, MT-010 and MT-019.

**Oracle partition: oracle-free.** There is no settled answer to read out; the
spike's job is to find out. So the demand is on the *negative* side: a "plausible
output" claim must say what would have counted as implausible, or it is an
impression.

## Model guidance

- **Spike model: `claude-opus-5` (Claude Opus 5)** — resolved value to be
  recorded here by the orchestrator at dispatch, by name, never the word
  "default". If the dispatch is overridden, the agent is asked to say so and the
  actual resolved model is written here instead.
- **Why this phase specifically:** the failure mode of a spike is not a broken
  test, it is a confident wrong conclusion that four later stories build on. The
  brief the agent needs is the constraint set and the falsifiable question, not
  a pre-decided method.
- **Success condition, falsifiable:** the document lets a reader who was not
  present add the right dependency line to `pyproject.toml` without repeating
  any of the work, and every number in it names what it was measured on. If a
  later story has to re-run the same probe to know what to depend on, the spike
  failed.
- **Verdict:** *to be recorded when the spike ends.*

## Out of scope

Any production code. Any story's acceptance criteria. Fine-tuning, retraining,
or evaluating translation quality. Choosing thresholds for detection or
furigana merging — those are MT-007 and MT-008, test-first.
