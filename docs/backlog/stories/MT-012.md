## Context

Brief feature 8: "show what the run cost, per chapter and running, so the
$2/chapter constraint is observable rather than assumed". `architecture.md` §4
(the `llm_call` table) and D6.

This is the story that turns a budget from a hope into a number. Two design
decisions are already recorded and are the reason this is its own story rather
than three lines inside MT-011: the ledger stores **token counts, not just
dollars**, so a chapter can be re-priced when rates change and so S5's
"confirmed against the provider's billing at least once" is possible; and it is
**append-only**, so a run's spend cannot be quietly rewritten.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — money arithmetic lives in `domain` and carries the 100% bar.

## Acceptance criteria

- **AC-1** — Given a response usage of (input 3,600; output 1,500; cache-write
  1,500; cache-read 0) on `claude-opus-5`, when it is priced, then the recorded
  cost is exactly **64,875 micro-dollars = $0.064875**, computed as
  `3600×5 + 1500×25 + 1500×6.25 + 0×0.50` per million. *(PO-1: the figure
  read $0.0555 in PLANNED, which is this formula with the cache-write term
  dropped; the formula is authoritative and matches `stack.md` §3.)*
- **AC-2** — Given a call recorded against a run, when the ledger is read, then
  it carries the run id, the page ordinal, the request id, the model id, all
  four token counts and the cost — and the rate-table version used.
- **AC-3** — Given a ledger with 20 calls, when the chapter total is requested,
  then it equals the sum of the individual costs exactly, with no floating-point
  drift beyond the defined rounding.
- **AC-4** — Given an attempt to update or delete an existing `llm_call` row,
  when it executes, then it fails — the ledger is append-only at the schema
  level, not by convention.
- **AC-5** — Given a model id absent from the rate table, when a call is priced,
  then a named error is raised identifying the model, and nothing is recorded.
  *(A silently-zero-priced call is the worst possible failure of this module.)*
- **AC-6** — Given a run that was resumed, when the chapter total is requested,
  then it includes calls from **both** runs against that chapter, not just the
  current one.
- **AC-7** — Given a rate table, when it is loaded, then it carries a version
  identifier and the rates for `claude-opus-5` and `claude-sonnet-5` in all four
  categories, and the loader rejects a table missing any category for a listed
  model.

**Amendments to this block, made in RED** (`## Contract` is amendable in place;
no acceptance criterion changed, so there is no `## Amendments` entry):

- **RED-A1 - AC-7 had no loader.** The criterion says "the loader rejects a
  table missing any category for a listed model" and the block named no loader
  and no error type. Added `load_rates` and `IncompleteRateTable`, and made
  `RATES` the loader's own output - a loader only the tests call is dead code
  that never guards the shipped table.
- **RED-A2 - `micro()` is where PO-4's quantisation lands.** "Exact integer
  micro-dollars" and "quantize once, at the end, ROUND_HALF_UP" are the same
  sentence only if one function owns the rounding. It is this one.
- **RED-A3 - the two cache counts are ordered differently** in `TokenUsage` and
  in `CostRecord`/`llm_call`. Stated rather than changed: `TokenUsage` is
  MT-011's frozen type and `llm_call`'s column order is MT-005's.
- **RED-A4 - `at` and `ordinal`.** `llm_call.at` is NOT NULL and `record_call`
  takes no timestamp, so it must stamp one; and `ordinal` is not `page_id`.
- **RED-A5 - the migration.** Measured on sqlite 3.53.1: ADD COLUMN refuses a
  NOT NULL column with no DEFAULT, and ADD/DROP leaves the columns in a
  different order from a fresh `CREATE TABLE`.
- **RED-A6 - `__add__` takes no isinstance guard**, because of the 100% branch
  floor on `domain` and `warn_unreachable`.

**Semantics, and the one that matters most:**

- **The float to remove is the one in the database, not the one in `Usd`
  (PO-2).** `Usd` already stores a `Decimal`, and `Decimal` does not have the
  `0.1 + 0.2 != 0.3` property that the micro-dollar rule was written to avoid —
  `Decimal("0.1") + Decimal("0.2") == Decimal("0.3")` exactly. The real drift
  risk is `llm_call.cost_usd REAL`, which is an IEEE-754 double. So: `Decimal`
  in memory, **integer micro-dollars on disk**, and `Usd.micro()` is the only
  bridge between them. `Usd`'s existing representation and its four-place
  `__str__` are unchanged, and MT-001's seven frozen tests in
  `tests/core/test_money.py` keep passing untouched.
- **Rounding, which nothing pinned before (PO-4).** For one category,
  `micro = tokens × rate_per_mtok` as an exact `Decimal` — the per-million
  cancels, so the units work out to micro-dollars directly. Sum the four
  categories **exactly**, then quantize **once**, at the end, to an integer with
  `ROUND_HALF_UP`. Never quantize per category. AC-1 needs no rounding at all
  (64,875 is already integral); a count like 1,501 cache-write tokens does
  (1501 × 6.25 = 9,381.25 → 9,381).
- **AC-3 then holds by construction, not by tolerance.** `chapter_total` sums
  the stored integers, and a sum of integers is exact. A test that asserts AC-3
  with `pytest.approx` has missed the point of the story.
- **Rates as published, $ per million tokens** (`docs/wiki/stack.md` §3, line
  330): `claude-opus-5` input 5.00, output 25.00, cache write 6.25 (1.25×),
  cache read 0.50 (0.1×); `claude-sonnet-5` input 2.00, output 10.00, cache
  write 2.50, cache read 0.20.
- **`price` takes `TokenUsage`, never the SDK's `Usage` (PO-3).** The contract
  said `Usage` in PLANNED. That is `anthropic.types.Usage`, and
  `src/mangatl/translate/client.py:7` states in terms that it "must not travel
  past this function" — `translate/client.py` is where the SDK type is mapped to
  the domain one. `mangatl.domain.translation.TokenUsage` already carries
  exactly the four counts, in a fixed field order, and its own docstring warns
  that swapping the two cache fields is a factor-of-12.5 error nothing
  downstream would notice. `domain` importing from the SDK would also be a
  `lint-imports` contract violation, so the `lint` gate would catch it — but
  after RED had written the wrong tests.
- **Thinking tokens bill as output tokens.** The API reports them within
  `output_tokens`, so no separate category exists and none should be invented —
  but the cost model's sensitivity analysis is entirely about this, so MT-011's
  measured figure belongs in the same conversation.
- **`RATE_TABLE_VERSION` is stored on every row.** Rates change; a ledger that
  cannot say which table priced a call cannot be reconciled against a bill.
- **Append-only is enforced by a schema trigger**, not by the absence of an
  update function (AC-4). The difference is that a trigger survives the next
  agent.

**Oracle partition: entirely mechanical.** Every criterion is arithmetic with a
known right answer, or a schema-level constraint. Nothing to calibrate, nothing
to invent. Pin AC-1's number exactly; a test that asserts "cost is positive" is
the shape of test this story exists to avoid.

| PO-5 | integration, sqlite | `tests/core/test_ledger.py` | a version bump with no migration; a migration that drops the money; a migration that forgets the triggers; a migration that reorders the columns |

**Levels.** Everything that is arithmetic is a pure unit test in
`tests/core/test_rates.py` and `tests/core/test_money.py`; everything that is a
claim about *the database* is an integration test against a real sqlite file in
`tests/core/test_ledger.py`. Nothing is end-to-end: no acceptance criterion here
describes a path a user walks, and MT-018 owns displaying the number.

**Independence of the observer.** Every stored value is read back through a
plain `sqlite3` connection that imports nothing from `mangatl.store` - MT-005's
convention, for `tdd-cycle`'s reason that "a codec that is uniformly wrong
round-trips through itself perfectly". AC-4 in particular executes the real
`UPDATE` and `DELETE` statements rather than asserting that no update function
is exported.

**Out of scope, pinned where it is cheap.** Nothing asserts a ceiling (MT-013),
a rendered running total (MT-018), a currency other than USD or a per-key
split. `test_a_second_identical_call_is_a_second_bill_rather_than_a_duplicate`
pins the *absence* of a UNIQUE key, which is the thing a rebuild-style migration
would add by accident.

### Other findings that should change the implementation approach

- **F-3 - `_migrate_to_current` is not version-aware, and must become so.**
  `src/mangatl/store/project.py:316` runs `_MIGRATE_TO_V2` unconditionally
  whenever `found < SCHEMA_VERSION`. With `SCHEMA_VERSION = 3`, opening the

  it. Nothing in the repository covered a v2 file before this story;
  `test_ledger.py::test_a_version_two_file_is_migrated_to_version_three_when_it_is_opened`
  is what covers it now.
- **F-4 - the v2 -> v3 step has to be a table rebuild.** Measured on sqlite
  3.53.1: `ALTER TABLE ... DROP COLUMN` works, but `ADD COLUMN` refuses
  `cost_micro_usd INTEGER NOT NULL` because it carries no DEFAULT, and an
  ADD/DROP pair leaves the columns in a different order from a fresh
  `CREATE TABLE`. Giving `cost_micro_usd` a `DEFAULT 0` to dodge this would
  reintroduce exactly the silently-zero-priced row AC-5 exists to prevent.
  Recorded as RED-A5.
- **F-5 - `__add__` must carry no isinstance guard.** `coverage-core` is
  `--cov-fail-under=100` with `branch = true` over `src/mangatl/domain`, and

  consequence for GREEN: `sum()` does not work on `Usd` (it starts at `0`), and
