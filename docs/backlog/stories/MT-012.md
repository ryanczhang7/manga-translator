## Context

Brief feature 8: "show what the run cost, per chapter and running, so the
$2/chapter constraint is observable rather than assumed". `architecture.md` §4
(the `llm_call` table) and D6.

This is the story that turns a budget from a hope into a number. Two design
decisions are already recorded and are the reason this is its own story rather
than three lines inside MT-011: the ledger stores **token counts, not just
dollars**, so a chapter can be re-priced when rates change and so S5's
"confirmed against the provider's billing at least once" is possible; and it is
**append-only**, so a run's spend cannot be quietly rewritten.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — money arithmetic lives in `domain` and carries the 100% bar.

## Acceptance criteria

- **AC-1** — Given a response usage of (input 3,600; output 1,500; cache-write
  1,500; cache-read 0) on `claude-opus-5`, when it is priced, then the recorded
  cost is $0.0555 to the cent-fraction the rate table defines, computed as
  `3600×5 + 1500×25 + 1500×6.25 + 0×0.50` per million.
- **AC-2** — Given a call recorded against a run, when the ledger is read, then
  it carries the run id, the page ordinal, the request id, the model id, all
  four token counts and the cost — and the rate-table version used.
- **AC-3** — Given a ledger with 20 calls, when the chapter total is requested,
  then it equals the sum of the individual costs exactly, with no floating-point
  drift beyond the defined rounding.
- **AC-4** — Given an attempt to update or delete an existing `llm_call` row,
  when it executes, then it fails — the ledger is append-only at the schema
  level, not by convention.
- **AC-5** — Given a model id absent from the rate table, when a call is priced,
  then a named error is raised identifying the model, and nothing is recorded.
  *(A silently-zero-priced call is the worst possible failure of this module.)*
- **AC-6** — Given a run that was resumed, when the chapter total is requested,
  then it includes calls from **both** runs against that chapter, not just the
  current one.
- **AC-7** — Given a rate table, when it is loaded, then it carries a version
  identifier and the rates for `claude-opus-5` and `claude-sonnet-5` in all four
  categories, and the loader rejects a table missing any category for a listed
  model.

## Contract

```
src/mangatl/domain/money.py
    class Usd:                              # integer micro-dollars internally
        @classmethod def from_tokens(cls, tokens: int, rate_per_mtok: Decimal) -> Usd
        def __add__(self, other: Usd) -> Usd
        def __str__(self) -> str            # "$1.14"

src/mangatl/domain/rates.py
    @dataclass(frozen=True) ModelRates:
        input_per_mtok: Decimal
        output_per_mtok: Decimal
        cache_write_per_mtok: Decimal
        cache_read_per_mtok: Decimal
    RATE_TABLE_VERSION: str                 # e.g. "2026-09-12"
    RATES: Mapping[str, ModelRates]
    class UnknownModel(Exception)

    @dataclass(frozen=True) CostRecord:
        input_tokens: int
        output_tokens: int
        cache_write_tokens: int
        cache_read_tokens: int
        cost: Usd
    def price(model_id: str, usage: Usage) -> CostRecord

src/mangatl/store/ledger.py
    def record_call(project, run_id, ordinal, request_id, record) -> None
    def chapter_total(project) -> Usd
    def run_total(project, run_id) -> Usd
```

**Semantics, and the one that matters most:**

- **Money is integer micro-dollars, never a float.** `0.1 + 0.2 != 0.3` is not
  an acceptable property for a budget guard to be built on, and MT-013 compares
  a projection against a ceiling. `Decimal` for the *rates* (they are exact
  decimal quantities as published), integer micro-dollars for the *amounts*.
- **Rates as published, $ per million tokens** (`docs/wiki/stack.md` §3):
  `claude-opus-5` input 5.00, output 25.00, cache write 6.25 (1.25×), cache read
  0.50 (0.1×); `claude-sonnet-5` input 2.00, output 10.00, cache write 2.50,
  cache read 0.20.
- **Thinking tokens bill as output tokens.** The API reports them within
  `output_tokens`, so no separate category exists and none should be invented —
  but the cost model's sensitivity analysis is entirely about this, so MT-011's
  measured figure belongs in the same conversation.
- **`RATE_TABLE_VERSION` is stored on every row.** Rates change; a ledger that
  cannot say which table priced a call cannot be reconciled against a bill.
- **Append-only is enforced by a schema trigger**, not by the absence of an
  update function (AC-4). The difference is that a trigger survives the next
  agent.

**Oracle partition: entirely mechanical.** Every criterion is arithmetic with a
known right answer, or a schema-level constraint. Nothing to calibrate, nothing
to invent. Pin AC-1's number exactly; a test that asserts "cost is positive" is
the shape of test this story exists to avoid.

## Deferred verifications

- *Falsifiable condition 1:* with `cache_read_per_mtok` and
  `cache_write_per_mtok` **swapped** in the rate table — a wrong value, and one
  that looks entirely plausible — AC-1 **must** fail.
- *Falsifiable condition 2:* with `chapter_total` made to filter by the current
  run id, AC-6 **must** fail.
- *Falsifiable condition 3:* with the append-only trigger removed, AC-4 **must**
  fail. (This is the one most likely to be "tested" by a comment.)
- **Owner: GATES.** Three mutations via `bash scripts/mutate.sh`.

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition: entirely mechanical.** Every number is in this contract;
  RED reads them out and does not derive them.
- **Success condition, falsifiable:** AC-1's test asserts the exact figure, not
  a range or a sign; AC-4's test attempts a real `UPDATE` against the database
  and asserts it raises, rather than asserting that no update function is
  exported. Either weaker form has failed RED.
- **Verdict:** *to be recorded.*

## Out of scope

Enforcing a ceiling (MT-013). Displaying cost (MT-018). Reconciling against the
provider's bill — that is S5, done once by the user against the real invoice,
and no story automates it. Currency conversion. Per-user or per-key accounting;
there is one user.
