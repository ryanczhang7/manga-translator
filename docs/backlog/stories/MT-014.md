## Context

Brief feature 3: "so pronouns, speaker attribution, honorifics and continuity
across bubbles are handled with the art and the surrounding lines in view". The
page image gives the model the art; this story gives it the *surrounding lines*
across page boundaries.

Without it, a character introduced on page 3 can be rendered three different
ways by page 17, and every one of those is a rejected line under the O2
definition — which makes this a direct contributor to the headline S1 metric,
not a polish feature.

The mechanism is the rolling context and glossary already budgeted for in the
cost model: ~900 tokens per page of previous-page English plus running glossary
(`docs/wiki/stack.md` §5/O4). Exceeding that budget breaks the cost estimate, so
the size cap below is a real constraint.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage` (every changed path is under `src/mangatl/**`), and `coverage-core`
for `src/mangatl/domain/glossary.py`, which sits inside its 100 % branch floor.
No optional gate is the only reader of anything this story changes. The live
consistency claim that was AC-7 is **MT-045** (PO-1), because no gate on any
machine this project has can run it.

## Acceptance criteria

- **AC-1** — Given a page 1 response that proposed "Sakura" for a given Japanese
  name, when page 2's request is assembled, then the glossary block contains that
  pairing.
- **AC-2** — Given a glossary entry, when the user **edits** the line it came
  from on the review screen, then the glossary entry is updated to the user's
  wording before the next page is translated.
  *(The human's choice outranks the machine's, always.)*
- **AC-3** — Given a chapter where the glossary would exceed
  `MAX_GLOSSARY_TOKENS`, when a request is assembled, then entries are dropped
  **least-recently-seen first**, and the block never exceeds the cap.
- **AC-4** — Given page N's request, when it is assembled, then it carries the
  previous page's proposed English lines, capped at `MAX_ROLLING_TOKENS`, and
  **not** the previous page's image.
- **AC-5** — Given page 1, when its request is assembled, then it carries an
  empty glossary and no rolling context, and does not fail.
- **AC-6** — Given the glossary and rolling context, when the request is
  assembled, then they appear **after** the only cache breakpoint (the `system`
  block), and nothing page-specific appears in or before it.

*AC-6 and AC-7 were settled in PLANNED on 2026-09-28 by the user; see PO-1 and
PO-4. Both edits were made while the story was still PLANNED, and are recorded
as AM-1 and AM-2 under `## Amendments` because `main` never saw the PLANNED
text.*

### C-1 `src/mangatl/domain/glossary.py` — new, pure, inside `coverage-core`

```python
MAX_GLOSSARY_TOKENS: int = 400
MAX_ROLLING_TOKENS: int = 500          # 400 + 500 == 900 == cost-model.awk ROLLING

Note = Literal["name", "honorific", "place", ""]
Source = Literal["model", "user"]

@dataclass(frozen=True)
class ProposedTerm:                    # what one response proposes; no page yet
    term_ja: str
    term_en: str
    note: str

@dataclass(frozen=True)
class GlossaryEntry:
    term_ja: str
    term_en: str
    note: str                          # "name" | "honorific" | "place" | ""
    first_seen_page: int               # page ordinal, 0-based (MT-004)
    last_seen_page: int
    source: Literal["model", "user"]

@dataclass(frozen=True)
class PromptContext:                   # NOT `PageContext`: pipeline.stage has one
    glossary_block: str
    rolling_block: str

EMPTY_CONTEXT: PromptContext = PromptContext("", "")

def estimate_tokens(text: str) -> int
def merge(entries: Sequence[GlossaryEntry], proposed: Sequence[ProposedTerm], page: int) -> list[GlossaryEntry]
def mark_seen(entries: Sequence[GlossaryEntry], source_texts: Sequence[str], page: int) -> list[GlossaryEntry]
def render_block(entries: Sequence[GlossaryEntry], max_tokens: int) -> str
def render_rolling(lines: Sequence[str], max_tokens: int) -> str
```

**`estimate_tokens(text) == ceil(len(text.encode("utf-8")) / 3)`** — the one
counter. Both caps, the implementation and every test use it; no test computes
a token count any other way. Three bytes per token is deliberately
conservative: Japanese is ~3 UTF-8 bytes and ~1 token per character, English is
~4 characters per token, so English is over-counted by about a third, which is
the safe direction for a budget cap. `estimate_tokens("") == 0`.

**`merge`** — model proposals for one page:
- a `term_ja` not in `entries` is appended as
  `GlossaryEntry(term_ja, term_en, note, page, page, "model")`;
- a `term_ja` already present keeps its `term_en`, `note`, `first_seen_page` and
  `source` **whatever its source** — continuity is the point, and a later page's
  different rendering is exactly the inconsistency this story ends. Only
  `last_seen_page` moves, to `max(existing, page)`;
- a proposal with an empty `term_ja` or `term_en` (after `.strip()`) is dropped;
- two proposals for one `term_ja` in the same batch: the first wins;
- input order of `entries` is preserved; new entries follow in proposal order.

**`mark_seen`** — an entry is *seen* on `page` when its `term_ja` is a substring
of any of that page's OCR `source_texts`. Its `last_seen_page` becomes
`max(existing, page)`; nothing else changes. This is what makes a character who
appears on every page "recent" even when the model does not re-propose them.

**`render_block`** — returns `""` for no entries. Otherwise

```
Glossary - use these renderings exactly:
{term_ja} = {term_en}
{term_ja} = {term_en} ({note})          # the "(note)" suffix only when note != ""
```

one line per entry, `\n`-joined, **no trailing newline**, entries in
`(first_seen_page, term_ja)` order. If `estimate_tokens(block) > max_tokens`,
entries are removed one at a time in **eviction order** until it fits:

    sort key, ascending, first removed first:
    (source == "user", last_seen_page, first_seen_page, term_ja)

i.e. every `"model"` entry goes before any `"user"` entry (PO-3), and within a
source the least-recently-**seen** goes first — not least-recently-added, which
is `first_seen_page` and is only the tie-break. If no entry fits, the result is
`""`, never a header alone. `estimate_tokens(render_block(e, n)) <= n` for every
input. Eviction is **render-only**: the store keeps every entry.

**`render_rolling`** — `lines` is the previous page's proposed English in
reading order, NULLs already removed by the caller. Returns `""` for no lines.
Otherwise

```
Previous page, in reading order:
{line}
{line}
```

`\n`-joined, no trailing newline. Over the cap, lines are dropped **from the
start** (the end of the previous page is what the next page continues) until it
fits; `""` if no line fits. `estimate_tokens(result) <= max_tokens` always.

Branch-light by design: this module is under `--cov-fail-under=100` with branch
coverage, so every `if` owes a test per arm.

### C-6 `src/mangatl/store/glossary.py` — new

```python
def read_entries(project: Project) -> list[GlossaryEntry]      # ORDER BY id
def upsert(project: Project, entry: GlossaryEntry) -> None       # ON CONFLICT (chapter_id, term_ja)
def reconcile_from_edit(project: Project, page_ordinal: int, reading_index: int, final_en: str) -> None
```

`region_id` in the original contract is replaced by `(page_ordinal,
reading_index)` — the addressing `write_proposed` and `read_proposed` already
use; no public API returns a region id. Each function opens its own
`project.transaction()`; none is called inside another's.

**`reconcile_from_edit`** (PO-2, the user's choice of the single-span rule):
read that line's `source_ja` and `proposed_en`. For every entry whose `term_ja`
is a substring of `source_ja`:

1. tokenise with `re.findall(r"\w+(?:[-'’]\w+)*|[^\w\s]", s)` —
   `"Sakura, wait!"` is `["Sakura", ",", "wait", "!"]` and `"Sakura-chan,
   wait!"` is `["Sakura-chan", ",", "wait", "!"]`;
2. find `term_en`'s token sequence in the proposed tokens. It must occur
   **exactly once**; otherwise leave the entry alone;
3. if it also occurs in the final tokens, leave the entry alone;
4. take `difflib.SequenceMatcher(None, proposed_tokens, final_tokens,
   autojunk=False).get_opcodes()`. Among the non-`equal` opcodes, exactly one
   may intersect `term_en`'s token range, it must be `replace`, and its a-range
   must **equal** that range. Otherwise leave the entry alone;
5. the new `term_en` is `final_en[start:end]`, the substring from the first
   replacement token's start to the last one's end (so `"Mr. Tanaka"` keeps its
   spacing). Upsert with `source="user"`; `first_seen_page` and
   `last_seen_page` unchanged.

Edits elsewhere in the line do not block the rule; only the opcode touching the
name matters. A line with `proposed_en` NULL changes nothing. There is no
production caller yet: **MT-017** calls it from the edit path, and its story
says so.

