## Context

Brief feature 3: "so pronouns, speaker attribution, honorifics and continuity
across bubbles are handled with the art and the surrounding lines in view". The
page image gives the model the art; this story gives it the *surrounding lines*
across page boundaries.

Without it, a character introduced on page 3 can be rendered three different
ways by page 17, and every one of those is a rejected line under the O2
definition — which makes this a direct contributor to the headline S1 metric,
not a polish feature.

The mechanism is the rolling context and glossary already budgeted for in the
cost model: ~900 tokens per page of previous-page English plus running glossary
(`docs/wiki/stack.md` §5/O4). Exceeding that budget breaks the cost estimate, so
the size cap below is a real constraint.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage`. AC-7 needs a live call, hence `required_gates: [integration]`.

## Acceptance criteria

- **AC-1** — Given a page 1 response that proposed "Sakura" for a given Japanese
  name, when page 2's request is assembled, then the glossary block contains that
  pairing.
- **AC-2** — Given a glossary entry, when the user **edits** the line it came
  from on the review screen, then the glossary entry is updated to the user's
  wording before the next page is translated.
  *(The human's choice outranks the machine's, always.)*
- **AC-3** — Given a chapter where the glossary would exceed
  `MAX_GLOSSARY_TOKENS`, when a request is assembled, then entries are dropped
  **least-recently-seen first**, and the block never exceeds the cap.
- **AC-4** — Given page N's request, when it is assembled, then it carries the
  previous page's proposed English lines, capped at `MAX_ROLLING_TOKENS`, and
  **not** the previous page's image.
- **AC-5** — Given page 1, when its request is assembled, then it carries an
  empty glossary and no rolling context, and does not fail.
- **AC-6** — Given the glossary and rolling context, when the request is
  assembled, then they appear **after** the cached prefix breakpoint — so
  `usage.cache_read_input_tokens` on page 2 onwards is non-zero.
- **AC-7** — *(integration)* Given a two-page fixture where a name appears on
  both pages, when both are translated live, then the same English name appears
  in both pages' proposals.
  *Control:* the same two pages translated with the glossary **disabled** must be
  allowed to differ — if they never differ, the fixture does not exercise the
  mechanism and AC-7 is measuring nothing. Record how many of K runs differed.

## Contract

```
src/mangatl/domain/glossary.py
    MAX_GLOSSARY_TOKENS: int          # budgeted; see Semantics
    MAX_ROLLING_TOKENS: int

    @dataclass(frozen=True) GlossaryEntry:
        term_ja: str
        term_en: str
        note: str                     # "name" | "honorific" | "place" | ""

        last_seen_page: int

    def render_block(entries, max_tokens: int) -> str

src/mangatl/translate/context.py
    @dataclass(frozen=True) PageContext:
        glossary_block: str
        rolling_block: str
    def build_context(project, ordinal: int) -> PageContext

src/mangatl/store/glossary.py
    def upsert(project, entry) -> None
    def reconcile_from_edit(project, region_id, final_en) -> None
```

**Semantics behind each number and each rule:**

- **`MAX_GLOSSARY_TOKENS` + `MAX_ROLLING_TOKENS` ≤ 900**, because 900 is the
  per-page rolling allowance the cost model assumes
  (`docs/wiki/cost-model.awk`, `ROLLING`). Exceeding it invalidates the $1.14
  figure that the whole budget argument rests on. Split them 400/500 unless a
  measurement says otherwise, and record the measurement.
- **`source: "user"` entries are never evicted** by AC-3's least-recently-seen
  rule, and never overwritten by a model proposal. The human's wording wins; a
  cache that can forget the user's correction is worse than no cache.
- **Eviction is least-recently-*seen*, not least-recently-added.** A character
  who appears on every page must survive; one who appeared once on page 2 is the
  right thing to drop at page 18.
- **The previous page's image is never carried forward** (AC-4). It would cost
  2,296 tokens per page and double the input bill, and the model does not need
  it: what continuity needs is the *words*.
- **AC-6's ordering is a cost criterion disguised as a structural one.** The
  cached prefix is the system prompt and the style guide; the glossary changes
  every page, so placing it before the breakpoint invalidates the cache on every
  request and costs the chapter its 19 cache reads.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1..AC-6 | **Mechanical** | Fake client, constructed glossaries. Token caps are asserted with the same counter the implementation uses; AC-6 is asserted on the assembled request structure, not on a live `usage`. |
| AC-7 | **Oracle-free** | A live, stochastic behaviour. Invent the consistency measure; the control is mandatory and its result is a *count out of K runs*, not a boolean. |

**AC-7 is a statistical claim about a non-deterministic system.** Do not write it
as a single run asserting equality. State K, state the observed counts for both
arms, and set the bar with headroom over the control.

## Deferred verifications

- *Falsifiable condition 1:* with `render_block` made to ignore `max_tokens`,
  AC-3 **must** fail.
- *Falsifiable condition 2:* with eviction changed from least-recently-**seen**
  to least-recently-**added** — a wrong value for the sort key, not a removed
  behaviour — AC-3's ordering assertion **must** fail. If it does not, the
  fixture does not distinguish the two and the criterion is weaker than it reads.
- *Falsifiable condition 3:* with `reconcile_from_edit` made a no-op, AC-2
  **must** fail.

## Out of scope

the glossary is derived from the lines the user already edits (AC-2) and a
second editing surface is a second thing to get wrong. Translation memory.
Speaker identification as a first-class model.
