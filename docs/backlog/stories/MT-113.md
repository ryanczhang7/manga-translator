## Context

The user-facing half of the batch (EPIC-09 Q-3, assumed: Start on Gemini
submits a batch). Today Start runs `RunController` -> `run_chapter` with the
full stage list and the panel shows per-page progress (`ui/progress.py`
`RunProgressPanel`, `PageStageStepper`, the cost readout). A batch has a
different shape: local stages per page as now (detect, clean, OCR - the
stepper shows them), then the glossary pass, then the submission, then a
wait of unknown length, then collection. The panel needs a **waiting** state
that says what was submitted and when, polls on a timer, and survives the
window being closed and the folder re-opened with a pending job.

The synchronous per-page run stays reachable: `mangatl-run --sync` (MT-112
AC-6 named the flag) and, in the window, nothing - Start is batch on Gemini,
and a per-page run is the CLI's. Anthropic has no batch; Start on Anthropic
runs as today.

What exists (read 2026-11-04, `main` at 07fdfc4):

- `pipeline.batch.submit_volume(project, run_id, submit, request_size,
  model_id, page_estimate, emit)` guards the volume once and records **one or
  more** `batch_job` rows (MT-110 PO-1, MT-111: a volume over 20 MB is
  several inline jobs) and emits `BatchSubmitted(run_id, job_ids,
  page_count, projection)`. It needs every page's OCR first, and **nothing in
  production calls it yet** - this story is its first caller.
- `pipeline.batch.collect_volume(project, job, collect, page_estimate, emit)`
  is one poll of **one** job; it emits `BatchWaiting`, `BatchCollected` or
  `BatchFailed`. `store.batch.pending_jobs(project)` returns a tuple.
- `compose.build_batch_binding(selection, display_name=)` and
  `compose.build_batch_collector(selection)` are the provider halves;
  `compose.build_pipeline(models_dir, translate=False)` is the local stages.
- `run_chapter` runs a `prelude` **before** page 1, i.e. before any OCR, so
  the glossary pre-pass cannot ride it on the batch path (that order is
  MT-130's for the per-page run). The batch path orders it itself (C-1).
- `open_folder` returns a `Workspace` for any folder with a project, so a
  pending folder today opens the review of pages that have no translation.

Required gates: `unit`, `coverage` (`tests/core`, `tests/ui`), both already
required; nothing optional needs adding.

## Acceptance criteria

- **AC-1** - Given a Gemini selection and a chapter, when Start is pressed,
  then the panel shows the local stages per page as today with the stepper's
  steps `Detecting`, `Reading`, `Done` (no `Translating` step), then the
  glossary pass and the submission run, and on `BatchSubmitted` the window
  shows the waiting panel: the line
  `Submitted {n} pages as one batch at {time}; waiting for Gemini.` - or
  `... as {k} batches ...` when the volume went as `k > 1` jobs - and
  `Projected {projection} of {ceiling}` (both `format_usd`; the projection is
  `BatchSubmitted.projection.next_call`, the ceiling the stored one the guard
  used).
- **AC-2** - While waiting, the controller asks for every pending job's answer
  every `BATCH_POLL_SECONDS` (60) on a single-shot Qt timer re-armed after
  each poll, never a thread sleep; the poll itself runs on a worker thread.
  Each poll that leaves a job pending sets `Last checked {time}.`; when a poll
  leaves **no** job pending and none failed, the review opens as it does after
  `RunFinished`; a `BatchFailed` shows the error banner naming the job's state
  and stops polling, leaving the panel. A poll that raises sets
  `Last checked {time}: {Type}: {message}` and polling continues.
- **AC-3** - Given a folder whose project has a pending job, when it is
  opened (dropped, chosen or given on the command line), then the window
  shows the waiting panel directly - not the summary, not the review, and not
  Start - with `Submitted {n} pages as ... at {time}; waiting for Gemini.`
  from the pending jobs (`n` their pages, `k` their count, `{time}` the
  earliest `submitted_at`), no projection line (C-4), and polls as in AC-2,
  the first poll at once. Without a Gemini selection it shows instead the
  error `Batch job {provider_job_id} is still pending, and collecting it needs
  the Gemini key that submitted it.` and polls nothing.
- **AC-4** - Given a Gemini selection and a stored ceiling the batch exceeds,
  when Start is pressed, then the local stages run and the panel then shows
  the budget refusal: the cost readout's spent figure and ceiling, marked
  aborted (from `CallPriced`, as a per-page budget stop shows it), and the
  banner `Batch not submitted \N{EM DASH} projected {projection} exceeds the
  {ceiling} budget.` (both `format_usd`; `{projection}` is the refused
  `CallPriced.projection.next_call`) with `No pages were translated.` and no
  action; no job is pending afterwards.
- **AC-5** - Given an Anthropic selection, Start runs the per-page pipeline
  exactly as before this story (the existing `test_start_run.py` assertions
  hold for that selection).
- **AC-6** - Closing the window while waiting stops the timer, waits for a
  poll in flight, cancels nothing at the provider, and the job stays pending;
  reopening is AC-3.

**C-1 - `pipeline/batch.py`: the batch run's order.**

```python
#: The batch path's whole Start, after the window has a models folder:
#: (project, models_dir, emit, cancelled) -> the batch_job ids recorded.
ChapterSubmit = Callable[[Project, Path, Callable[[RunEvent], None], Callable[[], bool]], tuple[int, ...]]

def submit_chapter(
    project: Project,
    stages: Sequence[Stage],          # the LOCAL stages: build_pipeline(..., translate=False).stages
    prelude: ChapterStep | None,      # the glossary pre-pass
    submit: BatchSubmitter,
    request_size: RequestSize,
    model_id: str,
    page_estimate: Usd,               # batch tier
    emit: Callable[[RunEvent], None],
    cancelled: Callable[[], bool],
) -> tuple[int, ...]:
```

1. `run_chapter(project, stages, local_emit, cancelled)` with **no** prelude;
   `local_emit` forwards every event except `RunFinished` (the local stages
   finishing is not the run finishing - the window would open the review).
   An aborted outcome returns `()`; its `RunAborted` has already reached
   `emit`.
2. `prelude(project, outcome.run_id, emit)` when not `None`: `BudgetRefused`
   -> `emit(RunAborted(reason=BUDGET, ordinal=None))`, return `()`; any other
   exception -> `RunAborted(reason=f"{type(e).__name__}: {e}", ordinal=None)`,
   return `()` (the runner's own wording for a failed prelude).
3. `cancelled()` true -> `RunAborted(reason=CANCELLED, ordinal=None)`, `()`.
4. Return `submit_volume(project, outcome.run_id, submit, request_size,
   model_id, page_estimate, emit)`.

The `run` row is the local stages' and is ended by `run_chapter`; the
prelude's ledger row and the `batch_job` rows carry its id.

**C-3 - `ui/run.py`: the setup and the controller.**

```python
BATCH_POLL_SECONDS: int = 60

@dataclass(frozen=True)
class BatchSetup:
    submit: ChapterSubmit                                           # C-1
    collect: Callable[[Project, BatchJob, Callable[[RunEvent], None]], BatchAnswer]   # one job, one poll
    ceiling: Callable[[Project], Usd]                               # the stored ceiling the guard used

#: The batch setup for the provider a Start would use now; `None` when it has
#: no batch; raises `ProviderError` when no provider can be selected.
BatchBuilder = Callable[[], BatchSetup | None]

@dataclass(frozen=True)
class RunSetup:
    resolve_models: ModelsResolver
    build_stages: StageBuilder
    select_model: ModelSelector
    build_batch: BatchBuilder | None = None    # PO-1: defaulted

@dataclass(frozen=True)
class WaitingState:
    page_count: int
    job_count: int
    submitted_at: datetime                     # aware
    projection: Usd | None                     # None on reopen (PO-4)
    ceiling: Usd | None

BatchEnd = Literal["collected", "failed", "not_submitted"]

class BatchController(QObject):
    event = Signal(object)     # every RunEvent, in order
    waiting = Signal(object)   # a WaitingState, once, when the wait begins
    ended = Signal(object)     # a BatchEnd, once
    poll_failed = Signal(object)  # RED A-R1: the exception a poll raised, once per failed poll
    poll_timer: QTimer         # single-shot, interval BATCH_POLL_SECONDS * 1000

    def __init__(self, project_dir: Path, batch: BatchSetup, models_dir: Path | None,
                 parent: QObject | None = None, *,
                 now: Callable[[], datetime] = <aware local now>) -> None
    def start(self) -> None    # models_dir given: worker runs batch.submit, then the wait;
                               # None: the wait at once from pending_jobs, first poll immediately
    def stop(self) -> None     # timer stopped, in-flight worker joined; nothing cancelled remotely
    def is_running(self) -> bool  # RED A-R4: True from start() until ended or stop()
                                  # (waiting with the timer armed counts); False after either
```

- Every worker opens its own `Project` (`open_project`, by this module's
  name - the seam the tests observe), as `RunController` does.
- After `submit`: if a `BatchSubmitted` was emitted -> `waiting` with
  `(page_count, len(job_ids), now(), projection.next_call,
  batch.ceiling(project))`, then the timer is armed. If none was ->
  `ended("not_submitted")`.
- A poll: `for job in pending_jobs(project): batch.collect(project, job,
  emit)`. Any `BatchFailed` -> `ended("failed")`, no re-arm. No job pending
  afterwards -> `ended("collected")`. Otherwise re-arm. An exception from a
  poll is emitted as no event; the controller passes it to the panel as the
  `Last checked {time}: {Type}: {message}` line (C-4 `poll_error`) and
  re-arms.
- **RED amendment A-R1.** The block named no channel for "passes it to the
  panel": the controller has only `event`, `waiting` and `ended`, and the
  panel is the window's, not the controller's. Added `poll_failed =
  Signal(object)`, emitted on the GUI thread with the exception itself; the
  window connects it to the waiting panel's `poll_error`. The tests connect to
  `poll_failed` and assert `type(error) is ConnectionError` and `str(error)`.
- **RED amendment A-R4.** `is_running()` was unspecified for a controller
  that is waiting with no worker alive. Pinned: `True` while waiting (so a
  `closeEvent` that checks it still stops the timer), `False` once `ended` has
  been emitted or `stop()` has returned.
- On a reopen (`models_dir=None`) `WaitingState.ceiling` is not pinned by any
  test (no line shows it, PO-4); `projection` is `None`.
- `ui` may import `store.batch` and `pipeline` (it already imports both).

### The export shape the tests pin (fact, not suggestion)

- `mangatl.pipeline.batch.submit_chapter(project, stages, prelude, submit,
  request_size, model_id, page_estimate, emit, cancelled) -> tuple[int, ...]`.
  It is called with `project` positional and the rest **by these keyword
  names**. Event streams are compared exactly: the local stages' events without
  `RunFinished`, then the prelude's own events, then `submit_volume`'s, and
  nothing else. Each abort is the last event and returns `()`:
  `RunAborted(BUDGET, None)`, `RunAborted(f"{Type}: {msg}", None)` or
  `RunAborted(CANCELLED, None)`.
- `mangatl.compose.build_batch_submit(selection) -> ChapterSubmit | None`. The
  closure is called positionally, `(project, models_dir, emit, cancelled)`.
  When **called**, it must look up these `mangatl.compose` globals by name,
  because the tests replace them there:
  - `build_pipeline`, with bound arguments exactly `{models_dir, translate=False}`;
  - `glossary_prelude`, once: `propose` is a `partial` of
    `gemini.propose_glossary` with `args == (client,)`, `model_id ==
    "gemini-3.1-pro-preview"`, `listing is glossary_pass_text` and
    `max_output_tokens == GLOSSARY_PASS_MAX_OUTPUT_TOKENS`;
  - `build_batch_binding`, once, with `selection` and
    `display_name=project.chapter.source_dir.name`;
  - `GeminiClient`, every construction exactly `GeminiClient(api_key=key)`;
  - **`submit_chapter`: `compose` must import it under that name.** It receives
    the binding's own `submit` and `request_size` objects, the prelude step
    that `glossary_prelude` returned, `page_estimate == $0.02`, and the
    caller's own `emit` and `cancelled`. The closure returns its result.

  Calling `_translator(selection)` to get the prelude satisfies all of this.
- `mangatl.ui.run`:
  - `BATCH_POLL_SECONDS == 60`;
  - `BatchSetup(submit, collect, ceiling)`, frozen, in that field order;
  - `RunSetup.build_batch`, the fourth field, defaulting to `None`;
  - `WaitingState(page_count, job_count, submitted_at, projection, ceiling)`,
    frozen and compared with `==` (`projection` is the `Usd` `next_call`);
  - `BatchController(project_dir, setup, models_dir, now=...)` with signals
    `event`, `waiting`, `ended` and `poll_failed`, and attribute `poll_timer`.
    That is a `QTimer` read through `isSingleShot()`, `interval() == 60_000`
    and `isActive()`. The tests "fire" it with `stop()` then `timeout.emit()`,
    so the poll must hang off `timeout`;
  - `ended` carries the strings `"collected"`, `"failed"` or `"not_submitted"`;
  - workers open projects through `mangatl.ui.run.open_project`
    (monkeypatched), never on the GUI thread;
  - `BatchSetup.ceiling(project)` is asked once per submission;
  - `batch.collect` is called positionally, `(project, job, emit)`;
  - no name `sleep` appears anywhere in `ui/run.py` (checked with `ast`).
- `mangatl.ui.batch_panel`:
  - `BatchWaitingPanel(now=...)`, keyword;
  - attributes `submitted`, `projection` and `last_checked`, QLabels with their
    object names, and `banner`: `None`, or a `progress.ErrorBanner` with
    `headline`, `body` and `actions == ()`;
  - methods `show_state`, `on_event` and `poll_error`;
  - `projection.isHidden()` when the state's projection is `None`;
  - `PendingBatch(source_dir, project_dir, jobs)`, frozen, in that order.
- `mangatl.ui.progress`: `BATCH_STAGE_STEPS`; `PageStageStepper(steps=...)`,
  keyword; `RunProgressPanel(batch=True, ceiling=...)`, keywords. The step
  labels keep object name `stage-step` and accessible name `"{step}: {state}"`.
- `MainWindow`: `batch_run`, `show_waiting(pending)`, plus the existing
  `_run_setup`, `run` (a `RunController` on the per-page path) and `opened`. On
  the batch path `build_stages` is never called. `build_batch` is called once,
  after `resolve_models` and before the project exists.
- `mangatl.app`:
  - `build_batch()`, no arguments;
  - `open_folder` returns `PendingBatch(folder.resolve(), project_dir_for(...),
    pending_jobs(...))`, and every project `app.open_project` opened is closed

**Decisions inside "Not constrained":**

- worker to GUI: two private queued signals on the controller (`_began`,
  `_polled`). Each slot ignores what arrives after `stop()`, so a poll that
  finishes after `stop()` arms nothing and ends nothing.
- `waiting` on a reopen comes from the poll worker, before it polls. The
  window builds the `BatchWaitingPanel` on `waiting`, not before, because
  `test_batch_reopen.py` reads the panel's text the moment it becomes the
  content. Until then, for a few milliseconds, the drop target stays.
- a poll asks every remaining job after a `BatchFailed`.
- `stop()` sets the submit's `cancelled` (as `RunController.cancel` does), so
  closing during the local stages stops at the next stage boundary.
- `WaitingState.ceiling` on a reopen is `None`.
- the window hands each controller event to whichever panel is the content
  (`_batch_event`), rather than connecting each panel. That way no connection
  outlives a panel that `setCentralWidget` deleted.
- the banner's text does not join the waiting panel's accessible name.

**Gaps, untested and so not built (law 1). Each is a candidate story or a
RED addition:**

- a `submit` that raises (for example `build_pipeline` on missing weights)
  kills the worker. The run panel then stays as it is, and `is_running()`
  stays `True` until close. `RunController` has the same gap today.
- a reopen whose jobs were all settled between `open_folder` and the first
  poll: `_reopened` takes `min()` of an empty sequence, the worker dies, and
  the window stays on the drop target.
- two jobs failing in one poll stack two failure banners.
- `ui/run.py` line 321 (`_on_began` after `stop()`, a stop during the

- `docs/wiki/design/components.md` is in `touches:` but is the Lead Designer's.

## Notes

PO decisions, PLANNED (lead-po, 2026-11-04). Each refines the criteria
before they freeze; the user may overrule any before GREEN.

- **PO-1 - `RunSetup.build_batch` is defaulted to `None`.** The planned
  contract made the field required "for `build_stages`' reason", but there
  are 20 constructor calls across 12 test files, and absence has a correct
  meaning (no batch: today's run). The risk a default carries - `app.py`
  forgetting it, silently disabling the batch - is pinned by an app-level
  test that `build_window`'s default `RunSetup` carries `app.build_batch`.
- **PO-2 - the setup is a builder called at Start, not a fixed field.** The
  provider is resolved when Start is pressed (environment plus stored key),
  as `build_stages` resolves it, so a `BatchSetup` fixed at window build time
  would bind the wrong provider after the key is entered.
- **PO-3 - several jobs.** Since MT-110 PO-1 (the user's) a volume can be `k`
  jobs. The line says `as one batch` for one and `as {k} batches` otherwise;
  a poll asks every pending job; the review opens when none is left pending.
  One failed job shows the banner and stops polling; jobs still pending stay
  pending and are polled again when the folder is reopened.
- **PO-4 - no projection line on reopen.** The projection is not stored, and
  recomputing it from today's rates could disagree with the figure the guard
  judged. Reopened, the panel shows what was submitted and when, not a cost.
- **PO-5 - the glossary pre-pass runs after the local stages on the batch
  path.** `run_chapter` runs its prelude before page 1, before OCR exists;
  the batch path is the first that needs the other order, so `submit_chapter`
  (C-1) owns it. The per-page run's order is still MT-130's.
- **PO-6 - a batch refusal never says a page was translated.** Today's budget
  banner reads "Pages 1-N are translated and can be reviewed"; under a batch
  no page has been translated, so C-5's banners say `No pages were
  translated.` and carry no action.
- Epic done-when check: this story delivers Start projecting, refusing or
  submitting, the surviving waiting state and collection into the review;
  the consistency pass is MT-114/115's. No gap absorbed.
- Known edge, not fixed here: a job refused part-way through a multi-job
  submission leaves the jobs before it pending; the banner shows the
  refusal, and reopening the folder polls them (AC-3).
- `test_folder_intake.py` is in `touches:` because AC-3 changes what opening
  a folder shows when a job is pending; RED confirms which intake tests pin
  the summary.
