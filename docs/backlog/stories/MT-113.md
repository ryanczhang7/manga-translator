## Context

The user-facing half of the batch (EPIC-09 Q-3, assumed: Start on Gemini
submits a batch). Today Start runs `RunController` -> `run_chapter` with the
full stage list and the panel shows per-page progress (`ui/progress.py`
`RunProgressPanel`, `PageStageStepper`, the cost readout). A batch has a
different shape: local stages per page as now (detect, clean, OCR - the
stepper shows them), then the glossary pass, then **one** submission, then a
wait of unknown length, then collection. The panel needs a **waiting** state
that says what was submitted and when, polls on a timer, and survives the
window being closed and the folder re-opened with a pending job.

The synchronous per-page run stays reachable: `mangatl-run --sync` (MT-112
AC-6 named the flag) and, in the window, nothing - Start is batch on Gemini,
and a per-page run is the CLI's. Anthropic has no batch; Start on Anthropic
runs as today.

`RunSetup` (MT-100 gave it `select_model`) gains what the window needs to
submit and to collect. All composition stays in `app.py`.

Required gates: `unit`, `coverage` (`tests/ui`).

## Acceptance criteria

- **AC-1** - Given a Gemini selection and a chapter, when Start is pressed,
  then the panel shows the local stages per page as today, then a line
  `Submitted {n} pages as one batch at {time}; waiting for Gemini.` with the
  projection's figure beside the ceiling (`format_usd`), and no per-page
  translate step is shown; the `BatchSubmitted` event drives it.
- **AC-2** - While waiting, the controller asks the collector every
  `BATCH_POLL_SECONDS` (60) on a Qt timer, not a thread sleep; each
  `BatchWaiting` updates a `Last checked {time}` line; `BatchCollected`
  opens the review as `RunFinished` does; `BatchFailed` shows the error
  banner with the state and leaves the panel.
- **AC-3** - Given a folder whose project has a pending job, when it is
  opened (dropped, chosen or given on the command line), then the window
  shows the waiting panel directly - not the summary and not Start - and
  polls as in AC-2.
- **AC-4** - Given a Gemini selection and a stored ceiling the batch exceeds,
  when Start is pressed, then the local stages run and the panel then shows
  the budget refusal with the three numbers, as a per-page `BUDGET` abort is
  shown today, and no job is pending afterwards.
- **AC-5** - Given an Anthropic selection, Start runs the per-page pipeline
  exactly as before this story (the existing `test_start_run.py` assertions
  hold for that selection).
- **AC-6** - Closing the window while waiting cancels nothing at the provider
  and the job stays pending; reopening is AC-3.

```python
# ui/run.py
BATCH_POLL_SECONDS: int = 60
@dataclass(frozen=True)
class RunSetup:
    resolve_models: ModelsResolver
    build_stages: StageBuilder
    select_model: ModelSelector
    batch: BatchSetup | None           # None: the provider has no batch (anthropic)
@dataclass(frozen=True)
class BatchSetup:
    submit: Callable[[Path], int]      # project_dir -> job row id; runs local stages + prelude + submit_volume on the worker
    collect: Callable[[Path], BatchAnswer]   # one poll
    pending: Callable[[Path], BatchJob | None]

class BatchController(QObject):        # start(): worker runs submit; then a QTimer drives collect
    event = Signal(object); ended = Signal(object)

# ui/batch_panel.py: BatchWaitingPanel(QWidget) with object names batch-submitted, batch-projection, batch-last-checked;
#   accessible name = its lines joined; the ErrorBanner reused for failure.
# main_window.py: _start chooses BatchController when run_setup.batch is not None; open paths check pending() first.
# components.md: a new §2 entry for BatchWaitingPanel - the PO writes it at REVIEW, the Lead Designer reviews.
```

Lines are exact strings with `{time}` as `HH:MM` local. **Callers of
`RunSetup(`**: `src/mangatl/app.py`, `tests/ui/test_app_first_run.py`,
`tests/ui/test_start_run.py` - the new field is required, for
`build_stages`'s reason. Oracle partition: all **mechanical**.
