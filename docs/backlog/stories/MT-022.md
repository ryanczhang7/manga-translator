## Context

Brief success criterion **S1**, the headline number: "at least 80% of the
benchmark chapter's text regions carry a line that is accepted as-is, with no
edit on the review screen… The denominator is every text region in the chapter's
hand-made ground-truth list, not every line the tool happened to propose."

Open question **O2** — what counts as accepted as-is — is resolved in
`docs/wiki/stack.md` §5/O2 and implemented as `domain.line.normalise` by MT-017.
**This story does not re-define it and must not carry a second copy.**

Open question **O1** — which chapter — **is the user's and is still open.** This
story builds the harness and ships fixtures small enough to test it. AC-8 is the
criterion that keeps the two apart.

The measurement reports **two numbers, and never suppresses either:**

- **S1b — chapter acceptance** = accepted / *ground-truth region count*. **The
  headline. The 80% bar attaches here** — the user decided this on 2026-09-12,
  choosing the uncheatable and strictly harder number over the one the brief's
  original wording implied. A missed region contributes 0 to the numerator and 1
  to the denominator.
- **S1a — translation acceptance** = accepted / *proposed*. Diagnostic, not a
  bar. It answers "of what the detector found, how good was the translation?",
  which is the question you need when S1b is low.

**The gap between them is the diagnosis, and it is an identity, not a slogan:**
with no spurious detections, `S1b = S1a × recall`. A large gap means fix the
detector; a small gap with a low S1b means fix the translation. AC-4 asserts it.

**A previously planned rule is deliberately absent, and must not be
reintroduced.** An earlier draft voided the report when detection recall fell
below 95% and suppressed S1a. That rule existed only to stop S1a being read as
the headline when detection was bad; with S1b as the headline, poor detection
lowers the headline directly and proportionally, so the rule guards nothing —
and it suppressed S1a exactly when S1a is most diagnostic. It is gone. Recall is
still reported on every run, and is a criterion in its own right under S2
(MT-023). If a later agent proposes adding a validity gate here, this paragraph
is the answer.

**What S1b cannot see, and why AC-9 exists.** A *spurious* region — a phantom
bubble where there is no text — is absent from the ground truth, so it changes
neither S1b's numerator nor its denominator. S1a partly covered this (a phantom
diluted its denominator); the headline does not. So the report carries the
spurious count beside S1b, and spurious detections are a first-class reported
failure under S2. A reader who quotes S1b alone is quoting half the result.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — `bench` is in the 100% set.

## Acceptance criteria

- **AC-1** — Given a chapter project and a ground-truth region list, when the
  measurement runs, then it reports **S1b** as the headline together with S1a,
  the accepted count, the proposed count, the ground-truth count, the recall and
  the **spurious count** — and both S1a and S1b are present on every run, under
  every input, with no suppression path.
- **AC-2** — Given a line whose final text differs from its proposal by **one
  word**, when it is scored, then it is a **rejection**. The same for a
  punctuation-only difference and for a capitalisation-only difference.
- **AC-3** — Given a line that was edited and then restored character-for-
  character, when it is scored, then it is an **acceptance**.
- **AC-4** — Given a run with **no spurious detections**, when it is scored, then
  `S1b == S1a × recall` exactly, to the report's stated precision — and given a
  run **with** spurious detections, that identity does **not** hold and the
  spurious count is non-zero.
  *(This is what makes "the gap is the diagnosis" a checkable claim. A report
  that satisfies the identity unconditionally has computed one of the two
  numbers from the other instead of from the data.)*
- **AC-5** — *(negative control: the metric can tell right from wrong)* Given the
  proposed lines rotated by one region, when scored, then **both** S1a and S1b
  are at or near 0%.
- **AC-6** — *(negative control: `normalise` does what it claims)* Given every
  final replaced by its NFD form with doubled interior spaces, when scored, then
  acceptance is **100%**. Given every final with one character changed
  (`.` → `!`), then acceptance is **0%**.
- **AC-7** — *(negative control: the headline is coupled to detection — the whole
  point of the user's decision)* Given 30% of regions dropped from the detector
  output, when scored, then S1a is **unchanged** and S1b falls by approximately
  30%.
- **AC-8** — Given a ground-truth document flagged `development_use: true`
  (MT-029's per-document marker, set by whoever annotates), when the
  measurement is run in benchmark mode — through `load_ground_truth` in its
  default mode, and again if a flagged `GroundTruth` reaches `measure`
  directly — then it **refuses** with `BenchmarkChapterUsedInDevelopment` and
  names the chapter. *(O1: the benchmark chapter is held out, and the harness enforces it
  rather than trusting a convention.)*
- **AC-9** — *(negative control: the report exposes what S1b cannot see)* Given
  1,000 spurious regions added to the detector output, when scored, then S1b is
  **unchanged**, S1a falls sharply, and the spurious count is reported as 1,000.

**Block 2 — `src/mangatl/bench/acceptance.py` (new).**

```
@dataclass(frozen=True)
class AcceptanceReport:
    s1b: float            # HEADLINE: accepted / ground_truth      (0.0 when ground_truth == 0)
    s1a: float            # diagnostic: accepted / proposed         (0.0 when proposed == 0)
    recall: float         # matched / ground_truth                  (0.0 when ground_truth == 0)
    accepted: int
    proposed: int
    matched: int
    spurious: int
    ground_truth: int

def measure(project: Project, truth: GroundTruth) -> AcceptanceReport
def main(argv: Sequence[str] | None = None) -> int     # python -m mangatl.bench.acceptance FOLDER [--truth PATH]
```

**The counts, pinned** (per truth page, summed over the chapter; every page of
`truth` is scored, and nothing else is):

- `proposals = project.read_regions(page.ordinal)`; `lines =
  read_review_lines(project, page.ordinal)` — positional against the same
  reading order, so `lines[i]` belongs to `proposals[i]`.
- `matches = match_regions(proposals, page.regions, width=page.width,
  height=page.height)` — mask IoU, one-to-one, never by index.
- `ground_truth += len(page.regions)`; `proposed += len(proposals)`;
  `matched += number of truth regions with region_id is not None`;
  `spurious += number of proposals with truth_index is None`. So `proposed ==
  matched + spurious` is an invariant of the matcher, not a computed field.
- **`accepted` counts truth regions whose matched proposal carries a line that
  `is_accepted_as_is`.** A spurious proposal's line is never counted, whatever
  it says; a missed truth region contributes 0 to the numerator and 1 to the
  denominator. A `None` line, or a line with `proposed_en is None`, is not
  accepted. This is the one definitional choice the contract makes beyond
  stack.md, and it is what makes AC-4 and AC-9 behave: with no spurious
  proposals, `proposed == matched`, so `s1a * recall == accepted/matched *
  matched/ground_truth == s1b` exactly; with spurious proposals `proposed >
  matched` and the identity fails while `s1b` does not move.
- `s1b`, `s1a`, `recall` are each computed **from the counts above,
  independently** — never one from another. The zero-denominator cases are
  `0.0`, never a raise and never `NaN`. Floats are unrounded; AC-4's "stated
  precision" is `math.isclose(s1b, s1a * recall, rel_tol=1e-9, abs_tol=1e-12)`.

**Refusals, pinned:** `measure` raises `BenchmarkChapterUsedInDevelopment`
naming `truth.chapter_name` if `truth.development_use` (AC-8's second route —
`load_ground_truth` in benchmark mode already refuses at the first); it raises
`InvalidGroundTruth` carrying every error line if `validate(truth,
project.chapter)` is not `ok` — a measurement against a document that fails
its own validator is not a measurement. Warnings (AC-8 of MT-029) do not stop
it; `main` prints them.

**`main`** (`python -m mangatl.bench.acceptance FOLDER [--truth PATH]`): opens
`open_project(project_dir_for(FOLDER))`, loads `truth_path_for(FOLDER)` (or
`--truth`) with the **default** `benchmark=True`, measures, prints the
validator's warnings (one per line, first) and then exactly these five lines in
this order, percentages to one decimal:

```
S1b chapter acceptance      {s1b:.1%}  accepted {accepted} / ground truth {ground_truth}   <- headline
S1a translation acceptance  {s1a:.1%}  accepted {accepted} / proposed {proposed}
recall                      {recall:.1%}  matched {matched} / ground truth {ground_truth}
spurious                    {spurious}
identity S1b = S1a x recall {holds|does not hold (spurious present)}
```

Returns `0`. Returns `2` with one sentence and no traceback for: no such
folder / no project there / no document at the path / `InvalidGroundTruth` /
`BenchmarkChapterUsedInDevelopment` (naming the chapter). No other exit code:
this command reports a number, it does not judge the 80 % bar.

## Test plan

One file, `tests/core/test_bench_acceptance.py`, unit level: the metric is pure
arithmetic over a store and a document, so a constructed project in `tmp_path`
falsifies every criterion and nothing needs a GPU, a network or the UI. No
conftest change, no committed fixture, no `skip`/`xfail`.

**Fixture (the truth is the constant, the project is what each case perturbs).**
Chapter `tmp_path/chapter-one`: `001.png` (200 x 200, white) and `002.png`
(200 x 200, RGB 250,250,250 - so the sha256 differ). Per page, ten regions
`_TRUTH_RECTS` = polygon corners `(5+39c, 5+45r, 35+39c, 35+45r)` for `r in 0..1`,
`c in 0..4`, reading index `5r + c`; ring polygons via `_bake_world.ring`, masks
via `_bake_world.mask_png` over the half-open rect `(x0, y0, x1+1, y1+1)` - exactly
the 31 x 31 px Pillow's inclusive polygon fill draws, so a region at its own place
has IoU 1.0 with its truth region and 0 with all others. Proposal for page `o`,
region `i`: `f"The café on street {10*o + i} is open."` (20 pairwise distinct after
`normalise`, composed `é`, five interior spaces, ending `.`). Each line's OCR text
is `せりふ{i}`. Baseline: every final committed equal to its proposal
(`commit_line(..., proposal, "accepted")`). The baseline project lives at
`project_dir_for(folder)`; the truth is `seed_ground_truth` of it at
`truth_path_for(folder)`, loaded with `load_ground_truth` (default benchmark
mode). It is all `seed`, so `validate` warns - deliberately left so: it is what
lets the "warnings do not stop it" and "main prints warnings first" cases mean
something. Every control builds a **fresh** project of the same chapter
(`tmp_path/control-N.mtproj`) and measures it against that same truth.
Spurious regions are 2 x 2 px squares at `(4*(k%50), 100 + 5*(k//50))` in the
empty bottom half (y >= 100), IoU 0 with every truth region.

   (`test_matching_is_by_mask_iou...`) or phantoms whose lines are rejected
   placed ahead of the real regions (AC-9, which is why the first ten phantoms

5. `write_regions` upserts by reading index, so re-writing a page with more
   regions keeps lines (and finals) on the existing indices and leaves the new
