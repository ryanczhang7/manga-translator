## Context

Brief success criterion **S1**, the headline number: "at least 80% of the
benchmark chapter's text regions carry a line that is accepted as-is, with no
edit on the review screen… The denominator is every text region in the chapter's
hand-made ground-truth list, not every line the tool happened to propose."

Open question **O2** — what counts as accepted as-is — is resolved in
`docs/wiki/stack.md` §5/O2 and implemented as `domain.line.normalise` by MT-017.
**This story does not re-define it and must not carry a second copy.**

Open question **O1** — which chapter — **is the user's and is still open.** This
story builds the harness and ships fixtures small enough to test it. AC-8 is the
criterion that keeps the two apart.

The measurement reports **two numbers, and never suppresses either:**

- **S1b — chapter acceptance** = accepted / *ground-truth region count*. **The
  headline. The 80% bar attaches here** — the user decided this on 2026-09-12,
  choosing the uncheatable and strictly harder number over the one the brief's
  original wording implied. A missed region contributes 0 to the numerator and 1
  to the denominator.
- **S1a — translation acceptance** = accepted / *proposed*. Diagnostic, not a
  bar. It answers "of what the detector found, how good was the translation?",
  which is the question you need when S1b is low.

**The gap between them is the diagnosis, and it is an identity, not a slogan:**
with no spurious detections, `S1b = S1a × recall`. A large gap means fix the
detector; a small gap with a low S1b means fix the translation. AC-4 asserts it.

**A previously planned rule is deliberately absent, and must not be
reintroduced.** An earlier draft voided the report when detection recall fell
below 95% and suppressed S1a. That rule existed only to stop S1a being read as
the headline when detection was bad; with S1b as the headline, poor detection
lowers the headline directly and proportionally, so the rule guards nothing —
and it suppressed S1a exactly when S1a is most diagnostic. It is gone. Recall is
still reported on every run, and is a criterion in its own right under S2
(MT-023). If a later agent proposes adding a validity gate here, this paragraph
is the answer.

**What S1b cannot see, and why AC-9 exists.** A *spurious* region — a phantom
bubble where there is no text — is absent from the ground truth, so it changes
neither S1b's numerator nor its denominator. S1a partly covered this (a phantom
diluted its denominator); the headline does not. So the report carries the
spurious count beside S1b, and spurious detections are a first-class reported
failure under S2. A reader who quotes S1b alone is quoting half the result.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — `bench` is in the 100% set.

## Acceptance criteria

- **AC-1** — Given a chapter project and a ground-truth region list, when the
  measurement runs, then it reports **S1b** as the headline together with S1a,
  the accepted count, the proposed count, the ground-truth count, the recall and
  the **spurious count** — and both S1a and S1b are present on every run, under
  every input, with no suppression path.
- **AC-2** — Given a line whose final text differs from its proposal by **one
  word**, when it is scored, then it is a **rejection**. The same for a
  punctuation-only difference and for a capitalisation-only difference.
- **AC-3** — Given a line that was edited and then restored character-for-
  character, when it is scored, then it is an **acceptance**.
- **AC-4** — Given a run with **no spurious detections**, when it is scored, then
  `S1b == S1a × recall` exactly, to the report's stated precision — and given a
  run **with** spurious detections, that identity does **not** hold and the
  spurious count is non-zero.
  *(This is what makes "the gap is the diagnosis" a checkable claim. A report
  that satisfies the identity unconditionally has computed one of the two
  numbers from the other instead of from the data.)*
- **AC-5** — *(negative control: the metric can tell right from wrong)* Given the
  proposed lines rotated by one region, when scored, then **both** S1a and S1b
  are at or near 0%.
- **AC-6** — *(negative control: `normalise` does what it claims)* Given every
  final replaced by its NFD form with doubled interior spaces, when scored, then
  acceptance is **100%**. Given every final with one character changed
  (`.` → `!`), then acceptance is **0%**.
- **AC-7** — *(negative control: the headline is coupled to detection — the whole
  point of the user's decision)* Given 30% of regions dropped from the detector
  output, when scored, then S1a is **unchanged** and S1b falls by approximately
  30%.
- **AC-8** — Given a chapter whose project file records that it was used during
  development (a development marker written by the fixture loader), when the
  measurement is run in benchmark mode, then it **refuses** and names the
  chapter. *(O1: the benchmark chapter is held out, and the harness enforces it
  rather than trusting a convention.)*
- **AC-9** — *(negative control: the report exposes what S1b cannot see)* Given
  1,000 spurious regions added to the detector output, when scored, then S1b is
  **unchanged**, S1a falls sharply, and the spurious count is reported as 1,000.

## Contract

```

        s1b: float                   # HEADLINE: accepted / ground_truth
        s1a: float                   # diagnostic: accepted / proposed
        recall: float                # matched / ground_truth
        accepted: int
        proposed: int
        matched: int
        spurious: int
        ground_truth: int

    def measure(project: Project, truth: GroundTruth) -> AcceptanceReport
```

**Where the ground truth comes from: MT-029.** The format, the loader, the
validator and the development-use refusal are all that story's, and this one
**imports** them. An earlier draft of this story declared `bench/truth.py`
itself, which left the annotation with no owner — a human marks 150–250 regions
on the benchmark chapter by hand, and nothing in the backlog created the file
that holds them. AC-8 below asserts the *behaviour* here because this is where
it is relied on; the mechanism is implemented once, in MT-029.

**Settled, and to be read out:**

- **`normalise` is imported from `mangatl.domain.line`.** One definition, one
  implementation. A second copy here is how the metric and the product drift
  apart and nobody notices for six stories.
- **`s1a` and `s1b` are both non-optional floats.** There is no `valid` flag,
  no `invalid_reason`, and no code path that declines to compute either. An
  earlier draft had all three; see `## Context` for why they are gone and why
  reintroducing them would be a regression rather than a safeguard.
- **Region matching between proposal and ground truth is by mask IoU ≥
  `IOU_MATCH_THRESHOLD`**, not by index — indices shift when a region is missed,
  and an index-based match would silently mis-pair everything after the first
  miss. `matched` counts ground-truth regions that found a partner; `spurious`
  counts proposals that did not; `proposed = matched + spurious`.
- **The 80% bar attaches to `s1b`.** Settled by the user on 2026-09-12. This
  story does not re-open it and does not need to encode the bar itself — the
  report prints the number; the bar is a judgement made against it.
- **`s1b` and `s1a` are computed independently from the counts**, not derived
  from each other. AC-4's identity is then a real check on the data rather than
  a tautology, which is exactly what its second half (spurious present ⇒
  identity fails) is there to force.

**Oracle partition:**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1..AC-3, AC-8 | **Mechanical** | Constructed projects and truth files. Exact counts, exact refusals. |
| AC-4 | **Mechanical** | An algebraic identity with a stated precision. Both halves are required: the identity holding *and* the identity failing when spurious regions are present. |
| AC-5..AC-7, AC-9 | **Mechanical, and they *are* the controls** | The five controls and their required values come from `stack.md` §5/O2 and are **settled**. Read them out; do not invent a sixth and do not soften one to "approximately" where a number is given. AC-6's two halves are 100% and 0% exactly; AC-9's spurious count is 1,000 exactly. |

This is the unusual story where the negative controls are themselves acceptance
criteria, because the artifact *is* a metric. A metric with no control is the
failure mode `story-authoring` documents at length, and here it would be a
metric measuring the product's headline claim.

## Deferred verifications

- *Falsifiable condition 1:* with `normalise` swapped for `str.strip` alone,
  AC-6's first half **must** fail (NFD input no longer matches).
- *Falsifiable condition 2:* with region matching changed from IoU to index,
  AC-7 **must** fail — S1a would move when regions are dropped.
- *Falsifiable condition 3:* with `s1b` computed as `s1a * recall` instead of
  from the counts — a plausible "simplification" that makes AC-4's first half
  pass by construction — **AC-4's second half and AC-9 must both fail.** This is
  the most valuable mutation in the story: it is the exact way an implementation
  can satisfy the headline identity while having stopped measuring the thing the
  user chose the headline for.
- *Falsifiable condition 4:* with `IOU_MATCH_THRESHOLD` set to `0.0` — a wrong
  value, so every proposal matches every region — **AC-9 must fail** (spurious
  collapses to zero) and AC-7 must fail.
- **Owner: GATES.** Four mutations via `bash scripts/mutate.sh`.

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition: entirely mechanical, and that is the surprise.** A story
  about a metric reads as oracle-free, and this one is not: the metric, its
  controls and their required values are all settled in `stack.md` §5/O2. The
  dispatch prompt must say so, or RED will design a metric that already exists.
- **Success condition, falsifiable:** all **five** controls from `stack.md`
  §5/O2 appear as tests with their stated expected values (≈0% on both numbers,
  100%, 0%, S1b −30% with S1a flat, S1b flat with spurious = 1,000); AC-4 is
  asserted in **both** directions; and `normalise` is imported rather than
  reimplemented. A second `normalise` in `bench` has failed RED regardless of
  whether the tests pass, and so has an AC-4 that only asserts the identity
  holding.
- **Verdict:** *to be recorded.*
