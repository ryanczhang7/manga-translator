## Context

EPIC-10 PO-1, PO-2, PO-3 and PO-6: the one mechanism both the automatic rule
(MT-121) and the user's action (MT-120) write, and the first consumer that
matters - the model call, which is the one that costs money.

**What exists.** `RawRegion` (`domain/region.py`) carries `kind:
Literal["bubble","box"]` and nothing reads it downstream. `write_regions` /
`read_regions` (`store/project.py:697,753`) persist it; the `region` table
(`store/schema.py`) has no exclusion column; `SCHEMA_VERSION` is 7.
`TranslateStage.run` (`pipeline/translate_stage.py`) reads
`read_lines(ordinal)` - one `OcrResult` per region, positional - hands them
all to `self.translate(image, ocr_results, context)`, and writes the result's
`lines` mapping (`reading_index -> English`) with `write_proposed`. The
listing the model sees is `[index] text` by `enumerate` (`page_prompt.user_text`),
and the no-call guard is `all(ocr_empty)` over what it is handed
(`translate/client.py`, `translate/gemini.py`).

**The shape.** A region gains `excluded: Literal["watermark", "user"] | None`
(default `None`), persisted in a new nullable column; the store gains one
call that sets or clears it for `(page_ordinal, reading_index)`; and the
translate stage hands the translator **only the included regions**, as a
contiguous listing, and maps the answer's indices back to reading indices
before writing. The translator packages (`translate/*`, `PageTranslator`)
are **unchanged**: exclusion is a stage concern, the model never learns a
region existed, and `components.md` §4.2's stable ordinals hold (PO-3).

**Why OCR is not touched** (PO-2): a restored region needs a line row to be
reviewed by hand, and the app has no per-page re-run; OCR is local and free.

**Schema v8 and MT-103.** MT-103 (EPIC-09) is also planned as "schema v8" on
`schema.py` / `project.py` and plans the same `tests/core/fixtures/schema_v7.sqlite`.
`plan.sh conflicts` reports the pair as CONFLICT; they run one after the
other, and **whichever lands second takes the next version number** - the
other's PLANNED story is renumbered then (one line, criteria not yet frozen).
This story is written as v8.

**A consequence for `write_regions`.** It upserts on `(page_id,
reading_index)`; the new column is written from the `RawRegion` like every
other, so a re-detection overwrites a user's exclusion with the detector's
(EPIC-10 "Deliberately not"). That is the existing rule for every column and
is pinned, not hidden.

Required gates that fail if this breaks: `unit`, `coverage`, and
`coverage-core` (`domain/**` at 100%: every branch of the new field's
validation needs a test). `architecture.md` §4's `region` row and a new D14
record the mechanism; the PO writes them at REVIEW.

## Acceptance criteria

- **AC-1** - Given `RawRegion(..., excluded="watermark")`, `excluded="user"`
  and the default, when constructed, then each is accepted and `excluded`
  reads back as given; given any other string, then `ValueError` names
  `excluded`. Positional construction sites that do not mention the field
  keep working (`merged_from`'s rule).
- **AC-2** - Given a page written with three regions of which the second is
  `excluded="watermark"`, when the page is read back, then the second region's
  `excluded` is `"watermark"` and the others' is `None`; a plain `SELECT
  excluded FROM region` shows `'watermark'` on that row and `NULL` on the
  others.
- **AC-3** - Given a stored page, when `set_excluded(ordinal, 1, "user")` is
  called, then `read_regions(ordinal)[1].excluded == "user"`, the region's
  other columns and its `line` row are unchanged, and `set_excluded(ordinal,
  1, None)` clears it; an index not on the page raises `ValueError` naming it
  with nothing written; a reason outside the two raises `ValueError`.
- **AC-4** - Given a project file at schema 7 with regions, when it is opened,
  then `schema_version` is 8, every region reads back with `excluded is None`
  and every other column unchanged, and a version-8 file is refused by a
  reader whose `SCHEMA_VERSION` is 7 with `SchemaTooNew` (the existing
  `test_schema_v7.py` pattern, on a committed v7 fixture).
- **AC-5** - Given a page of three regions with OCR text where the second is
  excluded, when `TranslateStage.run` runs, then the translator is called with
  **two** `OcrResult`s - the first and third regions' text, in that order -
  and when it returns `{0: "A", 1: "C"}` the store's proposals read
  `("A", None, "C")`: the excluded region's `proposed_en` stays `NULL`.
  *Control:* the same page with nothing excluded calls the translator with
  three results and stores `("A", "B", "C")`.
- **AC-6** - Given a page whose only non-excluded regions are all `ocr_empty`
  (and one excluded region with text), when the stage runs, then the
  translator is called with results that are all `ocr_empty`, so the
  existing no-call guard fires: no ledger row, no `CallPriced`, no proposal.
  *Control:* un-exclude that region and a call is made.
- **AC-7** - Given a page where the excluded region's `source_ja` is a glossary
  term and no included region's is, when the stage runs, then the glossary
  does not mark the term seen on that page (the excluded text is not handed
  to `_update_glossary`).

### C-1 The field

```python
# src/mangatl/domain/region.py
ExclusionReason = Literal["watermark", "user"]
EXCLUSION_REASONS: tuple[ExclusionReason, ...] = ("watermark", "user")

@dataclass(frozen=True)
class RawRegion:
    polygon: ...
    mask: bytes
    confidence: float
    kind: Literal["bubble", "box"]
    merged_from: tuple[int, ...] = ()
    #: Why this region is out of translation, cleaning and typesetting; None
    #: is "included". `watermark` is the detector's rule (MT-121), `user` the
    #: workspace's (MT-120). LAST and defaulted, for merged_from's reason.
    excluded: ExclusionReason | None = None
```

`__post_init__` raises `ValueError` naming `excluded` for a value outside
`EXCLUSION_REASONS` and `None`. `__all__` gains `ExclusionReason`,
`EXCLUSION_REASONS`. `kind` is untouched.

compares the `excluded` clause with whitespace collapsed, against each other and
against the literal `excluded TEXT CHECK (excluded IS NULL OR excluded IN
('watermark', 'user'))`. Keep the CHECK's words exactly that in both strings.

### C-3 The store call

```python
def set_excluded(self, page_ordinal: int, reading_index: int,
                 reason: ExclusionReason | None) -> None
```

A method of `Project`, beside `write_regions`. Opens its own `transaction()`
(so it refuses a caller already holding one, like every other write). Checks
the index against the page's region count **before** writing and raises
`ValueError` naming it, as `write_proposed` does; `reason` outside
`EXCLUSION_REASONS | {None}` raises `ValueError`. Touches only the `excluded`
column: no `line` row, no `cleaned_page` row is invalidated here - MT-119
decides what a toggle does to the cleaned image and says so there.

### C-4 The stage

In `TranslateStage.run`, after `read_lines`:

```python
regions = ctx.project.read_regions(ctx.page.ordinal)
included = [i for i, region in enumerate(regions) if region.excluded is None]
sent = [ocr_results[i] for i in included]
result = self.translate(image_bytes, sent, context)
proposals = {included[k]: text for k, text in result.lines.items()}
```

`record_call`, `CallPriced`, the guard and the orderings in the docstring
are unchanged. `_update_glossary(ctx, result, sent)` receives the sent
results (AC-7). `write_proposed(ordinal, proposals)`. A key in `result.lines`
outside `range(len(sent))` is the translator's `UnknownRegionIndex` already
(parse checks against the count handed in) and is not re-checked here. A
page with **no** included regions hands the translator an empty sequence;
`all([])` is `True`, so the existing guard makes no call - pin it (AC-6's
edge) rather than special-case it. `is_done` is unchanged: a page whose only
proposal-less regions are excluded is still done once any included one has
a proposal; a page whose regions are all excluded is never done and
re-running it is free.

`PageTranslator`, `translate/client.py`, `translate/gemini.py`,
`page_prompt.py`, `parse.py` - **unchanged**. No signature of an existing
export changes; `RawRegion` gains a defaulted trailing field only, so its 79
construction sites (`grep -rn "RawRegion(" src tests`) keep working.
