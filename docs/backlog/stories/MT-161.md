**What is settled** (the audit's `## Decided`, not to be reopened):
- Both behaviours below are correct in `src/mangatl/ui/workspace.py` today.
- The fix is tests only. No production file changes.
- N09 matters more than N07: it is on the ordinary path. `app.open_folder`
  opens every workspace on row 0 (`src/mangatl/app.py:175`,
  `window.page_strip.setCurrentRow(0)`), and `load_chapter` selects nothing
  ("nothing is selected yet", `workspace.py:1289`). So the restore in
  `_return_from_run` is the only thing that puts page 1 back after a run
  started from a freshly opened chapter.

**What is evidence, to verify rather than trust:** that each mutant below still
survives at this story's base (re-run each command first), and the audit's
reading of why N07 survives (below), which it reasoned and did not measure.

**The gap, one line each** (line numbers re-anchored at `e69ba49`, 2026-11-25; the audit measured at `64c0a4b`, where each `workspace.py` line was 9 lower - Notes PO-1):

- **N09** - `workspace.py:1617`, `_return_from_run`'s
  `if 0 <= self._run_row < self.page_strip.count():`. Changed to `0 <`, all of
  `tests/ui/test_rerun_workspace.py` passes, and so does all of `tests/ui`
  (audit E-3 has the counts). The one test that checks MT-125 AC-4's "the page
  shown before the run is shown again" starts the run on row 1
  (`test_a_finished_run_returns_the_body_reloaded_from_the_same_open_project`,
  `test_rerun_workspace.py:1044`), so the lower bound is never exercised. Under
  the mutant a run started on page 1 comes back with no page selected.
- **N07** - `workspace.py:1554`, `_on_rerun_dialog_finished`'s
  `self._focus_rerun()` on a rejected dialog. Replaced with `pass`, all of
  `test_rerun_workspace.py` passes, including
  `test_focus_returns_to_run_again_when_the_dialog_closes`. The audit's reading
  (reasoned, not measured): in that test Run again already holds the window's
  focus before it is activated, so `activateWindow()` on line 1552 restores it
  by itself, and the test cannot tell whether line 1554 ran. The test passes
  for a reason that is not the line it is named after.

## Acceptance criteria

- **AC-1** - Given a `Workspace` with a chapter loaded and **row 0** current
  in the page strip, when "Run again" is confirmed and the run finishes, then
  after the body returns the strip's current row is 0 and the canvas shows
  page 1. This test **fails** under N09:
  `bash scripts/mutate.sh src/mangatl/ui/workspace.py '1617s/if 0 <= self\._run_row </if 0 < self._run_row </' -- uv run --no-sync pytest -q -p no:cacheprovider tests/ui/test_rerun_return.py`.
- **AC-2** - Given a `Workspace` with a chapter loaded and focus on a control
  **other than** "Run again" (for example the page strip), when "Run again" is
  activated without moving focus to it (`click()`, as an accessibility default
  action does) and the dialog is cancelled, then focus lands on "Run again".
  This test **fails** under N07:
  `bash scripts/mutate.sh src/mangatl/ui/workspace.py '1554s/^            self\._focus_rerun()$/            pass/' -- uv run --no-sync pytest -q -p no:cacheprovider tests/ui/test_rerun_return.py`.
  If RED finds that focus lands on "Run again" under the mutant as well (Qt
  restoring it by some route the audit did not see), RED stops and records the
  measured focus widget, rather than weakening the assertion. N07 is then
  equivalent and AC-2 goes to the PO.

**"The canvas shows page 1".** C-3 left the choice to RED. Chosen:
`page_canvas.state() == "loaded"` **plus** the pixel colour of the pixmap the
canvas actually holds (`page_canvas.page_item.pixmap()`), compared with page
1's flat fill `QColor(40, 90, 120)`. Each page of the fixture is a distinct
flat colour (`_page_colour(ordinal)`), so the pixel names the page from what
is on screen rather than from the workspace's private `_page_ordinal`
bookkeeping; a canvas left showing page 2 or 4 fails it, which
`state() == "loaded"` alone would not catch. `_page_ordinal` is not asserted.

Edges: the boundary is the whole point of AC-1 (row 0 against `0 <`); later
rows are already covered by the existing hand-over tests. `## Out of scope`
items are not pinned.
