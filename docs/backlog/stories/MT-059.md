## Context

**Filed 2026-09-30 by the Lead PO**, the third of three stories that let the
window start a run ([[MT-057]] `## Context` has the split). With it the
brief's first five minutes (`product-brief.md` §3, steps 1-4) work from a
double-click: choose a folder, see what will be run and what it should cost,
press "Start run", watch it work, land in the review workspace.

It wires what exists; it designs no new stage:

- `mangatl.store.project.create_project(read_chapter(folder),
  project_dir_for(folder))` - exactly what `mangatl-run` does (`cli.py`), and
  the only way a project comes to exist.
- `mangatl.compose.build_pipeline(models_dir, translate=True)` - the
  composition root, the one module allowed to construct ONNX sessions and the
  Anthropic client (`architecture.md` §3, the composition-root exception to rule
  5; MT-036, MT-044).
- `mangatl.pipeline.runner.run_chapter(project, stages, emit, cancelled)`,
  whose events (`mangatl.domain.events`) [[MT-018]]'s `RunProgressPanel` and
  `CostReadout` render.
- `architecture.md` §6: "`ui` → `pipeline`: commands … returns immediately; the
  work runs on a worker thread", and "`pipeline` → `ui`: an event stream … Qt
  signals at the boundary". **No story has built that thread yet.** MT-018's
  out-of-scope attributes it to MT-015; MT-015 did not build it
  (`src/mangatl/ui` has no thread). It is this story's, and MT-018 carries a
  note saying so.

**A real design constraint, stated rather than resolved silently.** The window
cannot reach `build_pipeline` as the import contracts stand
(`pyproject.toml [tool.importlinter]`):

- `mangatl.compose` imports `onnxruntime` and `anthropic` at module import.
- `mangatl.ui` is a source module of both *"Only translate imports anthropic"*
  and *"Only detect, ocr and clean import onnxruntime"*, and import-linter
  counts indirect imports - so `ui → compose` breaks two contracts.
- `mangatl.app` is **also** listed in both, deliberately: "an exemption is
  earned by a gate that fails, not anticipated" (MT-036 PO-2, MT-044 PO-1).
- `mangatl.cli` was taken out of both for exactly this reason, once each, and
  that is the precedent.

**Decided by the user, 2026-09-30 (Q1 option (a), PO-3):** `mangatl.app` is
exempted from both contracts - the third instance of the composition-root
exception - imports `build_pipeline` inside the Start handler, and injects the
builder into the window. `ui` stays confined. The exemption is earned the way
the precedent's were (`## Contract`, "The exemption").

Required gates: `unit` and `coverage` (the run driven with an injected fake
stage list, offscreen, no weights, no key), and `lint` (import-linter), which is
the gate that must first *fail* and then pass for Q1's exemption to be earned.
`build_pipeline` itself stays outside required-gate coverage, as it already is
(`compose.py` docstring). `required_gates: []`.

## Acceptance criteria

- **AC-1** — Given a chapter summary for a folder with no project, when "Start
  run" is pressed, then the project is created beside the folder
  (`<folder>.mtproj`, as `mangatl-run` would create it) and the run begins; the
  input folder is not written. When [[MT-058]]'s estimate is over budget, the
  button reads "Start run anyway" (`components.md` §2) and does the same.
- **AC-2** — Given a run in progress, when the stages execute, then they run
  off the GUI thread and the window keeps processing events between them.
  *(Control: a fake stage that records `threading.current_thread()` must see a
  thread that is not the GUI thread; a GUI timer must fire while a fake stage is
  blocked.)*
- **AC-3** — Given a run in progress, when the runner emits events, then each
  one reaches the GUI thread, in emission order, and drives [[MT-018]]'s
  progress panel and cost readout. *(Control: a fake stage list emitting a
  known sequence must be received as exactly that sequence.)*
- **AC-4** — Given the run finishes (`RunFinished`), when the last event
  arrives, then the review `Workspace` opens on the chapter with the first page
  shown, and closing it closes the project (MT-054 C-4). No output folder is
  written - rendering is a separate press (brief §3 step 5, [[MT-021]]).
- **AC-5** — Given the run aborts (`RunAborted`, for the budget or an error),
  when the event arrives, then every page completed before it is kept, the
  panel shows MT-018's aborted or failed state, and its "Review pages 1–N"
  action opens the `Workspace` on the chapter.
- **AC-6** — Given the window is closed while a run is in progress, when it
  closes, then the run is cancelled through `run_chapter`'s `cancelled`
  callable, the window waits for the worker to return before the project is
  closed, and every page completed before the close is kept and resumable.
- **AC-7** — Given `MANGATL_MODELS` unset, empty, or naming something that is
  not a directory, when "Start run" is pressed, then the window shows "No models
  folder: set MANGATL_MODELS to the folder holding the model weights, then
  start the app again." and **nothing is created** - the models are resolved
  before the project, in `mangatl-run`'s order (MT-036 C-3). The environment
  variable is the only source (PO-4); the sentence does not mention
  `--models`, which a window user cannot pass. *(Control: with `MANGATL_MODELS`
  naming an existing directory, the builder is called with exactly that
  path.)*
- **AC-8** — Given no `ANTHROPIC_API_KEY`, when "Start run" is pressed, then
  the run starts exactly as it does with one - the window makes no up-front key
  check and refuses nothing (PO-5, the CLI's behaviour, MT-044 A-1) - and when
  the first page that needs a call fails, the run aborts: MT-018's failed state
  shows the abort reason, and the pages and stages completed before it are
  kept. *(In tests the failing call is a fake translate stage raising the
  error; that the real client raises at request time and not at construction
  is `compose.py`'s measured claim, not re-tested here. Control: the window
  code must not read `ANTHROPIC_API_KEY` at all - a test with the variable set
  and one without produce the same calls up to the failing stage.)*

**C-1 — `mangatl.ui.run` (new module).** `ui` may import `pipeline` and
`store` (layers contract); it may not import `mangatl.compose`.

```python
NO_MODELS: str = (
    "No models folder: set MANGATL_MODELS to the folder holding the model"
    " weights, then start the app again."
)                                             # AC-7, character-exact
ModelsResolver = Callable[[], Path | None]    # None: there is no models folder
StageBuilder = Callable[[Path], Sequence[Stage]]

@dataclass(frozen=True)
class RunSetup:
    resolve_models: ModelsResolver
    build_stages: StageBuilder

class RunController(QObject):
    event = Signal(object)   # each RunEvent, received on the GUI thread, in emission order
    ended = Signal(object)   # the RunOutcome, on the GUI thread, after the last `event`
    def __init__(self, project_dir: Path, stages: Sequence[Stage],
                 parent: QObject | None = None) -> None: ...
    def start(self) -> None      # starts the worker and returns at once
    def cancel(self) -> None     # thread-safe; `cancelled()` is True from then on
    def wait(self) -> None       # blocks until the worker has returned and closed its Project; no-op if not running
    def is_running(self) -> bool
```

The worker, on its own thread: `with open_project(project_dir) as project:
outcome = run_chapter(project, stages, <emit>, <cancelled>)`, then `ended`.
`<emit>` emits `event` from the worker thread; delivery to GUI-thread receivers
is Qt's queued connection. `threading.Thread` or `QThread` is GREEN's choice.
The worker opens its **own** `Project` - a `Project` crosses no thread
(`check_same_thread=True` stays; changing it needs the PO).

  frozen dataclasses, so they cross threads safely (MT-013's reason).

## Design notes

*Lead Designer, 2026-10-01. Recorded in `components.md` §1, §2 and §8 (each
marked MT-059). Copy is character-exact; `—` is U+2014, `–` is U+2013.*

**D-1 — Start button on `ChapterSummary`.**
- `QPushButton`, object name `summary-start`, dynamic property
  `variant="primary"` set in the constructor. Text `Start run`; `Start run
  anyway` when `summary.cost_estimate.over_budget` is True. Accessible name = text.
- Placement: one row **outside** the scroll area at its foot (where
  `summary-choose` is today), left-aligned, `space.4` above it: `Start run`
  **first (left)**, then `Choose a different folder`, `space.2` between them.
- Focus order: scroll area → `summary-start` → `summary-choose` (Tab;
  Shift+Tab reverses). On appearance focus stays on the scroll area (MT-057).
  Pin the order with `nextInFocusChain()`/Tab, **not** with the order of
  `findChildren(QAbstractButton)`, which is construction order and not a design fact.
- Activation: click, Space, Return, Enter - each once (same `_ActivatedByEnter`
  as Choose). No disabled or loading state: the press is acted on synchronously
  (models check, then create, then the run screen).
- **The summary now has two buttons** (`summary-start`, `summary-choose`). Three
  existing tests assert exactly one and are this story's RED changes:
  `tests/ui/test_chapter_summary.py` line 517 and
  `test_choose_a_different_folder_is_the_only_button_and_there_is_no_start_button`
  (line 658), and `tests/ui/test_cost_estimate.py`
  `test_the_summary_gains_the_estimate_but_no_button` (line 240). Compare as a set.
- Styling (`theme.qss.tmpl`, after the secondary rules; no rule exists today):
  `QPushButton[variant="primary"]` ground `color.accent.base`, text
  `color.text.on-accent`, `border: focus.width px solid transparent`,
  `background-clip: padding`; `:hover` ground `color.accent.hover`; `:pressed`
  ground `color.accent.pressed`; `:focus` `border-color: color.focus.ring`
  only. The transparent band means focus moves nothing and the white ring sits
  on `surface.base` (17.04:1), not on the accent (≈2.0:1). Label contrast
  ≈8.4 / 10.1 / 6.3:1 at rest / hover / pressed. **Three newly referenced
  tokens** (`accent.hover`, `accent.pressed`, `text.on-accent`):
  `tests/ui/test_tokens.py` `BASE_REFERENCED_COUNT` 39 → 42 and `ORPHAN_COUNT`
  87 → 84, a RED change. No `theme_hc` rule: the three map to
  `Highlight`/`HighlightedText` (§10.1's primary row), and the more specific
  attribute rules outrank the HC sheet's `QPushButton:hover/:pressed`.
- AC-7's refusal (recommended): `MainWindow.show_error(sentence)` - the drop
  target's error state with AC-7's sentence as headline, as every intake refusal.

**D-2 — The run screen.** On Start the window's central widget becomes MT-018's
`RunProgressPanel` (`run-progress`), nothing else. Window title stays `mangatl`.
No Stop run, no thumbnail, `CostReadout` stays inside the panel (the header
placement of layout.md is deferred with the run header). The panel has no focus
stop while running; focus must not be left on a deleted summary widget.

**D-3 — The failed state.** `RunAborted` whose reason is neither `budget` nor
`cancelled`. `{n}` = `ordinal + 1`, `{kept}` = `ordinal` (fallback when
`ordinal` is None: completed + skipped, as the budget path), `{total}` = page
count, `{reason}` = `RunAborted.reason` verbatim (the runner's
`"{Type}: {message}"`; never a traceback). Same `ErrorBanner` (danger variant,
glyph `⚠`, role Alert, announced once), inserted at the top of the panel.

| | kept ≥ 1 | kept = 0 |
|---|---|---|
| headline | `Run stopped at page {n} of {total} — page {n} failed.` | same |
| body | `{reason}` + `\n` + `Pages 1–{kept} are translated and can be reviewed and rendered.` | `{reason}` + `\n` + `No pages were translated.` |
| action | `Review pages 1–{kept}` → `review_requested.emit(kept)` | none |

- Accessible name stays `f"{headline} {body}"` (the shipped rule).
- `CostReadout` is **not** touched: no `mark_aborted`, no `show_final`. Its
  state after the event equals its state before (`unknown` in the keyless case).
  `aborted` means the budget was reached and nothing else.
- When the banner has an action, focus moves to it (the only control on screen);
  it activates on click, Space, Return and Enter (applies to the budget banner too).
- `PageStageStepper` failed step state: **deferred**, not built; the stepper
  stays as the last event left it. The banner names the page.

**D-4 — Cancellation** (`cancelled`, only on window close): no banner, no
readout change; the window is going away.

*Gap noted for the PO:* after a kept = 0 failure the window offers no next
step but closing, and reopening the folder opens a `Workspace` with no
translations (resume is out of scope, PO-2).
