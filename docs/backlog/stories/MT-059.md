## Context

**Filed 2026-09-30 by the Lead PO**, the third of three stories that let the
window start a run ([[MT-057]] `## Context` has the split). With it the
brief's first five minutes (`product-brief.md` §3, steps 1-4) work from a
double-click: choose a folder, see what will be run and what it should cost,
press "Start run", watch it work, land in the review workspace.

It wires what exists; it designs no new stage:

- `mangatl.store.project.create_project(read_chapter(folder),
  project_dir_for(folder))` - exactly what `mangatl-run` does (`cli.py`), and
  the only way a project comes to exist.
- `mangatl.compose.build_pipeline(models_dir, translate=True)` - the
  composition root, the one module allowed to construct ONNX sessions and the
  Anthropic client (`architecture.md` §3, the composition-root exception to rule
  5; MT-036, MT-044).
- `mangatl.pipeline.runner.run_chapter(project, stages, emit, cancelled)`,
  whose events (`mangatl.domain.events`) [[MT-018]]'s `RunProgressPanel` and
  `CostReadout` render.
- `architecture.md` §6: "`ui` → `pipeline`: commands … returns immediately; the
  work runs on a worker thread", and "`pipeline` → `ui`: an event stream … Qt
  signals at the boundary". **No story has built that thread yet.** MT-018's
  out-of-scope attributes it to MT-015; MT-015 did not build it
  (`src/mangatl/ui` has no thread). It is this story's, and MT-018 carries a
  note saying so.

**A real design constraint, stated rather than resolved silently.** The window
cannot reach `build_pipeline` as the import contracts stand
(`pyproject.toml [tool.importlinter]`):

- `mangatl.compose` imports `onnxruntime` and `anthropic` at module import.
- `mangatl.ui` is a source module of both *"Only translate imports anthropic"*
  and *"Only detect, ocr and clean import onnxruntime"*, and import-linter
  counts indirect imports - so `ui → compose` breaks two contracts.
- `mangatl.app` is **also** listed in both, deliberately: "an exemption is
  earned by a gate that fails, not anticipated" (MT-036 PO-2, MT-044 PO-1).
- `mangatl.cli` was taken out of both for exactly this reason, once each, and
  that is the precedent.

**Decided by the user, 2026-09-30 (Q1 option (a), PO-3):** `mangatl.app` is
exempted from both contracts - the third instance of the composition-root
exception - imports `build_pipeline` inside the Start handler, and injects the
builder into the window. `ui` stays confined. The exemption is earned the way
the precedent's were (`## Contract`, "The exemption").

Required gates: `unit` and `coverage` (the run driven with an injected fake
stage list, offscreen, no weights, no key), and `lint` (import-linter), which is
the gate that must first *fail* and then pass for Q1's exemption to be earned.
`build_pipeline` itself stays outside required-gate coverage, as it already is
(`compose.py` docstring). `required_gates: []`.

## Acceptance criteria

- **AC-1** — Given a chapter summary for a folder with no project, when "Start
  run" is pressed, then the project is created beside the folder
  (`<folder>.mtproj`, as `mangatl-run` would create it) and the run begins; the
  input folder is not written. When [[MT-058]]'s estimate is over budget, the
  button reads "Start run anyway" (`components.md` §2) and does the same.
- **AC-2** — Given a run in progress, when the stages execute, then they run
  off the GUI thread and the window keeps processing events between them.
  *(Control: a fake stage that records `threading.current_thread()` must see a
  thread that is not the GUI thread; a GUI timer must fire while a fake stage is
  blocked.)*
- **AC-3** — Given a run in progress, when the runner emits events, then each
  one reaches the GUI thread, in emission order, and drives [[MT-018]]'s
  progress panel and cost readout. *(Control: a fake stage list emitting a
  known sequence must be received as exactly that sequence.)*
- **AC-4** — Given the run finishes (`RunFinished`), when the last event
  arrives, then the review `Workspace` opens on the chapter with the first page
  shown, and closing it closes the project (MT-054 C-4). No output folder is
  written - rendering is a separate press (brief §3 step 5, [[MT-021]]).
- **AC-5** — Given the run aborts (`RunAborted`, for the budget or an error),
  when the event arrives, then every page completed before it is kept, the
  panel shows MT-018's aborted or failed state, and its "Review pages 1–N"
  action opens the `Workspace` on the chapter.
- **AC-6** — Given the window is closed while a run is in progress, when it
  closes, then the run is cancelled through `run_chapter`'s `cancelled`
  callable, the window waits for the worker to return before the project is
  closed, and every page completed before the close is kept and resumable.
- **AC-7** — Given `MANGATL_MODELS` unset, empty, or naming something that is
  not a directory, when "Start run" is pressed, then the window shows "No models
  folder: set MANGATL_MODELS to the folder holding the model weights, then
  start the app again." and **nothing is created** - the models are resolved
  before the project, in `mangatl-run`'s order (MT-036 C-3). The environment
  variable is the only source (PO-4); the sentence does not mention
  `--models`, which a window user cannot pass. *(Control: with `MANGATL_MODELS`
  naming an existing directory, the builder is called with exactly that
  path.)*
- **AC-8** — Given no `ANTHROPIC_API_KEY`, when "Start run" is pressed, then
  the run starts exactly as it does with one - the window makes no up-front key
  check and refuses nothing (PO-5, the CLI's behaviour, MT-044 A-1) - and when
  the first page that needs a call fails, the run aborts: MT-018's failed state
  shows the abort reason, and the pages and stages completed before it are
  kept. *(In tests the failing call is a fake translate stage raising the
  error; that the real client raises at request time and not at construction
  is `compose.py`'s measured claim, not re-tested here. Control: the window
  code must not read `ANTHROPIC_API_KEY` at all - a test with the variable set
  and one without produce the same calls up to the failing stage.)*

## Contract

**Not pinned yet** - at PLANNED → RED. Q1-Q4 are answered (PO-3 to PO-6).
Direction:

- **The stage list is injected** (PO-3). `mangatl.app` gives the window a
  stage-list factory (`Callable[[Path], Sequence[Stage]]` taking the models
  directory, or the like); `ui` never imports `compose`. Every test passes fake
  stages; no test loads weights or constructs a client. `app` imports
  `mangatl.compose` **inside** the function that builds the factory's result,
  not at module top, so a launch that only reviews a chapter does not import
  `onnxruntime` - import-linter counts function-body imports, so this saves
  start-up time, not the exemption.
- **The exemption** (PO-3). RED or GREEN, whichever first puts the import in
  place, runs `lint-imports`, pastes the two broken contracts naming
  `mangatl.app -> mangatl.compose`, removes `"mangatl.app"` from exactly those
  two `source_modules` lists (and nothing else - no `allow_indirect_imports`,
  no other name), reruns, pastes `kept`, and rewrites the two contract comments
  in `pyproject.toml` that say "`mangatl.app` stays listed". `mangatl.app`
  stays **out** of "Nothing imports ui" as today. `architecture.md` §3 rule 5's
  composition-root exception is amended by the Lead PO to name `mangatl.app` as
  its third instance. This changes what the `lint` gate guards, so the story
  carries a `## Gate probes` entry: with `"mangatl.app"` removed, an import of
  `mangatl.compose` added to a `mangatl.ui` module must still fail `lint`.
- **Models (PO-4).** `resolve_models_dir(None, os.environ)` is the resolution;
  the window catches `ModelsNotFound` and shows AC-7's sentence, not the
  exception's own text (which names `--models`).
- **`test_the_app_module_does_not_import_create_project`** (MT-054,
  `tests/ui/test_app_opens_chapter.py` line 564) stays and must still pass:
  `create_project` is called by the `ui` run controller (`ui` may import
  `store`), never by `mangatl.app`.
- **Threads and SQLite.** `open_project` / `create_project` use
  `sqlite3.connect` with its default `check_same_thread=True`. A `Project`
  created on the GUI thread and handed to the worker fails with
  `ProgrammingError` on its first query. So the worker opens (or creates) its
  own `Project`, and the `Workspace` opened after the run opens another, on the
  GUI thread, after the worker's is closed. RED pins which; GREEN must not
  "fix" it with `check_same_thread=False` without the PO.
- **The event bridge** is a `QObject` with one signal carrying a `RunEvent`,
  emitted from the worker and received on the GUI thread through a queued
  connection. The runner's `emit` is that signal's `emit`; `domain.events` are
  frozen dataclasses, so they cross threads safely (MT-013's reason).
- **Callers to list at RED:** `mangatl.app.build_window` (gains the factory
  injection), and any MT-055/MT-057 test that constructs the intake window
  directly.
- **Oracle partition.** *Settled:* "Start run", "Start run anyway"
  (`components.md` §2), the call sequence of `cli.main` (models, then read,
  then create, then build, then run), the no-output rule (brief §3), and the
  decisions PO-3 to PO-6. *PO-worded:* AC-7's sentence. *Mechanical:* AC-2,
  AC-3, AC-6, AC-7, AC-8 - each with the control named beside it.

## Model guidance

**GREEN, recommended to stay on `opus`, with a stated reason.** The failure
mode this harness exists to prevent is sharpest here: a threaded test that
flakes invites a `qtbot.wait` with a longer timeout, and a longer timeout is a
widened tolerance (`rules.md`). Condition that could come out either way:
GREEN's diff to `tests/` is empty *and* AC-2/AC-6 pass 20 runs in a row under
`bash scripts/gates.sh --gate unit`. Record the verdict when GREEN ends.

## Notes

### Open questions

None open. All four were answered by the user on 2026-09-30 ("accept all
recommendations"), recorded as PO-3 to PO-6; the questions are kept as put.

- **Q1 — RESOLVED (a), PO-3. How the window reaches the composition root.** See `## Context`.
  Options:
  (a) **exempt `mangatl.app`** from the anthropic and onnxruntime contracts, the
      third instance of the composition-root exception after `mangatl.cli`
      (MT-036, MT-044); `app` passes `build_pipeline` into the window as a
      factory, and `ui` stays confined. Earned the way the precedent was: RED
      or GREEN shows `lint-imports` failing with the import in place, removes
      the one name from each source list, shows `kept` again, and
      `architecture.md` §3 rule 5 is amended in the open. The import is made
      inside the Start handler, so a launch that only reviews does not load
      `onnxruntime` at start-up - import-linter counts function-body imports,
      so this does not avoid the exemption, only the start-up cost.
  (b) **a new entry module** (e.g. `mangatl.desktop`) that is exempt instead,
      and `app` stays confined. Same exemption, one more module.
  (c) **run `mangatl-run` as a subprocess** and parse its output. No
      exemption, but it throws away the typed event stream `architecture.md` §6
      and MT-018 are built on; progress would be scraped text.
  **Lead PO recommends (a).**
- **Q2 — RESOLVED (a), PO-4. Where a double-clicked app finds the weights.** `mangatl-run`
  takes `--models`, then `$MANGATL_MODELS`, then refuses with a sentence (MT-036
  PO-4: no silent default). A double-clicked app has no flag, and a user who
  double-clicks rarely has an environment variable. [[MT-024]] AC-7 bundles the
  weights and replaces the last branch. Until then: (a) `$MANGATL_MODELS` only,
  and AC-7's sentence names it; (b) a "Choose models folder…" step on first
  Start, remembered where? (no settings file exists); (c) this story waits for
  MT-024. **Lead PO recommends (a)**: the double-click experience is only whole
  after MT-024, and (b) would build a settings store MT-024 already owns.
- **Q3 — RESOLVED (a), PO-5. A missing API key.** On the command line a keyless run starts,
  detects and reads, and aborts on the first page that needs a call; the user
  chose that (MT-044 A-1) and `--no-translate` is the opt-out. From the window:
  (a) the same - the run aborts, and MT-018's failed state names the reason;
  (b) refuse "Start run" up front with a sentence naming `ANTHROPIC_API_KEY`
  (a check the CLI deliberately does not make); (c) offer a detect-and-read-only
  run. **Lead PO recommends (a)** for parity with A-1, with the observation that
  a window user pays a detection pass for nothing before learning it - (b) is
  the better experience and is one check.
- **Q4 — RESOLVED, PO-6. The budget the run is held to.** Every project created today
  stores `NULL` → `DEFAULT_CEILING` ($2.00). If [[MT-058]] Q2 adds a budget
  field, this story stores it on the new project; otherwise $2.00. No criterion
  depends on it beyond that; recorded so it is decided once.

### PO decisions at PLANNED (2026-09-30, lead-po)

- **PO-1 — no output folder from the window.** `mangatl-run` writes `<folder>_en`
  at the end of every finished run. The brief separates the two ("When it
  finishes, it shows the review screen … They press render", §3 steps 4-5), and
  review between them is the product. So the window's run ends in the
  `Workspace`, and writing is [[MT-021]]'s.
- **PO-2 — two gaps reported, not filed:** Stop run (the `RunProgressPanel`
  button and its confirm dialog) and resuming an interrupted run from the
  window. Both are in the design or implied by it, neither is in any story.
- **PO-3 — exempt `mangatl.app`: decided by the user, 2026-09-30 (Q1 (a)).**
  The third instance of `architecture.md` §3's composition-root exception;
  `compose` is imported inside the Start handler and the builder is injected
  into the window; `ui` stays confined. Earned by a failing `lint-imports` run
  and recorded as `## Contract` "The exemption" says. The Lead PO amends
  `architecture.md` §3 rule 5 when the exemption lands (at GREEN, alongside the
  `pyproject.toml` change), not before - "an exemption is earned by a gate that
  fails, not anticipated".
- **PO-4 — `MANGATL_MODELS` only, until MT-024: decided by the user,
  2026-09-30 (Q2 (a)).** AC-7. The window's sentence names the variable and not
  `--models`; that wording is the Lead PO's, consequential to the decision.
- **PO-5 — a missing API key behaves as on the command line: decided by the
  user, 2026-09-30 (Q3 (a)).** No up-front check; the run aborts on the first
  page that needs a call and MT-018's failed state names why. AC-8. The known
  cost - a detection and OCR pass paid in time before the user learns there is
  no key - is accepted, and MT-024's first-run prompt is what removes it.
- **PO-6 — $2.00: decided by the user, 2026-09-30 (Q4).** The project is
  created with the stored ceiling left `NULL` → `DEFAULT_CEILING`, exactly as
  `mangatl-run` creates it; this story writes no ceiling.
