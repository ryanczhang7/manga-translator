## Context

Brief feature 3, and the story the product's headline metric is about. The whole
reason the brief chose a cloud LLM over a local translation model is that it can
see the page: pronouns, speaker attribution, honorifics and continuity are
decided with the art in view.

`docs/wiki/stack.md` §5/O4 and `architecture.md` D5 fix the call shape, and both
constraints are budget constraints rather than preferences:

- **one call per page** — two passes per page costs $2.29 against a $2.00
  ceiling;
- **the page image capped at 1,568 px on the long edge** — an uncapped 2400×3400
  scan costs $1.95 against $1.14 capped.

Neither is a tuning knob. Changing either is a change to a stated constraint and
goes back to the user.

**Every criterion here is mechanical and runs against recorded response fixtures
and a fake client.** No test in this story makes a network call. The live
measurement that used to be AC-8 is now **MT-038** (PO-1 below), so
`required_gates` is empty: the artifact lives under `src/mangatl/translate/**`
and `src/mangatl/pipeline/translate_stage.py`, both of which the required `unit`
and `coverage` gates read via `covers | src/mangatl/**`. Verified against
`bash scripts/gates.sh --list` on 2026-09-18 — see PO-2.

## Acceptance criteria

- **AC-1** — Given a page with N ordered regions carrying Japanese text, when a
  translation request is assembled, then it contains exactly one image block,
  one system block, and one user block listing all N regions by reading index
  and source text.
- **AC-2** — Given a page image of any size, when it is prepared for the
  request, then its long edge is at most 1568 px, its aspect ratio is preserved,
  and its estimated token count (width × height ÷ 750) is recorded on the
  request.
- **AC-3** — Given a page image already smaller than 1568 px on its long edge,
  when it is prepared, then it is **not** upscaled.
- **AC-4** — Given a well-formed response naming every region index, when it is
  parsed, then each region receives its proposed English on the matching region
  id, and no region id is assigned a line belonging to another.
- **AC-5** — Given a response that omits region 3, when it is parsed and stored,
  then region 3's `line.proposed_en` remains **NULL** and the other regions are
  still assigned — the page is not discarded. *(NULL `proposed_en` is what
  "untranslated" means; see C-6. No new column, no schema version bump.)*
- **AC-6** — Given a response naming a region index that does not exist on the
  page, when it is parsed, then `UnknownRegionIndex` is raised naming the bad
  index, and **nothing is written to the store**.
- **AC-7** — Given a page whose regions are all `ocr_empty`, when the stage
  runs, then **no API call is made** and the page completes with no proposed
  lines. *(A page of wordless art must not cost money.)*

### C-1 — `TranslateStage` lives in `pipeline/`, not in `translate/`. Measured.

The story's first draft put it at `src/mangatl/translate/stage.py`. That is
**illegal** and `lint` proves it. This is MT-010 C-1 repeating itself exactly,
for the same two contracts, and it is the trap GREEN would otherwise hit late.

Two import-linter contracts bite at once, and they close from opposite sides:

* the **layers** contract puts `mangatl.translate` *below* `mangatl.pipeline`,
  so a stage in `mangatl.translate` may not import `PageContext` at all;
* the **"Only translate imports anthropic"** contract lists `mangatl.pipeline`
  among its `source_modules` with **no** `allow_indirect_imports`, so a module
  in `mangatl.pipeline` may not import `mangatl.translate` either — not under
  `TYPE_CHECKING`, not inside a function body, because import-linter reports
  those too.

So the stage lives in `pipeline/` and names its collaborator behind a `Callable`
alias whose every half is **stdlib or `domain`** — never `mangatl.translate`.
This mirrors `PageTranscriber` in `pipeline/ocr_stage.py` and `PageDetector` in
`pipeline/detect_stage.py`; read those two modules before writing this one.

```
src/mangatl/pipeline/translate_stage.py
    #: Page image bytes and the page's OCR results in, one result out.
    #: Every half is stdlib or domain. It must NOT name anything in
    #: mangatl.translate - that is the contract C-1 is about.
    PageTranslator = Callable[[bytes, Sequence[OcrResult]], TranslationResult]

    @dataclass
    class TranslateStage:            # implements pipeline.stage.Stage
        translate: PageTranslator
        name: str = "translate"
        def run(self, ctx: PageContext) -> None: ...
        def is_done(self, ctx: PageContext) -> bool: ...
```

**Not `frozen=True`** — MT-035 amendment R-1, measured twice there. `Stage.name`
is declared `name: str`, an instance attribute; a frozen field is *read-only*
and a `ClassVar` is a *class* variable, so neither spelling satisfies the
protocol under mypy `--strict`.

**RED amendment C-1/R-1 — `is_done` is "the page already has a proposal".**
*Reason:* the block gave `is_done`'s signature and not its semantics, and a
stage cannot be built without them. Pinned as:

> `is_done(ctx)` is `True` when **any** region of `ctx.page` carries a non-NULL
> `proposed_en`, i.e. `any(p is not None for p in read_proposed(ordinal))`.

This is not invention, it is the mirror of `OcrStage.is_done` — which C-1 already
tells GREEN to read before writing this module — with the same reasoning one step
along: OCR is done when the page has **lines** and not when it has *regions*,
because a page with regions and no lines is exactly the state a resumed run picks
up at; translation is done when the page has **proposals**, because a page with
lines and no proposals is that state one stage later. A page with no regions is
never done, matching what `DetectStage` and `OcrStage` both decide for it, and
AC-7's all-empty page is therefore re-visited on every resume — which costs
nothing, because `translate_page` makes no call for it (C-5/R-1).
Pinned by `test_translate_stage.py`'s three `is_done` tests.

### C-2 — the value types live in `domain`, and that is forced by C-1.

`PageTranslator`'s return type is named in `mangatl.pipeline`, so it cannot live
in `mangatl.translate`. `domain` is the only layer both `pipeline` and
`translate` may import. And the **"domain is independent"** contract forbids
`domain` from importing `anthropic`, so these are plain values — **not** the
SDK's `Message` or `Usage` objects. Whoever calls the SDK converts at the
boundary.

```
src/mangatl/domain/translation.py
    @dataclass(frozen=True)
    class TokenUsage:
        input_tokens: int
        output_tokens: int
        cache_read_tokens: int
        cache_write_tokens: int

    @dataclass(frozen=True)
    class TranslationResult:
        #: reading index -> proposed English. Sparse: an index absent here is
        #: AC-5's untranslated region. An EMPTY mapping is AC-7's no-call page.
        lines: Mapping[int, str]
        usage: TokenUsage
```

`TokenUsage` carries four plain ints because **MT-012 prices them and rates
change**; a ledger of dollars alone cannot be re-priced (`schema.py`, the
`llm_call` table, which already has exactly these four columns). This story
records them; it does not price them.

### C-3 — `translate/prompt.py`: the image cap and the request.

```
src/mangatl/translate/prompt.py
    MAX_IMAGE_LONG_EDGE_PX: int = 1568
    MAX_OUTPUT_TOKENS: int = 4096
    MODEL_ID: str = "claude-opus-5"

    def prepare_page_image(page_image: bytes) -> tuple[bytes, int]
        # (capped JPEG bytes, est_tokens)

    def build_request(page_image: bytes,
                      ocr_results: Sequence[OcrResult]) -> tuple[dict[str, Any], int]
        # (kwargs for client.messages.create(**kwargs), est_tokens)
```

**RED amendment C-3/R-1 — `build_request` returns `(kwargs, est_tokens)`, not a
bare `dict`.** *Reason: as drafted, AC-2 and C-3 contradict each other and the
contradiction only shows at runtime, against the real API.* AC-2 says the
estimated token count is "**recorded on the request**"; C-3 says the returned
dict is "kwargs for `client.messages.create(**request)`". `est_tokens` is not a
parameter of the Messages API, so a dict carrying it raises `TypeError: create()
got an unexpected keyword argument 'est_tokens'` — and the first run that finds
out is MT-038's, with a credential, after spending money. There is no field on
the API that could carry it either: `metadata` accepts `user_id` only.

The tuple is the module's own existing shape — `prepare_page_image` already
returns `(bytes, est_tokens)` — so this adds no type and no export, and AC-2 is
satisfied in full: the same call that builds the request produces the estimate,
and the estimate describes exactly the image the request carries. Pinned by
`test_the_request_reports_the_estimate_of_the_image_it_actually_carries`, which
decodes the base64 out of the request and recomputes `ceil(w*h/750)` from it.

**RED amendment C-3/R-2 — the image block precedes the text block.**
*Reason:* AC-1 pins the counts and not the order, so without this GREEN has to
guess, and the Anthropic API reference's own vision examples place the image
block before the text block it is about. One line, mechanical, and a request
assembled the other way round is a silent quality change nothing else in the
suite would notice. Pinned by
`test_the_image_block_comes_before_the_text_that_describes_it`.

**`prepare_page_image` takes encoded bytes, not an `NDArray`.** The first draft
said `NDArray[np.uint8]`. Bytes is what `PageTranslator` carries, what
`OcrStage` already reads off disk (`(...source_dir / page.filename).read_bytes()`),
and what keeps `mangatl.translate` from needing numpy at all.

**`build_request` takes no rolling-context parameter.** The first draft had
`context: PageContext`, which (a) collides with `pipeline.stage.PageContext`, a
completely different thing, and (b) cannot exist in this story anyway: AC-1
pins the request at *exactly* three blocks — one image, one system, one user —
with no context block. The previous page's English and the running glossary are
**MT-014**, and MT-014 adds the parameter.

### C-4 — `translate/parse.py`.

```
src/mangatl/translate/parse.py
    class UnknownRegionIndex(Exception)
    def parse_lines(response: Message,
                    region_indices: Sequence[int]) -> dict[int, str]
```

**JSON object keys are strings.** The structured-output response is
`{"0": "...", "3": "..."}`, so `parse_lines` converts keys to `int` and the
returned dict is `int`-keyed. A parser that left them as strings would fail
every lookup silently against an `int`-keyed region list — pin the conversion,
and pin that a non-integer key is an `UnknownRegionIndex` rather than a
`ValueError` escaping from `int()`.

`region_indices` is the page's actual reading indices, `0..N-1`. Any key outside
that set raises `UnknownRegionIndex` naming it (AC-6). `parse_lines` **validates
independently of the response schema**: the schema is the server's job and this
function's contract is its own. AC-6's test feeds a handcrafted fixture, so it
is testable whatever a real model would have done.

**RED amendment C-4/R-1 — the JSON comes out of the first `text` content block,
not out of `content[0]`.** *Reason:* the block said which `Message` goes in and
not where in it to look, and the obvious reading is wrong on the model this story
actually calls. Two facts from the Anthropic API reference, re-read in RED:

* `output_config.format` guarantees a **text** block carrying valid JSON — the
  documented access is `next(b.text for b in response.content if b.type ==
  "text")`;
* C-5 pins `thinking={"type": "adaptive"}`, so a real response may carry a
  **`thinking` block first**, and a thinking block has `.thinking` and no
  `.text`.

So `response.content[0].text` works against every hand-made fixture that has only
a text block and fails against production. The stand-in in `tests/core/conftest.py`
is built to expose exactly that: its thinking block deliberately has no `text`
attribute. Pinned by `test_a_thinking_block_in_front_of_the_json_does_not_hide_it`.

**RED amendment C-4/R-2 — `UnknownRegionIndex` derives from `Exception`
directly, and that is load-bearing.** *Reason:* C-4 requires a non-integer key to
raise `UnknownRegionIndex` "rather than a `ValueError` escaping from `int()`", and
if the type were a `ValueError` subclass no test could tell the two apart.
`UnknownRegionIndex.__bases__ == (Exception,)` is asserted.

### C-5 — `translate/client.py`: the call shape. Settled — read it out.

```
src/mangatl/translate/client.py
    def translate_page(client: Anthropic,
                       page_image: bytes,
                       ocr_results: Sequence[OcrResult]) -> TranslationResult
```

**Verified against the Anthropic API reference on 2026-09-18** (PO-5). Every
claim below held; none is folklore. An agent that "improves" this has changed
the cost model.

- **Model `claude-opus-5`.** Adaptive thinking: `thinking={"type": "adaptive"}`.
  `budget_tokens` is **rejected with a 400** on this model — confirmed.
- **`output_config={"effort": "medium", "format": {...}}`.** `effort` lives
  *inside* `output_config`, not top-level — confirmed. `medium` rather than the
  default `high` because `cost-model.awk` shows the chapter crossing $2.00 at
  3,200 thinking tokens per page.
- **Structured output via `output_config.format`, never prefill.** Assistant
  prefill returns a **400** on Opus 5 — confirmed. The deprecated top-level
  `output_format` parameter is not used.
- **`max_tokens=MAX_OUTPUT_TOKENS` (4096), non-streaming.** `max_tokens` is
  required by the API and the first draft omitted it. 4096 is a ceiling with
  headroom over the cost model's ~700 visible output tokens, and is far below
  the level at which streaming becomes necessary.
- **Prompt caching**: `system` is a **list of one text block** carrying
  `cache_control={"type": "ephemeral"}`. Render order is `tools` → `system` →
  `messages`, so the page image, the region list and (later) the rolling context
  sit in `messages`, *after* the breakpoint. Anything volatile before it
  invalidates the cache for every page.
- **`response.usage` is read on every response** and converted to `TokenUsage`
  (`usage.input_tokens`, `usage.output_tokens`,
  `usage.cache_read_input_tokens`, `usage.cache_creation_input_tokens`). MT-012
  prices it.

The JSON schema in `output_config.format` names the page's actual reading
indices as string `properties` with `additionalProperties: false`, and marks
**none of them required** — AC-5 turns on a compliant model being allowed to
omit one.

**RED amendment C-5/R-1 — AC-7's guard lives in `translate_page`, and a page
that made no call is priced at zero.** *Reason:* AC-7 says "**no API call is
made**", and the only place an API call can be made is here — the client is this
function's parameter and appears nowhere else in the story. A guard in
`TranslateStage.run` instead would leave `translate_page` willing to spend on a
blank page whenever anything else called it, and the stage has no client to count
calls on, so the criterion would not be testable in the form it is written. So:

> When every entry of `ocr_results` is `ocr_empty` — or there are none —
> `translate_page` returns `TranslationResult(lines={}, usage=TokenUsage(0, 0, 0,
> 0))` **without touching `client`**. A page where *any* region read something is
> sent, and `ocr_empty` is the flag it is decided on (MT-010 C-5/PO-3: stored,
> not derived, precisely so this is answerable before a call).

The zero `TokenUsage` rather than `None` is the second half, and it is MT-012's:
a ledger reader that had to unwrap an `Optional` for a case whose value is known
and is zero gets it wrong once and reports a `TypeError` instead of a cost.
Pinned by the five AC-7 tests in `test_translate_client.py` — four asserting
`client.calls == 0`, and one negative control asserting that a one-region page
with text **is** sent, without which "never call the API" would pass every one
of them.

### C-6 — the store: NULL `proposed_en` *is* "untranslated".

AC-5 says a region is "flagged `untranslated`". **That is not a new column.**
`line.proposed_en` is already `TEXT` and nullable, and `schema.py` says so
deliberately: *"NULL `final_en` means unedited ... `proposed_en` too, because
OCR writes `source_ja` before translation exists."* A story that added an
`untranslated` column would need a schema version bump and
`_migrate_to_current`, and would stop being one RED→GREEN cycle.

Two new methods on `store.project.Project`, mirroring `write_lines`/`read_lines`:

```
    def write_proposed(self, page_ordinal: int,
                       proposed: Mapping[int, str]) -> None
    def read_proposed(self, page_ordinal: int) -> tuple[str | None, ...]
```

- A **`Mapping` keyed by reading index**, not a positional `Sequence`, because
  AC-5 needs "region 3 was omitted" to be distinguishable from "region 3 was
  translated as the empty string", and AC-6 needs an index outside the page to
  be *expressible* so it can be rejected.
- `write_proposed` **updates only the rows it names** and leaves every other
  row's `proposed_en` untouched — it never clears the page first. By the time a
  user re-runs a chapter those rows carry translations that cost real money
  (`architecture.md` §4/§6).
- `read_proposed` returns one entry per region ordered by `reading_index`,
  `None` where the column is NULL. This is what AC-5's assertion reads.
- It opens its **own** `transaction()` and therefore refuses a caller that
  already holds one — `Project.transaction()` is not reentrant (MT-005 PO-5),
  so `TranslateStage.run` must not wrap it. `read_proposed` opens none, exactly
  as `read_lines` and `read_regions` open none, so it is usable inside one.

**RED amendment C-6/R-1 — `write_proposed` raises `ValueError` naming an index
the page does not have, and writes nothing.** *Reason:* the block says the
`Mapping` exists so that an index outside the page is *expressible* "**so it can
be rejected**", and a rejection needs a named type; without one GREEN either
invents an exception or — far more likely and far worse — silently drops the
entry, which loses a line the model was paid for and looks identical to AC-5.

`ValueError` and **not** `UnknownRegionIndex`: `mangatl.store` sits *below*
`mangatl.translate` in the layers contract and may not import it. `ValueError` is
also already this module's failure mode for exactly this class of caller mistake
— `write_lines`'s `zip(..., strict=True)` raises it when a result count does not
match the page's region count. The write opens its own transaction, so "nothing
is written" comes free from the rollback; the test asserts it anyway, because a
validate-as-you-go loop would leave half a page translated. Pinned by
`test_an_index_the_page_does_not_have_is_refused_and_nothing_is_written` and
`test_an_index_one_past_the_end_of_the_page_is_refused_too`.

AC-6's own "nothing is written to the store" does **not** depend on this: there,
`parse_lines` raises before any write is attempted at all. This amendment covers
the second door into the same room.

### C-7 — `est_tokens`, and which dimensions it is computed on.

**`est_tokens = ceil(width × height / 750)`, on the *capped* dimensions.**

- **`ceil`, not floor.** Reconciled against `stack.md` §5/O4's published figure:
  a 1568×1098 page gives 1,721,664 / 750 = 2295.552, and `ceil` is **2296**,
  which is exactly the number `stack.md` prints. Floor would give 2295 and
  quietly disagree with the document. `ceil` is also the safe direction for a
  figure the MT-013 budget guard projects with — never under-estimate spend.
- **On the capped dimensions, not the original.** The estimate must describe
  what is actually sent. An implementation computing it before the resize is a
  plausible, entirely silent error that would inflate every projection; AC-2's
  test pins the post-resize value.
- **1568 px** is Claude's documented image long-edge cap: beyond it the image is
  downscaled server-side anyway, so sending more is paying for bytes that are
  discarded.

**AC-3 is the no-upscale case and is not symmetric with AC-2.** An image already
under the cap is returned at its own dimensions. Enumerate at exactly 1568, one
pixel either side, both orientations, and a square.

### C-8 — `TranslateStage` is built but **not wired into `build_stages`**.

PO-6. `pipeline/stages.py` is **unchanged by this story** and `build_stages`
keeps its two-parameter signature. Nothing in AC-1..AC-7 requires the stage to
be in the pipeline's list, and putting it there now would make every existing
end-to-end run spend real money with no ledger (MT-012) and no budget guard
(MT-013) — the precise thing EPIC-04 exists to prevent.

This follows the established precedent rather than inventing one: MT-035 shipped
`DetectStage` and MT-010 shipped `OcrStage`, both correct and neither in any
stage list, until MT-036 wired them. **MT-013 is the wiring story here.**

**Oracle partition — this table goes into the RED dispatch verbatim.**

| AC | Kind | Instruction to RED |
|---|---|---|
| AC-1, AC-4, AC-5, AC-6, AC-7 | **Mechanical** | Recorded response fixtures and a fake client. Pin the request shape and the parse behaviour exactly; assert AC-7 by asserting the fake client was **not called**, which is the only form that catches it. |
| AC-2, AC-3 | **Mechanical** | Arithmetic on dimensions, per C-7. Enumerate at exactly 1568, one pixel either side, both orientations, and a square. |

**Every criterion in this story is mechanical.** There is no oracle-free
criterion left: the one measurement, the old AC-8, is MT-038 (PO-1). So there is
no invented metric here and no negative control of the metric kind — the
negative controls that matter are the two mutations in `## Deferred
verifications`, and both are owned by GATES.

**Do not assert on translation quality in this story.** Quality is S1 and is
measured by MT-022 against a held-out chapter. A test here that asserts a
particular English string against a live model is a test that fails on a model
update for no reason.

**No test in this story makes a network call.** `tests/core` only. A test that
constructs a real `Anthropic` client or reaches for `ANTHROPIC_API_KEY` has left

## Amendments

*All three entries are **PLANNED-phase** changes, made on 2026-09-18 while the
story was being prepared and **before it was dispatched to RED** — the one phase
in which criteria may change freely. They are recorded here anyway because
`check-boundaries.sh` compares the committed criteria against `origin/main`,
where the draft sits, and cannot tell a PLANNED sharpening from a mid-cycle
rewrite. It failed this PR until this section existed, which is the check working
as intended: the rule is "any criteria difference from the base branch carries a
record", not "trust the phase it happened in". **None of the three is a
weakening** — two make a criterion strictly harder to satisfy, and the third
moves one to a story that can actually discharge it.*

### A-1 — AC-5: "flagged `untranslated`" became a named, checkable column state

**It said:**

> Given a response that omits region 3, when it is parsed, then region 3 is
> flagged `untranslated` and the other regions are still assigned — the page is
> not discarded.

**It says:** the same, but *"then region 3's `line.proposed_en` remains **NULL***"*,
with the parenthetical that NULL `proposed_en` is what "untranslated" means and
that there is no new column and no schema version bump.

**Who approved it and why.** The Lead PO at PLANNED (**C-6**), before dispatch.
`untranslated` named no artefact that exists. The `line` table has no such
column, and a test developer reading the draft literally would have added one —
which means `SCHEMA_VERSION`, `_migrate_to_current`, and a story that is no
longer one RED→GREEN cycle. `schema.py` already settles it in the other
direction: *"NULL `final_en` means unedited … `proposed_en` too, because OCR
writes `source_ja` before translation exists."* The amended criterion names a
state a test can read with `read_proposed` and get `None` from. Strictly harder:
the original could have been satisfied by any flag anywhere.

### A-2 — AC-6: "a named error" became `UnknownRegionIndex`, and "nothing is written" was localised

**It said:**

> …then a named error is raised identifying the bad index, and nothing is
> written.

**It says:** *"then `UnknownRegionIndex` is raised naming the bad index, and
**nothing is written to the store**."*

**Who approved it and why.** The Lead PO at PLANNED (**C-4**), before dispatch.
"A named error" is satisfied by any exception with a name, `ValueError`
included, so the criterion could not distinguish a deliberate, catchable failure
from an incidental one — and `int()` raising `ValueError` on a non-integer key is
exactly the incidental failure that would have passed it. "Nothing is written"
did not say *where*; the store is the only place it matters and the only place a
test can check. `test_translate_parse.py` now asserts `__bases__ == (Exception,)`,
so the exception cannot quietly become a kind of `ValueError` either.

### A-3 — AC-8 was removed from this story and became MT-038

**It said:**

> **AC-8** — *(integration)* Given a real API call for one fixture page, when it
> completes, then `response.usage` is recorded, and the story's `## Notes`
> carries the **measured** input, output and thinking token counts, alongside
> the estimates in `docs/wiki/stack.md` §5/O4.

**It says:** nothing — the criterion is gone from MT-011, and
`required_gates: [integration]` became `required_gates: []`. It is
[MT-038](MT-038.md) AC-1, with the credential question attached to it.

**Who approved it and why. Decided by the user on 2026-09-18**, chosen from three
options put to them before RED was dispatched (**PO-1**). The measurement needs a
paid API call. This machine has no `ANTHROPIC_API_KEY`, no `ANTHROPIC_AUTH_TOKEN`
and no `ant` CLI, and the usual escape for a gate that cannot run — record it
BLOCKED and quote the PR's CI run — **does not exist for this one**:
`pyproject.toml` declares the marker as *"`network`: calls a paid API over the
network; never runs on CI"*. So AC-8 was the only criterion in an
eight-criterion story that no required gate and no CI job could ever discharge,
and its only available outcome was a waiver — in the exact place `EPIC-04` says a
waiver is unacceptable (*"An epic that reports 'cost looks fine' without a
measured number has not finished"*). Moving it does not drop it: EPIC-04's story
list and its done-when section were both updated to name MT-038, and MT-038
carries the cache-prefix risk found in PO-5 as its central measurement.

**This is a scope reduction and is called one.** MT-011 now ships seven
mechanical criteria, all covered by the required `unit` and `coverage` gates —
confirmed by `gates.sh` itself printing *"6 changed source path(s), all exercised
by a required gate"*.

**What the tests do NOT constrain** — yours to choose:

- the wording of the system prompt, and the layout of the user block. The only
  claims are: each region's `source_ja` appears **exactly once**, each reading
  index appears as a decimal string, and the source texts appear in reading
  order. Bullets, a table, YAML, JSON — all pass;
- any `description`, `title` or extra key inside the JSON schema beyond the four
  asserted;
- whether `prepare_page_image` uses Pillow, which resample filter it picks, and
  what JPEG quality it encodes at. Only the **format** and the **dimensions** are
  read, and the dimensions are read with a standard-library SOF/IHDR parser, not
  with a decoder that shares your assumptions;
- how the short edge is rounded. The long edge is pinned to 1568 exactly; the
  short edge is required to be `floor` or `ceil` of the exact scale, and the two
  exact-ratio cases (2352x1647 → 1568x1098, and every square) are pinned to the
  integer;
- the file layout below each imported module, and any private helper;
- whether `TranslateStage.run` short-circuits on an all-empty page. It may; the
  guard that AC-7 is about lives in `translate_page` (C-5/R-1), and the stage
  tests only assert the store afterwards.

### The response stand-in (`tests/core/conftest.py`)

`parse_lines` and `translate_page` are handed a duck, not an
`anthropic.types.Message`, because no test here makes a network call. It is
faithful in the two ways that decide the implementation:

- **structured output puts the JSON in a `text` content block.** Read it as
  `next(b.text for b in response.content if b.type == "text")`;
- **adaptive thinking may put a `thinking` block in front of it**, and a thinking
  block has `.thinking` and **no** `.text`. `FakeThinkingBlock` deliberately has
  no `text` attribute, so `response.content[0].text` raises `AttributeError`
  naming it rather than silently reading `""`.

`usage` is `FakeUsage(input_tokens, output_tokens, cache_read_input_tokens,
cache_creation_input_tokens)` — the SDK's four names, which `client.py` converts
to `TokenUsage`'s four.

### Choices the tests left open, and which way they went

- **PO-11 honoured: an `ocr_empty` region is listed in the user block with empty
  source text, and appears in the schema's `properties` like any other.** The
  schema is built from `range(len(ocr_results))`, so no region is filtered out
  anywhere; the system prompt tells the model that an empty entry is an OCR miss
  it should read off the art, and that a region it genuinely cannot read should
  be left out rather than guessed at. That is `stack.md` §5/O3's safety net
  stated to the model rather than merely relied on.
- **The user block is `[index] source text`, one region per line**, prefaced by
  one sentence naming the reading order. No region's text is repeated anywhere
  in the block, which is what `count(...) == 1` needs.
- **`prepare_page_image` uses Pillow, LANCZOS, JPEG quality 85**, and rounds the
  short edge with `round()` — inside the `[floor, ceil]` band the tests allow,
  and exact on the two exact-ratio cases. It **re-encodes to JPEG even when the
  page is already within the cap**, because the request's `media_type` says JPEG
  and the caller hands over whatever was in the scans folder.
- **`Project.write_proposed` is a plain `UPDATE line SET proposed_en = ?`**, not
  an upsert. It cannot touch `source_ja`, `ocr_empty` or `final_en` by
  construction, and it never clears the page. Every index is validated **before**
  the first write, so "nothing is written" does not rest on the rollback alone.
  A region with no `line` row yet is a state the pipeline cannot reach —
  `TranslateStage.run` builds its input from `read_lines` — so the `UPDATE`
  matching no row is not given a branch, and inventing a `source_ja` for it
  would be storing a transcription nobody made.
- **`TranslateStage.run` opens no transaction**, so `write_proposed`'s own is
  the only one; `read_proposed` opens none, so `is_done` is callable from inside
  one.

**PO-11 — a page with *some* `ocr_empty` regions: the empty regions ARE sent,

other.** No AC covers this, so no test in this story pins it; it is guidance for
GREEN, recorded here rather than discovered later.
