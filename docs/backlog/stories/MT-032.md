## Context

**Filed 2026-09-13, out of two sessions working this repository on the same day.**
Separate from [[MT-031]], which is about the phase guard misparsing paths. This
story is about **harness state read while something else is writing it**.

The harness keeps its state in one place per tree — `.claude/state/current-story.env`
names one story, `last-gate-run` records one run, `gates.sh` writes
`## Gate results` into whatever story `current-story.env` names. Every one of
those is correct for one thing at a time, and **nothing in the harness enforces
one thing at a time**.

**The scope is wider than "two Claude sessions", and that widening is the point.**
The obvious reading is that this only bites an unusual configuration. It does
not: an orchestrator that dispatches a subagent and then runs a script is *two
things in one tree*, and that is the ordinary shape of every phase in this
harness. The concrete instance below needed no second session.

## The three failures, ranked by whether anything catches them

### F-1 — an inconsistent gate summary. **Nothing catches this.** Highest priority.

`gates.sh` parses `.claude/harness/project.conf` into its `evidence`/`floor`
tables **once at start-up** (`scripts/gates.sh`, the table-building block around
lines 76–102), then runs the gate commands afterwards. Anything editing
`project.conf` or the files a gate reads, in between, produces a summary whose
numbers are each real and whose **pairing never existed**.

Observed by `manga-translator-8e` during MT-003's GREEN, running
`gates.sh --fast` while its own feature-developer subagent was mid-write. It
had checked `git status` first and seen a clean tree, which is why it judged the
run safe:

```
PASS  lint (1s, observed 5, floor 1)
PASS  unit (1s, observed 25, floor 12)
```

`[MEASURED — manga-translator-8e, 2026-09-13, MT-003 in GREEN. Not this
author's measurement.]`

`observed 5, floor 1` is the tell: the floor was read from `project.conf` as `1`
at start-up while the subagent was writing `5` into it, and the five contracts
were counted out of a `pyproject.toml` the subagent had just finished.

**The mechanism is confirmed independently** — `project.conf` is parsed into
`FLOORS` at load and the gate commands run later, so the interleaving is
reachable by construction; and `floor | lint | 5` is the value in the file now,
consistent with a read that caught it mid-write. `[MEASURED — this author,
reading `scripts/gates.sh` and `.claude/harness/project.conf`, 2026-09-13]`

**Why this one matters most: it has no backstop.** A `--fast` run is never
recorded, so nothing downstream compares it to anything. Its only consumer is a
human or an agent reading the summary and deciding the phase is healthy. Had
that summary been taken as the GREEN verdict, it would have recorded a pass
whose floor line no longer existed.

### F-2 — a gate record written into a story its author never ran. **Fails loudly at PR time.**

`gates.sh` writes `## Gate results` into the story named by `current-story.env`,
which is global to the tree rather than to the caller. A second session — or a
script run from the wrong context — can therefore stamp a record into a story it
is not working on.

**Do not over-claim this one.** The record carries a hash of the tree the gates
ran against, and `check-boundaries.sh` refuses a PR where that hash does not
match the code being merged. A record written against a half-edited tree
therefore **mismatches and fails the PR loudly**; it does not sail through. The
residue is misdirection and wasted time, not a false green.

### F-3 — the Stop hook's reminder addresses the wrong session. **Cosmetic.**

`.claude/hooks/gate-reminder.sh` reads `current-story.env` without any notion of
which session is asking, so a session with no active story of its own is told to
gate someone else's. This is how the whole class was noticed: it fired at this
author about MT-003, a story belonging to another session, which correctly
declined to run gates that would have written into a story file being edited.

## Acceptance criteria

- **AC-1** — Given `project.conf` is modified after `gates.sh` has parsed it and
  before its gate commands finish, when the run completes, then it **fails or
  warns** rather than printing a summary pairing a stale floor with a fresh
  observation. Re-reading the file and comparing, or hashing it at start and
  end, both satisfy this; printing an inconsistent pair does not.
- **AC-2** — Given the same interleaving, when the run completes, then the
  summary **says the configuration changed under it**, naming the file. A silent
  pass is the failure being fixed.
- **AC-3** — Given `gates.sh` is invoked while `current-story.env` names a story
  whose branch is **not** the current checkout, when it would write
  `## Gate results`, then it **refuses and says so** rather than writing.
  *`phase.sh set` already refuses on a branch mismatch; `gates.sh` does not, and
  the two should agree.*
- **AC-4** — Given the gate-reminder Stop hook fires when `current-story.env`
  names a story whose branch is not the current checkout, then its message
  **says so** instead of instructing the reader to gate a story they are not on.
- **AC-5** — Given a `--fast` run, when it completes, then its output states
  plainly that it is **not recorded and not a verdict**. *It already says "a
  partial run is not evidence of anything"; AC-5 is satisfied only if that line
  survives the AC-1 change and is not weakened.*

### C-0 The fix is detection, not locking — carried over from the story as filed

Do **not** add a lockfile or a mutex that serialises agents. The harness's
concurrency is a fact of how it is used — an orchestrator that dispatches a
subagent and then runs a script is two things in one tree — and a lock an
orchestrator can deadlock against its own subagent is worse than the race. Every
criterion here is satisfiable by *noticing* the interleaving and saying so.

This clause was the whole of the original `## Contract` alongside the file list,
and it is reproduced verbatim in substance because the blocks below expand that
section rather than replace it.

### C-3 AC-1 and AC-2: hash the conf, fail, name the file

Pin the mechanism, because AC-1 offers two and a guess here is how AC-5 regresses.

- Hash `.claude/harness/project.conf` immediately **after** the table-parsing
  block, and again immediately **before** the gate summary is printed.
- If the two differ, the run **FAILS** — not warns. AC-1 permits either; `FAIL`
  is chosen because this is the failure with **no backstop** (a `--fast` run is
  never recorded, so nothing downstream ever compares it), and because a WARN
  leaves `gates.sh && next-thing` proceeding on a summary the script has just
  said it cannot vouch for. The harness already refuses to call a vacuous gate a
  pass; this is the same judgement.
- The message **names the file** (AC-2) and says the summary's pairings may not
  correspond to any single state of it. Do not print the stale numbers as though
  they were fine and add a footnote.
- **The check runs in every mode, `--fast` included.** F-1 was observed on a
  `--fast` run. A check that only runs in full mode fixes nothing that was
  actually reported.
- Scope is `project.conf` and nothing else. "The files a gate reads" is out of
  scope — that is the tree hash's job, and widening it here would fire on every
  ordinary edit during a long `build`.

**Amended by RED, 2026-09-14 — the wording is pinned, because a test has to
assert it.** C-3 said "names the file" and "says the pairings may not
correspond"; an assertion needs literal text, and inventing it in GREEN after
RED asserted something else is a round trip for nothing. The tests in
`.claude/tests/gates.test.sh` pin exactly three substrings, and GREEN is free
in every other respect:

```
FAIL         config: .claude/harness/project.conf changed while the gates were running
```
```
may not correspond to any single state
```

`FAIL` + nine spaces is the existing `results` line format (`FAIL         changes: …`
at `scripts/gates.sh` ~line 597), so the cheapest implementation is another
pseudo-gate line appended to `results` with `fails=$((fails+1))` — which gets
exit 1, `RESULT=fail` in the stamp and "N required gate(s) failed" for free, and
lands *inside* the summary block rather than after it.

**What RED deliberately did NOT constrain**, so it stays GREEN's choice: whether
the per-gate `PASS lint (0s, observed 5, floor 1)` line is still printed
alongside the failure. The anti-footnote requirement is asserted as the run not
printing `All required gates passed` and exiting non-zero, which is the part
that misleads a reader. Also unconstrained: the behaviour under `--list` and
`--audit`, which run no gate commands.

### C-4 AC-3: refuse the story write, keep the run

- Compare the **story file's frontmatter `branch:`** against
  `git branch --show-current`, the same pair `phase.sh`'s `guard_transition`
  compares (`scripts/phase.sh` ~line 96).
- On mismatch: **refuse to write `## Gate results`**, print a line naming both
  branches, and leave the gates' own verdict and exit status untouched. The run
  was valid; the *recording* is what is misdirected.
- **Still write `.claude/state/last-gate-run`.** It is machine-local, it is what
  the Stop hook reads, and suppressing it would make the hook claim the gates
  had never run. `.claude/tests/gates.test.sh:473–490` asserts the stamp's
  contents and must keep passing unchanged.
- **Detached HEAD or no branch: do not refuse.** `phase.sh` guards with
  `[ -n "$cur" ]` and this must agree — fail open, as the harness does
  everywhere it cannot tell.
- `--story <id>` names the story explicitly; the comparison is still against
  that story's own frontmatter `branch:`, so an explicit `--story` on the wrong
  branch is refused too. It is not an override.

**Amended by RED, 2026-09-14 — the refusal line is pinned, and one factual
claim in this block is corrected.**

1. **The wording.** `.claude/tests/gates.test.sh` asserts this substring, with
   the two branch names substituted:

   ```
   not recorded: the checkout is on 'unrelated-session' but story T-1 belongs on 'story/T-1-fixture'
   ```

   It sits where the other `(not recorded: …)` lines already are, in the record
   block at `scripts/gates.sh` ~line 682. Nothing else about the line is pinned.

2. **`phase.sh` does *not* fail open on a detached HEAD, contrary to this
   block's parenthetical.** `[MEASURED — RED, 2026-09-14, throwaway fixture]`:

   ```
   detached: show-current=[]  abbrev=[HEAD]
   ```

   `guard_transition` uses `git rev-parse --abbrev-ref HEAD`, which prints the
   literal string `HEAD` when detached — non-empty, so `[ -n "$cur" ]` passes
   and `phase.sh set` *refuses* on a detached HEAD, telling you to check out a
   branch. The requirement C-4 states is unaffected and unambiguous:
   `gates.sh` uses `git branch --show-current`, which is empty when detached,
   and does not refuse. The two scripts therefore differ on this one case; that
   is a deliberate, recorded divergence rather than the accidental agreement the
   parenthetical claimed. Bringing `phase.sh` into line is out of scope for this
   story and belongs in its own, if anyone wants it.

### C-5 AC-4: say it, and stop blocking a session that is not on the story

- When the story's branch does not match the checkout, `gate-reminder.sh`
  **warns instead of blocking**, and the message names both branches.
- This is a behaviour change beyond "the message says so", and it is
  deliberate: measured, the hook today *blocks* — `{"decision":"block"}` — a
  session on `master` and tells it to gate a story belonging to

  story is not cosmetic, and leaving it as a block while merely improving the

- The branch-matching case is untouched: block exactly as it does today.

**Amended by RED, 2026-09-14 — where the hook reads "the story's branch", and
what the fixture had to be told.**

1. **The source of the branch is left to GREEN, on purpose.** Two are available:
   `BRANCH` from `load_state` (the hook already calls it), and the story file's
   frontmatter `branch:` (what C-4 pins for `gates.sh`). `phase.sh set` writes
   the first *from* the second, so they agree in practice, and the hook can run
   in a tree where the story file is missing. `.claude/tests/gate-reminder.test.sh`
   makes both agree in the fixture, so the assertions hold under either choice.
   If GREEN reads the frontmatter, it must fail open when the story file is
   absent — silence there is the same "cannot tell" case as a detached HEAD.

2. **The fixture in `gate-reminder.test.sh` had the mismatch all along, and

   written `BRANCH=story/T-1-fixture` while `git init` left the fixture on

   have turned into a warn — for a reason none of them is about. RED aligned the
   checkout with the state the fixture already claimed; see `## Regressions`.

3. **Pinned wording: none.** The tests assert only that the warn names both
   branch names (`story/T-1-fixture` and the checkout's). What the sentence
   around them says is GREEN's.

4. **Not constrained:** what the hook does on a mismatched branch in a case
   where it would have been *silent* anyway (GREEN, a fresh passing run). AC-4
   and C-5 are about the blocking paths; warning there too would be defensible

### C-8 How the race is made deterministic in a test

Measured by the orchestrator, and the reason this story is testable at all
without sleeps or a second process: **a gate command in the fixture can edit
`project.conf` itself.** `gates.test.sh` gate commands are `printf`s, so:

```
gate | lint | required | . | printf 'Contracts: 5 kept\n'; printf 'floor | lint | 5\n' >> .claude/harness/project.conf
```

reproduces F-1 exactly, every time, with no timing dependence. Use this; do not
write a test that races two processes.

## Test plan

Written by the Test Developer, 2026-09-14, phase RED. Two suites, both already
existing; no new file. Every gate command is a `printf`, so the suites test the
harness machinery rather than any toolchain.

**Level.** All of it is integration against the real scripts, run inside a
throwaway fixture repository by `.claude/tests/_lib.sh`. There is no lower level
available: `gates.sh` and `gate-reminder.sh` are shell scripts with no seams, and
the behaviour under test — "a value read at start-up no longer matches the file",
"the checkout is not the story's branch" — only exists when the whole script
runs. Nothing here is end-to-end in the expensive sense: the fixture is a
`mktemp -d`, the gates are `printf`s, and both suites finish in well under a
minute of actual work.

**Why no test races two processes.** C-8, and it is the reason this story is
testable at all. A fixture's own gate command can edit `project.conf`:

```
gate | lint | required | . | printf 'Contracts: 5 kept\n'; printf 'floor | lint | 5\n' >> .claude/harness/project.conf
```

That is the same interleaving F-1 was observed on, with the timing removed. It
is deterministic, needs no sleep and no second process, and reproduces the exact
pairing `manga-translator-8e` reported. Re-measured by RED before writing a line
of test: `PASS lint (0s, observed 5, floor 1)`, exit 0, with `floor | lint | 5`
on disk.

**Zero / one / many, boundaries, errors.** The interesting partition here is not
cardinality but *which mode and which verdict*: full and `--fast`; a passing run
and an already-failing one; a branch that matches, one that does not, and no
branch at all. All six combinations that can differ are covered. The two that
cannot — `--list` and `--audit` run no gate commands, so nothing can change
under them — are left unasserted and said so in C-3.

| Block | AC | What it pins |
|---|---|---|

Two blocking paths rather than one, deliberately: a fix applied to a single

### Out of scope, pinned where it was cheap

`## Out of scope` rules out a lockfile and any per-session state directory.
Nothing here asserts a lock's absence — a negative like that is untestable
without naming an implementation — but the DV-2 control does the useful half:
an ordinary run, in both modes, must be **unchanged**. A fix that serialised
anything would show up there first.

### One thing that should change the implementation approach

The `changes:` check at `scripts/gates.sh` ~line 569 already does exactly the

### What a reviewer should look at sceptically

1. **`cksum` is a CRC, not a cryptographic hash.** Two different manifests can
   collide. The threat here is an accidental interleaving, not an adversary, and
   a collision means one missed detection rather than a false accusation — but
   if that trade is not wanted, `sha1sum`/`shasum` is a one-line change, and the
   reason it was not taken is portability (`rules.md`: bash, awk, coreutils).
2. **An edit that is reverted before the summary is not detected.** The check
   answers "is the file I parsed still the file on disk", not "was it ever
   different in between". A conf edited to X and restored byte-for-byte during
   the run passes. Deliberate: the alternative is watching the file, which needs
   a second process — and the summary in that case does describe the file as it
   stands.
3. **The window between the table parse and the first fingerprint is not
   covered.** C-3 says "immediately after the table-parsing block", and this is
   immediately after it; an edit landing inside those few microseconds is
   invisible. Stated rather than hidden.
4. **The gate loop re-reads `$CONF` itself** (`done < "$CONF"` at the bottom of
   the loop), so a mid-run edit can change *which gates run*, not only which
   floors are reported. The fingerprint catches that case too — it is a
   difference like any other — but nobody should read this check as covering
   only the floors.
5. **The check also fires on `--gate` and `--required`**, which no assertion
   covers: C-3 pins "every mode, `--fast` included" and those two run gate
   commands as well, so excluding them would have been the odd choice. `--list`
   and `--audit` exit before it, as C-3 leaves unconstrained.
6. **A new non-zero exit path is a new way for CI to fail** (`## Callers`). It
   fires only when `.claude/harness/project.conf` changes between two points
   inside one `gates.sh` process. Nothing in `.github/workflows/gates.yml` or
   `scripts/ci-local.sh` writes that file; the DV-2 controls and the real
   `--fast` run above are the evidence. If a future step ever generates
   `project.conf`, this check is what will find out.
7. **AC-3 makes `## Gate results` absent where it used to be present.**
   `check-boundaries.sh` already fails on a missing record, which is the correct
   loud outcome — but it is a behaviour change in a script CI depends on, and it
   is worth a reviewer's second look at the one place it could bite: a run made
   deliberately from a detached HEAD still records, by design (C-4), and
   `phase.sh` refuses that same case. The divergence is recorded in C-4's RED
   amendment and was reproduced by the orchestrator.
8. **The hook's warn is long, and a runner that does not surface
   `systemMessage` drops it.** That is the pre-existing shape of `warn()` and
   this change did not alter it: the object carries no `decision`, so the stop
   proceeds either way. The consequence of C-5 is that a session on another
   branch *may* now stop with nothing said, where before it was stopped with
   something said. That is the trade AC-4 and PO-3 asked for.
