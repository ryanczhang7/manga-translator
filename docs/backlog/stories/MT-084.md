## Context

Filed by the EPIC-04 mutation audit,
`docs/wiki/audits/EPIC-04-2026-10-13.md`: survivors CL2, P7 and CL5
(`## Decided` item 5, `## Evidence` E-2).

The Claude path (`translate/client.py`, `translate/parse.py`) is reachable
whenever `ANTHROPIC_API_KEY` is set. It is not v1's default (MT-077 PO-1: v1
is Gemini-only), which is why this ranks below MT-082 and MT-083. The Gemini
adapter already pins its counterparts (GM1 to GM5 are killed). Three claims
the Claude adapter makes are not pinned:

- **CL2.** MT-044 C-5 says the ledger records "the model that actually served
  the request". `client.py:97` reads `response.model`. Changing it to the
  *request's* model leaves every test green, because the fake's default model
  (`tests/core/conftest.py:266`, `_FAKE_MODEL_ID = "claude-opus-5"`) equals
  `prompt.MODEL_ID`, and no test overrides it.
- **P7.** `first_text_block` (`parse.py:88`) returns the first block whose
  `type == "text"`. Changing that to "the first block that is not `thinking`"
  leaves every test green, because the only non-text block any fake builds is
  `FakeThinkingBlock`. `anthropic` 0.125.0's content union also includes
  `RedactedThinkingBlock` (fields `data` and `type`, **no `text`**), so the
  mutant would raise `AttributeError` on a real response that leads with one,
  and lose a paid page.
- **CL5.** `client.py:116` maps an absent `cache_creation_input_tokens`
  (`None`) to 0, "the zero it means". No test builds a usage with that field
  `None`, so `or 1` survives.

**Settled:** these three are unprotected; the code is correct. **Evidence, to
verify:** the mutant commands, and that `RedactedThinkingBlock` carries no
`text` in the installed SDK.

## Acceptance criteria

- **AC-1 (CL2)**: Given a response whose `model` differs from the model the
  request asked for (for example a dated snapshot id such as
  `"claude-opus-5-20261001"`), when `translate_page` returns, then
  `result.call.model_id` is the **response's** model. Fails under CL2.
- **AC-2 (P7)**: Given a response whose content starts with a
  `redacted_thinking` block (no `text` attribute) and then the JSON text
  block, when it is parsed, then the lines are read from the text block and
  nothing raises. Fails under P7.
- **AC-3 (CL5)**: Given a response whose usage has
  `cache_creation_input_tokens=None` and `cache_read_input_tokens=None`, when
  `translate_page` returns, then `result.usage.cache_write_tokens == 0` and
  `result.usage.cache_read_tokens == 0`. Fails under CL5.
