## Context

`architecture.md` D6: budget enforcement is a domain rule, not a warning. The
brief calls "under $2 per ~20-page chapter" a hard budget, and
`docs/wiki/cost-model.awk` shows a plausible adaptive-thinking volume (3,200
tokens per page) crossing it. This story is what makes an unverified estimate
**safe** rather than expensive.

The decisive design point: the guard runs **before** the call, on a projection,
not after it on a total. A guard that notices the overrun after paying for it has
not guarded anything.

**This story is the arithmetic, and only the arithmetic** (PO-1, decided by the
user on 2026-09-21). It builds one pure domain module: the projection, the
comparison against the ceiling, and the basis it reports. Putting that guard
into the running pipeline — wiring `TranslateStage` into `build_stages`,
recording calls into the ledger, emitting the abort — is **MT-044**, which
`depends_on` this story. See `## Amendments` for why the split happened and
`## Notes` PO-1 for what it costs.

**Which required gate would fail if this story's artifact broke:** `unit`,
`coverage` and `coverage-core` — `src/mangatl/domain/**` is read by all three
and all three are `required`. Verified against `bash scripts/gates.sh --list` on
2026-09-21; see `## Notes` → "Required gates".

- **AC-1** — Given a chapter ceiling of $2.00, $1.95 already spent, and a
  projected next-call cost of $0.06, when the guard is consulted, then it
  **refuses** and names the projection, the spend and the ceiling.
- **AC-2** — Given the same state and a projected next-call cost of $0.05, when
  the guard is consulted, then it permits — the comparison is against the
  ceiling, inclusive, and $1.95 + $0.05 = $2.00 ≤ $2.00.
- **AC-5** — Given a chapter with fewer than two priced calls, when a projection
  is requested, then it uses the configured per-page estimate rather than an
  extrapolation from one sample, and says which it used.
- **AC-6** — Given a chapter with five priced calls, when a projection is
  requested for the sixth, then it is the mean of the observed per-page costs,
  and the projection for the *whole remaining chapter* is that mean times the
  remaining page count.
- **AC-7** — Given a ceiling of $0.00, when the guard is first consulted, then
  it refuses — the projection for the first page already exceeds the ceiling, so
  no call is ever permitted.
- **AC-8** — Given a `Budget` constructed with no explicit ceiling, when a
  projection is checked against it, then the ceiling is `DEFAULT_CEILING`, which
  is $2.00.

## Contract

**RED may amend any block in this section, in place, with a reason, and GREEN
then builds what the amended block says.** That is the point of pinning it: the
contract is a working agreement RED is expected to sharpen, not a second set of
frozen criteria. The acceptance criteria above are frozen and change only
through `## Amendments`; nothing here is.

```
src/mangatl/domain/budget.py
    DEFAULT_CEILING: Usd                 # $2.00
    BOOTSTRAP_PAGE_ESTIMATE: Usd         # $0.06 — from cost-model.awk, design A
    MIN_SAMPLES_FOR_PROJECTION: int = 2

    @dataclass(frozen=True) Projection:
        next_call: Usd
        remaining_chapter: Usd
        basis: Literal["estimate", "observed"]
        sample_count: int

    @dataclass(frozen=True) Decision:
        permitted: bool
        reason: str | None
        spent: Usd
        ceiling: Usd
        projection: Projection

    class Budget:
        def __init__(self, ceiling: Usd = DEFAULT_CEILING) -> None
        def project(self, priced_calls: Sequence[Usd],
                    pages_remaining: int) -> Projection      # RED-A2
        def check(self, spent: Usd, projection: Projection) -> Decision
```

**Semantics behind each number:**

- **The comparison is `spent + projection.next_call <= ceiling`.** Inclusive, so
  landing exactly on the ceiling is permitted. AC-1 and AC-2 sit one cent either
  side of it deliberately: a strict-versus-inclusive slip is invisible in review
  and changes behaviour on exactly one input.
- **`BOOTSTRAP_PAGE_ESTIMATE` is $0.06**, which is $1.14 ÷ 20 rounded up to the
  cent (`docs/wiki/cost-model.awk`, design A). It is used only until
  `MIN_SAMPLES_FOR_PROJECTION` real calls exist. **Rounding up is deliberate**:
  an estimate that errs low is an estimate that lets a run start it cannot
  finish.
- **`MIN_SAMPLES_FOR_PROJECTION = 2`** because one page is not a sample — a
  single wordless page would project the whole chapter at nearly zero and
  disable the guard for the pages that follow.
- **`basis` is reported, not inferred.** MT-018 shows the user "projected $1.30
  (estimated)" versus "(from 5 pages)", and those are different claims.
- **The default ceiling is a default *argument*, not a lookup** (A-3). `Budget()`
  is $2.00. Where a real ceiling comes from is MT-044's question, and this
  module must not import anything from `store` — the `domain is independent`
  import-linter contract forbids it (`pyproject.toml:215`, whose
  `forbidden_modules` includes `mangatl.*`).
- **All arithmetic is exact.** `Usd` wraps a `Decimal` and `Usd.micro()` is the
  one place rounding happens, `ROUND_HALF_UP` (MT-012 PO-4). AC-6's *mean* is
  the first division this product performs on money: **RED must pin what happens
  when five costs do not divide by five.** The contract's position is that
  `project` rounds the mean **up** to the micro-dollar, for the same reason
  `BOOTSTRAP_PAGE_ESTIMATE` rounds up — under-projecting is the failure that
  costs money — but this is exactly the kind of block RED should amend if
  writing the test shows a better answer.
- **`Usd` has no division today** and `sum()` does not work on it: MT-012 gave
  `__add__` no `isinstance` guard, so folding needs
  `functools.reduce(operator.add, ...)`. **RED-A1 (below) closes the question of
  whether to add one: do not.**

### Contract amendments made in RED, 2026-09-21

*Authorised by the orchestrator on the same turn that resolved A-4. These are
`## Contract` amendments — the working agreement RED is expected to sharpen —
and neither touches an acceptance criterion.*

- **RED-A1 — `Usd` is not to be extended. GREEN must not add `__truediv__`,
  `__mul__` or any other method to `domain/money.py`.** The bullet above used to
  say extending was permitted, quoting `money.py`'s docstring. It is permitted
  and it is still the wrong move, for a reason the contract did not weigh:
  `domain/money.py` sits inside `coverage-core`'s `--cov-fail-under=100` with
  **branch coverage on**, and no acceptance criterion in this story covers a
  division or a multiplication *on `Usd`* — only the projection's value. A new
  dunder would therefore arrive with behaviour (a zero divisor, a negative
  operand, a non-`Usd` operand, `NotImplemented`) that nothing here specifies and
  that the 100% bar nonetheless demands be reached. That is how `money.py` grew a
  defensive branch it could not cover, which is exactly what its own docstring
  and `events.py`'s warn against.

  **It is also unnecessary.** Every figure this story needs is expressible with
  the existing API, because a `Usd` that came from the ledger is already a whole
  number of micro-dollars (`rates.price` returns `Usd.from_micro(exact.micro())`):

      total    = functools.reduce(operator.add, priced_calls)   # exact Decimal
      mean_mic = -(-total.micro() // len(priced_calls))          # integer ceiling
      next_call        = Usd.from_micro(mean_mic)
      remaining_chapter = Usd.from_micro(mean_mic * pages_remaining)

  `-(-a // b)` is integer ceiling division: exact, no `Decimal` context, no
  rounding mode, no float. GREEN is free to reach the same *values* another way —
  the tests assert values, not mechanism — but not by widening `Usd`.

- **RED-A2 — `spent` is dropped from `project`.** The signature block above is
  amended to `project(self, priced_calls, pages_remaining) -> Projection`. Under
  A-4's resolution the parameter is genuinely dead: a `Projection` is
  `next_call`, `remaining_chapter`, `basis` and `sample_count`, and not one of
  the four depends on prior spend. The spend enters at `check(spent, projection)`,
  which is the correct seam — it is the *comparison* that needs it, not the
  extrapolation. Keeping it would invite GREEN to make the projection depend on
  the spend, which no criterion asks for and which would make AC-6's mean a
  function of history.

  **Lint would not have caught it.** `pyproject.toml:108` selects
  `["E", "F", "I", "UP", "B", "SIM", "RUF"]`; **`ARG` is not selected**, so
  `ARG002 unused-method-argument` does not run and a dead parameter would have
  shipped silently through the `lint` gate. Verified 2026-09-21.

**Oracle partition: entirely mechanical.** Every criterion is arithmetic with a
stated right answer. Read the numbers out; do not calibrate anything. The
judgements in the story are already made above (inclusive comparison, round up,
two samples) and are recorded here so RED does not re-decide them. The one open
question the contract deliberately left to RED — the rounding of AC-6's mean —
is now **closed: round up**, pinned by a fixture on which round-up,
round-half-up and truncation give three different answers (`## Test plan`).

### What should change the implementation approach

1. **Do not extend `Usd`** — RED-A1, above. The four-line recipe there produces

2. **`Usd.__str__` truncates to four places.** Build the refusal message from

   asserted *value* from a rendered string.
3. **`sum()` does not work on `Usd`** — `__add__` has no `isinstance` guard and

   or sum `.micro()` integers.

   `warn_unreachable`; a zero ceiling, an empty `priced_calls` and a zero
   `pages_remaining` all fall out of the arithmetic without a special case. Note
   that the estimate branch (`n < 2`) already protects `reduce` from ever seeing
   an empty sequence, so no guard is needed for that either.
