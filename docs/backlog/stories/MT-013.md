## Context

`architecture.md` D6: budget enforcement is a domain rule, not a warning. The
brief calls "under $2 per ~20-page chapter" a hard budget, and
`docs/wiki/cost-model.awk` shows a plausible adaptive-thinking volume (3,200
tokens per page) crossing it. This story is what makes an unverified estimate
**safe** rather than expensive.

The decisive design point: the guard runs **before** the call, on a projection,
not after it on a total. A guard that notices the overrun after paying for it has
not guarded anything.

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage-core` — the projection and the comparison are `domain`.

## Acceptance criteria

- **AC-1** — Given a chapter ceiling of $2.00, $1.90 already spent, and a
  projected next-call cost of $0.06, when the guard is consulted, then it
  **refuses** and names the projection, the spend and the ceiling.
- **AC-2** — Given the same state and a projected next-call cost of $0.05, when
  the guard is consulted, then it permits — the comparison is against the
  ceiling, inclusive, and $1.95 ≤ $2.00.
- **AC-3** — Given a refusal, when the run ends, then it emits
  `RunAborted(reason="budget")` naming the page it stopped before, and every
  page already translated is persisted with its lines intact.
- **AC-4** — Given a refusal, when the ledger is read, then **no `llm_call` row
  exists for the refused page** — the call was never made.
- **AC-5** — Given a chapter with fewer than two priced calls, when a projection
  is requested, then it uses the configured per-page estimate rather than an
  extrapolation from one sample, and says which it used.
- **AC-6** — Given a chapter with five priced calls, when a projection is
  requested for the sixth, then it is the mean of the observed per-page costs,
  and the projection for the *whole remaining chapter* is that mean times the
  remaining page count.
- **AC-7** — Given a ceiling of $0.00, when a run starts, then it refuses before
  the first call, rather than making one call and then stopping.
- **AC-8** — Given `budget_ceiling_usd` absent from settings, when the guard is
  constructed, then the ceiling is $2.00.

## Contract

```
src/mangatl/domain/budget.py
    DEFAULT_CEILING: Usd                 # $2.00
    BOOTSTRAP_PAGE_ESTIMATE: Usd         # $0.06 — from cost-model.awk, design A
    MIN_SAMPLES_FOR_PROJECTION: int = 2

    @dataclass(frozen=True) Projection:
        next_call: Usd
        remaining_chapter: Usd
        basis: Literal["estimate", "observed"]
        sample_count: int

    @dataclass(frozen=True) Decision:
        permitted: bool
        reason: str | None
        spent: Usd
        ceiling: Usd
        projection: Projection

    class Budget:
        def __init__(self, ceiling: Usd) -> None
        def project(self, spent: Usd, priced_calls: Sequence[Usd],
                    pages_remaining: int) -> Projection
        def check(self, spent: Usd, projection: Projection) -> Decision
```

**Semantics behind each number:**

- **The comparison is `spent + projection.next_call <= ceiling`.** Inclusive, so
  landing exactly on the ceiling is permitted. AC-1 and AC-2 sit one cent either
  side of it deliberately: a strict-versus-inclusive slip is invisible in review
  and changes behaviour on exactly one input.
- **`BOOTSTRAP_PAGE_ESTIMATE` is $0.06**, which is $1.14 ÷ 20 rounded up to the
  cent (`docs/wiki/cost-model.awk`, design A). It is used only until
  `MIN_SAMPLES_FOR_PROJECTION` real calls exist. **Rounding up is deliberate**:
  an estimate that errs low is an estimate that lets a run start it cannot
  finish.
- **`MIN_SAMPLES_FOR_PROJECTION = 2`** because one page is not a sample — a
  single wordless page would project the whole chapter at nearly zero and
  disable the guard for the pages that follow.
- **`basis` is reported, not inferred.** MT-018 shows the user "projected $1.30
  (estimated)" versus "(from 5 pages)", and those are different claims.
- **The guard is consulted by `TranslateStage` before assembling the request**,
  so a refusal costs nothing — not even the image encode.

**Oracle partition: entirely mechanical.** Every criterion is arithmetic with a
stated right answer. Read the numbers out; do not calibrate anything. The only
judgement in the story is already made above (inclusive comparison, round up,
two samples) and is recorded here so RED does not re-decide it.

## Deferred verifications

- *Falsifiable condition 1:* with the comparison changed from `<=` to `<`, AC-2
  **must** fail and AC-1 must still pass. If both still pass, the criteria are
  not sitting on the boundary and RED did not do what this contract asked.
- *Falsifiable condition 2:* with the guard moved to **after** the call, AC-4
  **must** fail — a ledger row would exist for the refused page.
- *Falsifiable condition 3:* with `BOOTSTRAP_PAGE_ESTIMATE` set to `$0.00` — a
  wrong value rather than a removed behaviour — AC-5 and AC-7 **must** fail.
- **Owner: GATES.** Three mutations via `bash scripts/mutate.sh`.

## Model guidance

- **RED and GREEN models:** to be recorded at dispatch, by name. Defaults are
  `claude-opus-5` (Claude Opus 5).
- **Oracle partition: entirely mechanical.** Say so in the dispatch prompt, and
  say that the four judgement calls (inclusive comparison, round-up estimate,
  two-sample minimum, guard-before-call) are settled in this contract and are to
  be asserted, not reconsidered.
- **Success condition, falsifiable:** AC-1 and AC-2 differ by one cent across
  the boundary, and AC-4 asserts the **absence of a ledger row** rather than the
  presence of an abort event. A suite that checks only that the run stopped has
  not tested that the money was not spent.
- **Verdict:** *to be recorded.*

## Out of scope

Displaying any of this (MT-018 — see the designer's `approaching` / `exceeded` /
`aborted` states). Resuming a budget-aborted run with a raised ceiling is
permitted by the design but is not a criterion here; it falls out of MT-006's
resume and MT-012's cross-run totalling, and if it does not, that is a new story.
Changing the ceiling at runtime. Rate-limit or retry policy, which is a different
kind of failure.
