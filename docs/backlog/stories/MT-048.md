## Context

Split out of MT-015 by the user's decision at its PLANNED phase (MT-015 PO-1).
`docs/wiki/design/layout.md` §"The one breakpoint — 1440px" defines two layouts:

| | < 1440 | ≥ 1440 |
|---|---|---|
| `TranslationColumn` default width | 300 | 380 |
| `PageStrip` | a 28 px rail of status glyphs and index numbers | full 96 px with thumbnails |
| Header | counters, cost, zoom | the same plus the chapter name |

MT-015 built one layout (strip 96, column 340) with no breakpoint, and its AC-1
and AC-2 assert that layout. This story replaces it with the designed one, and
must therefore amend MT-015's tests deliberately — MT-015's AC-1 (96 / 340 at
1100 px) and AC-2 (1100 → 1900 leaves both side widths unchanged) are both false
under the breakpoint. Also resolve with the Lead Designer: `layout.md`'s region
table still says 340 for the column, which the breakpoint table overrides.

## Acceptance criteria

*To be written at planning, against `layout.md`. Among them: a resize that stays
on one side of 1440 gives the canvas the full delta; a resize that crosses it
reallocates exactly as the table says; the rail still selects pages and carries
every status glyph (A-10); a user-dragged column width is not overwritten by
crossing the breakpoint.*
