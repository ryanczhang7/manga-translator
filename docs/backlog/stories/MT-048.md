## Context

Split out of MT-015 by the user's decision at its PLANNED phase (MT-015 PO-1).
`docs/wiki/design/layout.md` §"The one breakpoint — 1440px" defines two layouts:

| | < 1440 | ≥ 1440 |
|---|---|---|
| `TranslationColumn` default width | 300 | 380 |
| `PageStrip` | a 28 px rail of index numbers | full 96 px |
| Header | counters, cost, zoom | the same plus the chapter name |

MT-015 built one layout (strip 96, column 340) with no breakpoint, and its AC-1
and AC-2 assert that layout. This story replaces it with the designed one, and
therefore amends MT-015's tests deliberately: MT-015's AC-1 (96 / 340 at
1100 px) and AC-2 (1100 → 1900 leaves both side widths unchanged) are both false
under the breakpoint. MT-015 is DONE; its story file is not edited, this one
records the supersession (PO-1).

**Narrowed on 2026-10-14 by the user (PO-1).** As filed, the breakpoint table
also promised thumbnails on the 96 px strip and page-status glyphs on the rail.
Neither exists: `PageStrip` is a `QListWidget` of filenames, and
`components.md` §`PageStrip`'s seven-status table is unbuilt. Those are
**MT-086** (status glyphs), **MT-087** (thumbnails) and **MT-088** (remembered
layout), all depending on this story. Here the rail shows the page's 1-based
index and nothing else, and the 96 px strip keeps showing filenames.

## Acceptance criteria

- **AC-1** — Given a window **1100 px** wide, when the workspace is laid out,
  then `PageStrip` is **28 px**, `TranslationColumn` is **300 px**, `PageCanvas`
  takes the remaining width, and every strip item's text is the page's 1-based
  index (`"1"`, `"2"`, …). Given a window **1900 px** wide, then `PageStrip` is
  **96 px**, `TranslationColumn` is **380 px**, and every strip item's text is
  the page's filename. Given a window **exactly 1440 px** wide, then the layout
  is the wide one (strip 96, column 380): the comparison is `>=`. In all three,
  each item's accessible text (`Qt.ItemDataRole.AccessibleTextRole`) is
  `Page N of M, <filename>`.
- **AC-2** — Given a resize that **stays on one side** of 1440 (1100 → 1400,
  and 1500 → 1900), when the layout settles, then `PageCanvas.width()` has
  increased by the **full** delta and `PageStrip.width()` and
  `TranslationColumn.width()` are unchanged.
- **AC-3** — Given the column has **not** been dragged, when the window is
  resized from 1100 to 1900 (crossing upward), then the strip is 96, the column
  is 380, and the canvas has grown by `800 − (96 − 28) − (380 − 300)` =
  **652 px**; when it is then resized back to 1100 (crossing downward), the
  strip is 28 and the column is 300 again.
- **AC-4** — Given the user has dragged the column to **400 px** at 1100, when
  the window is resized to 1900, then the column is **still 400**, the strip is
  96, and the canvas has grown by `800 − 68` = **732 px**; resized back to
  1100, the column is still 400 and the strip is 28.
- **AC-5** — Given a chapter is loaded, when the window is 1900 px wide, then a
  header label `chapterName` is **visible** and reads
  `ui.intake.display_name(chapter.source_dir)` (the folder name, middle-cut past
  40 characters — one rule with the intake heading); at 1100 px it is **hidden,
  not removed** (`isHidden()` is True, the widget is still a child of the
  header with its text set), and it reappears on crossing back up.
- **AC-6** — The rail still selects pages: given the window is 1100 px wide,
  when a strip item is made current, then `Workspace.show_page` runs for that
  ordinal exactly as at 1900 (the existing `currentRowChanged` wiring is
  unchanged), and the window minimum stays **1100 × 720**.

`COLUMN_MIN_WIDTH` 280, `COLUMN_MAX_WIDTH` 560, `CANVAS_MIN_WIDTH` 520,
`HEADER_HEIGHT` 48, `FOOTER_HEIGHT` 44 and `Workspace.MIN_SIZE` (1100, 720)
are unchanged.

**Block 2 — `PageStrip`.** Gains `set_rail(self, rail: bool) -> None` and a
read-only `is_rail` property. `set_rail(True)` sets the fixed width to
`STRIP_RAIL_WIDTH` and every item's text to its 1-based index;
`set_rail(False)` sets `STRIP_WIDTH` and the filename. Items are added through
a new `set_pages(self, filenames: Sequence[str]) -> None` (which `load_chapter`
calls instead of `addItem` in a loop); the strip keeps the filenames so a later
`set_rail` can relabel. Every item carries
`Qt.ItemDataRole.AccessibleTextRole == f"Page {i + 1} of {n}, {filename}"` in
both modes. Current row and selection survive `set_rail` (relabel, do not
rebuild). Default on construction: not rail (96), matching MT-015 until the
first `resizeEvent`.

**Block 3 — the breakpoint in `Workspace`.** `resizeEvent` calls
`self._apply_breakpoint()` after `super().resizeEvent(event)`.
`_apply_breakpoint` computes `wide = self.width() >= BREAKPOINT_WIDTH`, calls
`self.page_strip.set_rail(not wide)`, shows or hides `self.chapter_name`
(Block 5), and — **only when `self._column_dragged` is False** — sets the
splitter sizes to `[strip, remaining, COLUMN_DEFAULT_WIDE if wide else
COLUMN_DEFAULT_NARROW]`. While it does so it sets `self._reallocating = True`
so the `splitterMoved` handler ignores it. The `__init__` `setSizes` becomes
`[STRIP_WIDTH, CANVAS_MIN_WIDTH, COLUMN_DEFAULT_NARROW]` (the window opens
below 1440 at minimum size; the first resize corrects it either way). Crossing
is detected by the side changing, not by the event; a resize on one side must
not call `setSizes` at all (that is what keeps AC-2's full delta, as today).

**Block 4 — drag detection.** `self.splitter.splitterMoved` connects to
`_on_splitter_moved(pos, index)`: if `not self._reallocating` and `index == 2`,
set `self._column_dragged = True`. `QSplitter.moveSplitter` (what the tests use
for a drag) emits `splitterMoved`; `setSizes` does not — RED should confirm
this on PySide6 with a one-line probe and amend if it does not hold.
*(RED, 2026-10-14: confirmed, no amendment. Offscreen probe: after `setSizes`
`[]`; after `moveSplitter(600, 2)` `[(600, 2)]`; a later window `resize`
added nothing. Output in `## Handoff`.)* The flag
resets to False in `load_chapter` only (Lead Designer: "dragged state resets
only on opening another chapter"); MT-088 persists it across sessions.

*Lead Designer (Claude Fable 5.1, `claude-fable-5-1`), 2026-10-14; pasted by

**Scope.** The reallocation only. Page-status glyphs, thumbnails and remembered
splitter positions are three separate follow-up stories; this story must not
pretend they exist. `PageStrip` stays a `QListWidget`.

**Breakpoint.** Judged on the top-level window width: `width >= 1440` is wide,
`< 1440` narrow. Re-judged on every window resize and once on first show.

**Widths.**
- `PageStrip`: 28 px (narrow) / 96 px (wide), `setFixedWidth`.
- `TranslationColumn` default: 300 (narrow) / 380 (wide). User clamp 280–560
  unchanged. `COLUMN_DEFAULT_WIDTH = 340` goes away.
- `PageCanvas`: stretch 1, `minimumWidth` 520, unchanged. Canvas minimum
  outranks the column's 560 clamp (at 1100 a drag stops at 552).
- Window minimum 1100 × 720 unchanged; the narrow layout is the one at minimum.

**Rail content (narrow).** Each row shows the page's 1-based index number only:
`type.numeric`, `color.text.secondary`, `color.text.primary` on the current row.
Wide strip keeps showing filenames. Rows keep the same accessible name at both
widths; selection by click and by keyboard (Up/Down, Enter/Space) works at both.

**Header: chapter name.** New leading `QLabel` (`chapterName`), inserted before
the existing `addStretch(1)` so the `CostReadout` stays at the right end.
`type.body-strong`, `color.text.primary`, vertically centred, `space.4` from the
left edge (the header's existing contents margin). Text:
`ui.intake.display_name(chapter.source_dir)` — one rule with the intake heading.
May shrink; elide `Qt.ElideRight` when the header has no room; never squeeze the
readout. Accessible name "Chapter {name}". Below 1440: `setVisible(False)` —
hidden, not removed from the layout; text stays set so returning to wide shows
it with no reload.

**Behaviour the tests must assert.**
1. At 1100 (narrow): strip 28, column 300, chapter-name label not visible.
2. At 1440 (wide): strip 96, column 380, chapter-name label visible with the
   folder's display name.
3. Resize staying on one side (e.g. 1100 → 1439, 1440 → 1900): both side
   widths unchanged, canvas grows by exactly the delta.
4. Crossing in either direction (1439 → 1440, 1440 → 1439) with no drag:
   strip 28 ↔ 96 and column 300 ↔ 380.
5. Crossing after a user drag of the splitter: the dragged column width (within
   280–560) is kept; only the strip changes. Both directions.
6. Row accessible names and selection in the rail are identical to the 96 px
   strip's; the rail shows the 1-based index as its text.
7. Chapter name label hidden below 1440 is still in the layout tree with its
   text set (hidden, not removed).

**Tokens touched.** `type.body-strong`, `type.numeric`, `color.text.primary`,
`color.text.secondary`, `space.4`. No new tokens. *(PO, Block 5: applied in
