## Context

Filed by the EPIC-02 mutation audit, `docs/wiki/audits/EPIC-02-2026-11-25.md`,
for its surviving mutants S1, S2 and S3 (`## Decided` 2, 3 and 4;
`## Evidence` E-2, E-3 and E-4). This story adds tests only. All three
behaviours are correct in production code today. Deleting the line that
provides any one of them leaves every test passing.

**What is settled.** The three behaviours below are the intended ones, and the
fix is tests only. No production file changes.

**What is evidence, to verify rather than trust.** The audit found that each
mutant below survives. Re-run each command at this story's base first. The
audit's line numbers are for `a2b2003`. The expressions here match on line
text instead, so they still work if lines move.

- **S1** (`src/mangatl/store/intake.py:68`). `read_chapter` filters entries
  with `if entry.is_file() and entry.suffix.lower() in PAGE_SUFFIXES`. With
  `entry.is_file() and` removed, `test_intake.py` and `test_page.py` still pass
  (`34 passed`). So do the CLI, project and intake-UI tests (`333 passed`). The
  only subdirectory any test builds is the AC-2 test's `sub`, and the suffix
  check already excludes that.

      bash scripts/mutate.sh src/mangatl/store/intake.py 's/if entry.is_file() and entry.suffix/if entry.suffix/' -- uv run pytest -q -p no:cacheprovider tests/core/test_intake.py

- **S2** (`src/mangatl/store/project.py:744`). `open_project` calls
  `connection.close()` before `raise SchemaTooNew`. With that call removed,
  every `SchemaTooNew` test still passes (`35 passed` in `test_project.py`).
  The comment above the line gives the reason it exists: on Windows, an
  abandoned handle locks the file. MT-157 pinned the same property for a failed
  upgrade (its AC-4 rename test), but not for this refusal.

      bash scripts/mutate.sh src/mangatl/store/project.py '/if found > SCHEMA_VERSION:/,/raise SchemaTooNew/s/connection.close()/pass/' -- uv run pytest -q -p no:cacheprovider tests/core/test_project.py

- **S3** (`src/mangatl/store/project.py:1403`). `refresh_from_source` ends with
  `self._chapter = _read_chapter(self._connection)`. With that line removed,
  every refresh, stale and replace test still passes (`66 passed`, and
  `50 passed` in a wider selection). The docstring of the `chapter` property
  promises that a refresh re-derives it.

      bash scripts/mutate.sh src/mangatl/store/project.py 's/^        self._chapter = _read_chapter(self._connection)$/        pass/' -- uv run pytest -q -p no:cacheprovider tests/core/test_project.py

**Required gates that would fail if these broke:** `unit` and `coverage-core`.

## Acceptance criteria

- **AC-1** - Given a folder holding `a.png` and a subdirectory named
  `extra.png` that itself holds a valid image, when the folder is read as a
  chapter, then exactly one page, `a.png`, is returned and no error is raised.
  Fails under S1.
- **AC-2** - Given a project file whose `user_version` is above
  `SCHEMA_VERSION`, when `open_project` raises `SchemaTooNew`, then the project
  file can be renamed straight away while the exception is still held, as
  MT-157's AC-4 test does for a failed upgrade. Fails under S2 on Windows.
- **AC-3** - Given an open project whose scan `p3.png` has been replaced by an
  image of a different size, when `refresh_from_source` returns, then
  `project.chapter.pages` equals `project.pages()`, and that page carries the
  new hash, width and height. Fails under S3.

## Contract

**Writes:** `tests/core/test_intake.py`, `tests/core/test_project.py`

- Tests only, and GREEN is a no-op. Every test passes on arrival, so each one is
  earned by its mutation in `## Deferred verifications`.
- AC-1: build the images with the intake tests' `png_bytes` fixture
  (`tests/core/conftest.py`).
- AC-2: copy MT-157's approach in
  `test_a_failed_upgrade_releases_the_project_file_so_it_can_be_renamed`
  (`tests/core/test_migration_atomic.py`). Keep the `ExceptionInfo` alive and
  call `os.rename` on the file. That test also has an optional check that does
  not depend on the platform: record the connection `project._connect`
  returned, and assert it raises `sqlite3.ProgrammingError` when used. Prefer
  that check. **It is what makes AC-2 fail on Linux CI too**, because there a
  rename of an open SQLite file succeeds.
- AC-3: `test_replacing_one_scan_invalidates_that_page_only_and_leaves_the_others_intact`
  (`tests/core/test_project.py:754`) already builds this exact state, with
  `_REPLACEMENT_SIZE = (31, 7)`. RED chooses whether to extend it or add a
  sibling test.
