## Context

`EPIC-08` adds two translation providers (MT-080 Gemini, MT-081 OpenAI). Both
need the same five things Claude's request already carries - the system prompt,
the region listing, the context block, the capped page image and the response
JSON schema - and the same two things Claude's response already goes through -
`parse_lines` and `parse_terms`. Today all of it lives in
`translate/prompt.py` and `translate/parse.py` as **private helpers**
(`_SYSTEM_PROMPT`, `_user_text`, `_context_text`, `_GLOSSARY_SCHEMA`,
`_body`) or **typed to the Anthropic SDK** (`parse_lines(response: Message,
...)`). Two stories that both need a third thing that does not exist: the
third thing is this story (`story-authoring`, epics, "Ordering").

**This is a chore, run through the ordinary RED→GREEN path, not SCAFFOLD.**
There is no user-visible behaviour, but there is observable behaviour: new
public functions with pinned outputs, and one invariant that is the whole
point - **Claude's request and parse are byte-for-byte unchanged.** RED writes
the tests for the new names (they fail at import, which is the right failure);
the invariant is pinned by MT-011/MT-014's existing suites staying green with
no edit, plus one golden test here.

Why the same prompt for every provider: the brief's axis is accuracy, and the
only way the three providers' measured costs and acceptance rates (MT-080/081
`## Notes`, later `bench`) are comparable is if they were asked the same
question. A provider-specific prompt is a tuning decision for after the
measurements exist (`## Out of scope`).

**Which required gate would fail if this story's artifact broke:** `unit` and
`coverage` (`covers | unit | src/mangatl/**`). `required_gates` stays empty.

## Acceptance criteria

*Oracle partition: all **mechanical**. AC-1's "same bytes" is the one golden
comparison; everything else is a pinned value.*

- **AC-1** — Given any page image, OCR results and `PromptContext`, when
  `build_request` is called after this story, then the kwargs it returns are
  **equal** to the kwargs the pre-story `build_request` returned for the same
  inputs - pinned as: the `system[0].text` is `page_prompt.SYSTEM_PROMPT`,
  the last user content block's text is `page_prompt.user_text(ocr_results)`,
  the context block (when present) is `page_prompt.context_text(context)`,
  the image data is `page_prompt.prepare_page_image(page_image)[0]` base64,
  and `output_config.format.schema` is `page_prompt.response_schema(n)`. (The
  existing `test_translate_prompt.py` suite is the second half of this AC and
  must pass unedited.)
- **AC-2** — Given `n` regions, when `response_schema(n)` is called, then it
  is a JSON-schema object whose properties are exactly `"0".."n-1"` plus
  `glossary`, with **no `required` list** (an omitted region is legal, MT-011
  AC-5) and `additionalProperties: False`, and the `glossary` property is the
  array-of-`{term_ja, term_en, note}` schema MT-014 C-3 pins.
- **AC-3** — Given a JSON text, when `parse_lines_text(text, region_indices)`
  is called, then it returns what `parse_lines` returns for a `Message` whose
  first text block carries that text, including raising `UnknownRegionIndex`
  for the same inputs; and `parse_lines(message, ...)` is now implemented as
  `parse_lines_text(first_text_block(message), ...)`.
- **AC-4** — Given a JSON text, when `parse_terms_text(text)` is called, then
  it returns what `parse_terms` returns for the same body, malformed items
  skipped, `()` with no `glossary` key.
- **AC-5** — Given `page_prompt` is imported, then it imports nothing from
  `anthropic` (`sys.modules` check after a fresh import in a subprocess, or an
  AST check - RED chooses), so MT-080/081 can import it under a contract that
  forbids them the Anthropic SDK's types leaking through it.

### C-1 — `mangatl.translate.page_prompt`, new, SDK-free

```python
SYSTEM_PROMPT: str                      # moved from prompt._SYSTEM_PROMPT, text unchanged
MAX_IMAGE_LONG_EDGE_PX: int = 1568      # moved; prompt.py re-exports it unchanged
GLOSSARY_SCHEMA: dict[str, Any]         # moved from prompt._GLOSSARY_SCHEMA
def prepare_page_image(page_image: bytes) -> tuple[bytes, int]   # moved, body unchanged
def user_text(ocr_results: Sequence[OcrResult]) -> str           # was prompt._user_text
def context_text(context: PromptContext) -> str                  # was prompt._context_text
def response_schema(region_count: int) -> dict[str, Any]         # the object schema build_request inlines today
```

- `prepare_page_image`'s `est_tokens` stays Claude's `ceil(w*h/750)` rule and
  keeps its name and docstring. It is **not** a provider-neutral number; it is
  recorded on the request and consumed by nothing (MT-078 `## Context`), and
  MT-080/081 say so rather than inventing their own.
- The 1,568 px cap applies to every provider. It is a cost constraint
  (`stack.md` §5/O4 clause 1), not only Claude's server-side limit, and the
  same image for every provider is what makes the measurements comparable.

**Amended by lead-po at PLANNED→RED, 2026-10-10 - an import trap read out of
the tree:** `prompt.py` today imports `GLOSSARY_KEY` from `parse.py`, and
`parse.py` imports `anthropic.types.Message` at module level. A `page_prompt`
that imports `GLOSSARY_KEY` from `parse` therefore loads the SDK and fails
AC-5. So **`GLOSSARY_KEY` moves to `page_prompt`** (value unchanged, `"glossary"`),
`parse.py` imports it from there and keeps it in its `__all__` (C-3: the
name stays importable from `parse` for every existing caller), and
`page_prompt` imports nothing from `parse`. `parse.py` itself stays
SDK-typed - `parse_lines_text`/`parse_terms_text` are the neutral entry
points, and MT-080/081 importing them transitively loads `anthropic`, which
their contracts ("Only translate imports anthropic") permit. RED may amend if
a cleaner cut exists (e.g. `TYPE_CHECKING` for `Message`); say so.

### C-2 — `prompt.py` keeps its public surface

`__all__` unchanged: `MAX_IMAGE_LONG_EDGE_PX`, `MAX_OUTPUT_TOKENS`,
`MODEL_ID`, `build_request`, `prepare_page_image` - the last two names
re-exported from `page_prompt` so `tests/core/test_translate_prompt.py`
imports as before. `build_request` composes C-1's pieces and returns the same
dict. **Call shape untouched** (MT-011 C-5): `thinking`, `output_config`,
`cache_control` all as they are.

### C-3 — `parse.py` splits at the text

```python
def first_text_block(response: Message) -> str          # was _body's first line; raises StopIteration → keep as is, or ValueError: RED pins
def parse_lines_text(text: str, region_indices: Sequence[int]) -> dict[int, str]
def parse_terms_text(text: str) -> tuple[ProposedTerm, ...]
def parse_lines(response: Message, region_indices) -> dict[int, str]   # unchanged signature, delegates
def parse_terms(response: Message) -> tuple[ProposedTerm, ...]         # unchanged signature, delegates
```

`__all__` grows by the three new names. `UnknownRegionIndex`, `GLOSSARY_KEY`
unchanged. The non-JSON body still raises out of `json.loads` (MT-011's
accepted answer).

**Changed signatures: none.** Every existing export keeps its signature;
callers - **grep-listed by lead-po 2026-10-10 against the tree**
