## Context

Filed by the mutation audit `docs/wiki/audits/EPIC-05-2026-10-27.md`,
`## Decided` 3 and `## Evidence` E-3. **MED priority.** This is a **defect in
shipped code**, found while classifying survivor WS3. It is not a surviving
mutant.

**What happens.** The user commits a line on page A (Enter, `Ctrl+Enter`,
Accept or Revert), which starts the 500 ms save timer, and then selects page B
before the timer fires. Page B's row in the page strip then shows **page A's**
status and line counts.

**The mechanism**, read in `src/mangatl/ui/workspace.py` at `73b7b10`:

1. `show_page` sets `self._page_ordinal = ordinal` (`:1079`) and then calls
   `_load_regions`.
2. `_load_regions` flushes the pending saves (`:1123`), and so does `set_rows`
   (`:779`). Each successful save re-renders its row
   (`saveSucceeded` -> `_render` -> `rendered` -> `linesChanged`).
3. `linesChanged` runs `_refresh_page_progress` (`:1062-1073`). At that point
   the column still holds page A's rows, but `_page_ordinal` is already B. So
   page A's statuses are written onto row B, and nothing re-derives row B until
   one of B's own lines changes.

**Measured by the audit** with a scratch probe outside the tree, on
`tests/ui/test_line_review_workspace.py`'s fixtures with both pages set `done`.
Accepting one line on page 1 with `Ctrl+Enter` and then calling
`setCurrentRow(1)` moved page 2's row from
`PageProgress('translated', 0, 1, 0)` to
`PageProgress('failed', 1, 5, 1)`, which is page 1's value.

- Page 1's own row is correct, because it was refreshed at commit time.
- The store is correct.
- Reopening the chapter corrects the strip, because `load_chapter` derives it
  from the store.

**Why it matters.** The strip's glyph is how a reviewer sees which pages still
need reading (MT-086). A wrong glyph on an unvisited page misleads the
reviewer in either direction. For example, an unreviewed page can read as
reviewed after leaving a fully reviewed one.

**Settled (audit `## Decided` 3):** this is a defect, and the strip must show
each page's own lines.

**Evidence to verify, not assume:** the measured values above. RED reproduces
the defect with its own test on this story's fixture before relying on them.

Required gate that fails if this breaks: `unit` and `coverage`, which collect
`tests/ui/test_page_strip_status.py`.

## Acceptance criteria

- **AC-1** - Given the `reviewing` project with page 1 shown and page 2's strip
  row reading its own progress, when the user accepts one of page 1's lines
  and selects page 2 before that line's save timer fires, then page 2's strip
  row still reads exactly what it read before. Page 1's strip row reads page
  1's progress with that line accepted. All other rows are unchanged.
  - In the strip, `progress(0)` is page 1 and `progress(1)` is page 2. This
    criterion is about `progress(1)`.
  - Fails on the shipped code.
- **AC-2** - Given the same project, when the line's save completes after the
  page change, then the project file holds the accept for page 1's line. The
  fix must not drop or delay the pending save it reorders.
