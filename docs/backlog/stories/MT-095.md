## Context

Filed by the follow-up mutation audit
`docs/wiki/audits/audit-followups-EPIC-04-EPIC-07-2026-10-26.md`, survivors
**S93-1** and **S93-2** (`## Decided` 4, `## Evidence` E-3). **LOW priority.**

MT-093 closed FM4: a download that raises `OSError` mid-stream now has a test
proving the `.part` is removed and the same exception propagates. The clean-up
is `except BaseException: part.unlink(missing_ok=True); raise`
(`packaging/fetch_models.py:67-69`), and the breadth of that `except` is not
pinned. Measured at this audit's base (`c32c689`):

- `except BaseException:` -> `except OSError:` survives
  `tests/core/test_fetch_models.py` (18 passed) and all of `tests/core` (2348
  passed, exit 0);
- `except BaseException:` -> `except Exception:` survives
  `tests/core/test_fetch_models.py` (18 passed).

Both are realistic edits ("catch only I/O errors", "don't catch
BaseException"), and each reintroduces FM4 for a real interruption:

- `http.client.IncompleteRead`, which `urllib`'s response raises when the
  server closes the connection before the declared length, is an
  `HTTPException`: a subclass of `Exception` and **not** of `OSError` (MRO
  checked at audit time: `IncompleteRead, HTTPException, Exception,
  BaseException, object`). Under `except OSError` it leaves the `.part`.
- `KeyboardInterrupt` (Ctrl-C during a build fetch, which MT-093's own context
  names) is not an `Exception`. Under `except Exception` it leaves the `.part`.

Production effect, unchanged from FM4: a stray `packaging/models/**/*.part`.
It is reopened `"wb"` on the next run and never bundled
(`packaging/mangatl.spec` bundles manifest paths only). Low impact; a stated
contract with a gap.

**Settled (audit `## Decided` 4):** the code is correct; this story only adds
tests.

**Evidence to verify, not assume:** the two survivals above. RED re-runs each
mutant once against `tests/core/test_fetch_models.py` before writing.

Required gate that fails if this breaks: `unit`, `coverage` and
`coverage-core`, which all collect `tests/core/test_fetch_models.py`.

## Acceptance criteria

- **AC-1** - Given an opener whose response yields some bytes and then raises
  `http.client.IncompleteRead`, when `fetch_all` runs, then that same
  exception object propagates, and neither the final file nor its `.part`
  exists afterwards. Fails under `except OSError:`.
- **AC-2** - Given an opener whose response yields some bytes and then raises
  `KeyboardInterrupt`, when `fetch_all` runs, then that same exception object
  propagates, and neither the final file nor its `.part` exists afterwards.
  Fails under `except Exception:`.

  facts). Pin exactly.
- No `src/` or `packaging/` change. No signature change, so no caller list.
