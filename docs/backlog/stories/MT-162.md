## Context

**The live glossary measurement fails on `main`, and the code shows one
mechanism that produces exactly the failing rows.** `bash scripts/gates.sh
--gate live` WARNs (the gate is optional) on
`tests/integration/test_glossary_live.py::test_live_a_name_keeps_its_reading_with_continuity_and_drifts_without_it`
(MT-045). Observed twice on 2026-11-23, with the identical pattern: on
MT-147's branch (tree 91588a5, $0.330984 over 50 calls) and as a control on
origin/main f7eac97 in a clean worktree ($0.254546 over 50 calls). The full
record is MT-147's `### DV-4`. Model: `gemini-3.1-pro-preview`.

```
E       AssertionError: AC-1: continuity ON consistent in 0/10, needs >= 9; AC-2: continuity OFF inconsistent in only 0/10, needs >= 4 - the fixture does not exercise the mechanism (change the fixture, never the bar)
 0 on  Kakeru Sho    NO         翔=Sho(name)
 1 off Kakeru Kakeru yes        -
```

In all 10 "on" runs the pre-pass (`gemini.propose_glossary`) proposed
`翔=Sho(name)`, page 1 read `Kakeru` and page 2 read `Sho`. In all 10 "off"
runs both pages read `Kakeru`.

**What the code shows (a fact, read on f7eac97).** The glossary is proposed
once, *before* page 1 (`pipeline/prelude.py`, MT-105), and since MT-106 it is
the only source of glossary terms. But in `rolling` mode - the default
(`compose.build_pipeline(context_mode="rolling")`, `cli`, `app`) -
`pipeline/continuity.build_prompt_context` returns `EMPTY_CONTEXT` for
ordinal 0 "whatever the glossary holds". That rule is MT-014 AC-5, written
when the glossary was built *from* page 1's own proposals, so page 1 had
nothing to receive. Since MT-105 it means the one page that never sees the
chapter's glossary is page 1: it renders a name unguided, and every later
page is told to "use these renderings exactly". Whenever the model's unguided
reading differs from the pre-pass's, page 1 disagrees with the rest of the
chapter. The live test's "on" arm mirrors this faithfully (page 1 with
`EMPTY_CONTEXT`, page 2 with the pre-pass glossary), which is why it shows
`Kakeru` / `Sho`. Nothing "established on page 1" is overridden: the glossary
exists first, and page 1 is simply not given it. `neighbours` mode and the
batch path already hand page 1 the glossary (MT-107) and are not affected.

**What is NOT known.** Why page 1's unguided reading is now `Kakeru`. On
MT-045's recorded runs (its `## Notes`) an unguided page 1 read `Sho` in the
rows recorded there, which agreed with the pre-pass and hid this defect: "on"
was 10/10 consistent. Candidates, none established: drift in the Gemini model
behind the same id; a prompt or schema change since (MT-149's `ja` echo, for
one) shifting the reading; chance on a small fixture. This story does not
need the answer: the defect above is in our code whichever it is. Whether
fixing it restores the live "on" arm is a separate claim, measured only by
DV-3.

**Two things are broken and this story fixes one.** (1) MT-045 AC-1, the "on"
arm: a product defect, fixed here, offline, with doubles. (2) MT-045 AC-2,
the negative control: with continuity off both pages now read `Kakeru`, so the
fixture no longer produces drift and the measurement no longer discriminates.
That is a fixture change that can only be tuned against the live model. It is
split out (see `## Out of scope` and PO-2 in `## Notes`). The test's own rule
stands: the fixture changes, never the bar. No threshold moves in either story.

Epic: EPIC-04 (continuity across pages; MT-014 built the mechanism, MT-045
measures it). This story **reverses MT-014 AC-5 for a chapter with a
glossary** - a product decision, put to the user as PO-1 in `## Notes`.

**The required gate that fails if this breaks:** `unit`
(`uv run pytest -q tests/core tests/ui`), through `tests/core/test_continuity.py`
and `tests/core/test_glossary_live_mirror.py`. Every acceptance criterion is
offline, so `required_gates` stays empty. The `live` gate is optional,

## Acceptance criteria

All five are offline and run under `unit`. "Page 1" is ordinal 0. The
glossary block text is `domain.glossary.render_block`'s:
`"Glossary - use these renderings exactly:\n翔 = Sho (name)"`.

- **AC-1** — *(reproduces the defect at its source)* Given a chapter whose
  glossary holds `翔 = Sho (name)` and whose pages 0 and 1 already hold
  proposed English (a chapter re-run from the top), when
  `build_prompt_context(project, 0)` is called with no mode and again with
  `mode="rolling"`, then both return
  `PromptContext(glossary_block="Glossary - use these renderings exactly:\n翔 = Sho (name)", rolling_block="")`.
  Today both return `EMPTY_CONTEXT`.
- **AC-2** — *(the live failure, reproduced offline)* Given a two-page
  chapter whose glossary holds `翔 = Sho (name)` as the pre-pass writes it
  before page 1, and a double translator that renders the name with the
  rendering its handed glossary block gives 翔, and as `Kakeru` when the
  handed context has no entry for 翔, when the real `TranslateStage` in its
  default mode translates page 0 and then page 1, then the name line stored
  for page 0 and the one stored for page 1 both read `Sho`, and the glossary
  block handed to page 0's call equals the one handed to page 1's. Today page
  0 stores `Kakeru` and page 1 `Sho`: the live table's `on  Kakeru Sho  NO`.
  *Control:* the same double over the same chapter with an empty glossary
  stores `Kakeru` on both pages, so the double follows its context and is not
  a constant.
- **AC-3** — *(the fresh chapter is unchanged)* Given a chapter with **no**
  glossary entries whose pages 0 and 1 already hold proposed English, when
  `build_prompt_context(project, 0)` is called (no mode, and `"rolling"`),
  then it equals `EMPTY_CONTEXT` by value, and a default `TranslateStage`
  hands page 0's translator `EMPTY_CONTEXT` - so page 1 of a chapter with no
  glossary still sends MT-011's request, and page 1 never carries a
  previous-page block.
- **AC-4** — *(nothing else moves)* For ordinals 1 and above in `rolling`
  mode, and for every ordinal in `neighbours` mode, `build_prompt_context`
  returns what it returns on f7eac97: every existing test of those cases
  passes **unmodified**. The only existing tests this story may change are
  the ones listed in the Contract's C-4.
- **AC-5** — *(the live test's "on" arm sends what the product sends)* Given
  each of the three hand-shaped cases in
  `tests/core/test_glossary_live_mirror.py` (`_CASES`), when the pre-pass's
  terms are written as the prelude writes them and the real `TranslateStage`
  runs page 0, then the context handed to page 0's translator equals
  `_glossary_live.context_first(proposed)`; in the two-pre-pass-terms case
  that context is not empty (its glossary block contains `翔 = Shou (name)`
  and its rolling block is `""`); and the `context_first` the live test
  module uses is the same function object as the helper's.

**C-1 `pipeline/continuity.build_prompt_context` (the fix).** Signature
unchanged: `build_prompt_context(project: Project, ordinal: int, mode: ContextMode = "rolling") -> PromptContext`.
In `rolling` mode, ordinal 0 returns
`PromptContext(render_block(read_entries(project), MAX_GLOSSARY_TOKENS), "")`.
- The glossary block is the same call every later page makes, so page 1 and
  page 2 are handed the same block (AC-2) and the 400-token cap
  (`MAX_GLOSSARY_TOKENS`) applies to page 1 as to any page.
- The rolling block at ordinal 0 is the literal `""`: there is no previous
  page. It must not come from `project.read_proposed` of any ordinal (not
  `-1`, not `0`); AC-1 and AC-3 put proposed English on pages 0 and 1 so that
  a wrong read shows.
- An empty glossary renders `""` (`render_block` never returns a header
  alone), so the result is `PromptContext("", "")`, equal to `EMPTY_CONTEXT`
  by value. `translate.prompt.build_request` compares by value and
  `page_prompt.context_text` omits an empty block, so no change is needed in
  `translate/` and none is in scope.
- `neighbours` branch: untouched.
- No signature changes, so there is no caller list of the usual kind. What
  changes is a *value* existing tests pin: see C-4.

**C-2 Docstrings that would otherwise lie (GREEN, source).** Three places say
page 1 gets `EMPTY_CONTEXT` whatever the glossary holds:
`pipeline/continuity.py`'s module docstring, `TranslateStage.run`'s docstring

`EMPTY_CONTEXT`"), and the comment over `EMPTY_CONTEXT` in
`domain/glossary.py` ("Page 1's context (AC-5)"). Reword each to: page 1 gets
